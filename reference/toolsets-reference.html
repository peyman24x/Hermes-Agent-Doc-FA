مرجع تول‌ست‌ها

تول‌ست‌ها بسته‌های نام‌دار ابزارند که کنترل می‌کنند ایجنت چه کارهایی بتواند بکند. آن‌ها سازوکار اصلی پیکربندیِ دسترسی‌پذیری ابزارها به‌ازای هر پلتفرم، هر نشست یا هر وظیفه‌اند.

۱ تول‌ست‌ها چطور کار می‌کنند

هر ابزار دقیقاً به یک تول‌ست تعلق دارد. وقتی یک تول‌ست را فعال می‌کنید، همهٔ ابزارهای آن بسته برای ایجنت در دسترس می‌شوند. تول‌ست‌ها سه نوع‌اند:

  • هسته‌ای (Core) — یک گروه منطقیِ منسجم از ابزارهای مرتبط (مثلاً file شامل read_file، ‏write_file، ‏patch و search_files است)
  • ترکیبی (Composite) — چند تول‌ست هسته‌ای را برای یک سناریوی رایج ترکیب می‌کند (مثلاً debugging ابزارهای فایل، ترمینال و وب را یک‌جا دارد)
  • پلتفرمی (Platform) — یک پیکربندی کامل ابزار برای یک زمینهٔ استقرار مشخص (مثلاً hermes-cli پیش‌فرض نشست‌های تعاملی CLI است)

۲ پیکربندی تول‌ست‌ها

به‌ازای هر نشست (CLI)

hermes chat --toolsets web,file,terminal
hermes chat --toolsets debugging        # ترکیبی — به file + terminal + web باز می‌شود
hermes chat --toolsets all              # همه‌چیز

به‌ازای هر پلتفرم (config.yaml)

toolsets:
  - hermes-cli          # پیش‌فرض CLI
  # - hermes-telegram   # بازنویسی برای گیت‌وی تلگرام

مدیریت تعاملی

hermes tools                            # رابط curses برای فعال/غیرفعال‌کردن به‌ازای هر پلتفرم

یا داخل نشست:

/tools list
/tools disable browser
/tools enable homeassistant

۴ تول‌ست‌های پلتفرمی

تول‌ست‌های پلتفرمی پیکربندی کامل ابزار برای یک هدف استقرار را تعریف می‌کنند. بیشتر پلتفرم‌های پیام‌رسانی همان مجموعهٔ hermes-cli را دارند:

تول‌ستتفاوت با hermes-cli
hermes-cliتول‌ست کامل — پیش‌فرض نشست‌های تعاملی CLI. شامل فایل، ترمینال، وب، مرورگر، حافظه، مهارت‌ها، بینایی، image_gen، todo، tts، واگذاری، اجرای کد، cronjob، جستجوی نشست، clarify، computer_use، Home Assistant و ابزارهای کانبان (همگی در زمان اجرا با check_fn گیت دارند).
hermes-acp‏clarify، ‏cronjob، ‏image_generate، ‏text_to_speech، ‏computer_use، هر چهار ابزار Home Assistant و ابزارهای کانبان را حذف می‌کند. متمرکز بر کارهای کدنویسی در بستر IDE.
hermes-api-server‏clarify، ‏text_to_speech، ‏computer_use و ابزارهای کانبان را حذف می‌کند. بقیه را نگه می‌دارد — مناسب دسترسی برنامه‌پذیر که تعامل کاربری ممکن نیست.
hermes-cronمانند hermes-cli.
hermes-telegramمانند hermes-cli.
hermes-discord‏discord و discord_admin را روی hermes-cli اضافه می‌کند.
hermes-slackمانند hermes-cli.
hermes-whatsappمانند hermes-cli.
hermes-signalمانند hermes-cli.
hermes-matrixمانند hermes-cli.
hermes-mattermostمانند hermes-cli.
hermes-emailمانند hermes-cli.
hermes-smsمانند hermes-cli.
hermes-bluebubblesمانند hermes-cli.
hermes-dingtalkمانند hermes-cli.
hermes-feishuپنج ابزار feishu_doc_* / feishu_drive_* را اضافه می‌کند (فقط هندلر کامنت سند از آن‌ها استفاده می‌کند، نه آداپتور گفتگوی عادی).
hermes-qqbotمانند hermes-cli.
hermes-wecomمانند hermes-cli.
hermes-wecom-callbackمانند hermes-cli.
hermes-weixinمانند hermes-cli.
hermes-yuanbaoپنج ابزار yb_* (DM/گروه/استیکر) را روی hermes-cli اضافه می‌کند.
hermes-homeassistantمانند hermes-cli (ابزارهای Home Assistant از قبل پیش‌فرض‌اند و وقتی HASS_TOKEN ست شود فعال می‌شوند).
hermes-webhookزیرمجموعهٔ ایمنِ محدودشده — فقط web_search، ‏web_extract، ‏vision_analyze و clarify. اجراهای وب‌هوکی هیچ دسترسی ترمینال، فایل یا مرورگر نمی‌گیرند.
hermes-gatewayتول‌ست ارکستراتور داخلی گیت‌وی — اجتماع همهٔ تول‌ست‌های hermes-<platform>؛ وقتی استفاده می‌شود که گیت‌وی لازم باشد از هر مبدأ پیامی بپذیرد.

۵ تول‌ست‌های پویا

تول‌ست‌های سرور MCP

هر سرور MCP پیکربندی‌شده در زمان اجرا یک تول‌ست mcp-<server> می‌سازد. مثلاً اگر سرور MCP ی github پیکربندی کنید، یک تول‌ست mcp-github ساخته می‌شود که همهٔ ابزارهای عرضه‌شدهٔ آن سرور را دارد.

# config.yaml
mcp_servers:
  github:
    command: npx
    args: ["-y", "@modelcontextprotocol/server-github"]

این کار تول‌ست mcp-github را می‌سازد که می‌توانید در --toolsets یا پیکربندی‌های پلتفرم به آن ارجاع بدهید.

تول‌ست‌های پلاگینی

پلاگین‌ها می‌توانند حین مقداردهی اولیه با ctx.register_tool() تول‌ست خودشان را ثبت کنند. این‌ها کنار تول‌ست‌های داخلی ظاهر می‌شوند و به همان شکل فعال/غیرفعال می‌شوند.

تول‌ست‌های سفارشی

در config.yaml تول‌ست سفارشی تعریف کنید تا بسته‌های مخصوص پروژه بسازید:

toolsets:
  - hermes-cli
custom_toolsets:
  data-science:
    - file
    - terminal
    - code_execution
    - web
    - vision

وایلدکاردها

  • all یا * — به هر تول‌ست ثبت‌شده (داخلی + پویا + پلاگینی) باز می‌شود

چند ابزار علاوه بر عضویت در تول‌ست، یک بررسی دسترس‌پذیریِ اضافه هم دارند و فقط با all/* روشن نمی‌شوند:

  • ابزارهای قابلیت‌گیت‌شده (مرورگر، computer_use، ‏code_execution، فایشو، Home Assistant، cronjob) فقط وقتی پیش‌نیاز بک‌اند/اعتبارنامه‌شان پیکربندی شده باشد ظاهر می‌شوند.
  • ابزارهای گردش‌کارگیت‌شده — تول‌ست kanban — عمداً opt-in هستند. ‏all/* کانبان را فعال نمی‌کند؛ باید kanban را صریحاً فهرست کنید (یا کارگری دیسپچرزاده با HERMES_KANBAN_TASK ست‌شده باشید). ابزارهای کانبان وضعیت اشتراکی برد را تغییر می‌دهند، پس حتی زیر all هم پیش‌فرض خاموش می‌مانند.

۶ رابطه با hermes tools

فرمان hermes tools یک UI مبتنی بر curses برای روشن/خاموش‌کردن ابزارهای تکی به‌ازای هر پلتفرم می‌دهد. این دست در سطح ابزار کار می‌کند (ریزتر از تول‌ست‌ها) و در config.yaml ماندگار می‌شود. ابزارهای غیرفعال حتی اگر تول‌ستشان فعال باشد فیلتر می‌شوند.
