فرمان‌های پروفایل

این صفحه همهٔ فرمان‌های مرتبط با پروفایل‌های Hermes را پوشش می‌دهد. برای فرمان‌های عمومی CLI، مرجع فرمان‌های CLI را ببینید.

۱ hermes profile

hermes profile <subcommand>

فرمان سطح بالا برای مدیریت پروفایل‌ها. اجرای hermes profile بدون زیرفرمان، راهنما را نشان می‌دهد.

زیرفرمانتوضیح
listفهرست همهٔ پروفایل‌ها.
useتنظیم پروفایل فعال (پیش‌فرض).
createساخت پروفایل جدید.
describeخواندن یا تنظیم توضیحات یک پروفایل (ارکستراتور کانبان برای مسیریابی از آن استفاده می‌کند).
deleteحذف یک پروفایل.
showنمایش جزئیات یک پروفایل.
aliasبازتولید الیاس شل برای یک پروفایل.
renameتغییر نام یک پروفایل.
exportخروجی گرفتن از یک پروفایل به‌صورت آرشیو tar.gz.
importواردکردن یک پروفایل از آرشیو tar.gz.
installنصب توزیع پروفایل از یک URL گیت یا پوشهٔ محلی. توزیع‌های پروفایل را ببینید.
updateدریافت دوبارهٔ یک پروفایل مدیریت‌شده با توزیع و اعمال دوبارهٔ بستهٔ آن.
infoنمایش فرادادهٔ توزیع برای یک پروفایل (URL مبدأ، کامیت، آخرین به‌روزرسانی).

۲ hermes profile list

hermes profile list

همهٔ پروفایل‌ها را فهرست می‌کند. پروفایل فعالِ فعلی با * علامت خورده است.

مثال:

$ hermes profile list
  default
* work
  dev
  personal

هیچ گزینه‌ای ندارد.

۳ hermes profile use

hermes profile use <name>

‏<name> را به‌عنوان پروفایل فعال تنظیم می‌کند. همهٔ فرمان‌های بعدی hermes (بدون -p) از این پروفایل استفاده می‌کنند.

آرگومانتوضیح
<name>نام پروفایلی که باید فعال شود. برای بازگشت به پروفایل پایه از default استفاده کنید.

مثال:

hermes profile use work
hermes profile use default

۴ hermes profile create

hermes profile create <name> [options]

یک پروفایل جدید می‌سازد.

آرگومان / گزینهتوضیح
<name>نام پروفایل جدید. باید یک نام پوشهٔ معتبر باشد (حروف و ارقام، خط تیره، زیرخط).
--clone‏config.yaml، ‏.env، ‏SOUL.md و مهارت‌ها را از پروفایل فعلی کپی می‌کند.
--clone-allهمه‌چیز (پیکربندی، حافظه‌ها، مهارت‌ها، کرون، پلاگین‌ها) را از پروفایل فعلی کپی می‌کند. تاریخچهٔ مخصوص هر پروفایل مستثناست: نشست‌ها، ‏state.db، پشتیبان‌ها، اسنپ‌شات‌های وضعیت، چک‌پوینت‌ها.
--clone-from <profile>پیکربندی/مهارت‌ها/SOUL را به‌جای پروفایل فعلی از یک پروفایل مشخص کلون می‌کند. مگر همراه --clone-all باشد، --clone را هم implying می‌کند.
--no-aliasاز ساخت اسکریپت wrapper می‌پرد.
--description "<text>"توضیح یک‌ یا دومĕ جمله‌ای از اینکه این پروفایل در چه کاری خوب است. ارکستراتور کانبان برای مسیریابی وظایف بر اساس نقش — نه فقط نام پروفایل — از آن استفاده می‌کند. می‌توانید ردش کنید و بعداً با hermes profile describe اضافه‌اش کنید. در <profile_dir>/profile.yaml ذخیره می‌شود.
--no-skillsپروفایلی خالی می‌سازد که هیچ مهارت باندل‌شده‌ای فعال نداشته باشد. یک نشانگر .no-bundled-skills داخل پروفایل می‌نویسد تا اجراهای بعدی hermes update مجموعهٔ باندل‌شده را دوباره نکارند، و ترکیبش با --clone، ‏--clone-from یا --clone-all (که به هر حال مهارت‌ها را کپی می‌کنند) رد می‌شود. برای پروفایل‌های ارکستراتورِ باریک یا پروفایل‌های سندباکس که نباید کاتالوگ کامل مهارت‌ها را به ارث ببرند کاربرد دارد. برای فعال/غیرفعال‌کردن این حالت روی یک پروفایل ازقبل‌ساخته‌شده (از جمله ~/.hermes پیش‌فرض)، از hermes skills opt-out / hermes skills opt-in استفاده کنید.

ساختن یک پروفایل آن پوشهٔ پروفایل را نمی‌کند پوشهٔ پیش‌فرض پروژه/ورک‌اسپیس برای فرمان‌های ترمینال. اگر می‌خواهید پروفایلی در یک پروژهٔ مشخص شروع شود، terminal.cwd را در config.yaml همان پروفایل تنظیم کنید.

مثال‌ها:

# پروفایل خالی — نیاز به راه‌اندازی کامل
hermes profile create mybot

# کلون فقط پیکربندی از پروفایل فعلی
hermes profile create work --clone

# کلون همه‌چیز از پروفایل فعلی
hermes profile create backup --clone-all

# کلون پیکربندی از یک پروفایل مشخص
hermes profile create work2 --clone-from work

# کلون همه‌چیز از یک پروفایل مشخص
hermes profile create work2-backup --clone-from work --clone-all

۵ hermes profile describe

hermes profile describe [<name>] [options]

توضیحات یک پروفایل را می‌خواند یا تنظیم می‌کند. ارکستراتور کانبان برای مسیریابی وظایف بر اساس اینکه هر پروفایل در چه کاری خوب است — نه حدس زدن صرفاً از روی نام پروفایل — از این توضیحات استفاده می‌کند. در <profile_dir>/profile.yaml ذخیره می‌شود تا از ریبوت جان سالم ببرد و با گیت‌وی به اشتراک گذاشته شود.

بدون هیچ فلگی، توضیحات فعلی را چاپ می‌کند (یا اگر خالی باشد، پیام (no description set for '<name>') را می‌دهد).

آرگومان / گزینهتوضیح
<name>پروفایلی که باید توصیف شود. مگر --all --auto استفاده شود، الزامی است.
--text "<text>"توضیحات را دقیقاً روی این متن تنظیم می‌کند (نوشتهٔ کاربر). هر توضیحات موجودی را بازنویسی می‌کند.
--autoتولید خودکار یک توضیح ۱ تا ۲ جمله‌ای با LLM کمکی، بر اساس مهارت‌های نصب‌شده، مدل پیکربندی‌شده و نام پروفایل. مدل را زیر auxiliary.profile_describer در config.yaml پیکربندی کنید. توضیحات خودکار با description_auto: true علامت می‌خورند تا داشبورد آن‌ها را برای بازبینی پرچم بزند.
--overwriteهمراه --auto، توضیحات نوشتهٔ کاربر را هم جایگزین می‌کند (پیش‌فرض: از پروفایل‌هایی که توضیحاتشان صریحاً تنظیم شده می‌پرد).
--allهمراه --auto، همهٔ پروفایل‌های فاقد توضیحات را پوشش می‌دهد.

مثال‌ها:

# خواندن توضیحات فعلی
hermes profile describe researcher

# تنظیم صریح آن
hermes profile describe researcher --text "Reads source code and writes findings."

# گذاشتن تولید توضیح به عهدهٔ LLM
hermes profile describe researcher --auto

# پرکردن توضیحات همهٔ پروفایل‌هایی که توضیح ندارند
hermes profile describe --all --auto

۶ hermes profile delete

hermes profile delete <name> [options]

پروفایل را حذف می‌کند و الیاس شل‌اش را برمی‌دارد.

آرگومان / گزینهتوضیح
<name>پروفایلی که باید حذف شود.
--yes، ‏-yاز پرسش تأیید می‌پرد.

مثال:

hermes profile delete mybot
hermes profile delete mybot --yes
⚠️ هشدار

این کار کل پوشهٔ پروفایل شامل همهٔ پیکربندی، حافظه‌ها، نشست‌ها و مهارت‌ها را برای همیشه حذف می‌کند. پروفایل default (یعنی ~/.hermes) قابل حذف نیست — برای برداشتن همه‌چیز از hermes uninstall استفاده کنید.

۷ hermes profile show

hermes profile show <name>

جزئیات یک پروفایل را نشان می‌دهد؛ از جمله پوشهٔ خانگی، مدل پیکربندی‌شده، وضعیت گیت‌وی، تعداد مهارت‌ها و وضعیت فایل پیکربندی.

این پوشهٔ خانگی Hermes پروفایل را نشان می‌دهد، نه پوشهٔ کاری ترمینال. فرمان‌های ترمینال از terminal.cwd (یا پوشهٔ اجرا در بک‌اند محلی وقتی cwd: "." است) شروع می‌شوند.

آرگومانتوضیح
<name>پروفایلی که باید بازرسی شود.

مثال:

$ hermes profile show work
Profile: work
Path:    ~/.hermes/profiles/work
Model:   anthropic/claude-sonnet-4 (anthropic)
Gateway: stopped
Skills:  12
.env:    exists
SOUL.md: exists
Alias:   ~/.local/bin/work

۸ hermes profile alias

hermes profile alias <name> [options]

اسکریپت الیاس شل در ~/.local/bin/<name> را دوباره تولید می‌کند. وقتی الیاس به‌اشتباه حذف شده یا بعد از جابه‌جایی نصب Hermes باید به‌روزرسانی‌اش کنید کاربرد دارد.

آرگومان / گزینهتوضیح
<name>پروفایلی که الیاسش باید ساخته/به‌روزرسانی شود.
--removeبه‌جای ساخت اسکریپت wrapper، آن را حذف می‌کند.
--name <alias>نام سفارشی الیاس (پیش‌فرض: نام پروفایل).

مثال:

hermes profile alias work
# ساخت/به‌روزرسانی ~/.local/bin/work

hermes profile alias work --name mywork
# ساخت ~/.local/bin/mywork

hermes profile alias work --remove
# حذف اسکریپت wrapper

۹ hermes profile rename

hermes profile rename <old-name> <new-name>

نام یک پروفایل را تغییر می‌دهد. پوشه و الیاس شل را به‌روزرسانی می‌کند.

آرگومانتوضیح
<old-name>نام فعلی پروفایل.
<new-name>نام جدید پروفایل.

مثال:

hermes profile rename mybot assistant
# ~/.hermes/profiles/mybot → ~/.hermes/profiles/assistant
# ~/.local/bin/mybot → ~/.local/bin/assistant

۱۰ hermes profile export

hermes profile export <name> [options]

پروفایل را به‌صورت یک آرشیو فشردهٔ tar.gz خروجی می‌گیرد — اسنپ‌شاتی قابل‌حمل که می‌توانید از آن پشتیبان بگیرید، به ماشین دیگری ببرید یا به کسی بدهید. ‏auth.json و .env همیشه مستثنا هستند.

در گفتگو هم به‌صورت /export و هم در اپ دسکتاپ از طریق ⌘K → Export profile… یا منوی راست‌کلیکِ مربع پروفایل در دسترس است. خروجی دسکتاپ علاوه بر آن، ‏desktop.json (اسکین، حالت روشن/تاریک، تم‌های سفارشی، رنگ ریل، چیدمان پنجره) را هم در آرشیو می‌گذارد.

آرگومان / گزینهتوضیح
<name>پروفایلی که باید خروجی گرفته شود.
-o، ‏--output <path>مسیر فایل خروجی (پیش‌فرض: <name>.tar.gz).

مثال:

hermes profile export work
# ساخت work.tar.gz در پوشهٔ فعلی

hermes profile export work -o ./work-2026-03-29.tar.gz

برای اینکه دقیقاً چه چیزهایی در آرشیو می‌افتد و قبل از فرستادن آن به کسی چه چیزهایی را باید بررسی کنید، خروجی و واردکردن فایل پروفایل را ببینید.

۱۱ hermes profile import

hermes profile import <archive> [options]

پروفایلی را از یک آرشیو tar.gz به‌عنوان یک پروفایل جدید وارد می‌کند. از بازنویسی پروفایل موجود خودداری می‌کند و نمی‌تواند به‌صورت default (پروفایل ریشهٔ داخلی) وارد شود — در هر دو حالت --name را بدهید. وقتی نام با یک فرمان موجود تصادم نداشته باشد، یک wrapper شل ساخته می‌شود.

در گفتگو هم به‌صورت /import و هم در اپ دسکتاپ از طریق ⌘K → Import profile… یا دکمهٔ واردکردن کنار + ریل پروفایل‌ها در دسترس است. واردکردن دسکتاپ هر desktop.json همراه‌شده (تم، چیدمان) را هم اعمال می‌کند و شما را به پروفایل جدید می‌برد.

آرگومان / گزینهتوضیح
<archive>مسیر آرشیو tar.gz برای واردکردن.
--name <name>نام پروفایل واردشده (پیش‌فرض: استنتاج از آرشیو).

مثال:

hermes profile import ./work-2026-03-29.tar.gz
# استنتاج نام پروفایل از آرشیو

hermes profile import ./work-2026-03-29.tar.gz --name work-restored

۱۲ فرمان‌های توزیع

💡 نکته

با توزیع‌ها آشنا نیستید؟ با راهنمای کاربری توزیع‌های پروفایل شروع کنید — چرایی، زمان و چگونگی را با مثال‌های کامل پوشش می‌دهد. بخش‌های زیر یک مرجع خشک CLI‌اند برای وقتی که می‌دانید چه می‌خواهید.

توزیع‌ها یک پروفایل را به مصنوعی قابل‌اشتراک و نسخه‌دار تبدیل می‌کنند که به‌شکل مخزن گیت منتشر می‌شود. گیرنده توزیع را با یک فرمان نصب می‌کند و بعداً می‌تواند بدون دست زدن به حافظه‌ها، نشست‌ها یا اعتبارنامه‌های محلی‌اش، آن را در‌جا به‌روزرسانی کند.

‏auth.json و .env هرگز جزء توزیع نیستند — روی ماشین کاربرِ نصب‌کننده باقی می‌مانند.

داده‌های کاربری گیرنده (حافظه‌ها، نشست‌ها، احراز هویت، ویرایش‌های خودش روی .env) همیشه در طول نصب اولیه و به‌روزرسانی‌های بعدی حفظ می‌شود.

ℹ️ توجه

دو راه برای اشتراک‌گذاری پروفایل وجود دارد و مکمل یکدیگرند. ‏hermes profile export / import (و در گفتگو هم /export و /import) یک فایل تکی تولید می‌کنند — بدون مخزن، بدون مانیفست، و خروجی دسکتاپ تم و چیدمان شما را هم حمل می‌کند. توزیع (install / update / info) پروفایل را به‌شکل مخزن گیت منتشر می‌کند تا گیرندگان بعداً به‌روزرسانی‌های نسخه‌دار را بگیرند. کار دیگر فایل خروجی، پشتیبان‌گیری و بازیابی است. دو راه اشتراک‌گذاری پروفایل را ببینید.

hermes profile install

hermes profile install <source> [--name <name>] [--alias] [--force] [--yes]

یک توزیع پروفایل را از URL گیت یا یک پوشهٔ محلی نصب می‌کند.

گزینهتوضیح
<source>URL گیت (github.com/user/repo، ‏https://...، ‏git@...، ‏ssh://، ‏git://) یا پوشهٔ محلی‌ای که distribution.yaml در ریشهٔ آن باشد.
--name NAMEنام پروفایل را نسبت به مانیفست بازنویسی می‌کند.
--aliasعلاوه بر آن یک wrapper شل هم می‌سازد (مثلاً telemetry ← hermes -p telemetry).
--forceپروفایل هم‌نام موجود را بازنویسی می‌کند. داده‌های کاربر همچنان حفظ می‌شوند.
-y، ‏--yesاز پرسش تأییدِ پیش‌نمایش مانیفست می‌پرد.

نصب‌کننده مانیفست را نشان می‌دهد، متغیرهای محیطی موردنیاز را فهرست می‌کند و پیش از گرفتن تأیید، دربارهٔ کارهای کرون هشدار می‌دهد. متغیرهای محیطی الزامی در فایلی به‌نام .env.EXAMPLE می‌روند که آن را به .env کپی و پر می‌کنید.

مثال‌ها:

# نصب از یک مخزن GitHub (شکل کوتاه)
hermes profile install github.com/kyle/telemetry-distribution --alias

# نصب از یک URL کامل HTTPS گیت
hermes profile install https://github.com/kyle/telemetry-distribution.git

# نصب از SSH
hermes profile install git@github.com:kyle/telemetry-distribution.git

# نصب از پوشهٔ محلی در حین توسعه
hermes profile install ./telemetry/

hermes profile update

hermes profile update <name> [--force-config] [--yes]

توزیع را از منبع ثبت‌شده‌اش دوباره کلون می‌کند و به‌روزرسانی‌ها را اعمال می‌کند. فایل‌های متعلق به توزیع (‏SOUL.md، ‏skills/، ‏cron/، ‏mcp.json) بازنویسی می‌شوند؛ داده‌های کاربر (حافظه‌ها، نشست‌ها، احراز هویت، ‏.env) هرگز دست نمی‌خورند.

‏config.yaml به‌طور پیش‌فرض حفظ می‌شود تا بازنویسی‌های محلی شما بماند. برای ریست‌کردن آن به پیکربندیِ ارسالی توزیع، --force-config را بدهید.

hermes profile info

hermes profile info <name>

مانیفست توزیع پروفایل را چاپ می‌کند — نام، نسخه، نسخهٔ الزامی Hermes، نویسنده، الزامات متغیرهای محیطی، URL/مسیر منبع و مهر زمانیِ Installed: که در آخرین install یا update ثبت شده است. برای بررسی اینکه یک پروفایل اشتراکی قبل از نصب به چه چیزی نیاز دارد کاربرد دارد، و برای پیدا کردن مواردی مثل «این پروفایل ۶ ماه پیش نصب شده و از آن زمان به‌روزرسانی نشده».

‏hermes profile list هم نام و نسخهٔ توزیع را در یک ستون Distribution نشان می‌دهد و hermes profile show <name> / delete <name> هم URL منبع را نمایش می‌دهند تا یک‌نگاهی بفهمید کدام پروفایل‌ها از مخزن گیت آمده‌اند و کدام‌ها محلی ساخته شده‌اند.

توزیع‌های خصوصی

یک مخزن گیت خصوصی بدون هیچ پیکربندی اضافه‌ای به‌عنوان منبع توزیع کار می‌کند — نصب، کار git عادی شما را صدا می‌زند، پس هر احراز هویتی که شل شما از قبل برایش تنظیم است (کلید SSH، helper مربوط به git credential، اعتبارنامه‌های HTTPS ذخیره‌شدهٔ GitHub CLI) شفاف اعمال می‌شود.

# از کلید SSH شما استفاده می‌کند، مثل هر git clone دیگری
hermes profile install git@github.com:your-org/internal-assistant.git

# از git credential helper شما استفاده می‌کند
hermes profile install https://github.com/your-org/internal-assistant.git

اگر در حین نصب، عمل کلون در ترمینال شما به‌صورت تعاملی اعتبارنامه بخواهد، همان پرسش به داخل عبور می‌کند. اول احراز هویت‌تان را همان‌طور که معمولاً برای git clone روی همان مخزن استفاده می‌کنید راه بیندازید، بعد نصب کنید.

مانیفست توزیع (distribution.yaml)

هر توزیع یک distribution.yaml در ریشهٔ مخزن خودش دارد:

name: telemetry
version: 0.1.0
description: "Compliance monitoring harness"
hermes_requires: ">=0.12.0"
author: "Your Name"
license: "MIT"
env_requires:
  - name: OPENAI_API_KEY
    description: "OpenAI API key"
    required: true
  - name: GRAPHITI_MCP_URL
    description: "Memory graph URL"
    required: false
    default: "http://127.0.0.1:8000/sse"
distribution_owned:   # اختیاری؛ پیش‌فرض‌ها: SOUL.md، config.yaml،
                      #   mcp.json، skills/، cron/، distribution.yaml
  - SOUL.md
  - skills/compliance/
  - cron/

‏hermes_requires از >=، ‏<=، ‏==، ‏!=، ‏>، ‏< یا یک نسخهٔ لخت (که >= فرض می‌شود) پشتیبانی می‌کند. اگر نسخهٔ فعلی Hermes معیار را ارضا نکند، نصب با یک خطای واضح شکست می‌خورد.

‏distribution_owned اختیاری است. اگر تنظیم شود، فقط همان مسیرها در به‌روزرسانی جایگزین می‌شوند؛ هر چیز دیگری در پروفایل متعلق به کاربر می‌ماند. اگر حذف شود، پیش‌فرض‌های بالا اعمال می‌شوند.

انتشار یک توزیع

ساختن یک توزیع فقط یک git push است:

  1. در پوشهٔ پروفایل‌تان، یک distribution.yaml با دست‌کم name و version بسازید.
  2. یک مخزن گیت مقداردهی اولیه کنید (یا از مخزن موجود استفاده کنید) و به GitHub / GitLab / هر میزبانی که Hermes بتواند از آن کلون کند push بزنید.
  3. به گیرندگان بگویید hermes profile install <your-repo-url> را اجرا کنند.

برای انتشارهای نسخه‌دار از تگ‌های گیت استفاده کنید — گیرندگانی که HEAD را کلون می‌کنند آخرین وضعیت شما را می‌گیرند و شما همیشه می‌توانید version: را در مانیفست بالا ببرید.

۱۳ hermes -p / hermes --profile

hermes -p <name> <command> [options]
hermes --profile <name> <command> [options]

فلگ سراسری برای اجرای هر فرمان Hermes تحت یک پروفایل مشخص، بدون تغییر پیش‌فرض چسبنده. این فلگ پروفایل فعال را فقط برای طول همان فرمان بازنویسی می‌کند.

گزینهتوضیح
-p <name>، ‏--profile <name>پروفایلی که برای این فرمان استفاده می‌شود.

مثال‌ها:

hermes -p work chat -q "Check the server status"
hermes --profile dev gateway start
hermes -p personal skills list
hermes -p work config edit

۱۴ hermes completion

hermes completion <shell>

اسکریپت‌های تکمیل خودکار شل تولید می‌کند. شامل تکمیل نام پروفایل‌ها و زیرفرمان‌های پروفایل هم هست.

آرگومانتوضیح
<shell>شلی که تکمیل خودکار برایش تولید می‌شود: bash، ‏zsh یا fish.

مثال‌ها:

# نصب تکمیل خودکار
hermes completion bash >> ~/.bashrc
hermes completion zsh >> ~/.zshrc
hermes completion fish > ~/.config/fish/completions/hermes.fish

# بارگذاری دوباره شل
source ~/.bashrc

بعد از نصب، تکمیل با Tab برای این‌ها کار می‌کند:

  • hermes profile <TAB> — زیرفرمان‌ها (‏list، ‏use، ‏create و غیره)
  • hermes profile use <TAB> — نام پروفایل‌ها
  • hermes -p <TAB> — نام پروفایل‌ها
