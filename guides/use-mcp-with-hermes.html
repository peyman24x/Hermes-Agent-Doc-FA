استفاده از MCP با هرمس

این راهنما نشان می‌دهد چطور در گردش‌کارهای روزمره واقعاً از MCP با Hermes Agent استفاده کنید.

اگر صفحهٔ قابلیت توضیح می‌دهد که MCP چیست، این راهنما دربارهٔ این است که چطور سریع و ایمن از آن بهره ببرید.

۱ چه زمانی از MCP استفاده کنیم؟

از MCP استفاده کنید وقتی که:

  • ابزاری از قبل به شکل MCP وجود دارد و نمی‌خواهید یک ابزار بومی هرمس بسازید
  • می‌خواهید هرمس از طریق یک لایهٔ RPC تمیز روی یک سیستم محلی یا راه‌دور کار کند
  • کنترل ریزدانهٔ دسترسی برای هر سرور می‌خواهید
  • می‌خواهید بدون دست‌کاری هستهٔ هرمس، هرمس را به APIهای داخلی، پایگاه‌های داده یا سیستم‌های شرکت وصل کنید

از MCP استفاده نکنید وقتی که:

  • یک ابزار داخلی هرمس از قبل کار را خوب انجام می‌دهد
  • سرور سطح ابزاری عظیم و خطرناکی در دسترس می‌گذارد و برای فیلترکردنش آماده نیستید
  • فقط به یک یکپارچگی خیلی محدود نیاز دارید و یک ابزار بومی ساده‌تر و امن‌تر خواهد بود

۲ مدل ذهنی

MCP را یک لایهٔ آداپتور تصور کنید:

  • هرمس همان ایجنت می‌ماند
  • سرورهای MCP ابزار تأمین می‌کنند
  • هرمس آن ابزارها را در زمان شروع یا بارگذاری مجدد کشف می‌کند
  • مدل می‌تواند مثل ابزارهای عادی از آن‌ها استفاده کند
  • شما کنترل می‌کنید چه مقدار از هر سرور دیده شود

همان بخش آخر مهم است. استفادهٔ خوب از MCP فقط «وصل‌کردن همه‌چیز» نیست؛ «وصل‌کردن چیز درست، با کوچک‌ترین سطحِ مفید» است.

۳ گام ۱: نصب پشتیبانی MCP

اگر هرمس را با اسکریپت نصب استاندارد نصب کرده‌اید، پشتیبانی MCP از قبل شامل شده است (نصب‌کننده uv pip install -e ".[all]" را اجرا می‌کند).

اگر بدون اکستراها نصب کرده‌اید و باید MCP را جداگانه اضافه کنید:

cd ~/.hermes/hermes-agent
uv pip install -e ".[mcp]"

برای سرورهای مبتنی بر npm، مطمئن شوید Node.js و npx در دسترس‌اند.

برای بسیاری از سرورهای MCP پایتون، uvx پیش‌فرض خوبی است.

۴ گام ۲: اول یک سرور اضافه کنید

با یک سرورِ تنها و امن شروع کنید.

مثال: دسترسی فایل‌سیستم فقط به یک پوشهٔ پروژه.

mcp_servers:
  project_fs:
    command: "npx"
    args: ["-y", "@modelcontextprotocol/server-filesystem", "/home/user/my-project"]

بعد هرمس را اجرا کنید:

hermes chat

حالا چیزی مشخص بپرسید:

Inspect this project and summarize the repo layout.

۵ گام ۳: تأیید بارگذاری MCP

چند راه برای تأیید MCP دارید:

  • بنر/وضعیت هرمس وقتی پیکربندی شده باشد باید یکپارچگی MCP را نشان دهد
  • از هرمس بپرسید چه ابزارهایی در دسترس دارد
  • بعد از تغییر پیکربندی از /reload-mcp استفاده کنید
  • اگر سرور وصل نشد لاگ‌ها را چک کنید

یک پرامپت آزمایشیِ عملی:

Tell me which MCP-backed tools are available right now.

۶ گام ۴: بلافاصله فیلترکردن را شروع کنید

اگر سرور ابزارهای زیادی در دسترس می‌گذارد، کار را به بعد موکول نکنید.

مثال: فقط آنچه را می‌خواهید فهرست مجاز کنید

mcp_servers:
  github:
    command: "npx"
    args: ["-y", "@modelcontextprotocol/server-github"]
    env:
      GITHUB_PERSONAL_ACCESS_TOKEN: "***"
    tools:
      include: [list_issues, create_issue, search_code]

این معمولاً بهترین پیش‌فرض برای سیستم‌های حساس است.

۷ WSL2: پل‌زدن هرمس در WSL به Chrome ویندوز

این راه‌اندازی عملی است وقتی که:

  • هرمس داخل WSL2 اجرا می‌شود
  • مرورگری که می‌خواهید کنترل کنید همان Chrome عادی و واردشدهٔ شما روی ویندوز است
  • /browser connect از WSL دشوار یا ناپایدار است

در این راه‌اندازی هرمس مستقیم به Chrome وصل نمی‌شود. به‌جای آن:

  • هرمس در WSL اجرا می‌شود
  • هرمس یک سرور MCP محلیِ stdio راه می‌اندازد
  • آن سرور MCP از طریق interop ویندوز (cmd.exe یا powershell.exe) راه‌اندازی می‌شود
  • سرور MCP به نشست زندهٔ Chrome ویندوز شما وصل می‌شود

مدل ذهنی:

Hermes (WSL) -> MCP stdio bridge -> Windows Chrome

چرا این حالت مفید است

  • پروفایل واقعی مرورگر ویندوز، کوکی‌ها و ورودهایتان را نگه می‌دارید
  • هرمس در محیط یونیکسِ پشتیبانی‌شدهٔ خودش (WSL2) می‌ماند
  • کنترل مرورگر به‌شکل ابزارهای MCP در دسترس قرار می‌گیرد، به‌جای اتکا به انتقال مرورگرِ هستهٔ هرمس

سرور پیشنهادی

از chrome-devtools-mcp استفاده کنید.

اگر Chrome ویندوزتان از قبل دیباگ زندهٔ راه‌دور را از chrome://inspect/#remote-debugging فعال کرده، از WSL این‌طور اضافه‌اش کنید:

hermes mcp add chrome-devtools-win --command cmd.exe --args /c npx -y chrome-devtools-mcp@latest --autoConnect --no-usage-statistics

بعد از ذخیرهٔ سرور:

hermes mcp test chrome-devtools-win

سپس یک نشست تازهٔ هرمس شروع کنید یا اجرا کنید:

/reload-mcp

پرامپت نمونه

بعد از بارگذاری، هرمس می‌تواند مستقیم از ابزارهای مرورگر با پیشوند MCP استفاده کند. مثلاً:

调用 MCP 工具 mcp_chrome_devtools_win_list_pages，列出当前浏览器标签页。

کجا /browser connect ابزار اشتباهی است

اگر هرمس در WSL اجرا شود و Chrome روی ویندوز، /browser connect ممکن است شکست بخورد حتی وقتی Chrome باز و قابل دیباگ است.

دلایل رایج:

  • WSL نمی‌تواند به همان نقطهٔ پایانیِ محلی-میزبانی که Chrome برای ابزارهای ویندوز در دسترس می‌گذارد برسد
  • گردش‌کارهای دیباگ زندهٔ جدیدتر Chrome با ws://localhost:9222 کلاسیک یکی نیستند
  • اتصال به مرورگر از یک کمک‌کنندهٔ سمت ویندوز مثل chrome-devtools-mcp راحت‌تر است

در این موارد، /browser connect را برای راه‌اندازی‌های هم‌محیط نگه دارید و برای پل‌زدن مرورگر از WSL به ویندوز از MCP استفاده کنید.

دام‌های شناخته‌شده

  • وقتی از طریق MCP اجرایی‌های stdio ویندوز را به‌کار می‌برید، هرمس را از یک مسیر سوارشدهٔ ویندوز مثل /mnt/c/Users/<you> یا /mnt/c/workspace/... اجرا کنید.
  • اگر هرمس را از /root یا /home/... اجرا کنید، ویندوز ممکن است قبل از شروع سرور MCP هشدار پوشهٔ جاریِ UNC بدهد.
  • اگر chrome-devtools-mcp --autoConnect هنگام فهرست‌کردن صفحه‌ها تایم‌اوت شد، تب‌های پس‌زمینه/منجمد Chrome را کم کنید و دوباره تلاش کنید.

مثال: فهرست سیاهِ اقدام‌های خطرناک

mcp_servers:
  stripe:
    url: "https://mcp.stripe.com"
    headers:
      Authorization: "Bearer ***"
    tools:
      exclude: [delete_customer, refund_payment]

مثال: غیرفعال‌کردن رپرهای ابزاری هم

mcp_servers:
  docs:
    url: "https://mcp.docs.example.com"
    tools:
      prompts: false
      resources: false

۸ فیلترکردن واقعاً روی چه چیزی اثر می‌گذارد؟

در هرمس دو دسته عملکردِ در-دسترس-گذاشته‌شده از MCP وجود دارد:

  1. ابزارهای MCP بومیِ سرور
    • فیلتر با:
      • tools.include
      • tools.exclude
  2. رپرهای ابزاریِ افزودهٔ هرمس
    • فیلتر با:
      • tools.resources
      • tools.prompts

رپرهای ابزاری که ممکن است ببینید

منابع (Resources):

  • list_resources
  • read_resource

پرامپت‌ها (Prompts):

  • list_prompts
  • get_prompt

این رپرها فقط وقتی ظاهر می‌شوند که:

  • پیکربندی‌تان اجازه‌شان بدهد، و
  • نشست سرور MCP واقعاً آن قابلیت‌ها را پشتیبانی کند

پس هرمس وانمود نمی‌کند سروری منبع/پرامپت دارد وقتی ندارد.

۹ الگوهای رایج

الگو ۱: دستیار پروژهٔ محلی

وقتی می‌خواهید هرمس روی یک فضای کاری محدود استدلال کند، از MCP برای یک سرور فایل‌سیستم یا گیتِ محلیِ مخزن استفاده کنید.

mcp_servers:
  fs:
    command: "npx"
    args: ["-y", "@modelcontextprotocol/server-filesystem", "/home/user/project"]

  git:
    command: "uvx"
    args: ["mcp-server-git", "--repository", "/home/user/project"]

پرامپت‌های خوب:

Review the project structure and identify where configuration lives.
Check the local git state and summarize what changed recently.

الگو ۲: سابقهٔ کار بومیِ مخزن با Open Scaffold

وقتی می‌خواهید هرمس سابقهٔ پایدارِ کارِ هوش مصنوعی یک مخزن را بخواند — مأموریت، برنامه‌ها، یادداشت‌های شواهد، بسته‌های تحویل دست‌به‌دست و نتایج بازبینی/دروازه — از Open Scaffold استفاده کنید. هرمس همان ایجنت می‌ماند؛ Open Scaffold همان سابقهٔ محلیِ مخزن می‌ماند.

سرور را برای یک مخزنِ اسکافولدشده اضافه کنید:

hermes mcp add open_scaffold --command npx --args -y open-scaffold@latest mcp serve --repo /absolute/path/to/repo
hermes mcp test open_scaffold

سپس سطحِ در دسترس‌گذاشته‌شده را خواندنی‌محور نگه دارید. در پرامپتِ hermes mcp add گزینهٔ select را انتخاب کنید یا بعداً config.yaml را ویرایش کنید:

mcp_servers:
  open_scaffold:
    command: "npx"
    args: ["-y", "open-scaffold@latest", "mcp", "serve", "--repo", "/absolute/path/to/repo"]
    tools:
      include:
        - list_plans
        - get_plan
        - get_mission
        - list_evidence
        - get_evidence
        - get_status
        - search_plans
        - list_amendments
        - get_handoff
        - analyze_loop
        - gate_loop
      prompts: false

پرامپت‌های خوب:

Use the Open Scaffold MCP tools to compile the current handoff packet and tell me the next legal action.
Inspect the active plans and evidence notes, then say whether this repo is ready for human review or needs another attempt.

نکات مرزی:

  • MCP اسکافولد باز محلی‌محور است و به‌صورت پیش‌فرض فقط‌خواندنی.
  • ابزارهای نوشتن آن نیاز دارند سرور با --allow-write شروع شود؛ تا وقتی صریحاً نمی‌خواهید هرمس فایل‌های .osc را تغییر بدهد آن را فعال نکنید.
  • Open Scaffold کارها را ثبت و دروازه‌بندی می‌کند؛ به هرمس اجازهٔ merge، انتشار، استقرار یا راه‌انداختن رانتایم نمی‌دهد.
  • اگر به اسکیماهای ابزارِ تکرارپذیر نیاز دارید، open-scaffold@<version> را به‌جای @latest پین کنید.

الگو ۳: دستیار غربالگری گیت‌هاب

mcp_servers:
  github:
    command: "npx"
    args: ["-y", "@modelcontextprotocol/server-github"]
    env:
      GITHUB_PERSONAL_ACCESS_TOKEN: "***"
    tools:
      include: [list_issues, create_issue, update_issue, search_code]
      prompts: false
      resources: false

پرامپت‌های خوب:

List open issues about MCP, cluster them by theme, and draft a high-quality issue for the most common bug.
Search the repo for uses of _discover_and_register_server and explain how MCP tools are registered.

الگو ۴: دستیار API داخلی

mcp_servers:
  internal_api:
    url: "https://mcp.internal.example.com"
    headers:
      Authorization: "Bearer ***"
    tools:
      include: [list_customers, get_customer, list_invoices]
      resources: false
      prompts: false

پرامپت‌های خوب:

Look up customer ACME Corp and summarize recent invoice activity.

این دقیقاً از جاهایی است که یک فهرست مجاز سخت‌گیرانه خیلی بهتر از یک فهرست استثناست.

الگو ۴: سرورهای مستندات / دانش

بعضی سرورهای MCP پرامپت‌ها یا منابعی در دسترس می‌گذارند که بیشتر شبیه دارایی‌های دانشِ مشترک‌اند تا اقدام مستقیم.

mcp_servers:
  docs:
    url: "https://mcp.docs.example.com"
    tools:
      prompts: true
      resources: true

پرامپت‌های خوب:

List available MCP resources from the docs server, then read the onboarding guide and summarize it.
List prompts exposed by the docs server and tell me which ones would help with incident response.

۱۰ آموزش: راه‌اندازی سرتاسری با فیلترکردن

این هم یک توالی عملی.

فاز ۱: افزودن MCP گیت‌هاب با فهرست مجاز سخت‌گیرانه

mcp_servers:
  github:
    command: "npx"
    args: ["-y", "@modelcontextprotocol/server-github"]
    env:
      GITHUB_PERSONAL_ACCESS_TOKEN: "***"
    tools:
      include: [list_issues, create_issue, search_code]
      prompts: false
      resources: false

هرمس را اجرا کنید و بپرسید:

Search the codebase for references to MCP and summarize the main integration points.

فاز ۲: فقط وقتی لازم شد گسترش دهید

اگر بعداً به‌روزرسانی ایشو هم لازم شد:

tools:
  include: [list_issues, create_issue, update_issue, search_code]

بعد بارگذاری مجدد کنید:

/reload-mcp

فاز ۳: افزودن سرور دوم با سیاست متفاوت

mcp_servers:
  github:
    command: "npx"
    args: ["-y", "@modelcontextprotocol/server-github"]
    env:
      GITHUB_PERSONAL_ACCESS_TOKEN: "***"
    tools:
      include: [list_issues, create_issue, update_issue, search_code]
      prompts: false
      resources: false

  filesystem:
    command: "npx"
    args: ["-y", "@modelcontextprotocol/server-filesystem", "/home/user/project"]

حالا هرمس می‌تواند آن‌ها را ترکیب کند:

Inspect the local project files, then create a GitHub issue summarizing the bug you find.

اینجاست که MCP قدرتمند می‌شود: گردش‌کارهای چندسیستمی بدون تغییر هستهٔ هرمس.

۱۱ توصیه‌های استفادهٔ ایمن

برای سیستم‌های خطرناک فهرست مجاز را ترجیح دهید

برای هر چیزی که مالی است، روبه‌روی مشتری است یا مخرب:

  • از tools.include استفاده کنید
  • با کوچک‌ترین مجموعهٔ ممکن شروع کنید

ابزارهای کمکی بلااستفاده را غیرفعال کنید

اگر نمی‌خواهید مدل منابع/پرامپت‌های فراهم‌شدهٔ سرور را بگردد، خاموششان کنید:

tools:
  resources: false
  prompts: false

دامنهٔ سرورها را باریک نگه دارید

مثال‌ها:

  • سرور فایل‌سیستم ریشه‌دار روی یک پوشهٔ پروژه، نه کل پوشهٔ خانهٔ شما
  • سرور گیت اشاره‌کننده به یک مخزن
  • سرور API داخلی با دسترسی ابزاریِ عمدتاً خواندنی به‌صورت پیش‌فرض

بعد از تغییر پیکربندی بارگذاری مجدد کنید

/reload-mcp

این کار را بعد از تغییر این‌ها انجام دهید:

  • لیست‌های include/exclude
  • پرچم‌های enabled
  • کلیدهای resources/prompts
  • هدرهای احراز هویت / متغیرهای محیطی

۱۲ عیب‌یابی بر اساس علامت

«سرور وصل می‌شود ولی ابزارهایی که انتظار داشتم غایب‌اند»

علت‌های ممکن:

  • فیلترشده توسط tools.include
  • مستثنا شده توسط tools.exclude
  • رپرهای ابزاری با resources: false یا prompts: false غیرفعال شده‌اند
  • سرور واقعاً از منابع/پرامپت‌ها پشتیبانی نمی‌کند

«سرور پیکربندی شده ولی چیزی بارگذاری نمی‌شود»

چک کنید:

  • enabled: false در پیکربندی جا نمانده باشد
  • فرمان/ران‌تایم موجود باشد (npx، uvx و...)
  • نقطهٔ پایانی HTTP در دسترس باشد
  • متغیر محیطی احراز هویت یا هدرها درست باشند

«چرا ابزارهای کمتری از آنچه سرور MCP اعلام می‌کند می‌بینم؟»

چون هرمس حالا به سیاست هر-سروری شما و ثبتِ آگاه-از-قابلیت احترام می‌گذارد. این مورد انتظار است و معمولاً مطلوب.

«چطور یک سرور MCP را بدون حذف پیکربندی بردارم؟»

از این استفاده کنید:

enabled: false

این پیکربندی را نگه می‌دارد ولی جلوی اتصال و ثبت را می‌گیرد.

۱۳ راه‌اندازی‌های اولیهٔ MCP پیشنهادی

سرورهای خوب برای شروع، برای بیشتر کاربران:

  • فایل‌سیستم
  • گیت
  • GitHub
  • سرورهای MCP واکشی / مستندات
  • یک API داخلیِ باریک
