MiniMax OAuth

‏Hermes Agent از MiniMax از طریق جریان ورود OAuth مرورگری پشتیبانی می‌کند، با همان credential های پرتال MiniMax. نه کلید API لازم است نه کارت بانکی — یک بار وارد شوید و هرمس نشست تان را خودکار refresh می‌کند.

ترنسپورت از آداپتور anthropic_messages بازمصرف می‌کند ‏(‏MiniMax نقطهٔ پایانی سازگار-با-Anthropic-Messages روی ‎/anthropic‎ expose می‌کند)، پس همهٔ قابلیت‌های موجود فراخوانی ابزار، استریم و زمینه بدون هیچ تغییری در آداپتور کار می‌کنند.

# → Hermes opens your browser to the MiniMax authorization page
# → Approve access in the browser

hermes

بعد از اولین ورود، credential ها زیر ~/.hermes/auth.json ذخیره می‌شوند و قبل از هر نشست خودکار refresh می‌شوند.

ورود دستی

می‌توانید بدون گذر از انتخاب‌گر مدل هم ورود را فعال کنید:

hermes auth add minimax-oauth

منطقهٔ چین

اگر حسابتان روی پلتفرم چین است ‏(minimaxi.com)، به‌جایش از ارائه‌دهندهٔ مبتنی-بر-کلید-API ی minimax-cn استفاده کنید — ‏minimax-cn فقط با auth_type="api_key" ثبت شده ‏(بدون جریان OAuth). مقدار MINIMAX_CN_API_KEY ‏(و اختیاری MINIMAX_CN_BASE_URL) را مستقیم ست کنید:

echo 'MINIMAX_CN_API_KEY=your-key' >> ~/.hermes/.env

نشست‌های راه‌دور / بدون‌سر

روی سرورها یا کانتینرهایی که مرورگر ندارند:

hermes auth add minimax-oauth --no-browser

هرمس URL تأیید و کد کاربر را چاپ می‌کند — URL را روی هر دستگاهی باز کنید و کد را موقع پرسیدن وارد کنید.

۳ جریان OAuth

هرمس یک جریان OAuth مرورگری PKCE روی نقاط پایانی OAuth ی MiniMax پیاده می‌کند:

  1. هرمس جفت verifier/challenge ی PKCE و یک مقدار state تصادفی تولید می‌کند.
  2. به {base_url}/oauth/code با challenge درخواست POST می‌زند و user_code و verification_uri می‌گیرد.
  3. مرورگر شما verification_uri را باز می‌کند. اگر خواست، user_code را وارد کنید.
  4. هرمس تا رسیدن توکن ‏(یا گذشت مهلت) {base_url}/oauth/token را poll می‌کند.
  5. توکن‌ها ‏(access_token، ‏refresh_token، انقضا) زیر کلید minimax-oauth در ~/.hermes/auth.json ذخیره می‌شوند.

refresh توکن ‏(grant استاندارد refresh_token ی OAuth) در شروع هر نشست خودکار اجرا می‌شود وقتی access token کمتر از ۶۰ ثانیه تا انقضا دارد.

یا مستقیم مدل را ست کنید:

hermes config set model.default MiniMax-M2.7
hermes config set model.provider minimax-oauth

۵ مرجع پیکربندی

بعد از ورود، ~/.hermes/config.yaml مدخل‌هایی شبیه این خواهد داشت:

model:
  default: MiniMax-M2.7
  provider: minimax-oauth
  base_url: https://api.minimax.io/anthropic

نام‌های مستعار ارائه‌دهنده

همهٔ موارد زیر به minimax-oauth حل می‌شوند:

hermes --provider minimax-oauth    # canonical
hermes --provider minimax-portal   # alias
hermes --provider minimax-global   # alias
hermes --provider minimax_oauth    # alias (underscore form)

۶ متغیرهای محیطی

ارائه‌دهندهٔ minimax-oauth از MINIMAX_API_KEY یا MINIMAX_BASE_URL استفاده نمی‌کند. آن متغیرها فقط برای ارائه‌دهندگان مبتنی-بر-کلید-API ی minimax و minimax-cn هستند.

متغیراثر
MINIMAX_API_KEYفقط توسط ارائه‌دهندهٔ minimax استفاده می‌شود — برای minimax-oauth نادیده گرفته می‌شود
MINIMAX_CN_API_KEYفقط توسط ارائه‌دهندهٔ minimax-cn استفاده می‌شود — برای minimax-oauth نادیده گرفته می‌شود

برای فعال بودن minimax-oauth به‌عنوان ارائه‌دهنده، model.provider: minimax-oauth را در config.yaml ست کنید ‏(برای جریان هدایت‌شده hermes setup) یا برای یک فراخوانی ‎--provider minimax-oauth‎ بدهید:

hermes --provider minimax-oauth

۷ مدل‌ها

مدلبهترین برای
MiniMax-M2.7استدلال زمینه‌بلند، فراخوانی ابزار پیچیده
MiniMax-M2.7-highspeedتأخیر کمتر، کارهای سبک‌تر، فراخوانی‌های کمکی

هر دو مدل تا ۲۰۰٬۰۰۰ توکن زمینه را پشتیبانی می‌کنند.

وقتی minimax-oauth ارائه‌دهندهٔ اصلی باشد، مدل MiniMax-M2.7 به‌طور خودکار به‌عنوان مدل کمکی برای کارهای بینایی و واگذاری هم استفاده می‌شود.

۸ عیب‌یابی

توکن منقضی شد — دوباره خودکار وارد نمی‌شود

هرمس اگر توکن کمتر از ۶۰ ثانیه تا انقضا داشته باشد در شروع هر نشست آن را refresh می‌کند. اگر access token قبلاً منقضی شده باشد ‏(مثلاً بعد از یک دورهٔ طولانی آفلاین)، refresh خودکار در درخواست بعدی اتفاق می‌افتد. اگر refresh با refresh_token_reused یا invalid_grant شکست بخورد، هرمس نشست را نیازمند ورود مجدد علامت می‌زند.

وقتی شکست refresh پایانی باشد ‏(HTTP 4xx، ‏invalid_grant، لغو grant و...)، هرمس refresh token را مرده علامت و محلیاً قرنطینه می‌کند تا تبادل محکوم‌به‌شکست را مدام تکرار نکند. ایجنت یک پیام «re-authentication required» نشان می‌دهد و تا وقتی دوباره وارد نشوید مزاحم نیست.

راه حل:hermes auth add minimax-oauth را دوباره اجرا کنید تا ورود تازه شروع شود. قرنطینه در اولین تبادل موفق پاک می‌شود.

احراز هویت تایم‌اوت شد

جریان کد دستگاه پنجرهٔ انقضای متناهی دارد. اگر به‌موقع تأیید نکنید هرمس خطای timeout می‌دهد.

راه حل:hermes auth add minimax-oauth ‏(یا hermes model) را دوباره اجرا کنید. جریان از نو شروع می‌شود.

ناهم‌خوانی state ‏(احتمال CSRF)

هرمس تشخیص داد مقدار state برگشتی از سرور احراز با آنچه فرستاده بود نمی‌خواند.

راه حل:ورود را دوباره اجرا کنید. اگر ادامه پیدا کرد، چک کنید پروکسی یا ریدایرکتی پاسخ OAuth را دستکاری نمی‌کند.

ورود از سرور راه‌دور

اگر hermes نتواند پنجرهٔ مرورگری باز کند از ‎--no-browser‎ استفاده کنید:

hermes auth add minimax-oauth --no-browser

هرمس URL و کد را چاپ می‌کند. URL را روی هر دستگاهی باز کنید و جریان را همان‌جا کامل کنید.

خطای «Not logged into MiniMax OAuth» هنگام اجرا

مخزن احراز برای minimax-oauth هیچ credential ای ندارد. هنوز وارد نشده‌اید یا فایل credential حذف شده.

راه حل:hermes model را اجرا و گزینهٔ MiniMax (OAuth) را بردارید، یا hermes auth add minimax-oauth را بزنید.

خروج

برای حذف credential های ذخیره‌شدهٔ MiniMax OAuth:

hermes auth logout minimax-oauth
