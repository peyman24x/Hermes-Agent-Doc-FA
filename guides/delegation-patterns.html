خانه/راهنماها/الگوهای واگذاری

واگذاری و کار موازی

هرمس می‌تواند ایجنت‌های فرزندِ ایزوله بیندازد تا موازی روی وظایف کار کنند. هر زیرایجنت گفتگو، نشست ترمینال و تول‌ست خودش را دارد. فقط خلاصهٔ نهایی برمی‌گردد — فراخوانی‌های ابزار میانی هرگز وارد پنجرهٔ زمینهٔ شما نمی‌شوند.

مرجع کامل قابلیت در واگذاری به زیرایجنت است.

۱ کی واگذار کنیم

نامزدهای خوب برای واگذاری:

  • زیروظایف سنگین-استدلالی ‏(عیب‌یابی، بازبینی کد، سنتز تحقیق)
  • کارهایی که دادهٔ میانی را می‌ریزند داخل زمینهٔ شما
  • مسیرهای کاری مستقل موازی ‏(تحقیق A و B هم‌زمان)
  • وظایف زمینه‌تازه که می‌خواهید ایجنت بدون پیش‌فرض به آن نزدیک شود

چیز دیگری استفاده کنید:

  • یک فراخوانی ابزار ← مستقیم از ابزار استفاده کنید
  • کار مکانیکی چندمرحله‌ای با منطق بین مراحل ← execute_code
  • کارهای نیازمند تعامل با کاربر ← زیرایجنت‌ها نمی‌توانند clarify استفاده کنند
  • ویرایش سریع فایل ← مستقیم انجامش دهید
  • کار ماندگار بلندمدت که باید از بسته شدن نشست یا ری‌استارت فرایند جان سالم ببرد ← cronjob یا terminal(background=True, notify_on_complete=True). واگذاری سطح‌بالا ناهمگام است ولی همچنان محدود به همین فرایند.

۲ الگو: تحقیق موازی

سه موضوع را هم‌زمان بررسی کنید و خلاصه‌های ساختاریافته برگردانید:

Research these three topics in parallel:
1. Current state of WebAssembly outside the browser
2. RISC-V server chip adoption in 2025
3. Practical quantum computing applications

Focus on recent developments and key players.

پشت صحنه هرمس این را استفاده می‌کند:

delegate_task(tasks=[
    {
        "goal": "Research WebAssembly outside the browser in 2025",
        "context": "Focus on: runtimes (Wasmtime, Wasmer), cloud/edge use cases, WASI progress"
    },
    {
        "goal": "Research RISC-V server chip adoption",
        "context": "Focus on: server chips shipping, cloud providers adopting, software ecosystem"
    },
    {
        "goal": "Research practical quantum computing applications",
        "context": "Focus on: error correction breakthroughs, real-world use cases, key companies"
    }
])

هر سه هم‌زمان اجرا می‌شوند. هر زیرایجنت مستقل وب را جستجو و خلاصه‌ای برمی‌گرداند. بعد ایجنت والد آن‌ها را در یک خلاصهٔ منسجم سنتز می‌کند.

۳ الگو: بازبینی کد

یک بازبینی امنیتی را به زیرایجنتی با زمینه‌تازه بسپارید که بدون پیش‌فرض به کد نزدیک شود:

Review the authentication module at src/auth/ for security issues.
Check for SQL injection, JWT validation problems, password handling,
and session management. Fix anything you find and run the tests.

کلید ماجرا فیلد context است — باید همهٔ آنچه زیرایجنت لازم دارد را داشته باشد:

delegate_task(
    goal="Review src/auth/ for security issues and fix any found",
    context="""Project at /home/user/webapp. Python 3.11, Flask, PyJWT, bcrypt.
    Auth files: src/auth/login.py, src/auth/jwt.py, src/auth/middleware.py
    Test command: pytest tests/auth/ -v
    Focus on: SQL injection, JWT validation, password hashing, session management.
    Fix issues found and verify tests pass."""
)
⚠️

مسئلهٔ زمینه
زیرایجنت دربارهٔ گفتگوی شما به‌طور مطلق هیچ چیزی نمی‌دانند. کاملاً تازه شروع می‌کنند. اگر واگذار کنید «باگی که داشتیم روش بحث می‌کردیم رو درست کن»، زیرایجنت هیچ ایده‌ای ندارد منظورتان کدام باگ است. همیشه مسیر فایل‌ها، پیام خطاها، ساختار پروژه و محدودیت‌ها را صریح پاس بدهید.

۴ الگو: مقایسه گزینه‌ها

چند رویکرد به یک مسئله را موازی ارزیابی و بهترین را بردارید:

I need to add full-text search to our Django app. Evaluate three approaches
in parallel:
1. PostgreSQL tsvector (built-in)
2. Elasticsearch via django-elasticsearch-dsl
3. Meilisearch via meilisearch-python

For each: setup complexity, query capabilities, resource requirements,
and maintenance overhead. Compare them and recommend one.

هر زیرایجنت یک گزینه را مستقل بررسی می‌کند. چون ایزوله‌اند آلودگی متقاطع نیست — هر ارزیابی روی شایستگی خودش می‌ایستد. ایجنت والد هر سه خلاصه را می‌گیرد و مقایسه را انجام می‌دهد.

۵ الگو: بازآرایی چندفایلی

یک بازآرایی بزرگ را بین زیرایجنت‌های موازی تقسیم کنید، هر کدام بخشی از کدبیس:

delegate_task(tasks=[
    {
        "goal": "Refactor all API endpoint handlers to use the new response format",
        "context": """Project at /home/user/api-server.
        Files: src/handlers/users.py, src/handlers/auth.py, src/handlers/billing.py
        Old format: return {"data": result, "status": "ok"}
        New format: return APIResponse(data=result, status=200).to_dict()
        Import: from src.responses import APIResponse
        Run tests after: pytest tests/handlers/ -v"""
    },
    {
        "goal": "Update all client SDK methods to handle the new response format",
        "context": """Project at /home/user/api-server.
        Files: sdk/python/client.py, sdk/python/models.py
        Old parsing: result = response.json()["data"]
        New parsing: result = response.json()["data"] (same key, but add status code checking)
        Also update sdk/python/tests/test_client.py"""
    },
    {
        "goal": "Update API documentation to reflect the new response format",
        "context": """Project at /home/user/api-server.
        Docs at: docs/api/. Format: Markdown with code examples.
        Update all response examples from old format to new format.
        Add a 'Response Format' section to docs/api/overview.md explaining the schema."""
    }
])
💡

هر زیرایجنت نشست ترمینال خودش را دارد. می‌توانند بدون له‌هم‌زدن هم روی یک پوشهٔ پروژه کار کنند — تا وقتی فایل‌های متفاوتی را ویرایش می‌کنند. اگر دو زیرایجنت ممکن است به همان فایل دست بزنند، آن فایل را بعد از پایان کار موازی خودتان هندل کنید.

۶ الگو: اول جمع کن بعد تحلیل کن

از execute_code برای جمع‌آوری مکانیکی داده استفاده کنید و بعد تحلیل سنگین-استدلالی را واگذار کنید:

# Step 1: Mechanical gathering (execute_code is better here — no reasoning needed)
execute_code("""
from hermes_tools import web_search, web_extract

results = []
for query in ["AI funding Q1 2026", "AI startup acquisitions 2026", "AI IPOs 2026"]:
    r = web_search(query, limit=5)
    for item in r["data"]["web"]:
        results.append({"title": item["title"], "url": item["url"], "desc": item["description"]})

# Extract full content from top 5 most relevant
urls = [r["url"] for r in results[:5]]
content = web_extract(urls)

# Save for the analysis step
import json
with open("/tmp/ai-funding-data.json", "w") as f:
    json.dump({"search_results": results, "extracted": content["results"]}, f)
print(f"Collected {len(results)} results, extracted {len(content['results'])} pages")
""")

# Step 2: Reasoning-heavy analysis (delegation is better here)
delegate_task(
    goal="Analyze AI funding data and write a market report",
    context="""Raw data at /tmp/ai-funding-data.json contains search results and
    extracted web pages about AI funding, acquisitions, and IPOs in Q1 2026.
    Write a structured market report: key deals, trends, notable players,
    and outlook. Focus on deals over $100M."""
)

این اغلب کارآمدترین الگو است: execute_code ده‌ها فراخوانی ابزار ترتیبی را ارزان هندل می‌کند و بعد یک زیرایجنت تک‌وظیفهٔ گران استدلالی را با زمینهٔ تمیز انجام می‌دهد.

۷ دسترسی ابزار ارثی

زیرایجنت‌ها تول‌ست‌های فعال والد را به ارث می‌برند. ‏delegate_task پارامتر toolsets ی رو-به-مدل نمی‌پذیرد، پس کارِ واگذاری نمی‌تواند به خودش قابلیت‌هایی بدهد که والد ندارد. وقتی وظیفهٔ واگذاری‌شده به وب، ترمینال، فایل یا دسترسی دیگر نیاز دارد، ابزارهای والد را قبل از شروع گفتگو پیکربندی کنید. هرمس همچنان ابزارهای مسدود-فرزند مثل clarify، ‏memory و send_message را حذف می‌کند؛ فرزندان execute_code را برای فراخوانی برنامه‌پذیر ابزار نگه می‌دارند.

محدودیت‌ها

  • پیش‌فرض ۳ وظیفهٔ موازی:دسته‌ها پیش‌فرض ۳ زیرایجنت هم‌زمان دارند ‏(قابل تنظیم با delegation.max_concurrent_children در config.yaml؛ سقف سختی ندارد، فقط کف ۱).
  • واگذاری تودرتو opt-in است:زیرایجنت‌های برگ ‏(پیش‌فرض) نمی‌توانند delegate_task، ‏clarify، ‏memory یا execute_code صدا بزنند. زیرایجنت‌های ارکستراتور ‏(role="orchestrator") برای واگذاری بیشتر delegate_task نگه می‌دارند ولی فقط وقتی delegation.max_spawn_depth بالاتر از پیش‌فرض ۱ باشد ‏(کف ۱، بی‌سقف)؛ سه تای دیگر همچنان مسدودند. خاموشی global با delegation.orchestrator_enabled: false.

تنظیم هم‌زمانی و عمق

پیکربندیپیش‌فرضبازهاثر
max_concurrent_children۳≥۱اندازهٔ دستهٔ موازی per فراخوانی delegate_task
max_spawn_depth۱≥۱چند سطح واگذاری می‌تواند بیشتر بیندازد

مثال: اجرای ۳۰ کارگر موازی با زیرایجنت‌های تودرتو:

delegation:
  max_concurrent_children: 30
  max_spawn_depth: 2
  • ترمینال‌های جدا — هر زیرایجنت نشست ترمینال خودش را با پوشهٔ کاری و وضعیت جدا دارد
  • بدون تاریخچهٔ گفتگو — زیرایجنت‌ها فقط goal و context ای را می‌بینند که والد هنگام صدازدن delegate_task می‌گذارد
  • پیش‌فرض ۵۰ تکرار — برای کارهای ساده max_iterations را پایین‌تر بیاورید تا هزینه کم شود
  • ماندگار نیست — واگذاری سطح‌بالا پس‌زمینه اجرا و نتیجه‌اش را بعداً برمی‌گرداند ولی همچنان به نشست و فرایند هرمسِ مالک گره خورده. بستن نشست، ‎/stop‎، ‎/new‎ یا ری‌استارت فرایند می‌تواند کارِ در جریان را لغو یا سرگردان کند. برای کاری که باید از این مرزها جان سالم ببرد از cronjob یا terminal(background=True, notify_on_complete=True) استفاده کنید.

۸ نکته‌ها

  • در هدف‌ها دقیق باشید.«باگ رو درست کن» خیلی مبهم است. «TypeError ی api/handlers.py خط ۴۷ رو درست کن که process_request() از parse_body() مقدار None می‌گیره» به زیرایجنت به‌قدر کافی برای کار می‌دهد.
  • مسیر فایل‌ها را بدهید.زیرایجنت ساختار پروژه‌تان را نمی‌دانند. همیشه مسیر مطلق فایل‌های مرتبط، ریشهٔ پروژه و فرمان تست را بدهید.
  • برای ایزوله کردن زمینه از واگذاری استفاده کنید.گاهی یک دید تازه می‌خواهید. واگذاری مجبورتان می‌کند مسئله را شفاف صورت‌بندی کنید و زیرایجنت بدون پیش‌فرض‌هایی که در گفتگویتان انباشته شده به آن نزدیک می‌شود.
  • نتایج را چک کنید.خلاصه‌های زیرایجنت فقط خلاصه‌اند. اگر زیرایجنتی گفت «باگ رو درست کردم و تست‌ها پاس شد» خودتان تست‌ها را اجرا یا diff را بخوانید.

برای مرجع کامل واگذاری — همهٔ پارامترها، یکپارچگی ACP و پیکربندی پیشرفته — بخش واگذاری به زیرایجنت را ببینید.
