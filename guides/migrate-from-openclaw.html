مهاجرت از OpenClaw

‏hermes claw migrate راه‌اندازی OpenClaw ‏(یا Clawdbot/Moldbot ی قدیمی) شما را وارد Hermes می‌کند. این راهنما دقیقاً پوشش می‌دهد چه چیزی مهاجرت می‌کند، نگاشت کلیدهای پیکربندی چگونه است و بعد از مهاجرت چه چیزهایی را باید تأیید کنید.

📌

به‌جایش از Claude Code یا OpenAI Codex CLI می‌آیید؟ از hermes import-agent استفاده کنید.

💡

اگر راه‌اندازی OpenClaw تان چندارائه‌دهنده‌ای بود، hermes setup --portal آن را به یک OAuth فشرده می‌کند — بیش از ۳۰۰ مدل به‌اضلاف Tool Gateway در یک ورود. بخش Nous Portal را ببینید.

۱ شروع سریع

# Preview then migrate (always shows a preview first, then asks to confirm)
hermes claw migrate

# Preview only, no changes
hermes claw migrate --dry-run

# Full migration including API keys, skip confirmation
hermes claw migrate --preset full --migrate-secrets --yes

مهاجرت همیشه قبل از هر تغییری پیش‌نمایش کاملی از آنچه وارد می‌شود نشان می‌دهد. فهرست را مرور کنید، بعد تأیید کنید تا ادامه یابد.

به‌طور پیش‌فرض از ~/.openclaw/ می‌خواند. پوشه‌های قدیمی ~/.clawdbot/ یا ~/.moltbot/ خودکار تشخیص داده می‌شوند. نام فایل‌های config ی قدیمی هم ‏(clawdbot.json، ‏moltbot.json) همین‌طور.

گزینه‌ها

گزینهتوضیح
--dry-runفقط پیش‌نمایش — بعد از نمایش آنچه مهاجرت می‌شد متوقف می‌شود.
--preset <name>full ‏(همهٔ تنظیمات سازگار) یا user-data ‏(پیکربندی زیرساخت را حذف می‌کند). هیچ preset ای به‌طور پیش‌فرض رازها را وارد نمی‌کند — ‎--migrate-secrets‎ را صریح بدهید.

--source <path>پوشهٔ سفارشی OpenClaw.
--workspace-target <path>AGENTS.md کجا گذاشته شود.
--skill-conflict <mode>skip ‏(پیش‌فرض)، overwrite یا rename.
--yesپرامپت تأیید بعد از پیش‌نمایش را رد کن.

۳ حل کلید API

وقتی ‎--migrate-secrets‎ فعال باشد، کلیدهای API از چهار منبع با ترتیب اولویت جمع می‌شوند:

  1. مقادیر config — ‏models.providers.*.apiKey و کلیدهای ارائه‌دهندهٔ TTS در openclaw.json
  2. فایل محیط — ‏~/.openclaw/.env ‏(کلیدهایی مثل OPENROUTER_API_KEY، ‏ANTHROPIC_API_KEY و...)
  3. زیرشیء env ی config — ‏openclaw.json ← "env" یا "env"."vars" ‏(بعضی راه‌اندازی‌ها کلیدها را این‌جا ذخیره می‌کنند نه در فایل .env جدا)
  4. پروفایل‌های auth — ‏~/.openclaw/agents/main/agent/auth-profiles.json ‏(credential های per-ایجنت)

مقادیر config اولویت دارند. هر منبع بعدی شکاف‌های باقی‌مانده را پر می‌کند.

مقصدهای کلیدی پشتیبانی‌شده

OPENROUTER_API_KEY، ‏OPENAI_API_KEY، ‏ANTHROPIC_API_KEY، ‏DEEPSEEK_API_KEY، ‏GEMINI_API_KEY، ‏ZAI_API_KEY، ‏MINIMAX_API_KEY، ‏ELEVENLABS_API_KEY، ‏TELEGRAM_BOT_TOKEN، ‏VOICE_TOOLS_OPENAI_KEY

کلیدهایی که در این allowlist نیستند هرگز کپی نمی‌شوند.

مدیریت SecretRef

مقادیر config ی OpenClaw برای توکن‌ها و کلیدهای API می‌تواند سه قالب داشته باشد:

// Plain string
"channels": { "telegram": { "botToken": "123456:ABC-DEF..." } }

// Environment template
"channels": { "telegram": { "botToken": "${TELEGRAM_BOT_TOKEN}" } }

// SecretRef object
"channels": { "telegram": { "botToken": { "source": "env", "id": "TELEGRAM_BOT_TOKEN" } } }

مهاجرت هر سه قالب را حل می‌کند. برای قالب‌های محیطی و اشیاء SecretRef با source: "env" مقدار را در ~/.openclaw/.env و زیرشیء env ی openclaw.json جستجو می‌کند. اشیاء SecretRef با source: "file" یا source: "exec" خودکار قابل حل نیستند — مهاجرت درباره‌شان هشدار می‌دهد و آن مقادیر باید دستی از طریق hermes config set به هرمس اضافه شوند.

۴ بعد از مهاجرت

  1. گزارش مهاجرت را چک کنید — در پایان با شمار موارد مهاجرت‌یافته، رد‌شده و دارای-تداخل چاپ می‌شود.
  2. فایل‌های آرشیو را مرور کنید — هر چیزی در ~/.hermes/migration/openclaw/<timestamp>/archive/ به توجه دستی نیاز دارد.
  3. نشست جدید شروع کنید — مهارت‌ها و مدخل‌های حافظهٔ وارد‌شده در نشست‌های جدید اثر می‌کنند نه نشست فعلی.
  4. کلیدهای API را تأیید کنید — hermes status را اجرا کنید تا احراز ارائه‌دهنده‌ها چک شود.
  5. پیام‌رسانی را تست کنید — اگر توکن پلتفرمی مهاجرت دادید گیت‌وی را ری‌استارت کنید: systemctl --user restart hermes-gateway
  6. سیاست‌های نشست را چک کنید — hermes config show را اجرا و مطمئن شوید مقدار session_reset با انتظارات می‌خواند.
  7. واتساپ را دوباره جفت کنید — واتساپ از جفت‌سازی کد QR استفاده می‌کند ‏(Baileys) نه مهاجرت توکن. برای جفت‌سازی hermes whatsapp را اجرا کنید.
  8. پاک‌سازی آرشیو — بعد از مطمئن شدن از کارکرد همه‌چیز، hermes claw cleanup را اجرا کنید تا پوشه‌های باقی‌ماندهٔ OpenClaw به ‎.pre-migration/ تغییر نام یابند ‏(جلوی آشفتگی وضعیت را می‌گیرد).

۵ عیب‌یابی

«OpenClaw directory not found»

مهاجرت ~/.openclaw/ را چک می‌کند، بعد ~/.clawdbot/ و بعد ~/.moltbot/. اگر نصب تان جای دیگری است از ‎--source /path/to/your/openclaw‎ استفاده کنید.

«No provider API keys found»

کلیدها بسته به نسخهٔ OpenClaw تان ممکن است چند جا ذخیره شده باشند: داخل openclaw.json زیر models.providers.*.apiKey، در ~/.openclaw/.env، در زیرشیء "env" ی openclaw.json یا در agents/main/agent/auth-profiles.json. مهاجرت هر چهار جا را چک می‌کند. اگر کلیدها SecretRef با source: "file" یا source: "exec" باشند خودکار قابل حل نیستند — با hermes config set اضافه‌شان کنید.

مهارت‌ها بعد از مهاجرت ظاهر نمی‌شوند

مهارت‌های وارد‌شده در ~/.hermes/skills/openclaw-imports/ می‌افتند. برای اثرگذاری نشست جدیدی شروع کنید یا با ‎/skills‎ بار بودنشان را تأیید کنید.

صدای TTS مهاجرت نکرد

‏OpenClaw تنظیمات TTS را دو جا نگه می‌دارد: messages.tts.providers.* و config ی سطح‌بالای talk. مهاجرت هر دو را چک می‌کند. اگر voice ID تان از طریق UI ی OpenClaw ست شده بود ‏(در مسیری متفاوت ذخیره می‌شود) شاید لازم باشد دستی ستش کنید: hermes config set tts.elevenlabs.voice_id YOUR_VOICE_ID
