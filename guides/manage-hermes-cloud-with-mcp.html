مدیریت Hermes Cloud با MCP

Hermes Cloud نمونه‌های میزبانی‌شدهٔ Hermes Agent را برای شما اجرا می‌کند. معمولاً از صفحهٔ ‎/agents‎ در Nous Portal مدیریتشان می‌کنید. این راهنما هرمس محلیِ شما را به سرور MCP ی Portal وصل می‌کند تا نمونه‌های ابری را فقط با خواستن مدیریت کنید — «لیست ایجنت‌های ابری من»، «اون خاموش رو ری‌استارت کن»، «هزینه‌اش چقدر درمیاد» — بدون ترک ترمینال.

این یک سرور استاندارد MCP ی میزبانی‌شده توسط Nous Research است که با همان ورود OAuth ای گیت‌دار شده که برای Portal استفاده می‌کنید. بعد از اتصال، هرمس دو ابزار می‌گیرد که از طرف شما صدا می‌زند.

۱ با آن چه کار می‌شود کرد

بعد از اتصال، مدل می‌تواند این‌ها را روی سازمان Hermes Cloud تان صدا بزند:

بخواهید که…زیر کاپوت
«لیست ایجنت‌های ابری من»agents ‏(list)
«وضعیت <name> چیه؟»agents ‏(get / status)
«تقریباً هزینهٔ این نمونه چقدره؟»agents ‏(cost_estimate)
«‎<name> رو روشن/خاموش/ری‌استارت کن»agent ‏(start / stop / restart)
«یک نمونهٔ جدید به اسم <name> بساز»agent ‏(create)
«‎<name> رو نابود کن»agent ‏(destroy)
«env / تصویر روی <name> رو به‌روز کن»agent ‏(update_env / update_image)

هر فراخوانی با هویت Portal ی شما روی سازمان خودتان اجرا می‌شود و عضویت در هر فراخوانی دوباره چک می‌شود — این اتصال فقط به نمونه‌هایی دست می‌زند که همین حالا هم از رابط وب کنترلشان می‌کنید.

۲ پیش‌نیازها

  • حساب Nous Portal با دسترسی به Hermes Cloud ‏(حداقل یک نمونه، یا توانایی ساختش).
  • پشتیبانی MCP نصب شده. اگر اسکریپت نصب استاندارد را زده‌اید از قبل هست؛ وگرنه: 
    cd ~/.hermes/hermes-agent
uv pip install -e ".[mcp]"

به کلید API یا client secret جداگانه نیاز ندارید — سرور از OAuth با PKCE استفاده می‌کند و ورود یک رفت‌وبرگشت مرورگری است.

۳ گام ۱: افزودن سرور

hermes mcp add --url https://portal.nousresearch.com/mcp --auth oauth hermes-cloud

‎--auth oauth‎ به هرمس می‌گوید این یک سرور HTTP ی محافظت‌شده با OAuth است. در اولین اتصال هرمس:

  1. نقاط پایانی OAuth ی سرور را خودکار کشف می‌کند ‏(متادیتای RFC 9728 / 8414).
  2. خودش را به‌عنوان سرویس‌گیرنده ثبت می‌کند ‏(Dynamic Client Registration ی RFC 7591) — رازی برای کپی کردن نیست.
  3. مرورگرتان را برای ورود و تأیید به Portal باز می‌کند.
  4. توکن حاصل را زیر ~/.hermes/mcp-tokens/ ذخیره و دوباره استفاده می‌کند ‏(refresh خودکار است).

انتخاب سازمان

اگر حسابتان Portal به بیش از یک سازمان تعلق دارد، مرورگر هنگام تأیید یک انتخاب‌گر سازمان نشان می‌دهد — بردارید این اتصال باید کدام سازمان را مدیریت کند. انتخاب یک بار و داخل مرورگر انجام می‌شود؛ چیزی برای دادن در خط فرمان نیست. حساب‌های تک‌سازمانی این مرحله را رد می‌کنند و خودکار bind می‌شوند.

هر وقت لازم شد اتصال به سازمان دیگری اشاره کند، سرور را بردارید و دوباره اضافه کنید ‏(hermes mcp remove hermes-cloud و بعد دوباره فرمان add) و در مرورگر سازمان دیگر را بردارید.

۴ گام ۲: تأیید اتصال

hermes mcp test hermes-cloud

بعد یک نشست شروع ‏(یا reload) کنید:

hermes chat
/reload-mcp

برای تأیید زنده بودن ابزارها یک سؤال فقط-خواندنی بپرسید:

List my Hermes Cloud agents and their current status.

باید همان نمونه‌های صفحهٔ ‎/agents‎ ی Portal برگردند.

۵ گام ۳: استفاده

سؤال‌های فقط-خواندنی همیشه امن‌اند:

Which of my cloud agents is currently running, and roughly what is each one costing?

اقدام‌های چرخهٔ حیات به درخواست‌های ساده نگاشت می‌شوند:

Restart the instance called research-bot.
Create a new Hermes Cloud instance named scratch, then tell me when it's ready.

هرمس برمی‌گرداند که هر ابزار چه داده — فهرست نمونه‌ها، وضعیت جدید، جزئیات نمونهٔ ساخته‌شده — تا مطمئن شوید اقدام جا افتاده.

۶ پیکربندی

بعد از hermes mcp add سرور در ~/.hermes/config.yaml زندگی می‌کند:

mcp_servers:
  hermes-cloud:
    url: "https://portal.nousresearch.com/mcp"
    auth: oauth

هیچ credential ای وارد config.yaml نمی‌شود — توکن OAuth جدا زیر ~/.hermes/mcp-tokens/ نگه داشته می‌شود، همان‌طور که refresh token ی Portal بیرون config می‌ماند.

محدود کردن سطح ابزار

سرور هم ابزارهای خواندن ‏(agents) و هم ابزارهای تغییردهنده ‏(agent) را expose می‌کند. اگر می‌خواهید اتصال فقط-خواندنی باشد — لیست و بازرسی، ولی هیچ‌وقت start/stop/create/destroy — آن را به ابزار agents محدود کنید:

mcp_servers:
  hermes-cloud:
    url: "https://portal.nousresearch.com/mcp"
    auth: oauth
    tools:
      include: [agents]

بعد از تغییر config یک ‎/reload-mcp‎ بزنید. مدل کامل فیلترینگ ‏(include/exclude، ‏prompts، ‏resources) را در استفاده از MCP با هرمس ببینید.

۷ عیب‌یابی

مرورگر انتخاب‌گر سازمان نشان می‌دهد و مطمئن نیستم کدام را بردارم

به چند سازمان Portal تعلق دارید. سازمانی را بردارید که نمونه‌های Hermes Cloud اش را می‌خواهید با این اتصال مدیریت کنید. اگر شک دارید، همان سازمانی است که نمونه‌های صفحهٔ ‎/agents‎ ی Portal را می‌بینید. بعداً با برداشتن و دوباره افزودن سرور می‌توانید دوباره انتخاب کنید.

خطای invalid_client یا unknown client هنگام اتصال

ثبت سرویس‌گیرندهٔ ذخیره‌شده دیگر با سرور نمی‌خواند ‏(مثلاً قبلاً به محیط متفاوتی وصل شده‌اید). وضعیت OAuth ی کش‌شدهٔ این سرور را پاک و دوباره اضافه کنید:

hermes mcp remove hermes-cloud
rm -f ~/.hermes/mcp-tokens/hermes-cloud.*
hermes mcp add --url https://portal.nousresearch.com/mcp --auth oauth hermes-cloud

بعد از افزودن سرور ابزارها ظاهر نمی‌شوند

داخل نشست MCP را دوباره بار کنید و دوباره چک کنید:

/reload-mcp
Tell me which MCP-backed tools are available right now.

اگر هنوز غایب‌اند، hermes mcp test hermes-cloud را اجرا کنید تا خطای اتصال را مستقیم ببینید.

دوباره ازم می‌خواهد وارد شوم

توکن‌های OAuth خودکار refresh می‌شوند ولی اگر Portal نشست تان را باطل کند ‏(تغییر رمز، ‏revoke، انقضا)، فراخوانی بعدی re-authorize می‌خواهد. فرمان hermes mcp add را دوباره اجرا کنید — جریان مرورگری توکن تازه ضرب می‌کند.

بدون‌سر / SSH / host راه‌دور

callback ی مرورگر OAuth روی ماشینی اجرا می‌شود که هرمس رویش است. روی host راه‌دور پورت loopback را از طریق SSH forward کنید — همان الگوی هر ورود OAuth دیگری. بخش OAuth روی SSH / Host های راه‌دور را ببینید.

۸ ببینید نیز

  • Nous Portal — اشتراک، مدل‌ها و Tool Gateway پشت همین ورود
  • استفاده از MCP با هرمس — اتصال و فیلترکردن کلی سرورهای MCP
  • نمای کلی قابلیت MCP — MCP چیست و هرمس چطور استفاده می‌کند
  • مرجع پیکربندی MCP — همهٔ فیلدهای mcp_servers از جمله auth: oauth
  • OAuth روی SSH — ورود از محیط‌های راه‌دور یا فقط-مرورگر
