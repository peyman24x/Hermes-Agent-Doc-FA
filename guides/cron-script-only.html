کارهای Cron فقط-اسکریپتی ‏(بدون LLM)

گاهی از قبل دقیقاً می‌دانید چه پیامی می‌خواهید بفرستید. به استدلال ایجنت نیازی ندارید — فقط می‌خواهید یک اسکریپت با تایمر اجرا شود و خروجی‌اش ‏(اگر باشد) در تلگرام / دیسکورد / اسلک / Signal بنشیند.

هرمس به این حالت بدون-ایجنت می‌گوید. یعنی سیستم cron منهای LLM.

   ┌──────────────────┐          ┌──────────────────┐
   │ scheduler tick   │  every   │ run script       │
   │ (every N minutes)│ ──────▶ │ (bash or python) │
   └──────────────────┘          └──────────────────┘
                                          │
                                          │ stdout
                                          ▼
                                 ┌──────────────────┐
                                 │ delivery router  │
                                 │ (telegram/disc…) │
                                 └──────────────────┘
  • بدون فراخوانی LLM.صفر توکن، صفر حلقهٔ ایجنت، صفر هزینهٔ مدل.
  • اسکریپت خودِ کار است.اسکریپت تصمیم می‌گیرد هشدار بدهد یا نه. خروجی بدهد ← پیام فرستاده می‌شود. چیزی ندهد ← تیک بی‌صدا.
  • Bash یا Python.فایل‌های ‎.sh‎ / ‎.bash‎ زیر bash از PATH اجرا می‌شوند ‏(در دسترس نبود، ‎/bin/bash‎)؛ هر پسوند دیگری زیر مفسر پایتون فعلی اجرا می‌شود. مسیرها باید داخل ~/.hermes/scripts/ حل شوند ‏(شکل نسبی، مطلق یا ~ اشکالی ندارد اگر در همان پوشه بمانند). اسکریپت‌های cron از محیط فرایند هرمس credential های ارائه‌دهنده به ارث نمی‌برند.
  • همان زمان‌بند.کنار کارهای LLM در cronjob زندگی می‌کند — توقف، ادامه، فهرست، لاگ‌ها و هدف‌گیری تحویل همه همان‌طور کار می‌کنند.

۱ کی استفاده کنیم

حالت بدون-ایجنت برای:

  • نگهبان‌های رم / دیسک / GPU.هر ۵ دقیقه اجرا شود، فقط وقتی آستانه شکست هشدار بدهد.
  • قلاب‌های CI.استقرار تمام شد ← SHA ی کامیت را پست کن. ساخت شکست خورد ← ۱۰۰ خط آخر لاگ را بفرست.
  • سنجه‌های دوره‌ای.«درآمد روزانه Stripe ساعت ۹ صبح» به‌صورت یک فراخوانی ساده API + چاپ مرتب.
  • poller های رویداد خارجی.یک API را چک کن، روی تغییر وضعیت هشدار بده.
  • ضربان‌ها.هر N دقیقه به یک داشبورد ping بده تا ثابت شود host زنده است.

وقتی لازم است ایجنت تصمیم بگیرد چه بگوید — خلاصهٔ یک سند بلند، انتخاب موارد جالب از یک فید، پیش‌نویس پیام دوستانه — از کار cron معمولی ‏(LLM-محور) استفاده کنید. مسیر بدون-ایجنت برای حالت‌هایی است که stdout ی اسکریپت همین حالا خودِ پیام است.

۲ ساختن از داخل چت

برد واقعی حالت بدون-ایجنت این است که خود ایجنت می‌تواند نگهبان را برایتان راه بیندازد — بدون ویرایشگر، بدون شل، بدون حفظ فلگ‌های CLI. توصیف می‌کنید چه می‌خواهید، هرمس اسکریپت را می‌نویسد، زمان‌بندی می‌کند و می‌گوید کی فعال می‌شود.

نمونه گفتگو

شما: اگه رم بالای ۸۵٪ بود هر ۵ دقیقه تو تلگرام بهم خبر بده

هرمس: ‏(می‌نویسد ~/.hermes/scripts/memory-watchdog.sh و بعد cronjob(...) را با no_agent=true صدا می‌زند)

راه افتاد. هر ۵ دقیقه اجرا می‌شه و فقط وقتی رم بالای ۸۵٪ باشه تلگرام خبر می‌ده. اسکریپت: memory-watchdog.sh. شناسهٔ کار: abc123.

زیر کاپوت ایجنت دو فراخوانی ابزار می‌زند:

# 1. Write the check script
write_file(
    path="~/.hermes/scripts/memory-watchdog.sh",
    content='''#!/usr/bin/env bash
ram_pct=$(free | awk '/^Mem:/ {printf "%d", $3 * 100 / $2}')
if [ "$ram_pct" -ge 85 ]; then
  echo "RAM ${ram_pct}% on $(hostname)"
fi
# Empty stdout = silent tick; no message sent.
''',
)

# 2. Schedule it — no_agent=True skips the LLM on every tick
cronjob(
    action="create",
    schedule="every 5m",
    script="memory-watchdog.sh",
    no_agent=True,
    deliver="telegram",
    name="memory-watchdog",
)

از آن به بعد هر تیک رایگان است: زمان‌بند اسکریپت را اجرا می‌کند، stdout اش را اگر غیرخالی به تلگرام پایپ می‌کند و هرگز به مدلی دست نمی‌زند.

ایجنت برای شما چه تصمیم‌هایی می‌گیرد

وقتی درخواستی مثل «به من خبر بده وقتی X» یا «هر N دقیقه Y رو چک کن و اگه Z بود بگو» بیان کنید، توضیح ابزار cronjob ی هرمس بهش می‌گوید هر وقت محتوای پیام کامل توسط اسکریپت تعیین می‌شود سراغ no_agent=True برود. وقتی درخواست به استدلال نیاز دارد ‏(«issue های جدید رو خلاصه کن»، ‏«تیترهای جالب‌تر رو بردار»، ‏«یه یادآوری دوستانه بنویس») به مسیر عادی LLM-محور برمی‌گردد.

لازم نیست خودتان ‎--no-agent‎ مشخص کنید. فقط رفتار را توصیف کنید.

مدیریت نگهبان‌ها از داخل چت

ایجنت همان‌طور که کار می‌سازد می‌تواند متوقف، ادامه، ویرایش و حذف هم بکند:

شما: نگهبان رم رو امشب خاموش کن

هرمس: ‏(cronjob(action='pause', job_id='abc123') را صدا می‌زند)

مکث شد. با «دوباره روشنش کن» یا hermes cron resume abc123 ادامه می‌دی.

شما: تغییرش بده به هر ۱۵ دقیقه

هرمس: ‏(cronjob(action='update', job_id='abc123', schedule='every 15m') را صدا می‌زند)

کل چرخهٔ حیات ‏(create / list / update / pause / resume / run-now / remove) در دسترس ایجنت است بدون اینکه شما هیچ فرمان CLI ای یاد بگیرید.

۳ ساختن از CLI

شل را ترجیح می‌دهید؟ مسیر CLI همان نتیجه را با سه فرمان می‌دهد:

# 1. Write your script
cat > ~/.hermes/scripts/memory-watchdog.sh <<'EOF'
#!/usr/bin/env bash
# Alert when RAM usage is over 85%. Silent otherwise.
RAM_PCT=$(free | awk '/^Mem:/ {printf "%d", $3 * 100 / $2}')
if [ "$RAM_PCT" -ge 85 ]; then
  echo "⚠ RAM ${RAM_PCT}% on $(hostname)"
fi
# Empty stdout = silent run; no message sent.
EOF
chmod +x ~/.hermes/scripts/memory-watchdog.sh

# 2. Schedule it
hermes cron create "every 5m" \
  --no-agent \
  --script memory-watchdog.sh \
  --deliver telegram \
  --name "memory-watchdog"

# 3. Verify
hermes cron list
hermes cron run <job_id>    # fire it once to test

همین. بدون پرامپت، بدون مهارت، بدون مدل.

۴ نگاشت خروجی اسکریپت به تحویل

رفتار اسکریپتنتیجه
Exit 0 با stdout غیرخالیstdout عیناً تحویل داده می‌شود
Exit 0 با stdout خالیتیک بی‌صدا — بدون تحویل
Exit 0 با {"wakeAgent": false} در خط آخرِ stdoutتیک بی‌صدا ‏(دروازهٔ مشترک با کارهای LLM)
کد خروج غیرصفرهشدار خطا تحویل داده می‌شود ‏(تا نگهبان خراب بی‌سروصدا شکست نخورد)
تایم‌اوت اسکریپتهشدار خطا تحویل داده می‌شود

رفتار «خالی = بی‌صدا» کلید الگوی کلاسیک نگهبان است: اسکریپت آزاد است هر دقیقه اجرا شود ولی کانال فقط وقتی پیامی می‌بیند که واقعاً چیزی نیاز به توجه داشته باشد.

۵ قوانین اسکریپت

اسکریپت‌ها باید در ~/.hermes/scripts/ باشند. این هم هنگام ساخت کار اعمال می‌شود هم هنگام اجرا — مسیرهای مطلق، باز شدن ~/ و الگوهای پیمایش مسیر ‏(../) رد می‌شوند. همین پوشه با دروازهٔ اسکریپت pre-check که کارهای LLM استفاده می‌کنند مشترک است.

انتخاب مفسر با پسوند فایل است:

پسوندمفسر
.sh، .bashbash از PATH ‏(fallback: ‎/bin/bash‎)
هر چیز دیگرsys.executable ‏(پایتون فعلی)

عمداً shebang های ‎#!/...‎ را محترم نمی‌شماریم — صریح و کوچک نگه داشتن مجموعهٔ مفسرها سطحی که زمان‌بند بهش اعتماد می‌کند را کم می‌کند.

۶ نحو زمان‌بندی

مثل همهٔ کارهای cron دیگر:

hermes cron create "every 5m"        # interval
hermes cron create "every 2h"
hermes cron create "0 9 * * *"       # standard cron: 9am daily
hermes cron create "30m"             # one-shot: run once in 30 minutes

نحو کامل را در مرجع قابلیت cron ببینید.

مقاصد تحویل

‏‎--deliver‎ همهٔ چیزهایی را قبول می‌کند که گیت‌وی می‌شناسد. چند شکل رایج:

--deliver telegram                       # platform home channel
--deliver telegram:-1001234567890        # specific chat
--deliver telegram:-1001234567890:17585  # specific Telegram forum topic
--deliver discord:#ops
--deliver slack:#engineering
--deliver signal:+15551234567
--deliver local                          # just save to ~/.hermes/cron/output/

برای پلتفرم‌های توکن-بات ‏(Telegram، ‏Discord، ‏Slack، ‏Signal، ‏SMS، ‏WhatsApp) در زمان اجرای اسکریپت گیت‌وی در حال اجرا لازم نیست — ابزار مستقیماً نقطهٔ پایانی REST هر پلتفرم را با credential های موجود در ~/.hermes/.env / ~/.hermes/config.yaml صدا می‌زند.

۷ ویرایش و چرخهٔ حیات

hermes cron list                                    # see all jobs
hermes cron pause <job_id>                          # stop firing, keep definition
hermes cron resume <job_id>
hermes cron edit <job_id> --schedule "every 10m"    # adjust cadence
hermes cron edit <job_id> --agent                   # flip to LLM mode
hermes cron edit <job_id> --no-agent --script …     # flip back
hermes cron remove <job_id>                         # delete it

هرچه روی کارهای LLM کار می‌کند ‏(pause، ‏resume، ‏trigger دستی، تغییر مقصد تحویل) روی کارهای بدون-ایجنت هم کار می‌کند.

مثال کامل: هشدار فضای دیسک

cat > ~/.hermes/scripts/disk-alert.sh <<'EOF'
#!/usr/bin/env bash
# Alert when / or /home is over 90% full.
THRESHOLD=90
df -h / /home 2>/dev/null | awk -v t="$THRESHOLD" '
  NR > 1 && $5+0 >= t {
    printf "⚠ Disk %s full on %s\n", $5, $6
  }
'
EOF
chmod +x ~/.hermes/scripts/disk-alert.sh

hermes cron create "*/15 * * * *" \
  --no-agent \
  --script disk-alert.sh \
  --deliver telegram \
  --name "disk-alert"

وقتی هر دو فایل‌سیستم زیر ۹۰٪ هستند بی‌صداست؛ وقتی یکی پر می‌شود دقیقاً یک خط per فایل‌سیستمِ بالای آستانه فعال می‌شود.

۸ مقایسه با الگوهای دیگر

رویکردچه چیزی اجرا می‌شودکی استفاده کنیم
cronjob --no-agent ‏(این صفحه)اسکریپت شما روی زمان‌بند هرمسنگهبان‌ها / هشدارها / سنجه‌های تکراری که به استدلال نیاز ندارند
cronjob ‏(پیش‌فرض، LLM)ایجنت با اسکریپت pre-check اختیاریوقتی محتوای پیام به استدلال روی داده نیاز دارد
cron سیستم‌عامل + curl به اشتراک وب‌هوکاسکریپت شما روی زمان‌بند سیستم‌عاملوقتی ممکن است خود هرمس ناسالم باشد ‏(چیزی که پایش می‌کنید)

برای نگهبان‌های حیاتی سلامت سیستم که باید حتی وقتی گیت‌وی پایین است هم فعال شوند، از cron سطح سیستم‌عامل با یک curl ساده به اشتراک وب‌هوک هرمس ‏(یا هر نقطهٔ پایانی هشدار خارجی) استفاده کنید — آن‌ها به‌عنوان فرایندهای مستقل سیستم‌عامل اجرا می‌شوند و به بالا بودن هرمس وابسته نیستند. زمان‌بند داخل-گیت‌وی انتخاب درست است وقتی چیزِ تحت پایش بیرونی است.

۹ مرتبط

  • اتوماسیون هر چیزی با Cron — الگوهای cron ی LLM-محور.
  • مرجع وظایف زمان‌بندی‌شده ‏(Cron) — نحو کامل زمان‌بندی، چرخهٔ حیات، مسیریابی تحویل.
  • اشتراک‌های وب‌هوک — نقاط ورود HTTP ی fire-and-forget برای زمان‌بندهای خارجی.
  • درون‌مایهٔ گیت‌وی — جزئیات مسیریاب تحویل.
