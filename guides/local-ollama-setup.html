خانه/راهنماها/اجرای محلی با Ollama — بدون هزینه

اجرای هرمس به‌صورت محلی با Ollama — هزینهٔ API صفر

مسئله

API‌های ابری LLM per توکن پول می‌گیرند. یک نشست سنگین کدنویسی می‌تواند ۵ تا ۲۰ دلار آب بخورد. برای پروژه‌های شخصی، یادگیری یا کارهای حساس-به-حریم‌خصوصی این جمع می‌شود — و هر گفتگوی شما را به شخص ثالثی می‌فرستید.

این راهنما چه چیزی حل می‌کند

Hermes Agent را کاملاً روی سخت‌افزار خودتان راه می‌اندازید با Ollama به‌عنوان backend مدل. بدون کلید API، بدون اشتراک، بدون خروج داده از ماشین شما. بعد از پیکربندی، هرمس دقیقاً مثل وقتی کار می‌کند که OpenRouter یا Anthropic دارد — فرمان‌های ترمینال، ویرایش فایل، مرور وب، واگذاری — ولی مدل محلی اجرا می‌شود.

آخرِ کار این‌ها را خواهید داشت:

  • Ollama که یک یا چند مدل open-weight را سرویس می‌کند
  • هرمس متصل به Ollama به‌عنوان نقطهٔ پایانی سفارشی
  • یک ایجنت محلی کارا که می‌تواند فایل ویرایش کند، فرمان اجرا کند و وب بگردد
  • اختیاری: بات تلگرام/دیسکورد که کاملاً روی سخت‌افزار خودتان کار می‌کند

۱ چه چیزی لازم دارید

قطعهحداقلتوصیه‌شده
رم۸ گیگ ‏(برای مدل‌های 3B)۳۲ گیگ به بالا ‏(برای مدل‌های 27B+)
فضای ذخیره۵ گیگ آزاد۳۰ گیگ به بالا ‏(برای چند مدل)
CPU۴ هسته۸+ هسته ‏(AMD EPYC، Ryzen، Intel Xeon)
GPUلازم نیستNVIDIA با VRAM ی ۸+ گیگ سرعت را به‌طور چشمگیری بالا می‌برد
💡

فقط-CPU جواب می‌دهد ولی پاسخ‌ها کندتر انتظار داشته باشید.‏Ollama روی سرورهای فقط-CPU اجرا می‌شود. مدل 9B روی CPU ی مدرن ۸ هسته‌ای حدود ۱۰ توکن/ثانیه می‌دهد. مدل 31B روی CPU کندتر است ‏(حدود ۲ تا ۵ توکن/ثانیه) — هر پاسخ ۳۰ تا ۱۲۰ ثانیه طول می‌کشد ولی کار می‌کند. GPU این را به‌طرز چشمگیری بهتر می‌کند. برای راه‌اندازی‌های فقط-CPU تایم‌اوت API را با متغیر محیطی باز کنید ‏(کلید config.yaml ندارد):

# ~/.hermes/.env
HERMES_API_TIMEOUT=1800   # 30 minutes — generous for slow local models

۲ گام ۱: نصب Ollama

curl -fsSL https://ollama.com/install.sh | sh

تأیید کنید در حال اجراست:

ollama --version
curl http://localhost:11434/api/tags   # Should return {"models":[]}

گام ۲: گرفتن یک مدل

بر اساس سخت‌افزارانتان انتخاب کنید:

مدلحجم روی دیسکرم لازمفراخوانی ابزاربهترین برای
gemma4:31bحدود ۲۰ گیگ۲۴+ گیگبلهبهترین کیفیت — ابزار و reasoning قوی
gemma2:27bحدود ۱۶ گیگ۲۰+ گیگخیرکارهای مکالمه‌ای، بدون ابزار
gemma2:9bحدود ۵ گیگ۸+ گیگخیرچت سریع، پرسش‌وپاسخ — نمی‌تواند ابزار صدا بزند
llama3.2:3bحدود ۲ گیگ۴+ گیگخیرفقط پاسخ‌های سبک و سریع
⚠️

فراخوانی ابزار مهم است.هرمس یک دستیار ایجنتی است — از طریق فراخوانی ابزار فایل ویرایش می‌کند، فرمان اجرا می‌کند و وب می‌گردد. مدل‌های بدون پشتیبانی فراخوانی ابزار فقط چت می‌کنند؛ نمی‌توانند اقدام کنند. برای تجربهٔ کامل هرمس مدلی بردارید که ابزار را پشتیبانی کند ‏(مثل gemma4:31b).

مدل انتخابیتان را بگیرید:

ollama pull gemma4:31b
📌

چند مدل:می‌توانید چند مدل بگیرید و داخل هرمس با ‎/model‎ بینشان سوئیچ کنید. ‏Ollama مدل فعال را به‌صورت درخواستی در حافظه بار و بقیه را خودکار تخلیه می‌کند.

تأیید کنید مدل کار می‌کند:

curl http://localhost:11434/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gemma4:31b",
    "messages": [{"role": "user", "content": "Say hello"}],
    "max_tokens": 50
  }'

باید پاسخی JSON حاوی جواب مدل ببینید.

۳ گام ۳: پیکربندی هرمس

ویزارد راه‌اندازی هرمس را اجرا کنید:

hermes setup

وقتی ارائه‌دهنده پرسید گزینهٔ Custom Endpoint را بردارید و وارد کنید:

  • URL پایه: http://localhost:11434/v1
  • کلید API: خالی بگذارید یا no-key بنویسید ‏(‏Ollama لازم ندارد)
  • مدل: gemma4:31b ‏(یا هر مدلی که گرفتید)

یا مستقیم ~/.hermes/config.yaml را ویرایش کنید:

model:
  default: "gemma4:31b"
  provider: "custom"
  base_url: "http://localhost:11434/v1"

۴ گام ۴: شروع استفاده

hermes

تمام. حالا یک ایجنت کاملاً محلی دارید. امتحانش کنید:

You: List all Python files in this directory and count the lines of code in each

You: Read the README.md and summarize what this project does

You: Create a Python script that fetches the weather for Ho Chi Minh City

هرمس از ابزار ترمینال، عملیات فایل و مدل محلی‌تان استفاده می‌کند — بدون هیچ فراخوانی ابری.

گام ۵: انتخاب مدل مناسب کار

هر کاری بزرگ‌ترین مدل را نمی‌خواهد. راهنمای عملی:

وظیفهمدل توصیه‌شدهچرا
ویرایش فایل، کد، فرمان‌های ترمینالgemma4:31bتنها مدل با فراخوانی ابزار قابل‌اعتماد
پرسش‌وپاسخ سریع ‏(بدون نیاز به ابزار)gemma2:9bپاسخ سریع برای کارهای مکالمه‌ای
چت سبکllama3.2:3bسریع‌ترین ولی خیلی محدود
📌

برای کار ایجنتی کامل ‏(ویرایش فایل، اجرای فرمان، مرور وب)، gemma4:31b فعلاً بهترین گزینهٔ محلی با پشتیبانی فراخوانی ابزار است. کتابخانهٔ مدل‌های Ollama را برای مدل‌های جدیدتر چک کنید — پشتیبانی فراخوانی ابزار به‌سرعت در حال گسترش است.

سوئیچ مدل وسط نشست:

/model gemma2:9b

۵ گام ۶: بهینه‌سازی برای سرعت

افزایش پنجرهٔ زمینهٔ Ollama

به‌طور پیش‌فرض Ollama زمینهٔ ۲۰۴۸ توکنی استفاده می‌کند. هرمس برای کار ایجنتی با ابزار حداقل ۶۴٬۰۰۰ توکن لازم دارد:

# Create a Modelfile that extends context
cat > /tmp/Modelfile << 'EOF'
FROM gemma4:31b
PARAMETER num_ctx 64000
EOF

ollama create gemma4-64k -f /tmp/Modelfile

بعد پیکربندی هرمس را طوری عوض کنید که نام مدل gemma4-64k باشد.

بار نگه داشتن مدل

به‌طور پیش‌فرض Ollama بعد از ۵ دقیقه بی‌کاری مدل را تخلیه می‌کند. برای بات گیت‌وی دائمی بار نگهش دارید:

# Set keep-alive to 24 hours
curl http://localhost:11434/api/generate \
  -d '{"model": "gemma4:31b", "keep_alive": "24h"}'

یا global در محیط Ollama ست کنید:

# /etc/systemd/system/ollama.service.d/override.conf
[Service]
Environment="OLLAMA_KEEP_ALIVE=24h"

استفاده از انتقال به GPU ‏(در صورت وجود)

اگر NVIDIA دارید Ollama خودکار لایه‌ها را منتقل می‌کند. چک کنید:

ollama ps   # Shows which model is loaded and how many GPU layers

برای مدل 31B روی GPU ی ۱۲ گیگی، انتقال جزئی می‌گیرید ‏(حدود ۴۰ لایه روی GPU بقیه روی CPU) که همچنان شتاب معناداری می‌دهد.

۶ گام ۷: اجرا به‌عنوان بات گیت‌وی ‏(اختیاری)

وقتی هرمس محلی در CLI کار کرد، می‌توانید به‌عنوان بات تلگرام یا دیسکورد expose‌اش کنید — همچنان کاملاً روی سخت‌افزار خودتان.

تلگرام

  1. بات را از طریق @BotFather بسازید و توکن بگیرید
  2. به ~/.hermes/config.yaml اضافه کنید: 
    model:
  default: "gemma4:31b"
  provider: "custom"
  base_url: "http://localhost:11434/v1"

platforms:
  telegram:
    enabled: true
    token: "YOUR_TELEGRAM_BOT_TOKEN"
  3. گیت‌وی را اجرا کنید: 
    hermes gateway

حالا در تلگرام به بات پیام بدهید — با مدل محلی‌تان پاسخ می‌دهد.

دیسکورد

  1. در discord.com/developers یک اپ بسازید
  2. به config اضافه کنید: 
    platforms:
  discord:
    enabled: true
    token: "YOUR_DISCORD_BOT_TOKEN"
  3. اجرا: hermes gateway

گام ۸: راه‌اندازی fallback ‏(اختیاری)

مدل‌های محلی ممکن است در کارهای پیچیده زورشان نرسد. یک fallback ی ابری راه بیندازید که فقط وقتی مدل محلی شکست خورد فعال شود:

model:
  default: "gemma4:31b"
  provider: "custom"
  base_url: "http://localhost:11434/v1"

fallback_providers:
  - provider: openrouter
    model: anthropic/claude-sonnet-4

این‌طوری ۹۰٪ مصرف شما رایگان است ‏(محلی) و فقط کارهای سخت به API پرداختی می‌روند.

۷ عیب‌یابی

«Connection refused» هنگام شروع

Ollama اجرا نمی‌شود. روشنش کنید:

sudo systemctl start ollama
# or
ollama serve

پاسخ‌های کند

  • چک کنید اندازهٔ مدل نسبت به رم:اگر مدل رم بیشتری از موجود می‌خواهد به دیسک swap می‌شود. مدل کوچک‌تر بردارید یا رم اضافه کنید.
  • chek ollama ps:اگر هیچ لایه‌ای به GPU منتقل نشده پاسخ‌ها مقید به CPU هستند. برای سرورهای فقط-CPU طبیعی است.
  • زمینه را کم کنید:گفتگوهای بزرگ استنتاج را کند می‌کنند. مرتب ‎/compress‎ بزنید یا آستانهٔ فشرده‌سازی پایین‌تری در config ست کنید.

پاسخ اول کند ‏(prefill)

هرمس با هر فراخوانی API یک payload ثابت می‌فرستد — system prompt به‌اضلاف اسکیماهای ابزار همهٔ ابزارهای فعال — قبل از محتوای گفتگوی شما. روی راه‌اندازی‌های فقط-CPU یا کم-VRAM، پردازش آن پرامپت ‏(فاز prefill) نوبت اول را غالب می‌کند: مدل می‌تواند چند دقیقه بی‌صدا بنشیند در حالی که پرامپت را هضم می‌کند و بعد با سرعت معمول تولید می‌کند. رفتار موردانتظار است نه hang. راهنمای LLM محلی مک همین اثر را مستند کرده — حین prefill روی زمینه‌های بزرگ مدل‌های محلی ممکن است چند دقیقه هیچ خروجی‌ای نداشته باشند — و هرمس برای نقاط پایانی محلی تایم‌اوت خواندن استریمش را خودکار از ۱۲۰ ثانیه به ۱۸۰۰ ثانیه بالا می‌برد ‏(HERMES_STREAM_READ_TIMEOUT).

چه چیزی کمک می‌کند:

  • مدل را بار نگه دارید — ‏Ollama مدل‌های بی‌کار را بعد از ۵ دقیقه تخلیه می‌کند و یک بارگذاری کامل قبل از prefill بعدی اضافه می‌شود. OLLAMA_KEEP_ALIVE=24h را ست کنید ‏(بخش «بار نگه داشتن مدل»).
  • تایم‌اوت API را باز کنید — HERMES_API_TIMEOUT=1800 را در ~/.hermes/.env بگذارید ‏(بخش «چه چیزی لازم دارید»).
  • پرامپت ثابت را اندازه بگیرید و کوتاه کنید — hermes prompt-size را اجرا کنید تا تفکیک بایتی system prompt و اسکیماهای ابزار را ببینید، بعد تول‌ست‌های بی‌استفاده را با hermes tools غیرفعال و مهارت‌های بلااستفاده را با hermes skills حذف کنید.
  • انتقال GPU استفاده کنید — حتی انتقال جزئی شتاب معناداری می‌دهد.

مدل فراخوانی ابزار را رعایت نمی‌کند

مدل‌های بدون پشتیبانی فراخوانی ابزار به‌جای فراخوانی ساختاریافته متن ساده تولید می‌کنند. راه‌حل‌ها:

  • مدل با پشتیبانی فراخوانی ابزار بردارید — از مدل‌های فهرست بالا فقط gemma4:31b فراخوانی ابزار قابل‌اعتماد دارد.
  • هرمس تعمیر خودکار دارد — فراخوانی‌های بدشکل ابزار را تشخیص و تلاش می‌کند خودکار درست کند.
  • fallback راه بیندازید — اگر مدل محلی ۳ بار شکست بخورد هرمس به ارائه‌دهندهٔ ابری برمی‌گردد.

اگر مدل JSON خامی مثل {"name": "web_search", ...} در پاسخش چاپ کرد به‌جای اینکه واقعاً ابزار را اجرا کند، معمولاً مقصر سرور است نه مدل — فراخوانی ابزار فعال نیست یا قالب فراخوانی parse نمی‌شود. جدول راه‌حل per-server در بخش «فراخوانی‌های ابزار متن می‌شوند» صفحهٔ ارائه‌دهندگان مدل را ببینید ‏(llama.cpp به ‎--jinja‎ نیاز دارد، vLLM به ‎--enable-auto-tool-choice --tool-call-parser hermes‎ و...).

خطاهای پنجرهٔ زمینه

زمینهٔ پیش‌فرض Ollama ‏(۲۰۴۸ توکن) برای کار ایجنتی خیلی کوچک است. بخش گام ۶ را برای افزایشش ببینید.

۸ مقایسه هزینه

اجرا محلی نسبت به API‌های ابری چیزی ذخیره می‌کند — بر اساس یک نشست کدنویسی معمولی ‏(حدود ۱۰۰ هزار توکن ورودی، ۲۰ هزار توکن خروجی):

ارائه‌دهندههزینه per نشستماهانه ‏(استفاده روزانه)
Anthropic Claude Sonnetحدود ۰٫۸۰ دلارحدود ۲۴ دلار
OpenRouter ‏(GPT-4o)حدود ۰٫۶۰ دلارحدود ۱۸ دلار
Ollama ‏(محلی)۰٫۰۰ دلار۰٫۰۰ دلار

تنها هزینه‌تان برق است — تقریباً ۰٫۰۱ تا ۰٫۰۵ دلار per نشست بسته به سخت‌افزار.

چه چیزهایی محلی خوب جواب می‌دهد

  • ویرایش فایل و تولید کد — مدل‌های 9B+ خوب هندلش می‌کنند
  • فرمان‌های ترمینال — هرمس فرمان را بسته‌بندی، اجرا و خروجی را می‌خواند فارغ از مدل
  • مرور وب — ابزار مرورگر گیرش را انجام می‌دهد؛ مدل فقط نتایج را تفسیر می‌کند
  • کارهای cron و وظایف زمان‌بندی‌شده — مثل راه‌اندازی‌های ابری کار می‌کنند
  • گیت‌وی چندپلتفرمی — تلگرام، دیسکورد و اسلک همگی با مدل‌های محلی کار می‌کنند

چه چیزهایی با مدل‌های ابری بهتر است

  • استدلال چندمرحله‌ای خیلی پیچیده — ‏70B+ یا مدل‌های ابری مثل Claude Opus به‌طور محسوس بهترند
  • پنجره‌های زمینهٔ بلند — مدل‌های ابری ۱۰۰ هزار تا ۱ میلیون توکن می‌دهند؛ زمان‌های اجرای محلی اغلب زیر حداقل ۶۴K ی هرمس پیش‌فرض می‌مانند مگر پیکربندی‌شان کنید
  • سرعت در پاسخ‌های بلند — استنتاج ابری برای تولیدهای طولانی از محلیِ فقط-CPU سریع‌تر است

نقطهٔ طلایی: کارهای روزمره محلی، برای کارهای سخت fallback ابری راه بیندازید.
