OAuth روی SSH / Host های راه‌دور

بعضی ارائه‌دهنده‌های هرمس — Spotify و سرورهای MCP ی راه‌دور ‏(Linear، ‏Sentry، ‏Atlassian، ‏Asana، ‏Figma و...) — از جریان OAuth با ریدایرکت loopback استفاده می‌کنند. سرور احراز هویت مرورگر شما را به http://127.0.0.1:<port>/callback ریدایرکت می‌کند تا شنوندهٔ HTTP کوچکی که هرمس راه انداخته کد احراز را بگیرد.

وقتی هرمس و مرورگرتان روی یک ماشین‌اند این بی‌نقص کار می‌کند. لحظه‌ای که نیستند می‌شکند: مرورگر لپ‌تاپ شما سعی می‌کند به 127.0.0.1 روی لپ‌تاپ برسد در حالی که شنونده به 127.0.0.1 روی سرور راه‌دور bind شده.

راه‌حل یک forward محلی SSH تک‌خطی است. برای سرورهای MCP روی ترمینال تعاملی اغلب می‌توانید به‌جایش URL ی ریدایرکت را برگردانید و بچسبانید ‏(بدون تونل).

‏xAI Grok OAuth ‏(xai-oauth) از کد دستگاه OAuth استفاده می‌کند نه callback ی loopback — URL ی تأییدی چاپ‌شده را در هر مرورگری باز کنید و هرمس تا تأیید poll می‌کند. هیچ تونل SSH لازم نیست. xAI Grok OAuth را ببینید.

۱ خلاصهٔ فوری

# On your local machine (laptop), in a separate terminal:
ssh -N -L 43827:127.0.0.1:43827 user@remote-host

# In your existing SSH session on the remote machine:
hermes auth spotify --no-browser
# → Hermes prints an authorize URL. Open it in a browser on your laptop.
# → Your browser redirects to 127.0.0.1:43827/callback, the tunnel forwards
#   the request to the remote listener, login completes.

هرمس پورت دقیقی که bind کرده را روی خط Waiting for callback on ... چاپ می‌کند — از همان‌جا بردارید. Spotify پیش‌فرضش پورت 43827 است.

اگر ارائه‌دهنده‌تان در جدول نیست، تونل لازم ندارید.

۲ سرورهای MCP

سرورهای MCP ی راه‌دور ‏(Linear، ‏Sentry، ‏Atlassian، ‏Asana، ‏Figma و...) همان جریان ریدایرکت loopback را استفاده می‌کنند. هرمس per سرور خودکار پورت آزادی برمی‌دارد و هنگام شروع جریان OAuth URL ی تأیید را چاپ می‌کند — یا هنگام شروع ‏(وقتی سرور جدیدی در mcp_servers: ظاهر شود) یا وقتی hermes mcp login <server> اجرا کنید.

از host راه‌دور دو راه برای کامل کردن دارید:

گزینهٔ ۱ — برگرداندن URL ی ریدایرکت ‏(بدون راه‌اندازی، همه‌جا کار می‌کند)

روی ترمینال تعاملی هرمس کنار اجرای شنوندهٔ محلی از شما می‌خواهد URL ی ریدایرکت را بچسبانید. بعد از تأیید در مرورگر، ریدایرکت به http://127.0.0.1:<port>/callback خطای اتصال نشان می‌دهد — طبیعی است. URL کامل را از نوار آدرس مرورگر کپی و در پرامپت هرمس بچسبانید:

  MCP OAuth: authorization required.
  Open this URL in your browser:

    https://mcp.linear.app/authorize?response_type=code&...

  Or paste the redirect URL here (or the ?code=...&state=... portion) and press Enter:
> https://mcp.linear.app/callback?code=abc123&state=xyz
  Got authorization code from paste — completing flow.

رشتهٔ کوئری لختِ ‎?code=...&state=...‎ هم قبول می‌شود. این برای هر سرور MCP ای با auth: oauth کار می‌کند و هیچ تغییر پیکربندی SSH نمی‌خواهد.

گزینهٔ ۲ — port forward ی SSH ‏(مثل Spotify)

هرمس پورت دقیق bind‌شده را در راهنمای نشست SSH چاپ می‌کند. ترمینال جداگانه‌ای روی لپ‌تاپ باز کنید:

ssh -N -L <port>:127.0.0.1:<port> user@remote-host

بعد URL ی تأیید را مثل همیشه در مرورگر باز کنید؛ ریدایرکت از داخل تونل عبور می‌کند و شنونده می‌گیردش. وقتی لازم است جریان بدون حضور شما کامل شود ‏(مثلاً re-auth اسکریپت‌شده که امکان چسباندن تعاملی نیست) از این استفاده کنید.

⚠️

دام — مسابقهٔ بارگذاری مجدد config با مهلت ۳۰ ثانیه:اگر از داخل نشست در حال اجرای هرمس ~/.hermes/config.yaml را برای افزودن سرور MCP ی OAuth ویرایش کنید، CLI اتصال‌های MCP را با مهلت ۳۰ ثانیه خودکار بارگذاری مجدد می‌کند. برای کامل کردن یک جریان OAuth تعاملی کافی نیست و reload تسلیم می‌شود. به‌جایش hermes mcp login <server> را از ترمینال تازه اجرا کنید — سقفی ندارد و ۵ دقیقه کامل برای چسباندن صبر می‌کند.

۳ چرا شنونده نمی‌تواند فقط روی 0.0.0.0 بنشیند

‏Spotify و بیشتر سرورهای OAuth ی MCP پارامتر redirect_uri را با یک allowlist اعتبارسنجی می‌کنند. هر دو شکل loopback را الزامی می‌کنند ‏(http://127.0.0.1:<exact-port>/callback). Bind کردن شنونده روی 0.0.0.0 یا پورت متفاوت باعث می‌شود سرور احراز درخواست را به‌عنوان ناهمخوانی redirect_uri رد کند. تونل SSH شکل loopback را سرتاسری دست‌نخورده نگه می‌دارد.

۴ قدم‌به‌قدم: یک پرش SSH

۱. تونل را از ماشین محلی راه بیندازید

# Spotify (port 43827)
ssh -N -L 43827:127.0.0.1:43827 user@remote-host

‎-N‎ یعنی «شل راه‌دور باز نکن، فقط تونل را نگه دار». این ترمینال را تا پایان ورود روشن نگه دارید.

۲. در نشست SSH ی جداگانه فرمان احراز را اجرا کنید

ssh user@remote-host
hermes auth spotify --no-browser

هرمس نشست SSH را تشخیص می‌دهد، باز شدن خودکار مرورگر را رد می‌کند و URL ی تأیید به‌اضلاف خطی مثل Waiting for callback on http://127.0.0.1:<port>/callback چاپ می‌کند.

۳. URL را در مرورگر محلی باز کنید

URL ی تأیید را از ترمینال راه‌دور کپی و در مرورگر لپ‌تاپ بچسبانید. صفحهٔ اجازه را تأیید کنید. سرور احراز به http://127.0.0.1:<port>/callback ریدایرکت می‌کند؛ مرورگر به تونل می‌خورد، درخواست به شنوندهٔ راه‌دور forward می‌شود و هرمس Login successful! چاپ می‌کند.

وقتی خط موفقیت را دیدید می‌توانید تونل را جمع کنید ‏(Ctrl+C در ترمینال اول).

۵ قدم‌به‌قدم: از میان jump box

اگر از طریق bastion / jump host به هرمس می‌رسید، از ‎-J‎ داخلی SSH ‏(ProxyJump) استفاده کنید:

ssh -N -L 43827:127.0.0.1:43827 -J jump-user@jump-host user@final-host

این یک اتصال SSH از داخل jump host زنجیر می‌کند بدون اینکه پورت loopback روی خود jump box بیفتد. مقدار 127.0.0.1:43827 ی محلی روی لپ‌تاپ مستقیم تا 127.0.0.1:43827 روی host نهایی راه‌دور تونل می‌شود.

برای OpenSSH های قدیمی که ‎-J‎ ندارند، شکل بلند:

ssh -N \
    -o "ProxyCommand=ssh -W %h:%p jump-user@jump-host" \
    -L 43827:127.0.0.1:43827 \
    user@final-host

۶ Mosh، ‏tmux و ControlMaster

تونل خاصیتِ اتصال SSH زیرین است. اگر هرمس را داخل tmux روی نشست mosh اجرا می‌کنید، roaming ی mosh forwarding ی ‎-L‎ را حمل نمی‌کند. یک نشست SSH سادهٔ جداگانه فقط برای تونل ‎-L‎ باز کنید — آن اتصالی است که باید حین جریان احراز زنده بماند. نشست تعاملی mosh/tmux می‌تواند عادی هرمس را ادامه دهد.

اگر ssh -o ControlMaster=auto استفاده می‌کنید، port forward ها روی اتصال multiplex عمر master را دارند. اگر تونل بالا نیامد master را ری‌استارت کنید:

ssh -O exit user@remote-host
ssh -N -L 43827:127.0.0.1:43827 user@remote-host

۷ عیب‌یابی

خطای bind [127.0.0.1]:43827: Address already in use

چیزی روی لپ‌تاپ تان آن پورت را گرفته. یا تونل قبلی تمیز بسته نشده یا هرمس محلی هم رویش گوش می‌دهد. مقصر را پیدا و بکشید:

# macOS / Linux
lsof -iTCP:43827 -sTCP:LISTEN
kill <PID>

بعد فرمان ssh -L را دوباره امتحان کنید.

احراز هویت منتظر callback ی محلی تایم‌اوت شد

ریدایرکت هرگز به شنوندهٔ راه‌دور نرسیده. چک کنید تونل هنوز زنده است ‏(ssh -N خروجی نشان نمی‌دهد پس به ترمینالی که بازش کردید نگاه کنید)، مطمئن شوید پورت آخرین خط Waiting for callback on ... را استفاده کردید ‏(هرمس ممکن است اگر پورت موردعلاقه اشغال باشد خودکار bump کند)، در صورت نیاز تونل را ری‌استارت و فرمان احراز را دوباره اجرا کنید.

توکن‌ها در ~/.hermes اشتباه می‌افتند

توکن‌ها زیر کاربر لینوکسی نوشته می‌شوند که hermes auth add ... را اجرا کرده. اگر گیت‌وی / سرویس systemd تان با کاربر دیگری اجرا می‌شود ‏(مثلاً root یا کاربر اختصاصی hermes)، با همان کاربر احراز کنید تا توکن‌ها در auth.json ی همان کاربر بیفتند. مثلاً sudo -u hermes -i یا معادلش.
