گوگل Vertex AI

‏Hermes Agent از مدل‌های Gemini روی Google Cloud Vertex AI از طریق نقطهٔ پایانی سازگار-OpenAI ی Vertex پشتیبانی می‌کند. برخلاف ارائه‌دهندهٔ Google AI Studio ‏(که کلید API ی ایستا روی generativelanguage.googleapis.com استفاده می‌کند)، Vertex به شما محدودیت نرخ درجهٔ سازمانی و صورتحساب/اعتبارهای GCP می‌دهد و انتخاب درست است وقتی می‌خواهید مصرف Gemini روی حساب Google Cloud تان بیفتد نه یک کلید AI Studio.

📌

‏Vertex با OAuth2 احراز هویت می‌کند، نه کلید API
Vertex برای نقطهٔ پایانی استاندارد هیچ کلید API ی ایستایی ندارد. هر درخواست به یک توکن دسترسی OAuth2 کوتاه‌عمر ‏(عمر حدود ۱ ساعت) نیاز دارد که یا از JSON ی service-account یا از Application Default Credentials ‏(ADC) ضرب می‌شود. هرمس این توکن‌ها را برایتان ضرب و خودکار refresh می‌کند — هرگز توکن را دستی نمی‌چسبانید. برای همین چسباندن یک توکن موقت در فیلد api_key ی ارائه‌دهندهٔ سفارشی کار نمی‌کند: وسط نشست منقضی می‌شود.

۱ پیش‌نیازها

  • یک پروژهٔ Google Cloud با API ی Vertex AI فعال و صورتحساب فعال.
  • Credential، یکی از این‌ها:
    • فایل کلید JSON ی service-account با نقش roles/aiplatform.user، یا
    • Application Default Credentials از طریق gcloud auth application-default login ‏(یا متادیتا سرور هنگام اجرا روی VM ی GCP).
  • google-auth — دفعهٔ اول که Vertex را انتخاب کنید خودکار نصب می‌شود ‏(نصب lazy). اگر شکست خورد hermes setup را اجرا کنید تا نصب مدیریت‌شده تعمیر شود.

۲ شروع سریع

# Option A — service account JSON (recommended for servers / gateways)
echo "VERTEX_CREDENTIALS_PATH=/path/to/service-account.json" >> ~/.hermes/.env

# Option B — Application Default Credentials (good for local dev)
gcloud auth application-default login

# Select Vertex as your provider
hermes model
# → Choose "More providers..." → "Google Vertex AI"
# → Enter your GCP project ID (or leave blank to use the one in your credentials)
# → Choose a region (default: global)
# → Select a Gemini model

# Start chatting
hermes chat

۳ پیکربندی

‏Vertex تنظیماتش را بر اساس حساسیت جدا می‌کند:

  • مسیر credential اشاره‌گر به یک راز است و در ~/.hermes/.env زندگی می‌کند.
  • شناسهٔ پروژه و منطقه تنظیمات مسیریابی غیرمحرمانه‌اند و در ~/.hermes/config.yaml زندگی می‌کنند.

فایل ~/.hermes/.env:

# One of these (checked in this order); omit both to use ADC:
VERTEX_CREDENTIALS_PATH=/path/to/service-account.json
GOOGLE_APPLICATION_CREDENTIALS=/path/to/service-account.json

فایل ~/.hermes/config.yaml:

model:
  default: google/gemini-3-flash-preview
  provider: vertex

vertex:
  project_id: my-gcp-project   # blank → use the project embedded in the credentials
  region: global               # "global" is required for the Gemini 3.x previews
💡

متغیرهای محیطی از config.yaml قوی‌ترند:VERTEX_PROJECT_ID و VERTEX_REGION مقادیر vertex.project_id / vertex.region در config.yaml را بازنویسی می‌کنند. آن‌ها را برای بازنویسی per-shell استفاده کنید؛ تنظیمات ماندگار را در config.yaml نگه دارید.

احراز هویت چطور کار می‌کند

  1. هرمس credential ها را به این ترتیب حل می‌کند: VERTEX_CREDENTIALS_PATH ← GOOGLE_APPLICATION_CREDENTIALS ← ADC.
  2. یک توکن دسترسی OAuth2 با دامنهٔ cloud-platform ضرب و کش می‌کند؛ تا ۵ دقیقه مانده به انقضا refresh می‌شود.
  3. توکن به یک سرویس‌گیرندهٔ استاندارد OpenAI داده می‌شود که به نقطهٔ پایانی Vertex اشاره می‌کند: 
    https://aiplatform.googleapis.com/v1beta1/projects/{project}/locations/{region}/endpoints/openapi
    موقعیت‌های منطقه‌ای به‌جایش از host ی {region}-aiplatform.googleapis.com استفاده می‌کنند.
  4. اگر نشستی بیشتر از عمر توکن طول بکشد و درخواستی 401 برگرداند، هرمس توکن را دوباره ضرب و خودکار retry می‌کند. روی گیت‌وی بلندمدت اگر refresh token ی ADC خودش منقضی شده باشد و JSON ی service-account پیکربندی شده باشد، هرمس به آن fallback می‌کند.

۴ مدل‌های موجود

‏Vertex پیشوند فروشندهٔ google/ را روی شناسه‌های مدل الزامی می‌کند. انتخاب‌گر hermes model این‌ها را می‌دهد:

مدلشناسه
Gemini 3.1 Pro Previewgoogle/gemini-3.1-pro-preview
Gemini 3 Pro Previewgoogle/gemini-3-pro-preview
Gemini 3 Flash Previewgoogle/gemini-3-flash-preview
Gemini 3.1 Flash Lite Previewgoogle/gemini-3.1-flash-lite-preview
Gemini 2.5 Progoogle/gemini-2.5-pro
Gemini 2.5 Flashgoogle/gemini-2.5-flash
📌

منطقهٔ global برای Gemini 3.x:مدل‌های preview ی Gemini 3.x از طریق نقطهٔ پایانی global سرویس می‌شوند. نقاط پایانی منطقه‌ای ‏(us-central1 و...) ممکن است 404 بدهند. مگر دلیل مشخصی برای pin کردن منطقه داشته باشید region: global را دست نزنید.

۵ سوئیچ مدل وسط نشست

/model google/gemini-3-pro-preview
/model google/gemini-3-flash-preview

‏‎/model‎ بین ارائه‌دهنده‌ها و مدل‌هایی که قبلاً پیکربندی شده‌اند سوئیچ می‌کند؛ credential جدید جمع نمی‌کند. اول Vertex را با hermes model پیکربندی کنید.

Reasoning / تفکر

‏Vertex بودجهٔ تفکر Gemini را از سطح سازگار-OpenAI expose می‌کند. هرمس تنظیم reasoning-effort را خودکار روی extra_body.google.thinking_config نگاشت می‌کند، پس reasoning_effort همان‌طور که روی سطوح دیگر Gemini کار می‌کند این‌جا هم کار می‌کند.

۶ عیب‌یابی

«Vertex AI credentials could not be resolved»

هرمس نه JSON ی service-account پیدا کرده نه ADC ی کارا. یا VERTEX_CREDENTIALS_PATH را در ~/.hermes/.env ست کنید یا gcloud auth application-default login را اجرا کنید. اگر پروژه‌تان داخل credential جاسازی نشده، vertex.project_id را در config.yaml ست کنید.

google-auth نصب نیست

هرمس بار اولی که ارائه‌دهندهٔ Vertex را انتخاب کنید lazy نصبش می‌کند. اگر شکست خورد hermes setup را اجرا کنید تا نصب مدیریت‌شده تعمیر شود.

خطای 404 روی مدل‌های Gemini 3.x

احتمالاً روی نقطهٔ پایانی منطقه‌ای هستید. region: global را در بخش vertex: ی config.yaml ست کنید ‏(یا VERTEX_REGION را بردارید).

خطای 403 / اجازه‌نامهٔ رد شده

حساب خدمت ‏(یا هویت ADC ی شما) به نقش roles/aiplatform.user روی پروژه نیاز دارد و API ی Vertex AI باید برای آن پروژه فعال باشد.

برای تشخیص، hermes doctor را اجرا کنید — گزارش می‌دهد credential های Vertex قابل حل هستند یا نه ‏(مسیر service-account یا ADC) و آیا ارائه‌دهنده پیکربندی شده است.
