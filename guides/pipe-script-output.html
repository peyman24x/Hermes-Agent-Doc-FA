خانه/راهنماها/ارسال خروجی اسکریپت به پیام‌رسان‌ها

پایپ کردن خروجی اسکریپت به پلتفرم‌های پیام‌رسانی

‏hermes send یک CLI ی کوچک و اسکریپت‌پذیر است که پیامی را به هر پلتفرم پیام‌رسانیِ از قبل پیکربندی‌شده در هرمس می‌فشارد. مثل یک curl چندپلتفرمی برای اعلان‌هاست — نه گیت‌وی در حال اجرا می‌خواهد، نه LLM، و لازم نیست توکن بات را در تک‌تک اسکریپت‌هایتان دوباره بچسبانید.

برای این‌ها استفاده‌اش کنید:

  • پایش سیستم ‏(رم، ‏دیسک، دمای GPU، تمام شدن کار طولانی)
  • اعلان‌های CI/CD ‏(استقرار انجام شد، شکست تست)
  • اسکریپت‌های Cron که باید نتیجه را بهتان خبر دهند
  • پیام‌های تک‌ضرب سریع از ترمینال
  • پایپ کردن خروجی هر ابزاری به هر جا ‏(make | hermes send --to slack:#builds)

این فرمان همان credential ها و آداپتورهای پلتفرمی که hermes gateway از قبل استفاده می‌کند را بازمصرف می‌کند، پس سطح پیکربندی دوم برای نگهداری نیست.

۱ شروع سریع

# Plain text to the home channel for a platform
hermes send --to telegram "deploy finished"

# Pipe in stdout from anything
echo "RAM 92%" | hermes send --to telegram:-1001234567890

# Send a file
hermes send --to discord:#ops --file /tmp/report.md

# Attach a subject/header line
hermes send --to slack:#eng --subject "[CI] build.log" --file build.log

# Thread target (Telegram topic, Discord thread)
hermes send --to telegram:-1001234567890:17585 "threaded reply"

# List every configured target
hermes send --list

# Filter by platform
hermes send --list telegram

۲ مرجع آرگومان‌ها

فلگتوضیح
-t, --to TARGETمقصد. قالب‌های هدف را ببینید.
message ‏(موقعیتی)متن پیام. برای خواندن از ‎--file‎ یا stdin حذفش کنید.
-f, --file PATHبدنه را از فایل بخوان. ‎--file -‎ استریم stdin را اجباری می‌کند.
-s, --subject LINEیک خط سربرگ/موضوع قبل از بدنه اضافه می‌کند.
-l, --listفهرست مقاصد موجود. فیلتر موقعیتی پلتفرم هم اختیاری است.
-q, --quietدر موفقیت هیچ stdout ای ندارد ‏(فقط کد خروج — ایده‌آل برای اسکریپت).
--jsonنتیجهٔ JSON خام ارسال را چاپ می‌کند.
-h, --helpمتن راهنمای داخلی.

هر پلتفرمی که هرمس آداپتور دارد به‌عنوان هدف کار می‌کند: telegram، ‏discord، ‏slack، ‏signal، ‏sms، ‏whatsapp، ‏matrix، ‏mattermost، ‏feishu، ‏dingtalk، ‏wecom، ‏weixin، ‏email و دیگران.

کدهای خروج

کدمعنا
0ارسال ‏(یا فهرست) موفق بود
1تحویل در سطح پلتفرم شکست خورد ‏(احراز، مجوز، شبکه)
2خطای استفاده / آرگومان / پیکربندی

کدهای خروج قرارداد استاندارد یونیکس را دنبال می‌کنند تا اسکریپت‌هایتان رویشان شاخه بزنند همان‌طور که روی curl یا grep شاخه می‌زنید.

۳ حل کردن بدنهٔ پیام

‏hermes send بدنهٔ پیام را با این ترتیب حل می‌کند:

  1. آرگومان موقعیتی — hermes send --to telegram "hi"
  2. ‎--file PATH‎ — hermes send --to telegram --file msg.txt
  3. stdin پایپ‌شده — echo hi | hermes send --to telegram

وقتی stdin یک TTY است ‏(بدون پایپ) هرمس منتظر ورود نمی‌ماند — به‌جایش خطای استفادهٔ روشنی می‌گیرید. این جلوگیر می‌شود اسکریپت‌ها اگر تصادفی بدنه را جا بیندازند معلق بمانند.

۴ نمونه‌های دنیای واقعی

پایش: هشدار رم / دیسک

فراخوانی‌های ad-hoc ی curl https://api.telegram.org/... در نگهبان‌های تان را با یک خط قابل‌حمل عوض کنید:

#!/usr/bin/env bash
ram_pct=$(free | awk '/^Mem:/ {printf "%d", $3 * 100 / $2}')
if [ "$ram_pct" -ge 85 ]; then
  hermes send --to telegram --subject "⚠ MEMORY WARNING" \
    "RAM ${ram_pct}% on $(hostname)"
fi

چون hermes send پیکربندی هرمس شما را بازمصرف می‌کند، همان اسکریپت روی هر host ای که هرمس نصب است کار می‌کند — لازم نیست توکن بات را دستی در محیط هر ماشین export کنید.

💡

به گیت‌وی دربارهٔ خودش هشدار ندهید:برای نگهبان‌هایی که ممکن است وقتی خود گیت‌وی در سختی است فعال شوند ‏(هشدار OOM، هشدار پرشدن دیسک)، همچنان از فراخوانی مینیمال curl استفاده کنید نه hermes send. اگر مفسر پایتون نتواند بار شود چون ماشین در حال تقلاست، هنوز می‌خواهید آن هشدار برسد.

CI / CD: نتیجهٔ ساخت و تست

# In .github/workflows/deploy.yml or any CI script
if ./scripts/deploy.sh; then
  hermes send --to slack:#deploys "✅ ${CI_COMMIT_SHA:0:7} deployed"
else
  tail -n 100 deploy.log | hermes send \
    --to slack:#deploys --subject "❌ deploy failed"
  exit 1
fi

Cron: گزارش روزانه

# Crontab entry
0 9 * * * /usr/local/bin/generate-metrics.sh \
  | /home/me/.hermes/bin/hermes send \
      --to telegram --subject "Daily metrics $(date +%Y-%m-%d)"

کارهای طولانی: خبر دادن موقع پایان

./train.py --epochs 200 && \
  hermes send --to telegram "training done" || \
  hermes send --to telegram "training failed (exit $?)"

اسکریپت‌نویسی با ‎--json‎ و ‎--quiet‎

# Hard-fail a script if delivery fails; don't clutter logs on success
hermes send --to telegram --quiet "keepalive" || {
  echo "Telegram delivery failed" >&2
  exit 1
}

# Capture the message ID for later editing / threading
msg_id=$(hermes send --to discord:#ops --json "build started" \
  | jq -r .message_id)

۵ آیا hermes send به گیت‌وی نیاز دارد؟

معمولاً نه.برای هر پلتفرم توکن-بات — ‏Telegram، ‏Discord، ‏Slack، ‏Signal، ‏SMS، ‏WhatsApp Cloud API و بیشتر بقیه — ‏hermes send مستقیماً نقطهٔ پایانی REST پلتفرم را با credential های ~/.hermes/.env و ~/.hermes/config.yaml صدا می‌زند. یک زیرفرایند مستقل است که همین که پیام تحویل شد خارج می‌شود.

گیت‌وی زنده فقط برای پلتفرم‌های افزونه‌ای لازم است که به اتصال دائمی آداپتور تکیه دارند ‏(مثلاً افزونهٔ سفارشی که WebSocket ی بلندعمر باز نگه می‌دارد). در آن صورت خطای روشنی به سمت گیت‌وی اشاره می‌کند؛ با hermes gateway start بالا بیاورید و دوباره امتحان کنید.

۶ فهرست و کشف مقاصد

قبل از ارسال به کانال مشخص، می‌توانید ببینید چه چیزی موجوده:

# Every target across every configured platform
hermes send --list

# Just Telegram targets
hermes send --list telegram

# Machine-readable
hermes send --list --json

فهرست از ~/.hermes/channel_directory.json ساخته می‌شود که گیت‌وی در حال اجرا هر چند دقیقه refresh می‌کند. اگر «no channels discovered yet» دیدید، یک بار گیت‌وی را اجرا کنید ‏(hermes gateway start) تا کش پر شود.

نام‌های دوستانه ‏(discord:#ops، ‏slack:#engineering) هنگام ارسال با این کش حل می‌شوند، پس لازم نیست شناسه‌های عددی را حفظ باشید.

۷ مقایسه با رویکردهای دیگر

رویکردچندپلتفرمیبازمصرف credential هرمسگیت‌وی لازم؟بهترین برای
hermes send✅✅نه ‏(توکن-بات)همهٔ کاربردهای این صفحه
curl خام به هر پلتفرمهرکدام جدا اسکریپت می‌شوددستینهنگهبان‌های حیاتی
کار cron با ‎--deliver‎✅✅نهوظایف ایجنتی زمان‌بندی‌شده

‏hermes send عمداً ساده‌ترین سطح ممکن است. اگر می‌خواهید یک ایجنت تصمیم بگیرد چه بگوید، کار cron زمان‌بندی کنید — پاسخ نهایی ایجنت خودکار به مقصد deliver: ی پیکربندی‌شده تحویل داده می‌شود ‏(ایجنت دیگر خودش پیام نمی‌فرستد). اگر اجرای زمان‌بندی‌شده با محتوای تولید-LLM می‌خواهید از cronjob(action='create', prompt=...) با deliver='telegram:...' استفاده کنید. اگر فقط پایپ کردن یک رشتهٔ خام لازم دارید، سراغ hermes send بروید.

۸ مرتبط

  • اتوماسیون هر چیزی با Cron — کارهای زمان‌بندی‌شده‌ای که خروجی‌شان خودکار به هر پلتفرمی تحویل می‌شود.
  • درون‌مایهٔ گیت‌وی — مسیریاب تحویلی که hermes send با تحویل cron شریک است.
  • راه‌اندازی پلتفرم‌های پیام‌رسانی — پیکربندی یک‌بارهٔ هر پلتفرم.
