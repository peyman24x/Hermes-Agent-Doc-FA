خانه/راهنماها/کار با مهارت‌ها

کار با مهارت‌ها

مهارت‌ها سندهای دانشی درخواستی‌اند که به هرمس یاد می‌دهند چطور کارهای مشخص را هندل کند — از تولید ASCII art تا مدیریت PR های گیت‌هاب. این راهنما استفادهٔ روزمره از آن‌ها را قدم‌به‌قدم نشان می‌دهد.

مرجع فنی کامل در سیستم مهارت‌ها است.

۱ پیدا کردن مهارت‌ها

هر نصب هرمس با مهارت‌های همراه عرضه می‌شود. ببینید چه چیزهایی موجود است:

# In any chat session:
/skills

# Or from the CLI:
hermes skills list

فهرستی فشرده با نام‌ها و توضیحات نشان می‌دهد:

ascii-art         Generate ASCII art using pyfiglet, cowsay, boxes...
arxiv             Search and retrieve academic papers from arXiv...
github-pr-workflow Full PR lifecycle — create branches, commit...
plan              Plan mode — inspect context, write a markdown...
excalidraw        Create hand-drawn style diagrams using Excalidraw...

جستجوی یک مهارت

# Search by keyword
/skills search docker
/skills search music

هاب مهارت‌ها

مهارت‌های اختیاری رسمی ‏(مهارت‌های سنگین‌تر یا خاص که به‌طور پیش‌فرض فعال نیستند) از طریق Hub در دسترس‌اند:

# Browse official optional skills
/skills browse

# Search the hub
/skills search blockchain

۲ استفاده از یک مهارت

هر مهارت نصب‌شده خودبه‌خود یک فرمان اسلش است. فقط نامش را تایپ کنید:

# Load a skill and give it a task
/ascii-art Make a banner that says "HELLO WORLD"
/plan Design a REST API for a todo app
/github-pr-workflow Create a PR for the auth refactor

# Just the skill name (no task) loads it and lets you describe what you need
/excalidraw

از طریق مکالمهٔ طبیعی هم می‌توانید مهارت‌ها را فعال کنید — از هرمس بخواهید از مهارت مشخصی استفاده کند و آن را با ابزار skill_view بارگذاری می‌کند.

افشای تدریجی

مهارت‌ها از الگوی بارگذاری کم‌مصرف-توکن استفاده می‌کنند. ایجنت همه‌چیز را یک‌جا نمی‌کارد:

  1. skills_list() — فهرست فشردهٔ همهٔ مهارت‌ها ‏(حدود ۳ هزار توکن). هنگام شروع نشست بار می‌شود.
  2. skill_view(name) — محتوای کامل SKILL.md برای یک مهارت. وقتی ایجنت تصمیم گرفت نیاز دارد بار می‌شود.
  3. skill_view(name, file_path) — یک فایل مرجع مشخص داخل مهارت. فقط اگر لازم باشد.

یعنی مهارت‌ها تا واقعاً استفاده نشوند هیچ توکنی نمی‌خورند.

۳ نصب از هاب

مهارت‌های اختیاری رسمی همراه هرمس می‌آیند ولی پیش‌فرض فعال نیستند. صریح نصبشان کنید:

# Install an official optional skill
hermes skills install official/research/arxiv

# Install from the hub in a chat session
/skills install official/creative/songwriting-and-ai-music

# Install SKILL.md and its referenced support files from an HTTP(S) URL
hermes skills install https://sharethis.chat/SKILL.md
/skills install https://example.com/SKILL.md --name my-skill

چه اتفاقی می‌افتد:

  1. پوشهٔ مهارت در ~/.hermes/skills/ کپی می‌شود
  2. در خروجی skills_list تان ظاهر می‌شود
  3. به‌عنوان فرمان اسلش در دسترس می‌شود
💡

مهارت‌های نصب‌شده در نشست‌های جدید اثر می‌کنند. اگر همین نشست لازمش دارید ‎/reset‎ بزنید تا تازه شروع شود یا ‎--now‎ اضافه کنید تا کش پرامپت بلافاصله باطل شود ‏(نوبت بعد گران‌تر است).

تأیید نصب

# Check it's there
hermes skills list | grep arxiv

# Or in chat
/skills search arxiv

۴ مهارت‌های ارائه‌شده توسط افزونه‌ها

افزونه‌ها می‌توانند مهارت‌های خودشان را با نام‌های فضادار ‏(plugin:skill) بسته‌بندی کنند. این جلوی برخورد نام با مهارت‌های داخلی را می‌گیرد.

# Load a plugin skill by its qualified name
skill_view("superpowers:writing-plans")

# Built-in skill with the same base name is unaffected
skill_view("writing-plans")

مهارت‌های افزونه‌ای در system prompt فهرست نمی‌شوند و در skills_list ظاهر نمی‌شوند. opt-in هستند — وقتی دانستید افزونه‌ای مهارتی دارد صریح بارگذاری‌اش کنید. موقع بارگذاری، ایجنت بنری می‌بیند که مهارت‌های خواهر همان افزونه را فهرست می‌کند.

برای بسته‌بندی مهارت داخل افزونهٔ خودتان بخش «Bundle skills» در ساخت پلاگین هرمس را ببینید.

۵ پیکربندی تنظیمات مهارت‌ها

بعضی مهارت‌ها در frontmatter خود پیکربندی موردنیازشان را اعلام می‌کنند:

metadata:
  hermes:
    config:
      - key: tenor.api_key
        description: "Tenor API key for GIF search"
        prompt: "Enter your Tenor API key"
        url: "https://developers.google.com/tenor/guides/quickstart"

وقتی مهارتی با config برای اولین بار بار شود، هرمس مقادیر را از شما می‌پرسد. در config.yaml زیر skills.config.* ذخیره می‌شوند.

مدیریت config ی مهارت از CLI:

# Interactive config for a specific skill
hermes skills config gif-search

# View all skill config
hermes config get skills.config --json

۶ ساخت مهارت خودتان

مهارت‌ها فقط فایل‌های markdown با frontmatter ی YAML اند. ساختنش زیر پنج دقیقه طول می‌کشد.

۱. ساخت پوشه

mkdir -p ~/.hermes/skills/my-category/my-skill

۲. نوشتن SKILL.md

name: my-skill
description: Brief description of what this skill does
version: 1.0.0
metadata:
  hermes:
    tags: [my-tag, automation]
    category: my-category

# My Skill

## When to Use
Use this skill when the user asks about [specific topic] or needs to [specific task].

## Procedure
1. First, check if [prerequisite] is available
2. Run `command --with-flags`
3. Parse the output and present results

## Pitfalls
- Common failure: [description]. Fix: [solution]
- Watch out for [edge case]

## Verification
Run `check-command` to confirm the result is correct.

۳. افزودن فایل‌های مرجع ‏(اختیاری)

مهارت‌ها می‌توانند فایل‌های پشتیبان داشته باشند که ایجنت به‌صورت درخواستی بار می‌کند:

my-skill/
├── SKILL.md                    # Main skill document
├── references/
│   ├── api-docs.md             # API reference the agent can consult
│   └── examples.md             # Example inputs/outputs
├── templates/
│   └── config.yaml             # Template files the agent can use
└── scripts/
    └── setup.sh                # Scripts the agent can execute

در SKILL.md ارجاعشان دهید:

For API details, load the reference: `skill_view("my-skill", "references/api-docs.md")`

۴. تستش کنید

نشست جدیدی شروع و مهارت را امتحان کنید:

hermes chat -q "/my-skill help me with the thing"

مهارت خودکار ظاهر می‌شود — ثبت‌نامی لازم نیست. بیندازیدش در ~/.hermes/skills/ و زنده است.

📌

ایجنت خودش هم می‌تواند با skill_manage مهارت بسازد و به‌روزرسانی کند. بعد از حل یک مسئلهٔ پیچیده، هرمس ممکن است پیشنهاد دهد رویکرد را برای دفعهٔ بعد به‌عنوان مهارت ذخیره کند.

۷ مدیریت مهارت per-پلتفرم

کنترل کنید کدام مهارت روی کدام پلتفرم موجوده:

hermes skills

یک TUI تعاملی باز می‌شود که می‌توانید مهارت‌ها را per پلتفرم ‏(CLI، ‏Telegram، ‏Discord و...) فعال یا غیرفعال کنید. کاربردی وقتی می‌خواهید بعضی مهارت‌ها فقط در زمینه‌های خاص باشند — مثلاً مهارت‌های توسعه روشن تلگرام نباشند.

۸ مهارت‌ها در برابر حافظه

هر دو بین نشست‌ها می‌مانند ولی هدف متفاوتی دارند:

مهارت‌هاحافظه
چهدانش رویه‌ای — چطور کارها انجام می‌شوددانش واقعیتی — چیزها چیستند
کیبه‌صورت درخواستی، فقط وقتی مربوط استخودکار در هر نشست تزریق می‌شود
اندازهمی‌تواند بزرگ باشد ‏(صدها خط)باید فشرده باشد ‏(فقط واقعیت‌های کلیدی)
هزینهتا بار نشود صفر توکنکوچک ولی هزینهٔ توکن ثابت
مثال«چطور روی Kubernetes مستقر کنیم»«کاربر حالت شب ترجیح می‌دهد، ساکن PST است»
کی می‌سازدشما، ایجنت یا نصب از Hubایجنت، بر اساس گفتگوها

قاعدهٔ سرانگشتی:اگر جای‌اش در یک سند مرجع است، مهارت است. اگر جای‌اش روی یک برگهٔ یادداشت چسبان است، حافظه است.

نکته‌ها

  • مهارت‌ها را متمرکز نگه دارید.مهارتی که بخواهد «همهٔ DevOps» را پوشش دهد هم خیلی بلند هم خیلی مبهم می‌شود. مهارتی که «استقرار برنامهٔ پایتونی روی Fly.io» را پوشش دهد به‌قدر کافی خاص و واقعاً مفید است.
  • بگذارید ایجنت مهارت بسازد.بعد از یک کار پیچیدهٔ چندمرحله‌ای هرمس اغلب پیشنهاد می‌دهد رویکرد را به‌عنوان مهارت ذخیره کند. بله بگویید — این مهارت‌های authored-by-agent دقیقاً همان گردش‌کار را با دام‌های کشف‌شده در مسیر ثبت می‌کنند.
  • از دسته‌ها استفاده کنید.مهارت‌ها را در زیرپوشه‌ها سازماندهی کنید ‏(~/.hermes/skills/devops/، ‏~/.hermes/skills/research/ و...). فهرست قابل مدیریت می‌ماند و ایجنت سریع‌تر مهارت مرتبط را پیدا می‌کند.
  • مهارت‌های کهنه را به‌روز کنید.اگر از مهارتی استفاده کردید و به مشکلاتی خوردید که پوشش نمی‌داد، به هرمس بگویید مهارت را با آموخته‌هایتان به‌روز کند. مهارت‌های نگهداری‌نشده بدهکار می‌شوند.

برای مرجع کامل مهارت‌ها — فیلدهای frontmatter، فعال‌سازی شرطی، پوشه‌های خارجی و بیشتر — بخش سیستم مهارت‌ها را ببینید.
