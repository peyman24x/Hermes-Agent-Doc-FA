خانه/راهنماها/ثبت اپ Microsoft Graph

ثبت یک برنامهٔ Microsoft Graph

خط لولهٔ جلسات Teams رونوشت‌ها، ضبط‌ها و مصنوع‌های مرتبط جلسات را با احراز هویت فقط-اپلیکیشن ‏(daemon) از Microsoft Graph می‌خواند — بدون ورود کاربر، بدون تأیید تعاملی per جلسه. این به یک ثبت اپلیکیشن Azure AD با مجوزهای application ی admin-consent شده نیاز دارد.

این راهنما عبور می‌کند از:

  1. ساخت ثبت اپلیکیشن
  2. ساخت client secret
  3. اعطای مجوزهای Graph API که خط لوله لازم دارد
  4. ‏Admin-consent کردن آن مجوزها
  5. ‏(اختیاری) محدود کردن اپ به کاربران مشخص با Application Access Policy

برای تمام کردن این مسیر به دسترسی مدیر tenant نیاز دارید ‏(یا مدیری که از طرف شما consent بدهد). مقادیری که جمع می‌کنید را علامت‌گذاری کنید — آخرش در ~/.hermes/.env می‌روند.

۱ پیش‌نیازها

  • یک tenant مایکروسافت ۳۶۵ با Teams Premium یا لایسنس‌های Teams ای که رونوشت و ضبط جلسه تولید کنند
  • دسترسی مدیریتی به پرتال Azure در entra.microsoft.com
  • یک نقطهٔ پایانی HTTPS عموماً در دسترس برای اعلان تغییرات Graph ‏(بعداً در مرحلهٔ شنوندهٔ وب‌هوک راه می‌افتد)

۲ گام ۱: ساخت App Registration

  1. به‌عنوان مدیر tenant وارد entra.microsoft.com شوید.
  2. به Identity → Applications → App registrations بروید.
  3. روی New registration کلیک کنید.
  4. پر کنید:
    • Name: ‏Hermes Teams Meeting Pipeline ‏(یا هر اسمی که بشناسید).
    • Supported account types: «Accounts in this organizational directory only (Single tenant)».
    • Redirect URI: خالی بگذارید — احراز فقط-اپلیکیشن لازم ندارد.
  5. روی Register کلیک کنید.

به صفحهٔ نمای کلی اپ می‌رسید. دو مقدار را کپی کنید:

  • Application (client) ID ← MSGRAPH_CLIENT_ID
  • Directory (tenant) ID ← MSGRAPH_TENANT_ID

۳ گام ۲: ساخت Client Secret

  1. در ناوبری کناری Certificates & secrets را باز کنید.
  2. روی New client secret کلیک کنید.
  3. Description: ‏hermes-graph-secret. ‏Expires: مقداری هماهنگ با سیاست چرخش تان بردارید ‏(۶ تا ۲۴ ماه رایج است).
  4. روی Add کلیک کنید.
  5. ستون Value را بلافاصله کپی کنید — فقط یک بار نشان داده می‌شود. همان MSGRAPH_CLIENT_SECRET است.

ستون Secret ID خودِ راز نیست. شما ستون Value را می‌خواهید.

۴ گام ۳: اعطای مجوزهای Graph API

خط لوله از حداقلِ مجموعهٔ مجوزهای application استفاده می‌کند. فقط چیزی را اضافه کنید که لازم دارید؛ هر مجوز، دامنهٔ خواندن اپ در سراسر tenant را بازتر می‌کند.

  1. در ناوبری کناری API permissions را باز کنید.
  2. Add a permission → Microsoft Graph → Application permissions را بزنید.
  3. از جدول زیر مجوزهایی را که با کاری که از خط لوله می‌خواهید می‌خواند اضافه کنید.
  4. بعد از افزودن، روی Grant admin consent for <tenant> کلیک کنید. ستون Status باید برای هر مجوز تیک سبز شود.

لازم برای خلاصه‌های رونوشت-محور

مجوزبه اپ اجازهٔ چه چیزی را می‌دهد
OnlineMeetings.Read.Allخواندن متادیتای جلسات آنلاین Teams ‏(موضوع، شرکت‌کنندگان، URL ی ورود).
OnlineMeetingTranscript.Read.Allخواندن رونوشت‌هایی که Teams تولید می‌کند.

لازم برای fallback ی ضبط ‏(وقتی رونوشت موجود نیست)

مجوزبه اپ اجازهٔ چه چیزی را می‌دهد
OnlineMeetingRecording.Read.Allدانلود ضبط‌های جلسهٔ Teams برای پردازش STT آفلاین.
CallRecords.Read.Allحل کردن جلسات از سوابق تماس وقتی فقط URL ی ورود معلوم است.

لازم برای تحویل خروجی خلاصه‌ها ‏(فقط حالت graph)

اگر platforms.teams.extra.delivery_mode روی graph باشد، خط لوله خلاصه‌ها را از طریق API ی Graph داخل یک کانال یا گفتگوی Teams پست می‌کند. اگر از حالت delivery ی incoming_webhook استفاده می‌کنید این‌ها را رد کنید.

مجوزبه اپ اجازهٔ چه چیزی را می‌دهد
ChannelMessage.Sendپست پیام داخل کانال‌های Teams از طرف اپ.
Chat.ReadWrite.Allپست پیام داخل گفتگوهای ۱:۱ و گروهی ‏(فقط اگر chat_id را هدف تحویل ست کرده باشید).

توصیه نمی‌شود

  • OnlineMeetings.ReadWrite.All / Chat.ReadWrite بدون ‎.All‎ — بازتر از نیاز خط لوله.
  • مجوزهای delegated — خط لوله از جریان فقط-اپلیکیشن ‏(client-credentials) استفاده می‌کند؛ مجوزهای delegated بدون ورود کاربر کار نمی‌کنند.

۵ گام ۴: ‏(توصیه‌شده) محدود کردن اپ با Application Access Policy

به‌طور پیش‌فرض مجوزهای application مثل OnlineMeetings.Read.All به اپ دسترسی به همهٔ جلسات tenant را می‌دهند. برای دموهای شرکتی و tenant های dev اشکالی ندارد؛ برای production تقریباً حتماً می‌خواهید محدود کنید اپ بتواند جلسات کدام کاربران را بخواند.

مایکروسافت دقیقاً برای همین Application Access Policies را برای Teams فراهم کرده. این سیاست فقط از PowerShell قابل مدیریت است؛ UI ی پرتال ندارد.

از یک PowerShell ادمین با ماژول MicrosoftTeams نصب‌شده و متصل ‏(Connect-MicrosoftTeams):

# Create a policy scoped to the Hermes app
New-CsApplicationAccessPolicy `
  -Identity "Hermes-Meeting-Pipeline-Policy" `
  -AppIds "<MSGRAPH_CLIENT_ID>" `
  -Description "Restrict Hermes meeting pipeline to allow-listed users"

# Grant the policy to specific users whose meetings the pipeline may read
Grant-CsApplicationAccessPolicy `
  -PolicyName "Hermes-Meeting-Pipeline-Policy" `
  -Identity "alice@example.com"

Grant-CsApplicationAccessPolicy `
  -PolicyName "Hermes-Meeting-Pipeline-Policy" `
  -Identity "bob@example.com"

انتشار بعد از اعطا تا ۳۰ دقیقه ممکن است طول بکشد. با این تأیید کنید:

Test-CsApplicationAccessPolicy -Identity "alice@example.com" -AppId "<MSGRAPH_CLIENT_ID>"

بدون سیاست، جلسات هر کاربری خواندنی است — همان چیزی که مجوز از نظر فنی می‌دهد. این مرحله را روی tenant ی تولیدی رد نکنید.

۶ گام ۵: نوشتن credential ها در فایل env

سه مقدار جمع‌آوری‌شده را در ~/.hermes/.env بگذارید:

MSGRAPH_TENANT_ID=<directory-tenant-id>
MSGRAPH_CLIENT_ID=<application-client-id>
MSGRAPH_CLIENT_SECRET=<client-secret-value>

مجوزهای فایل را طوری ست کنید که فقط خودتان بخوانید:

chmod 600 ~/.hermes/.env

۷ گام ۶: تأیید جریان توکن

هرمس یک تست دود احراز Graph همراه دارد. از نصب Hermes تان:

python -c "
import asyncio
from tools.microsoft_graph_auth import MicrosoftGraphTokenProvider
provider = MicrosoftGraphTokenProvider.from_env()
token = asyncio.run(provider.get_access_token())
print('Token acquired, length:', len(token))
print(provider.inspect_token_health())
"

اجرای موفق یک رشتهٔ توکن بلند و دیکشنری سلامت با cached: True و expires_in_seconds نزدیک ۳۶۰۰ چاپ می‌کند. شکست‌ها یک MicrosoftGraphTokenError با کد خطای Azure می‌دهند — رایج‌ترین‌ها:

خطای Azureمعناراه حل
AADSTS7000215: Invalid client secretمقدار راز ناهم‌خوان یا منقضی.در گام ۲ راز جدید بسازید؛ ‎.env را به‌روز کنید.
AADSTS700016: Application not foundMSGRAPH_CLIENT_ID یا tenant غلط.چک کنید مقادیر گام ۱ از همان اپ باشند.
AADSTS90002: Tenant not foundغلط تایپی در MSGRAPH_TENANT_ID.Directory (tenant) ID را دوباره از نمای کلی اپ کپی کنید.
insufficient_claims هنگام فراخوانی ‏(نه هنگام توکن)توکن گرفته می‌شود ولی Graph برمی‌گرداند 401/403.گام ۳ admin-consent را رد کرده‌اید یا مجوزها را اضافه کردید ولی هنوز دوباره consent نکرده‌اید. به API permissions برگردید و Grant admin consent را دوباره بزنید.

۸ چرخاندن Client Secret

رازهای سرویس‌گیرندهٔ Azure انقضای قطعی دارند. قبل از انقضای رازتان:

  1. در گام ۲ یک client secret دوم بسازید بدون حذف اولی.
  2. MSGRAPH_CLIENT_SECRET را در ~/.hermes/.env با مقدار جدید به‌روز کنید.
  3. گیت‌وی را ری‌استارت کنید تا راز جدید خوانده شود: hermes gateway restart.
  4. با تست دود بالا تأیید کنید.
  5. راز قدیمی را از پرتال Azure حذف کنید.

۹ قدم‌های بعدی

وقتی credential ها تمیز تأیید شدند ادامه دهید با:

  • راه‌اندازی شنوندهٔ وب‌هوک — بالا آوردن پلتفرم گیت‌وی msgraph_webhook که اعلان تغییرات Graph را می‌گیرد.
  • پیکربندی خط لوله — تنظیم زمان اجرای خط لولهٔ جلسات Teams و CLI ی عملیات.
  • تحویل خروجی — رساندن خلاصه‌ها به کانال یا گفتگوی Teams.

آن صفحه‌ها کنار PR‌هایی که زمان اجرای مربوطه را اضافه می‌کنند منتشر می‌شوند. این راه‌اندازی credential ها پیش‌نیازی مستقل است و انجامش از قبل امن است.
