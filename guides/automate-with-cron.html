اتوماسیون هر چیزی با Cron

آموزش بات خلاصهٔ روزانه مبانی را پوشش می‌دهد. این راهنما جلوتر می‌رود — پنج الگوی اتوماسیون دنیای واقعی که می‌توانید برای گردش‌کارهای خودتان تطبیق دهید.

مرجع کامل قابلیت در وظایف زمان‌بندی‌شده ‏(Cron) است.

📌

مفهوم کلیدی
کارهای cron در نشست‌های ایجنتی تازه اجرا می‌شوند بدون هیچ حافظه‌ای از گفتگوی فعلی شما. پرامپت‌ها باید کاملاً خودبسنده باشند — هر چیزی که ایجنت باید بداند داخلشان باشد.

💡

‏LLM لازم ندارید؟ دو گزینهٔ صفر-توکنی دارید.

  • نگهبان تکرارشونده که اسکریپت خودش دقیقاً پیام نهایی را تولید می‌کند ‏(هشدار رم، هشدار دیسک، ضربان): از کارهای cron فقط-اسکریپتی استفاده کنید. همان زمان‌بند، بدون LLM. می‌توانید در چت از هرمس بخواهید برایتان راه بیندازد — ابزار cronjob می‌داند کی no_agent=True بردارد و خودش اسکریپت را می‌نویسد.
  • تک‌ضرب از داخل اسکریپتی که همین حالا در حال اجراست ‏(مرحلهٔ CI، قلاب post-commit، اسکریپت استقرار، مانیتور زمان‌بندی‌شدهٔ خارجی): از hermes send استفاده کنید تا stdout یا فایل مستقیم به تلگرام / دیسکورد / اسلک و... پایپ شود بدون ساخت مدخل cron.

۱ الگوی ۱: پایش تغییر وب‌سایت

یک URL را برای تغییرات زیر نظر بگیرید و فقط وقتی چیزی فرق کرد خبرتان کنند.

پارامتر script سلاح مخفی این‌جاست. یک اسکریپت پایتون قبل از هر اجرا می‌رود و stdout اش به زمینهٔ ایجنت تبدیل می‌شود. کار مکانیکی ‏(گرفتن، مقایسه) با اسکریپت است؛ کار استدلال ‏(این تغییر جالب هست؟) با ایجنت.

اسکریپت پایش را بسازید:

mkdir -p ~/.hermes/scripts

فایل ~/.hermes/scripts/watch-site.py:

import hashlib, json, os, urllib.request

URL = "https://example.com/pricing"
STATE_FILE = os.path.expanduser("~/.hermes/scripts/.watch-site-state.json")

# Fetch current content
req = urllib.request.Request(URL, headers={"User-Agent": "Hermes-Monitor/1.0"})
content = urllib.request.urlopen(req, timeout=30).read().decode()
current_hash = hashlib.sha256(content.encode()).hexdigest()

# Load previous state
prev_hash = None
if os.path.exists(STATE_FILE):
    with open(STATE_FILE) as f:
        prev_hash = json.load(f).get("hash")

# Save current state
with open(STATE_FILE, "w") as f:
    json.dump({"hash": current_hash, "url": URL}, f)

# Output for the agent
if prev_hash and prev_hash != current_hash:
    print(f"CHANGE DETECTED on {URL}")
    print(f"Previous hash: {prev_hash}")
    print(f"Current hash: {current_hash}")
    print(f"\nCurrent content (first 2000 chars):\n{content[:2000]}")
else:
    print("NO_CHANGE")

کار cron را راه بیندازید:

/cron add "every 1h" "If the script output says CHANGE DETECTED, summarize what changed on the page and why it might matter. If it says NO_CHANGE, respond with just [SILENT]." --script ~/.hermes/scripts/watch-site.py --name "Pricing monitor" --deliver telegram
💡

ترفند [SILENT]:برای کارهای پایش cron به ایجنت بگویید وقتی چیزی عوض نشده فقط ‎[SILENT]‎ پاسخ بدهد. تحویل cron مقدار [SILENT] را نشانگر بی‌صدایی می‌گیرد، پس فقط وقتی واقعاً اتفاقی افتاده خبر می‌شوید — بدون اسپم در ساعات خلوت.

۲ الگوی ۲: گزارش هفتگی

اطلاعات چند منبع را در یک خلاصهٔ قالب‌بندی‌شده جمع کنید. هفته‌ای یک بار اجرا و به کانال خانگی‌تان تحویل می‌شود.

/cron add "0 9 * * 1" "Generate a weekly report covering:

1. Search the web for the top 5 AI news stories from the past week
2. Search GitHub for trending repositories in the 'machine-learning' topic
3. Check Hacker News for the most discussed AI/ML posts

Format as a clean summary with sections for each source. Include links.
Keep it under 500 words — highlight only what matters." --name "Weekly AI digest" --deliver telegram

از CLI:

hermes cron create "0 9 * * 1" \
  "Generate a weekly report covering the top AI news, trending ML GitHub repos, and most-discussed HN posts. Format with sections, include links, keep under 500 words." \
  --name "Weekly AI digest" \
  --deliver telegram

مقدار 0 9 * * 1 یک عبارت cron ی استاندارد است: ساعت ۹ صبح هر دوشنبه.

۳ الگوی ۳: ناظر مخزن گیت‌هاب

یک مخزن را برای issue ها، PR‌ها یا انتشارهای جدید زیر نظر بگیرید:

/cron add "every 6h" "Check the GitHub repository NousResearch/hermes-agent for:
- New issues opened in the last 6 hours
- New PRs opened or merged in the last 6 hours
- Any new releases

Use the terminal to run gh commands:
  gh issue list --repo NousResearch/hermes-agent --state open --json number,title,author,createdAt --limit 10
  gh pr list --repo NousResearch/hermes-agent --state all --json number,title,author,createdAt,mergedAt --limit 10

Filter to only items from the last 6 hours. If nothing new, respond with [SILENT].
Otherwise, provide a concise summary of the activity." --name "Repo watcher" --deliver discord
⚠️

پرامپت‌های خودبسنده
ببینید پرامپت چطور فرمان‌های دقیق gh را شامل می‌شود. ایجنت cron هیچ تاریخچهٔ گفتگویی از اجراهای قبلی ندارد — همه‌چیز را صریح بنویسید. ‏(حافظهٔ پایدار بارگذاری می‌شود پس ترجیحات ماندگارِ ذخیره‌شده در MEMORY.md منتقل می‌شوند ولی روی آن برای جزئیات حیاتیِ کار حساب باز نکنید.)

۴ الگوی ۴: خط لولهٔ جمع‌آوری داده

در فواصل منظم داده بگیرید، در فایل ذخیره کنید و روند زمانی تشخیص دهید. این الگو اسکریپت ‏(برای جمع‌آوری) را با ایجنت ‏(برای تحلیل) ترکیب می‌کند.

فایل ~/.hermes/scripts/collect-prices.py:

import json, os, urllib.request
from datetime import datetime

DATA_DIR = os.path.expanduser("~/.hermes/data/prices")
os.makedirs(DATA_DIR, exist_ok=True)

# Fetch current data (example: crypto prices)
url = "https://api.coingecko.com/api/v3/simple/price?ids=bitcoin,ethereum&vs_currencies=usd"
data = json.loads(urllib.request.urlopen(url, timeout=30).read())

# Append to history file
entry = {"timestamp": datetime.now().isoformat(), "prices": data}
history_file = os.path.join(DATA_DIR, "history.jsonl")
with open(history_file, "a") as f:
    f.write(json.dumps(entry) + "\n")

# Load recent history for analysis
lines = open(history_file).readlines()
recent = [json.loads(l) for l in lines[-24:]]  # Last 24 data points

# Output for the agent
print(f"Current: BTC=${data['bitcoin']['usd']}, ETH=${data['ethereum']['usd']}")
print(f"Data points collected: {len(lines)} total, showing last {len(recent)}")
print(f"\nRecent history:")
for r in recent[-6:]:
    print(f"  {r['timestamp']}: BTC=${r['prices']['bitcoin']['usd']}, ETH=${r['prices']['ethereum']['usd']}")
/cron add "every 1h" "Analyze the price data from the script output. Report:
1. Current prices
2. Trend direction over the last 6 data points (up/down/flat)
3. Any notable movements (>5% change)

If prices are flat and nothing notable, respond with [SILENT].
If there's a significant move, explain what happened." \
  --script ~/.hermes/scripts/collect-prices.py \
  --name "Price tracker" \
  --deliver telegram

اسکریپت جمع‌آوری مکانیکی را انجام می‌دهد؛ ایجنت لایهٔ استدلال را اضافه می‌کند.

۵ الگوی ۵: گردش‌کار چندمهارتی

مهارت‌ها را برای وظایف زمان‌بندی‌شدهٔ پیچیده زنجیر کنید. مهارت‌ها قبل از اجرای پرامپت به ترتیب بارگذاری می‌شوند.

# Use the arxiv skill to find papers, then the obsidian skill to save notes
/cron add "0 8 * * *" "Search arXiv for the 3 most interesting papers on 'language model reasoning' from the past day. For each paper, create an Obsidian note with the title, authors, abstract summary, and key contribution." \
  --skill arxiv \
  --skill obsidian \
  --name "Paper digest"

مستقیم از ابزار:

cronjob(
    action="create",
    skills=["arxiv", "obsidian"],
    prompt="Search arXiv for papers on 'language model reasoning' from the past day. Save the top 3 as Obsidian notes.",
    schedule="0 8 * * *",
    name="Paper digest",
    deliver="local"
)

مهارت‌ها به ترتیب بار می‌شوند — اول arxiv ‏(به ایجنت یاد می‌دهد مقاله جستجو کند)، بعد obsidian ‏(یاد می‌دهد یادداشت بنویسد). پرامپت این دو را به هم گره می‌زند.

۶ مدیریت کارها

# List all active jobs
/cron list

# Trigger a job immediately (for testing)
/cron run <job_id>

# Pause a job without deleting it
/cron pause <job_id>

# Edit a running job's schedule or prompt
/cron edit <job_id> --schedule "every 4h"
/cron edit <job_id> --prompt "Updated task description"

# Add or remove skills from an existing job
/cron edit <job_id> --skill arxiv --skill obsidian
/cron edit <job_id> --clear-skills

# Remove a job permanently
/cron remove <job_id>

مقاصد تحویل

فلگ ‎--deliver‎ کنترل می‌کند نتایج کجا بروند:

هدفنمونهکاربرد
origin--deliver originهمان گفتگویی که کار را ساخته ‏(پیش‌فرض)
local--deliver localفقط در فایل محلی ذخیره شود
telegram--deliver telegramکانال خانگی تلگرام شما
discord--deliver discordکانال خانگی دیسکورد شما
slack--deliver slackکانال خانگی اسلک شما
گفتگوی مشخص--deliver telegram:-1001234567890یک گروه تلگرامی مشخص
رشته‌دار--deliver telegram:-1001234567890:17585تاپیک مشخص تلگرام
Bot Chat--deliver bot-chatخروجی وارد Bot Chat متعارف همین پروفایل می‌شود — بات می‌خواند و پاسخ می‌دهد
Bot Chat ‏(نام‌دار)--deliver bot-chat:researchBot Chat ی پروفایل محلی دیگر

تحویل Bot Chat

مقصدهای bot-chat خروجی کار را به‌صورت یک پیام واقعی داخل نشست «Bot Chat» ی متعارف پروفایل تحویل می‌دهند — بات مثل هر پیام دیگری دریافتش می‌کند، هر چه نیاز به اقدام دارد انجام می‌دهد و همان‌جا پاسخ می‌دهد. هدفی که باید استفاده کنید وقتی می‌خواهید بات خروجی زمان‌بندی‌شده را ببیند و واکنش نشان دهد نه اینکه فقط در تاریخچهٔ Run آرشیو شود.

چیزهایی که باید بدانید:

  • محلی-به-ماشین.پروفایل باید روی ماشینی که زمان‌بند روش اجراست موجود باشد ‏(hermes profile list). نام‌ها هنگام ساخت اعتبارسنجی می‌شوند؛ پروفایل‌های گیت‌وی/ماشین دیگر قابل هدف‌گیری نیستند.
  • هزینهٔ یک نوبت بات دارد.هر تحویل یک نوبت کامل ایجنت در Bot Chat ی بات مقصد اجرا می‌کند — برای کارهای پرتکرار بودجه‌بندی کنید.
  • ترکیب‌شدنی.‏--deliver bot-chat,telegram هم به بات پست می‌کند هم کانال خانگی تلگرام شما. توکن all هرگز به مقاصد bot-chat باز نمی‌شود.
  • پیام تحویل‌شده پیشوندی دارد تا بات بداند از یک کار زمان‌بندی‌شده آمده نه از شما.

۷ نکته‌ها

  • پرامپت‌ها را خودبسنده کنید.ایجنت در کار cron هیچ حافظه‌ای از گفتگوهایتان ندارد. URL ها، نام مخازن، ترجیحات قالب و دستورالعمل‌های تحویل را مستقیم در پرامپت بیاورید.
  • [SILENT] را عامدانه استفاده کنید.برای کارهای پایش دستوری مثل «اگر چیزی عوض نشد فقط ‎[SILENT]‎ پاسخ بده» اضافه کنید. از ایجنت نخواهید در حالت بی‌اتفاق توکن را توضیح دهد — cron مقدار [SILENT] را نشانگر سرکوب تحویل می‌گیرد.
  • برای جمع‌آوری داده از اسکریپت استفاده کنید.پارامتر script اجازه می‌دهد یک اسکریپت پایتونی بخش‌های کسل‌کننده را هندل کند ‏(درخواست‌های HTTP، ورودی/خروجی فایل، پیگیری وضعیت). ایجنت فقط stdout اسکریپت را می‌بیند و رویش استدلال می‌کند. ارزان‌تر و مطمئن‌تر از این است که خود ایجنت گیرش بیندازد.
  • با ‎/cron run‎ تست کنید.قبل از انتظار برای زمان‌بندی، با ‎/cron run <job_id>‎ بلافاصله اجرا کنید و درستی خروجی را تأیید کنید.
  • عبارات زمان‌بندی.قالب‌های پشتیبانی‌شده: تأخیر نسبی ‏(30m)، بازه‌ای ‏(every 2h)، عبارت استاندارد cron ‏(0 9 * * *) و مهر زمانی ISO ‏(2025-06-15T09:00:00). زبان طبیعی مثل daily at 9am پشتیبانی نمی‌شود — از 0 9 * * * استفاده کنید.

برای مرجع کامل cron — همهٔ پارامترها، حالت‌های مرزی و جزئیات داخلی — بخش وظایف زمان‌بندی‌شده ‏(Cron) را ببینید.
