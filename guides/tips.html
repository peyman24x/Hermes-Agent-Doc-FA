نکات و بهترین شیوه‌ها

مجموعه‌ای از بردهای سریع: نکته‌های عملی که بلافاصله با هرمس مؤثرترتان می‌کند. هر بخش به جنبهٔ متفاوتی می‌پردازد — سرتیترها را اسکن کنید و به بخش مربوطه بپرید.

💡

گیج شدید کدام مدل را بردارید؟
‏hermes setup --portal را اجرا کنید — بیش از ۳۰۰ مدل شامل Claude، ‏GPT-5 و Gemini زیر یک اشتراک می‌گیرید. Nous Portal را ببینید.

۱ گرفتن بهترین نتیجه‌ها

دقیق بگویید چه می‌خواهید

پرامپت مبهم نتیجهٔ مبهم می‌دهد. به‌جای «کد رو درست کن» بگویید «خطای TypeError در api/handlers.py خط ۴۷ رو درست کن — تابع process_request() از parse_body() مقدار None می‌گیره». هرچی زمینه بیشتر، تکرار کمتر.

زمینه را از اول بدهید

درخواست‌تان را با جزئیات مربوطه شروع کنید: مسیر فایل‌ها، پیام‌های خطا، رفتار موردانتظار. یک پیام خوب‌ساخته از سه دور روشن‌سازی بهتر است. traceback های خطا را مستقیم بچسبانید — ایجنت می‌تواند parse شان کند.

برای دستورالعمل‌های تکراری از فایل‌های زمینه استفاده کنید

اگر دیدید مدام همان دستورالعمل‌ها را تکرار می‌کنید ‏(«تب نه، فاصله»، «ما pytest استفاده می‌کنیم»، «API روی /api/v2 است»)، آن‌ها را در یک فایل AGENTS.md بگذارید. ایجنت هر نشست خودکار می‌خواندش — بعد از راه‌اندازی صفر زحمت.

بگذارید ایجنت از ابزارهایش استفاده کند

سعی نکنید هر قدم را دستش بگیرید. بگویید «تست خراب رو پیدا و درست کن» نه «فایل tests/test_foo.py رو باز کن، خط ۴۲ رو ببین بعد...». ایجنت جستجوی فایل، دسترسی ترمینال و اجرای کد دارد — بگذارید کاوش و تکرار کند.

برای گردش‌کارهای پیچیده از مهارت‌ها استفاده کنید

قبل از اینکه پرامپت بلندی دربارهٔ «چطور یک کار انجام شود» بنویسید، چک کنید مهارت آماده‌اش هست یا نه. ‎/skills‎ را بزنید تا مهارت‌های موجود را ببینید یا مستقیم صدایشان کنید مثل ‎/axolotl‎ یا ‎/github-pr-workflow‎.

۲ نکات کاربر حرفه‌ای CLI

ورودی چندخطی

برای درج خط جدید بدون ارسال، ‏Alt+Enter یا ‏Ctrl+J یا ‏Shift+Enter را بزنید. Shift+Enter فقط وقتی کار می‌کند که ترمینال آن را ضربهٔ مجزا بفرستد ‏(Kitty / foot / WezTerm / Ghostty به‌صورت پیش‌فرض؛ iTerm2 / Alacritty / ترمینال VS Code بعد از فعال کردن پروتکل کیبورد Kitty). دو تای دیگر در همهٔ ترمینال‌ها کار می‌کنند.

تشخیص چسباندن

CLI چسباندن‌های چندخطی را خودکار تشخیص می‌دهد. بلوک کد یا traceback خطا را مستقیم بچسبانید — هر خط جدا فرستاده نمی‌شود. کل paste بافر و یک‌جا ارسال می‌شود.

قطع کردن و تغییر مسیر

یک بار Ctrl+C بزنید تا ایجنت وسط پاسخ قطع شود. بعد می‌توانید پیام جدیدی تایپ کنید تا مسیرش را عوض کنید. دو بار Ctrl+C در بازهٔ ۲ ثانیه خروج اجباری است. وقتی ایجنت راه اشتباه می‌رود طلاست.

ازسرگیری نشست‌ها با ‎-c‎

چیزی از نشست آخر یادتان رفته؟ hermes -c را اجرا کنید تا دقیقاً از همان‌جا ادامه دهید با تاریخچه کامل گفتگو. با عنوان هم می‌توانید ادامه دهید: hermes -r "my research project".

چسباندن تصویر از کلیپ‌بورد

Ctrl+V را بزنید تا تصویر از کلیپ‌بورد مستقیم داخل گفتگو بیاید. ایجنت با بینایی، اسکرین‌شات، دیاگرام، پاپ‌آپ خطا یا ماکت UI را تحلیل می‌کند — لازم نیست اول در فایل ذخیره کنید.

تکمیل خودکار فرمان‌های اسلش

‏/‎ را تایپ و Tab را بزنید تا همهٔ فرمان‌ها را ببینید. هم فرمان‌های داخلی ‏(/compress، ‏/model، ‏/title) و هم تک‌تک مهارت‌های نصب‌شده. چیزی لازم نیست حفظ باشید — Tab همه را پوشش می‌دهد.

💡

با ‎/verbose‎ بین حالت‌های نمایش خروجی ابزار بچرخید: off ← new ← all ← verbose. حالت all برای تماشای کارِ ایجنت عالی است؛ off برای پرسش‌وپاسخ ساده تمیزترین است.

۳ فایل‌های زمینه

AGENTS.md: مغز پروژهٔ شما

یک AGENTS.md در ریشهٔ پروژه بسازید با تصمیم‌های معماری، قراردادهای کدنویسی و دستورالعمل‌های مخصوص پروژه. این خودکار در هر نشست تزریق می‌شود، پس ایجنت همیشه قوانین پروژه‌تان را می‌داند.

# Project Context
- This is a FastAPI backend with SQLAlchemy ORM
- Always use async/await for database operations
- Tests go in tests/ and use pytest-asyncio
- Never commit .env files

SOUL.md: شخصی‌سازی شخصیت

می‌خواهید هرمس صدای پیش‌فرض پایداری داشته باشد؟ ~/.hermes/SOUL.md را ویرایش کنید ‏(یا $HERMES_HOME/SOUL.md اگر خانهٔ سفارشی برای هرمس دارید). هرمس حالا خودکار یک SOUL آغازین می‌کارد و همان فایل global را منبع شخصیت کل نمونه می‌گیرد.

مرور کامل را در استفاده از SOUL.md با هرمس ببینید.

# Soul
You are a senior backend engineer. Be terse and direct.
Skip explanations unless asked. Prefer one-liners over verbose solutions.
Always consider error handling and edge cases.

‏SOUL.md برای شخصیت ماندگار. AGENTS.md برای دستورالعمل‌های مخصوص پروژه.

سازگاری با cursorrules.

از قبل فایل ‎.cursorrules‎ یا ‎.cursor/rules/*.mdc‎ دارید؟ هرمس آن‌ها را هم می‌خواند. لازم نیست قراردادهای کدنویسی‌تان را دو جا بنویسید — خودکار از پوشهٔ کاری بارگذاری می‌شوند.

کشف

هرمس AGENTS.md ی سطح‌بالای پوشهٔ کاری فعلی را هنگام شروع نشست بار می‌کند. فایل‌های AGENTS.md ی زیرپوشه‌ها هنگام فراخوانی ابزار به‌صورت lazy کشف می‌شوند ‏(از طریق subdirectory_hints.py) و داخل نتایج ابزار تزریق می‌شوند — از اول داخل system prompt بارگذاری نمی‌شوند.

💡

فایل‌های زمینه را متمرکز و موجز نگه دارید. هر کاراکتر از بودجهٔ توکن شما حساب می‌شود چون در تک‌تک پیام‌ها تزریق می‌شوند.

۴ حافظه و مهارت‌ها

حافظه در برابر مهارت‌ها: چه چیزی کجا

حافظه برای واقعیت‌هاست: محیط شما، ترجیحات، جای پروژه‌ها و چیزهایی که ایجنت درباره‌تان یاد گرفته. مهارت‌ها برای رویه‌هاست: گردش‌کارهای چندمرحله‌ای، دستورالعمل‌های مخصوص ابزار و دستورالعمل‌های قابل‌استفادهٔ مجدد. حافظه برای «چه»، مهارت برای «چگونه».

کی مهارت بسازیم

کاری پیدا کردید که ۵ قدم یا بیشتر دارد و دوباره انجامش خواهید داد؟ از ایجنت بخواهید برایش مهارت بسازد. بگویید «همین کاری که الان کردی رو به‌عنوان مهارتی به اسم deploy-staging ذخیره کن». دفعهٔ بعد فقط ‎/deploy-staging‎ را بزنید و ایجنت کل رویه را بار می‌کند.

مدیریت ظرفیت حافظه

حافظه عمداً محدود است ‏(حدود ۲٬۲۰۰ کاراکتر برای MEMORY.md و حدود ۱٬۳۷۵ کاراکتر برای USER.md). وقتی پر شود ایجنت مدخل‌ها را ادغام می‌کند. می‌توانید کمکش کنید: بگویید «حافظه‌ات رو مرتب کن» یا «یادداشت قدیمی Python 3.9 رو بردار — ما حالا روی ۳.۱۲ هستیم».

بگذارید ایجنت به یاد بسپارد

بعد از یک نشست پربار بگویید «این‌ها رو واسه دفعهٔ بعد یادت بمونه» و ایجنت نکات کلیدی را ذخیره می‌کند. مشخص هم می‌توانید باشید: «تو حافظه ذخیره کن که CI ما GitHub Actions با گردش‌کار deploy.yml است».

⚠️

حافظه یک اسنپ‌شات منجمد است — تغییرات وسط نشست تا شروع نشست بعد وارد system prompt نمی‌شوند. ایجنت بلافاصله روی دیسک می‌نویسد ولی کش پرامپت وسط نشست باطل نمی‌شود.

۵ کارایی و هزینه

کش پرامپت را نشکنید

بیشتر ارائه‌دهندگان LLM پیشوند گفتگو را کش می‌کنند ‏(system prompt + تاریخچه). اگر system prompt تان را پایدار نگه دارید ‏(همان فایل‌های زمینه، همان حافظه)، پیام‌های بعدی نشست cache hit می‌گیرند که به‌طور چشمگیری ارزان‌تر است. کش به مدل و حساب کلید خورده — پس سوئیچ صریح ‎/model‎ یا fallback خودکار ارائه‌دهنده یا چرخش استخر credential همه نوبت بعد را مجبور می‌کند کل گفتگو را با قیمت کامل ورودی دوباره بخواند. سوئیچ گاه‌به‌گاه اشکالی ندارد؛ سوئیچ مکرر در نشستی طولانی هزینه‌تان را ضربدر می‌کند.

قبل از خوردن به سقف ‎/compress‎ بزنید

نشست‌های طولانی توکن جمع می‌کنند. وقتی دیدید پاسخ‌ها کند شده یا قطع می‌شوند ‎/compress‎ را اجرا کنید. این تاریخچهٔ گفتگو را خلاصه می‌کند، زمینهٔ کلیدی را حفظ و توکن را به‌طور چشمگیری کم می‌کند. با ‎/usage‎ وضعیت را چک کنید.

برای کار موازی واگذار کنید

سه موضوع را باید هم‌زمان بررسی کنید؟ از ایجنت بخواهید delegate_task با زیروظایف موازی استفاده کند. هر زیرایجنت مستقل با زمینهٔ خودش اجرا می‌شود و فقط خلاصه‌های نهایی برمی‌گردند — مصرف توکن گفتگوی اصلی‌تان را به‌شدت کم می‌کند.

برای عملیات دسته‌ای از execute_code استفاده کنید

به‌جای اجرای فرمان‌های ترمینالی یکی‌یکی، از ایجنت بخواهید اسکریپتی بنویسد که همه را یک‌جا انجام دهد. «یه اسکریپت پایتون بنویس همهٔ فایل‌های jpeg. رو به jpg. تغییر نام بده و اجراش کن» ارزان‌تر و سریع‌تر از تغییر نام تک‌تک است.

مدل درست را انتخاب کنید

با ‎/model‎ وسط نشست سوئیچ کنید. برای reasoning و تصمیم‌های معماری از مدل frontier ‏(Claude Sonnet/Opus، ‏GPT-4o) استفاده کنید. برای کارهای ساده مثل قالب‌بندی، تغییر نام یا تولید boilerplate به مدلی سریع‌تر سوئیچ کنید. در نظر داشته باشید هر سوئیچ کش پرامپت را ریست می‌کند ‏(بالا را ببینید)؛ پس در نشست‌های طولانی اغلب ارزان‌تر است که روی مدل دیگر یک نشست تازه شروع کنید تا رفت‌وبرگشت کنید.

💡

دوره‌ای ‎/usage‎ را اجرا کنید تا مصرف توکن تان را ببینید. ‎/insights‎ نمای وسیع‌تری از الگوهای مصرف ۳۰ روز اخیر می‌دهد. برای دیدن هزینهٔ ثابت per-پیام قبل از هر گفتگو — system prompt، فهرست مهارت‌ها، حافظه، اسکیماهای ابزار — ‏hermes prompt-size را اجرا کنید ‏(آفلاین هم کار می‌کند).

۶ نکات پیام‌رسانی

کانال خانگی ست کنید

در گفتگوی تلگرام یا دیسکورد موردعلاقه‌تان ‎/sethome‎ را بزنید تا کانال خانگی شود. نتایج کارهای Cron و خروجی وظایف زمان‌بندی‌شده اینجا تحویل داده می‌شوند. بدون آن، ایجنت جایی برای فرستادن پیام‌های پیش‌دستانه ندارد.

با ‎/title‎ نشست‌ها را سازماندهی کنید

نشست‌هایتان را نام‌دار کنید: ‎/title auth-refactor‎ یا ‎/title research-llm-quantization‎. نشست‌های نام‌دار با hermes sessions list راحت پیدا و با hermes -r "auth-refactor" ادامه می‌یابند. نشست‌های بی‌اسم روی هم تلنبار می‌شوند و غیرقابل تفکیک.

جفت‌سازی DM برای دسترسی تیمی

به‌جای جمع کردن دستی شناسهٔ کاربران برای allowlist، جفت‌سازی DM را فعال کنید. وقتی هم‌تیمی به بات DM بدهد یک کد جفت‌سازی یک‌بارمصرف می‌گیرد. شما با hermes pairing approve telegram XKGH5N7P تأیید می‌کنید — ساده و امن.

حالت‌های نمایش پیشرفت ابزار

با ‎/verbose‎ کنترل کنید چقدر فعالیت ابزار ببینید. در پلتفرم‌های پیام‌رسانی معمولاً کمتر بهتر است — روی new بمانید تا فقط فراخوانی‌های جدید ابزار را ببینید. در CLI حالت all نمای زندهٔ رضایت‌بخشی از همهٔ کارهای ایجنت می‌دهد.

💡

به‌طور پیش‌فرض نشست‌های پیام‌رسانی هرگز خودکار ریست نمی‌شوند — زمینه تا وقتی ‎/reset‎ بزنید یا فشرده‌سازی فعال شود می‌ماند. اگر می‌خواهید نشست‌ها خودکار ریست شوند ‏(بعد از بی‌کاری یا روزانه ساعت معین) از طریق بخش session_reset در ~/.hermes/config.yaml opt-in کنید.

۷ امنیت

برای کد نامطمئن از Docker استفاده کنید

وقتی با مخازن نامطمئن کار می‌کنید یا کد ناآشنا اجرا می‌کنید، Docker یا Daytona را به‌عنوان backend ترمینال ست کنید. TERMINAL_ENV=docker را در .env بگذارید. فرمان‌های مخرب داخل کانتینر نمی‌توانند به سیستم host آسیب بزنند.

# In your .env:
TERMINAL_ENV=docker
TERMINAL_DOCKER_IMAGE=hermes-sandbox:latest

از دام‌های انکودینگ ویندوز بپرهیزید

روی ویندوز بعضی انکودینگ‌های پیش‌فرض ‏(مثل cp125x) نمی‌توانند همهٔ کاراکترهای یونیکد را نشان دهند و موقع نوشتن فایل در تست‌ها یا اسکریپت‌ها UnicodeEncodeError می‌دهند.

  • باز کردن فایل‌ها با انکودینگ صریح UTF-8 را ترجیح دهید: 
    with open("results.txt", "w", encoding="utf-8") as f:
    f.write("✓ All good\n")
  • در PowerShell می‌توانید نشست فعلی را برای خروجی کنسول و فرمان‌های native به UTF-8 ببرید: 
    $OutputEncoding = [Console]::OutputEncoding = [Text.UTF8Encoding]::new($false)

این کار PowerShell و فرایندهای فرزند را روی UTF-8 نگه می‌دارد و از شکست‌های مخصوص-ویندوز جلوگیری می‌کند.

قبل از انتخاب «همیشه» بازبینی کنید

وقتی ایجنت تأیید فرمان خطرناک را فعال کند ‏(rm -rf، ‏DROP TABLE و...) چهار گزینه دارید: once، ‏session، ‏always، ‏deny. قبل از انتخاب always خوب فکر کنید — آن الگو را برای همیشه allowlist می‌کند. تا وقتی مطمئن نشده‌اید با session شروع کنید.

تأیید فرمان توری امنیتی شماست

هرمس هر فرمان را قبل از اجرا با فهرستی منتخب از الگوهای خطرناک چک می‌کند: حذف بازگشتی، ‏SQL drop، پایپ curl به شل و بیشتر. این را در production خاموش نکنید — دلیل خوبی برای وجودش هست.

⚠️

هنگام اجرا با backend کانتینری ‏(Docker، ‏Singularity، ‏Modal، ‏Daytona) چک‌های فرمان خطرناک رد می‌شوند چون خود کانتینر مرز امنیتی است. مطمئن شوید ایمیج‌های کانتینرتان درست قفل شده‌اند.

برای بات‌های پیام‌رسان از allowlist استفاده کنید

هرگز GATEWAY_ALLOW_ALL_USERS=true را روی باتی با دسترسی ترمینال ست نکنید. همیشه از allowlist های مخصوص پلتفرم ‏(TELEGRAM_ALLOWED_USERS، ‏DISCORD_ALLOWED_USERS) یا جفت‌سازی DM استفاده کنید تا کنترل کنید چه کسی با ایجنت تان حرف می‌زند.

# Recommended: explicit allowlists per platform
TELEGRAM_ALLOWED_USERS=123456789,987654321
DISCORD_ALLOWED_USERS=123456789012345678

# Or use cross-platform allowlist
GATEWAY_ALLOWED_USERS=123456789,987654321

نکته‌ای دارید که باید در این صفحه باشد؟ issue یا PR باز کنید — مشارکت‌های اجتماعی خوش‌آمدند.
