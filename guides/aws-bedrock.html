AWS Bedrock

Hermes Agent از Amazon Bedrock به‌عنوان یک ارائه‌دهندهٔ بومی پشتیبانی می‌کند. این قابلیت دسترسی کامل به اکوسیستم Bedrock را فراهم می‌کند: احراز هویت IAM، ‏Guardrails، پروفایل‌های استنتاج میان‌منطقه‌ای و همهٔ مدل‌های پایه.

هرمس هر خانوادهٔ مدل را از طریق API مناسب آن مسیریابی می‌کند:

خانوادهٔ مدلمسیر APIدلیل
Anthropic ClaudeAnthropic SDK (AnthropicBedrock)کش پرامپت، بودجهٔ تفکر و تفکر تطبیقی — قابلیت‌هایی که از طریق Converse ارائه نمی‌شوند
OpenAI GPT-5.5 / GPT-5.6 (Sol، Terra، Luna)نقطهٔ پایانی OpenAI Responses در Bedrock Mantle (bedrock-mantle.<region>.api.aws/openai/v1)این مدل‌ها فقط در Mantle ارائه می‌شوند — کارت مدل آن‌ها، پشتیبانی از bedrock-runtime/Converse را رد می‌کند
سایر مدل‌ها (Nova، DeepSeek، Llama، GPT-OSS و…)Converse API بومی (bedrock-runtime)مجموعهٔ کامل قابلیت‌های Bedrock: ‏Guardrails، پروفایل‌های استنتاج و استریم

هر سه مسیر از زنجیرهٔ اعتبارنامهٔ AWS و سازوکار تعیین منطقهٔ یکسانی استفاده می‌کنند — به پیکربندی جداگانه نیازی نیست. درخواست‌های نقطهٔ پایانی Mantle در صورت تنظیم AWS_BEARER_TOKEN_BEDROCK با آن احراز هویت می‌شوند؛ در غیر این صورت، از طریق زنجیرهٔ استاندارد اعتبارنامهٔ boto3 با SigV4 امضا می‌شوند.

۱ پیش‌نیازها

  • اعتبارنامه‌های AWS — هر منبعی که زنجیرهٔ اعتبارنامهٔ boto3 پشتیبانی کند:
    • نقش IAM نمونه (EC2، ECS، Lambda — بدون پیکربندی)
    • متغیرهای محیطی AWS_ACCESS_KEY_ID و AWS_SECRET_ACCESS_KEY
    • AWS_PROFILE برای SSO یا پروفایل‌های نام‌دار
    • aws configure برای توسعهٔ محلی
  • boto3 — نصب با cd ~/.hermes/hermes-agent && uv pip install -e ".[bedrock]"
  • مجوزهای IAM — دست‌کم:
    • bedrock:InvokeModel و bedrock:InvokeModelWithResponseStream (برای استنتاج)
    • bedrock:ListFoundationModels و bedrock:ListInferenceProfiles (برای کشف مدل)
نکته — EC2 / ECS / Lambda

روی منابع محاسباتی AWS، یک نقش IAM با AmazonBedrockFullAccess متصل کنید و کار تمام است. نه کلید API لازم است، نه پیکربندی .env — هرمس نقش نمونه را خودکار تشخیص می‌دهد.

۲ شروع سریع

# Install with Bedrock support
cd ~/.hermes/hermes-agent && uv pip install -e ".[bedrock]"

# Select Bedrock as your provider
hermes model
# → Choose "More providers..." → "AWS Bedrock"
# → Select your region and model

# Start chatting
hermes chat

۳ پیکربندی

پس از اجرای hermes model، فایل ~/.hermes/config.yaml شامل این موارد خواهد بود:

model:
  default: us.anthropic.claude-sonnet-4-6
  provider: bedrock
  base_url: https://bedrock-runtime.us-east-2.amazonaws.com

bedrock:
  region: us-east-2

منطقه

منطقهٔ AWS را به یکی از روش‌های زیر تنظیم کنید (به‌ترتیب از بالاترین اولویت):

  1. bedrock.region در config.yaml
  2. متغیر محیطی AWS_REGION
  3. متغیر محیطی AWS_DEFAULT_REGION
  4. پیش‌فرض: us-east-1

محافظ‌ها (Guardrails)

برای اعمال Amazon Bedrock Guardrails به همهٔ فراخوانی‌های مدل:

bedrock:
  region: us-east-2
  guardrail:
    guardrail_identifier: "abc123def456"  # From the Bedrock console
    guardrail_version: "1"                # Version number or "DRAFT"
    stream_processing_mode: "async"       # "sync" or "async"
    trace: "disabled"                     # "enabled", "disabled", or "enabled_full"

محافظ در مسیر Converse از طریق guardrailConfig و در مسیر Claude از طریق هدرهای InvokeModel در Anthropic Bedrock SDK متصل می‌شود؛ بنابراین کش پرامپت و تفکر حفظ می‌شوند. درخواست مسدودشده به‌صورت رد درخواست توسط فیلتر محتوا نمایش داده می‌شود، نه متن مدل. stream_processing_mode فقط در Converse کاربرد دارد.

AWS محافظ‌های Guardrails را روی نقطهٔ پایانی Mantle Responses که مدل‌های openai.gpt-5.x استفاده می‌کنند اعمال نمی‌کند (مستندات AWS)؛ اگر به محافظ نیاز دارید، مدلی را انتخاب کنید که از طریق Converse ارائه می‌شود.

کشف مدل

هرمس مدل‌های در دسترس را از طریق صفحهٔ کنترل Bedrock خودکار کشف می‌کند. می‌توانید کشف مدل را سفارشی کنید:

bedrock:
  discovery:
    enabled: true
    provider_filter: ["anthropic", "amazon"]  # Only show these providers
    refresh_interval: 3600                     # Cache for 1 hour

کش پرامپت (cachePoint)

هرمس در مسیر Converse API در Bedrock، با افزودن نشانگرهای cachePoint پس از پرامپت سیستم، تعریف ابزارها و آخرین پیام، کش پرامپت را خودکار اعمال می‌کند. چون ارسال بلوک cachePoint به مدلی که از آن پشتیبانی نمی‌کند، خطای ValidationException ایجاد می‌کند، نشانگرها فقط برای مدل‌های فهرست مجازِ تأییدشده (شناسه‌های مدل Anthropic Claude و Amazon Nova) اضافه می‌شوند؛ مدل‌های ناشناخته به‌طور پیش‌فرض نشانگر کش ندارند. مدل‌های Claude معمولاً از مسیر AnthropicBedrock SDK استفاده می‌کنند که کش پرامپت خودش را دارد — مسیر cachePoint در Converse، مدل Nova و مسیر پشتیبان Claude با توکن حامل را پوشش می‌دهد. پیکربندی لازم نیست؛ خواندن و نوشتن کش در محاسبهٔ مصرف نمایش داده می‌شود.

سنجش پنجرهٔ زمینه

برای مدل‌هایی که پنجرهٔ زمینهٔ آن‌ها در جدول ثابت هرمس نیست، هرمس می‌تواند با ارسال درخواست‌های بیش‌ازحد بزرگ در سطوح ثابت (حدود ۱٫۳ و ۲٫۲ میلیون توکن) و خواندن مقدار maximum گزارش‌شده در خطای اعتبارسنجی طول Bedrock، حد واقعی را بسنجد. مقادیر سنجیده‌شده وارد همان کش فرادادهٔ جدول ثابت می‌شوند؛ ورودی‌های کهنهٔ کش که پنجرهٔ مدل را کمتر از واقع گزارش می‌کنند (مثلاً ورودی‌هایی که پیش از عرضهٔ عمومی پنجرهٔ یک‌میلیونی مدل ثبت شده‌اند)، خودکار حذف می‌شوند و مقدار بزرگ‌ترِ شناخته‌شده جای آن‌ها را می‌گیرد.

۴ مدل‌های در دسترس

مدل‌های Bedrock برای فراخوانی درخواستی از شناسه‌های پروفایل استنتاج استفاده می‌کنند. انتخاب‌گر hermes model این موارد را خودکار نمایش می‌دهد و مدل‌های پیشنهادی را در بالای فهرست می‌آورد:

توجه — استنتاج میان‌منطقه‌ای

مدل‌هایی با پیشوند us. از پروفایل‌های استنتاج میان‌منطقه‌ای استفاده می‌کنند که ظرفیت بهتر و انتقال خودکار هنگام خرابی را در مناطق AWS فراهم می‌کنند. مدل‌هایی با پیشوند global. در همهٔ مناطق در دسترس جهان مسیریابی می‌شوند. شناسه‌های مدل openai.* از OpenAI را Bedrock Mantle در منطقهٔ پیکربندی‌شده ارائه می‌کند و این مدل‌ها از پیشوندهای پروفایل استنتاج استفاده نمی‌کنند.

۵ تغییر مدل در میانهٔ نشست

در طول گفتگو از فرمان /model استفاده کنید:

/model us.amazon.nova-pro-v1:0
/model deepseek.v3.2
/model us.anthropic.claude-opus-4-6-v1

۶ بررسی‌های تشخیصی

hermes doctor

فرمان doctor موارد زیر را بررسی می‌کند:

  • در دسترس بودن اعتبارنامه‌های AWS (متغیرهای محیطی، نقش IAM، ‏SSO)
  • نصب بودن boto3
  • قابل‌دسترسی بودن API ‏Bedrock (ListFoundationModels)
  • تعداد مدل‌های در دسترس در منطقهٔ شما

۷ گیت‌وی (پلتفرم‌های پیام‌رسانی)

Bedrock با همهٔ پلتفرم‌های گیت‌وی هرمس (Telegram، Discord، Slack، Feishu و غیره) کار می‌کند. Bedrock را به‌عنوان ارائه‌دهنده پیکربندی کنید، سپس گیت‌وی را به‌شکل معمول راه‌اندازی کنید:

hermes gateway setup
hermes gateway start

گیت‌وی config.yaml را می‌خواند و از همان پیکربندی ارائه‌دهندهٔ Bedrock استفاده می‌کند.

۸ عیب‌یابی

«کلید API پیدا نشد» / «اعتبارنامهٔ AWS وجود ندارد»

هرمس اعتبارنامه‌ها را به این ترتیب بررسی می‌کند:

  1. AWS_BEARER_TOKEN_BEDROCK
  2. AWS_ACCESS_KEY_ID و AWS_SECRET_ACCESS_KEY
  3. AWS_PROFILE
  4. فرادادهٔ نمونهٔ EC2 ‏(IMDS)
  5. اعتبارنامه‌های کانتینر ECS
  6. نقش اجرای Lambda

اگر هیچ‌کدام پیدا نشد، aws configure را اجرا کنید یا یک نقش IAM به نمونهٔ محاسباتی خود متصل کنید.

«فراخوانی شناسهٔ مدل … با توان عملیاتی درخواستی پشتیبانی نمی‌شود»

به‌جای شناسهٔ خام مدل پایه، از شناسهٔ پروفایل استنتاج (با پیشوند us. یا global.) استفاده کنید. برای مثال:

  • نادرست: anthropic.claude-sonnet-4-6
  • درست: us.anthropic.claude-sonnet-4-6

ThrottlingException

به محدودیت نرخ Bedrock برای این مدل رسیده‌اید. هرمس خودکار با فاصلهٔ زمانی افزایشی دوباره تلاش می‌کند. برای افزایش محدودیت‌ها، در کنسول AWS Service Quotas درخواست افزایش سهمیه بدهید.
