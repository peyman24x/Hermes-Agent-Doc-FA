نصب

هرمس ایجنت (Hermes Agent) را در کمتر از دو دقیقه آمادهٔ کار کنید!

💡 پشتیبانی پلتفرم‌ها

برای ماتریس کامل پشتیبانی (کدام سیستم‌عامل‌ها، روش‌های توزیع و قابلیت‌های وابسته به پلتفرم پشتیبانی می‌شوند) به صفحهٔ پشتیبانی پلتفرم‌ها مراجعه کنید.

۱ نصب سریع

با نصب‌کنندهٔ Hermes Desktop در مک یا ویندوز (توصیه‌شده)

برای نصب آسانِ هم‌زمانِ اپلیکیشن‌های خط فرمان و دسکتاپ، نصب‌کنندهٔ Hermes Desktop را از وب‌سایت ما دانلود و اجرا کنید.

بدون Hermes Desktop

برای نصبِ فقط-خط‌فرمان بدون Hermes Desktop، این را اجرا کنید:

لینوکس / مک / WSL2 / اندروید (Termux)

bash
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash

ویندوز (بومی)

در PowerShell اجرا کنید:

powershell
iex (irm https://hermes-agent.nousresearch.com/install.ps1)

اگر بعد از یک نصبِ فقط-خط‌فرمان بخواهید Hermes Desktop را هم نصب و اجرا کنید، کافی است این را بزنید:

bash
hermes desktop

نصب‌کننده چه کاری انجام می‌دهد؟

نصب‌کننده همه‌چیز را خودکار انجام می‌دهد — تمام وابستگی‌ها (Python، Node.js، ripgrep و ffmpeg)، کلون مخزن، محیط مجازی، راه‌اندازی فرمان سراسری hermes و پیکربندی ارائه‌دهندهٔ LLM. در پایان کار، آمادهٔ گفتگو هستید.

چیدمان نصب

محل قرارگیری فایل‌ها به نصب‌کننده بستگی دارد؛ اینکه به‌عنوان کاربر عادی نصب می‌کنید یا به‌عنوان root:

نصب‌کنندهمحل کدباینری hermesپوشهٔ داده
به‌ازای-کاربر (نصب‌کنندهٔ git)~/.hermes/hermes-agent/~/.local/bin/hermes (سیم‌لینک)~/.hermes/
حالت root (sudo curl … | sudo bash)/usr/local/lib/hermes-agent//usr/local/bin/hermes/root/.hermes/ (یا $HERMES_HOME)

چیدمانِ FHS در حالت root (/usr/local/lib/… و /usr/local/bin/hermes) همان‌جایی است که سایر ابزارهای توسعهٔ سراسریِ سیستم روی لینوکس نصب می‌شوند. این حالت برای استقرار روی ماشین‌های مشترک مفید است که در آن یک نصب سیستمی باید به همهٔ کاربران سرویس بدهد. پیکربندیِ به‌ازای-کاربر (احراز هویت، مهارت‌ها، نشست‌ها) همچنان زیر ~/.hermes/ هر کاربر یا HERMES_HOME صریح قرار می‌گیرد.

پس از نصب

شل را دوباره بارگذاری کنید و شروع به گفتگو کنید:

bash
source ~/.bashrc   # یا: source ~/.zshrc
hermes             # شروع گفتگو!

برای پیکربندی مجدد تنظیمات مختلف در آینده، از فرمان‌های اختصاصی استفاده کنید:

bash
hermes model          # انتخاب ارائه‌دهنده و مدل LLM
hermes tools          # پیکربندی ابزارهای فعال
hermes gateway setup  # راه‌اندازی پلتفرم‌های پیام‌رسانی
hermes config set     # تنظیم مقادیر پیکربندی تکی
hermes config get     # مشاهدهٔ مقادیر پیکربندی تکی
hermes setup          # یا اجرای ویزارد کامل راه‌اندازی برای پیکربندی همه‌چیز یک‌جا
💡 سریع‌ترین مسیر: Nous Portal

یک اشتراک بیش از ۳۰۰ مدل را پوشش می‌دهد به‌علاوهٔ گیت‌وی ابزار (جستجوی وب، تولید تصویر، TTS، مرورگر ابری). دیگر با کلیدهای جداگانهٔ هر ابزار سروکله نزنید:

bash
hermes setup --portal

این فرمان شما را وارد حساب می‌کند، Nous را به‌عنوان ارائه‌دهندهٔ شما تنظیم می‌کند و گیت‌وی ابزار را در یک دستور فعال می‌کند.

💡 همین حالا هرمس را روی ماشین دیگری اجرا می‌کنید؟

لازم نیست راه‌اندازی‌تان را از صفر بسازید. یک پشتیبان کامل را با hermes import بازیابی کنید (به «صادرات هرمس به ماشین دیگر» مراجعه کنید)، یا تنها یک ایجنت را با hermes profile import منتقل کنید (به «انتقال یک پروفایل به ماشین دیگر» مراجعه کنید). توجه داشته باشید که خروجیِ پروفایل به‌طور عمدی شامل اعتبارنامه‌ها نیست، پس خروجیِ تنها، یک پشتیبان کامل نیست — «hermes backup در برابر hermes profile export» توضیح می‌دهد از کدام استفاده کنید.

۲ پیش‌نیازها

نصب‌کننده: در پلتفرم‌های غیر ویندوزی، تنها پیش‌نیاز Git است. در لینوکس، مطمئن شوید curl و xz-utils موجودند (نصب‌کننده، Node.js را به‌صورت آرشیو .tar.xz دانلود می‌کند). اپلیکیشن دسکتاپ به‌طور اضافه به g++ (یا build-essential در دبیان/اوبونتو) برای کامپایل ماژول‌های نیتیو نیاز دارد. نصب‌کننده بقیهٔ موارد را خودکار مدیریت می‌کند:

  • uv (مدیر پکیج سریع پایتون)
  • Python 3.11 (از طریق uv، بدون نیاز به sudo)
  • Node.js v22 (برای اتوماسیون مرورگر و پل واتساپ)
  • ripgrep (جستجوی سریع فایل)
  • ffmpeg (تبدیل فرمت صوت برای TTS)
ℹ️ توجه

نیازی نیست پایتون، Node.js، ripgrep یا ffmpeg را دستی نصب کنید. نصب‌کننده تشخیص می‌دهد چه چیزی غایب است و آن را برایتان نصب می‌کند. فقط مطمئن شوید git در دسترس است (git --version). در لینوکس، curl و xz-utils نصب باشند (در دبیان/اوبونتو: sudo apt install curl xz-utils). برای اپلیکیشن دسکتاپ، build-essential را هم نصب کنید (sudo apt install build-essential).

💡 کاربران Nix

Nix دیگر یک مسیر نصبِ پشتیبانی‌شدهٔ رسمی نیست (فقط تلاشِ در حد توان). اگر از قبل از Nix استفاده می‌کنید (روی NixOS، مک یا لینوکس)، یک مسیر راه‌اندازی اختصاصی با Nix flake، ماژول تعریف‌محور NixOS و حالت کانتینر اختیاری وجود دارد. به راهنمای «راه‌اندازی Nix و NixOS» مراجعه کنید.

۳ نصب دستی / نصب توسعه‌دهنده

اگر می‌خواهید مخزن را کلون کنید و از سورس نصب کنید — برای مشارکت، اجرا از یک شاخهٔ خاص، یا کنترل کامل روی محیط مجازی — به بخش «راه‌اندازی توسعه» در راهنمای مشارکت مراجعه کنید: Contributing → Development Setup.

۴ نصب بدون Sudo / کاربر سرویس سیستمی

اجرای هرمس با یک کاربرِ بدون امتیازِ اختصاصی (مثلاً یک حساب سرویس systemd با نام hermes، یا هر کاربری که دسترسی sudo ندارد) پشتیبانی می‌شود. تنها چیزی در مسیر نصب که واقعاً به root نیاز دارد، مرحلهٔ --with-deps پلی‌رایت است که با apt کتابخانه‌های مشترک (libnss3، libxkbcommon و غیره) مورد نیاز کرومیوم را نصب می‌کند. نصب‌کننده تشخیص می‌دهد که sudo در دسترس است یا نه و در نبودِ آن به‌ نرم‌ی تنزل می‌کند — باینری کرومیوم را در کش پلی‌رایت خودِ کاربرِ سرویس نصب می‌کند و دقیق‌ترین فرمانی را که مدیر سیستم باید جداگانه اجرا کند چاپ می‌کند.

تقسیم‌بندی توصیه‌شده (دبیان/اوبونتو):

  1. یک بار، به‌عنوان کاربر مدیریتیِ دارای sudo، کتابخانه‌های سیستمی مورد نیاز کرومیوم را نصب کنید:
    bash
    sudo npx playwright install-deps chromium

    (می‌توانید این را از هر جایی اجرا کنید — npx پلی‌رایت را در لحظه دریافت می‌کند.)

  2. به‌عنوان کاربر سرویسِ بدون امتیاز، نصب‌کنندهٔ معمولی را اجرا کنید. نبودِ sudo را تشخیص می‌دهد، --with-deps را رد می‌کند و کرومیوم را در کش محلی پلی‌رایت همان کاربر نصب می‌کند:
    bash
    curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash

    اگر می‌خواهید مرحلهٔ پلی‌رایت را به‌طور کامل رد کنید — مثلاً چون به‌صورت headless اجرا می‌کنید و اتوماسیون مرورگر نمی‌خواهید — پرچم --skip-browser را بدهید:

    bash
    curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash -s -- --skip-browser

    نصب‌کننده همچنین cua-driver را از پیش نصب می‌کند تا تول‌ست «کنترل کامپیوتر» (Computer Use) بلافاصله پس از فعال‌سازی‌اش کار کند؛ با --skip-computer-use می‌توانید از آن صرف‌نظر کنید (آن‌گاه هنگام فعال‌سازی ابزار، در لحظهٔ نیاز نصب خواهد شد).

  3. فرمان hermes را برای شل‌های کاربر سرویس در دسترس کنید. نصب‌کننده لانچر را در ~/.local/bin/hermes می‌نویسد. حساب‌های سرویس سیستمی اغلب PATH مینیمالی دارند که ~/.local/bin را شامل نمی‌شود. یا آن را به محیط کاربر اضافه کنید، یا لانچر را در یک مسیر سیستمی سیم‌لینک کنید:
    bash
    # گزینهٔ A — افزودن به پروفایل کاربر سرویس
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc

# گزینهٔ B — سیم‌لینک سراسری (به‌عنوان مدیر اجرا کنید)
sudo ln -s /home/hermes/.hermes/hermes-agent/venv/bin/hermes /usr/local/bin/hermes
  4. بررسی نهایی: hermes doctor باید بدون خطا اجرا شود. اگر خطای ModuleNotFoundError: No module named 'dotenv' گرفتید، یعنی فایل سورسِ hermes مخزن (~/.hermes/hermes-agent/hermes) را با پایتونِ سیستم اجرا کرده‌اید نه لانچر venv (~/.hermes/hermes-agent/venv/bin/hermes) — گام ۳ را اصلاح کنید.
  5. گیت‌وی پیام‌رسانی را از این حساب اجرا می‌کنید؟ یک سرویس در سطح کاربر با خروج از سیستم متوقف می‌شود و تا وقتی lingering برای کاربر سرویس فعال نشود، هنگام بوت شروع نمی‌شود:
    bash
    sudo loginctl enable-linger <service-user>

    برای خود راه‌اندازی سرویس به «گیت‌وی پیام‌رسانی» مراجعه کنید.

همین الگو روی آرچ (نصب‌کننده از pacman با همان منطق تشخیص sudo استفاده می‌کند)، فدورا/RHEL و openSUSE هم کار می‌کند — این توزیع‌ها اصلاً از --with-deps پشتیبانی نمی‌کنند، پس مدیر سیستم همیشه کتابخانه‌های سیستمی را جداگانه نصب می‌کند. فرمان‌های مربوطهٔ dnf/zypper توسط نصب‌کننده چاپ می‌شوند.

برای تشخیص‌های بیشتر، hermes doctor را اجرا کنید — دقیقاً می‌گوید چه چیزی کم است و چگونه درستش کنید.

۶ تشخیص خودکار روش نصب

هرمس به‌طور خودکار تشخیص می‌دهد که از طریق نصب‌کنندهٔ git، داکر یا NixOS نصب شده است، و hermes update فرمان به‌روزرسانیِ منطبق با همان مسیر را چاپ می‌کند. هیچ متغیر محیطی برای تنظیم وجود ندارد — تشخیص بر اساس چیدمان نصب انجام می‌شود (چک‌اوت ~/.hermes/hermes-agent/، مُهر ایمیج داکر، یا مسیر Nix store). hermes doctor نیز روش تشخیص‌شده را در خلاصهٔ محیط خود نشان می‌دهد.
