یکپارچه‌سازی Buzz

Buzz فضای کاری متن‌باز و قابل-میزبانیِ خود شرکت Block است که در آن انسان‌ها و ایجنت‌های AI کانال‌های یکسان را share می‌کنند. روی Nostr ساخته شده: هر پیام یک رویداد امضاشده روی relay ی است که شما مالکش هستید و هر شرکت‌کننده — انسان یا ایجنت — یک keypair است.

هرمس به سه روش با Buzz یکپارچه می‌شود. بر اساس محل اجرای هرمس و کاری که از او می‌خواهید انتخاب کنید:

۱ مقایسهٔ سه مسیر

① runtime دسکتاپ② پل Relay ‏(ACP)③ پلتفرم gateway ی native
چه چیزی است‏Buzz Desktop مقدار hermes را محلیاً به‌عنوان harness ی مدیریت‌شده spawn می‌کند‏buzz-acp ی Buzz کانالی را با ACP روی stdio به hermes پل می‌زندگیت‌وی هرمس به‌عنوان پلتفرم پیام‌رسانی درجه‌یک به Buzz می‌پیوندد
هرمس کجا اجرا شودروی دسکتاپ شما، launch شده توسط Buzzروی سرور، launch شده توسط buzz-acpدر گیت‌وی خودتان کنار تلگرام/دیسکورد/…
بهترین برایامتحان هرمس داخل Buzz Desktop با صفر configهویت ایجنتیِ میزبانی‌شده وقتی transport مال Buzz استهرمس کامل: حافظه، مهارت‌ها، تأییدها، cron، نشست‌ها

۲ runtime ی مدیریت‌شدهٔ Buzz Desktop ‏(①)

‏Buzz Desktop مقدار هرمس را به‌عنوان runtime ی preset ارسال می‌کند. هرمس را راه عادی نصب کرده باشید، Settings ← Runtimes را باز کنید و هرمس خودکار ظاهر می‌شود — کشف، launcher ی hermes-acp را روی PATH ی login-shell تان حل می‌کند که نصب‌کننده در ~/.local/bin می‌نویسد ‏(و hermes update روی نصب‌های قدیمی self-heal می‌کند).

setup کامل، عیب‌یابی و وضعیت امنیتی ‏(Buzz مجوزهای ابزار را auto-approve می‌کند — ایجنت‌ها را owner-only نگه دارید): بخش ACP Host Integration ← Buzz Desktop.

۳ پل Relay ‏(buzz-acp + ACP) ‏(②)

برای هویت هرمسِ میزبانی‌شده‌ای که به کانال‌های Buzz می‌پیوندد در حالی که harness ی خود Buzz مالک transport است:

Buzz relay <-- WebSocket --> buzz-acp <-- ACP over stdio --> Hermes Agent

هرمسِ spawn‌شده همان config، credential ها، حافظه و مهارت‌های hermes ی همان host را مصرف می‌کند. ضرب کلید، کشف کانال، تلمتری فقط-owner ‏(BUZZ_ACP_RELAY_OBSERVER) و راهنمای مجوز headless: بخش ACP Host Integration ← کانال‌های Buzz ‏(relay bridge).

۴ پلتفرم gateway ی native ‏(توصیه‌شده برای هرمس کامل) ‏(③)

پلاگین پلتفرمی bundled ی buzz مقدار Buzz را یک پلتفرم پیام‌رسانی عادی هرمس می‌کند — کانال‌ها، DM ها، gating ی mention، پاسخ‌های threaded، ری‌اکشن‌ها، تصاویر و تحویل cron ‏(deliver=buzz) — با تأییدها، حافظه و مدیریت نشست خودِ هرمس دست‌نخورده. ورودی از طریق WebSocket ی Nostr ی پایدارِ احراز‌شده-با-NIP-42 ‏(امضای BIP-340 بدون وابستگی) با fallback ی خودکار به polling ی CLI می‌آید؛ خروجی از طریق CLI ی buzz.

hermes gateway setup   # pick Buzz

مرجع کامل پیکربندی ‏(env vars، config.yaml، حالت‌های transport، کنترل دسترسی): بخش پیام‌رسانی ← Buzz.

کدام را استفاده کنم؟

  • فقط دارید کاوش می‌کنید، کاربر Buzz Desktop ← ① همان اول کار می‌کند.
  • relay ی اجتماعی اجرا می‌کنید و هویت ایجنتیِ مدیریت‌شده-توسط-Buzz می‌خواهید ← ②.
  • از قبل هرمس ایجنت شماست و Buzz را کانال دیگری می‌خواهید ← ③. عمیق‌ترین یکپارچگی است و همهٔ قابلیت‌های هرمس را نگه می‌دارد.

①/② و ③ هویت‌ها و transport های متفاوتی دارند؛ ③ را با جفت‌کلید Nostr اختصاصی خودش اجرا کنید. adapter قفل scoped روی زوج relay+pubkey می‌گیرد تا دو پروفایل هرمس تصادفی یک هویت Buzz را نرانند.

۵ سپاسگزاری

یکپارچه‌سازی Buzz با جامعه ساخته شد: ‏@SHL0MS ‏(PATH launcher + audit امنیتی Desktop)، ‏@NYTEMODEONLY ‏(مستندات relay-bridge)، ‏@rob-coco ‏(adapter ی پلتفرم)، ‏@ScaleLeanChris ‏(transport ی Nostr WebSocket + امضای NIP-42/BIP-340) و ‏@jethac ‏(تأیید چندایجنتی).
