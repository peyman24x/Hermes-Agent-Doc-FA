اپلیکیشن دسکتاپ

اپ دسکتاپ هرمس یک اپ بومی است که دور همان ایجنتی که از CLI و گیت‌وی می‌گیرید ساخته شده — همان پیکربندی، همان کلیدهای API، همان نشست‌ها، همان مهارت‌ها، همان حافظه. یک محصول جداگانه یا کلون سبک‌وزن نیست؛ از همان هسته و تنظیمات Hermes Agent استفاده می‌کند و آن را با UI‌ای مدرن و بادقت-طراحی‌شده هدایت می‌کند. اگر hermes را در ترمینال استفاده کرده‌اید، هر چیزی که آنجا راه‌اندازی کرده‌اید همین‌جاست، و هر کاری اینجا می‌کنید آنجا ظاهر می‌شود.

روی مک، ویندوز و لینوکس اجرا می‌شود.

💡 کدام رابط، کدام است؟

هرمس چند فرانت‌اند دارد که همه با همان ایجنت حرف می‌زنند:

  • اپ دسکتاپ (همین صفحه) — اپلیکیشن بومی با UI خاص‌ساخت برای چت، پیکربندی و مدیریت.
  • CLI‏ (hermes) و TUI‏ (hermes --tui) — رابط‌های ترمینالی.
  • داشبورد وب‏ (hermes dashboard) — پنل مدیریت مرورگری؛ تب اختیاری Chat آن TUI را از طریق شبه‌ترمینال جاسازی می‌کند.

هر کدام را که با لحظه‌تان می‌خواند بردارید. وضعیتشان مشترک است، پس می‌توانید نشست را در یکی شروع و در دیگری ازسر بگیرید.

۱ نصب

از «راهنمای نصب» بخش شروع کار پیروی کنید. اگر هرمس را از قبل نصب دارید، کافی است اجرا کنید:

bash
hermes desktop

این از پیکربندی، کلیدها، نشست‌ها و مهارت‌های فعلی‌تان استفاده می‌کند.

۲ چه چیزی در اپ هست

اپ دسکتاپ به‌صورت پنجره‌ای چت-اول با سایدبار چپ برای ناوبری سازمان یافته. برای مدیریت چند گفتگوی هم‌زمان ایجنت، پیکربندی ارائه‌دهندگان پیام‌رسانی، ساخت آرتیفکت، مرور ساختار پوشهٔ پروژه‌ها و کار هم‌زمان روی چند پروژه ساخته شده.

چت

مرکز اپ. این‌ها را دارید:

  • پاسخ‌های استریم‌شده با فعالیت زندهٔ ابزار و خلاصه‌های ساخت‌یافتهٔ فراخوانی ابزار حین کار ایجنت.
  • همان تاریخچهٔ گفتگو مثل هر سطح دیگر هرمس — نشست‌هایی که اینجا شروع می‌شوند در CLI/TUI ازسرگرفتنی‌اند و برعکس.
  • کشیدن-و-رهاکردن فایل‌ها در هر جای ناحیهٔ چت برای پیوست به پیام بعدی‌تان.
  • ریل پیش‌نمایش دست-راست — صفحات وب، فایل‌ها و خروجی ابزارها را کنار هم رندر کنید در حالی که به چت ادامه می‌دهید.
  • تاریخچهٔ کامپوزر و ویرایش صف — در کامپوزر خالی کلیدهای بالا/پایین را بزنید تا پرامپت‌های قبلی بازیابی شوند، و پیام‌های صف‌شده را قبل از ارسال ویرایش کنید. فشردن Stop (یا Esc) وقتی نوبت‌ها در صف‌اند صف را متوقف و بالای کامپوزر بازش می‌کند؛ از آنجا ادامه دهید، یا مدخل‌های تکی را بفرستید، ویرایش یا حذف کنید.
  • ریل خط‌زمانی گفتگو — چت‌های طولانی ریل باریکی از نشانگرها در لبهٔ رونوشت می‌گیرند، یکی به‌ازای هر پرامپت. هاور کنید تا فهرست پرامپت‌ها باز شود، روی یکی کلیک کنید تا مستقیم به آن نقطهٔ گفتگو بپرید. (وقتی چت مشتی نوبت گرفت ظاهر می‌شود.)
  • یافتن در صفحه — ‏Cmd/Ctrl+F نوار جستجویی باز می‌کند که رونوشت رندرشدهٔ چت را می‌گردد. Enter / ‏Shift+Enter (یا Cmd/Ctrl+G / ‏Cmd/Ctrl+Shift+G حین بازبودن نوار) بین تطبیق‌ها قدم می‌زنند؛ ‏Esc می‌بندد.

نوار وضعیت

نوار پایین چت، وضعیت زندهٔ نشست را نشان و کنترل‌های سریع را بدون بازکردن Settings عرضه می‌کند:

  • سوییچ YOLO به‌ازای-نشست — ‏YOLO را فقط برای همین نشست روشن/خاموش کنید (مطابق TUI). ‏YOLO اعلان‌های تأیید فرمان خطرناک را دور می‌زند، پس بدانید چه چیزی را خاموش می‌کنید — به «امنیت ← حالت YOLO» مراجعه کنید.
  • سنجهٔ مصرف زمینه — سنجهٔ زندهٔ «X٪ پُر» از پنجرهٔ زمینهٔ نشست. کلیک کنید تا پاپ‌اور Context Usage با تفکیک توکن به‌ازای-دسته باز شود (پرامپت سیستمی، تعاریف ابزار، مهارت‌ها، حافظه، قواعد، ‏MCP، تعاریف ساب‌ایجنت و خود گفتگو) تا دقیقاً ببینید پیش از فشرده‌سازی چه چیزی پنجره را می‌خورد.
  • عناصر قابل‌سفارشی — روی نوار وضعیت راست‌کلیک‏ (**Show in status bar**) و انتخاب کنید چه ظاهر شود: سنجهٔ زمینه، ورک‌اسپیس، مدل، تأییدها، تایمرهای نوبت/نشست، ترمینال، Command Center، نسخهٔ بک‌اند و بیشتر — یا کلاً نوار را پنهان کنید‏ (**Cmd/Ctrl+Shift+S** سوییچش می‌کند).

با نمونهٔ هرمسی روی ماشین دیگری چت می‌کنید به‌جای بک‌اند محلیِ همراه؟ به «اتصال به بک‌اند راهن» پایین مراجعه کنید.

کشف مخزن

هرمس دسکتاپ برای سایدبار Projects مخازن گیت محلی را با اسکن پوشهٔ خانگی‌تان تا عمق کراندار کشف می‌کند. می‌توانید به‌ازای-پروفایل در Settings ← Workspace یا در config.yaml تغییرش دهید:

yaml
desktop:
  repo_scan_enabled: true
  repo_scan_roots: []
  repo_scan_exclude_paths: []
  • repo_scan_enabled: false اسکن فایل‌سیستم را کلاً متوقف می‌کند. سطرهای کشِ کشف-از-دیسکِ آن پروفایل پاک می‌شوند؛ پروژه‌های صریح و مخازنِ استنتاج‌شده از نشست‌های عمدی هرمس در دسترس می‌مانند.
  • repo_scan_roots را روی فهرستی از پوشه‌ها بگذارید تا اسکن محدود شود. فهرست خالی، اسکن پیش‌فرض پوشهٔ خانگی را نگه می‌دارد.
  • repo_scan_exclude_paths پوشه‌هایی که کل زیردرخت‌شان باید رد شود.

تغییر هر کدام از این مقادیر فقط کشِ کشف-از-دیسکِ همان پروفایل را بی‌اعتبار و نوسازیِ منطبق-با-سیاست را شروع می‌کند. Hide from sidebar اقدام کیوریشن جداگانه‌ای به‌ازای-آیتم باقی می‌ماند.

انتخاب مدل

انتخاب‌گر مدل در کامپوزر زندگی می‌کند، کمی چپ میکروفون. کلیک کنید تا مدل، تلاش استدلال و حالت سریع از یک دراپ‌داون عوض شوند.

  • انتخاب‌گر کامپوزر وضعیت UI چسبان است و هرگز به پیش‌فرض‌تان دست نمی‌زند. محلی یادآوری می‌شود (به‌ازای-دستگاه) و در نشست‌های جدید و ری‌استارت‌ها همراه‌تان می‌ماند به‌جای برگشتن ناگهانی به پیش‌فرض — یک بار مدلی بردارید و Cmd/Ctrl+N بعدی با آن باز می‌شود. در چت زنده، تعویض مدل تغییر را به همین چت فعلی محدود می‌کند؛ به‌هرحال انتخاب هنگام ساخت/سوییچ نشست سوار می‌شود و هرگز در پیش‌فرض پروفایل نوشته نمی‌شود. (تعویض پروفایل به پیش‌فرض خودش دوباره بکار می‌شود.)
  • پیش‌فرض را در Settings ← Model بگذارید. آن مدل «اصلی» پیش‌فرض سراسری به‌ازای-پروفایل شماست — چیزی که چت‌های جدید، کرون‌ها، ساب‌ایجنت‌ها و کارهای کمکی از آن شروع می‌کنند، و تنها جایی است که آن را می‌نویسد. هر پروفایل پیش‌فرض خودش را نگه می‌دارد.
  • پیش‌تنظیمات تلاش/سریع به‌ازای-مدل. هر مدل انتخاب تلاش استدلال و حالت سریع خودش را در اپ دسکتاپ یاد می‌آورد و با هر بار برداشتن همان مدل دوباره روی نشست اعمال می‌شود. این پیش‌تنظیمات یک راحتی دسکتاپ‌اند و کرون‌ها یا ساب‌ایجنت‌ها را تغییر نمی‌دهند.
  • تعویض میان-چت کش پرامپت را ریست می‌کند. تعویض مدل داخل چت زنده یعنی پیام بعدی کل گفتگو را به قیمت کامل ورودی می‌خواند (کش‌های پرامپت ارائه‌دهنده به مدل کلید می‌خورند). گاهی اشکال ندارد؛ روی چت طولانی، چتِ تازه روی مدل جدید اغلب ارزان‌تر از رفت‌وبرگشت است.

مرورگر فایل

پوشهٔ کاری را بدون ترک اپ کاوش و پیش‌نمایش کنید — مفید برای همراهی‌کردن با ایجنت هنگام خواندن، نوشتن و ویرایش فایل‌ها. پوشهٔ پروژهٔ اولیه را با hermes desktop --cwd <path> (یا متغیر محیطی HERMES_DESKTOP_CWD) بگذارید.

آرتیفکت‌ها

نمای Artifacts آنچه نشست‌هایتان تولید می‌کنند — تصاویر، فایل‌ها و لینک‌ها — را در یک گالری قابل‌جستجو و قابل‌مرور جمع می‌کند. از سایدبار، پالت فرمان‏ (**Artifacts — Browse generated outputs**) یا میان‌بر nav.artifactsی که خودتان می‌بندید بازش کنید. خروجی‌های اخیر نشست‌ها را خودکار اندکس می‌کند؛ هر آرتیفکت نشان می‌دهد کدام نشستش را ساخته با پرشی به همان چت، و تصاویر و فایل‌ها در پیش‌نمایشی با اکشن‌های دانلود / باز‌کردن-در-مرورگر / کپی باز می‌شوند.

پنجره‌ها، تب‌ها و پنل‌ها

اپ برای کار هم‌زمان روی چند چیز ساخته شده:

  • تب‌ها — Cmd/Ctrl+T تب نشست جدید؛ ‏Ctrl+Tab / ‏Ctrl+Shift+Tab چرخش نشست‌ها، و Ctrl+1…9 پرش به نشست اخیر بر اساس موقعیت. Cmd/Ctrl+W تب متمرکز را می‌بندد و Cmd/Ctrl+Shift+T آخرین بسته‌شده را دوباره باز می‌کند.
  • چند پنجره — Cmd/Ctrl+Shift+N پنجرهٔ جدید، و هر نشستی از منوی زمینه‌اش (**New window**) یا از پالت فرمان قابل جداکردن است. پنجرهٔ جداشده همان یک چت را بدون سایدبار سراسری رندر می‌کند — برای پارک‌کردن نشست طولانی روی مانیتور دیگر دست‌ودل‌باز. خروجی زندهٔ ایجنت به هر پنجره‌ای که نشست را نشان می‌دهد استریم می‌شود.
  • پنل‌ها — Cmd/Ctrl+B سایدبار چپ، ‏Cmd/Ctrl+J راستی و Cmd/Ctrl+\ سوییچ این‌که سایدبارها کدام طرف بنشینند.

ترمینال

یک ترمینال واقعی در سایدبار راست، کنار مرورگر فایل:

  • Ctrl+` ترمینال را نشان می‌دهد (اگر نیست می‌سازد)؛ ‏Ctrl+Shift+` یکی اضافه می‌سازد. چند ترمینال در ریل تب می‌نشینند — Ctrl+Shift+↓/↑ بین‌شان قدم می‌زند، ‏Ctrl+Shift+W فعال را می‌بندد.
  • شل‌ها حین مخفی‌بودن زنده‌اند. بستن یا پنهان‌کردن پنل شل‌تان را نمی‌کشد — هر ترمینال باز با اسکرول‌بک و پروسه‌های در حال اجرایش مانت می‌ماند تا صریح نبندیدش.
  • Add to chat — خروجی ترمینال را انتخاب و به‌عنوان زمینه برای پیام بعدی به کامپوزر بفرستید.

بازبینی گیت و ورک‌تری‌ها

برای نشست‌های در حال اجرا داخل مخزن گیت، اپ سطح کنترل-نسخهٔ داخلی دارد:

  • پنل بازبینی — Cmd/Ctrl+G پنل بازبینی درخت کاری را سوییچ می‌کند: شاخه و وضعیت جلو/عقب، فایل‌های تغییرکرده (نمای فهرست یا درخت) و دیف‌های در دامنهٔ Uncommitted، ‏Branch یا Last turn (فقط آنچه ایجنت در جدیدترین نوبتش تغییر داد). فایل‌ها را stage/unstage کنید، تغییرات را revert کنید، پیام کامیت بنویسید (یا **Generate commit message**)، سپس Commit یا Commit & Push — و Create PR از طریق CLI گیت‌هاب‏ (gh)، یا کل کار را به ایجنت بسپارید با Ask Hermes to open PR. ساخت و تعویض شاخه هم از همین‌جا ممکن است.
  • ورک‌تری‌ها — Cmd/Ctrl+Shift+B (یا **New worktree** روی پروژه‌ای در سایدبار) ورک‌تری گیت روی شاخه‌ای جدید می‌سازد تا ایجنتی روی کپی موازی مخزن کار کند بدون دست‌زدن به چک‌اوت شما. ورک‌تری‌ها به‌صورت لِین‌های خودشان زیر پروژه ظاهر می‌شوند؛ حذف یکی پیشنهاد حذف پوشهٔ ورک‌تری را می‌دهد (شاخه می‌ماند) یا فقط پنهان‌کردن لِین و نگه‌داشتن روی دیسک، با گزینهٔ force وقتی تغییرات کامیت‌نشده دارد.

گراف حافظه

Memory Graph (پالت فرمان ← *Memory Graph*، یا آیتم نوار وضعیت) نقشهٔ تعاملی چیزهایی است که هرمس برای شما آموخته — مهارت‌ها و حافظه‌ها به‌صورت گراف گرهیِ زوم‌شونده با خط‌زمان، فیلترپذیر بر All / Used / Learned. کنترل اشتراک، چیدمان نقشه را به‌صورت کد فشرده‌ای صادر می‌کند که به دیگری پیست کنید (فقط چیدمان — هیچ‌کدام از متن حافظه یا مهارت شما داخلش نیست) و کدها را همین‌طور وارد می‌کند.

Quick Entry

Quick Entry یک کامپوزر کوچکِ همیشه-در-دسترس است که با هات‌کی سراسری از هر جای سیستم‌تان احضار می‌شود — پرامپتی شلیک کنید بدون سوییچ‌به (یا حتی بازبودن) پنجرهٔ اصلی. در Settings ← Advanced ← Quick Entry فعالش کنید؛ میان‌بر پیش‌فرض Ctrl/Cmd+Shift+Space است و می‌توانید خودتان بگذارید (حداقل یک اصلاح‌کننده لازم دارد). اگر اپ دیگری Already آن آکورد را گرفته باشد، سطر تنظیمات می‌گوید تا یکی دیگر بردارید.

صوت

با هرمس حرف بزنید و شنیدنش، همان حالت صوتی موجود در جاهای دیگر. روی مک، OS یک بار برای دسترسی میکروفون می‌پرسد.

حالت HUD

⌘/Ctrl+Shift+H (یا دکمهٔ عنوان‌بار) چت را به نوار شناورِ بدون-کروم و همیشه-رو‌-بالا جدا می‌کند که روی هر چیزی که در آن کار می‌کنید می‌نشیند. پنجرهٔ اپ کنار می‌رود؛ ‏HUD گفتگوی زنده و کامپوزری نگه می‌دارد. جایی که پارکش می‌کنید زمینه است — موقعیت نوار به هرمس می‌گوید دربارهٔ کدام اپ و صفحه می‌پرسید، پس «این»، «اینجا» و «اون صفحه» به چیزی زیرش حل می‌شوند.

  • جابه‌جایی نوار — هر جای کامپوزر را فشار داده و نگه دارید یک لحظه، بعد بکشید. فشار سریع همچنان تایپ می‌کند؛ فشار نگه‌داشته پنجره را می‌گیرد. این تنها راه جابه‌جایی HUD است — عنوان‌باری برای کشیدن ندارد.
  • تغییر اندازه — گوشهٔ پایین-راست نوار را بکشید.
  • پرش به نشانگر — ⌘/Ctrl+Shift+G (هات‌کی سراسری، از هر اپی کار می‌کند) ‏HUD را به جایی که مکان‌نماست می‌پراند.
  • خروج — دکمهٔ خروج روی نوار، یا دوباره ⌘/Ctrl+Shift+H. پنجرهٔ اپ با نشست سالم‌تان برمی‌گردد.

۳ تنظیمات و آنبوردینگ

ارائه‌دهندگان، مدل‌ها، ابزارها و اعتبارنامه‌ها را از یک UI واقعی به‌جای ویرایش YAML مدیریت کنید. آنبوردینگ اولین‌بار شما را در چند ثانیه به اولین پیام‌تان می‌رساند. پنل‌های تنظیمات ارائه‌دهندگان/کلیدها، انتخاب مدل، پیکربندی تول‌ست، سرورهای MCP، گیت‌وی و مدیریت نشست را پوشش می‌دهند.

  • پنل تنظیمات ارائه‌دهندگان — جای اختصاصی مدیریت ارائه‌دهندگان استنتاج، با UX حساب‌ها / کلیدهای-API برای ورود و نگهداری اعتبار به‌ازای-ارائه‌دهنده.
  • همهٔ ارائه‌دهندگان و مدل‌ها در منوها — ‏GUI فهرست کامل ارائه‌دهندگان و هر مدلی که hermes model می‌شناسد را ظاهر می‌کند، پس از همان کاتالوگی که CLI می‌بیند انتخاب می‌کنید نه زیرمجموعه‌ای گزینش‌شده.
  • xAI Grok OAuth — گروک ارائه‌دهندهٔ OAuth درجه‌یکِ لانچر است؛ مثل بقیه از جریان مرورگر وارد شوید.
  • نصب بک‌اندهای ابزار از GUI — گام‌های نصب پس‌از-راه‌اندازیِ یک بک‌اند ابزار را مستقیم از اپ اجرا کنید به‌جای افتادن به ترمینال.
  • انتخاب‌گر فونت ترمینال — فونت نصب‌شده را در Settings ← Appearance بردارید. نردفونت‌هایی مثل MesloLGS NF جداکننده‌ها و آیکون‌های Powerlevel10k را در ترمینال‌های تعاملی و ایجنتی هر دو رندر می‌کنند؛ تنظیم به‌ازای-پروفایل ذخیره می‌شود.
  • هشدار مدل-کمکی — اگر مدل اصلی را به ارائه‌دهندهٔ جدیدی ببرید در حالی که کارهای کمکی (عنوان‌گذاری، خلاصه‌سازی و کمک‌های مشابه) هنوز به ارائه‌دهندهٔ دیگری پین‌اند، اپ هشدار می‌دهد تا ناآگاهانه کار را بین دو ارائه‌دهنده نشکنید.
  • تم‌های VS Code Marketplace — فراتر از پیش‌تنظیم‌های داخلی، تنظیمات ظاهر جستجوی زندهٔ VS Code Marketplace دارد: هر تم رنگی را بردارید و اپ دانلود، تبدیل و نصبش می‌کند به‌عنوان تم دسکتاپ. همان واردکننده از پالت فرمان (*Install theme*) هم هست و تم‌های واردشده دوباره حذف‌پذیرند.
  • بیدارنگه‌داشتن کامپیوتر — Settings ← Advanced ← Keep computer awake مانع خواب ماشین می‌شود تا اجراهای طولانی یا شبانشین ایجنت ادامه یابند (نمایشگر همچنان می‌تواند تاریک شود). تنظیمی به‌ازای-کامپیوتر است.

آنبوردینگ اولین‌بار روی سیستم طراحی اورلیِ یکپارچه بازطراحی شده، و می‌توانید Choose provider later را بردارید تا از راه‌اندازی ارائه‌دهنده بگذرید و اول وارد اپ شوید.

تنظیمات به‌ازای-پروفایل: دامنهٔ «Applies to»

وقتی دو یا چند پروفایل دارید، صفحات تنظیماتِ پشتیبان‌شده-با-پیکربندی — Model، ‏Workspace، ‏Safety، ‏Memory & Context، ‏Voice، ‏Chat، ‏Advanced و Tools & Keys — و اورلی Messaging ردیف چیپ مشترک Applies to در بالا نشان می‌دهند. انتخاب می‌کند ویرایش‌هایتان کدام پروفایل را هدف بگیرند:

  • انتخاب پیش‌فرض دنبال پروفایل فعال می‌رود که دقیقاً مثل قبل رفتار می‌کند — پروفیلی که در آن هستید را ویرایش کنید.
  • پروفایل دیگری بردارید تا تنظیمات او را بدون سوییچ‌کردن کل اپ ببینید و ویرایش کنید؛ انتخاب بین صفحات تنظیمات پایدار می‌ماند.
  • تعویض پروفایل فعالِ اپ انتخاب‌گر را ریست می‌کند تا ویرایش‌ها خاموش روی پروفایل قبلاً-انتخاب‌شده فرود نیایند.
  • با کمتر از دو پروفایل ردیف چیپ کلاً مخفی است.

(صفحهٔ Gateways پروفایل‌ها را متفاوت هندل می‌کند — با زیربخش Per-profile overrides خودش — و نمای‌های Capabilities و Scheduled Jobs انتخاب‌گر دامنهٔ خودشان را دارند.)

پنل‌های مدیریت

اپ سطح مدیریت گسترده‌تر هرمس را هم ظاهر می‌کند تا به ترمینال نیفتید:

  • Skills — مرور، نصب و مدیریت مهارت‌ها.
  • گراف حافظه (Star Map) — در چت /journey (نام‌مستقل‌های /learning، ‏/memory-graph) را تایپ کنید تا صورت‌فلکی تعاملیِ مهارت‌ها و حافظه‌های آموخته‌شده در طول زمان باز شود، با اسکرابر پخش. گره‌ها مستقیم از پنل قابل ویرایش یا حذف‌اند (مهارت‌ها آرشیو، حافظه‌ها حذف می‌شوند). به «سفر یادگیری» در صفحهٔ حافظه مراجعه کنید.
  • Cron — دیدن و مدیریت کارهای زمان‌بندی‌شده.
  • Profiles — جابه‌جایی بین پروفایل‌های هرمس (پیکربندی/مهارت/نشست ایزوله).
  • Messaging — راه‌اندازی کانال‌های گیت‌وی.
  • Agents و Command Center — سطوح ارکستراسیون برای کار چندایجنتی.

حالت بات (داخلی)

حالت بات همراه اپ عرضه و به‌طور پیش‌فرض روشن است: فهرستی «یک چت به‌ازای هر ایجنت» که هر پروفایل هرمس را به‌صورت باتی با آواتار خودش (چهرهٔ هندسی، تصویر آپلودی، پرترهٔ AI یا پت پیکسلی)، گفتگوی Bot Chat متعارف خودش و روتین‌های خودش (کارهای تکرارشونده با پشتوانهٔ کرون هرمس) نشان می‌دهد. فهرست در سایدبار چپ به‌صورت تبی کنار گفتگوهایتان زندگی می‌کند — نوار تب Sessions | Bots — نه پنل دومی زیر فهرست نشست. نصب‌هایی که چیدمان قدیمیِ انباشته را گرفتند یک‌بار خودکار به نوار تب منتقل می‌شوند؛ اگر خودتان پنل‌ها را دستی چیده‌اید، چیدمان‌تان دست‌نخورده می‌ماند. پنل Cronjobs (روتین‌ها) فقط تا وقتی تب Bots فعال است کنار چت می‌نشیند و با برگشتن به Sessions کنار می‌رود (بیلدهای قدیمی همیشه نمایشش می‌دهند).

از فهرست ایجنت‌های جدید بسازید — نام / عنوان / توضیح به‌علاوهٔ افشای Advanced با سطح کامل قابلیت‌ها (مدل، ‏SOUL، مهارت‌ها، تول‌ست‌ها، سرورهای MCP) — آن‌ها را در بخش‌ها گروه کنید، و گفتگوهای گروهی باز کنید که چند بات در آن شور می‌کنند. گفتگوهای گروهی به‌صورت سطرهای مستقل سبک-دیسکورد در فهرست ظاهر می‌شوند — آواتارهای عضوِ انباشته، شمار عضو، پیش‌نمایش آخرین خط اتاق، و نشان «نیاز به شما» — درهم‌آمیخته با سطرهای بات در همان ترتیب پین+تازگی. کلیک روی سطر گروه، اتاق را به‌صورت تبی باز می‌کند که پنجرهٔ چت اصلی را می‌گیرد (بیلدهای قدیمی داخل پنل کناری بات‌ها بازش می‌کنند).

بات‌ها به هم پیام می‌دهند: در هر چتی @researcher have a look at this را تایپ کنید و بات فعال پیام را تحویل و گزارش پس می‌دهد، و بات‌ها مستقیم به Bot Chatهای هم می‌رسند‏ (hermes -p <bot> chat). بک‌اند پروتکل پیام‌رسانی را به نشست Bot Chat متعارف هر بات خودکار می‌آموزد (پیکربندی agent.bot_mode_protocol، پیش‌فرض روشن) — از جمله وقتی بات هم‌تیمی‌ای آن را بدون-سرپرست از CLI باز می‌کند — پس پاسخ‌ها و تحویل‌های بات-به-بات بدون دست‌زدن به SOUL.md شما کار می‌کنند و نشست‌های عادی‌تان دست‌نخورده می‌مانند.

نشست‌های حالت بات — Bot Chat متعارف هر بات و هر نشستِ عضوِ اتاق گروهی — همیشه از سایدبار سراسری Sessions پنهان‌اند. در پنل Bots زندگی می‌کنند (سطرهای فهرست، نمای‌های اتاق و مرورگر نشست هر بات) به‌جای درهم‌آمیختن با گفتگوهای خودتان.

بات‌هایی که استفاده نمی‌کنید را می‌توان کنار گذاشت: راست‌کلیک روی سطر بات ← ‏Hide Bot. بات‌های مخفی از فهرست می‌روند ولی کار می‌کنند — @منشن‌ها همچنان حل و عضویت گروهی دست‌نخورده است. هر وقت حداقل یک بات مخفی باشد کلید چشمی در سرصفحهٔ Bots ظاهر می‌شود؛ کلیک کنید تا بات‌های مخفی کم‌رنگ درجا دیده شوند (راست‌کلیک ← Unhide Bot یکی را برمی‌گرداند)، و چشم وقتی بات مخفی فعالیت خوانده‌نشده دارد نقطه می‌گیرد. وضعیت مخفی در پروفایل بات ذخیره می‌شود، پس با بات بین ماشین‌ها می‌رود.

نمی‌خواهیدش؟ در Settings ← Plugins ← Bots خاموشش کنید — فهرست، پنل روتین‌ها و میان‌افزار کامپوزر زنده ثبت‌بردارند، بدون ری‌استارت.

راهنمای کامل — ساخت ایجنت (شامل انتخاب‌گر چندماشینی Create on)، فهرست بین اتصال‌ها، منشن‌های بات-به-بات و اینکه اتاق‌های گروهی تصمیم می‌گیرند چه کسی پاسخ دهد: «حالت بات».

کیبورد و ناوبری

  • پالت فرمان — Cmd+K یا Cmd+P (‏Ctrl+K / ‏Ctrl+P در ویندوز/لینوکس) برای پرش به اکشن‌ها و ناوبری اپ از کیبورد: باز کردن هر صفحه یا بخش تنظیمات، پرش به نشست با عنوان یا شناسه، تعویض مدل/تم/حالت رنگ، تولید ترمینال، ری‌استارت گیت‌وی، به‌روزرسانی هرمس و بیشتر.
  • میان‌برهای بازبندشونده — Settings ← Keyboard Shortcuts (یا Cmd/Ctrl+/) پنل میان‌برها را باز می‌کند که تقریباً هر بایندینی را بازنگاشت کنید — سوییچ پروفایل، ناوبری نشست، سوییچ نماها و هر میان‌بری که پلاگین‌های دسکتاپ آورده‌اند. انتساب‌های تکراری به‌عنوان تعارض علامت می‌خورند. چند پیش‌فرضِ ارزش‌دانستن: Cmd/Ctrl+N نشست جدید، ‏Cmd/Ctrl+. ‏Command Center، ‏Cmd/Ctrl+, ‏Settings، ‏Cmd/Ctrl+Shift+F جستجوی نشست‌ها، ‏Cmd/Ctrl+1–9 تعویض پروفایل، ‏Shift+X سوییچ روشن/تاریک.
  • میان‌برهای زوم سفارشی — رابط را با گام‌های نیم‌پله زوم کنید برای کنترل ریزتر روی اندازهٔ متن.
  • سوییچر زبان UI — زبان رابط اپ را درون اپ عوض کنید.

نشست‌ها و پروفایل‌ها

  • بازطراحی فهرست نشست — فهرست نشست بازکار شده با آرشیو و بهداشت عمومی نشست تا فهرست با رشدش قابل‌مدار بماند.
  • جستجوی نشست با شناسه — یافتن مستقیم نشست مشخصی با شناسه‌اش.
  • نشست‌های چندپروفایلی هم‌زمان — نشست‌هایی روی چند پروفایل هم‌زمان اجرا کنید، و نشستی در پروفایل دیگر را با لینک‌های بین‌پروفایلی @session ارجاع دهید.
  • صادرات / درون‌ریزی پروفایل — کل راه‌اندازی را به‌صورت یک فایل به اشتراک بگذارید. ⌘K ← Export profile… (یا راست‌کلیک روی مربع پروفایل در ریل) یک .tar.gz با مهارت‌ها، حافظه، پرسونا، کرون‌ها، پلاگین‌ها و تنظیمات می‌نویسد؛ کلیدهای API حذف می‌شوند. صادرات از دسکتاپ ظاهر و رابط شما را هم باندل می‌کند — پوسته، حالت روشن/تاریک، تم‌های سفارشی، رنگ ریل پروفایل و چیدمان پنجره — تا پروفایلِ درون‌ریزی‌شده همان‌شکلی برسد که فرستنده داشت. درون‌ریزی با ⌘K ← Import profile… یا دکمهٔ کنار + ریل؛ اورلی را اعمال و در پروفایل جدید می‌گذاردتان. همان آرشیو با /export / ‏/import در چت و hermes profile export / ‏import از شل کار می‌کند.

۴ به‌روزرسانی

اپ در پس‌زمینه به‌روزرسانی می‌گیرد و وقتی آماده بود به‌روزرسانی یک‌کلیکی پیشنهاد می‌دهد.

اپ دسکتاپ و بک‌اند هرمسی که با آن حرف می‌زند روی ساعت‌های جدا به‌روز می‌شوند — بستهٔ اپ روی ماشین شما، بک‌اند هرجا اجرا می‌شود. وقتی بیش از یک هدف به‌روزرسانی وجود دارد (گیت‌وی راهن، یا چند گیت‌وی ثبت‌شده)، امکانات به‌روزرسانی‏ (**Update now** در پنل About، سطر ⌘K ‏**Update Hermes** و توستِ آماده-به‌روزرسانی) همه‌چیز را به‌روز می‌کنند: اول بک‌اند متصل، بعد هر گیت‌وی ثبت‌شدهٔ واجدشرط دیگر (مدخل‌های Hermes Cloud توسط پلتفرم مدیریت و رد می‌شوند)، و خود اپ دسکتاپ در آخر، چون اعمال به‌روزرسانی کلاینت اپ را دوباره راه می‌اندازد. نصب‌های تک‌ماشینی تجربهٔ تک‌دکمه را نگه می‌دارند.

پس از هر به‌روزرسانی بک‌اند، اپ نسخهٔ خودش را هم دوباره چک و اگر GUI هنوز عقب است با اکشن یک‌کلیکی Update desktop app هشدار می‌دهد — پس به‌روزرسانی بک‌اند راهن هرگز نمی‌تواند خاموش شما را روی بیلد کهنهٔ دسکتاپ رها کند. فرایند به‌روزرسانی دستی هم با GUI کار می‌کند.

۵ حذف نصب

Settings ← About ← Danger zone را باز کنید و انتخاب کنید چقدر حذف شود:

  • فقط حذف Chat GUI — اپ دسکتاپ و داده‌هایش را برمی‌دارد؛ ایجنت هرمس، پیکربندی و چت‌هایتان می‌مانند. (همان hermes uninstall --gui.)
  • حذف GUI + ایجنت، حفظ داده‌هایم — اپ و ایجنت را برمی‌دارد ولی پیکربندی، چت‌ها و رازها را برای نصب مجدد آینده نگه می‌دارد. (همان hermes uninstall.)
  • حذف همه‌چیز — اپ، ایجنت و همهٔ داده‌های کاربر. (همان hermes uninstall --full.)

اپ برای تمام‌کردن کار بسته می‌شود (پاک‌سازی بعد از خروجش اجرا می‌شود تا باندل اپِ در حال اجرا و venv خودش را بردارد). گزینه‌های حذف-ایجنت وقتی ایجنت محلی نصب نیست خودکار مخفی‌اند (مثلاً کلاینت «سبکِ» فقط-GUI متصل به بک‌اند راهن).

همین کار از ترمینال هم می‌شود — hermes uninstall --gui فقط برای GUI، یا hermes uninstall / hermes uninstall --full برای ایجنت هم.

ℹ️ توجه

اجرای hermes uninstall --gui از یک چک‌اوت سورس (بیلد dev مربوط به hermes desktop) همچنین node_modules ورک‌اسپیس و خروجی بیلد apps/desktop/{dist,release} را برمی‌دارد، چون مصنوعات بیلد GUI‌اند. با hermes desktop (یا npm install + بیلد مجدد) بازیابی‌پذیرند — ولی اگر فعالانه روی اپ دسکتاپ هک می‌کنید، انتظار نصب مجدد وابستگی‌ها را داشته باشید.

۶ مرجع CLI: hermes desktop

برای اجرا از CLI، ساده hermes desktop را بزنید. به‌طور پیش‌فرض وابستگی‌های Node ورک‌اسپیس را نصب، اپ Electronِ بازبستهٔ سیستم‌عامل فعلی را بیلد و سپس همان مصنوع بسته‌شده را اجرا می‌کند.

۷ چگونه کار می‌کند

اپ بسته‌شده پوستهٔ Electron و سطح چت React بومی را حمل می‌کند. در اولین اجرا می‌تواند زمان اجرای Hermes Agent را در HERMES_HOME نصب کند‏ (~/.hermes، یا %LOCALAPPDATA%\hermes در ویندوز) — همان چیدمانی که نصب CLI استفاده می‌کند، و به همین دلیل این دو قابل‌معاوضه‌اند. حل بک‌اند اول به HERMES_DESKTOP_HERMES_ROOT احترام می‌گذارد، بعد یک نصب مدیریت‌شدهٔ کامل، بعد یک hermes کاویده‌شده روی PATH (مگر --ignore-existing / ‏HERMES_DESKTOP_IGNORE_EXISTING=1 تنظیم باشد)، و در نهایت بازنویسی صریح فرمان HERMES_DESKTOP_HERMES برای بسته‌سازهایی مثل Nix. رندرکنندهٔ React با بک‌اند headlessای که اپ برایتان راه می‌اندازد حرف می‌زند — پروسه‌ای hermes serve که API مربوط به JSON-RPC/WebSocket گیت‌وی tui_gateway را سرو می‌کند — و زمان اجرای ایجنت را بازاستفاده می‌کند به‌جای جاسازی hermes --tui. اپ دسکتاپ خودبسسته است: بک‌اند hermes serve خودش را اجرا و هرگز داشبورد وب را باز نمی‌کند یا لازم ندارد. (زمان‌های اجرای قدیمی‌تر از فرمان serve خودکار به dashboard --no-open ‏headless برمی‌گردند، پس به‌روزرسانی اپ هرگز از بک‌اندش جلو نمی‌زند.) منطق نصب، حل-بک‌اند و خودبه‌روزرسانی در پروسهٔ اصلی Electron زندگی می‌کنند.

۸ اتصال به بک‌اند راهن

به‌طور پیش‌فرض اپ بک‌اند محلی خودش را شروع و مدیریت می‌کند. به‌جایش می‌توانید به بک‌اند هرمسی که روی ماشین دیگری اجرا می‌شود اشاره کنید — یک VPS، سرور خانگی یا مینی‌ای پشت Tailscale.

همهٔ چیزهای مربوط به اتصال روی یک صفحهٔ تنظیمات است: Settings ← Gateways. (بیلدهای قدیمی این را بین صفحات جدا Gateway و Connections می‌شکستند — حالا یکپارچه شده‌اند و دیپ‌لینک‌های قدیمی ?tab=connections به صفحهٔ یکپارچه ریدایرکت می‌شوند.)

Settings ← Gateways ← Connection mode جایگزین‌های گیت‌وی محلی را پیشنهاد می‌دهد:

  • گیت‌وی راهن — URL یک بک‌اند hermes serve که خودتان اجرا می‌کنید را وارد و وارد شوید. این حالتی است که بقیهٔ این بخش توضیحش می‌دهد.
  • Hermes Cloud — یک بار به Hermes Cloud وارد شوید و از ایجنت‌های حساب‌تان انتخاب کنید؛ بدون URL برای پیست. اپ ایجنت‌هایتان را کشف می‌کند (با انتخاب‌گر سازمان اگر حساب‌تان چند سازمان را می‌پوشاند)، و اتصال به یکی، نشست را خودکار سوییچ می‌کند. نوار وضعیت اتصال ابری را حین فعال‌بودنش نشان می‌دهد.

اتصال‌های گیت‌وی در سطح ماشین‌اند: صفحهٔ Gateways مدیریت می‌کند این دسکتاپ به کدام بک‌اندهای گیت‌وی وصل شود، و پروفایل‌ها از گیت‌وی‌هایی که به آن‌ها وصل می‌شوید کشف می‌شوند. نشست‌ها یک‌زمان یک گیت‌وی انتخاب می‌کنند، و ریل پروفایلِ مجاور پروفایلی را که روی همان گیت‌وی کشف شده انتخاب می‌کند.

رجیستری چند-اتصالی

پایین‌تر همان صفحهٔ Settings ← Gateways، بخش Registered gateways فهرست نام‌داری از هر گیت‌وی هرمسی که اپ می‌شناسد را مدیریت می‌کند — زمان اجرای محلی، هر تعداد گیت‌وی راهن‏ (‏LAN، ‏Tailscale، اینترنت)، نمونه‌های Hermes Cloud و هاست‌های SSH — همه با هم در یک جا ماندگار. با دکمهٔ دوتیروته در انتهای راست ریل پروفایل سایدبار‏ (**Connect another Hermes gateway…**) یا با ⌘K ← Gateways به آن بپرید. راهنمای کامل — فهرست اتحادیهٔ ایجنت‌ها، هندل‌های @name-device، به‌روزرسانی ناوگانی و سطح SDK پلاگین — در «اتصال دسکتاپ به چند نمونهٔ هرمس».

  • هر اتصال نام یکتا لازم دارد (نام دستگاهی مثل «Homelab» یا «لپ‌تاپ کاری»). وقتی نام پروفایلی روی چند گیت‌وی ثبت‌شده موجود است، سطوح آن را به‌صورت @profile-device تفکیک می‌کنند (مثلاً @research-homelab).
  • از سایدبار Sessions گیت‌وی عوض کنید. انتخاب‌گر گیت‌ویِ نام‌دار وقتی بیش از یک گیت‌وی ثبت است ظاهر می‌شود و هر اندازهٔ رجیستری را بدون شبیه‌کردن گیت‌وی‌ها به پروفایل‌ها هندل می‌کند. ریل پروفایل مجاور آن‌گاه فقط ایجنت‌های همان گیت‌وی را نشان و آخرین پروفایلِ استفاده‌شدهٔ آنجا را یاد می‌آورد؛ مجموعه‌های بزرگ پروفایل مستقل فشرده می‌شوند.
  • انتخاب چیزی که بعد از ری‌استارت باز شود. Open on launch پیش‌فرض سازگار-به-عقبِ Primary gateway را نگه می‌دارد، یا می‌تواند Last used را پس از اتصال موفق ازسر بگیرد. این ترجیح بیرون از باندل اپلیکیشن ذخیره و از به‌روزرسانی‌های دسکتاپ جان سالم به در می‌برد.
  • افزودن / ویرایش / حذف / تست اتصال‌ها از پنل. جریان Add هر چهار نوع را پیشنهاد می‌دهد — Local، ‏Hermes Cloud، ‏Remote gateway و SSH (دکمهٔ Local تا وقتی مدخل محلیِ مدیریت‌شده-با-اپ وجود دارد غیرفعال است، و راهنمایی افزودن‌های ابری را به جریان ورود/کشف بالا می‌فرستد). مدخل محلی توسط اپ مدیریت و قابل حذف نیست. Test مستقیم پای‌های HTTP و WebSocket خودِ اتصال را می‌کاود.
  • تکراری‌ها هنگام ذخیره رد می‌شوند: فقط یک مدخل محلی همیشه؛ مدخل‌های راهن و ابری روی URL نرمال‌شده یکتاسازی می‌شوند (تریم، حذف اسلش انتهایی، حروف کوچک — بین هر دو نوع)؛ مدخل‌های SSH روی user@host:port نرمال‌شده به‌علاوهٔ پروفایل راهن.
  • تنظیمات موجود اولین باری که بیلدی با رجیستری اجرا می‌کنید خودکار وارد می‌شوند: اتصال سراسری فعلی و هر بازنویسی قدیمی به‌ازای-پروفایل، مدخل نام‌دار می‌شوند. فایل تنظیمات قدیمی دست‌نخورده می‌ماند تا بیلدهای قدیمی کار کنند.
  • مدخل‌های ابری از جریان ورود/کشف Hermes Cloud بالا می‌آیند، نه از URL دست‌نویس.
  • توکن‌ها با کی‌رینگ OS رمزنگاری‌شده ذخیره می‌شوند (با ورود صریح به متن-ساده روی لینوکس‌های بدون-کی‌رینگ).

مسیریابی کنار-به-کنار زنده است: هر گیت‌وی ثبت‌شده بک‌اندها و سوکت‌های خودش را در لحظه شماره می‌گیرد (کلیدخورده به اتصال + پروفایل)، ‏SDK پلاگین فهرست اتحادیهٔ ایجنت‌ها را عرضه می‌کند‏ (host.agents() / ‏host.ensureAgent())، و Update all instances در صفحهٔ Gateways فرمان hermes update را یک‌جا به هر گیت‌وی واجدشرط می‌فرستد — مدخل‌های Hermes Cloud رد می‌شوند (پلتفرم به‌روزشان می‌کند) و هر نمونه نتیجهٔ خودش را گزارش می‌دهد.

ℹ️ بک‌اند راهن یک پروسهٔ hermes serve در حال اجراست

«بک‌اند راهن» یعنی سروری که hermes serve روی ماشین راهن اجرا می‌شود — همان پروسه‌ای که اپ دسکتاپ به آن وصل می‌شود. هیچ‌چیز از این بخش کار نمی‌کند مگر آن بک‌اند واقعاً بالا و در دسترس باشد. اپ دسکتاپ شروعش نمی‌کند؛ شما (یا یک سرویس systemd) باید hermes serve را روی میزبان راهن نگه دارید و اپ به آن متصل می‌شود. اگر از کانال‌های پیام‌رسانی هم استفاده می‌کنید (تلگرام، دیسکورد و غیره)، گیت‌وی پروسهٔ جداگانهٔ بلندمدتی است که مستقل شروع می‌کنید — به یادداشت پس از گام‌های راه‌اندازی مراجعه کنید.

اتصال دو نیمه دارد: روی بک‌اند آن را با یک ارائه‌دهندهٔ احراز هویت محافظت می‌کنید، و در اپ URL بک‌اند را وارد و وارد می‌شوید. اتصال بک‌اند به آدرس غیرحلقه‌محلی، دروازهٔ احرازش را خودکار درگیر می‌کند و ارائه‌دهنده‌ای که پیکربندی می‌کنید همان چیزی است که به اپ دسکتاپ اجازهٔ عبور می‌دهد.

ارائه‌دهنده را بر اساس زندگی‌محل بک‌اند انتخاب کنید:

  • OAuth (‏Nous Portal) — برای هر چیز قابل‌دسترس فراتر از ماشین خودتان ترجیح‌دارد. ورودها مقابل حساب Nous شما تأیید می‌شوند، پس این گزینهٔ مناسب VPS، هاست عمومی یا هر بک‌اند راهنی است. داشبورد را با hermes dashboard register (یا صفحهٔ /local-dashboards پورتال) ثبت کنید تا کلاینت OAuthش تأمین شود، سپس از اپ با Sign in with Nous Research وارد شوید. یک ارائه‌دهندهٔ OIDC خودمیزبان هم همین‌طور کار می‌کند اگر IDP خودتان را اجرا می‌کنید.
  • نام‌کاربری/رمزعبور — فقط استفادهٔ محلی / شبکهٔ مطمئن. ساده‌ترین گزینه وقتی بک‌اند روی همان LAN مطمئن یا فقط روی VPN ‏(مثلاً Tailscale) در دسترس است. یک اعتبار مشترک تکی را بدون ارائه‌دهندهٔ هویت خارجی محافظت می‌کند، پس برای داشبوردی در معرض اینترنت عمومی استفاده‌اش نکنید — آنجا سراغ OAuth بروید.

بقیهٔ این بخش مسیر نام‌کاربری/رمزعبور را نشان می‌دهد چون سریع‌ترین راه‌اندازی روی شبکهٔ مطمئن است؛ برای مسیر OAuth به «داشبورد وب ← ارائه‌دهندهٔ پیش‌فرض: Nous Research» مراجعه کنید.

روی بک‌اند (ماشین راهن)

نام کاربری و رمز بگذارید، سپس بک‌اند را متصل به آدرس قابل‌دسترسی اجرا کنید. اعتبارها در ~/.hermes/.env زندگی می‌کنند (فایل رازها، حالت 0600):

bash
# ۱. تنظیم اعتبار ورود داشبورد.
cat >> ~/.hermes/.env <<'EOF'
HERMES_DASHBOARD_BASIC_AUTH_USERNAME=admin
HERMES_DASHBOARD_BASIC_AUTH_PASSWORD=choose-a-strong-password
# توصیه‌شده: یک راز امضای پایدار تا نشست‌ها از ری‌استارت جان سالم ببرند.
# بدون آن، کلید تصادفی به‌ازای هر بوت تولید و با هر ری‌استارت
# خارج می‌شوید.
HERMES_DASHBOARD_BASIC_AUTH_SECRET=$(openssl rand -base64 32)
EOF
chmod 600 ~/.hermes/.env

# ۲. اجرای بک‌اند متصل به آدرس قابل‌دسترس. اتصال غیرحلقه‌محلی
#    دروازهٔ احراز را درگیر می‌کند؛ ارائه‌دهندهٔ نام‌کاربری/رمز ورود را هندل می‌کند.
hermes serve --host 0.0.0.0 --port 9119

پروسهٔ hermes serve را تا وقتی می‌خواهید اپ دسکتاپ بتواند وصل شود نگه دارید — اگر بایستد، اپ دیگر به بک‌اند نمی‌رسد. زیر systemd، ‏tmux یا مدیر پروسهٔ دلخواهتان اجرایش کنید تا از خروج و ری‌بوت جان سالم به در ببرد.

جداگانه، اگر به کانال‌های پیام‌رسانی تکیه دارید مطمئن شوید گیت‌وی روی میزبان راهن اجراست — بک‌اند hermes serve چیزی است که اپ دسکتاپ با آن حرف می‌زند، ولی نشست‌های گیت‌وی تلگرام/دیسکورد/اسلک شما پروسهٔ متفاوتی‌اند که خودتان شروع و نگه می‌دارید. برای راه‌اندازی گیت‌وی به «پیام‌رسان‌ها» مراجعه کنید.

ترجیح می‌دهید رمز متنی در سکونت نگذارید؟ به‌جایش HERMES_DASHBOARD_BASIC_AUTH_PASSWORD_HASH را روی هش scrypt بگذارید — با python -c "from plugins.dashboard_auth.basic import hash_password; print(hash_password('PW'))" محاسبهاش کنید. سطح پیکربندی کامل (کلیدهای config.yaml، هر متغیر محیطی، محدودکنندهٔ نرخ): «داشبورد وب ← ارائه‌دهندهٔ نام‌کاربری/رمزعبور».

بک‌اند را به‌عنوان سرویس systemd اجرا می‌کنید؟ به یونیت EnvironmentFile=%h/.hermes/.env بدهید تا اعتبارها هنگام بوت در محیط باشند.

⚠️ هشدار

بک‌اند .env شما را می‌خواند و می‌نویسد (کلیدهای API، رازها) و می‌تواند فرمان ایجنت اجرا کند. راه‌اندازی نام‌کاربری/رمزعبور بالا برای شبکهٔ مطمئن است — هرگز بک‌اندِ محافظت‌شده-با-رمز را مستقیم در معرض اینترنت باز نکنید؛ پشت VPN بگذاریدش. Tailscale گزینهٔ تمیز است: به IP تیل‌اسکیل ماشین متصل شوید‏ (--host <tailscale-ip>) و http://<tailscale-ip>:9119 را به‌عنوان URL راهن استفاده کنید تا فقط تیل‌نتتان بتواند برسد. برای دسترسی به بک‌اند از اینترنت عمومی، به‌جایش از ارائه‌دهندهٔ OAuth (‏Nous Portal) استفاده کنید.

در اپ

Settings ← Gateways ← Remote gateway:

  1. Remote URL — ‏http://<backend-host>:9119 (پیشوندهای مسیر مثل /hermes اگر پروکسی معکوس جلویش باشد کار می‌کنند)
  2. Sign in — اپ تشخیص می‌دهد بک‌اند کدام ارائه‌دهنده را اعلام کرده و دکمه را تطبیق می‌دهد. برای بک‌اند نام‌کاربری/رمز، دکمهٔ Sign in را نشان می‌دهد که فرم اعتبار باز می‌کند (اعتبارهای گام ۱ را وارد کنید). برای بک‌اند OAuth، ‏Sign in with <provider> را نشان می‌دهد که ورود مرورگریِ ارائه‌دهنده را اجرا می‌کند. به‌هرحال اپ با نشستِ احراز‌شده‌ای مقابل بک‌اند تمام می‌کند.
  3. Save and reconnect — پوستهٔ دسکتاپ را روی بک‌اند راهن سوییچ می‌کند. نشست خودکار نوسازی می‌شود؛ با تنظیم HERMES_DASHBOARD_BASIC_AUTH_SECRET از ری‌استارت‌ها وارد مانده‌اید.

URL بک‌اند را بدون UI هم می‌توانید با متغیر محیطی HERMES_DESKTOP_REMOTE_URL پیش از اجرای اپ بگذارید (تنظیم درون‌اپی را بازنویسی می‌کند)؛ ورود همچنان از پنل تنظیمات Gateways.

ℹ️ میزبان‌های راهن به‌ازای-پروفایل

میزبان گیت‌وی راهن به‌ازای پروفایل پیکربندی می‌شود، پس هر پروفایل می‌تواند به بک‌اند راهن خودش اشاره کند (یا روی محلی‌اش بماند). تعویض پروفایل عوض می‌کند اپ به کدام میزبان راهن وصل شود.

عیب‌یابی اتصال راهن

  • ورود با ۴۰۱ / «Invalid credentials» شکست می‌خورد — نام کاربری یا رمز با HERMES_DASHBOARD_BASIC_AUTH_USERNAME / ‏HERMES_DASHBOARD_BASIC_AUTH_PASSWORD بک‌اند مطابق نیست. بک‌اند برای کاربر ناشناس و رمز غلط همان خطای عمومی را برمی‌گرداند (بدین‌وسیله oracle شمارش کاربر نیست)، پس هر دو را دوباره چک کنید. روشن‌بودن دروازه را با curl -s http://<host>:9119/api/status | jq '.auth_required, .auth_providers' تأیید کنید — باید true بگوید و شامل "basic" باشد.
  • دکمهٔ «Sign in» نیست — به‌جایش توکن نشست می‌خواهد — ارائه‌دهندهٔ نام‌کاربری/رمزِ بک‌اند فعال نیست. /api/status در auth_providers لیستِ "basic" را نخواهد داشت. مطمئن شوید هم نام کاربری و هم رمز (یا هش رمز) در ~/.hermes/.env تنظیم‌اند و پروسهٔ داشبورد واقعاً بارگذاری‌شان کرده.
  • با هر ری‌استارت خارج می‌شوید — HERMES_DASHBOARD_BASIC_AUTH_SECRET را روی مقدار پایداری بگذارید. بدون آن کلید امضای توکن به‌ازای هر بوت دوباره تولید و همهٔ نشست‌ها بی‌اعتبار می‌شوند.
  • اتصال رد شد / تایم‌اوت — بک‌اند به 127.0.0.1 (پیش‌فرض) متصل است یا فایروال/VPN پورت را می‌بندد. به 0.0.0.0 یا IP تیل‌اسکیل متصل و پورت را به شبکهٔ مطمئنتان باز کنید.

۹ گسترش اپ دسکتاپ

اپ دسکتاپ مشارکت‌محور است — پنل‌ها، صفحه‌ها، ناوبری سایدبار، آیتم‌های نوار وضعیت، فرمان‌های پالت، کلیدبایندها و تم‌ها همه از یک SDK ثبت می‌شوند، و می‌توانید خودتان اضافه کنید. یک پلاگین یک فایل ESM تکی است که در $HERMES_HOME/desktop-plugins/<id>/plugin.js انداخته می‌شود؛ اپ در چند ثانیه بارگذاری‌اش می‌کند و با هر ذخیره هات‌ری‌لود می‌شود. پلاگین‌های نصب‌شده را به‌صورت زنده در Settings ← Plugins مدیریت کنید.

برای مرجع کامل به «SDK پلاگین دسکتاپ» مراجعه کنید. (این از سیستم پلاگین داشبورد وب جدا است.)

بخش Agent plugins روی همان صفحهٔ Settings ← Plugins، پلاگین‌های سمت-بک‌اند (ایجنت)ی که نصب کرده‌اید را مدیریت می‌کند — نصب‌های user، ‏git، ‏project، ‏pip و قابل‌حمل. داخلی‌های همراه-مخزن (آداپتورهای پلتفرم، پلاگین‌های ارائه‌دهنده و مشابه) آنجا فهرست نمی‌شوند: به‌طور پیش‌فرض فعال عرضه و از سطوح خودشان پیکربندی می‌شوند، پس بخش روی چیزهایی که خودتان اضافه کرده‌اید متمرکز می‌ماند. با دو یا چند پروفایل، بخش انتخاب‌گر Applies to خودش را هم دارد تا پلاگین‌های ایجنتِ پروفایل دیگری را بدون سوییچ‌کردن کل اپ فهرست و سوییچ کنید (‏RPC مربوط به plugins.manage پارامتر اختیاری profile را برای همین می‌پذیرد).

۱۰ عیب‌یابی

نوبت‌های شکست‌خورده لایهٔ شکست را نام می‌برند

وقتی نوبتی شکست می‌خورد، چت کارت خطایی رندر می‌کند که کدام لایه شکست خورده را نام می‌برد — ارائه‌دهنده/مدل، اندپوینت سفارشی، اتصال استریم، احراز هویت، صورت‌حساب، گیت‌وی، زمان اجرای محلی یا دیسک — به‌جای توست خطای عمومی. کارت اکشن‌های بازیابیِ منطبق با شکست پیشنهاد می‌کند:

  • Retry — نوبت شکست‌خورده را درجا دوباره اجرا می‌کند (وقتی retry شکست را قطعاً بازتولید می‌کند مخفی است، مثلاً رد سیاست-محتوا).
  • Switch provider — برای شکست‌های ارائه‌دهنده/اندپوینت/احراز/صورت‌حساب به Settings ← Models می‌پرد.
  • Open logs — HERMES_HOME/logs را در مدیر فایلتان باز می‌کند. روی اتصال راهن یا Cloud دکمه Open Desktop logs خوانده می‌شود: لاگ‌های محلیِ سمت-دسکتاپ را باز می‌کند (شواهد ترنسپورت)، چون لاگ‌های گیت‌وی/ایجنتِ نوبتِ شکست‌خورده روی ماشین راهن‌اند.
  • Send diagnostics — پس از اعلان رضایت صریح، باندل دیباگِ پاک‌سازی‌شده را در ذخیره‌گاه درونی Nous آپلود می‌کند (همان خط لولهٔ hermes debug share --nous؛ رازها همیشه پاک می‌شوند، باندل فقط برای کارکنان Nous قابل‌مشاهده و پس از ۱۴ روز خودکار حذف است). با موفقیت، لینک نمای خصوصی می‌گیرید که در ترد پشتیبان‌تان پیست کنید، به‌علاوهٔ لینک‌های سریع به GitHub Issues، ‏Nous Portal Support و دیسکورد. روی اتصال راهن یا Cloud بک‌اند لاگ‌های ایجنت/گیت‌وی خودش را باندل و لاگ محلی دسکتاپ کنارش پیوست می‌شود تا پشتیبان هر دو نیمه را ببیند.
  • Copy error details — خلاصهٔ متنی-سادهٔ فشرده (لایه، کد، ارائه‌دهنده/مدل، پیام خطا) را کپی می‌کند تا در گزارش باگ یا دیسکورد پیست کنید.

لایه از همان طبقه‌بند خطایی می‌آید که حلقهٔ retry ایجنت استفاده می‌کند، پس معناشناسی واقعی شکست را بازتاب می‌دهد نه حدسی از متن پیام. بک‌اندهای قدیمی‌تر از این توصیف‌گر، کارت را با عنوان عمومی و اکشن‌های Retry / ‏Open logs / ‏Copy error details رندر می‌کنند.

لاگ‌های بوت در HERMES_HOME/logs/desktop.log فرود می‌آیند (خروجی بک‌اند و تریس‌بک‌های پایتون اخیر را شامل می‌شود) — اگر اپ خرابی بوت گزارش کرد اول آن را چک کنید. از CLI هم می‌توانید دنبالش بروید:

bash
hermes logs gui -f

ریست‌های رایج:

bash
# اجبار راه‌اندازی-اولِ تمیز (مک/لینوکس)
rm "$HOME/.hermes/hermes-agent/.hermes-bootstrap-complete"

# بازسازی venv پایتونیِ خراب (مک/لینوکس)
rm -rf "$HOME/.hermes/hermes-agent/venv"

# ریست پرامپت گیرکردهٔ میکروفون مک
tccutil reset Microphone com.nousresearch.hermes

«کلید میزبان از آخرین اتصال تغییر کرده» (SSH راهن)

اگر SSH راهن‌تان نصب مجدد شده یا کلید میزبانش چرخیده، SSH ایمن شکست می‌خورد و دسکتاپ به‌جای retry یک اورلی خطا قفل می‌کند (retry تا وقتی کلید کهنه پاک نشود هرگز موفق نمی‌شود). تأیید کنید تغییر موردانتظار است، سپس مدخل قدیمی را حذف و از اورلی retry کنید:

bash
ssh-keygen -R <host>

پس از پاک‌کردن مدخل روی Retry کلیک کنید (یا اتصال را در Settings ← Gateway دوباره اعمال کنید) — قفل ریست و بوت بعدی تازه شماره می‌گیرد.

«Build desktop app» روی دانلود Electron گیر کرده

بیلد زمان اجرای Electron ‏(~۱۱۴ مگابایت) را از ریلیزهای گیت‌هاب دانلود می‌کند. اگر نصب‌کننده روی گام Build desktop app با خروجی زندهٔ تکرارشوندهٔ retrying attempt=… بایستد، گیت‌هاب روی شبکهٔ شما مسدود یا کند شده (فایروال، پروکسی یا منطقه).

نصب‌کننده این را خوددرمانی می‌کند: در بیلد ناموفق (۱) زیپ کش‌شدهٔ خراب Electron را پاک و retry می‌کند، سپس (۲) اگر باز هم شکست خورد و ELECTRON_MIRROR نگذاشته‌اید، یک بار دیگر از طریق npmmirror.com — آینهٔ غیررسمی جامعهٔ Electron — retry می‌کند. @electron/get دانلود را SHASUM-چک می‌کند، ولی چک‌سام‌ها از همان آینه می‌آیند — یعنی دانلود خراب/ناقص را می‌گیرد، نه آینهٔ نفوذشده را. اگر نمی‌خواهید به میزبان شخص‌ثالث اعتماد کنید، ELECTRON_MIRROR خودتان را پین کنید (پایین)؛ بیلد هرگز چیزی را که گذاشته‌اید بازنویسی نمی‌کند.

برای انتخاب آینهٔ خودتان (مثلاً شرکتی/مطمئن)، پیش از نصب ELECTRON_MIRROR را بگذارید یا دستی بازبیلد کنید:

bash
ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ \
  bash -c 'cd "$HOME/.hermes/hermes-agent/apps/desktop" && CSC_IDENTITY_AUTO_DISCOVERY=false npm run pack'

پاک‌کردن دستی زیپ کش‌شدهٔ خراب:

bash
rm -f "$HOME/Library/Caches/electron"/electron-*.zip   # مک
rm -f "$HOME/.cache/electron"/electron-*.zip            # لینوکس

۱۱ ساخت از سورس

اگر می‌خواهید روی خود اپ هک کنید، وابستگی‌های ورک‌اسپیس را یک بار از ریشهٔ مخزن نصب کنید، سپس سرور dev را از apps/desktop اجرا کنید:

bash
npm install          # از ریشهٔ مخزن — apps/desktop و web و apps/shared را لینک می‌کند
cd apps/desktop
npm run dev          # رندرکنندهٔ Vite + Electron که بک‌اند پایتون را بوت می‌کند

اپ را به چک‌اوت مشخصی اشاره دهید، یا از پیکربندی واقعی‌تان سندباکس کنید:

bash
HERMES_DESKTOP_HERMES_ROOT=/path/to/clone npm run dev
HERMES_HOME=/tmp/throwaway npm run dev
npm run dev:fake-boot   # تمرین اورلی شروع با تأخیرهای قطعی

ساخت نصب‌کننده‌ها:

bash
npm run dist:mac     # DMG + zip
npm run dist:win     # NSIS + MSI
npm run dist:linux   # AppImage + deb + rpm
npm run pack         # اپ بازبسته زیر release/ (بدون نصب‌کننده)

امضا و نوتاریزیشن مک/ویندوز وقتی اعتبارنامه‌های مربوطه در محیط موجود باشند خودکار اجرا می‌شوند‏ (CSC_LINK / ‏CSC_KEY_PASSWORD / ‏APPLE_* برای مک، ‏WIN_CSC_* برای ویندوز).

مجوزهای مک و بازبیلدهای محلی (TCC)

مک مجوزها (دسترسی کامل دیسک، Desktop/Downloads/Documents، دسترس‌پذیری، اتوماسیون، میکروفون) را مقابل هویت امضای کد اپ به خاطر می‌سپارد، نه مسیرش. اپ‌های محلی-بیلد و خودبه‌روزشونده با امضای ad-hocِ پین‌شده-به-شناسهٔ پایدار امضا می‌شوند، پس مجوزها از بدو امر از به‌روزرسانی‌ها جان سالم به در می‌برند.

برای قوی‌ترین تضمین — هویتی لنگرشده-به-گواهی، همان سازوکاری که کاربران yabai/skhd به آن تکیه می‌کنند — یک‌بار گواهی امضای کدِ خودامضای بسازید و به هرمس بگویید استفاده‌اش کند:

  1. ‏Keychain Access ← Certificate Assistant ← Create a Certificate…
  2. نام: Hermes Local Signing، نوع هویت: *Self-Signed Root*، نوع گواهی: Code Signing.
  3. hermes config set desktop.macos_signing_identity "Hermes Local Signing"

به‌روزرسانی بعدی اپِ بازبیلدشده را با همان گواهی دوباره امضا می‌کند؛ هر مجوز TCC زنده می‌ماند. هیچ اکانت Apple Developer لازم نیست. بیلدهای نوتاریزه‌شدهٔ رسمی تشخیص و هرگز دوباره-امضا نمی‌شوند.

یادداشت یک‌باره: تغییر هویت امضا (از جمله اولین به‌روزرسانی پس از این اصلاح) هویت اپ را یک بار عوض می‌کند، پس مک یک بار آخر می‌پرسد. از آن پس مجوزها پایدارند. اگر مجوزی گیر کرد، با tccutil reset All com.nousresearch.hermes ریست و دوباره بدهید.
