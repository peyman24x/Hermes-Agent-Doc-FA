خانه/پیام‌رسان‌ها/Mattermost

راه‌اندازی Mattermost

هرمس ایجنت با Mattermost به‌صورت بات یکپارچه می‌شود و اجازه می‌دهد از طریق پیام خصوصی یا کانال‌های تیم با دستیار هوش مصنوعی‌تان گفتگو کنید. Mattermost جایگزین متن‌بازِ خودمیزبانِ Slack است — روی زیرساخت خودتان اجرایش می‌کنید و کنترل کامل داده‌ها را دارید. بات از طریق REST API نسخهٔ v4 و WebSocket برای رویدادهای لحظه‌ای وصل می‌شود، پیام‌ها را از خط‌لولهٔ هرمس ایجنت ‏(شامل استفاده از ابزار، حافظه و استدلال) عبور می‌دهد و در لحظه پاسخ می‌دهد. متن، پیوست فایل، تصویر و فرمان اسلش را پشتیبانی می‌کند.

کتابخانهٔ خارجی Mattermost لازم نیست — آداپتور از aiohttp استفاده می‌کند که از قبل وابستگی هرمس است.

پیش از راه‌اندازی، بخشی که بیشتر افراد می‌خواهند بدانند: رفتار هرمس پس از ورود به نمونهٔ Mattermost شما چگونه است.

۱ رفتار هرمس

زمینهرفتار
پیام‌های خصوصی ‏(DM)هرمس به همهٔ پیام‌ها پاسخ می‌دهد؛ نیازی به @منشن نیست. هر DM نشست مستقل خودش را دارد.
کانال‌های عمومی/خصوصیهرمس وقتی @منشن شود پاسخ می‌دهد. بدون منشن، پیام نادیده گرفته می‌شود.
تردهااگر MATTERMOST_REPLY_MODE=thread باشد، هرمس در تردی زیر پیام شما ریپلای می‌دهد. زمینهٔ ترد از کانال والد ایزوله می‌ماند.
کانال‌های مشترک چندکاربرهبه‌طور پیش‌فرض هرمس تاریخچهٔ نشست را داخل کانال به‌ازای هر کاربر جدا می‌کند. دو نفر که در یک کانال حرف می‌زنند مگر صریحاً غیرفعالش کنید رونویسی مشترک ندارند.
💡 نکته

اگر می‌خواهید هرمس به‌صورت گفتگوهای تردی ‏(تودرتوی زیر پیام اصلی‌تان) جواب بدهد، ‏MATTERMOST_REPLY_MODE=thread را بگذارید. پیش‌فرض off است که پیام‌های تخت در کانال می‌فرستد.

مدل نشست در Mattermost

به‌طور پیش‌فرض:

  • هر DM نشست مستقل خودش را دارد
  • هر ترد فضای‌نام نشست خودش را دارد
  • هر کاربر در یک کانال مشترک، داخل همان کانال نشست خودش را دارد

این با config.yaml کنترل می‌شود:

yaml
group_sessions_per_user: true

فقط اگر صریحاً یک گفتگوی مشترک برای کل کانال می‌خواهید false کنید:

yaml
group_sessions_per_user: false

نشست مشترک برای کانال مشارکتی مفید است ولی یعنی:

  • کاربران در رشد زمینه و هزینهٔ توکن شریک‌اند
  • یک کار سنگین-ابزارِ طولانیِ یک نفر می‌تواند زمینهٔ بقیه را متورم کند
  • اجرای در-جریانِ یک نفر می‌تواند پیام بعدیِ فرد دیگری در همان کانال را قطع کند

این راهنما کل فرایند راه‌اندازی را قدم‌به‌قدم توضیح می‌دهد — از ساخت بات روی Mattermost تا ارسال اولین پیام.

۲ گام ۱: فعال‌سازی حساب‌های بات

قبل از ساخت بات باید حساب‌های بات روی سرور Mattermost شما فعال باشند.

  1. به‌عنوان System Admin وارد Mattermost شوید.
  2. به System Console ← Integrations ← Bot Accounts بروید.
  3. ‏Enable Bot Account Creation را true کنید.
  4. Save را کلیک کنید.
📌 نکته

اگر دسترسی System Admin ندارید، از مدیر Mattermost بخواهید حساب‌های بات را فعال و یکی برایتان بسازد.

۳ گام ۲: ساخت حساب بات

  1. در Mattermost منوی ☰ ‏(بالا-چپ) ← Integrations ← Bot Accounts را کلیک کنید.
  2. Add Bot Account را کلیک کنید.
  3. جزئیات را پر کنید:
    • Username: مثل hermes
    • Display Name: مثل Hermes Agent
    • Description: اختیاری
    • Role: مقدار Member کافی است
  4. Create Bot Account را کلیک کنید.
  5. ‏Mattermost توکن بات را نمایش می‌دهد. فوراً کپیش کنید.
⚠️ توکن فقط یک‌بار نمایش داده می‌شود

توکن بات فقط هنگام ساخت حساب بات یک‌بار نشان داده می‌شود. اگر گمش کردید باید از تنظیمات حساب بات بازتولیدش کنید. هرگز توکن را عمومی به اشتراک نگذارید یا به گیت کامیت نکنید — هر کسی با این توکن کنترل کامل بات را دارد.

توکن را جایی امن نگه دارید ‏(مثلاً مدیر رمز). در گام ۵ لازمش دارید.

💡 نکته

می‌توانید به‌جای حساب بات از personal access token استفاده کنید. به Profile ← Security ← Personal Access Tokens ← Create Token بروید. این وقتی مفید است که بخواهید هرمس به‌عنوان کاربر خودتان پست کند نه یک کاربر بات جداگانه.

۴ گام ۳: افزودن بات به کانال‌ها

بات باید عضو هر کانالی باشد که می‌خواهید آنجا پاسخ دهد:

  1. کانال موردنظر را باز کنید.
  2. روی نام کانال کلیک کنید ← Add Members.
  3. یوزرنیم بات‌تان ‏(مثل hermes) را جست‌وجو و اضافه کنید.

برای DM ها کافی است با بات یک گفتگوی خصوصی باز کنید — بلافاصله می‌تواند پاسخ دهد.

۵ گام ۴: یافتن شناسهٔ کاربری Mattermost

هرمس ایجنت از شناسهٔ کاربری Mattermost شما برای کنترل اینکه چه کسی با بات تعامل کند استفاده می‌کند. برای یافتنش:

  1. روی آواتار‌تان ‏(گوشهٔ بالا-چپ) کلیک کنید ← Profile.
  2. شناسهٔ کاربری در دیالوگ پروفایل نمایش داده می‌شود — برای کپی رویش کلیک کنید.

شناسهٔ کاربری شما رشته‌ای الفبایی-عددیِ ۲۶کاراکتری مثل 3uo8dkh1p7g1mfk49ear5fzs5c است.

⚠️ هشدار

شناسهٔ کاربری شما یوزرنیم‌تان نیست. یوزرنیم همان چیزی است که بعد از @ می‌آید ‏(مثل @alice). شناسهٔ کاربری شناسهٔ بلند الفبایی-عددی‌ای است که Mattermost داخلی استفاده می‌کند.

روش جایگزین: شناسهٔ کاربری را از API هم می‌شود گرفت:

bash
curl -H "Authorization: Bearer YOUR_TOKEN" \
  https://your-mattermost-server/api/v4/users/me | jq .id
💡 نکته

برای گرفتن Channel ID: روی نام کانال کلیک کنید ← View Info. شناسهٔ کانال در پنل اطلاعات نمایش داده می‌شود. اگر بخواهید کانال خانگی را دستی تنظیم کنید به آن نیاز دارید.

۶ گام ۵: پیکربندی هرمس ایجنت

گزینهٔ A: راه‌اندازی تعاملی ‏(توصیه‌شده)

bash
hermes gateway setup

هنگام پرسش Mattermost را انتخاب کنید و URL سرور، توکن بات و شناسهٔ کاربری را بچسبانید.

گزینهٔ B: پیکربندی دستی

این‌ها را به فایل ~/.hermes/.env اضافه کنید:

bash
# الزامی
MATTERMOST_URL=https://mm.example.com
MATTERMOST_TOKEN=***
MATTERMOST_ALLOWED_USERS=3uo8dkh1p7g1mfk49ear5fzs5c

# چند کاربر مجاز (با ویرگول)
# MATTERMOST_ALLOWED_USERS=3uo8dkh1p7g1mfk49ear5fzs5c,8fk2jd9s0a7bncm1xqw4tp6r3e

# اختیاری: حالت ریپلای (thread یا off، پیش‌فرض: off)
# MATTERMOST_REPLY_MODE=thread

# اختیاری: پاسخ بدون @منشن (پیش‌فرض: true = منشن لازم)
# MATTERMOST_REQUIRE_MENTION=false

# اختیاری: کانال‌های پاسخ-بدون-منشن (شناسه‌ها با ویرگول)
# MATTERMOST_FREE_RESPONSE_CHANNELS=channel_id_1,channel_id_2

تنظیم رفتاری اختیاری در ~/.hermes/config.yaml:

yaml
group_sessions_per_user: true
  • ‏group_sessions_per_user: true زمینهٔ هر شرکت‌کننده را داخل کانال‌ها و تردهای مشترک ایزوله نگه می‌دارد

شروع گیت‌وی

بعد از پیکربندی، گیت‌وی Mattermost را شروع کنید:

bash
hermes gateway

بات باید ظرف چند ثانیه به سرور Mattermost شما وصل شود. برای تست بهش پیام بدهید — DM یا در کانالی که افزوده شده.

💡 نکته

می‌توانید hermes gateway را در پس‌زمینه یا به‌صورت سرویس systemd برای عملکرد مداوم اجرا کنید. جزئیات در مستندات استقرار.

۷ کانال خانگی

می‌توانید یک «کانال خانگی» تعیین کنید که بات پیام‌های پیش‌فعال را به آن بفرستد ‏(مثل خروجی job های کرون، یادآوری‌ها و اعلان‌ها). دو راه دارد:

با فرمان اسلش

/sethome را در هر کانال Mattermostی که بات حضور دارد تایپ کنید. همان کانال کانال خانگی می‌شود.

پیکربندی دستی

این را به ~/.hermes/.env اضافه کنید:

bash
MATTERMOST_HOME_CHANNEL=abc123def456ghi789jkl012mn

شناسه را با Channel ID واقعی جایگزین کنید ‏(کلیک روی نام کانال ← View Info ← کپی شناسه).

۸ حالت ریپلای

تنظیم MATTERMOST_REPLY_MODE کنترل می‌کند هرمس پاسخ‌ها را چطور پست کند:

حالترفتار
off ‏(پیش‌فرض)هرمس پیام‌های تخت در کانال پست می‌کند مثل یک کاربر عادی.
threadهرمس در تردی زیر پیام اصلی‌تان ریپلای می‌دهد. کانال‌ها را وقتی رفت‌وبرگشت زیاد است تمیز نگه می‌دارد.

در ~/.hermes/.env تنظیمش کنید:

bash
MATTERMOST_REPLY_MODE=thread

۹ رفتار منشن

به‌طور پیش‌فرض بات فقط با @منشن در کانال‌ها پاسخ می‌دهد. قابل تغییر است:

متغیرپیش‌فرضتوضیح
MATTERMOST_REQUIRE_MENTIONtrueبرای پاسخ به همهٔ پیام‌های کانال‌ها false کنید ‏(DM ها همیشه کار می‌کنند).
MATTERMOST_FREE_RESPONSE_CHANNELS—شناسه‌های کانال جداشده با ویرگول که بات حتی وقتی require_mention روشن است بدون @منشن پاسخ می‌دهد.

برای یافتن شناسهٔ کانال در Mattermost: کانال را باز کنید، روی سربرگ نام کانال کلیک و شناسه را در URL یا جزئیات کانال پیدا کنید.

وقتی بات @منشن شود، منشن قبل از پردازش خودکار از متن پیام حذف می‌شود.

۱۰ لیست‌مجاز کانال (allowed_channels)

بات را به مجموعهٔ ثابتی از کانال‌های Mattermost محدود کنید. با تنظیم، بات فقط در کانال‌هایی که شناسه‌شان در فهرست است پاسخ می‌دهد — پیام‌های هر کانال دیگری بی‌صدا نادیده گرفته می‌شوند حتی با @منشن.

‏DM ها از این فیلتر معاف‌اند، پس کاربران مجاز همیشه در پیام خصوصی به بات می‌رسند.

yaml
mattermost:
  allowed_channels:
    - "abc123def456ghi789jkl012mno"   # ‎#ops
    - "xyz987uvw654rst321opq098nml"   # ‎#incident-response

یا با متغیر محیطی ‏(جداشده با ویرگول):

bash
MATTERMOST_ALLOWED_CHANNELS="abc123def456ghi789jkl012mno,xyz987uvw654rst321opq098nml"

رفتار:

  • خالی / تنظیم‌نشده ← بدون محدودیت ‏(کاملاً سازگار رو به عقب).
  • غیرخالی ← شناسهٔ کانال باید روی فهرست باشد وگرنه پیام قبل از هر gating دیگری ‏(شرط منشن، ‏MATTERMOST_FREE_RESPONSE_CHANNELS و...) رد می‌شود.
  • شناسهٔ کانال را از UI ‏Mattermost ← سربرگ کانال ← «View Info» یا از URL کانال بگیرید.

همچنین ببینید: تفکیک فرمان ادمین/کاربر.

۱۱ عیب‌یابی

بات به پیام‌ها پاسخ نمی‌دهد

علت: بات عضو کانال نیست، یا MATTERMOST_ALLOWED_USERS شناسهٔ کاربری شما را ندارد.

راه‌حل: بات را به کانال اضافه کنید ‏(نام کانال ← Add Members ← جست‌وجوی بات). تأیید کنید شناسهٔ کاربری‌تان در MATTERMOST_ALLOWED_USERS است. گیت‌وی را ری‌استارت کنید.

خطاهای 403 Forbidden

علت: توکن بات نامعتبر است یا بات حق پست در کانال ندارد.

راه‌حل: درستی MATTERMOST_TOKEN در فایل .env را چک کنید. مطمئن شوید حساب بات غیرفعال (deactivate) نشده. تأیید کنید بات به کانال اضافه شده. اگر personal access token استفاده می‌کنید مطمئن شوید حسابتان دسترسی‌های لازم را دارد.

قطعی‌های WebSocket / حلقهٔ اتصال‌مجدد

علت: ناپایداری شبکه، ری‌استارت‌های سرور Mattermost یا مشکلات فایروال/پروکسی با اتصالات WebSocket.

راه‌حل: آداپتور خودکار با backoff نمایی reconnect می‌شود ‏(۲ ثانیه ← ۶۰ ثانیه). پیکربندی WebSocket سرورتان را چک کنید — پروکسی‌های معکوس ‏(nginx، ‏Apache) هدرهای upgrade وب‌سوکت لازم دارند. تأیید کنید هیچ فایروالی اتصالات WebSocket سرور Mattermost را نمی‌بندد.

برای nginx مطمئن شوید پیکربندی شامل این است:

nginx
location /api/v4/websocket {
    proxy_pass http://mattermost-backend;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 600s;
}

«Failed to authenticate» هنگام شروع

علت: توکن یا URL سرور اشتباه است.

راه‌حل: تأیید کنید MATTERMOST_URL به سرور Mattermost شما اشاره دارد ‏(با https://، بدون اسلش انتهایی). اعتبار MATTERMOST_TOKEN را چک کنید — با curl امتحانش کنید:

bash
curl -H "Authorization: Bearer YOUR_TOKEN" \
  https://your-server/api/v4/users/me

اگر اطلاعات کاربر بات برگرداند توکن معتبر است. اگر خطا برگرداند توکن را بازتولید کنید.

بات آفلاین است

علت: گیت‌وی هرمس اجرا نیست یا اتصالش شکست خورده.

راه‌حل: چک کنید hermes gateway در حال اجراست. خروجی ترمینال را برای پیام‌های خطا ببینید. مسائل رایج: URL اشتباه، توکن منقضی، در دسترس نبودن سرور Mattermost.

«User not allowed» / بات شما را نادیده می‌گیرد

علت: شناسهٔ کاربری شما در MATTERMOST_ALLOWED_USERS نیست.

راه‌حل: شناسه‌تان را به MATTERMOST_ALLOWED_USERS در ~/.hermes/.env اضافه و گیت‌وی را ری‌استارت کنید. یادتان باشد: شناسهٔ کاربری رشتهٔ الفبایی-عددی ۲۶کاراکتری است نه @yوزرنیم شما.

۱۲ پرامپت به‌ازای-کانال

پرامپت‌های سیستمی زودگذر را به کانال‌های مشخص Mattermost اختصاص دهید. پرامپت در زمان اجرا در هر نوبت تزریق می‌شود — هرگز در تاریخچهٔ رونویسی ذخیره نمی‌شود — پس تغییرات فوراً اثر می‌کنند.

yaml
mattermost:
  channel_prompts:
    "channel_id_abc123": |
      You are a research assistant. Focus on academic sources,
      citations, and concise synthesis.
    "channel_id_def456": |
      Code review mode. Be precise about edge cases and
      performance implications.

کلیدها شناسه‌های کانال Mattermost‌اند ‏(در URL کانال یا از API). همهٔ پیام‌های کانال منطبق پرامپت را به‌عنوان دستور سیستمی زودگذر دریافت می‌کنند.

۱۳ امنیت

⚠️ هشدار

همیشه MATTERMOST_ALLOWED_USERS را تنظیم کنید تا مشخص شود چه کسی با بات تعامل می‌کند. بدون آن، گیت‌وی به‌عنوان اقدام ایمنی همهٔ کاربران را پیش‌فرض رد می‌کند. فقط شناسهٔ کاربری افراد مورداطمینان را اضافه کنید — کاربران مجاز دسترسی کامل به قابلیت‌های ایجنت دارند شامل استفاده از ابزار و دسترسی سیستم.

برای اطلاعات بیشتر دربارهٔ امن‌سازی استقرار هرمس ایجنت، راهنمای امنیت را ببینید.

۱۴ یادداشت‌ها

  • دوستدار خودمیزبانی: با هر نمونهٔ خودمیزبان Mattermost کار می‌کند. نه حساب Mattermost Cloud می‌خواهد نه اشتراک.
  • بدون وابستگی اضافه: آداپتور برای HTTP و WebSocket از aiohttp استفاده می‌کند که همراه هرمس ایجنت هست.
  • سازگار با Team Edition: هم با Mattermost Team Edition ‏(رایگان) هم Enterprise Edition کار می‌کند.
