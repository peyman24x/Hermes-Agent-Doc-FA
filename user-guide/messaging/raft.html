راه‌اندازی Raft

هرمس به‌عنوان یک ایجنت خارجی از طریق پل کانال-بیداری محلی به ‏Raft وصل می‌شود. آداپتور یک نقطهٔ پایانی HTTP روی loopback راه می‌اندازد که سرنخ‌های بیداریِ بدون-محتوا را از پل می‌گیرد و به خط‌لولهٔ نشست گیت‌وی هرمس تزریق می‌کند. ایجنت پیام‌ها را از طریق CLI ‏Raft می‌خواند و می‌فرستد — آداپتور هیچ‌وقت بدنهٔ پیام‌ها یا نشانگرهای تحویل را لمس نمی‌کند.

📌 تقسیم کار
  • پل مالک: مصرف سرنخ بیداری، حذف تکرار، backoff، اتصال‌مجدد، تحویل حداقل-یک‌بار و لاگ اثبات است.
  • آداپتور هرمس مالک: یک نقطهٔ پایانی wake روی localhost و تزریق یک اطلاع کوتاه در زمینهٔ ایجنت است.
  • ایجنت مالک: کشیدن پیام‌ها ‏(raft message check)، پاسخ ‏(raft message send) و همهٔ تعاملات دیگر با Raft از طریق CLI.

آداپتور هیچ اعتبارنامهٔ Raft ندارد — فقط یک توکن مشترک به‌ازای-نشست برای احراز localhost بین پل و نقطهٔ پایانی.

۱ پیش‌نیازها

  • یک ورک‌اسپیس Raft که بتوانید در آن External Agent بسازید
  • ‏CLI ‏Raft نصب‌شده و وارد‌شده به آن پروفایل External Agent
  • aiohttp — بستهٔ پایتونی ‏(در extras ‏[all] هرمس هست)

در Raft منوی Agents را باز کنید، یک External Agent بسازید و کارت راه‌اندازی را برای نصب CLI و ورود پروفایل دنبال کنید. بعد از ساخت ایجنت، Raft یک راهنمای setup هرمس با متغیرهای محیطی و پیکربندی لازم برای شروع گیت‌وی نشان می‌دهد.

۲ راه‌اندازی

به ~/.hermes/.env اضافه کنید:

bash
RAFT_PROFILE=your-agent-profile

همین — آداپتور وقتی ‏RAFT_PROFILE تنظیم شود خودکار فعال می‌شود. توکن پل به‌ازای-نشست تولید، پورت گذرا انتخاب و پروسهٔ فرزند پل هنگام شروع گیت‌وی خودکار spawn می‌شود.

۳ نحوهٔ کار

text
Raft Server → Bridge (wake-hints SSE) → POST /wake → Hermes Adapter → Agent context
Agent → raft message check → Raft Server (message bodies)
Agent → raft message send → Raft Server (replies)
  1. سرور Raft سرنخ‌های بیداری را از طریق SSE به پروسهٔ پل می‌فرستد.
  2. پل هر سرنخ را به‌صورت ‏POST /wake به نقطهٔ پایانی loopback آداپتور فوروارد می‌کند.
  3. آداپتور توکن پل را تأیید، مطمئن می‌شود payload بدون‌محتواست و یک اطلاع بیداری داخل نشست هرمس تزریق می‌کند.
  4. ایجنت اطلاع بیداری را می‌بیند و با CLI ‏Raft پیام‌ها را می‌خواند و جواب می‌دهد.

payload های بیداری طبق قرارداد بدون‌محتوایند — فقط متادیتا حمل می‌کنند ‏(شناسهٔ رویداد، شناسهٔ پیام، timestamp ها) و هرگز بدنهٔ پیام، نام کانال یا هویت فرستنده نه. آداپتور هر payloadی با فیلدهای محتوادار ‏(text، ‏body، ‏content، ‏messages و...) را رد می‌کند.

۴ پل ‏(Bridge)

آداپتور خودکار ‏raft agent bridge را به‌عنوان پروسهٔ فرزند spawn می‌کند و URL نقطهٔ پایانی و توکن را می‌دهد. پل با پروفایل پیکربندی‌شده به سرور Raft وصل و شروع به فوروارد سرنخ‌های بیداری می‌کند. هنگام خاموشی گیت‌وی خاتمه می‌یابد.
