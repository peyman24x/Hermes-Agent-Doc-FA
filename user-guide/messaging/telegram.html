خانه/پیام‌رسان‌ها/تلگرام

راه‌اندازی تلگرام

هرمس ایجنت با تلگرام به‌صورت یک بات گفتگوی کامل‌عیار یکپارچه می‌شود. پس از اتصال، می‌توانید از هر دستگاهی با ایجنت‌تان چت کنید، یادداشت‌های صوتی بفرستید که خودکار رونویسی می‌شوند، نتایج کارهای زمان‌بندی‌شده دریافت کنید و از ایجنت در گفتگوهای گروهی استفاده کنید. یکپارچه‌سازی بر پایهٔ python-telegram-bot است و متن، صوت، تصویر و پیوست فایل را پشتیبانی می‌کند.

۱ گام ۱: ساخت بات با BotFather

هر بات تلگرامی به یک توکن API از @BotFather نیاز دارد.

  1. تلگرام را باز و @BotFather را جست‌وجو کنید
  2. /newbot بفرستید
  3. یک نام نمایشی انتخاب کنید (مثلاً «Hermes Agent») — هر چیزی می‌تواند باشد
  4. یک یوزرنیم انتخاب کنید — باید یکتا و به bot ختم شود (مثلاً my_hermes_bot)
  5. BotFather با توکن API شما پاسخ می‌دهد:
token
123456789:ABCdefGHIjklMNOpqrSTUvwxYZ
⚠️ هشدار

توکن بات را محرمانه نگه دارید. هر کسی با این توکن می‌تواند بات‌تان را کنترل کند. اگر لو رفت، بلافاصله با /revoke در BotFather لغوش کنید.

۲ گام ۲: سفارشی‌سازی بات (اختیاری)

فرمانهدف

/setabouttextمتن کوتاه در صفحهٔ پروفایل بات
/setuserpicآپلود آواتار برای بات

💡 نکته

برای /setcommands یک مجموعهٔ شروع مفید:

commands
help - Show help information
new - Start a new conversation
sethome - Set this chat as the home channel

نشانگر وضعیت آنلاین/آفلاین (اختیاری)

بات‌های تلگرام نقطهٔ حضور واقعی آنلاین/آفلاین ندارند — آن نقطهٔ سبز قابلیتِ حساب-کاربری است، نه چیزی که Bot API عرضه کند. نزدیک‌ترین سطح، توضیح کوتاه بات است. status_indicator را فعال کنید و هرمس آن توضیح را هنگام اتصال گیت‌وی روی Online و هنگام خاموشی تمیز روی Offline می‌گذارد:

yaml
gateway:
  platforms:
    telegram:
      extra:
        status_indicator: true
        status_online: "🟢 Online"     # اختیاری (پیش‌فرض: "Online")
        status_offline: "🔴 Offline"   # اختیاری (پیش‌فرض: "Offline")

توضیح کوتاه سراسری بات است (همهٔ کاربران می‌بینند). فقط خاموشیِ تمیز «Offline» می‌نویسد؛ کرش سخت وضعیت آخر را می‌گذارد. پیش‌فرض خاموش.

اولویت و سقف منوی فرمان (اختیاری)

هرمس منوی فرمان را هنگام شروع گیت‌وی خودکار ثبت می‌کند. سقف پیش‌فرض ۶۰ فرمان است. اگر فرمان‌های محلی/پلاگینی دارید که باید در انتخابگر / تلگرام بمانند، اولویت‌شان کنید:

yaml
platforms:
  telegram:
    extra:
      command_menu:
        max_commands: 60
        priority_mode: prepend  # prepend | append | replace
        priority:
          - my_plugin_command

priority_mode: ‏prepend فرمان‌های شما اول، بعد پیش‌فرض‌های هرمس؛ ‏append پیش‌فرض‌ها اول؛ ‏replace فقط فهرست شما. تلگرام تا ۱۰۰ فرمان می‌پذیرد ولی هرمس برای اطمینان روی ۶۰ سقف می‌زند و مقادیر را به ۱..۱۰۰ محدود می‌کند.

۳ گام ۳: حالت حریم خصوصی (بحرانی برای گروه‌ها)

بات‌های تلگرام حالت حریم خصوصی دارند که پیش‌فرض روشن است. رایج‌ترین منبع سردرگمی در استفاده از بات در گروه‌ها همین است.

با حریم خصوصی روشن، بات فقط می‌بیند: پیام‌های شروع‌شونده با /؛ ‏ریپلای‌های مستقیم به پیام‌های خود بات؛ پیام‌های سرویس (عضویت/خروج، پین و غیره)؛ و پیام‌های کانال‌هایی که بات ادمین آن‌هاست.

با حریم خصوصی خاموش، بات هر پیام گروه را دریافت می‌کند.

غیرفعال‌کردن حریم خصوصی

  1. به @BotFather پیام دهید
  2. /mybots بفرستید
  3. بات‌تان را انتخاب کنید
  4. Bot Settings ← Group Privacy ← Turn off
⚠️ هشدار

باید بات را از گروه حذف و دوباره اضافه کنید پس از تغییر تنظیم حریم خصوصی. تلگرام وضعیت حریم را هنگام پیوستن بات کش می‌کند و تا حذف/افزودن مجدد به‌روز نمی‌شود.

💡 نکته

جایگزین: بات را به ادمین گروه ارتقا دهید. بات‌های ادمین همیشه همهٔ پیام‌ها را صرف‌نظر از تنظیم حریم دریافت می‌کنند.

مشاهدهٔ گفتگوی گروه بدون پاسخ خودکار

برای رفتار گروهی سبک OpenClaw/Yuanbao، بات را طوری تنظیم کنید که گفتگوی عادی گروه را ببیند ولی فقط هنگام تریگر مستقیم پاسخ دهد:

yaml + bash
telegram:
  allowed_chats:
    - "-1001234567890"
  group_allowed_chats:
    - "-1001234567890"
  require_mention: true
  observe_unmentioned_group_messages: true

# معادل متغیر محیطی:
TELEGRAM_ALLOWED_CHATS=-1001234567890
TELEGRAM_GROUP_ALLOWED_CHATS=-1001234567890
TELEGRAM_OBSERVE_UNMENTIONED_GROUP_MESSAGES=true

پیام‌های گروهیِ بدون-منشن از چت‌های صریحاً مجاز به رونوشت نشست مشترک چت/تاپیک به‌صورت زمینهٔ مشاهده‌شده الصاق می‌شوند، ولی ایجنت را اعزام نمی‌کنند. یک @botname بعدی، ‏ریپلای یا الگوی منشنِ پیکربندی‌شده می‌تواند از آن زمینهٔ مشاهده‌شده استفاده کند. پیامِ تریگرشده با [nickname|user_id] تگ و یک پرامپت ایمنی به‌ازایی-نوبت می‌گیرد تا مدل خطوط مشاهده‌شدهٔ قبلی را زمینه تلقی کند نه دستورالعمل خطاب‌شده به بات.

۴ گام ۴: یافتن شناسهٔ کاربر

هرمس از شناسه‌های عددی کاربر تلگرام برای کنترل دسترسی استفاده می‌کند. شناسهٔ کاربر شما یوزرنیم‌تان نیست — عددی مثل 123456789 است.

روش ۱ (توصیه‌شده): به @userinfobot پیام دهید — بلافاصله شناسه‌تان را پاسخ می‌دهد.

روش ۲: به @get_id_bot پیام دهید.

۵ گام ۵: پیکربندی هرمس و شروع

گزینهٔ A (توصیه‌شده): hermes gateway setup — تلگرام را انتخاب کنید؛ ویزارد توکن بات و شناسه‌های مجاز را می‌پرسد و پیکربندی را می‌نویسد.

گزینهٔ B: دستی به ~/.hermes/.env اضافه کنید:

bash
TELEGRAM_BOT_TOKEN=123456789:ABCdefGHIjklMNOpqrSTUvwxYZ
TELEGRAM_ALLOWED_USERS=123456789    # جدا با ویرگول برای چند کاربر

# شروع:
hermes gateway

بات باید ظرف چند ثانیه آنلاین شود. در تلگرام به آن پیام بدهید تا تأیید کنید.

ارسال فایل‌های تولیدی از ترمینال‌های داکری

اگر بک‌اند ترمینال docker است، پیوست‌های تلگرام توسط پروسهٔ گیت‌وی ارسال می‌شوند نه از داخل کانتینر. مسیر MEDIA:/... باید روی میزبانی که گیت‌وی اجرا می‌شود خوانا باشد. الگوی توصیه‌شده:

yaml
terminal:
  backend: docker
  docker_volumes:
    - "/home/user/.hermes/cache/documents:/output"

داخل داکر به /output/... بنویسید و مسیر مرئی-برای-میزبان را در MEDIA: بدهید. اگر از قبل docker_volumes: دارید، مانت جدید را به همان فهرست بیفزایید — کلیدهای تکراری YAML خاموش بر هم‌دست‌های قبلی را بازنویسی می‌کنند.

پسوندهای پشتیبانی‌شدهٔ MEDIA:

دستهپسوندها
تصاویرpng jpg jpeg gif webp bmp tiff svg
صوتmp3 wav ogg m4a opus flac aac
ویدیوmp4 mov webm mkv avi
اسنادpdf txt md csv json xml html yaml yml log
آفیسdocx xlsx pptx odt ods odp
آرشیوzip rar 7z tar gz bz2
کتاب / پکیجepub apk ipa

همهٔ این فهرست روی پلتفرم‌های دارای پشتیبانی بومی‏ (تلگرام، دیسکورد، سیگنال، اسلک، واتساپ، فیشو، ماتریکس و غیره) به‌صورت پیوست بومی تحویل می‌شوند؛ روی بقیه به لینک یا نشانگر متنی برمی‌گردند. دسته‌های پررنگ در آخرین ریلیزها اضافه شدند — اگر روی مدلِ گفتنِ «here is the file: /path/to/report.docx» تکیه داشتید، به MEDIA:/path/to/report.docx بروید.

۶ حالت Webhook

پیش‌فرض هرمس با long polling وصل می‌شود. برای استقرارهای ابری‏ (‏Fly.io، ‏Railway، ‏Render و غیره) وب‌هوک به‌صرفه‌تر است — تلگرام به‌روزرسانی‌ها را به URL ‏HTTPS بات‌تان پوش می‌کند و ماشین می‌تواند بین پیام‌ها بخوابد.

Polling ‏(پیش‌فرض)Webhook
جهتگیت‌وی ← تلگرام (خروجی)تلگرام ← گیت‌وی (ورودی)
بهترین برایسرورهای محلی، همیشه-روشنپلتفرم‌های ابری با بیدارباش خودکار
راه‌اندازیبدون پیکربندی اضافهTELEGRAM_WEBHOOK_URL
هزینهٔ بیکاریماشین باید روشن بماندماشین می‌تواند بین پیام‌ها بخوابد
bash — در ~/.hermes/.env
TELEGRAM_WEBHOOK_URL=https://my-app.fly.dev/telegram
TELEGRAM_WEBHOOK_SECRET="$(openssl rand -hex 32)"  # الزامی
# TELEGRAM_WEBHOOK_PORT=8443        # اختیاری، پیش‌فرض 8443

TELEGRAM_WEBHOOK_SECRET الزامی است — گیت‌وی بدون آن شروع نمی‌شود. مثال استقرار Fly.io:

bash + toml
fly secrets set TELEGRAM_WEBHOOK_URL=https://my-app.fly.dev/telegram
fly secrets set TELEGRAM_WEBHOOK_SECRET=$(openssl rand -hex 32)

# fly.toml:
[[services]]
  internal_port = 8443
  protocol = "tcp"
  [[services.ports]]
    handlers = ["tls", "http"]
    port = 443

fly deploy

لاگ گیت‌وی باید نشان دهد: [telegram] Connected to Telegram (webhook mode).

۷ پشتیبانی پراکسی

yaml + bash
# config.yaml (توصیه‌شده):
telegram:
  proxy_url: "socks5://127.0.0.1:1080"

# یا متغیر محیطی:
TELEGRAM_PROXY=socks5://127.0.0.1:1080

طرح‌های پشتیبانی‌شده: http://، ‏https://، ‏socks5://. پراکسی روی اتصال اصلی و ترنسپورت IP جایگزین اعمال می‌شود. اگر پراکسی مخصوص تلگرام تنظیم نباشد، به HTTPS_PROXY / ‏HTTP_PROXY / ‏ALL_PROXY برمی‌گردد. اگر مسیر کشف IP جایگزین ناسالم است: ‏HERMES_TELEGRAM_DISABLE_FALLBACK_IPS=true و ‏HERMES_TELEGRAM_FALLBACK_DISCOVERY_TIMEOUT ‏(پیش‌فرض ۵ ثانیه).

۸ کانال خانگی و پیام‌های صوتی

کانال خانگی

با /sethome در هر چتی‏ (‏DM یا گروه) آن را به‌عنوان کانال خانگی تعیین کنید — نتایج کرون به این کانال تحویل می‌شود. دستی هم می‌شود:

bash
TELEGRAM_HOME_CHANNEL=-1001234567890
TELEGRAM_HOME_CHANNEL_NAME="My Notes"
# در حالت تاپیک برای تحویل کرون:
TELEGRAM_CRON_THREAD_ID=<topic_thread_id>

شناسهٔ چت گروه عدد منفی است. شناسهٔ DM شخصی شما همان شناسهٔ کاربرتان است.

پیام‌های صوتی ورودی (گفتار-به-متن)

یادداشت‌های صوتی شما خودکار توسط ارائه‌دهندهٔ STT رونویسی و به‌صورت متن در گفتگو تزریق می‌شوند: local از faster-whisper روی ماشین هرمس؛ ‏groq نیازمند GROQ_API_KEY؛ ‏openai نیازمند VOICE_TOOLS_OPENAI_KEY.

ردکردن STT: اگر می‌خواهید خود ایجنت صوت را هندل کند، ‏stt.enabled: false بگذارید — پیام صوتی دانلود ولی رونویسی نمی‌شود و ایجنت نشانی فایل را می‌گیرد:

نشانگر
[The user sent a voice message: /home/<user>/.hermes/cache/audio/<hash>.ogg]

پیام‌های صوتی خروجی (متن-به-گفتار)

صوت تولیدی TTS به‌صورت حباب صوتی بومی تلگرام تحویل می‌شود: OpenAI و ElevenLabs بومی Opus می‌سازند؛ ‏Edge TTS ‏(ارائه‌دهندهٔ رایگان پیش‌فرض) MP3 می‌دهد و برای تبدیل به Opus به ffmpeg نیاز دارد:

bash
# Ubuntu/Debian
sudo apt install ffmpeg
# macOS
brew install ffmpeg

بدون ffmpeg، صوت Edge به‌صورت فایل صوتی معمولی فرستاده می‌شود (هنوز پخش‌شدنی، ولی پخش‌کنندهٔ مستطیلی).

۹ فایل‌های بزرگ (بالای ۲۰MB) با سرور Bot API محلی

‏Bot API عمومی تلگرام دانلود getFile را روی ۲۰ مگابایت سقف می‌زند. راه مستند، اجرای یک دیمن محلی telegram-bot-api است که سقف را به ۲ گیگابایت می‌رساند و هرمس با دیدن base_url سفارشی، سقف داخلی خود را خودکار بالا می‌برد. این قابلیت‌ها را باز می‌کند: یادداشت‌های صوتی طولانی (جلسهٔ ۴۵ دقیقه‌ای)، ویدیوهای بزرگ برای پردازش بینایی و آرشیو صوت خام.

گام ۱: دریافت اعتبارنامهٔ MTProto

سرور محلی با لایهٔ MTProto تلگرام حرف می‌زند و به api_id و api_hash نیاز دارد — از my.telegram.org/apps.

گام ۲: اجرای سرور با داکر

yaml — docker-compose
services:
  tg-bot-api:
    image: aiogram/telegram-bot-api:latest
    container_name: tg-bot-api
    restart: unless-stopped
    ports:
      - "127.0.0.1:8081:8081"   # فقط loopback؛ نکتهٔ امنیتی را ببینید
    environment:
      TELEGRAM_API_ID: "12345"           # api_id شما
      TELEGRAM_API_HASH: "abcdef..."     # api_hash شما
      TELEGRAM_LOCAL: "1"                # حالت --local (‏۲۰MB ← ۲GB)
    volumes:
      - ./tg-bot-api-data:/var/lib/telegram-bot-api
⚠️ امنیت

سرور Bot API محلی توکن بات را در مسیر URL می‌گیرد بدون احراز اضافه. هر کسی که به پورت برسد می‌تواند کاملاً بات را کنترل کند. کانتینر را به 127.0.0.1 بایند کنید و/یا جلویش پروکسی معکوس روی شبکهٔ خصوصی. هرگز پورت 8081 را در اینترنت باز نکنید.

گام ۳: خروج بات از API عمومی (یک‌بار)

bash
curl "https://api.telegram.org/bot<YOUR_BOT_TOKEN>/logOut"
# پاسخ موردانتظار: {"ok":true,"result":true}

# تأیید: سرور محلی می‌تواند صحبت کند:
curl "http://127.0.0.1:8081/bot<YOUR_BOT_TOKEN>/getMe"

گام ۴: اشارهٔ هرمس به سرور محلی

yaml — در ~/.hermes/config.yaml
platforms:
  telegram:
    extra:
      base_url: "http://127.0.0.1:8081/bot"
      base_file_url: "http://127.0.0.1:8081/file/bot"
      local_mode: true        # فقط اگر دایرکتوری داده بات برای هرمس خواناست
⚠️ از platforms.telegram.extra استفاده کنید نه telegram.extra

فعلاً فقط فرم platforms.<name>.extra در پیکربندی عمیق-مرج می‌شود. کلیدهای زیر بلوک سطح‌بالای telegram.extra خاموش دور ریخته می‌شوند.

گام ۵: local_mode — دسترسی فایل روی دیسک

سرور محلی دو راه دارد: بدون --local فایل روی HTTP سرو می‌شود (سقف ۲۰MB می‌ماند)؛ با --local فایل روی فایل‌سیستم نوشته و getFile مسیر مطلق برمی‌گرداند. هرمس باید بایت‌ها را از دیسک بخواند — local_mode: true بگذارید و مطمئن شوید پروسهٔ هرمس مسیر را می‌تواند بخواند. دو سناریو: همان ماشین‏ (والوم داده را به دایرکتوری خوانا برای هرمس بایند کنید و user: در compose تطبیق دهید)؛ ماشین‌های متفاوت‏ (دایرکتوری داده سرور باید در همان مسیر مطلق با ماشین هرمس به اشتراک باشد — NFS خوب کار می‌کند). اگر local_mode: true ولی stat شکست بخورد، پایتون-تلگرام-بات خاموش به HTTP برمی‌گردد که در حالت --local با 404 پاسخ می‌دهد — علامتش در gateway.log: [Telegram] Failed to cache voice: Not Found.

گام ۶: تست

یادداشت صوتی بالای ۲۰MB بفرستید و tail -f ~/.hermes/logs/gateway.log | grep -iE "telegram|cache" — باید [Telegram] Cached user voice at ... ببینید بدون ردِ «too large».

۱۰ استفاده در گروه

  • حریم خصوصی تعیین می‌کند بات چه پیام‌هایی می‌بیند.
  • TELEGRAM_ALLOWED_USERS همچنان اعمال می‌شود — فقط کاربران مجاز می‌توانند بات را تریگر کنند، حتی در گروه.
  • با telegram.require_mention: true بات از گفتگوی عادی گروه پاسخ نمی‌دهد. پیام‌ها پذیرفته می‌شوند وقتی: ریپلای به بات؛ منشن @botusername؛ ‏/command@botusername؛ یا تطبیق mention_patterns.
  • با چند بات هرمس در یک گروه، exclusive_bot_mentions ‏(پیش‌فرض روشن) مسیریابی قطعی می‌کند — فقط بات‌های منشن‌شده پردازش می‌کنند.
  • تغییر یوزرنیم بات در BotFather خودکار برداشت می‌شود.
  • telegram.ignored_threads هرمس را در تاپیک‌های مشخص ساکت نگه می‌دارد.
  • مشاهده بدون پاسخ: observe_unmentioned_group_messages: true همان‌طور که بالا گفته شد.

چند بات هرمس در یک گروه

برای هر پروفایل یک توکن بات جدا بسازید و به‌ازای-پروفایل گیت‌وی اجرا کنید — توکن یکسان در چند گیت‌ویِ هم‌زمان پذیرفته نمی‌شود. پیکربندی توصیه‌شده: require_mention: true + exclusive_bot_mentions: true + mention_patterns: [].

bash
hermes gateway start && hermes -p research gateway start

با exclusive_bot_mentions، پیامی مثل @research_bot @ops_bot summarize this فقط توسط آن دو پردازش می‌شود — بقیه حتی با ریپلای هم ساکت می‌مانند.

عیب‌یابی: در DM کار می‌کند ولی گروه نه

  1. تحویل تلگرام: حریم خصوصی BotFather را خاموش، بات را ادمین یا مستقیم منشن کنید.
  2. بازپیوستن: پس از تغییر حریم، بات را از گروه حذف و دوباره اضافه کنید.
  3. مجوز هرمس: فرستنده در TELEGRAM_ALLOWED_USERS یا TELEGRAM_GROUP_ALLOWED_USERS است یا گروه در TELEGRAM_GROUP_ALLOWED_CHATS.
  4. فیلتر منشن: با require_mention: true گفتگوی عادی نادیده گرفته می‌شود.
  5. چند-بات: هر پروفایل توکن یکتا و exclusive_bot_mentions روشن.

شناسهٔ گروه عدد منفی است — در TELEGRAM_GROUP_ALLOWED_CHATS بگذارید، نه فهرست کاربر.

مثال پیکربندی تریگر گروهی

yaml
telegram:
  require_mention: true
  exclusive_bot_mentions: true
  mention_patterns:
    - "^\\s*chompy\\b"     # پیام‌هایی که با chompy شروع می‌شوند هم تریگر می‌کنند
  ignored_threads:
    - 31
    - "42"                 # تاپیک‌هایی که هرمس همیشه ساکت می‌ماند

یادداشت‌های mention_patterns: regex پایتون؛ تطبیق بدون حساسیت به بزرگی/کوچکی؛ روی متن پیام و کپشن رسانه؛ الگوهای نامعتبر با هشدار نادیده؛ برای شروع-پیام با ^ لنگر کنید.

۱۱ تاپیک‌های DM خصوصی (Bot API 9.4)

Bot API 9.4 ‏(فوریه ۲۰۲۶) تاپیک‌های خصوصی را معرفی کرد — بات‌ها می‌توانند رشته‌های تاپیک را مستقیم در چت یک‌به‌یک بسازند. هر تاپیک نشست، تاریخچه و زمینهٔ کاملاً ایزولهٔ خودش را می‌گیرد.

پیکربندی

پیش‌نیاز: کاربر باید حالت Topics را در DM فعال کند‏ (اطلاعات چت ← Topics). بدون آن هرمس The chat is not a forum لاگ و رد می‌شود.

yaml
platforms:
  telegram:
    extra:
      dm_topics:
      - chat_id: 123456789
        topics:
        - name: General
          icon_color: 7322096
        - name: Website
          icon_color: 9367192
        - name: Research
          icon_color: 16766590
          skill: arxiv              # بارگذاری خودکار مهارت در این تاپیک

هرمس در شروع گیت‌وی createForumTopic می‌زند، ‏thread_id را در config پس می‌نویسد و هر تاپیک به نشست ایزوله نگاشت می‌شود. با ignore_root_dm: true ریشهٔ DM به لابی تبدیل می‌شود.

حالت چندنشستی DM با /topic

یک DM چندنشستیِ سبک ChatGPT — یک بات، گفتگوهای موازی بی‌شمار. کاربر-محور است: بدون config، بدون نام تاپیک از-پیش-اعلام‌شده.

فرماثر
/topicدر ریشهٔ DM: فعال‌سازی + ساخت تاپیک System پین‌شده
/topic <id>در تاپیک: بازیابی نشست قبلی به تاپیک فعلی
/topic offدر ریشهٔ DM: غیرفعال‌سازی و پاک‌کردن پیوندها
/topicدر تاپیک: نمایش پیوند نشست فعلی

پس از فعال‌سازی ریشهٔ DM به لابی تبدیل می‌شود و کاربران با دکمهٔ + تلگرام تاپیک دلخواه می‌سازند — هرکدام نشست مستقل هرمس. نام تاپیک خودکار با عنوان نشست هم‌نام می‌شود. با disable_topic_auto_rename: true این را خاموش کنید. /new داخل تاپیک فقط همان تاپیک را ریست می‌کند. حذف با /topic off یا sqlite3 مستقیم.

۱۲ پیوند مهارت به تاپیک گروهی

سوپرگروه‌های دارای حالت Topics از قبل به‌ازای-تاپیک ایزوله‌اند؛ با group_topics می‌توانید بارگذاری خودکار مهارت هم بدهید:

yaml
platforms:
  telegram:
    extra:
      group_topics:
      - chat_id: -1001234567890       # شناسهٔ سوپرگروه
        topics:
        - name: Engineering
          thread_id: 5
          skill: software-development
        - name: Research
          thread_id: 12
          skill: arxiv

thread_id را از URL تاپیک در تلگرام وب/دسکتاپ بردارید: t.me/c/1234567890/5 — آخرین عدد. chat_id سوپرگروه با پیشوند -100.

۱۳ استریم، پیام‌های ریچ و پیش‌نمایش لینک

ترنسپورت استریم

‏Bot API 9.5 استریم بومی با sendMessageDraft آورد. هرمس یکی از ۴ ترنسپورت را برمی‌گزیند:

مقداررفتار
auto ‏(پیش‌فرض)پیش‌نویس بومی روی چت‌های پشتیبان‌شده (فعلاً DM تلگرام)؛ ویرایشی برای بقیه
draftاجبار پیش‌نویس بومی؛ با پشتیبان‌نشدن با هشدار به ویرایشی سقوط می‌کند
editمسیر ویرایشیِ پیشین برای همه
offبدون استریم

در DM: edit یک پیام می‌فرستد و پیشرونده ویرایشش می‌کند؛ ‏auto/draft پیش‌نمایش پیش‌نویس متحرک نشان می‌دهد و پاسخ نهایی به‌صورت پیام معمولی می‌رسد. گروه‌ها همیشه ویرایشی‌اند (محدودیت تلگرام). خرابی فریم پیش‌نویس به ویرایشی برمی‌گردد.

پیام‌های ریچ (Bot API 10.1)

پاسخ‌های نهایی حاوی جدول/چک‌لیست/details/ریاضی با sendRichMessage تلگرام از **مارک‌داون خام** ارسال می‌شوند. پیش‌فرض خاموش — کلیدها: rich_messages: true و rich_drafts: false. با فعال‌بودن، هر رد تلگرام شفاف به MarkdownV2 برمی‌گردد و پیام گم نمی‌شود. جدول‌ها در MarkdownV2 نرمال می‌شوند: جدول‌های کوچک به فهرست‌های گلوله‌ای گروه‌ردیفی؛ بزرگ‌ترها به بلوک کد هم‌تراز.

پیش‌نمایش لینک

برای سرکوب خودکار پیش‌نمایش لینک تلگرام: disable_link_previews: true.

۱۴ فهرست مجاز گروه

دو گیت مستقل:

  • شناسه‌های کاربر فرستنده‏ (group_allow_from / TELEGRAM_GROUP_ALLOWED_USERS) — فقط برای گروه؛ به DM دسترسی نمی‌دهد.
  • شناسه‌های چت‏ (group_allowed_chats / TELEGRAM_GROUP_ALLOWED_CHATS) — هر عضو این گروه‌ها مجاز است.

با * هر فرستنده/چتی مجاز می‌شود. قبل از PR شمارهٔ ۱۷۶۸۶ کاربران شناسهٔ چت را در GROUP_ALLOWED_USERS می‌گذاشتند — شناسه‌های منفی هنوز محترم‌اند ولی هشدار منسوخ لاگ می‌شود.

حالت مهمان (guest_mode)

برای گروه‌های دوستانه که بات را عمدتاً ساکت ولی با پینگ صریح در دسترس می‌خواهید: guest_mode: true — پیام از گروهِ خارج از فهرست فقط با @منشن صریح پردازش می‌شود. هر نوبت منشن لازم است؛ چسبندگی نشست برای مهمان نیست.

۱۵ کنترل دسترسی فرمان‌های اسلش

پیش‌فرض همهٔ کاربران مجاز همهٔ فرمان‌ها را اجرا می‌کنند. برای تفکیک مدیر/کاربر: allow_admin_from و user_allowed_commands را اضافه کنید. غیرمدیرها فقط فرمان‌های فهرست‌شده + /help و /whoami را می‌توانند. بدون allow_admin_from تفکیک خاموش است. /whoami سطح شما را نشان می‌دهد.

yaml
gateway:
  platforms:
    telegram:
      extra:
        allow_from: ["123456789", "555555555"]  # همهٔ کاربران مجاز
        allow_admin_from: ["123456789"]          # مدیرها
        user_allowed_commands: [status, model, history]  # غیرمدیرها

۱۶ امکانات تکمیلی

انتخاب‌گر تعاملی مدل

/model بدون آرگومان: دکمه‌های ارائه‌دهنده ← فهرست مدل صفحه‌بندی‌شده با Prev/Next/Back/Cancel. همه در همان پیام ویرایش می‌شود. اگر نام مدل را می‌دانید مستقیم /model <name> بزنید.

IPهای جایگزین DNS-over-HTTPS

در شبکه‌های محدود، آداپتور تلگرام با کشف IPهای جایگزین از Google/Cloudflare DNS روی DoH تلاش می‌کند؛ IPv4های شناخته قبل از نام میزبان امتحان می‌شوند؛ اگر DoH هم بسته باشد از لیست IPv4 هاردکد استفاده می‌شود. TELEGRAM_FALLBACK_IPS برای تعیین صریح.

واکنش‌ها

بات می‌تواند 👀 (شروع پردازش)، ✅ (موفق) و ❌ (خطا) روی پیام بگذارد: reactions: true. برخلاف دیسکورد، تلگرام همهٔ واکنش‌های بات را در یک فراخوانی جایگزین می‌کند.

پرامپت به‌ازای-کانال

پرامپت سیستمی زودگذر به گروه/تاپیک اختصاصی: channel_prompts با کلید شناسهٔ چت یا تاپیک؛ تاپیک بر گروه مقدم است.

تأیید فرمان و شفاف‌سازی

فرمان خطرناک در چت تأیید می‌خواهد؛ clarify با دکمه‌های بومی رندر می‌شود؛ agent.clarify_timeout ‏(پیش‌فرض ۶۰۰ ثانیه).

اعلان پوش

حالت important ‏(پیش‌فرض) فقط پاسخ نهایی/تأیید/فرمان اسلش را زنگ می‌زند؛ ‏all همه را. با display.platforms.telegram.notifications یا HERMES_TELEGRAM_NOTIFICATIONS.

پیام وضعیت ویرایش-درجا و پین پیام کاربر

فراخوانی‌های وضعیت در همان حباب ویرایش می‌شوند؛ پیام کاربر حین نوبت پین و پس از پاسخ آنپین می‌شود — بدون پیکربندی.

⚠️ امنیت

همیشه TELEGRAM_ALLOWED_USERS را تنظیم کنید — بدون آن گیت‌وی همه را رد می‌کند. توکن بات را هرگز عمومی نکنید؛ اگر لو رفت با /revoke بلافاصله لغو کنید.
