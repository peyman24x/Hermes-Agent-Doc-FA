شنوندهٔ وب‌هوک Microsoft Graph

پلتفرم گیت‌وی ‏msgraph_webhook یک شنوندهٔ رویداد ورودی است. نحوهٔ دریافت اعلان‌های تغییر از Microsoft Graph توسط هرمس است — «یک جلسهٔ Teams تمام شد»، «پیام جدیدی در این چت نشست»، «این رویداد تقویم به‌روز شد». متفاوت از پلتفرم teams ‏(که بات چتی است که کاربران تایپ می‌کنند) — این یکی M365 است که به هرمس خبر می‌دهد اتفاقی افتاده، نه یک انسان.

الان مصرف‌کنندهٔ اصلی خط‌لولهٔ خلاصهٔ جلسات Teams است: Graph اطلاع می‌دهد وقتی جلسه‌ای رونویسی تولید کرده، خط‌لوله آن را می‌گیرد و هرمس خلاصه را به Teams برمی‌گرداند. سایر منابع Graph ‏(/chats/.../messages، ‏/users/.../events) از همین شنونده استفاده می‌کنند — مصرف‌کننده‌های خط‌لوله با PR های خودشان می‌آیند.

۱ پیش‌نیازها

  • اعتبارنامهٔ اپلیکیشن Microsoft Graph — ثبت اپلیکیشن Microsoft Graph
  • یک URL عمومی HTTPS قابل‌دسترس برای Microsoft Graph ‏(Graph نقاط پایانی خصوصی را صدا نمی‌زند). تونل توسعه برای تست کافی است؛ تولید دامنهٔ واقعی با گواهی معتبر می‌خواهد.
  • رمز مشترک قوی به‌عنوان مقدار ‏clientState. با ‏openssl rand -hex 32 تولید و در ‏~/.hermes/.env به‌صورت ‏MSGRAPH_WEBHOOK_CLIENT_STATE بگذارید.

۲ شروع سریع

حداقل config.yaml:

yaml
platforms:
  msgraph_webhook:
    enabled: true
    extra:
      host: 127.0.0.1
      port: 8646
      client_state: "replace-with-a-strong-secret"
      accepted_resources:
        - "communications/onlineMeetings"

یا با env در ‏~/.hermes/.env ‏(هنگام شروع auto-merge):

bash
MSGRAPH_WEBHOOK_ENABLED=true
MSGRAPH_WEBHOOK_PORT=8646
MSGRAPH_WEBHOOK_CLIENT_STATE=<تولید-با-openssl-rand-hex-32>
MSGRAPH_WEBHOOK_ACCEPTED_RESOURCES=communications/onlineMeetings

یادداشت: میزبان bind از ‏extra.host در config.yaml خوانده می‌شود ‏(مثال بالا)؛ override محیطیِ ‏MSGRAPH_WEBHOOK_HOST وجود ندارد.

گیت‌وی را شروع کنید: ‏hermes gateway run. شنونده این‌ها را expose می‌کند:

  • ‏POST /msgraph/webhook — اعلان‌های تغییر از Graph
  • ‏GET /msgraph/webhook?validationToken=... — دست‌دادن اعتبارسنجی اشتراک Graph
  • ‏GET /health — probe آماده‌باشی با شمارنده‌های پذیرفته/تکراری

شنونده را عمومی expose کنید ‏(پروکسی معکوس، تونل توسعه، ingress). URL اعلان شما برای اشتراک‌های Graph، مبدأ HTTPS عمومی‌تان + مسیر ‏/msgraph/webhook است:

https://ops.example.com/msgraph/webhook

۳ پیکربندی

همهٔ تنظیمات زیر ‏platforms.msgraph_webhook.extra می‌روند:

تنظیمپیش‌فرضتوضیح
hostتنظیم‌نشده ‏(dual-stack: همهٔ interface ها، IPv4+IPv6)آدرس bind شنوندهٔ HTTP. bind غیر-loopback نیازمند ‏allowed_source_cidrs؛ ‏loopback ‏(127.0.0.1/::1) ساده‌ترین setup برای تونل توسعه/پروکسی معکوس است.
port8646پورت bind.
webhook_path/msgraph/webhookمسیر URL که Graph بهش POST می‌کند.
health_path/healthنقطهٔ پایانی آماده‌باشی.
client_state—رمز مشترکی که Graph در هر اعلان بازتاب می‌دهد. با ‏hmac.compare_digest مقایسه می‌شود — با ‏openssl rand -hex 32 بسازید.
accepted_resources[] ‏(همه پذیرفته)لیست مجاز مسیرها/الگوهای منبع Graph. ستارهٔ انتهایی تطبیق پیشوندی است. اسلش ابتدایی هم تحمل می‌شود. مثال: ‏["communications/onlineMeetings", "chats/*/messages"].
max_seen_receipts5000حجم کش حذف‌تکرار برای شناسه‌های اعلان. قدیمی‌ترین‌ها با رسیدن به سقف تخلیه می‌شوند.
allowed_source_cidrs[]برای bind غیر-loopback الزامی. فقط وقتی شنونده روی loopback است و جلویش تونل/پروکسی معکوس محلی دارید خالی بگذارید.

بیشتر تنظیمات معادل env ‏(MSGRAPH_WEBHOOK_*) دارند که هنگام شروع گیت‌وی به config ادغام می‌شود ‏(استثنا host که فقط-config است — یادداشت بالا) — مرجع متغیرهای محیطی را ببینید.

۴ مقاوم‌سازی امنیتی

‏clientState چک اصلی احراز است

هر اعلان Graph رشتهٔ ‏clientStateای را شامل می‌شود که اشتراکتان ثبت کرده بود. شنونده هر اعلانی که ‏clientStateاش نخواند با مقایسهٔ timing-safe رد می‌کند. این مکانیزم مستند خود مایکروسافت است — مقدار را رمز مشترک قوی تلقی کنید.

اگر ‏client_state تنظیم نباشد شنونده از شروع امتناع می‌کند.

لیست مجاز IP مبدأ ‏(استقرارهای تولید)

برای تولید، شنونده را به بازه‌های IP مبدأ منتشرشدهٔ وب‌هوک Graph مایکروسافت محدود کنید. مایکروسافت بازه‌های egress را در سرویس وب IP و URL آفیس ۳۶۵ مستند کرده. پیکربندی:

yaml
platforms:
  msgraph_webhook:
    enabled: true
    extra:
      host: 0.0.0.0
      client_state: "..."
      allowed_source_cidrs:
        - "52.96.0.0/14"
        - "52.104.0.0/14"
        # ...بازه‌های egress فعلی دستهٔ "Common" + "Teams" مایکروسافت ۳۶۵ را اضافه کنید

یا به‌عنوان env:

bash
MSGRAPH_WEBHOOK_ALLOWED_SOURCE_CIDRS="52.96.0.0/14,52.104.0.0/14"

bind کردن میزبانی غیر-loopback مثل ‏0.0.0.0، ‏:: یا IP شبکهٔ محلی بدون ‏allowed_source_cidrs هنگام شروع رد می‌شود. اگر تونل توسعه یا پروکسی معکوس روی همان ماشین دارید، هرمس را روی ‏127.0.0.1 یا ‏::1 بایند و لیست را همانجا خالی بگذارید. رشته‌های CIDR نامعتبر هشدار لاگ می‌خورند و نادیده گرفته می‌شوند. فهرست IP مایکروسافت را هر سه‌ماهه بازبینی کنید — عوض می‌شود.

خاتمهٔ TLS

شنونده HTTP خام صحبت می‌کند. TLS را در پروکسی معکوس‌تان ‏(Caddy، ‏Nginx، ‏Cloudflare Tunnel، ‏AWS ALB) خاتمه دهید و روی شبکهٔ محلی به شنونده پروکسی کنید. Graph تحویل به endpoint های غیر-HTTPS را رد می‌کند، پس هیچ مسیری برای رسیدن ترافیک رمزنشده از طرف خود Graph وجود ندارد.

بهداشت پاسخ

در موفقیت شنونده ‏202 Accepted با بدنهٔ خالی برمی‌گرداند — شمارنده‌های داخلی خارج از پاسخ سیمی می‌مانند. اپراتورها شمارنده‌ها را از ‏/health مشاهده می‌کنند که با همان قواعد IP مبدأِ مسیر webhook محافظت می‌شود.

جدول کدهای وضعیت:

پیامدوضعیت
اعلان(ها) پذیرفته یا حذف‌تکرار شدند202
دست‌دادن اعتبارسنجی ‏(GET با validationToken)200 ‏(توکن بازتاب می‌شود)
همهٔ اقلام batch در clientState شکست خوردند403
JSON خراب / آرایهٔ value غایب / منبع ناشناخته400
IP مبدأ در لیست مجاز نیست403
GET لخت بدون validationToken400

۵ عیب‌یابی

مشکلچه چیزی را چک کنیم
اعتبارسنجی اشتراک Graph شکست می‌خوردURL عمومی قابل‌دسترس است؟ مسیر ‏/msgraph/webhook مطابق است؟ GET با ‏validationToken تا ۱۰ ثانیه توکن را عیناً به‌صورت ‏text/plain بازتاب می‌دهد؟
POST انجام می‌شود ولی چیزی ingest نمی‌شود‏client_state با مقدار ثبت‌شدهٔ اشتراک بخواند. اگر مقدار جابه‌جا شده ‏openssl rand -hex 32 را دوباره اجرا و اشتراک جدید بسازید. چک کنید ‏accepted_resources شامل مسیر منبعی باشد که Graph می‌فرستد.
همهٔ اعلان‌ها 403 می‌گیرندعدم‌تطبیق clientState ‏(جعلی، یا اشتراک با مقدار دیگری ثبت شده). اشتراک را با ‏hermes teams-pipeline subscribe --client-state "$MSGRAPH_WEBHOOK_CLIENT_STATE" ... دوباره بسازید.
شنونده روی ‏0.0.0.0 از شروع امتناع می‌کند‏allowed_source_cidrs را روی بازه‌های egress فعلی وب‌هوک مایکروسافت بگذارید، یا هرمس را روی ‏127.0.0.1/::1 پشت تونل/پروکسی بایند کنید.
شنونده شروع می‌شود ولی ‏curl http://localhost:8646/health معلق می‌ماندتعارض bind پورت. ‏ss -tlnp | grep 8646 را چک و در صورت نیاز ‏port: را عوض کنید.
درخواست‌های واقعی Graph مایکروسافت 403 می‌گیرندلیست مجاز IP مبدأ خیلی تنگ است. فهرست را به بازه‌های egress فعلی مایکروسافت پهن کنید. اگر هنوز مسیر تونل را اعتبارسنجی می‌کنید، هرمس را روی loopback بایند و expose شدن را به تونل بسپارید.
