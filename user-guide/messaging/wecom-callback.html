‏WeCom Callback ‏(اپ ساخته‌شدهٔ خودی)

هرمس را به‌عنوان یک اپلیکیشن سازمانیِ ساخته‌شدهٔ خودی با مدل callback/webhook به WeCom ‏(وی‌چت سازمانی) وصل کنید.

📌 WeCom Bot در برابر WeCom Callback

هرمس دو حالت یکپارچه‌سازی WeCom دارد:

  • ‏WeCom Bot — سبک بات، اتصال از طریق WebSocket. راه‌اندازی ساده‌تر، کار در چت گروهی.
  • ‏WeCom Callback ‏(این صفحه) — اپ ساخته‌شدهٔ خودی، دریافت XML رمزنگاری‌شده. در نوار کناری WeCom کاربران به‌عنوان اپ درجه‌یک دیده می‌شود. مسیریابی چند-کورپوری پشتیبانی می‌کند.

hermes gateway setup را اجرا و WeCom Callback را انتخاب کنید تا راهنمای گام‌به‌گام ببینید.

۱ نحوهٔ کار

  1. در کنسول مدیریت WeCom یک اپلیکیشن ساخته‌شدهٔ خودی ثبت می‌کنید
  2. ‏WeCom XML رمزنگاری‌شده را به endpoint callback شما push می‌کند
  3. هرمس پیام را decrypt و برای ایجنت صف می‌کند
  4. بلافاصله ACK می‌دهد ‏(بی‌صدا — هیچ چیزی به کاربر نمایش داده نمی‌شود)
  5. ایجنت درخواست را پردازش می‌کند ‏(معمولاً ۳ تا ۳۰ دقیقه)
  6. ریپلای به‌صورت پیش‌فعال از طریق API ‏message/send ویکام تحویل می‌شود

۲ پیش‌نیازها

  • حساب سازمانی WeCom با دسترسی ادمین
  • بسته‌های پایتونی ‏aiohttp و httpx ‏(در نصب پیش‌فرض هستند)
  • سروری عمومی‌دسترس برای URL کال‌بک ‏(یا تونلی مثل ngrok)

۳ راه‌اندازی

۱. ساخت اپ خودساخته در WeCom

  1. به کنسول مدیریت WeCom ← Applications ← Create App بروید
  2. ‏Corp ID را یادداشت کنید ‏(بالای کنسول ادمین نشان داده می‌شود)
  3. در تنظیمات اپ، یک Corp Secret بسازید
  4. ‏Agent ID را از صفحهٔ نمای کلی اپ یادداشت کنید
  5. تحت Receive Messages، URL کال‌بک را پیکربندی کنید:
    • URL: ‏http://YOUR_PUBLIC_IP:8645/wecom/callback
    • Token: توکن تصادفی بسازید ‏(WeComp فراهم می‌کند)
    • EncodingAESKey: کلیدی تولید کنید ‏(WeComp فراهم می‌کند)

۲. پیکربندی متغیرهای محیطی

به فایل .env اضافه کنید:

bash
WECOM_CALLBACK_CORP_ID=your-corp-id
WECOM_CALLBACK_CORP_SECRET=your-corp-secret
WECOM_CALLBACK_AGENT_ID=1000002
WECOM_CALLBACK_TOKEN=your-callback-token
WECOM_CALLBACK_ENCODING_AES_KEY=your-43-char-aes-key

# اختیاری
# WECOM_CALLBACK_HOST=  # pin اختیاری؛ خالی = dual-stack (همهٔ interface ها، IPv4+IPv6)
WECOM_CALLBACK_PORT=8645
WECOM_CALLBACK_ALLOWED_USERS=user1,user2

۳. شروع گیت‌وی

hermes gateway

‏(از ‏hermes gateway start فقط بعد از ثبت سرویس systemd/launchd توسط ‏hermes gateway install استفاده کنید.)

آداپتور کال‌بک سرور HTTP روی پورت پیکربندی‌شده اجرا می‌کند. ویکام URL کال‌بک را با یک GET تأیید و بعد ارسال پیام‌ها با POST را شروع می‌کند.

۴ مرجع پیکربندی

این‌ها را در config.yaml زیر ‏platforms.wecom_callback.extra بگذارید یا از متغیرهای محیطی استفاده کنید:

تنظیمپیش‌فرضتوضیح
corp_id—Corp ID سازمانی ویکام ‏(الزامی)
corp_secret—رمز Corp برای اپ خودساخته ‏(الزامی)
agent_id—Agent ID اپ خودساخته ‏(الزامی)
token—توکن تأیید کال‌بک ‏(الزامی)
encoding_aes_key—کلید AES چهل‌وسه‌کاراکتری برای رمزنگاری کال‌بک ‏(الزامی)
hostتنظیم‌نشده ‏(dual-stack: همهٔ interface ها، IPv4+IPv6)آدرس bind سرور HTTP کال‌بک
port8645پورت سرور HTTP کال‌بک
path/wecom/callbackمسیر URL نقطهٔ پایانی کال‌بک

۵ مسیریابی چند-اپی

برای سازمان‌هایی که چند اپ خودساخته دارند ‏(مثلاً بین دپارتمان‌ها یا زیرمجموعه‌های مختلف)، فهرست apps را در config.yaml پیکربندی کنید:

yaml
platforms:
  wecom_callback:
    enabled: true
    extra:
      host: "0.0.0.0"
      port: 8645
      apps:
        - name: "dept-a"
          corp_id: "ww_corp_a"
          corp_secret: "secret-a"
          agent_id: "1000002"
          token: "token-a"
          encoding_aes_key: "key-a-43-chars..."
        - name: "dept-b"
          corp_id: "ww_corp_b"
          corp_secret: "secret-b"
          agent_id: "1000003"
          token: "token-b"
          encoding_aes_key: "key-b-43-chars..."

کاربران با ‏corp_id:user_id scope می‌شوند تا تداخل بین‌-کورپوری پیشگیری شود. وقتی کاربری پیام می‌فرستد، آداپتور ثبت می‌کند متعلق به کدام اپ ‏(کورپ) است و ریپلای‌ها را از طریق توکن دسترسی همان اپ مسیریابی می‌کند.

۶ کنترل دسترسی

bash
# لیست مجاز کاربران خاص
WECOM_CALLBACK_ALLOWED_USERS=zhangsan,lisi,wangwu

# یا اجازه به همهٔ کاربران
WECOM_CALLBACK_ALLOW_ALL_USERS=true

۷ نقاط پایانی

آداپتور این‌ها را expose می‌کند:

متدمسیرهدف
GET/wecom/callbackدست‌دادن تأیید URL ‏(ویکام هنگام setup این را می‌فرستد)
POST/wecom/callbackکال‌بک پیام رمزنگاری‌شده ‏(ویکام پیام‌های کاربران را اینجا می‌فرستد)
GET/healthچک سلامت — ‏{"status": "ok"} برمی‌گرداند

۸ رمزنگاری

همهٔ payload های کال‌بک با AES-CBC با EncodingAESKey رمزنگاری می‌شوند. آداپتور هندل می‌کند:

  • ورودی: Decrypt کردن payload XML، تأیید امضای SHA1
  • خروجی: ریپلای‌ها از طریق API پیش‌فعال ارسال می‌شوند ‏(نه پاسخ رمزنگاری‌شدهٔ کال‌بک)

پیاده‌سازی رمزنگاری با SDK رسمی WXBizMsgCrypt تنسنت سازگار است.

۹ محدودیت‌ها

  • بدون استریم — ریپلای‌ها بعد از اتمام کار ایجنت به‌صورت پیام کامل می‌رسند
  • بدون نشانگر تایپ — مدل کال‌بک وضعیت تایپ را پشتیبانی نمی‌کند
  • فقط متن — الان ورودی متن پشتیبانی می‌شود؛ ورودی تصویر/فایل/صوت هنوز پیاده نشده. ایجنت قابلیت رسانهٔ خروجی را از سرنخ پلتفرم ویکام می‌شناسد ‏(تصویر، سند، ویدیو، صوت).
  • تأخیر پاسخ — نشست‌های ایجنت ۳ تا ۳۰ دقیقه طول می‌کشند؛ کاربر ریپلای را وقتی پردازش تمام شد می‌بیند

۱۰ عیب‌یابی

اعتبارسنجی امضا شکست می‌خورد.
‏WeComp هر درخواستی را با Tokenی که در کنسول ادمین ثبت کرده‌اید امضا می‌کند. عدم‌تطبیق بین توکن پیکربندی‌شده در هرمس و توکن موردانتظار کنسول ادمین رایج‌ترین علت است. هر دو Token و EncodingAESKey را دوباره از کنسول کپی کنید — به‌راحتی بریده می‌شوند. فاصلهٔ سفید دور = در مقادیر ‏~/.hermes/.env هم چک‌های امضا را می‌شکند. بعد از اصلاح، ‏hermes gateway run را ری‌استارت کنید.

URL کال‌بک قابل‌دسترس نیست / مرحلهٔ تأیید شکست می‌خورد.
‏WeComp به URL عمومی ثبت‌شده شما ضربه می‌زند. تأیید کنید:
۱. پروکسی معکوس / تونل شما ‏/wecom/callback را به پورت گیت‌وی فوروارد می‌کند.
۲. URL در کنسول ادمین HTTPS است ‏(ویکام HTTP خام را رد می‌کند).
۳. از بیرون شبکه‌تان، ‏curl -i https://<your-domain>/wecom/callback چیزی غیر از timeout برگرداند ‏(۴xx بدون query params کافی است — فقط یعنی شنونده قابل‌رسید است).

پورت قابل‌دسترس نیست / شنونده bind نشده.
لاگ‌های ‏hermes gateway run را برای host/port بایندشده چک کنید. اگر آداپتور روی ‏127.0.0.1 بایند شده باید جلویش پروکسی معکوس یا تونل بگذارید — سرورهای ویکام نمی‌توانند به loopback برسند. ‏extra.host را خالی بگذارید تا bind پیش‌فرض dual-stack ‏(همهٔ interface ها، IPv4+IPv6) اعمال شود، یا یک interface را در config.yaml pin کنید ‏(+ ‏allowed_source_cidrs اگر مستقیم expose می‌کنید)، یا loopback نگه دارید و از تونلی مثل Cloudflare Tunnel / nginx استفاده کنید.
