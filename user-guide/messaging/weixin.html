‏Weixin ‏(WeChat)

هرمس را به ‏WeChat ‏(微信)، پلتفرم پیام‌رسانی شخصی تنسنت، وصل کنید. آداپتور از ‏‏iLink Bot API تنسنت برای حساب‌های شخصی WeChat استفاده می‌کند — این جدا از WeCom ‏(وی‌چت سازمانی) است. پیام‌ها با long-polling تحویل می‌شوند، پس endpoint عمومی یا وب‌هوک لازم نیست.

📌 نکته

این آداپتور برای حساب‌های شخصی WeChat است. اگر وی‌چت سازمانی می‌خواهید، به‌جایش آداپتور WeCom را ببینید.

⚠️ هویت بات iLink — گروه‌های عادی ویکام ممکن است کار نکنند

ورود QR هرمس را به یک هویت بات iLink ‏(مثل ‏a5ace6fd482e@im.bot) وصل می‌کند، نه یک حساب شخصی عادیِ کاملاً قابل‌اسکریپت. پیامدها:

  • هویت بات iLink معمولاً نمی‌تواند مثل یک مخاطب عادی به گروه‌های عادی ویکام دعوت شود.
  • ‏iLink معمولاً رویدادهای گروه عادی ویکام را ‏(شامل @منشن‌های حساب شخصیِ اسکن‌کنندهٔ QR) برای بیشتر حساب‌های نوع-بات به گیت‌وی تحویل نمی‌دهد.
  • @منشن‌کردن حساب شخصی ویکامی که QR را اسکن کرده همان @منشن‌کردن بات iLink نیست — بات یک هویت جداگانه است.
  • تنظیمات ‏WEIXIN_GROUP_POLICY/WEIXIN_GROUP_ALLOWED_USERS پایین فقط وقتی اثر دارند که iLink واقعاً رویدادهای گروهی را برای نوع حسابتان برگرداند. اگر ندهد، مستقل از سیاست، پیام‌های گروهی هرگز به هرمس نمی‌رسند.

در عمل بیشتر استقرارها فقط DM به بات iLink را مطمئن کار می‌کنند. اگر بعد از پیکربندی تحویل گروهی کار نکرد، محدودیت سمت iLink است نه هرمس. گیت‌وی هر وقت ‏WEIXIN_GROUP_POLICY چیزی غیر از ‏disabled باشد در شروع یک ‏WARNING لاگ می‌کند.

۱ پیش‌نیازها

  • یک حساب شخصی WeChat
  • بسته‌های پایتونی: ‏aiohttp و ‏cryptography
  • رندر QR ترمینال با نصب هرمس همراه extra ‏messaging موجود است

وابستگی‌های لازم را نصب کنید:

bash
pip install aiohttp cryptography
# اختیاری: برای نمایش کد QR در ترمینال
cd ~/.hermes/hermes-agent && uv pip install -e ".[messaging]"

۲ راه‌اندازی

۱. اجرای ویزارد راه‌اندازی

ساده‌ترین راه اتصال حسابتان، راه‌اندازی تعاملی است:

hermes gateway setup

هنگام پرسش Weixin را انتخاب کنید. ویزارد:

  1. کد QR را از iLink Bot API درخواست می‌کند
  2. کد QR را در ترمینال نمایش می‌دهد ‏(یا URL می‌دهد)
  3. منتظر اسکن QR با اپ موبایل ویکام می‌ماند
  4. تأیید ورود روی گوشی از شما می‌خواهد
  5. اعتبارنامه‌های حساب را خودکار در ‏~/.hermes/weixin/accounts/ ذخیره می‌کند

بعد از تأیید چیزی شبیه این می‌بینید:

微信连接成功，account_id=your-account-id

ویزارد ‏account_id، ‏token و ‏base_url را ذخیره می‌کند تا لازم نباشد دستی پیکربندی کنید.

۲. پیکربندی متغیرهای محیطی

بعد از ورود اولیهٔ QR، دست‌کم شناسهٔ حساب را در ‏~/.hermes/.env تنظیم کنید:

bash
WEIXIN_ACCOUNT_ID=your-account-id

# اختیاری: override توکن (معمولاً خودکار از ورود QR ذخیره می‌شود)
# WEIXIN_TOKEN=your-bot-token

# اختیاری: محدودکردن دسترسی
WEIXIN_DM_POLICY=open
WEIXIN_ALLOWED_USERS=user_id_1,user_id_2

# اختیاری: بازگرداندن رفتار قدیمی تقسیم چندخطی
# WEIXIN_SPLIT_MULTILINE_MESSAGES=true

# اختیاری: کانال خانگی برای کرون/اعلان‌ها
WEIXIN_HOME_CHANNEL=chat_id
WEIXIN_HOME_CHANNEL_NAME=Home

۳. شروع گیت‌وی

hermes gateway

آداپتور اعتبارنامه‌های ذخیره‌شده را بازیابی، به API آیلینک وصل و long-polling پیام‌ها را شروع می‌کند.

۳ قابلیت‌ها

  • ترنسپورت long-poll — بدون endpoint عمومی، وب‌هوک یا WebSocket
  • ورود با کد QR — setup اسکن‌و-وصل با ‏hermes gateway setup
  • پیام‌رسانی DM — سیاست‌های دسترسی قابل‌پیکربندی؛ پیام گروهی به تحویل واقعی رویدادهای گروهی توسط iLink برای هویت متصل وابسته است ‏(اغلب برای حساب‌های بات iLink چنین نیست — هشدار بالای صفحه)
  • پشتیبانی رسانه — تصویر، ویدیو، فایل و پیام صوتی
  • ‏CDN رمزنگاری AES-128-ECB — رمزنگاری/رمزگشایی خودکار همهٔ انتقالات رسانه
  • ماندگاری توکن زمینه — تداوم ریپلای دیسک-محور بین ری‌استارت‌ها
  • قالب‌بندی مارک‌داون — مارک‌داون حفظ می‌شود شامل تیترها، جدول‌ها و بلوک‌های کد تا کلاینت‌های ویکامِ پشتیبان مارک‌داون بومی رندر کنند
  • تکه‌تکه‌کردن هوشمند پیام — پیام‌ها زیر سقف یک حباب واحد می‌مانند؛ فقط payload های بزرگ در مرزهای منطقی تقسیم می‌شوند
  • نشانگر تایپ — حین پردازش ایجنت وضعیت «typing…» در کلاینت ویکام نشان داده می‌شود
  • محافظ SSRF — URL های رسانهٔ خروجی قبل از دانلود اعتبارسنجی می‌شوند
  • حذف تکرار پیام — پنجرهٔ لغزان ۵ دقیقه‌ای مانع پردازش دوباره می‌شود
  • retry خودکار با backoff — بازیابی از خطاهای گذرای API

این‌ها را در config.yaml زیر ‏platforms.weixin.extra تنظیم کنید:

۵ سیاست‌های دسترسی

سیاست DM

کنترل می‌کند چه کسی می‌تواند به بات DM بدهد:

مقداررفتار
openهر کسی می‌تواند DM بدهد ‏(پیش‌فرض)
allowlistفقط شناسه‌های داخل ‏allow_from حق DM دارند
disabledهمهٔ DM ها نادیده گرفته می‌شوند
pairingحالت جفت‌سازی ‏(راه‌اندازی اولیه)
 
WEIXIN_DM_POLICY=allowlist
WEIXIN_ALLOWED_USERS=user_id_1,user_id_2

‏WEIXIN_ALLOWED_USERS یک فیلتر ورودی است نه سیستم دعوت. ورود QR یک هویت بات iLink را به هرمس وصل می‌کند. افراد دیگر QR هرمس را با حسابتان اسکن نمی‌کنند؛ باید از طریق ویکام به بات/مخاطبِ iLink متصل پیام بدهند و هرمس فقط وقتی فرستنده را پردازش می‌کند که شناسهٔ کاربری Weixin او در ‏WEIXIN_ALLOWED_USERS باشد.

جریان عملی راه‌اندازی:

  1. هرمس را یک‌بار با ‏hermes gateway setup جفت کنید و حساب بات iLink متصل را یادداشت کنید.
  2. هر کاربر مجاز یک پیام خصوصی به آن بات/مخاطب بدهد.
  3. شناسهٔ فرستنده/کاربر را از لاگ‌های گیت‌وی یا payload رویداد ورودی بخوانید.
  4. آن شناسه‌ها را به ‏WEIXIN_ALLOWED_USERS بیفزایید و گیت‌وی را ری‌استارت کنید.

اگر فقط حسابِ اسکن‌کنندهٔ QR می‌تواند با هرمس حرف بزند، تأیید کنید سایر کاربران به خود هویت بات iLink پیام می‌دهند نه به حساب شخصی ویکامی که ورود QR را انجام داده. بات iLink هویت جداگانه‌ای است و مسیریابی مخاطب/گروه عادی ویکام ممکن است توسط رفتار iLink تنسنت محدود شود.

سیاست گروهی

کنترل می‌کند بات در چه گروه‌هایی پاسخ دهد وقتی iLink برای هویت متصل رویدادهای گروهی تحویل دهد. برای هویت‌های بات iLink حاصل ورود QR ‏(مثل ‏...@im.bot) معمولاً اصلاً رویداد گروهی تحویل نمی‌شود، پس ممکن است این سیاست هیچ اثری نداشته باشد — هشدار محدودیت iLink بالای صفحه را ببینید.

مقداررفتار
openبات در همهٔ گروه‌ها پاسخ می‌دهد ‏(اگر رویدادها تحویل شوند)
allowlistبات فقط در شناسه‌های گروهِ ‏group_allow_from پاسخ می‌دهد ‏(اگر رویدادها تحویل شوند)
disabledهمهٔ پیام‌های گروه نادیده گرفته می‌شوند ‏(پیش‌فرض)
 
WEIXIN_GROUP_POLICY=allowlist
# توجه: این فهرست جداشده با ویرگول از «شناسه‌های چت گروهی» است، نه شناسه‌های کاربر عضو،
# با اینکه نام متغیر USERS دارد. هنگام پیکربندی این را در نظر داشته باشید.
WEIXIN_GROUP_ALLOWED_USERS=group_id_1,group_id_2
📌 یادداشت

سیاست گروهی پیش‌فرض برای ویکسین ‏disabled است ‏(برخلاف ویکام که پیش‌فرضش ‏open است). عمدی است — حساب‌های شخصی WeChat ممکن است در گروه‌های زیادی باشند و هویت‌های بات iLink معمولاً اصلاً نمی‌توانند پیام‌های گروه عادی ویکام بگیرند. اگر ‏WEIXIN_GROUP_POLICY را غیر از ‏disabled بگذارید گیت‌وی هنگام شروع WARNING لاگ می‌کند.

۶ پشتیبانی رسانه

ورودی ‏(دریافت)

آداپتور پیوست‌های رسانه‌ای کاربران را دریافت، از CDN ویکام دانلود، decrypt و برای پردازش ایجنت محلی کش می‌کند:

نوعنحوهٔ هندل
تصاویردانلود، decrypt با AES و کش به‌صورت JPEG.
ویدیودانلود، decrypt و کش به‌صورت MP4.
فایل‌هادانلود، decrypt و کش. نام فایل اصلی حفظ می‌شود.
صوتاگر رونویسی متنی موجود باشد به‌عنوان متن استخراج می‌شود. وگرنه صدا ‏(فرمت SILK) دانلود و کش می‌شود.

پیام‌های نقل‌قولی: رسانهٔ پیام‌های نقل‌قول‌شده هم استخراج می‌شود تا ایجنت زمینهٔ داشته باشد کاربر به چه جواب داده.

‏CDN رمزنگاری‌شدهٔ AES-128-ECB

فایل‌های رسانه‌ای ویکام از طریق CDN رمزنگاری‌شده منتقل می‌شوند. آداپتور شفاف هندل می‌کند:

  • ورودی: رسانهٔ رمزشده با URLهای ‏encrypted_query_param از CDN دانلود و با AES-128-ECB با کلید به‌ازای-فایل داخل payload پیام decrypt می‌شود.
  • خروجی: فایل‌ها محلی با کلید تصادفی AES-128-ECB رمز، روی CDN آپلود و مرجع رمزشده در پیام خروجی گنجانده می‌شود.
  • کلید AES ۱۶ بایت ‏(۱۲۸ بیت) است. کلیدها ممکن است base64 خام یا hex برسند — آداپتور هر دو فرمت را هندل می‌کند.
  • نیازمند بستهٔ پایتونی ‏cryptography است.

پیکربندی لازم نیست — رمزنگاری و رمزگشایی خودکار انجام می‌شود.

خروجی ‏(ارسال)

متدچه چیزی می‌فرستد
sendپیام‌های متنی با قالب‌بندی مارک‌داون
send_image / ‏send_image_fileپیام‌های تصویری بومی ‏(با آپلود CDN)
send_documentپیوست‌های فایل ‏(با آپلود CDN)
send_videoپیام‌های ویدیویی ‏(با آپلود CDN)

همهٔ رسانه‌های خروجی از جریان آپلود CDN رمزنگاری‌شده می‌روند:

  1. تولید کلید تصادفی AES-128
  2. رمزنگاری فایل با AES-128-ECB + ‏padding ‏PKCS#7
  3. درخواست URL آپلود از API آیلینک ‏(getuploadurl)
  4. آپلود ciphertext روی CDN
  5. ارسال پیام با مرجع رسانهٔ رمزشده

۷ ماندگاری توکن زمینه

‏API بات iLink نیازمند است یک ‏context_token با هر پیام خروجی برای هر همتا بازتاب داده شود. آداپتور یک مخزن توکن زمینهٔ دیسک-محور نگه می‌دارد:

  • توکن‌ها به‌ازای حساب+همتا در ‏~/.hermes/weixin/accounts/<account_id>.context-tokens.json ذخیره می‌شوند
  • هنگام شروع توکن‌های ذخیره‌شده قبلی بازیابی می‌شوند
  • هر پیام ورودی توکن ذخیره‌شدهٔ آن فرستنده را به‌روز می‌کند
  • پیام‌های خروجی خودکار آخرین توکن زمینه را شامل می‌شوند

این تداوم ریپلای را حتی بعد از ری‌استارت گیت‌وی تضمین می‌کند.

۸ قالب‌بندی مارک‌داون

کلاینت‌های ویکام متصل از طریق iLink Bot API مارک‌داون را مستقیم رندر می‌کنند، پس آداپتور مارک‌داون را حفظ می‌کند نه بازنویسی:

  • تیترها به‌صورت heading مارک‌داون می‌مانند ‏(#، ‏## و...)
  • جدول‌ها به‌صورت جدول مارک‌داون می‌مانند
  • بلوک‌های کد به‌صورت code fence محصور می‌مانند
  • خط‌های خالی مفرط بیرون بلوک‌های کد به دو خط‌جدید فشرده می‌شوند

۹ تکه‌تکه‌کردن پیام

پیام‌ها هرجا در سقف پلتفرم جا شوند به‌صورت یک پیام چت واحد تحویل می‌گیرند. فقط payload های بزرگ‌تر برای ارسال تقسیم می‌شوند:

  • حداکثر طول پیام: ۴۰۰۰ کاراکتر
  • پیام‌های زیر سقف حتی با چند پاراگراف یا خط‌جدید دست‌نخورده می‌مانند
  • پیام‌های بزرگ در مرزهای منطقی تقسیم می‌شوند ‏(پاراگراف‌ها، خطوط خالی، code fence ها)
  • بلوک‌های کد هرجا ممکن دست‌نخورده نگه داشته می‌شوند ‏(هرگز وسط بلوک تقسیم نمی‌شوند مگر خود fence از سقف بگذرد)
  • بلوک‌های فردِ بزرگ به منطق برشِ آداپتور پایه برمی‌گردند
  • تأخیر ۰٫۳ ثانیه‌ای بین تکه‌ها مانع drop شدن به‌خاطر rate-limit ویکام هنگام ارسال چندتکه می‌شود

۱۰ نشانگر تایپ

آداپتور وضعیت تایپ را در کلاینت ویکام نشان می‌دهد:

  1. وقتی پیامی می‌رسد آداپتور ‏typing_ticket را از طریق API ‏getconfig می‌گیرد
  2. تیکت‌های تایپ ۱۰ دقیقه به‌ازای هر کاربر کش می‌شوند
  3. ‏send_typing سیگنال شروع تایپ و ‏stop_typing سیگنال توقف می‌فرستد
  4. گیت‌وی حین پردازش پیام توسط ایجنت خودکار نشانگر تایپ را تریگر می‌کند

۱۱ اتصال Long-Poll

آداپتور برای دریافت پیام از HTTP long-polling استفاده می‌کند ‏(نه WebSocket):

نحوهٔ کار

  1. Connect: اعتبارنامه‌ها را تأیید و حلقهٔ poll را شروع می‌کند
  2. Poll: ‏getupdates را با timeout ۳۵ ثانیه صدا می‌زند؛ سرور درخواست را نگه می‌دارد تا پیام برسد یا timeout تمام شود
  3. Dispatch: پیام‌های ورودی هم‌زمان با ‏asyncio.create_task dispatch می‌شوند
  4. بافر sync: نشانگر sync دائمی ‏(get_updates_buf) روی دیسک ذخیره می‌شود تا آداپتور بعد از ری‌استارت از موقعیت درست ادامه دهد

رفتار retry

در خطاهای API آداپتور استراتژی retry ساده‌ای دارد:

شرطرفتار
خطای گذرا ‏(اول–دوم)retry بعد از ۲ ثانیه
خطاهای مکرر ‏(سوم+)۳۰ ثانیه backoff، بعد ریست شمارنده
نشست منقضی ‏(errcode=-14)توقف ۱۰ دقیقه ‏(احتمالاً ورود مجدد لازم است)
Timeoutبلافاصله دوباره poll ‏(رفتار عادی long-poll)

حذف تکرار

پیام‌های ورودی با شناسهٔ پیام با پنجرهٔ ۵ دقیقه‌ای dedupe می‌شوند. مانع پردازش دوباره در لغزش شبکه یا هم‌پوشانی پاسخ‌های poll.

قفل توکن

در هر لحظه فقط یک نمونهٔ گیت‌وی ویکسین می‌تواند از یک توکن استفاده کند. آداپتور هنگام شروع قفل scoped می‌گیرد و هنگام خاموشی آزاد می‌کند. اگر گیت‌وی دیگری همان توکن را استفاده کند، شروع با پیام خطای گویا شکست می‌خورد.
