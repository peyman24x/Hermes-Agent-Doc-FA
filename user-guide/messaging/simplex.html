SimpleX Chat

SimpleX Chat پلتفرم پیام‌رسانی خصوصی و غیرمتمرکزی است که کاربران مالک مخاطبان و گروه‌های خودشان هستند. برخلاف سایر پلتفرم‌ها SimpleX هیچ شناسهٔ کاربری پایداری تخصیص نمی‌دهد — هر مخاطب با شناسهٔ داخلی مبهمی که هنگام اتصال تولید می‌شود شناخته می‌شود؛ همین آن را به یکی از خصوصی‌ترین پیام‌رسان‌های موجود تبدیل کرده است.

hermes gateway setup را اجرا و SimpleX را انتخاب کنید تا راهنمای گام‌به‌گام ببینید.

۱ پیش‌نیازها

  • ‏CLI ‏simplex-chat نصب‌شده و در حال اجرا به‌عنوان دیمن
  • بستهٔ پایتونی ‏websockets ‏(pip install websockets)

نصب simplex-chat

آخرین ریلیز را از صفحهٔ ریلیزهای گیت‌هاب simplex-chat دانلود کنید:

bash
# باینری Linux / macOS
curl -L https://github.com/simplex-chat/simplex-chat/releases/latest/download/simplex-chat-ubuntu-22_04-x86_64 -o simplex-chat
chmod +x simplex-chat

پروژهٔ SimpleX Chat ایمیج Docker آماده برای کلاینت چت منتشر نمی‌کند؛ برای اجرا زیر Docker از مخزن simplex-chat از سورس بسازید.

۲ شروع دیمن

bash
simplex-chat -p 5225

دیمن پیش‌فرض روی WebSocket آدرس ‏ws://127.0.0.1:5225 گوش می‌دهد.

۳ پیکربندی هرمس

با ویزارد راه‌اندازی

hermes gateway setup

SimpleX Chat را انتخاب و طبق پرسش‌ها پیش بروید.

با متغیرهای محیطی

به ‏~/.hermes/.env اضافه کنید:

SIMPLEX_WS_URL=ws://127.0.0.1:5225
SIMPLEX_ALLOWED_USERS=<contact-id-1>,<contact-id-2>
SIMPLEX_HOME_CHANNEL=<contact-id>
متغیرلازمتوضیح
SIMPLEX_WS_URLبلهWebSocket URL دیمن simplex-chat
SIMPLEX_ALLOWED_USERSتوصیه‌شدهلیست مجاز جداشده با ویرگول. هر ورودی هم می‌تواند ‏contactId عددی باشد هم نام نمایشی — هر دو فرم کار می‌کند.
SIMPLEX_ALLOW_ALL_USERSاختیاری‏true برای اجازه به هر مخاطبی ‏(با احتیاط)
SIMPLEX_AUTO_ACCEPTاختیاریپذیرش خودکار درخواست‌های مخاطب ورودی ‏(پیش‌فرض: true)
SIMPLEX_GROUP_ALLOWEDاختیاریشناسه‌های گروهی که بات درشان شرکت می‌کند جداشده با ویرگول، یا ‏* برای هر گروهی. حذف = نادیده گرفتن کامل پیام‌های گروهی
SIMPLEX_HOME_CHANNELاختیاریشناسهٔ پیش‌فرض مخاطب/گروه برای تحویل کارهای کرون
SIMPLEX_HOME_CHANNEL_NAMEاختیاریبرچسب خوانا برای کانال خانگی
HERMES_SIMPLEX_TEXT_BATCH_DELAYاختیاریثانیه دورهٔ سکوت ‏(پیش‌فرض: 0.8) برای ادغام پیام‌های متنی ورودیِ پشت‌سرهم در یک رویداد واحد

۴ یافتن contact ID یا نام نمایشی

بعد از شروع دیمن، با مخاطب ایجنت گفتگو باز کنید. ‏contactId عددی در لاگ‌های نشست ظاهر می‌شود. اگر ترجیح می‌دهید از نام نمایشی نشان‌داده‌شده در UI سیمپلکس استفاده کنید آن هم کار می‌کند — ‏SIMPLEX_ALLOWED_USERS هر دو فرم را می‌پذیرد.

۵ مجوزدهی

به‌طور پیش‌فرض همهٔ مخاطبان رد می‌شوند. باید یکی از این دو:

  1. ‏SIMPLEX_ALLOWED_USERS را فهرست جداشده با ویرگول از ‏contactId ها و/یا نام‌های نمایشی کنید ‏(مثل ‏SIMPLEX_ALLOWED_USERS=4,alice که هم contactId ۴ را می‌گیرد هم مخاطبی با نام نمایشی «alice» را)، یا
  2. از جفت‌سازی DM استفاده کنید — هر پیامی به بات بدهید تا کد جفت‌سازی جواب بدهد؛ کد را با ‏hermes pairing approve simplex <CODE> تأیید کنید.

۶ چت‌های گروهی

به‌طور پیش‌فرض آداپتور پیام‌های گروه را نادیده می‌گیرد — باتی که در گروه است وگرنه ترافیک همهٔ اعضا را پردازش می‌کند. صریحاً انتخاب کنید:

SIMPLEX_GROUP_ALLOWED=12,34          # شناسه‌های گروه خاص
# یا
SIMPLEX_GROUP_ALLOWED=*              # هر گروهی که بات در آن است

خطاب گروه‌ها با پیشوند ‏group: روی شناسهٔ چت، مثل ‏simplex:group:12 به‌عنوان هدف ‏deliver= کرون یا داخل فراخوانی ‏hermes send.

۷ ارسال با hermes send

‏SimpleX به‌عنوان هدف ارسال مستقل کار می‌کند — دیمن باید روشن باشد ولی برای متن ساده گیت‌وی زنده لازم نیست:

bash
hermes send --to simplex:alice "hello"          # DM با نام نمایشی مخاطب
hermes send --to simplex:group:12 "hello"       # گروه با شناسهٔ عددی
hermes send --to simplex "hello"                # SIMPLEX_HOME_CHANNEL

حین اجرای گیت‌وی، آداپتور مخاطبان و گروه‌های مجازتان را در directory کانال‌ها فهرست می‌کند ‏(هر ۵ دقیقه refresh)، پس ‏hermes send --list آنها را با نام نشان می‌دهد. قبل از اولین اجرای گیت‌وی پلتفرم همچنان در ‏--list با سرنخ «هنوز کانالی کشف نشده» می‌آید — هدف‌های مستقیم مثل بالا مستقلاً کار می‌کنند.

۸ پیوست‌ها

آداپتور پیوست‌های بومی SimpleX را در هر دو جهت پشتیبانی می‌کند:

  • ورودی — تصاویر، یادداشت‌های صوتی و فایل‌های ورودی از طریق جریان XFTP دیمن پذیرفته می‌شوند ‏(rcvFileDescrReady ← ‏/freceive ← انتظار برای ‏rcvFileComplete) و به‌صورت ‏MessageEvent.media_urls با ‏MessageType مناسب ‏(PHOTO، ‏VOICE، ‏TEXT+document) داده می‌شوند.
  • خروجی — ‏send_image_file، ‏send_voice، ‏send_document و ‏send_video همه فرم ساختاریافتهٔ ‏/_send با ‏filePath را استفاده می‌کنند تا کلاینت SimpleX گیرنده تصاویر را درجا رندر و یادداشت‌های صوتی را درجا پخش کند نه به‌عنوان دانلود.

ریپلای‌های ایجنت می‌توانند تگ‌های ‏MEDIA:/path/to/file را هم در متن ساده داشته باشند — آداپتور تگ را از بدنه برمی‌دارد و فایل را یا به‌عنوان یادداشت صوتی ‏(پسوندهای صوتی) یا document می‌فرستد.

۹ استفاده از SimpleX با کارهای کرون

python
cronjob(
    action="create",
    schedule="every 1h",
    deliver="simplex",          # از SIMPLEX_HOME_CHANNEL استفاده می‌کند
    prompt="Check for alerts and summarise."
)

یا یک مخاطب مشخص را از طریق فیلد ‏deliver: کار کرون هدف بگیرید، یا از اسکریپت شل با CLI ‏hermes send:

hermes send simplex:<contact-id> "Done!"

۱۰ نکات حریم خصوصی

  • ‏SimpleX هرگز شماره تلفن یا ایمیل لو نمی‌دهد — مخاطبان از شناسه‌های مبهم استفاده می‌کنند
  • ارتباط هرمس و دیمن WebSocket محلی است ‏(ws://127.0.0.1:5225) — هیچ داده‌ای از ماشین شما خارج نمی‌شود
  • پیام‌ها قبل از رسیدن به دیمن توسط پروتکل SimpleX رمزنگاری سرتاسری می‌شوند

۱۱ عیب‌یابی

«Cannot reach daemon» — مطمئن شوید ‏simplex-chat -p 5225 اجراست و پورت با ‏SIMPLEX_WS_URL بخواند.

«websockets not installed» — ‏pip install websockets را اجرا کنید.

پیام‌ها دریافت نمی‌شوند — چک کنید شناسهٔ مخاطب در ‏SIMPLEX_ALLOWED_USERS باشد یا از طریق جفت‌سازی DM تأییدش کنید.
