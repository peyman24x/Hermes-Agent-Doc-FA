خانه/پیام‌رسان‌ها/ایمیل

راه‌اندازی ایمیل

هرمس می‌تواند با پروتکل‌های استاندارد IMAP و SMTP ایمیل دریافت و پاسخ دهد. به نشانی ایجنت ایمیل بزنید و در همان ترد جواب می‌گیرد — نه کلاینت خاصی لازم است نه API بات. با Gmail، ‏Outlook، ‏Yahoo، ‏Fastmail یا هر ارائه‌دهندهٔ پشتیبان IMAP/SMTP کار می‌کند.

📌 فقط آداپتور گیت‌وی: بدون وابستگی خارجی

این صفحه آداپتور گیت‌وی ایمیل را پوشش می‌دهد که از ماژول‌های داخلی پایتون ‏imaplib، ‏smtplib و email استفاده می‌کند. برای این مسیر هیچ بسته یا سرویس خارجی اضافه‌ای لازم نیست.

این جدا از مهارت ایمیل Himalaya همراه‌بسته است که به ایجنت اجازه مدیریت ایمیل از طریق فرمان‌های ترمینال را می‌دهد و CLI خارجی himalaya و فایل پیکربندی Himalaya لازم دارد.

کاربردچه چیزی را پیکربندی کنیموابستگی خارجی
اجازه دهیم مردم به ایجنت هرمس ایمیل بزنند و پاسخ بگیرندآداپتور گیت‌وی ایمیل در همین صفحههیچ — فراتر از یک حساب ایمیل IMAP/SMTP
اجازه دهیم ایجنت از ابزارهای ترمینال پیام‌های صندوق را بازرسی، نوشته، جابه‌جا و مدیریت کندمهارت ایمیل Himalaya‏CLI ‏himalaya و ‏~/.config/himalaya/config.toml

۱ پیش‌نیازها

  • یک حساب ایمیل اختصاصی برای ایجنت هرمس ‏(ایمیل شخصی‌تان را استفاده نکنید)
  • ‏IMAP فعال روی حساب ایمیل
  • یک رمز اپ (App Password) اگر Gmail یا ارائه‌دهندهٔ دارای 2FA استفاده می‌کنید

راه‌اندازی Gmail

  1. احراز هویت دومرحله‌ای را روی حساب Google خود فعال کنید
  2. به App Passwords بروید
  3. رمز اپ جدید بسازید ‏(«Mail» یا «Other» را انتخاب کنید)
  4. رمز ۱۶کاراکتری را کپی کنید — به‌جای رمز معمولی از این استفاده می‌کنید

‏Outlook / Microsoft 365

  1. به تنظیمات امنیتی بروید
  2. اگر 2FA فعال نیست فعالش کنید
  3. تحت «Additional security options» رمز اپ بسازید
  4. میزبان IMAP: ‏outlook.office365.com، میزبان SMTP: ‏smtp.office365.com

سایر ارائه‌دهندگان

بیشتر ارائه‌دهندگان ایمیل IMAP/SMTP دارند. مستندات ارائه‌دهنده‌تان را برای این‌ها چک کنید:

  • میزبان و پورت IMAP ‏(معمولاً پورت ۹۹۳ با SSL)
  • میزبان و پورت SMTP ‏(معمولاً پورت ۵۸۷ با STARTTLS)
  • آیا رمز اپ لازم است یا نه

۲ گام ۱: پیکربندی هرمس

ساده‌ترین راه:

bash
hermes gateway setup

Email را از منوی پلتفرم انتخاب کنید. ویزارد نشانی ایمیل، رمز، میزبان‌های IMAP/SMTP و فرستندگان مجاز را می‌پرسد.

پیکربندی دستی

به ~/.hermes/.env اضافه کنید:

bash
# الزامی
EMAIL_ADDRESS=hermes@gmail.com
EMAIL_PASSWORD=abcd efgh ijkl mnop    # رمز اپ (نه رمز معمولی)
EMAIL_IMAP_HOST=imap.gmail.com
EMAIL_SMTP_HOST=smtp.gmail.com

# امنیت (توصیه‌شده)
EMAIL_ALLOWED_USERS=your@email.com,colleague@work.com

# اختیاری
EMAIL_IMAP_PORT=993                    # پیش‌فرض: 993 (IMAP SSL)
EMAIL_SMTP_PORT=587                    # پیش‌فرض: 587 (SMTP STARTTLS)
EMAIL_POLL_INTERVAL=15                 # فاصلهٔ ثانیه‌ای چک صندوق (پیش‌فرض: 15)
EMAIL_HOME_ADDRESS=your@email.com      # هدف تحویل پیش‌فرض کارهای کرون

۳ گام ۲: شروع گیت‌وی

bash
hermes gateway              # اجرا در پیش‌زمینه
hermes gateway install      # نصب به‌عنوان سرویس کاربر
sudo hermes gateway install --system   # فقط لینوکس: سرویس سیستمی زمان‌بوت

آداپتور هنگام شروع:

  1. اتصالات IMAP و SMTP را تست می‌کند
  2. همهٔ پیام‌های موجود صندوق را «خوانده‌شده» علامت می‌زند ‏(فقط ایمیل‌های جدید پردازش می‌شوند)
  3. پایش پیام‌های جدید را شروع می‌کند

۴ نحوهٔ کار

دریافت پیام‌ها

آداپتور با فاصلهٔ قابل‌پیکربندی ‏(پیش‌فرض: ۱۵ ثانیه) صندوق IMAP را برای پیام‌های UNSEEN پایش می‌کند. برای هر ایمیل جدید:

  • خط موضوع به‌عنوان زمینه لحاظ می‌شود ‏(مثل [Subject: Deploy to production])
  • ایمیل‌های ریپلای ‏(موضوع با Re:) پیشوند موضوع را رد می‌کنند — زمینهٔ ترد از قبل برقرار است
  • پیوست‌ها محلی کش می‌شوند:
    • تصاویر ‏(JPEG، ‏PNG، ‏GIF، ‏WebP) ← در دسترس ابزار بینایی
    • اسناد ‏(PDF، ‏ZIP و غیره) ← در دسترس دسترسی فایل
  • ایمیل‌های فقط-HTML برای استخراج متن ساده از تگ خالی می‌شوند
  • پیام‌های خودِ سیستم برای پیشگیری از حلقهٔ ریپلای فیلتر می‌شوند
  • فرستندگان خودکار/noreply بی‌صدا نادیده گرفته می‌شوند — ‏noreply@، ‏mailer-daemon@، ‏bounce@، ‏no-reply@ و ایمیل‌هایی با هدرهای Auto-Submitted، ‏Precedence: bulk یا List-Unsubscribe

ارسال ریپلای

ریپلای‌ها از طریق SMTP با threading صحیح ایمیل ارسال می‌شوند:

  • هدرهای In-Reply-To و References ترد را حفظ می‌کنند
  • خط موضوع با پیشوند Re: حفظ می‌شود ‏(بدون Re: Re: دوتایی)
  • Message-ID با دومین ایجنت تولید می‌شود
  • پاسخ‌ها به‌صورت متن ساده ‏(UTF-8) فرستاده می‌شوند

پیوست فایل

ایجنت می‌تواند در ریپلای‌ها پیوست فایل بفرستد. ‏MEDIA:/path/to/file را در پاسخ بگنجانید تا فایل به ایمیل خروجی پیوست شود.

ردکردن پیوست‌ها

برای نادیده‌گرفتن همهٔ پیوست‌های ورودی ‏(محافظت بدافزار یا صرفه‌جویی پهنای‌باند) به config.yaml اضافه کنید:

yaml
platforms:
  email:
    skip_attachments: true

با فعال‌بودن، بخش‌های پیوست و inline قبل از decode شدن payload رد می‌شوند. متن بدنهٔ ایمیل همچنان عادی پردازش می‌شود.

۵ کنترل دسترسی

دسترسی ایمیل به‌طور پیش‌فرض سخت‌گیرانه‌تر از پلتفرم‌های چت‌گونه است:

  1. ‏EMAIL_ALLOWED_USERS تنظیم شده ← فقط ایمیل‌های آن نشانی‌ها پردازش می‌شوند
  2. لیست مجاز تنظیم نشده ← فرستندگان ناشناس بی‌صدا نادیده گرفته می‌شوند
  3. ‏EMAIL_ALLOW_ALL_USERS=true ← هر فرستنده‌ای پذیرفته می‌شود ‏(با احتیاط)
  4. ‏platforms.email.unauthorized_dm_behavior: pair ← فرستندگان ناشناس کد جفت‌سازی می‌گیرند
⚠️ هشدار

برای عملیات عادی از صندوق اختصاصی استفاده و EMAIL_ALLOWED_USERS را پیکربندی کنید. جفت‌سازی ایمیل اختیاری است چون صندوق‌های مشترک اغلب پیام‌های نخواندهٔ نامرتبط دارند و هرمس نباید به‌طور پیش‌فرض به آن مخاطبان جواب بدهد.

۶ عیب‌یابی

مشکلراه‌حل
«IMAP connection failed» هنگام شروع‏EMAIL_IMAP_HOST و EMAIL_IMAP_PORT را تأیید کنید. مطمئن شوید IMAP روی حساب فعال است. برای Gmail: ‏Settings ← Forwarding and POP/IMAP.
«SMTP connection failed» هنگام شروع‏EMAIL_SMTP_HOST و EMAIL_SMTP_PORT را تأیید کنید. درستی رمز را چک کنید ‏(برای Gmail از App Password استفاده کنید).
پیام‌ها دریافت نمی‌شوندچک کنید EMAIL_ALLOWED_USERS شامل ایمیل فرستنده باشد. پوشهٔ اسپم را چک کنید — بعضی ارائه‌دهندگان ریپلای‌های خودکار را فلگ می‌زنند.
«Authentication failed»برای Gmail باید App Password استفاده کنید نه رمز معمولی. اول 2FA را فعال کنید.
ریپلای‌های تکراریمطمئن شوید فقط یک نمونه گیت‌وی اجراست. ‏hermes gateway status را چک کنید.
پاسخ کندفاصلهٔ پیش‌فرض پایش ۱۵ ثانیه است. با EMAIL_POLL_INTERVAL=5 سریع‌ترش کنید ‏(ولی اتصالات IMAP بیشتر).
ریپلای‌ها ترد نمی‌شوندآداپتور از هدرهای In-Reply-To استفاده می‌کند. بعضی کلاینت‌های ایمیل ‏(به‌خصوص وبی) ممکن است با پیام‌های خودکار درست ترد نکنند.

۷ امنیت

⚠️ هشدار

از حساب ایمیل اختصاصی استفاده کنید. ایمیل شخصی‌تان را استفاده نکنید — ایجنت رمز را در .env ذخیره و دسترسی کامل صندوق از طریق IMAP دارد.

  • به‌جای رمز اصلی از App Password استفاده کنید ‏(برای Gmail با 2FA الزامی)
  • ‏EMAIL_ALLOWED_USERS را بگذارید تا مشخص شود چه کسی با ایجنت تعامل کند
  • رمز در ~/.hermes/.env ذخیره می‌شود — از این فایل محافظت کنید ‏(chmod 600)
  • ‏IMAP از SSL ‏(پورت ۹۹۳) و SMTP از STARTTLS ‏(پورت ۵۸۷) به‌طور پیش‌فرض استفاده می‌کنند — اتصالات رمزنگاری می‌شوند
