خانه/پیام‌رسان‌ها/DingTalk

راه‌اندازی DingTalk

هرمس ایجنت به‌عنوان چت‌بات با DingTalk ‏(钉钉) یکپارچه می‌شود و اجازه می‌دهد از طریق پیام خصوصی یا چت گروهی با دستیار هوش مصنوعی‌تان گفتگو کنید. بات از طریق Stream Mode دینگ‌تاک وصل می‌شود — اتصال WebSocket طولانی‌عمر که هیچ URL عمومی یا سرور وب‌هوکی نمی‌خواهد — و با پیام‌های مارک‌داونی از طریق API وب‌هوک نشست دینگ‌تاک جواب می‌دهد.

پیش از راه‌اندازی، بخشی که بیشتر افراد می‌خواهند بدانند: رفتار هرمس پس از ورود به ورک‌اسپیس دینگ‌تاک شما چگونه است.

۱ رفتار هرمس

زمینهرفتار
‏DM ها ‏(چت ۱:۱)هرمس به همهٔ پیام‌ها پاسخ می‌دهد. نیازی به منشن نیست. هر DM نشست مستقل دارد.
چت‌های گروهیهرمس وقتی منشن شود پاسخ می‌دهد. بدون منشن، پیام نادیده گرفته می‌شود.
گروه‌های مشترک چندکاربرهبه‌طور پیش‌فرض هرمس تاریخچهٔ نشست را داخل گروه به‌ازای هر کاربر جدا می‌کند. دو نفر که در یک گروه حرف می‌زنند مگر صریحاً غیرفعالش کنید رونویسی مشترک ندارند.

مدل نشست در DingTalk

به‌طور پیش‌فرض:

  • هر DM نشست مستقل خودش را دارد
  • هر کاربر در چت گروهی مشترک، داخل همان گروه نشست خودش را دارد

این با config.yaml کنترل می‌شود:

yaml
group_sessions_per_user: true

فقط اگر صریحاً یک گفتگوی مشترک برای کل گروه می‌خواهید false کنید:

yaml
group_sessions_per_user: false

این راهنما کل فرایند راه‌اندازی را قدم‌به‌قدم توضیح می‌دهد — از ساخت بات دینگ‌تاک تا ارسال اولین پیام.

۲ پیش‌نیازها

بسته‌های پایتونی لازم را نصب کنید:

cd ~/.hermes/hermes-agent && uv pip install -e ".[dingtalk]"

یا تکی:

pip install dingtalk-stream httpx alibabacloud-dingtalk
  • ‏dingtalk-stream — SDK رسمی دینگ‌تاک برای Stream Mode ‏(پیام‌رسانی لحظه‌ای مبتنی بر WebSocket)
  • ‏httpx — کلاینت HTTP ناهمگام برای ارسال ریپلای از طریق وب‌هوک‌های نشست
  • ‏alibabacloud-dingtalk — SDK OpenAPI دینگ‌تاک برای AI Card ها، واکنش ایموجی و دانلود رسانه

۳ گام ۱: ساخت اپ دینگ‌تاک

  1. به کنسول توسعه‌دهندگان DingTalk بروید.
  2. با حساب ادمین دینگ‌تاک وارد شوید.
  3. روی Application Development ← Custom Apps ← Create App via H5 Micro-App کلیک کنید ‏(یا Robot بسته به نسخهٔ کنسول).
  4. پر کنید:
    • App Name: مثل ‏Hermes Agent
    • Description: اختیاری
  5. بعد از ساخت به Credentials & Basic Info بروید و Client ID ‏(AppKey) و Client Secret ‏(AppSecret) را پیدا کنید. هر دو را کپی کنید.
⚠️ اعتبارنامه فقط یک‌بار نمایش داده می‌شود

‏Client Secret فقط هنگام ساخت اپ یک‌بار نمایش داده می‌شود. اگر گمش کردید باید بازتولیدش کنید. هرگز این اعتبارنامه‌ها را عمومی به اشتراک نگذارید یا به گیت کامیت نکنید.

۴ گام ۲: فعال‌سازی قابلیت ربات

  1. در صفحهٔ تنظیمات اپ به Add Capability ← Robot بروید.
  2. قابلیت ربات را فعال کنید.
  3. تحت Message Reception Mode مقدار Stream Mode را انتخاب کنید ‏(توصیه‌شده — بدون URL عمومی).
💡 نکته

‏Stream Mode پیکربندی توصیه‌شده است. اتصال WebSocket طولانی‌عمرِ شروع‌شده از ماشین شما استفاده می‌کند، پس IP عمومی، دامنه یا endpoint وب‌هوک لازم ندارد. پشت NAT، فایروال و روی ماشین‌های محلی کار می‌کند.

۵ گام ۳: یافتن شناسهٔ کاربری دینگ‌تاک

هرمس ایجنت از شناسهٔ کاربری دینگ‌تاک شما برای کنترل اینکه چه کسی با بات تعامل کند استفاده می‌کند. شناسه‌های کاربری دینگ‌تاک رشته‌های الفبایی-عددی تنظیمشده توسط ادمین سازمان‌تان هستند.

برای یافتن شناسه‌تان:

  1. از ادمین سازمان دینگ‌تاک بپرسید — شناسه‌ها در کنسول ادمین دینگ‌تاک زیر Contacts ← Members پیکربندی می‌شوند.
  2. روش جایگزین: بات ‏sender_id هر پیام ورودی را لاگ می‌کند. گیت‌وی را شروع، به بات پیام بدهید و بعد شناسه‌تان را در لاگ‌ها چک کنید.

۶ گام ۴: پیکربندی هرمس ایجنت

گزینهٔ A: راه‌اندازی تعاملی ‏(توصیه‌شده)

hermes gateway setup

هنگام پرسش DingTalk را انتخاب کنید. ویزارد setup از یکی از دو مسیر مجوز می‌دهد:

  • جریان دستگاهی QR-code ‏(توصیه‌شده). QR چاپ‌شده در ترمینال را با اپ موبایل دینگ‌تاک اسکن کنید — ‏Client ID و Client Secret خودکار برگردانده و در ‏~/.hermes/.env نوشته می‌شوند. بدون رفت‌وآمد به کنسول توسعه‌دهنده.
  • چسباندن دستی. اگر قبلاً اعتبارنامه دارید ‏(یا اسکن QR راحت نیست)، هنگام پرسش Client ID، ‏Client Secret و شناسه‌های کاربر مجاز را بچسبانید.
📌 افشای برند openClaw

چون ‏verification_uri_complete دینگ‌تاک در لایهٔ API به هویت openClaw هاردکد شده، QR فعلاً تا زمانی که Alibaba / DingTalk-Real-AI قالب اختصاصی هرمس را سمت سرور ثبت کند زیر رشتهٔ مبدأ ‏openClaw مجوز می‌دهد. این صرفاً نحوهٔ نمایش صفحهٔ رضایت دینگ‌تاک است — باتی که می‌سازید کاملاً متعلق به خودتان و خصوصی به tenant شماست.

گزینهٔ B: پیکربندی دستی

این‌ها را به فایل ‏~/.hermes/.env اضافه کنید:

bash
# الزامی
DINGTALK_CLIENT_ID=your-app-key
DINGTALK_CLIENT_SECRET=your-app-secret

# امنیت: محدودکردن تعامل با بات
DINGTALK_ALLOWED_USERS=user-id-1

# چند کاربر مجاز (با ویرگول)
# DINGTALK_ALLOWED_USERS=user-id-1,user-id-2

# اختیاری: گیت چت گروهی (مثل Slack/Telegram/Discord/WhatsApp)
# DINGTALK_REQUIRE_MENTION=true
# DINGTALK_FREE_RESPONSE_CHATS=cidABC==,cidDEF==
# DINGTALK_MENTION_PATTERNS=^小马
# DINGTALK_HOME_CHANNEL=cidXXXX==
# DINGTALK_ALLOW_ALL_USERS=true

تنظیم رفتاری اختیاری در config.yaml:

yaml
group_sessions_per_user: true

gateway:
  platforms:
    dingtalk:
      extra:
        # منشن در گروه‌ها قبل از ریپلای بات لازم باشد (هم‌ترازی با Slack/Telegram/Discord).
        # DM ها این را نادیده می‌گیرند — بات همیشه در چت ۱:۱ جواب می‌دهد.
        require_mention: true

        # لیست مجاز به‌ازای-پلتفرم. با تنظیم فقط این شناسه‌های کاربر دینگ‌تاک حق تعامل دارند
        # (همان معناشناسی DINGTALK_ALLOWED_USERS ولی scope اینجا به‌جای .env).
        allowed_users:
          - user-id-1
          - user-id-2
  • ‏group_sessions_per_user: true زمینهٔ هر شرکت‌کننده را داخل چت‌های گروهی مشترک ایزوله نگه می‌دارد
  • ‏require_mention: true مانع پاسخ بات به هر پیام گروهی می‌شود — فقط وقتی کسی @منشنش کند جواب می‌دهد
  • ‏allowed_users زیر ‏dingtalk.extra جایگزینی برای ‏DINGTALK_ALLOWED_USERS است؛ یکی را بگذارید ‏(اگر هر دو تنظیم شوند فقط کاربران حاضر در هر دو فهرست مجازند)

شروع گیت‌وی

بعد از پیکربندی، گیت‌وی دینگ‌تاک را شروع کنید:

hermes gateway

بات باید ظرف چند ثانیه به Stream Mode دینگ‌تاک وصل شود. برای تست بهش پیام بدهید — DM یا در گروهی که افزوده شده.

💡 نکته

می‌توانید ‏hermes gateway را در پس‌زمینه یا به‌صورت سرویس systemd برای عملکرد مداوم اجرا کنید. جزئیات در مستندات استقرار.

۷ قابلیت‌ها

‏AI Card ها

هرمس می‌تواند به‌جای پیام مارک‌داونی ساده با AI Card های دینگ‌تاک ریپلای دهد. کارت‌ها نمایش غنی‌تر و ساختاریافته‌تری دارند و از به‌روزرسانی استریم حین تولید پاسخ ایجنت پشتیبانی می‌کنند.

برای فعال‌کردن AI Card ها شناسهٔ قالب کارت را در config.yaml تنظیم کنید:

yaml
platforms:
  dingtalk:
    enabled: true
    extra:
      card_template_id: "your-card-template-id"

شناسهٔ قالب کارت را در کنسول توسعه‌دهندگان دینگ‌تاک زیر تنظیمات AI Card اپ‌تان پیدا می‌کنید. با فعال‌شدن AI Card ها همهٔ ریپلای‌ها به‌صورت کارت با به‌روزرسانی متنی استریم ارسال می‌شوند.

واکنش‌های ایموجی

هرمس خودکار برای نشان دادن وضعیت پردازش روی پیام‌هایتان واکنش ایموجی می‌گذارد:

  • 🤔Thinking — وقتی بات شروع به پردازش پیام شما می‌کند اضافه می‌شود
  • 🥳Done — وقتی پاسخ کامل شد ‏(جایگزین واکنش Thinking)

این واکنش‌ها هم در DM هم در چت گروهی کار می‌کنند.

تنظیمات نمایش

رفتار نمایش دینگ‌تاک را مستقل از سایر پلتفرم‌ها سفارشی کنید:

yaml
display:
  platforms:
    dingtalk:
      show_reasoning: false   # نمایش استدلال/تفکر مدل در ریپلای‌ها
      streaming: true         # پاسخ‌های استریم (با AI Card کار می‌کند)
      tool_progress: all      # نمایش پیشرفت اجرای ابزار (all/new/off)
      interim_assistant_messages: true  # نمایش پیام‌های میان‌متن توضیحی

برای تجربهٔ تمیزتر پیشرفت ابزار و پیام‌های میانی را خاموش کنید:

yaml
display:
  platforms:
    dingtalk:
      tool_progress: off
      interim_assistant_messages: false

۸ عیب‌یابی

بات به پیام‌ها پاسخ نمی‌دهد

علت: قابلیت ربات فعال نیست یا ‏DINGTALK_ALLOWED_USERS شناسهٔ شما را ندارد.

راه‌حل: تأیید کنید قابلیت ربات در تنظیمات اپ فعال و Stream Mode انتخاب شده. چک کنید شناسه‌تان در ‏DINGTALK_ALLOWED_USERS باشد. گیت‌وی را ری‌استارت کنید.

خطای «dingtalk-stream not installed»

علت: بستهٔ پایتونی ‏dingtalk-stream نصب نیست.

راه‌حل:

pip install dingtalk-stream httpx

خطای «DINGTALK_CLIENT_ID and DINGTALK_CLIENT_SECRET required»

علت: اعتبارنامه‌ها در محیط یا فایل .env تنظیم نیستند.

راه‌حل: تأیید کنید ‏DINGTALK_CLIENT_ID و ‏DINGTALK_CLIENT_SECRET درست در ‏~/.hermes/.env تنظیم‌اند. ‏Client ID همان AppKey و ‏Client Secret همان AppSecret از کنسول توسعه‌دهندگان است.

قطع Stream / حلقهٔ اتصال‌مجدد

علت: ناپایداری شبکه، نگهداشت پلتفرم دینگ‌تاک یا مشکلات اعتبارنامه.

راه‌حل: آداپتور خودکار با backoff نمایی reconnect می‌شود ‏(۲ ← ۵ ← ۱۰ ← ۳۰ ← ۶۰ ثانیه). اعتبار اعتبارنامه‌ها و غیرفعال نبودن اپ را چک کنید. مطمئن شوید شبکه‌تان اتصالات WebSocket خروجی را اجازه می‌دهد.

بات آفلاین است

علت: گیت‌وی هرمس اجرا نیست یا اتصال شکست خورده.

راه‌حل: چک کنید ‏hermes gateway در حال اجراست. خروجی ترمینال را برای پیام خطا ببینید. مسائل رایج: اعتبارنامه اشتباه، اپ غیرفعال، نصب نبودن ‏dingtalk-stream یا ‏httpx.

«No session_webhook available»

علت: بات خواست جواب بدهد ولی URL وب‌هوک نشست نداشت. معمولاً وقتی اتفاق می‌افتد که وب‌هوک منقضی شده یا بین دریافت پیام و ارسال ریپلای، بات ری‌استارت شده.

راه‌حل: پیام جدیدی به بات بدهید — هر پیام ورودی وب‌هوک نشست تازه‌ای برای ریپلای فراهم می‌کند. این محدودیت عادی دینگ‌تاک است؛ بات فقط می‌تواند به پیام‌هایی که اخیراً دریافت کرده ریپلای بدهد.

۹ امنیت

⚠️ هشدار

همیشه ‏DINGTALK_ALLOWED_USERS را تنظیم کنید تا مشخص شود چه کسی با بات تعامل می‌کند. بدون آن، گیت‌وی به‌عنوان اقدام ایمنی همهٔ کاربران را پیش‌فرض رد می‌کند. فقط شناسهٔ کاربری افراد مورداطمینان را اضافه کنید — کاربران مجاز دسترسی کامل به قابلیت‌های ایجنت دارند شامل استفاده از ابزار و دسترسی سیستم.

برای اطلاعات بیشتر دربارهٔ امن‌سازی استقرار هرمس ایجنت، راهنمای امنیت را ببینید.

۱۰ یادداشت‌ها

  • ‏Stream Mode: هیچ URL عمومی، نام دامنه یا سرور وب‌هوکی لازم نیست. اتصال از ماشین شما با WebSocket شروع می‌شود، پس پشت NAT و فایروال کار می‌کند.
  • ‏AI Card ها: به‌صورت اختیاری با کارت‌های AI غنی به‌جای مارک‌داون خام ریپلای دهید. از طریق ‏card_template_id پیکربندی می‌شود.
  • واکنش‌های ایموجی: واکنش‌های خودکار 🤔Thinking/🥳Done برای وضعیت پردازش.
  • پاسخ‌های مارک‌داونی: ریپلای‌ها با فرمت مارک‌داون دینگ‌تاک برای نمایش متن غنی قالب می‌گیرند.
  • پشتیبانی رسانه: تصاویر و فایل‌های پیام ورودی خودکار حل و توسط ابزارهای بینایی قابل‌پردازش‌اند.
  • حذف تکرار پیام: آداپتور پیام‌ها را با پنجرهٔ ۵ دقیقه‌ای dedupe می‌کند تا همان پیام دوبار پردازش نشود.
  • اتصال‌مجدد خودکار: اگر اتصال stream قطع شود آداپتور با backoff نمایی خودکار برمی‌گردد.
  • سقف طول پیام: پاسخ‌ها به ۲۰٬۰۰۰ کاراکتر به‌ازای هر پیام سقف می‌خورند. پاسخ‌های بلندتر بریده می‌شوند.
