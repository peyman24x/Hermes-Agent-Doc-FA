یکپارچه‌سازی Home Assistant

هرمس ایجنت به دو شکل با Home Assistant یکپارچه می‌شود:

  1. پلتفرم گیت‌وی — با WebSocket روی تغییرات وضعیت لحظه‌ای مشترک می‌شود و به رویدادها پاسخ می‌دهد
  2. ابزارهای خانهٔ هوشمند — چهار ابزار قابل-فراخوانی-توسط-LLM برای پرس‌وجو و کنترل دستگاه‌ها از طریق REST API

۱ راه‌اندازی

۱. ساخت توکن دسترسی طولانی‌عمر

  1. نمونهٔ Home Assistant خود را باز کنید
  2. به Profile بروید ‏(روی نامتان در نوار کناری کلیک کنید)
  3. به Long-Lived Access Tokens اسکرول کنید
  4. ‏Create Token را بزنید و نامی مثل «Hermes Agent» بدهید
  5. توکن را کپی کنید

۲. پیکربندی متغیرهای محیطی

bash — افزودن به ~/.hermes/.env
# الزامی: توکن دسترسی طولانی‌عمر شما
HASS_TOKEN=your-long-lived-access-token

# اختیاری: URL هوم‌اسسیستنت (پیش‌فرض: http://homeassistant.local:8123)
HASS_URL=http://192.168.1.100:8123
📌 نکته

تول‌ست homeassistant وقتی ‏HASS_TOKEN تنظیم شود خودکار فعال می‌گردد. هم پلتفرم گیت‌وی هم ابزارهای کنترل دستگاه از همین یک توکن فعال می‌شوند.

۳. شروع گیت‌وی

bash
hermes gateway

‏Home Assistant به‌عنوان یک پلتفرم متصل کنار سایر پیام‌رسان‌ها ‏(تلگرام، دیسکورد و...) ظاهر می‌شود.

۲ ابزارهای موجود

هرمس ایجنت چهار ابزار برای کنترل خانهٔ هوشمند ثبت می‌کند:

ha_list_entities

فهرست موجودیت‌های Home Assistant، با فیلتر اختیاری بر اساس دامنه یا ناحیه.

پارامترها:

  • ‏domain (اختیاری) — فیلتر بر اساس دامنهٔ موجودیت: ‏light، ‏switch، ‏climate، ‏sensor، ‏binary_sensor، ‏cover، ‏fan، ‏media_player و غیره
  • ‏area (اختیاری) — فیلتر بر اساس نام ناحیه/اتاق ‏(با نام‌های دوستانه تطبیق می‌یابد): ‏«living room»، ‏«kitchen»، ‏«bedroom» و غیره

مثال:

List all lights in the living room

شناسه‌های موجودیت، وضعیت‌ها و نام‌های دوستانه را برمی‌گرداند.

ha_get_state

وضعیت تفصیلی یک موجودیت را می‌گیرد شامل همهٔ ویژگی‌ها ‏(روشنایی، رنگ، دمای هدف، قرائت سنسور و...).

پارامترها:

  • ‏entity_id (الزامی) — موجودیت مورد پرس‌وجو، مثل ‏light.living_room، ‏climate.thermostat، ‏sensor.temperature

مثال:

What's the current state of climate.thermostat?

برمی‌گرداند: وضعیت، همهٔ ویژگی‌ها، timestamp های آخرین تغییر/به‌روزرسانی.

ha_list_services

سرویس‌ها ‏(اکشن‌های) موجود برای کنترل دستگاه را فهرست می‌کند. نشان می‌دهد روی هر نوع دستگاه چه اکشن‌هایی ممکن است و چه پارامترهایی می‌پذیرند.

پارامترها:

  • ‏domain (اختیاری) — فیلتر بر اساس دامنه، مثل ‏light، ‏climate، ‏switch

مثال:

What services are available for climate devices?

ha_call_service

یک سرویس Home Assistant را برای کنترل دستگاه صدا می‌زند.

پارامترها:

  • ‏domain (الزامی) — دامنهٔ سرویس: ‏light، ‏switch، ‏climate، ‏cover، ‏media_player، ‏fan، ‏scene، ‏script
  • ‏service (الزامی) — نام سرویس: ‏turn_on، ‏turn_off، ‏toggle، ‏set_temperature، ‏set_hvac_mode، ‏open_cover، ‏close_cover، ‏set_volume_level
  • ‏entity_id (اختیاری) — موجودیت هدف، مثل ‏light.living_room
  • ‏data (اختیاری) — پارامترهای اضافی به‌صورت آبجکت JSON

مثال‌ها:

Turn on the living room lights
→ ha_call_service(domain="light", service="turn_on", entity_id="light.living_room")
Set the thermostat to 22 degrees in heat mode
→ ha_call_service(domain="climate", service="set_temperature",
    entity_id="climate.thermostat", data={"temperature": 22, "hvac_mode": "heat"})
Set living room lights to blue at 50% brightness
→ ha_call_service(domain="light", service="turn_on",
    entity_id="light.living_room", data={"brightness": 128, "color_name": "blue"})

۳ پلتفرم گیت‌وی: رویدادهای لحظه‌ای

آداپتور گیت‌وی Home Assistant از طریق WebSocket وصل و به رویدادهای state_changed مشترک می‌شود. وقتی وضعیت دستگاهی عوض شود و با فیلترهای شما بخواند، به‌عنوان پیام به ایجنت فوروارد می‌شود.

فیلترکردن رویدادها

⚠️ پیکربندی الزامی

به‌طور پیش‌فرض هیچ رویدادی فوروارد نمی‌شود. برای دریافت رویدادها باید دست‌کم یکی از ‏watch_domains، ‏watch_entities یا ‏watch_all را پیکربندی کنید. بدون فیلتر، هنگام شروع هشدار لاگ می‌شود و همهٔ تغییرات وضعیت بی‌صدا دور ریخته می‌شوند.

رویدادهایی که ایجنت می‌بیند را در config.yaml زیر بخش extra پلتفرم Home Assistant پیکربندی کنید:

yaml
platforms:
  homeassistant:
    enabled: true
    extra:
      watch_domains:
        - climate
        - binary_sensor
        - alarm_control_panel
        - light
      watch_entities:
        - sensor.front_door_battery
      ignore_entities:
        - sensor.uptime
        - sensor.cpu_usage
        - sensor.memory_usage
      cooldown_seconds: 30
تنظیمپیش‌فرضتوضیح
watch_domains—فقط این دامنه‌های موجودیت پایش شوند ‏(مثل climate، ‏light، ‏binary_sensor)
watch_entities—فقط این شناسه‌های موجودیت خاص پایش شوند
watch_allfalseبرای دریافت همهٔ تغییرات وضعیت ‏true کنید ‏(برای بیشتر راه‌اندازی‌ها توصیه نمی‌شود)
ignore_entities—این موجودیت‌ها همیشه نادیده گرفته شوند ‏(قبل از فیلترهای دامنه/موجودیت اعمال می‌شود)
cooldown_seconds30حداقل ثانیه بین رویدادهای یک موجودیت واحد
💡 نکته

با مجموعهٔ متمرکزی از دامنه‌ها شروع کنید — ‏climate، ‏binary_sensor و ‏alarm_control_panel مفیدترین اتوماسیون‌ها را پوشش می‌دهند. در صورت نیاز بیشترشان کنید. با ignore_entities سنسورهای پرسر‌وصدا مثل دمای CPU یا شمارندهٔ uptime را سرکوب کنید.

قالب‌بندی رویداد

تغییرات وضعیت بر اساس دامنه به پیام‌های خوانا قالب می‌گیرند:

دامنهقالب
climate«HVAC mode changed from 'off' to 'heat' (current: 21, target: 23)»
sensor«changed from 21°C to 22°C»
binary_sensor«triggered» / «cleared»
light، ‏switch، ‏fan«turned on» / «turned off»
alarm_control_panel«alarm state changed from 'armed_away' to 'triggered'»
(سایر)«changed from 'old' to 'new'»

پاسخ‌های ایجنت

پیام‌های خروجی ایجنت به‌صورت اعلان ماندگار Home Assistant تحویل می‌شوند ‏(از طریق ‏persistent_notification.create). این‌ها در پنل اعلان HA با عنوان «Hermes Agent» ظاهر می‌شوند.

مدیریت اتصال

  • WebSocket با ضربان ۳۰ثانیه‌ای برای رویدادهای لحظه‌ای
  • اتصال‌مجدد خودکار با backoff: ‏۵ ← ۱۰ ← ۳۰ ← ۶۰ ثانیه
  • REST API برای اعلان‌های خروجی ‏(نشست جداگانه برای جلوگیری از تعارض WebSocket)
  • مجوزدهی — رویدادهای HA همیشه مجازند ‏(لیست کاربر لازم ندارد چون ‏HASS_TOKEN اتصال را احراز می‌کند)

۴ امنیت

ابزارهای Home Assistant محدودیت‌های امنیتی اجرا می‌کنند:

⚠️ دامنه‌های مسدود

دامنه‌های سرویس زیر برای جلوگیری از اجرای کد دلخواه روی میزبان HA مسدودند:

  • ‏shell_command — فرمان‌های شل دلخواه
  • ‏command_line — سنسورها/کلیدهایی که فرمان اجرا می‌کنند
  • ‏python_script — اجرای اسکریپتی پایتون
  • ‏pyscript — یکپارچه‌سازی اسکریپت‌نویسی گسترده‌تر
  • ‏hassio — کنترل افزونه، خاموش/راه‌اندازی مجدد میزبان
  • ‏rest_command — درخواست‌های HTTP از سرور HA ‏(بردار SSRF)

تلاش برای فراخوانی سرویس در این دامنه‌ها خطا برمی‌گرداند.

شناسه‌های موجودیت با الگوی ‏^[a-z_][a-z0-9_]*\.[a-z0-9_]+$ اعتبارسنجی می‌شوند تا حملات تزریق پیشگیری شود.

۵ نمونه‌های اتوماسیون

روتین صبحگاهی

text
User: Start my morning routine

Agent:
1. ha_call_service(domain="light", service="turn_on",
     entity_id="light.bedroom", data={"brightness": 128})
2. ha_call_service(domain="climate", service="set_temperature",
     entity_id="climate.thermostat", data={"temperature": 22})
3. ha_call_service(domain="media_player", service="turn_on",
     entity_id="media_player.kitchen_speaker")

بررسی امنیت خانه

text
User: Is the house secure?

Agent:
1. ha_list_entities(domain="binary_sensor")
     → checks door/window sensors
2. ha_get_state(entity_id="alarm_control_panel.home")
     → checks alarm status
3. ha_list_entities(domain="lock")
     → checks lock states
4. Reports: "All doors closed, alarm is armed_away, all locks engaged."

اتوماسیون واکنشی ‏(از طریق رویدادهای گیت‌وی)

وقتی به‌عنوان پلتفرم گیت‌وی متصل باشد، ایجنت می‌تواند به رویدادها واکنش نشان دهد:

text
[Home Assistant] Front Door: triggered (was cleared)

Agent automatically:
1. ha_get_state(entity_id="binary_sensor.front_door")
2. ha_call_service(domain="light", service="turn_on",
     entity_id="light.hallway")
3. Sends notification: "Front door opened. Hallway lights turned on."

۶ عیب‌یابی

متغیرهای محیطی برداشته نمی‌شوند.
آداپتور اعتبارنامه‌ها را از ‏~/.hermes/.env ‏(هنگام شروع auto-merge) یا از config.yaml می‌خواند. چک کنید فایل زیر خانهٔ پروفایل فعال هرمس باشد و دور URL/توکن کوتیشن اضافی نباشد. بعد از ویرایش گیت‌وی را ری‌استارت کنید — تغییرات env فقط هنگام شروع پروسه اعمال می‌شوند.

احراز REST شکست می‌خورد ‏(401 Unauthorized).
توکن باید یک ‌Long-Lived Access Token ساخته‌شده از صفحهٔ پروفایل کاربری HA‌تان باشد ‏(Profile ← Security ← Long-lived access tokens). توکن‌های نشست کوتاه‌عمرِ UI کار نمی‌کنند. همچنین تأیید کنید URL پایه scheme و پورت دارد ‏(مثل ‏http://homeassistant.local:8123) و از میزبانی که هرمس را اجرا می‌کند قابل‌رسید است — دستور زیر باید ‏{"message": "API running."} برگرداند:

bash
curl -H "Authorization: Bearer <token>" <url>/api/
→ قبلیMatrix بعدی ←Raft
