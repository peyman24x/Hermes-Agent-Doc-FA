جلسات Microsoft Teams

وقتی می‌خواهید هرمس رویدادهای جلسهٔ Microsoft Graph را دریافت کند، اول رونویسی‌ها را بگیرد، در صورت نیاز به دانلود ضبط به‌اضافهٔ STT برگردد و خلاصهٔ ساختاریافته را به مقصدهای پایین‌دستی تحویل دهد، از خط‌لولهٔ جلسات Teams استفاده کنید.

پیش‌نیازها: راه‌اندازی پایهٔ بات/اعتبارنامه را در ‏Microsoft Teams ببینید.

hermes gateway setup را اجرا و Teams Meetings را انتخاب کنید تا راهنمای گام‌به‌گام ببینید.

این صفحه روی setup و فعال‌سازی تمرکز دارد:

  • اعتبارنامه‌های Graph
  • پیکربندی شنوندهٔ وب‌هوک
  • حالت‌های تحویل Teams
  • شکل پیکربندی خط‌لوله

برای عملیات روز-دوم، چک‌های go-live و کاربرگ اپراتور از راهنمای اختصاصی استفاده کنید: ‏ادارهٔ خط‌لولهٔ جلسات Teams.

۱ این قابلیت چه می‌کند

خط‌لوله:

  1. رویدادهای وب‌هوک Microsoft Graph را دریافت می‌کند
  2. جلسه را حل و اول آرتیفکت‌های رونویسی را ترجیح می‌دهد
  3. وقتی رونویسی قابل‌استفاده نیست به دانلود ضبط + STT برمی‌گردد
  4. وضعیت ماندگار job ها و رکوردهای sink را محلی ذخیره می‌کند
  5. می‌تواند خلاصه‌ها را در Notion، Linear و Microsoft Teams بنویسد

اکشن‌های اپراتوری در CLI می‌مانند ‏(زیرفرمان ‏teams-pipeline توسط افزونهٔ ‏teams_pipeline ثبت می‌شود — با ‏hermes plugins enable teams_pipeline یا ‏plugins.enabled: [teams_pipeline] در config.yaml فعالش کنید):

bash
hermes teams-pipeline validate
hermes teams-pipeline list
hermes teams-pipeline maintain-subscriptions

۲ پیش‌نیازها

قبل از فعال‌کردن خط‌لوله جلسات مطمئن شوید:

  • نصب کاری از هرمس دارید
  • راه‌اندازی موجود بات Microsoft Teams را دارید اگر تحویل خروجی Teams می‌خواهید
  • اعتبارنامه‌های اپلیکیشن Microsoft Graph با دسترسی‌های لازم برای منابع جلسه‌ای که قصد اشتراک دارید
  • URL عمومی HTTPS که Microsoft Graph بتواند برای تحویل وب‌هوک صدا بزند
  • ‏ffmpeg نصب است اگر fallback ضبط+STT می‌خواهید

۳ گام ۱: افزودن اعتبارنامه‌های Microsoft Graph

اعتبارنامه‌های فقط-اپ Graph را به ‏~/.hermes/.env بیفزایید:

bash
MSGRAPH_TENANT_ID=<tenant-id>
MSGRAPH_CLIENT_ID=<client-id>
MSGRAPH_CLIENT_SECRET=<client-secret>

این اعتبارنامه‌ها استفاده می‌شوند توسط:

  • زیربنای کلاینت Graph
  • فرمان‌های نگهداشت اشتراک
  • حل جلسه و گرفتن آرتیفکت‌ها
  • تحویل خروجی Teams مبتنی بر Graph وقتی توکن دسترسی Teams اختصاصی نمی‌دهید

۴ گام ۲: فعال‌سازی شنوندهٔ وب‌هوک Graph

شنوندهٔ وب‌هوک یک پلتفرم گیت‌وی به نام ‏msgraph_webhook است. حداقل آن را فعال و مقدار client state بگذارید:

bash
MSGRAPH_WEBHOOK_ENABLED=true
MSGRAPH_WEBHOOK_PORT=8646
MSGRAPH_WEBHOOK_CLIENT_STATE=<random-shared-secret>
MSGRAPH_WEBHOOK_ACCEPTED_RESOURCES=communications/onlineMeetings

میزبان bind از ‏extra.host پلتفرم در config.yaml خوانده می‌شود ‏(متغیر env ‏MSGRAPH_WEBHOOK_HOST وجود ندارد — مرجع شنوندهٔ وب‌هوک را ببینید).

شنونده expose می‌کند:

  • ‏/msgraph/webhook برای اعلان‌های Graph
  • ‏/health برای چک سلامت ساده

باید endpoint عمومی HTTPS خود را به این شنونده مسیریابی کنید. مثلاً اگر دامنهٔ عمومی شما ‏https://ops.example.com باشد URL اعلان Graph شما معمولاً:

https://ops.example.com/msgraph/webhook

۵ گام ۳: پیکربندی تحویل Teams و رفتار خط‌لوله

خط‌لوله جلسات پیکربندی runtime‌اش را از ورودی موجود پلتفرم teams می‌خواند. تنظیمات خاص-خط‌لوله زیر ‏teams.extra.meeting_pipeline زندگی می‌کنند. تحویل خروجی Teams روی همان سطح پیکربندی عادی پلتفرم Teams می‌ماند.

مثال config.yaml:

yaml
platforms:
  msgraph_webhook:
    enabled: true
    extra:
      host: 127.0.0.1
      port: 8646
      client_state: "replace-me"
      accepted_resources:
        - "communications/onlineMeetings"

  teams:
    enabled: true
    extra:
      client_id: "your-teams-client-id"
      client_secret: "your-teams-client-secret"
      tenant_id: "your-teams-tenant-id"

      # تحویل خلاصهٔ خروجی
      delivery_mode: "graph" # یا incoming_webhook
      team_id: "team-id"
      channel_id: "channel-id"
      # incoming_webhook_url: "https://..."

      meeting_pipeline:
        transcript_min_chars: 80
        transcript_required: false
        transcription_fallback: true
        ffmpeg_extract_audio: true
        notion:
          enabled: false
        linear:
          enabled: false

اگر شنونده را به میزبانی غیر-loopback مثل ‏0.0.0.0 بایند کردید باید ‏allowed_source_cidrs را هم روی بازه‌های egress وب‌هوک مایکروسافت بگذارید. bind های loopback ‏(127.0.0.1/::1) همان setup مقصدیِ تونل توسعه و پروکسی معکوس محلی هستند.

حالت‌های تحویل Teams

خط‌لوله دو حالت تحویل خلاصهٔ Teams داخل افزونهٔ موجود Teams دارد.

incoming_webhook

وقتی یک پست وب‌هوکی ساده در Teams می‌خواهید بدون ساخت پیام کانال از طریق Graph.

پیکربندی لازم:

yaml
platforms:
  teams:
    enabled: true
    extra:
      delivery_mode: "incoming_webhook"
      incoming_webhook_url: "https://..."

graph

وقتی می‌خواهید هرمس خلاصه را از طریق Microsoft Graph داخل یک چت یا کانال Teams پست کند.

هدف‌های پشتیبانی‌شده:

  • ‏chat_id
  • ‏team_id + ‏channel_id
  • ‏team_id + fallback ‏home_channel پلتفرم موجود Teams
yaml
platforms:
  teams:
    enabled: true
    extra:
      delivery_mode: "graph"
      team_id: "team-id"
      channel_id: "channel-id"

۶ گام ۴: شروع گیت‌وی

بعد از به‌روزرسانی پیکربندی هرمس را عادی شروع کنید:

hermes gateway run

یا اگر هرمس را در Docker اجرا می‌کنید گیت‌وی را همان‌طور که برای استقرارتان انجام می‌دهید شروع کنید.

شنونده را چک کنید:

curl http://localhost:8646/health

۷ گام ۵: ساخت اشتراک‌های Graph

برای ساخت و بازرسی اشتراک‌ها از CLI افزونه استفاده کنید.

مثال‌ها:

bash
hermes teams-pipeline subscribe \
  --resource communications/onlineMeetings/getAllTranscripts \
  --notification-url https://ops.example.com/msgraph/webhook \
  --client-state "$MSGRAPH_WEBHOOK_CLIENT_STATE"

hermes teams-pipeline subscribe \
  --resource communications/onlineMeetings/getAllRecordings \
  --notification-url https://ops.example.com/msgraph/webhook \
  --client-state "$MSGRAPH_WEBHOOK_CLIENT_STATE"
⚠️ اشتراک‌های Graph ظرف ۷۲ ساعت منقضی می‌شوند

‏Microsoft Graph اشتراک‌های وب‌هوک را روی ۷۲ ساعت سقف می‌زند و خودکار تمدیدشان نمی‌کند. قبل از go-live باید زمان‌بندی ‏hermes teams-pipeline maintain-subscriptions را راه بیندازید وگرنه اعلان‌ها سه روز بعد از هر ساخت دستی اشتراک بی‌صدا متوقف می‌شوند. بخش «خودکارسازی تمدید اشتراک» ‏(الزامی برای تولید) را در کتاب عملیات اپراتور ببینید — سه گزینه ‏(کرون هرمس، timer سیستم‌دی، crontab خام).

برای نگهداشت اشتراک و جریان‌های اپراتوری روز-دوم با راهنما ادامه دهید: ‏ادارهٔ خط‌لولهٔ جلسات Teams.

۸ اعتبارسنجی

اسنپ‌شات اعتبارسنجی داخلی را اجرا کنید:

hermes teams-pipeline validate

چک‌های همراه مفید:

hermes teams-pipeline token-health
hermes teams-pipeline subscriptions

۹ عیب‌یابی

مشکلچه چیزی را چک کنیم
اعتبارسنجی وب‌هوک Graph شکست می‌خورددرستی و قابل‌دسترس بودن URL عمومی را تأیید و مطمئن شوید Graph دقیقاً مسیر ‏/msgraph/webhook را صدا می‌زند
job ها در ‏hermes teams-pipeline list ظاهر نمی‌شوندتأیید کنید ‏msgraph_webhook فعال است و اشتراک‌ها به URL اعلان درست اشاره دارند
اولویت-رونویسی هرگز موفق نمی‌شوددسترسی‌های Graph برای منابع رونویسی و موجود بودن آرتیفکت رونویسی برای آن جلسه را چک کنید
fallback ضبط شکست می‌خوردنصب بودن ‏ffmpeg و دسترسی اپ Graph به آرتیفکت‌های ضبط را تأیید کنید
تحویل خلاصهٔ Teams شکست می‌خورد‏delivery_mode، شناسه‌های هدف و پیکربندی احراز Teams را دوباره چک کنید
