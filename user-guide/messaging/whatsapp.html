خانه/پیام‌رسان‌ها/واتساپ

راه‌اندازی واتساپ

هرمس از طریق یک پل داخلی مبتنی بر Baileys به واتساپ وصل می‌شود. این پل با شبیه‌سازی یک نشست WhatsApp Web کار می‌کند — نه از طریق API رسمی WhatsApp Business. نه حساب توسعه‌دهندهٔ Meta لازم است نه احراز Business.

hermes gateway setup را اجرا کنید و WhatsApp را انتخاب کنید تا راهنمای گام‌به‌گام را ببینید.

💡 دو یکپارچه‌سازی واتساپ

این صفحه برای پل Baileys است — راه‌اندازی سریع، حساب‌های شخصی، بدون نیاز به URL عمومی، با ریسک مسدودی.

اگر یک بات تجاری واقعی دارید و ثبات می‌خواهید، به‌جایش راهنمای WhatsApp Business Cloud API را ببینید. مسیر رسمیِ پشتیبانی‌شده توسط Meta است: بدون ریسک مسدودی حساب، ولی حساب Meta Business و URL وب‌هوک عمومی می‌خواهد.

دو آداپتور در صورت نیاز می‌توانند روی شماره‌های تلفن مختلف موازی هم اجرا شوند.

⚠️ API غیررسمی — ریسک مسدودی

واتساپ بات‌های شخص ثالث را خارج از Business API به‌طور رسمی پشتیبانی نمی‌کند. استفاده از پل شخص ثالث ریسک کوچکی از محدودشدن حساب دارد. برای کمینه‌کردن ریسک:

  • برای بات یک شماره تلفن اختصاصی استفاده کنید ‏(نه شماره شخصی‌تان)
  • پیام انبوه/اسپم نفرستید — مصرف را گفتگویی نگه دارید
  • ارسال خودکار پیام به افرادی که قبلاً پیام نداده‌اند راه نیندازید
⚠️ به‌روزرسانی‌های پروتکل WhatsApp Web

واتساپ هر از گاهی پروتکل Web خود را به‌روز می‌کند که می‌تواند موقتاً سازگاری پل‌های شخص ثالث را بشکند. در این موارد هرمس وابستگی پل را به‌روز می‌کند. اگر بات بعد از یک به‌روزرسانی واتساپ از کار افتاد، آخرین نسخهٔ هرمس را بگیرید و دوباره جفت‌سازی (pair) کنید.

۲ پیش‌نیازها

  • ‏Node.js نسخهٔ ۱۸+ و npm — پل واتساپ به‌صورت پروسهٔ Node.js اجرا می‌شود
  • یک گوشی با واتساپ نصب‌شده ‏(برای اسکن کد QR)

برخلاف پل‌های قدیمی مبتنی بر مرورگر، پل فعلی مبتنی بر Baileys به پشتهٔ وابستگی Chromium یا Puppeteer محلی نیاز ندارد.

۳ گام ۱: اجرای ویزارد راه‌اندازی

bash
hermes whatsapp

ویزارد این کارها را می‌کند:

  1. حالت موردنظر را می‌پرسد ‏(bot یا self-chat)
  2. در صورت نیاز وابستگی‌های پل را نصب می‌کند
  3. یک کد QR در ترمینال نمایش می‌دهد
  4. منتظر اسکن شما می‌ماند

برای اسکن کد QR:

  1. واتساپ را روی گوشی باز کنید
  2. به Settings ← Linked Devices بروید
  3. Link a Device را بزنید
  4. دوربین را به سمت کد QR ترمینال بگیرید

پس از جفت‌شدن، ویزارد اتصال را تأیید و خارج می‌شود. نشست شما خودکار ذخیره می‌شود.

💡 نکته

اگر کد QR به‌هم‌ریخته به نظر رسید، مطمئن شوید ترمینال دست‌کم ۶۰ ستون عرض دارد و یونیکد را پشتیبانی می‌کند. همچنین می‌توانید یک شبیه‌ساز ترمینال دیگر امتحان کنید.

۴ گام ۲: گرفتن شماره تلفن دوم ‏(حالت بات)

برای حالت بات به شماره‌ای نیاز دارید که قبلاً با واتساپ ثبت نشده باشد. سه گزینه:

گزینههزینهیادداشت‌ها
Google Voiceرایگانفقط آمریکا. در voice.google.com شماره بگیرید. واتساپ را از طریق SMS داخل اپ Google Voice تأیید کنید.
سیم‌کارت اعتباری۵–۱۵ دلار یک‌بارهر اپراتوری. فعال کنید، واتساپ را تأیید کنید، بعد سیم می‌تواند در کشو بماند. شماره باید فعال بماند ‏(هر ۹۰ روز یک تماس).
سرویس‌های VoIPرایگان–۵ دلار/ماه‏TextNow، ‏TextFree یا مشابه. بعضی شماره‌های VoIP توسط واتساپ مسدود شده‌اند — اگر اولی جواب نداد چندتا امتحان کنید.

بعد از گرفتن شماره:

  1. واتساپ را روی یک گوشی نصب کنید ‏(یا اپ WhatsApp Business با دو سیم‌کارت)
  2. شماره جدید را با واتساپ ثبت کنید
  3. ‏hermes whatsapp را اجرا و کد QR آن حساب واتساپ را اسکن کنید

۵ گام ۳: پیکربندی هرمس

این‌ها را به فایل ~/.hermes/.env اضافه کنید:

bash
# الزامی
WHATSAPP_ENABLED=true
WHATSAPP_MODE=bot                          # "bot" یا "self-chat"

# کنترل دسترسی — یکی از این گزینه‌ها:
WHATSAPP_ALLOWED_USERS=15551234567         # شماره‌ها جدا با ویرگول (با کد کشور، بدون +)
# WHATSAPP_ALLOWED_USERS=*                 # یا با * همه مجاز شوند
# WHATSAPP_ALLOW_ALL_USERS=true            # یا این فلگ را بگذارید (همان اثر *)
💡 میان‌بر allow-all

گذاشتن WHATSAPP_ALLOWED_USERS=* همهٔ فرستندگان را مجاز می‌کند ‏(معادل WHATSAPP_ALLOW_ALL_USERS=true). با لیست‌مجاز گروه سیگنال هم‌خوان است. برای استفاده از جریان جفت‌سازی به‌جایش، هر دو متغیر را حذف و به سیستم جفت‌سازی DM اتکا کنید.

تنظیمات رفتاری اختیاری در ~/.hermes/config.yaml:

yaml
unauthorized_dm_behavior: pair

whatsapp:
  unauthorized_dm_behavior: ignore
  • ‏unauthorized_dm_behavior: pair پیش‌فرض سراسری است. فرستندگان ناشناس DM کد جفت‌سازی می‌گیرند.
  • ‏whatsapp.unauthorized_dm_behavior: ignore باعث می‌شود واتساپ برای DM های غیرمجاز ساکت بماند — معمولاً انتخاب بهتر برای شمارهٔ خصوصی.

سپس گیت‌وی را شروع کنید:

bash
hermes gateway              # پیش‌زمینه
hermes gateway install      # نصب به‌عنوان سرویس کاربر
sudo hermes gateway install --system   # فقط لینوکس: سرویس سیستمی زمان‌بوت

گیت‌وی پل واتساپ را با نشست ذخیره‌شده خودکار شروع می‌کند.

۶ ماندگاری نشست

پل Baileys نشستش را زیر ~/.hermes/platforms/whatsapp/session ذخیره می‌کند. یعنی:

  • نشست‌ها از ری‌استارت جان سالم می‌برند — لازم نیست هر بار کد QR را دوباره اسکن کنید
  • دادهٔ نشست شامل کلیدهای رمزنگاری و اعتبارنامه‌های دستگاه است
  • این پوشهٔ نشست را به اشتراک نگذارید یا کامیت نکنید — دسترسی کامل به حساب واتساپ می‌دهد

۷ جفت‌سازی مجدد

اگر نشست بشکند ‏(ریست گوشی، به‌روزرسانی واتساپ، unlink دستی)، خطاهای اتصال در لاگ‌های گیت‌وی می‌بینید. برای رفع:

bash
hermes whatsapp

این فرمان کد QR تازه تولید می‌کند. دوباره اسکن کنید تا نشست برقرار شود. گیت‌وی قطعی‌های موقتی ‏(لغزش شبکه، آفلاین‌شدن لحظه‌ای گوشی) را خودکار با منطق اتصال‌مجدد هندل می‌کند.

۸ پیام‌های صوتی

هرمس صدا را روی واتساپ پشتیبانی می‌کند:

  • ورودی: پیام‌های صوتی ‏(.ogg opus) خودکار با ارائه‌دهندهٔ STT پیکربندی‌شده رونویسی می‌شوند: ‏faster-whisper محلی، ‏Groq Whisper ‏(GROQ_API_KEY) یا OpenAI Whisper ‏(VOICE_TOOLS_OPENAI_KEY)
  • خروجی: پاسخ‌های TTS به‌صورت پیوست فایل صوتی MP3 فرستاده می‌شوند
  • پاسخ‌های ایجنت به‌طور پیش‌فرض با پیشوند «⚕ **Hermes Agent**» می‌آیند. می‌توانید در config.yaml سفارشی یا خاموشش کنید:
yaml — ~/.hermes/config.yaml
whatsapp:
  reply_prefix: ""                          # رشتهٔ خالی هدر را خاموش می‌کند
  # reply_prefix: "🤖 *My Bot*\n──────\n"  # پیشوند سفارشی (\n برای خط جدید)
  send_read_receipts: false                 # علامت‌گذاری پیام‌های ورودی پذیرفته‌شده به‌عنوان خوانده‌شده (تیک آبی)

وقتی send_read_receipts برابر true باشد، آداپتور پیام‌های ورودیِ پذیرفته‌شده توسط سیاست را پس از عبور از فیلترهای DM/گروه/منشن خوانده‌شده علامت می‌زند. پیام‌های ردشده ‏(مثلاً از فرستندگان خارج از لیست مجاز) خوانده‌شده علامت نمی‌خورند. برای حریم خصوصی به‌طور پیش‌فرض خاموش است. تغییر این تنظیم، زیرپروسهٔ پل را در اتصال بعدی خودکار ری‌استارت می‌کند.

۹ قالب‌بندی و تحویل پیام

واتساپ از پاسخ‌های استریم ‏(تدریجی) پشتیبانی می‌کند — بات پیامش را هم‌زمان با تولید متن AI در لحظه ویرایش می‌کند، مثل دیسکورد و تلگرام. در درون، واتساپ از نظر قابلیت‌های تحویل پلتفرمی از نوع TIER_MEDIUM طبقه‌بندی می‌شود.

تکه‌تکه‌کردن (Chunking)

پاسخ‌های بلند خودکار در ۴٬۰۹۶ کاراکتر به‌ازای هر تکه به چند پیام تقسیم می‌شوند ‏(حد عملی نمایش واتساپ). نیازی به پیکربندی نیست — گیت‌وی تقسیم را هندل و تکه‌ها را متوالی می‌فرستد.

مارک‌داون سازگار با واتساپ

مارک‌داون استاندارد در پاسخ‌های AI خودکار به قالب‌بندی بومی واتساپ تبدیل می‌شود:

مارک‌داونواتساپرندر
**bold***bold*ضخیم
~~strikethrough~~~strikethrough~خط‌خورده
# Heading*Heading*متن ضخیم ‏(تیتر بومی ندارد)
[link text](url)link text (url)URL درون‌خطی

بلوک‌های کد و کد درون‌خطی عیناً حفظ می‌شوند چون واتساپ قالب‌بندی triple-backtick را به‌صورت بومی پشتیبانی می‌کند.

پیشرفت ابزار

وقتی ایجنت ابزار صدا می‌زند ‏(جست‌وجوی وب، عملیات فایل و...)، واتساپ نشانگرهای پیشرفت زنده نشان می‌دهد که کدام ابزار در حال اجراست. پیش‌فرض فعال است — پیکربندی نمی‌خواهد.

نظرسنجی بومی، clarify به‌صورت نظرسنجی و موقعیت مکانی

آداپتور پل Baileys ‏(حالت بات) چند نوع پیام بومی واتساپ را پشتیبانی می‌کند:

  • نظرسنجی‌ها — ایجنت می‌تواند از طریق نقطهٔ پایانی /send-poll پل، یک نظرسنجی بومی واتساپ بفرستد ‏(پرسش + گزینه‌ها). رأی‌های نظرسنجی به گفتگو برمی‌گردند.
  • پرسش‌های clarify به‌صورت نظرسنجی — وقتی ایجنت پرسش clarify چندگزینه‌ای می‌پرسد، به‌صورت نظرسنجی بومی تک‌انتخابی رندر می‌شود؛ لمس یک گزینه پاسخ پرسش است. اگر ارسال نظرسنجی شکست بخورد، آداپتور به پرسش متنی ساده سقوط می‌کند. پرامپت‌های تأیید هرگز به نظرسنجی نگاشت نمی‌شوند — نظرسنجی فقط برای clarify های واقعاً چندگزینه‌ای است.
  • پین موقعیت مکانی — ایجنت می‌تواند از طریق /send-location پین بومی موقعیت بفرستد ‏(عرض/طول جغرافیایی، نام/نشانی اختیاری)، و موقعیت‌های اشتراک‌گذاری‌شدهٔ ورودی ‏(شامل موقعیت زنده) به‌عنوان پیام موقعیت به ایجنت می‌رسند.

همهٔ این‌ها در حالت بات ‏(Baileys) از جعبه کار می‌کنند؛ پیکربندی لازم نیست.

دسته‌بندی پیام (Debounce)

واتساپ هر پیام را جدا تحویل می‌دهد، پس رگبار سریع ‏(بچ‌های فورواردشده، چسباندن‌های چندتکه، متن چندخطی) بدون آن به‌ازای هر قطعه یک فراخوانی جداگانهٔ ایجنت راه می‌انداخت — هدر دادن توکن و تولید چند پاسخ ناهم‌پیوسته. آداپتور پیام‌های متنی متوالی از یک چت را بافر و بعد از یک دورهٔ کوتاه سکوت ‏(پیش‌فرض ۵ ثانیه، برای قطعات خیلی بلند ۱۰ ثانیه) به‌عنوان یک درخواست ترکیبی dispatch می‌کند. تنظیم از طریق config.yaml:

yaml — ~/.hermes/config.yaml
gateway:
  platforms:
    whatsapp:
      extra:
        text_batch_delay_seconds: 5.0         # دورهٔ سکوت قبل از flush دسته
        text_batch_split_delay_seconds: 10.0  # تأخیر طولانی‌شده نزدیک آستانهٔ تقسیم

برای ارسال فوری هر پیام ‏(غیرفعال‌کردن دسته‌بندی) ‏text_batch_delay_seconds: 0 بگذارید.

۱۰ عیب‌یابی

مشکلراه‌حل
کد QR اسکن نمی‌شودترمینال به اندازهٔ کافی پهن باشد ‏(۶۰+ ستون). ترمینال دیگری امتحان کنید. مطمئن شوید از حساب واتساپ درست اسکن می‌کنید ‏(شمارهٔ بات، نه شخصی).
کد QR منقضی می‌شودکدهای QR هر ~۲۰ ثانیه refresh می‌شوند. اگر timeout شد، hermes whatsapp را دوباره اجرا کنید.
نشست ماندگار نمی‌شودچک کنید ~/.hermes/platforms/whatsapp/session وجود دارد و نوشتنی است. اگر کانتینری است، به‌عنوان والوم ماندگار مانت کنید.
خروج غیرمنتظره از حسابواتساپ دستگاه‌ها را پس از بی‌فعالیتی طولانی unlink می‌کند. گوشی روشن و متصل بماند؛ در صورت نیاز با hermes whatsapp دوباره جفت کنید.
کرش پل یا حلقهٔ اتصال‌مجددگیت‌وی را ری‌استارت کنید، هرمس را به‌روز کنید، و اگر نشست توسط تغییر پروتکل واتساپ بی‌اعتبار شد دوباره جفت کنید.
بات بعد از به‌روزرسانی واتساپ از کار افتادهرمس را برای آخرین نسخهٔ پل به‌روز کنید، سپس دوباره جفت کنید.
‏macOS: «Node.js نصب نیست» ولی node در ترمینال کار می‌کندسرویس‌های launchd مسیر PATH شل شما را ارث نمی‌برند. ‏hermes gateway install را اجرا کنید تا PATH فعلی دوباره در plist snapshot شود، سپس hermes gateway start. جزئیات در مستندات سرویس گیت‌وی.
پیام‌ها دریافت نمی‌شوندتأیید کنید WHATSAPP_ALLOWED_USERS شمارهٔ فرستنده را دارد ‏(با کد کشور، بدون + و فاصله) یا آن را * کنید. ‏WHATSAPP_DEBUG=true را در .env بگذارید و گیت‌وی را ری‌استارت کنید تا رویدادهای خام پیام در bridge.log دیده شوند.
بات به غریبه‌ها با کد جفت‌سازی جواب می‌دهداگر می‌خواهید DM های غیرمجاز بی‌صدا نادیده گرفته شوند، ‏whatsapp.unauthorized_dm_behavior: ignore را در ~/.hermes/config.yaml بگذارید.

۱۱ امنیت

⚠️ هشدار

قبل از رفتن روی خط، کنترل دسترسی را پیکربندی کنید. ‏WHATSAPP_ALLOWED_USERS را با شماره‌های مشخص ‏(با کد کشور، بدون +) تنظیم کنید، با * همه را مجاز کنید، یا ‏WHATSAPP_ALLOW_ALL_USERS=true بگذارید. بدون هیچ‌کدام، گیت‌وی به‌عنوان اقدام ایمنی همهٔ پیام‌های ورودی را رد می‌کند.

به‌طور پیش‌فرض DM های غیرمجاز همچنان کد جفت‌سازی می‌گیرند. اگر می‌خواهید شمارهٔ خصوصی واتساپ نسبت به غریبه‌ها کاملاً ساکت بماند:

yaml
whatsapp:
  unauthorized_dm_behavior: ignore
  • پوشهٔ ~/.hermes/platforms/whatsapp/session اعتبارنامهٔ کامل نشست را دارد — مثل رمز عبور ازش محافظت کنید
  • دسترسی فایل: ‏chmod 700 ~/.hermes/platforms/whatsapp/session
