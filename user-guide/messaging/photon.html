‏Photon iMessage

هرمس را از طریق Photon به ‏iMessage وصل کنید — سرویس مدیریتی که تخصیص خط اپل و لایهٔ پیشگیری از سوءاستفاده را هندل می‌کند تا مجبور نباشید رلهٔ مک خودتان را اجرا کنید.

سطح رایگان از استخر خط اشتراکی iMessage فوتون استفاده می‌کند — گیرنده‌های مختلف ممکن است شماره‌های ارسال مختلفی ببینند، ولی هر گفتگو پایدار می‌ماند. سطح تجاریِ پرداختی به هر کاربر همان شمارهٔ اختصاصی را می‌دهد؛ افزونه هر دو را پشتیبانی می‌کند و سطح رایگان نقطهٔ شروع توصیه‌شده است.

📌 شروع رایگان

استخر خط اشتراکی فوتون رایگان است. برای فرستادن اولین iMessage از هرمس اشتراک لازم نیست — فقط شماره تلفنی که بتوانیم به حسابتان قفل کنیم.

۱ معماری

‏فوتون یک کانال اتصال-دائمی است مثل دیسکورد یا اسلک — بدون وب‌هوک، بدون URL عمومی، بدون رمز امضا برای مدیریت.

‏SDK ‏spectrum-ts یک جریان gRPC طولانی‌عمر به فوتون برای هر دو جهت نگه می‌دارد. چون SDK فقط TypeScript است، هرمس آن را در یک Node sidecar کوچکِ تحت-نظارت اجرا و از طریق loopback با حرف می‌زند:

  • ورودی — sidecar جریان gRPC ‏app.messages SDK را مصرف و هر پیام را روی loopback ‏(GET /inbound با NDJSON) به آداپتور پایتونی فوروارد می‌کند. آداپتور حذف تکرار و dispatch به ایجنت می‌کند و در قطع جریان خودکار reconnect می‌شود.
  • خروجی — ریپلای‌ها POST های loopback به sidecar هستند که روی SDK ‏space.send(...) صدا می‌زند.

افزونهٔ پایتونی sidecar را خودکار شروع، نظارت و خاموش می‌کند.

۲ پیش‌نیازها

  • حساب فوتون — ثبت‌نام در ‏app.photon.codes
  • ‏Node.js نسخهٔ ۱۸.۱۷ یا جدیدتر روی PATH ‏(node --version)
  • شماره تلفنی که بتواند iMessage دریافت کند ‏(برای قفل حسابتان استفاده می‌شود)

همین — هیچ URL عمومی یا تونلی برای راه‌اندازی نیست.

۳ راه‌اندازی اولیه

یا ویزارد واحد گیت‌وی را اجرا و Photon iMessage را انتخاب کنید:

hermes gateway setup

…یا setup فوتون را مستقیم اجرا کنید ‏(ویزارد همین جریان را صدا می‌زند):

bash
# ورود device-code + پروژه + کاربر + وابستگی‌های sidecar، همه در یک
hermes photon setup --phone +15551234567

راه‌اندازی به ترتیب:

  1. ورود دستگاهی ‏(client_id=photon-cli) — ‏https://app.photon.codes/ را برای تأیید باز و bearer token ذخیره می‌کند.
  2. پروژهٔ ‏Hermes Agent را روی حسابتان پیدا یا می‌سازد.
  3. Spectrum را فعال، شناسهٔ Spectrum پروژه را می‌خواند و رمز پروژه را می‌چرخاند.
  4. شماره تلفن شما را به‌عنوان کاربر Spectrum ثبت می‌کند — اگر کاربری با آن شماره موجود باشد رد می‌شود، پس اجرای مجدد امن است.
  5. خط iMessage تخصیصی‌تان را چاپ می‌کند — شماره‌ای که برای رسیدن به ایجنت بهش پیام می‌دهید.
  6. ‏npm install را داخل دایرکتوری sidecar افزونه اجرا می‌کند. روی درخت‌های نصب فقط-خواندنی ‏(ایمیج‌های Docker میزبانی‌شده، ‏Podman، ‏Nix) sidecar خودکار به آینهٔ نوشتنی زیر ‏~/.hermes/photon/sidecar برمی‌گردد؛ ‏PHOTON_SIDECAR_DIR را بگذارید تا مکان صریح قفل شود.

اعتبارنامه‌های runtime در ‏~/.hermes/.env نوشته می‌شوند ‏(PHOTON_PROJECT_ID = شناسهٔ پروژهٔ Spectrum، ‏PHOTON_PROJECT_SECRET) — همان جایی که همهٔ کانال‌های دیگر توکنشان را نگه می‌دارند. متادیتای مدیریتی ‏(توکن دستگاه، شناسهٔ پروژهٔ داشبورد) در ‏~/.hermes/auth.json زیر ‏credential_pool.photon / ‏credential_pool.photon_project زندگی می‌کند.

۴ مجوز کاربران

‏Photon همان مدل مجوز سایر کانال‌های هرمس را دارد. یکی از این‌ها:

جفت‌سازی DM ‏(پیش‌فرض). وقتی شمارهٔ ناشناسی به خط فوتون شما پیام دهد، هرمس کد جفت‌سازی جواب می‌دهد. تأیید کنید:

hermes pairing approve photon <CODE>

با ‏hermes pairing list کدهای در انتظار و کاربران تأییدشده را ببینید.

پیش-مجوز شماره‌های خاص ‏(در ‏~/.hermes/.env):

PHOTON_ALLOWED_USERS=+15551234567,+15559876543

دسترسی باز ‏(فقط توسعه، در ‏~/.hermes/.env):

PHOTON_ALLOW_ALL_USERS=true

وقتی ‏PHOTON_ALLOWED_USERS تنظیم باشد، فرستندگان ناشناخته بی‌صدا نادیده گرفته می‌شوند نه اینکه کد جفت‌سازی بگیرند ‏(لیست مجاز علامت می‌دهد که عمداً دسترسی را محدود کرده‌اید).

منشن اجباری در چت‌های گروهی

به‌طور پیش‌فرض هرمس به همهٔ DM ها و پیام‌های گروهی مجاز پاسخ می‌دهد. برای انتخابی‌کردن چت گروهی گیت منشن را فعال کنید ‏(DM ها همچنان همیشه کار می‌کنند):

yaml
gateway:
  platforms:
    photon:
      enabled: true
      require_mention: true

با ‏require_mention: true پیام‌های چت گروهی مگر الگوی واژه-بیداری بخوانند نادیده گرفته می‌شوند. پیش‌فرض‌ها واریانت‌های «Hermes» و «‎@Hermes agent» را می‌گیرند. برای نام سفارشی الگوهای regex بگذارید:

yaml
gateway:
  platforms:
    photon:
      require_mention: true
      mention_patterns:
        - '(?<![\w@])@?amos\b[,:\-]?'

هر دو کلید env هم می‌پذیرند ‏(PHOTON_REQUIRE_MENTION، ‏PHOTON_MENTION_PATTERNS). همین مدل gating منشن کانال BlueBubbles/iMessage است.

۵ شروع گیت‌وی

hermes gateway start

چیزی شبیه این می‌بینید:

[photon] connected — sidecar on 127.0.0.1:8789, streaming inbound over gRPC

به شمارهٔ تخصیص‌شده‌تان iMessage بدهید و هرمس جواب می‌دهد.

۶ وضعیت و عیب‌یابی

hermes photon status

اعتبارنامه‌های ذخیره‌شده، سلامت sidecar، شمارهٔ ثبتی و خط iMessage تخصیصی‌ای که هرمس استفاده می‌کند را چاپ می‌کند. وقتی توکن فوتون و پروژهٔ داشبورد موجود باشند، ‏status ردیف‌های شمارهٔ گمشده را از داشبورد بدون provision خط جدید refresh می‌کند.

text
Photon iMessage status
──────────────────────
  device token        : ✓ stored
  dashboard project   : 3c90c3cc-0d44-4b50-...
  spectrum project id : sp-...
  project secret      : ✓ stored
  my number           : +15551234567
  assigned number     : +16282679185
  node binary         : /usr/bin/node
  sidecar deps        : ✓ installed

مشکلات رایج:

  • ‏sidecar deps : ✗ run hermes photon install-sidecar — Node نصب است ولی ‏spectrum-ts نیست. فرمان پیشنهادی را اجرا کنید.
  • ‏device token : ✗ missing — ‏hermes photon setup را برای ورود اجرا کنید.
  • ‏No iMessage line assigned yet — Spectrum فعال شده ولی هنوز خطی provision نشده؛ ‏hermes photon setup را دوباره اجرا یا داشبورد را چک کنید.
  • sidecar شروع نمی‌شود — تأیید کنید ‏node --version نسخهٔ ۱۸.۱۷+ است و ‏hermes photon install-sidecar بدون خطا تمام شده.

۷ محدودیت‌های فعلی

  • پیوست‌های ورودی فقط-متادیتا هستند. رویدادهای ورودی نام فایل + MIME حمل می‌کنند؛ ایجنت نشانگر می‌بیند ولی هنوز نمی‌تواند بایت‌ها را بخواند. ‏SDK بایت پیوست‌ها را با ‏content.read() expose می‌کند، پس این یک کار پیگیری sidecar است.
  • پیوست‌های خروجی پشتیبانی می‌شوند. هرمس تصویر، یادداشت صوتی، ویدیو و سند را از طریق سازنده‌های محتوایی ‏attachment()/voice() در spectrum-ts از طریق endpoint ‏/send-attachment سایدکار می‌فرستد. کپشن‌ها بعد از رسانه به‌عنوان حباب جداگانهٔ iMessage می‌آیند.
  • نظرسنجی‌های بومی پشتیبانی می‌شوند. هرمس محتوای نظرسنجی را از طریق سازندهٔ ‏poll() spectrum-ts از endpoint ‏/send-poll سایدکار می‌فرستد.
  • جلوه‌های پیام پشتیبانی می‌شوند. هرمس متن با جلوه‌های بومی حباب/صفحهٔ iMessage را از طریق سازندهٔ ‏effect() از endpoint ‏/send-effect می‌فرستد.
  • سهمیه‌های رایگان فوتون: ۵٬۰۰۰ پیام به‌ازای سرور در روز، ‏۵۰ شروع گفتگوی جدید به‌ازای هر خط اشتراکی در روز. افزایش قابل‌درخواست است — ایمیل به ‏help@photon.codes.
  • کرون و ارسال‌های مستقل گیت‌وی روشن می‌خواهند. فرستنده‌های خارج-از-پروسه ‏(کارهای کرون، ‏hermes send، داشبورد) همان sidecar را که گیت‌وی spawn کرده بازمصرف می‌کنند — پورت/توکنش را از ‏<hermes-home>/runtime/photon-sidecar.json می‌خوانند که بعد از عبور health-check نوشته و هنگام توقف حذف می‌شود. اگر ارسال مستقلی گفت گیت‌وی ظاهراً خاموش است، اول گیت‌وی را شروع ‏(یا ری‌استارت) کنید.
  • خط‌های اشتراکی/رایگان نمی‌توانند گفتگو با هدف جدید شروع کنند. سیاست سمت-فوتون: خط اشتراکی فقط بعد از اینکه عددی اول به خط پیام داده باشد می‌تواند بهش پیام بفرستد. ارسال کرون/مستقیم به گیرندهٔ کاملاً جدید حتی با setup درست هرمس توسط فوتون رد می‌شود — یا بگذارید گیرنده یک‌بار به خط پیام دهد، یا به خط اختصاصی مهاجرت کنید.
