راه‌اندازی Microsoft Teams

هرمس ایجنت را به‌عنوان بات به Microsoft Teams وصل کنید. برخلاف Socket Mode اسلک، Teams پیام‌ها را با فراخوانی یک وب‌هوک عمومی HTTPS تحویل می‌دهد، پس نمونه‌تان نقطهٔ پایانی قابل‌دسترس عمومی می‌خواهد — یا تونل توسعه ‏(توسعهٔ محلی) یا دامنهٔ واقعی ‏(تولید).

خلاصهٔ جلسه از رویدادهای Microsoft Graph می‌خواهید نه گفتگوی عادی بات؟ صفحهٔ اختصاصی را ببینید: جلسات Teams.

hermes gateway setup را اجرا و Microsoft Teams را انتخاب کنید تا راهنمای گام‌به‌گام ببینید.

۱ نحوهٔ پاسخ بات

زمینهرفتار
چت شخصی ‏(DM)بات به همهٔ پیام‌ها پاسخ می‌دهد. بدون نیاز به @منشن.
چت گروهیبات فقط با @منشن پاسخ می‌دهد.
کانالبات فقط با @منشن پاسخ می‌دهد.

‏Teams منشن‌ها را به‌صورت پیام‌های عادی با تگ‌های ‏<at>BotName</at> تحویل می‌دهد که هرمس قبل از پردازش خودکار حذفشان می‌کند.

برای نصب‌های سورسی/محلی extra تیمز را بگنجانید تا آداپتور همراه‌بسته SDK مایکروسافت تیمز را import کند:

bash
uv sync --extra teams
# یا برای نصب‌های قابل‌ویرایش:
uv pip install -e ".[teams]"

۲ گام ۱: نصب CLI ‏Teams

‏@microsoft/teams.cli ثبت بات را خودکار می‌کند — بدون نیاز به پرتال Azure.

bash
npm install -g @microsoft/teams.cli@preview
teams login

برای تأیید ورود و یافتن شناسهٔ آبجکت AAD خودتان ‏(لازم برای ‏TEAMS_ALLOWED_USERS):

teams status --verbose

۳ گام ۲: expose کردن پورت وب‌هوک

‏Teams نمی‌تواند به ‏localhost پیام بدهد. برای توسعه محلی از هر ابزار تونلی URL عمومی HTTPS بگیرید. پورت پیش‌فرض ‏3978 است — در صورت نیاز با ‏TEAMS_PORT عوضش کنید.

bash
# devtunnel (مایکروسافت)
devtunnel create hermes-bot --allow-anonymous
devtunnel port create hermes-bot -p 3978 --protocol http  # اگر TEAMS_PORT را عوض کردید 3978 را جایگزین کنید
devtunnel host hermes-bot

# ngrok
ngrok http 3978  # اگر TEAMS_PORT را عوض کردید 3978 را جایگزین کنید

# cloudflared
cloudflared tunnel --url http://localhost:3978  # اگر TEAMS_PORT را عوض کردید 3978 را جایگزین کنید

URL ‏https:// خروجی را کپی کنید — در گام بعد استفاده می‌شود. حین توسعه تونل را روشن نگه دارید.

URL عمومی تونل HTTPS است ولی شنوندهٔ وب‌هوک محلی هرمس HTTP خام است. تونل TLS را خاتمه و HTTP را به پورت ‏3978 فوروارد می‌کند؛ پورت محلی تونل را HTTPS پیکربندی نکنید.

برای تولید، endpoint بات را به‌جایش روی دامنهٔ عمومی سرورتان تنظیم کنید ‏(استقرار تولید را ببینید).

۴ گام ۳: ساخت بات

bash
teams app create \
  --name "Hermes" \
  --endpoint "https://<your-tunnel-url>/api/messages"

‏CLI مقدارهای ‏CLIENT_ID، ‏CLIENT_SECRET و ‏TENANT_ID را به‌اضافهٔ لینک نصب برای گام ۶ چاپ می‌کند. رمز کلاینت را ذخیره کنید — دیگر نمایش داده نمی‌شود.

۵ گام ۴: پیکربندی متغیرهای محیطی

به ‏~/.hermes/.env اضافه کنید:

bash
# الزامی
TEAMS_CLIENT_ID=<your-client-id>
TEAMS_CLIENT_SECRET=<your-client-secret>
TEAMS_TENANT_ID=<your-tenant-id>

# محدودکردن دسترسی به کاربران خاص (توصیه‌شده)
# شناسه‌های آبجکت AAD از `teams status --verbose`
TEAMS_ALLOWED_USERS=<your-aad-object-id>

۶ گام ۵: شروع گیت‌وی

Docker ‏(باید از دایرکتوری حاوی ‏docker-compose.yml اجرا شود — معمولاً مخزون clone‌شدهٔ hermes-agent، نه ‏~):

bash
cd /path/to/hermes-agent
HERMES_UID=$(id -u) HERMES_GID=$(id -g) docker compose up -d gateway

نصب native / systemd ‏(نصب تک‌خطی معمولی hermes زیر ‏~/.hermes/hermes-agent):

bash
hermes gateway restart
# یا پیش‌زمینه: hermes gateway run

‏SDK تیمز اختیاری است؛ وقتی Teams فعال باشد گیت‌وی آن را در اولین شروع به‌صورت lazy داخل venv خود هرمس نصب می‌کند ‏(روی Ubuntu 24.04 از ‏pip سیستم استفاده نکنید — به PEP 668 ‏externally-managed-environment برمی‌خورد). نصب دستی در venv هرمس:

bash
~/.hermes/hermes-agent/venv/bin/pip install microsoft-teams-apps aiohttp
# یا از clone ایجنت: uv sync --extra teams

پورت پیش‌فرض وب‌هوک ‏3978 است ‏(با ‏TEAMS_PORT override کنید). چک کنید اجراست:

bash
curl http://localhost:3978/health   # باید برگرداند: ok
# Docker:
docker logs -f hermes
# Native:
hermes gateway status -l

دنبال این بگردید:

[teams] Webhook server listening on * (all interfaces, IPv4+IPv6):3978/api/messages

۷ گام ۶: نصب اپ در Teams

teams app get <teamsAppId> --install-link

لینک چاپ‌شده را در مرورگر باز کنید — مستقیم در کلاینت Teams باز می‌شود. بعد از نصب، به بات DM بدهید — آماده است.

۹ قابلیت‌ها

کارت‌های تأیید تعاملی

وقتی ایجنت لازم است فرمان بالقوه خطرناکی اجرا کند، به‌جای اینکه از شما بخواهد ‏/approve تایپ کنید، کارت Adaptive با چهار دکمه می‌فرستد:

  • Allow Once — تأیید همین فرمان مشخص
  • Allow Session — تأیید این الگو تا آخر نشست
  • Always Allow — تأیید همیشگی این الگو
  • Deny — رد فرمان

کلیک روی دکمه، تأیید را درجا حل و کارت را با تصمیم جایگزین می‌کند.

تحویل خلاصهٔ جلسات ‏(خط‌لولهٔ جلسات Teams)

وقتی افزونهٔ خط‌لولهٔ جلسات Teams فعال باشد ‏(msgraph-webhook)، این آداپتور تحویل خروجی خلاصه‌های جلسه را هم هندل می‌کند — یک سطح یکپارچه‌سازی Teams، نه دو. بعد از خلاصه‌شدن رونویسی جلسه، نویسنده خلاصه را به هدف Teams انتخابی‌تان پست می‌کند.

تحویل خلاصهٔ خط‌لوله زیر ورودی پلتفرم teams کنار پیکربندی بات تنظیم می‌شود:

yaml
platforms:
  teams:
    enabled: true
    extra:
      # پیکربندی موجود بات (client_id, client_secret, tenant_id, port) ...

      # تحویل خلاصهٔ جلسه (فقط وقتی افزونه teams_pipeline فعال است)
      delivery_mode: "graph"       # یا "incoming_webhook"
      # برای delivery_mode: graph — یکی را انتخاب کنید:
      chat_id: "19:meeting_..."    # پست در یک چت Teams
      # team_id: "..."             # یا پست در یک کانال
      # channel_id: "..."
      # access_token: "..."        # اختیاری؛ به اعتبارنامه‌های اپ MSGRAPH_* برمی‌گردد
      # برای delivery_mode: incoming_webhook:
      # incoming_webhook_url: "https://outlook.office.com/webhook/..."
حالتکِیموازنه
incoming_webhook«یک خلاصه ساده در این کانال پست کن» با URL ثابتِ تولیدشده توسط Teams.بدون threading ریپلای، بدون واکنش؛ با هویت پیکربندی‌شدهٔ وب‌هوک نمایش داده می‌شود.
graphپست‌های تردی کانال یا پست چت ۱:۱/گروهی تحت هویت بات از طریق Microsoft Graph.نیازمند ثبت اپ Graph با دسترسی اپلیکیشنی ‏ChannelMessage.Send ‏(کانال) یا ‏Chat.ReadWrite.All ‏(چت).

اگر افزونهٔ ‏teams_pipeline فعال نباشد این تنظیمات بی‌اثرند — فقط وقتی سیم می‌خورند که runtime خط‌لوله به ورودی وب‌هوک Graph متصل شود.

۱۰ استقرار تولید

برای سرور دائمی، TLS را در پروکسی معکوس خاتمه دهید و درخواست‌ها را به شنوندهٔ HTTP خام هرمس — معمولاً ‏http://127.0.0.1:3978 — فوروارد کنید. endpoint عمومی HTTPS پروکسی را در Teams ثبت کنید:

bash
teams app create \
  --name "Hermes" \
  --endpoint "https://your-domain.com/api/messages"

اگر قبلاً بات ساخته‌اید و فقط endpoint را باید عوض کنید:

teams app update --id <teamsAppId> --endpoint "https://your-domain.com/api/messages"

مطمئن شوید endpoint عمومی HTTPS از اینترنت قابل‌رسید و دارای گواهی TLS معتبر است. Teams گواهی self-signed را رد می‌کند. شنونده هرمس را پشت پروکسی نگه دارید؛ پورت ‏3978 خودش HTTPS سرو نمی‌کند.

۱۱ عیب‌یابی

مشکلراه‌حل
خطای ‏Can't find a suitable configuration file از ‏docker composeدر مخزنی که ‏docker-compose.yml دارد نیستید، یا نصبتان native است — به‌جایش ‏hermes gateway restart یا اول ‏cd به clone
‏requirements not met / ‏Teams SDK missing / ‏No adapter available for teamsگیت‌وی را ری‌استارت کنید تا lazy-install اجرا شود، یا در venv هرمس نصب کنید: ‏~/.hermes/hermes-agent/venv/bin/pip install microsoft-teams-apps aiohttp. ‏pip سیستم روی Ubuntu 24.04 شکست می‌خورد ‏(PEP 668) و به هر حال سرویس را تحت تأثیر نمی‌گذارد
endpoint ‏health کار می‌کند ولی بات جواب نمی‌دهدچک کنید تونل هنوز روشن است و endpoint پیام‌رسانی بات با URL تونل مطابق است
لاگ‌ها هنگام ارسال پیام توسط Teams نشان می‌دهند ‏"UNKNOWN / HTTP/1.0" 400تونل یا پروکسی HTTPS را به شنوندهٔ HTTP خام هرمس فوروارد می‌کند. TLS را در پروکسی خاتمه و HTTP را به پورت ‏3978 فوروارد کنید
‏KeyError: 'teams' در لاگ‌هاکانتینر را ری‌استارت کنید — در نسخهٔ فعلی رفع شده
بات با خطاهای احراز جواب می‌دهدتأیید کنید ‏TEAMS_CLIENT_ID، ‏TEAMS_CLIENT_SECRET و ‏TEAMS_TENANT_ID همه درست تنظیم‌اند
‏No inference provider configuredچک کنید ‏ANTHROPIC_API_KEY ‏(یا کلید ارائه‌دهندهٔ دیگر) در ‏~/.hermes/.env تنظیم شده باشد
بات پیام می‌گیرد ولی نادیده می‌گیرداحتمالاً شناسهٔ آبجکت AAD شما در ‏TEAMS_ALLOWED_USERS نیست. با ‏teams status --verbose پیدا کنید
URL تونل با ری‌استارت عوض می‌شود‏URL های devtunnel اگر تونل نام‌دار بسازید پایدارند ‏(devtunnel create hermes-bot). ‏ngrok و cloudflared هر بار URL جدید می‌سازند مگر طرح پرداختی داشته باشید — با تغییر، endpoint بات را با ‏teams app update به‌روز کنید
‏Teams نشان می‌دهد «This bot is not responding»وب‌هوک خطا برگردانده. traceback ها را در ‏docker logs hermes / ‏hermes gateway status -l چک کنید
‏[teams] Failed to connect در لاگ‌هاSDK احرازشکست خورده. اعتبارنامه‌ها و تطبیق tenant ID با حساب ‏teams login را دوباره چک کنید

۱۲ امنیت

⚠️ هشدار

همیشه ‏TEAMS_ALLOWED_USERS را با شناسه‌های آبجکت AAD کاربران مجاز تنظیم کنید. بدون این، هر کسی بتواند بات شما را پیدا یا نصب کند با آن تعامل می‌کند.

با ‏TEAMS_CLIENT_SECRET مثل رمز عبور رفتار کنید — به‌طور دوره‌ای از پرتال Azure یا CLI تیمز بچرخانیدش.

  • اعتبارنامه‌ها را در ‏~/.hermes/.env با دسترسی ‏600 ذخیره کنید ‏(chmod 600 ~/.hermes/.env)
  • بات فقط پیام‌های کاربران ‏TEAMS_ALLOWED_USERS را می‌پذیرد؛ پیام‌های غیرمجاز بی‌صدا دور ریخته می‌شوند
  • endpoint عمومی شما ‏(/api/messages) توسط Bot Framework تیمز احراز می‌شود — درخواست‌های بدون JWT معتبر رد می‌شوند
