یکپارچه‌سازی Open WebUI

Open WebUI ‏(۱۲۶ هزار ستاره) محبوب‌ترین رابط چت خودمیزبان برای هوش مصنوعی است. با سرور API داخلی هرمس ایجنت می‌توانید از Open WebUI به‌عنوان یک فرانت وب صیقل‌خورده برای ایجنت‌تان استفاده کنید — با مدیریت گفتگو، حساب کاربری و رابط چت مدرن.

۱ معماری

text
Open WebUI (رابط مرورگر، پورت 3000)
        │  POST /v1/chat/completions
        ▼
hermes-agent (سرور API گیت‌وی، پورت 8642)
        │  پاسخ استریم SSE
        ▼
   Open WebUI

‏Open WebUI مثل اتصال به OpenAI به سرور API هرمس ایجنت وصل می‌شود. هرمس درخواست‌ها را با تول‌ست کاملش هندل می‌کند — ترمینال، عملیات فایل، جست‌وجوی وب، حافظه، مهارت‌ها — و پاسخ نهایی را برمی‌گرداند.

📌 مکان runtime

سرور API یک runtime ایجنت هرمس است نه پروکسی خالص LLM. برای هر درخواست، هرمس یک ‏AIAgent سمت-سرور روی میزبان سرور API می‌سازد. فراخوانی‌های ابزار همانجا که سرور API اجراست اجرا می‌شوند.

مثلاً اگر لپ‌تاپی Open WebUI یا کلاینت سازگار-با-OpenAI دیگری را به سرور API هرمس روی ماشین راه‌دور اشاره دهد، ‏pwd، ابزارهای فایل، ابزارهای مرورگر، ابزارهای MCP محلی و سایر ابزارهای ورک‌اسپیس روی میزبانِ راه‌دورِ سرور API اجرا می‌شوند نه روی لپ‌تاپ.

‏Open WebUI سرور-به-سرور با هرمس حرف می‌زند، پس برای این یکپارچه‌سازی ‏API_SERVER_CORS_ORIGINS لازم نیست.

۲ راه‌اندازی سریع

۱. فعال‌سازی سرور API

hermes config set API_SERVER_ENABLED true
hermes config set API_SERVER_KEY your-secret-key

‏hermes config set فلگ را خودکار به config.yaml و رمز را به ‏~/.hermes/.env مسیریابی می‌کند. اگر گیت‌وی از قبل اجراست ری‌استارتش کنید تا تغییر اعمال شود:

hermes gateway stop && hermes gateway

۲. شروع گیت‌وی هرمس ایجنت

hermes gateway

باید ببینید:

[API Server] API server listening on http://127.0.0.1:8642

۳. تأیید قابل‌دسترس بودن سرور API

bash
curl -s http://127.0.0.1:8642/health
# {"status": "ok", ...}

curl -s -H "Authorization: Bearer your-secret-key" http://127.0.0.1:8642/v1/models
# {"object":"list","data":[{"id":"hermes-agent", ...}]}

اگر ‏/health شکست خورد، گیت‌وی ‏API_SERVER_ENABLED=true را برنداشته — ری‌استارتش کنید. اگر ‏/v1/models مقدار ‏401 برگرداند، هدر Authorization شما با ‏API_SERVER_KEY نمی‌خواند.

۴. شروع Open WebUI

bash
docker run -d -p 3000:8080 \
  -e OPENAI_API_BASE_URL=http://host.docker.internal:8642/v1 \
  -e OPENAI_API_KEY=your-secret-key \
  -e ENABLE_OLLAMA_API=false \
  --add-host=host.docker.internal:host-gateway \
  -v open-webui:/app/backend/data \
  --name open-webui \
  --restart always \
  ghcr.io/open-webui/open-webui:main

‏ENABLE_OLLAMA_API=false بک‌اند پیش‌فرض Ollama را سرکوب می‌کند که وگرنه خالی ظاهر شده و انتخاب‌گر مدل را شلوغ می‌کند. اگر واقعاً Ollama هم کنارش دارید حذفش کنید.

اولین اجرا ۱۵ تا ۳۰ ثانیه طول می‌کشد: ‏Open WebUI بار اول مدل‌های embedding ‏sentence-transformer ‏(~۱۵۰MB) را دانلود می‌کند. قبل از بازکردن UI منتظر بمانید ‏docker logs open-webui آرام بگیرد.

۵. بازکردن UI

به ‏http://localhost:3000 بروید. حساب ادمین بسازید ‏(اولین کاربر ادمین می‌شود). باید ایجنت‌تان را در کشویی مدل ببینید ‏(به نام پروفایل شما، یا ‏hermes-agent برای پروفایل پیش‌فرض). شروع به چت کنید!

۳ راه‌اندازی Docker Compose

برای setup ماندگارتر یک ‏docker-compose.yml بسازید:

yaml
services:
  open-webui:
    image: ghcr.io/open-webui/open-webui:main
    ports:
      - "3000:8080"
    volumes:
      - open-webui:/app/backend/data
    environment:
      - OPENAI_API_BASE_URL=http://host.docker.internal:8642/v1
      - OPENAI_API_KEY=your-secret-key
      - ENABLE_OLLAMA_API=false
    extra_hosts:
      - "host.docker.internal:host-gateway"
    restart: always

volumes:
  open-webui:

سپس:

docker compose up -d

۴ پیکربندی از طریق Admin UI

اگر ترجیح می‌دهید اتصال را از طریق UI به‌جای متغیرهای محیطی پیکربندی کنید:

  1. وارد Open WebUI شوید ‏(http://localhost:3000)
  2. روی آواتار پروفایل کلیک ← Admin Settings
  3. به Connections بروید
  4. تحت OpenAI API روی آیکون آچار ‏(Manage) کلیک کنید
  5. روی + Add New Connection کلیک کنید
  6. وارد کنید:
    • URL: ‏http://host.docker.internal:8642/v1
    • API Key: دقیقاً همان مقدار ‏API_SERVER_KEY در هرمس
  7. برای تأیید اتصال روی تیک کلیک کنید
  8. Save را بزنید

مدل ایجنت‌تان حالا باید در کشویی مدل ظاهر شود ‏(به نام پروفایل، یا ‏hermes-agent برای پروفایل پیش‌فرض).

⚠️ هشدار

متغیرهای محیطی فقط روی اولین اجرای Open WebUI اثر دارند. بعد از آن تنظیمات اتصال در دیتابیس داخلی‌اش ذخیره می‌شود. برای تغییر بعدی از Admin UI استفاده کنید یا والوم Docker را حذف و از نو شروع کنید.

۵ نوع API: ‏Chat Completions در برابر Responses

‏Open WebUI هنگام اتصال به بک‌اند دو حالت API دارد:

حالتقالبکِی
Chat Completions ‏(پیش‌فرض)/v1/chat/completionsتوصیه‌شده. از جعبه کار می‌کند.
Responses ‏(آزمایشی)/v1/responsesبرای وضعیت گفتگوی سمت-سرور با ‏previous_response_id.

استفاده از Chat Completions ‏(توصیه‌شده)

این پیش‌فرض است و پیکربندی اضافه نمی‌خواهد. ‏Open WebUI درخواست‌های استاندارد قالب OpenAI می‌فرستد و هرمس ایجنت مطابق جواب می‌دهد. هر درخواست تاریخچهٔ کامل گفتگو را شامل است.

استفاده از Responses API

برای حالت Responses API:

  1. به ‏Admin Settings ← Connections ← OpenAI ← Manage بروید
  2. اتصال hermes-agent را ویرایش کنید
  3. API Type را از «Chat Completions» به ‏«Responses (Experimental)» عوض کنید
  4. ذخیره کنید

با Responses API، ‏Open WebUI درخواست‌ها را در قالب Responses ‏(آرایهٔ input + instructions) می‌فرستد و هرمس ایجنت می‌تواند تاریخچهٔ کامل فراخوانی ابزار را بین نوبت‌ها با ‏previous_response_id حفظ کند. وقتی ‏stream: true باشد هرمس اقلام ‏function_call و ‏function_call_output بومی-مشخصات را هم استریم می‌کند که UI ساختاریافتهٔ سفارشیِ فراخوانی-ابزار را در کلاینت‌هایی که رویدادهای Responses را رندر می‌کنند ممکن می‌سازد.

📌 نکته

‏Open WebUI الان حتی در حالت Responses هم تاریخچهٔ گفتگو را سمت-کلاینت مدیریت می‌کند — به‌جای ‏previous_response_id تاریخچهٔ کامل پیام را در هر درخواست می‌فرستد. مزیت اصلی Responses امروز، جریان رویداد ساختاریافته است: دلتاهای متنی و اقلام ‏function_call/function_call_output به‌عنوان رویدادهای SSE مربوط به OpenAI Responses می‌آیند به‌جای chunk های Chat Completions.

۶ نحوهٔ کار

وقتی در Open WebUI پیام می‌فرستید:

  1. ‏Open WebUI یک درخواست ‏POST /v1/chat/completions با پیام و تاریخچهٔ گفتگوی شما می‌فرستد
  2. هرمس ایجنت با پروفایل سرور API، پیکربندی مدل/ارائه‌دهنده، حافظه، مهارت‌ها و تول‌ست‌های پیکربندی‌شدهٔ سرور API یک نمونهٔ ‏AIAgent سمت-سرور می‌سازد
  3. ایجنت درخواستتان را پردازش می‌کند — ممکن است روی میزبان سرور API ابزار صدا بزند ‏(ترمینال، عملیات فایل، جست‌وجوی وب و...)
  4. هم‌زمان با اجرای ابزارها، پیام‌های پیشرفت درون‌خطی به UI استریم می‌شوند تا ببینید ایجنت چه می‌کند ‏(مثل ‏`💻 ls -la`، ‏`🔍 Python 3.12 release`)
  5. پاسخ متنی نهایی ایجنت به Open WebUI استریم می‌شود
  6. ‏Open WebUI پاسخ را در رابط چتش نمایش می‌دهد

ایجنت شما به همان ابزارها و قابلیت‌های نمونهٔ هرمسِ سرور API دسترسی دارد. اگر سرور API راه‌دور باشد آن ابزارها هم راه‌دورند.

اگر امروز ابزارها باید علیه ورک‌اسپیس محلی‌تان اجرا شوند، هرمس را محلی اجرا کنید و به ارائه‌دهندهٔ خالص LLM یا پراکسی خالص مدل سازگار-با-OpenAI اشاره دهید ‏(مثل vLLM، ‏LiteLLM، ‏Ollama، ‏llama.cpp، ‏OpenAI، ‏OpenRouter و...). یک حالت split-runtime آینده برای «مغز راه‌دور، دست‌های محلی» در ‏issue شمارهٔ ۱۸۷۱۵ پیگیری می‌شود؛ رفتار فعلی سرور API این نیست.

💡 پیشرفت ابزار

با روشن بودن استریم ‏(پیش‌فرض)، حین اجرای ابزارها نشانگرهای کوتاه درون‌خطی می‌بینید — ایموجی ابزار و آرگومان کلیدی‌اش. این‌ها قبل از پاسخ نهایی ایجنت در جریان پاسخ می‌آیند و دید به آنچه پشت صحنه می‌گذرد می‌دهند.

۸ عیب‌یابی

هیچ مدلی در کشویی ظاهر نمی‌شود

  • چک کنید URL پسوند ‏/v1 دارد: ‏http://host.docker.internal:8642/v1 ‏(نه فقط ‏:8642)
  • تأیید اجرای گیت‌وی: ‏curl http://localhost:8642/health باید ‏{"status": "ok"} برگرداند
  • چک فهرست مدل‌ها: ‏curl -H "Authorization: Bearer your-secret-key" http://localhost:8642/v1/models باید فهرستی با ‏hermes-agent برگرداند
  • شبکهٔ Docker: داخل Docker منظورت از localhost خود کانتینر است نه میزبان. از host.docker.internal یا ‏--network=host استفاده کنید.
  • بک‌اند خالی Ollama سایه می‌اندازد: اگر ‏ENABLE_OLLAMA_API=false را حذف کردید، ‏Open WebUI بخش Ollama خالی بالای مدل‌های هرمس نشان می‌دهد. کانتینر را با ‏-e ENABLE_OLLAMA_API=false ری‌استارت یا Ollama را در ‏Admin Settings ← Connections خاموش کنید.

تست اتصال پاس می‌شود ولی مدلی لود نمی‌شود

تقریباً همیشه پسوند ‏/v1 جاافتاده است. تست اتصال Open WebUI فقط چک اتصال ساده است — فهرست‌شدن مدل را تأیید نمی‌کند.

پاسخ خیلی طول می‌کشد

هرمس ایجنت ممکن است چند فراخوانی ابزار ‏(خواندن فایل، اجرای فرمان، جست‌وجوی وب) قبل از تولید پاسخ نهایی اجرا کند. برای پرسش‌های پیچیده طبیعی است. پاسخ وقتی ایجنت تمام شد یک‌جا ظاهر می‌شود.

خطاهای «Invalid API key»

مطمئن شوید ‏OPENAI_API_KEY در Open WebUI با ‏API_SERVER_KEY هرمس ایجنت یکی است.

⚠️ هشدار

‏Open WebUI بعد از اولین اجرا تنظیمات اتصال سازگار-با-OpenAI را در دیتابیس خودش ماندگار می‌کند. اگر اشتباهاً کلید اشتباهی در Admin UI ذخیره کردید، فقط اصلاح متغیرهای محیطی کافی نیست — اتصال ذخیره‌شده را در ‏Admin Settings ← Connections به‌روز یا حذف کنید، یا دایرکتوری داده / دیتابیس Open WebUI را ریست کنید.

۹ راه‌اندازی چندکاربره با پروفایل‌ها

برای اجرای نمونه‌های جداگانهٔ هرمس به‌ازای هر کاربر — هرکدام با config، حافظه و مهارت‌های خودشان — از پروفایل‌ها استفاده کنید. هر پروفایل سرور API خودش را روی پورت مختلف اجرا و خودکار نام پروفایل را به‌عنوان مدل در Open WebUI اعلان می‌کند.

۱. ساخت پروفایل‌ها و پیکربندی سرورهای API

‏API_SERVER_* متغیر env هستند نه کلید YAML، پس در .env هر پروفایل بنویسیدشان. پورت‌های خارج از بازهٔ پلتفرم‌های پیش‌فرض انتخاب کنید ‏(8644 آداپتور webhook، ‏8645 wecom-callback، ‏8646 msgraph-webhook)، مثلاً ‏8650+:

bash
hermes profile create alice
cat >> ~/.hermes/profiles/alice/.env <<EOF
API_SERVER_ENABLED=true
API_SERVER_PORT=8650
API_SERVER_KEY=alice-secret
EOF

hermes profile create bob
cat >> ~/.hermes/profiles/bob/.env <<EOF
API_SERVER_ENABLED=true
API_SERVER_PORT=8651
API_SERVER_KEY=bob-secret
EOF

۲. شروع هر گیت‌وی

hermes -p alice gateway &
hermes -p bob gateway &

۳. افزودن اتصال‌ها در Open WebUI

در ‏Admin Settings ← Connections ← OpenAI API ← Manage به‌ازای هر پروفایل یک اتصال اضافه کنید:

اتصالURLAPI Key
Alicehttp://host.docker.internal:8650/v1alice-secret
Bobhttp://host.docker.internal:8651/v1bob-secret

کشویی مدل ‏alice و ‏bob را به‌عنوان دو مدل مجزا نشان خواهد داد. می‌توانید از طریق پنل ادمین مدل‌ها را به کاربران Open WebUI تخصیص دهید و به هر کاربر ایجنت هرمس ایزولهٔ خودش را بدهید.

💡 نام مدل سفارشی

نام مدل پیش‌فرض نام پروفایل است. برای override، در ‏.env پروفایل ‏API_SERVER_MODEL_NAME را تنظیم کنید:

hermes -p alice config set API_SERVER_MODEL_NAME "Alice's Agent"

۱۰ ‏Docker لینوکس ‏(بدون Docker Desktop)

روی لینوکس بدون Docker Desktop مقدار ‏host.docker.internal به‌طور پیش‌فرض حل نمی‌شود. گزینه‌ها:

bash
# گزینهٔ ۱: افزودن نگاشت میزبان
docker run --add-host=host.docker.internal:host-gateway ...

# گزینهٔ ۲: شبکه‌سازی host
docker run --network=host -e OPENAI_API_BASE_URL=http://localhost:8642/v1 ...

# گزینهٔ ۳: IP bridge داکر
docker run -e OPENAI_API_BASE_URL=http://172.17.0.1:8642/v1 ...
