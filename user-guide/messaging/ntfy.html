ntfy

ntfy یک سرویس اعلان pub-sub ساده مبتنی بر HTTP است. با سرور عمومی رایگان ntfy.sh یا هر نمونهٔ خودمیزبان کار می‌کند و هر کلاینتی که بتواند درخواست HTTP بزند را پشتیبانی می‌کند — گوشی، مرورگر، اسکریپت، ساعت.

‏ntfy یک کانال پوش سبک عالی برای هرمس است: از اپ موبایل ntfy روی یک تاپیک subscribe کنید، برای حرف زدن با ایجنت به تاپیک پیام بدهید و پاسخ را روی گوشی بگیرید.

hermes gateway setup را اجرا و ntfy را انتخاب کنید تا راهنمای گام‌به‌گام ببینید.

۱ پیش‌نیازها

  • یک نام تاپیک ‏(هر رشتهٔ یکتایی — مثل hermes-myname-2026)
  • اپ موبایل ntfy نصب‌شده و مشترک آن تاپیک
  • اختیاری: سرور ntfy خودمیزبان، یا توکن حساب ntfy.sh برای تاپیک‌های خصوصی/رزرو

همین. بدون SDK، بدون دیمن، بدون Node.js. آداپتور از httpx استفاده می‌کند که از قبل وابستگی هرمس است.

۲ پیکربندی هرمس

با ویزارد راه‌اندازی

bash
hermes gateway setup

ntfy را انتخاب و طبق پرسش‌ها پیش بروید.

با متغیرهای محیطی

این‌ها را به ~/.hermes/.env اضافه کنید:

bash
NTFY_TOPIC=hermes-myname-2026
NTFY_ALLOWED_USERS=hermes-myname-2026
NTFY_HOME_CHANNEL=hermes-myname-2026
متغیرلازمتوضیح
NTFY_TOPICبلهتاپیک اشتراک ‏(پیام‌های ورودی)
NTFY_SERVER_URLاختیاریURL سرور ‏(پیش‌فرض: https://ntfy.sh) — برای حریم خصوصی به ntfy خودمیزبان اشاره دهید
NTFY_TOKENاختیاریتوکن Bearer ‏(مثل tk_xyz) یا user:pass برای احراز Basic
NTFY_PUBLISH_TOPICاختیاریتاپیک جدا برای ریپلای‌های خروجی ‏(پیش‌فرض همان NTFY_TOPIC)
NTFY_MARKDOWNاختیاری‏true برای ارسال ریپلای‌ها با هدر X-Markdown: true
NTFY_ALLOWED_USERSتوصیه‌شدهنام‌های تاپیک مجاز جداشده با ویرگول ‏(به‌عنوان شناسهٔ کاربر پردازش می‌شوند؛ پایین را ببینید)
NTFY_ALLOW_ALL_USERSاختیاری‏true برای اجازه به هر ناشر — فقط برای تاپیک‌های خصوصیِ دارای توکن خواندن امن است
NTFY_HOME_CHANNELاختیاریتاپیک پیش‌فرض تحویل کرون / اعلان‌ها
NTFY_HOME_CHANNEL_NAMEاختیاریبرچسب خوانا برای کانال خانگی

۳ مدل هویت — قبل از استقرار بخوانید

‏ntfy هویت کاربر احرازشدهٔ بومی ندارد. فیلد title پیام منتشرشده در اختیار ناشر است و می‌تواند هر چیزی باشد که فرستنده بخواهد. آداپتور هرمس برای مجوزدهی از title استفاده نمی‌کند — این اجازه می‌داد هر ناشری که تاپیک را بداند خودش را به‌جای کاربر مجاز جا بزند.

به‌جایش، خود نام تاپیک همان هویت است. هر پیام منتشرشده به تاپیک به‌عنوان پیام از طرف همان کاربر منطقی ‏(تاپیک) پردازش می‌شود. پس NTFY_ALLOWED_USERS معمولاً فقط خود نام تاپیک است — لیست‌مجاز تک‌عضوی که کل کانال را گیت می‌زند.

یعنی هر کسی که تاپیک را بداند می‌تواند با ایجنت حرف بزند. برای تبدیل این به یک مرز اعتماد واقعی:

  • ‏ntfy را خودمیزبان کنید و تاپیک را با کنترل دسترسی قفل کنید. فقط کلاینت‌های مجاز دارای توکن خواندن/نوشتن می‌توانند منتشر کنند.
  • یا از یک تاپیک خصوصی روی ntfy.sh استفاده کنید ‏(تاپیک‌های رزرو حساب می‌خواهند) و با NTFY_TOKEN محافظتش کنید.
  • یا نامی بلند و غیرقابل‌حدس انتخاب کنید ‏(hermes-7d4f9c8b-2026) و آن را رمز مشترک فرض کنید. سبک‌ترین راه‌اندازی است ولی نام تاپیک از طریق لاگ‌ها یا اسکرین‌شات‌ها لو می‌رود.

در همهٔ حالت‌ها، مگر تاپیک زیرین کنترل دسترسی داشته باشد دادهٔ حساس از ntfy عبور ندهید.

۴ شروع سریع — گفتگو با ایجنت از گوشی

  1. نام تاپیک را انتخاب کنید: ‏hermes-myname-2026
  2. روی گوشی: اپ ntfy را نصب، دکمهٔ + را بزنید و hermes-myname-2026 را وارد کنید
  3. روی میزبان:
bash
echo 'NTFY_TOPIC=hermes-myname-2026' >> ~/.hermes/.env
echo 'NTFY_ALLOWED_USERS=hermes-myname-2026' >> ~/.hermes/.env
hermes gateway restart
  1. از اپ ntfy به تاپیک پیام بدهید. ریپلای ایجنت به‌صورت اعلان پوش می‌رسد.

۵ استفاده از ntfy با کارهای کرون

وقتی NTFY_HOME_CHANNEL تنظیم باشد، کارهای کرون می‌توانند به ntfy تحویل شوند:

python
cronjob(
    action="create",
    schedule="every 1h",
    deliver="ntfy",          # از NTFY_HOME_CHANNEL استفاده می‌کند
    prompt="Check for alerts and summarise."
)

یا صریحاً یک تاپیک مشخص را از طریق فیلد deliver: کار کرون هدف بگیرید، یا از اسکریپت شل با CLI ‏hermes send:

bash
hermes send ntfy:alerts-channel "Done!"

این حتی وقتی کرون خارج-از-پروسه از گیت‌وی اجرا می‌شود کار می‌کند — افزونه یک standalone_sender_fn ثبت می‌کند که اتصال HTTP خودش را باز می‌کند.

۶ خودمیزبان‌کردن ntfy

اگر کنترل کامل می‌خواهید:

bash
# Docker
docker run -p 80:80 -it binwiederhier/ntfy serve

# Native
go install heckel.io/ntfy/v2@latest
ntfy serve

سپس هرمس را به آن اشاره دهید:

bash
NTFY_SERVER_URL=https://ntfy.mydomain.com
NTFY_TOPIC=hermes
NTFY_TOKEN=tk_abc123  # اگر کنترل دسترسی گذاشته باشید

خودمیزبانی کنترل دسترسی تاپیک، سیاست ماندگاری پیام، پیوست‌ها و تگ‌های ایموجی می‌دهد. مستندات سرور ntfy را ببینید.

۷ قالب‌بندی مارک‌داون

کلاینت‌های ntfy وقتی ناشر هدر X-Markdown: true بگذارد مارک‌داون رندر می‌کنند. برای فعال‌سازی روی ریپلای‌های خروجی هرمس:

bash
NTFY_MARKDOWN=true

یا در config.yaml:

yaml
platforms:
  ntfy:
    extra:
      markdown: true

اپ موبایل زیرمجموعه‌ای از CommonMark را پشتیبانی می‌کند — ضخیم، ایتالیک، فهرست، لینک، بلوک کد محصور. مجموعهٔ دقیق را در مستندات مارک‌داون ntfy ببینید.

۸ راه‌اندازی فقط-خروجی ‏(اعلان بدون ورودی)

اگر فقط می‌خواهید هرمس به ntfy اعلان push کند ‏(خلاصه‌های کرون، هشدارها) و هیچ‌وقت پیام قبول نکند، هم NTFY_TOPIC هم NTFY_PUBLISH_TOPIC را یک مقدار بگذارید و NTFY_ALLOWED_USERS را کلاً حذف کنید. بدون لیست مجاز، ایجنت هرگز به پیام‌های ورودی پاسخ نمی‌دهد — گوشی‌تان پوش می‌گیرد ولی گفتگو یک‌طرفه است.

۹ محدودیت‌ها

  • حجم پیام: ntfy بدنهٔ پیام را روی ۴۰۹۶ کاراکتر سقف می‌زند. هرمس هنگام عبور با هشدار برش می‌زند.
  • بدون نشانگر تایپ: پروتکل چنین چیزی expose نمی‌کند؛ ‏send_typing no-op است.
  • بدون ترد یا پیوست: ntfy فقط اعلان پوش ساده است. ریپلای‌های بلند داخل بدنهٔ پیام می‌مانند، بدون fanout ترد.
  • بدون هویت کاربر بومی: بخش مدل هویت بالاتر را ببینید.

۱۰ عیب‌یابی

شکست احراز / 401 — ‏NTFY_TOKEN اشتباه است یا توکن حق publish/subscribe روی این تاپیک ندارد. آداپتور حلقهٔ reconnect را روی 401 متوقف می‌کند و وضعیت runtime گیت‌وی ‏fatal: ntfy_unauthorized نشان می‌دهد. توکن را درست کنید و گیت‌وی را ری‌استارت کنید.

تاپیک پیدا نشد / 404 — ‏NTFY_TOPIC روی سرور پیکربندی‌شده وجود ندارد. در ntfy.sh تاپیک‌ها با اولین publish خودکار ساخته می‌شوند، پس 404 یعنی به سروری خودمیزبان اشاره دارید که تاپیکش provision نشده. آداپتور حلقهٔ reconnect را با ‏fatal: ntfy_topic_not_found متوقف می‌کند.

متصل است ولی پیامی نمی‌آید — چک کنید NTFY_ALLOWED_USERS خود نام تاپیک را داشته باشد. در مدل هویت ntfy، تاپیک همان کاربر است؛ خالی‌گذاشتن لیست مجاز همه‌چیز را رد می‌کند.

هر ۶۰ ثانیه reconnect می‌شود — پیش‌فرض keepalive استریم ۵۵ ثانیه است؛ ممکن است ntfy مشکلات شبکه‌ای متناوب داشته باشد. آداپتور backoff نمایی اعمال می‌کند ‏(۲ ← ۵ ← ۱۰ ← ۳۰ ← ۶۰ ثانیه) و وقتی استریم ≥۶۰ ثانیه زنده بماند به صفر برمی‌گردد.
