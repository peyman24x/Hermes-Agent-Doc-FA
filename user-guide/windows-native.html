خانه/کار با Hermes/راهنمای ویندوز ‏(بومی)

راهنمای ویندوز ‏(Native)

‏هرمس روی ویندوز ۱۰ و ۱۱ به‌صورت native اجرا می‌شود — بدون WSL، بدون Cygwin، بدون Docker. این صفحه کاوش عمیق است: چه چیزی natively کار می‌کند، چه چیزی فقط-WSL است، نصب‌کننده واقعاً چه می‌کند و پیچ‌ومهره‌های مخصوص-ویندوزی که شاید لازم شود دست بزنید.

فقط نصب می‌خواهید؟ همان یک‌خطیِ صفحهٔ نصب کافی است. وقتی چیزی غافلگیرتان کرد به اینجا برگردید.

💡 WSL ترجیح می‌دهید؟

اگر یک محیط POSIX واقعی می‌خواهید ‏(برای ترمینال تعبیه‌شدهٔ داشبورد، معناشناسی fork، file watcher های سبک-لینوکسی و…) بخش راهنمای ویندوز ‏(WSL2) را ببینید. هر دو تمیز همزیست می‌شوند: دادهٔ native زیر ‏%LOCALAPPDATA%\hermes و دادهٔ WSL زیر ‏~/.hermes.

۱ نصب سریع

‏PowerShell ‏(یا Windows Terminal) را باز و اجرا کنید:

iex (irm https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.ps1)

بدون نیاز به مجوز admin. نصب‌کننده به ‏%LOCALAPPDATA%\hermes\ می‌رود و hermes را به User PATH تان اضافه می‌کند — بعد از پایان یک ترمینال جدید باز کنید.

گزینه‌های نصب‌کننده

& ([scriptblock]::Create((irm https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.ps1))) -NoVenv -SkipSetup -Branch main
پارامترپیش‌فرضهدف
-Branchmainclone ی یک branch مشخص ‏(برای تست PR ها مفید)
-Commitunsetپین نصب روی SHA ی commit خاص ‏(بر -Branch مقدم)
-Tagunsetپین نصب روی tag ی git خاص ‏(مثل v0.14.0)
-NoVenvoffرد شدن از ساخت venv ‏(پیشرفته — خودتان Python را مدیریت می‌کنید)
-SkipSetupoffرد شدن از ویزارد hermes setup ی بعد-از-نصب
-HermesHome%LOCALAPPDATA%\hermesبازنویسی دایرکتوری داده
-InstallDir%LOCALAPPDATA%\hermes\hermes-agentبازنویسی محل کد

نصب‌کننده fetch های بی‌ثبات git را auto-retry و BOM را از هر payload ی دانلودشدهٔ install.ps1 حذف می‌کند، پس BOM ی UTF-8 گرفته‌شده حین انتقال HTTP دیگر فرم ‏scriptblock::Create((irm ...)) را نمی‌شکند.

نصب‌کنندهٔ دسکتاپ ‏(جایگزین)

یک GUI نصب‌کنندهٔ نازک هم موجود است — برای وقتی ترجیح می‌دهید یک exe. را دابل‌کلیک کنید تا PowerShell باز کنید. ‏Hermes Desktop را دانلود، نصب‌کننده را اجرا کنید؛ در اولین اجرا GUI زیر کاپوت install.ps1 را صدا می‌زند تا Python ‏(از طریق uv)، ‏Node، ‏PortableGit و بقیهٔ bootstrap ی وابستگی‌ها فراهم شود. بعد از اولین اجرا، اپ دسکتاپ و CLI ی hermes نصب‌شده-با-PowerShell همان نصب ‏%LOCALAPPDATA%\hermes\hermes-agent و دایرکتوری دادهٔ %LOCALAPPDATA%\hermes را شریک می‌شوند — آزادانه بین GUI و CLI سوئیچ کنید.

نصب‌کنندهٔ دسکتاپ را وقتی بخواهید که تجربهٔ نصب آشنای ویندوزی باشد یا هرمس را به غیر-توسعه‌دهنده تحویل دهید؛ یک‌خطی PowerShell را وقتی که همین حالا داخل ترمینال هستید.

bootstrap ی وابستگی‌ها ‏(dep_ensure)

در اولین اجرا ‏(و on-demand وقتی ابزار گمشده آشکار شود) هرمس یک bootstrapper ی کوچک پایتونی — hermes_cli/dep_ensure.py — اجرا می‌کند که وابستگی‌های غیر-پایتونی لازم را بررسی و lazy نصب می‌کند. روی ویندوز مربوطه‌ها:

وابستگیچرا هرمس لازمش دارد
PortableGitbash.exe را برای ابزار terminal و git را برای clone های درون-نشست فراهم می‌کند. موقع نصب provision می‌شود نه توسط dep_ensure.
Node.js ۲۶لازم برای ابزار مرورگر ‏(agent-browser)، پُل وب TUI و پل WhatsApp.
ffmpegتبدیل فرمت صدا برای TTS / پیام‌های صوتی.
ripgrepجستجوی سریع فایل — اگر نباشد به grep برمی‌گردد.
پکیج‌های npmagent-browser، ‏Chromium ی Playwright و هر dep ی Node مخصوص-تول‌ست یک بار در اولین استفاده از ابزار مرورگر نصب می‌شوند.

هر dep بررسی‌ای شبیه shutil.which(...) دارد؛ اگر باینری غایب باشد و اجرا تعاملی باشد dep_ensure پیشنهاد نصب می‌دهد ‏(منطق نصب واقعی به scripts\install.ps1 -ensure <dep> واگذار می‌شود). اجراهای غیرتعاملی ‏(گیت‌وی، cron، launch های headless ی دسکتاپ) پرامپت را skip و به‌جایش خطای واضح «this feature needs <dep>» نشان می‌دهند.

۲ نصب‌کننده واقعاً چه می‌کند

از بالا به پایین به ترتیب:

  1. uv را bootstrap می‌کند — مدیر سریع Python ی Astral؛ نصب در %USERPROFILE%\.local\bin.
  2. Python ۳٫۱۱ را با uv نصب می‌کند. بدون نیاز به Python موجود.
  3. Node.js ۲۶ نصب می‌کند ‏(winget اگر موجود، وگرنه tarball ی portable ی Node باز‌شده زیر %LOCALAPPDATA%\hermes\node). برای ابزار مرورگر و پل WhatsApp.
  4. Git ی portable نصب می‌کند — اگر git از قبل روی PATH باشد همان استفاده می‌شود؛ وگرنه یک PortableGit ی trimmed و خودکفا ‎(~۴۵MB‎، از release ی رسمی git-for-windows) در %LOCALAPPDATA%\hermes\git دانلود می‌شود. بدون admin، بدون registry ی نصب ویندوز، بدون تداخل با هیچ‌چیز دیگر روی جعبه.
  5. مخزن را clone می‌کند به %LOCALAPPDATA%\hermes\hermes-agent و داخلش virtualenv می‌سازد.
  6. ‏uv pip install طبقه‌بندی‌شده — اول .[all] را امتحان و در صورت flake شدن یک وابستگی git+https روی GitHub ی rate-limit شده به مجموعه‌های کوچکتر برمی‌گردد ‏([messaging,dashboard,ext] ← [messaging] ← .). جلوگیری از حالت شکستِ «یک flake تو را به نصب لخت می‌اندازد».
  7. SDK های پیام‌رسانی را کلیدخورده-با-.env خودکار نصب می‌کند — اگر TELEGRAM_BOT_TOKEN / DISCORD_BOT_TOKEN / SLACK_BOT_TOKEN / SLACK_APP_TOKEN / WHATSAPP_ENABLED حاضر باشند، python -m ensurepip --upgrade و pip install های هدفمند اجرا می‌شوند تا SDK هر پلتفرم واقعاً importable باشد.
  8. HERMES_GIT_BASH_PATH را ست می‌کند روی bash.exe ی حل‌شده تا هرمس در شل‌های تازه قطعی پیدایش کند.
  9. %LOCALAPPDATA%\hermes\bin را به User PATH اضافه و HERMES_HOME=%LOCALAPPDATA%\hermes را ست می‌کند — بعد از باز کردن ترمینال جدید فرمان hermes در دسترس ‏(و اشاره‌گر به دایرکتوری داده‌تان) می‌شود. فقط launcher های hermes.exe / hermes-acp.exe داخل این bin کپی می‌شوند؛ venv\Scripts عمداً روی PATH گذاشته نمی‌شود تا هرمس هرگز فرمان python ی شما را سایه ناندازد.
  10. hermes setup را اجرا می‌کند — ویزارد عادی اولین-اجرا ‏(مدل، ارائه‌دهنده، تول‌ست‌ها). با -SkipSetup رد شود.
💡 رد شدن از شکار ارائه‌دهنده روی ویندوز

روی ویندوز، setup ی کلید API ی per-tool ‏(Firecrawl، ‏FAL، ‏Browser Use، ‏OpenAI TTS) پراصطکاک‌ترین بخش رسیدن به ایجنتی کاراست. اشتراک Nous Portal مدل و همهٔ آن ابزارها را با یک ورود OAuth پوشش می‌دهد. بعد از اتمام نصب‌کننده ‏hermes setup --portal را اجرا کنید تا همه‌چیز سیم‌کشی شود.

تب /chat ی داشبورد یک ترمینال واقعی را از طریق PTY ی POSIX ‏(ptyprocess) تعبیه می‌کند. ویندوز native معادل این primitive را ندارد؛ pywinpty / ConPTY ی پایتون کار می‌کردند ولی پیاده‌سازی جدایی‌اند — آینده تلقی شوند. بقیهٔ داشبورد natively کار می‌کند — فقط همان یک تب بنر «برای این از WSL2 استفاده کنید» نشان می‌دهد.

۴ اجرای فرمان‌های شل روی ویندوز

ابزار terminal ی هرمس فرمان‌ها را از طریق Git Bash اجرا می‌کند، همان استراتژی Claude Code. این شکاف POSIX-vs-Windows را بدون بازنویسی هر ابزار دور می‌زند.

ترتیب حل bash.exe:

  1. متغیر محیطی HERMES_GIT_BASH_PATH اگر ست باشد.
  2. ‏%LOCALAPPDATA%\hermes\git\usr\bin\bash.exe ‏(PortableGit مدیریت‌شده توسط نصب‌کننده).
  3. ‏%LOCALAPPDATA%\hermes\git\bin\bash.exe ‏(چیدمان قدیمی‌تر Git-for-Windows).
  4. نصب سیستمی Git-for-Windows ‏(%ProgramFiles%\Git\bin\bash.exe و…).
  5. MSYS2، ‏Cygwin یا هر bash.exe ی روی PATH به‌عنوان آخرین چاره.

نصب‌کننده HERMES_GIT_BASH_PATH را صریحاً ست می‌کند تا نشست‌های PowerShell تازه مجبور به کشف دوباره نباشند. اگر می‌خواهید هرمس bash مشخصی را مصرف کند override اش کنید — مثلاً Git Bash سیستمی‌تان یا bash ی میزبانی-WSL از طریق symlink.

دام: چیدمان MinGit با نصب‌کنندهٔ کامل Git-for-Windows فرق دارد — bash زیر usr\bin\bash.exe زندگی می‌کند نه bin\bash.exe. هرمس هر دو را چک می‌کند. اگر zip ی MinGit را دستی باز می‌کنید مطمئن شوید نوع غیر-busybox را برداشته‌اید ‏(MinGit-*-64-bit.zip نه MinGit-*-busybox*.zip) — buildهای busybox به‌جای bash مقدار ash دارند و بیشتر coreutils ها غایب‌اند.

۵ کنسول UTF-8 روی ویندوز

stdio پیش‌فرض پایتون روی ویندوز از code page فعال کنسول استفاده می‌کند ‏(معمولاً cp1252 یا cp437). بنر هرمس، فهرست دستورات اسلش، فید ابزار، پانل‌های Rich و توضیحات مهارت‌ها همه Unicode دارند. بدون مداخله هرکدام ممکن است با ‏UnicodeEncodeError: 'charmap' codec can't encode character… کرش کند.

اصلاح در ‏hermes_cli/stdio.py::configure_windows_stdio() است که زود در هر نقطهٔ ورود صدا زده می‌شود. این تابع:

  1. code page ی کنسول را با kernel32.SetConsoleCP / SetConsoleOutputCP به CP_UTF8 ‏(۶۵۰۰۱) فلپ می‌کند.
  2. sys.stdout / sys.stderr / sys.stdin را با errors='replace' به UTF-8 reconfigure می‌کند.
  3. PYTHONIOENCODING=utf-8 و PYTHONUTF8=1 را ست می‌کند ‏(با setdefault تا مقادیر صریح کاربر برنده شوند) تا زیرپروسه‌های فرزند پایتون UTF-8 را به ارث برند.
  4. اگر نه EDITOR نه VISUAL ست باشد EDITOR=notepad می‌گذارد ‏(بخش Editor پایین).

Idempotent است. روی غیر-ویندوز no-op.

انصراف: HERMES_DISABLE_WINDOWS_UTF8=1 در محیط به مسیر legacy ی stdio ی cp1252 برمی‌گردد. برای bisect کردن باگ انکودینگ مفید؛ بعید است تنظیم درست در عملیات عادی باشد.

۶ ویرایشگر ‏(Ctrl-X Ctrl-E و ‎/edit‎)

قبل از PR ی ‎#۲۱۵۶۱‎ فشردن Ctrl-X Ctrl-E یا تایپ /edit روی ویندوز بی‌سروصدا هیچ نمی‌کرد. prompt_toolkit فهرست fallback ی لخت-POSIX ثابتی دارد ‏(/usr/bin/nano، ‏/usr/bin/pico، ‏/usr/bin/vi و…) که روی ویندوز هرگز resolve نمی‌شود — حتی با Git for Windows کامل.

shim ی stdio ی ویندوزی هرمس حالا EDITOR=notepad را به‌عنوان پیش‌فرض ست می‌کند. Notepad با هر نصب ویندوز ارسال می‌شود و به‌عنوان ویرایشگر بلاک‌کننده کار می‌کند — ‏subprocess.call(["notepad", file]) تا بسته شدن پنجره بلاک می‌ماند.

override های کاربر همچنان برنده‌اند ‏(قبل از setdefault بررسی می‌شوند):

ویرایشگرفرمان PowerShell
VS Code$env:EDITOR = "code --wait"
Notepad++$env:EDITOR = "'C:\Program Files\Notepad++\notepad++.exe' -multiInst -nosession"
Neovim$env:EDITOR = "nvim"
Helix$env:EDITOR = "hx"

فلگ --wait روی VS Code حیاتی است — بدون آن ویرایشگر فوراً برمی‌گردد و هرمس بافر خالی می‌گیرد.

به‌صورت دائمی در پروفایل PowerShell تان:

# In $PROFILE
$env:EDITOR = "code --wait"

یا به‌عنوان متغیر محیطی User در System Properties تا هر شل جدید بگیردش.

Ctrl+Enter برای newline در CLI

‏Windows Terminal مقدار Ctrl+Enter را به‌عنوان توالی کلید اختصاصی عبور می‌دهد. هرمس آن را به «درج newline» bind کرده تا پرامپت‌های چندخطی را در CLI بدون fallback به Esc-سپس-Enter بسازید. در Windows Terminal، ‏ترمینال یکپارچهٔ VS Code و هر console host ی مدرن ویندوزی که escape sequence های VT را محترم بشمارد کار می‌کند.

روی کنسول‌های legacy ی cmd.exe مقدار Ctrl+Enter به Enter ساده جمع می‌شود — از Esc Enter استفاده کنید یا به Windows Terminal ارتقا دهید ‏(رایگان و روی ویندوز ۱۱ پیش‌فرض است).

۷ اجرای گیت‌وی موقع ورود به ویندوز

‏hermes gateway install روی ویندوز از Scheduled Tasks با fallback ی پوشهٔ Startup استفاده می‌کند — بدون نیاز به admin.

نصب

hermes gateway install

زیر کاپوت:

  1. ‏schtasks /Create /SC ONLOGON /RL LIMITED /TN HermesGateway — ثبت تسکی که موقع ورود شما با مجوزهای استاندارد ‏(غیر-elevated) اجرا شود. بدون پرامپت UAC.
  2. اگر schtasks توسط group policy بلاک شود، به نوشتن shortcut ی start /min cmd.exe /d /c <wrapper> در %APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup برمی‌گردد. همان اثر، کمی ساده‌تر.
  3. گیت‌وی را جدا‌شده از طریق pythonw.exe spawn می‌کند نه python.exe. ‏pythonw.exe کنسول الصاقی ندارد که آن را در برابر broadcast های CTRL_C_EVENT از پروسه‌های خواهر ایمن می‌کند ‏(مسئله واقعی‌ای که قبلاً وقتی در همان process group چیزی را Ctrl+C می‌کردید گیت‌وی را می‌کشت).

فلگ‌های spawn: ‏DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP | CREATE_NO_WINDOW | CREATE_BREAKAWAY_FROM_JOB.

مدیریت

hermes gateway status      # Merged view: schtasks + Startup folder + running PID
hermes gateway start       # Starts the scheduled task now
hermes gateway stop        # Graceful SIGTERM equivalent (TerminateProcess via psutil)
hermes gateway restart
hermes gateway uninstall   # Removes schtasks entry, Startup shortcut, pid file

‏hermes gateway status idempotent است — هزار بار پشت‌سرهم صدا بزنید هرگز تصادفی گیت‌وی را نمی‌کشد ‏(قبل از PR ی ‎#۲۱۵۶۱‎ از طریق برخورد os.kill(pid, 0) با CTRL_C_EVENT در سطح C بی‌سروصدا همین کار را می‌کرد — داستانش در بخش internals ی مدیریت-پروسه پایین).

چرا نه یک Windows Service؟

سرویس‌ها برای نصب admin می‌خواهند و چرخه‌حیات گیت‌وی را به boot ی ماشین گره می‌زنند نه login ی کاربر. کاربر معمول هرمس این را می‌خواهد: وارد شدم ← گیت‌وی حاضر، خارج شدم ← گیت‌وی برود. Scheduled Tasks دقیقاً همین را بدون elevation انجام می‌دهد. اگر واقعاً سرویس می‌خواهید با nssm یا sc create دستی بسازید — ولی احتمالاً نمی‌خواهید.

۸ چیدمان داده و ابزار مرورگر

چیدمان داده

مسیرمحتوا
‏%LOCALAPPDATA%\hermes\hermes-agent\checkout ی git + venv. امن برای Remove-Item -Recurse و نصب دوباره.
‏%LOCALAPPDATA%\hermes\git\PortableGit ‏(فقط اگر نصب‌کننده provision کرده باشد).
‏%LOCALAPPDATA%\hermes\node\Node.js ی portable ‏(فقط اگر نصب‌کننده provision کرده باشد).
‏%LOCALAPPDATA%\hermes\bin\launcher های hermes / hermes-acp و uv.exe ی مدیریت‌شدهٔ هرمس.
‏%LOCALAPPDATA%\hermes\ ‏(ریشه)config، auth، مهارت‌ها، نشست‌ها، لاگ‌های شما ‏(config.yaml، .env، skills\، sessions\، logs\ و…). بین نصب‌ها دوام دارد.

روی ویندوز native نصب‌کننده HERMES_HOME=%LOCALAPPDATA%\hermes را ست می‌کند، پس داده و نصب دور-ریختنی زیر همان ریشهٔ %LOCALAPPDATA%\hermes اند: نصب/runtime زیرپوشه‌های hermes-agent\، ‏git\، ‏node\ و bin\ هستند و فایل‌های داده مستقیماً در %LOCALAPPDATA%\hermes. نصب دوباره فقط checkout ی hermes-agent\ را جایگزین می‌کند پس داده‌تان دوام می‌آورد — ولی چون هر دو یک ریشه دارند اگر داده می‌خواهید نگه دارید هرگز Remove-Item -Recurse %LOCALAPPDATA%\hermes نزنید؛ زیردایرکتوری hermes-agent\ را حذف کنید. شکل دایرکتوری داده‌تان دقیقاً مثل ~/.hermes ی لینوکس است و می‌توانید بین ماشین‌ها mirrorش کنید.

Override ی HERMES_HOME: متغیر محیطی را روی دایرکتوری داده دیگری ست کنید ‏(مثلاً %USERPROFILE%\.hermes تا با چیدمان Linux/WSL یکی شود). مثل لینوکس کار می‌کند.

ابزار مرورگر

  • نصب‌کننده agent-browser را از طریق npm روی PATH می‌گذارد.
  • ‏shutil.which("agent-browser", path=...) shim ی cmd. را خودکار برمی‌دارد — CreateProcessW نمی‌تواند shebang ی بی‌پسوند اجرا کند، پس هرمس همیشه به wrapper ی CMD. حل می‌شود. اسکریپت shebang دار را دستی invoke نکنید؛ همیشه از cmd. بروید.
  • ‏Chromium ی Playwright در اولین اجرا خودنصب می‌شود ‏(npx playwright install chromium). اگر نصب شکست خورد hermes doctor آن را با سرنخ اصلاح surface می‌کند.

۹ یادداشت‌های عملی و عیب‌یابی

PATH بعد از نصب

نصب‌کننده %LOCALAPPDATA%\hermes\bin را با SetEnvironmentVariable به User PATH تان اضافه می‌کند. ترمینال‌های موجود نمی‌گیرندش — بعد از نصب پنجرهٔ PowerShell جدید ‏(یا تب جدید Windows Terminal) باز کنید. ببندید-و-دوباره باز کنید؛ مگر اینکه بدانید چه می‌کنید $env:PATH += … دستی نزنید.

تأیید:

Get-Command hermes        # should print C:\Users\<you>\AppData\Local\hermes\bin\hermes.exe
hermes --version

متغیرهای محیطی

هرمس هم $env:X ‏(scope ی پروسه) و هم متغیرهای محیطی User ‏(دائمی، از System Properties ← Environment Variables) را محترم می‌شمارد. مسیر عادی ست کردن کلیدهای API در ‏%LOCALAPPDATA%\hermes\.env ‏(HERMES_HOME تان) است — مثل لینوکس:

OPENROUTER_API_KEY=sk-or-...
TELEGRAM_BOT_TOKEN=...

secrets را داخل متغیرهای محیطی User نگذارید مگر واقعاً بخواهید هر پروسهٔ ویندوزی ببیندشان ‏(همان نیست که می‌خواهید).

متغیرهای env ی مخصوص-ویندوز

متغیراثر
HERMES_GIT_BASH_PATHبازنویسی کشف bash.exe. به هر bash ی اشاره دهید — Git-for-Windows کامل، ‏bash ی WSL از طریق symlink، ‏MSYS2، ‏Cygwin. نصب‌کننده خودکار ست می‌کند.
HERMES_DISABLE_WINDOWS_UTF8۱ = خاموش کردن shim ی stdio ی UTF-8 و برگشت به code page ی locale. برای bisect باگ انکودینگ.
EDITOR / ‏VISUALویرایشگر شما برای /edit و Ctrl-X Ctrl-E. اگر هر دو unset باشند هرمس پیش‌فرض notepad.

حذف نصب

hermes uninstall

مسیر تمیز همین است — ورودی schtasks، shortcut ی Startup، ‏shim ی hermes.cmd را حذف، ‏%LOCALAPPDATA%\hermes\hermes-agent\ را delete و User PATH را trim می‌کند. بقیهٔ %LOCALAPPDATA%\hermes\ ‏(config، auth، مهارت‌ها، نشست‌ها، لاگ‌ها) را برای نصب دوباره ول می‌کند.

برای نابودی همه‌چیز:

hermes uninstall
Remove-Item -Recurse -Force "$env:LOCALAPPDATA\hermes"
# Also remove a legacy CLI/WSL data dir if you ever used one:
Remove-Item -Recurse -Force "$env:USERPROFILE\.hermes"

زیرفرمان hermes uninstall حالت ثبت شدن ورودی schtasks تحت نام تسک متفاوت ‏(نصب‌های قدیمی) را هم هندل می‌کند — بر اساس مسیر نصب جستجو می‌کند نه نام هاردکد تسک.

internals ی مدیریت پروسه

موارد پس‌زمینه‌ای — مگر اینکه با عجیب‌بودن «داره خودشو می‌کشه» دیباگ می‌کنید skip کنید.

روی لینوکس و macOS اصطلاح POSIX ی os.kill(pid, 0) یک بررسی مجوز no-op است: «این PID زنده است و می‌توانم سیگنال بدهم؟». روی ویندوز os.kill ی پایتون sig=0 را به CTRL_C_EVENT نگاشت می‌کند — در مقدار صحیح ۰ تصادم دارند — و از طریق GenerateConsoleCtrlEvent(0, pid) مسیریابی می‌شود که Ctrl+C را به کل گروه پروسهٔ کنسول حاوی PID هدف broadcast می‌کند. آن ‏bpo-14484 است، از ۲۰۱۲ باز. فیکس نمی‌شود چون تغییرش اسکریپت‌هایی که به رفتار فعلی تکیه دارند را می‌شکند.

نتیجه: هر codepath ی که روی ویندوز «بررسی زنده بودن PID» را با os.kill(pid, 0) می‌گفت بی‌سروصدا هدف را می‌کشت. هرمس هر چنین سایتی ‏(۱۴ مورد در ۱۱ فایل) به gateway.status._pid_exists() مهاجرت داد که از psutil.pid_exists() استفاده می‌کند ‏(که روی ویندوز OpenProcess + GetExitCodeProcess به کار می‌برد — بدون سیگنال). اگر پلاگین یا وصله می‌نویسید مستقیم psutil.pid_exists() یا gateway.status._pid_exists() — هرگز os.kill(pid, 0).

‏scripts/check-windows-footguns.py همین را در CI اجبار می‌کند: هر فراخوانی جدید os.kill(pid, 0) چک «Windows footguns (blocking)» را fail می‌کند مگر خط نشانگر ‏# windows-footgun: ok — <reason> داشته باشد.

دام‌های رایج

‏hermes: command not found درست بعد از نصب.
یک پنجرهٔ PowerShell جدید باز کنید. نصب‌کننده bin را به User PATH اضافه کرده ولی شل‌های موجود باید ری‌استارت شوند. فعلاً می‌توانید & "$env:LOCALAPPDATA\hermes\bin\hermes.exe" را اجرا کنید.

‏WinError 193: %1 is not a valid Win32 application هنگام اجرای ابزار.
به invocation ی اسکریپت-shebang داری خورده‌اید که shim ی cmd. را دور زده. هرمس فرمان‌ها را از طریق shutil.which(cmd, path=local_bin) حل می‌کند تا PATHEXT مقدار CMD. را بگیرد — اگر ابزار را با مسیر هاردکد صدا می‌زنید به نوع cmd. سوئیچ کنید ‏(npx.cmd نه npx).

[scriptblock]::Create(...) با «The assignment expression is not valid» شکست می‌خورد.
دانلود install.ps1 تان BOM ی UTF-8 گرفته. فرم irm | iex خودش BOM را حذف می‌کند؛ ‏scriptblock::Create((irm ...)) نه. با فرم ساده irm | iex دوباره اجرا کنید یا اسکریپت را دستی دانلود و با [IO.File]::WriteAllText($path, $text, (New-Object Text.UTF8Encoding $false)) بدون BOM ذخیره کنید.

گیت‌وی بعد از ری‌استارت بالا نمی‌ماند.
‏hermes gateway status را چک کنید — ورودی schtasks، ‏shortcut ی Startup ‏(اگر استفاده شده) و PID ی زنده را ادغام نشان می‌دهد. اگر schtasks ثبت شده ولی اجرا نیست شاید group policy تریگرهای ONLOGON را بلاک کند. با ‏schtasks /Query /TN HermesGateway /V /FO LIST علت شکست تسک را ببینید یا با HERMES_GATEWAY_FORCE_STARTUP=1 uninstall/reinstall کنید تا مسیر Startup-folder برود.

/edit بعد از ست کردن $env:EDITOR هنوز هیچ نمی‌کند.
فقط در پروسهٔ فعلی ست کرده‌اید؛ شل را ببندید و دوباره باز کنید یا در User scope ی System Properties ← Environment Variables ست کنید. در پنجرهٔ PowerShell جدید با echo $env:EDITOR تأیید کنید.

ابزار مرورگر launch می‌شود ولی ابزارها timeout می‌شوند.
‏Chromium در اولین اجرا خودنصب است. اگر نصب شکست خورده ‏(GitHub ی rate-limit شده، ‏لرزش CDN ی Playwright)، ‏hermes doctor را اجرا کنید — Chromium ی غایب را surface و دقیقاً فرمان npx playwright install chromium را چاپ می‌کند.

agent-browser با خطای عجیب نسخهٔ Node شکست می‌خورد.
نصب‌کننده Node ۲۶ را در %LOCALAPPDATA%\hermes\node provision می‌کند ولی PATH تان ممکن است اول Node ۱۸ سیستمی قدیمی را داشته باشد. یا دایرکتوری node ی هرمس را جلوتر روی PATH ببرید یا اگر جای دیگری Node مصرف نمی‌کنید نصب سیستمی را حذف کنید.

نویسه‌های چینی/ژاپنی/عربی در CLI به‌صورت ? نمایش داده می‌شوند.
shim ی stdio ی UTF-8 فعال نشده. بررسی کنید HERMES_DISABLE_WINDOWS_UTF8 ست نباشد. اگر خالی است و هنوز ؟ می‌بینید شاید console host ‏(cmd.exe خیلی قدیمی) اصلاً UTF-8 را پشتیبانی نکند — به Windows Terminal سوئیچ کنید.

گیت‌وی نمی‌تواند عکس تلگرامی بفرستد — «BadRequest: payload contains invalid characters».
ربطی به ویندوز ندارد ولی گاهی اول همانجا surface می‌شود. معمولاً یعنی مسیر فایل‌تان backslash های unescaped داخل body ی JSON دارد. تلگرام باید مسیرهای نرمال‌شدهٔ هرمس را دریافت کند نه مسیرهای خام ویندوز — اگر داخل پلاگین سفارشی می‌بینیدش مطمئن شوید مسیر تأمین‌شده-توسط-هرمس را پاس می‌دهید نه str(Path(...)) از ورودی کاربر.

عجیب‌بودن انکودینگِ «روی ماشین دیگرم کار می‌کرد» بعد از git pull.
اگر config یا مهارتی از هرمس را روی ویندوز با ویرایشگری غیر-UTF-8 ویرایش کرده باشید ‏(Notepad روی نسخه‌های قدیمی ویندوز، بعضی IME های چینی) فایل ممکن است با BOM ذخیره شده باشد. هرمس utf-8-sig را در اکثر خواندن‌های config تحمل می‌کند ولی BOM داخل scalar ی تاشده ی YAML ‏(description: &) بی‌سروصدا parse ی YAML را می‌شکند. فایل را دوباره به‌صورت UTF-8 ساده بدون BOM ذخیره کنید.
