خانه/کار با Hermes/پیکربندی مدل‌ها

پیکربندی مدل‌ها

هرمس دو نوع جایگاه مدل دارد:

  • مدل اصلی — چیزی که ایجنت با آن فکر می‌کند. هر پیام کاربر، هر حلقهٔ فراخوانی ابزار و هر پاسخ استریم‌شده از این مدل می‌گذرد.
  • مدل‌های کمکی — کارهای جانبیِ کوچک‌تری که ایجنت برون‌سپاری می‌کند. فشرده‌سازی زمینه، بینایی (تحلیل تصویر)، خلاصه‌سازی صفحهٔ وب، امتیازدهی تأیید، مسیریابی ابزار MCP، تولید عنوان نشست و جستجوی مهارت. هر کدام جایگاه خودش را دارد و می‌تواند مستقل بازنویسی شود.

این صفحه پیکربندی هر دو را از داشبورد پوشش می‌دهد. اگر فایل‌های پیکربندی یا CLI را ترجیح می‌دهید، به «روش‌های جایگزین» در پایین بپرید.

💡 سریع‌ترین مسیر: Nous Portal

Nous Portal بیش از ۳۰۰ مدل زیر یک اشتراک ارائه می‌کند. روی نصب تازه، hermes setup --portal را اجرا کنید تا با یک فرمان وارد شوید و Nous ارائه‌دهندهٔ شما شود. آنچه متصل شده را با hermes portal info ببینید.

  • مشترکان پورتال همچنین ۱۰٪ تخفیف روی ارائه‌دهندگان صورت‌حساب-توکنی می‌گیرند.
ℹ️ طرح‌وارهٔ model: — رشتهٔ خالی در برابر نگاشت

در نصب کاملاً تازه، پیکربندی پیش‌فرضِ همراه model: "" دارد (یک نشانگر رشتهٔ خالی به معنی «هنوز پیکربندی نشده»). اولین باری که hermes setup یا hermes model را اجرا کنید، آن کلید درجا به نگاشتی با زیرکلیدهای provider، ‏default، ‏base_url و api_mode ارتقا می‌یابد — شکلی که در سراسر این صفحه می‌بینید. اگر هرگز رشتهٔ خالی در config.yaml دیدید، hermes model را اجرا کنید (یا در داشبورد **Change** را بزنید) و هرمس فرم دیکشنری را برایتان می‌نویسد.

۱ صفحهٔ Models

داشبورد را باز کنید و در سایدبار روی Models کلیک کنید. دو بخش می‌گیرید:

  1. Model Settings — پنل بالایی، جایی که مدل‌ها را به جایگاه‌ها نسبت می‌دهید.
  2. Usage analytics — کارت‌های رتبه‌بندی‌شده که هر مدلی که در بازهٔ انتخابی نشست اجرا کرده را با شمارش توکن، هزینه و نشان‌های قابلیت نشان می‌دهند.

کارت بالایی پنل Model Settings است. سطر اصلی همیشه نشان می‌دهد ایجنت برای نشست‌های جدید چه چیزی راه می‌اندازد. برای باز کردن انتخاب‌گر روی Change کلیک کنید.

۲ تنظیم مدل اصلی

روی سطر Main model روی Change کلیک کنید. انتخاب‌گر دو ستون دارد:

  • چپ — ارائه‌دهندگان احرازشده. فقط ارائه‌دهندگانی که راه‌اندازی کرده‌اید (کلید API تنظیم‌شده، OAuth شده، یا اندپوینت سفارشی تعریف‌شده) اینجا می‌آیند. اگر ارائه‌دهنده‌ای غایب است، به Keys بروید و اعتبارش را اضافه کنید.
  • راست — فهرست گزینش‌شدهٔ مدل‌های ارائه‌دهندهٔ انتخاب‌شده. این‌ها مدل‌های ايجنتی‌ای هستند که هرمس برای آن ارائه‌دهنده توصیه می‌کند، نه خروجی خام /models (که در OpenRouter شامل ۴۰۰+ مدل از جمله TTS، مولدهای تصویر و reranker است).

در جعبهٔ فیلتر تایپ کنید تا بر اساس نام ارائه‌دهنده، اسلاگ یا شناسهٔ مدل محدود شود.

مدلی را بردارید، Switch بزنید، و هرمس آن را در ~/.hermes/config.yaml زیر بخش model می‌نویسد. این فقط به نشست‌های جدید اعمال می‌شود — هر تب چتی که از قبل باز است با همان مدلی که با آن شروع شد به کار ادامه می‌دهد. برای تعویض داغ چت فعلی، از فرمان اسلش /model داخلش استفاده کنید.

تعویض میان-نشستی و هشدارهای زمینه

وقتی داخل نشست فعال مدل را عوض می‌کنید (انتخاب‌گر مدل TUI، ‏CLI هرمس، یا /model در تلگرام/دیسکورد)، هرمس تخمین می‌زند آیا پیام بعدی شما فشرده‌سازی پیش-پروازِ زمینه را مقابل پنجرهٔ مدل جدید اجرا خواهد کرد. اگر نشست از قبل نزدیک یا بالای آستانهٔ فشرده‌سازی آن مدل باشد (به «فشرده‌سازی زمینه» در مستندات پیکربندی مراجعه کنید)، پاسخ تعویض شامل هشداری می‌شود — همان مسیر warning_message که برای اعلان‌های مدل-گران استفاده می‌شود. تعویض همچنان بلافاصله اعمال می‌شود؛ فشرده‌سازی روی اولین پیام کاربر پس از تعویض، قبل از پاسخ مدل اجرا می‌شود.

⚠️ تعویض میان-نشستی کش پرامپت را ریست می‌کند

کش‌های پرامپت به مدلی که درخواست را سرو می‌کند کلید می‌خورند، پس هر تغییر مدلِ وسط گفتگو — تعویض صریح /model، یک fallback خودکار، یا چرخش استخر اعتبارنامه روی حساب متفاوت — یعنی پیام بعدی کل گفتگو را به قیمت کامل توکن ورودی می‌خواند به‌جای نرخ کش‌شده (با ~۷۵–۹۰٪ تخفیف). روی نشست طولانی این خواندن یک‌باره می‌تواند تفاوت به‌ازای-توکن دو مدل را کمرنگ کند. وقتی لازم است عوض کنید، ولی ترجیحاً اوایل گفتگو یا بلافاصله بعد از شروع نشست تازه.

سطح‌های آموزش-داده بدون سرپرست

مدل‌هایی مثل muse-spark-1.2-contributor تخفیف دارند چون فروشنده ممکن است روی پرامپت‌ها و تکمیل‌های شما آموزش ببیند. انتخاب تعاملی مدل همیشه یک اعلان تأیید نشان می‌دهد. مسیرهای شروعِ غیرتعاملی مثل کارگرهای کانبان و ایجنت‌های کرونی، چون نمی‌توانند آن سؤال را بپرسند، ایمن متوقف می‌شوند.

اگر آموزش روی دادهٔ بار کاریِ بدون-سرپرست برایتان قابل‌قبول است، یک اقرار پایدار ثبت کنید:

bash
hermes config set security.allow_data_training_tiers_noninteractive true

هرمس همچنان هشدار کامل سیاست-داده و کلید اقرار را در هر شروعِ بدون-سرپرست چاپ می‌کند، پس لاگ‌های کارگر رد ممیزی نگه می‌دارند. این تنظیم هشدارهای مدل-گران یا مسیریابی ارائه‌دهنده را تأیید نمی‌کند و جایگزین اعلان تأیید تعاملی هم نیست. با hermes config unset security.allow_data_training_tiers_noninteractive لغوش کنید.

۳ تنظیم مدل‌های کمکی

روی Show auxiliary کلیک کنید تا ۱۱ جایگاه کار آشکار شوند. هر کار کمکی به‌طور پیش‌فرض auto است — یعنی هرمس برای آن کار مدل اصلی شما را هم امتحان می‌کند. اگر آن مسیر در دسترس نباشد یا به شکلی از جنس ظرفیت بسوزد، ‏auto ابتدا هر fallback_chain مخصوص-کار را دنبال می‌کند، بعد زنجیرهٔ اصلی fallback_providers / ‏fallback_model، و در نهایت زنجیرهٔ کشف کمکیِ داخلی هرمس. وقتی برای یک کار جانبی مدل ارزان‌تر یا سریع‌تری می‌خواهید، همان کار را بازنویسی کنید.

بازنویسی به‌ازای-کار

روی هر سطر کمکی Change کلیک کنید. همان انتخاب‌گر باز می‌شود، همان رفتار — ارائه‌دهنده + مدل را بردارید و Switch بزنید. سطر به‌جای auto (use main model) نمایش provider · model را می‌گیرد.

ریست همه به auto

اگر بیش‌ازحد تنظیم کرده‌اید و می‌خواهید از نو شروع کنید، بالای بخش کمکی Reset all to auto را بزنید. هر جایگاه به استفاده از مدل اصلی‌تان برمی‌گردد.

۴ میان‌بر «Use as»

هر کارت مدل در صفحه یک دراپ‌داون Use as دارد. این مسیر سریع است — مدلی را که در تحلیل‌هایتان می‌بینید بردارید، Use as را بزنید، و با یک کلیک به جایگاه اصلی یا هر کار کمکی مشخصی نسبتش دهید. گزینه‌های دراپ‌داون:

  • Main model — مثل کلیک Change روی سطر اصلی.
  • All auxiliary tasks — این مدل را یک‌جا به هر ۱۱ جایگاه کمکی نسبت می‌دهد. مفید وقتی همهٔ کارهای جانبی را روی یک مدل flash ارزان می‌خواهید.
  • گزینه‌های کار تکی — ‏Vision، ‏Web Extract، ‏Compression و غیره. مدلِ نسبت‌داده‌شدهٔ فعلی هر کار با current علامت می‌خورد.

کارت‌ها وقتی الان به چیزی نسبت داده شده‌اند نشان main یا aux · <task> می‌گیرند — تا در یک نگاه ببینید کدام مدل‌های تاریخی‌تان کجا وصل‌اند.

۵ چه چیزی در config.yaml نوشته می‌شود

وقتی از داشبورد ذخیره می‌کنید، هرمس در ~/.hermes/config.yaml می‌نویسد:

مدل اصلی:

yaml
model:
  provider: openrouter
  default: anthropic/claude-opus-4.7
  base_url: ''        # با تعویض ارائه‌دهنده پاک می‌شود
  api_mode: chat_completions

بازنویسی کمکی (مثال — بینایی روی gemini-flash):

yaml
auxiliary:
  vision:
    provider: openrouter
    model: google/gemini-2.5-flash
    base_url: ''
    api_key: ''
    timeout: 120
    extra_body: {}
    download_timeout: 30

کمکی روی auto (پیش‌فرض):

yaml
auxiliary:
  compression:
    provider: auto
    model: ''
    base_url: ''
    # ... سایر فیلدها بدون تغییر

provider: auto با model: '' به هرمس می‌گوید برای آن کار از مدل اصلی استفاده کند، در حالی که اگر مسیر اصلی نتوانست فراخوانی کمکی را سرو کند، سیاست fallback همچنان رعایت می‌شود.

زنجیره‌های fallback مخصوص-کارِ اختیاری زیر همان کار کمکی زندگی می‌کنند:

yaml
auxiliary:
  title_generation:
    provider: auto
    model: ''
    fallback_chain:
      - provider: openrouter
        model: inclusionai/ring-2.6-1t:free

وقتی fallback_chain غایب باشد، auto قبل از زنجیرهٔ کشف کمکیِ داخلی، از زنجیرهٔ سطح‌بالا fallback_providers استفاده می‌کند.

۶ گزینه‌های درخواست به‌ازای-ارائه‌دهنده

مدخل‌های ارائه‌دهنده‏ (providers.<name> در دیکشنری providers:، یا آیتم‌های فهرست قدیمی custom_providers) دو پیچ می‌پذیرند که شکل گفتگوی هرمس با اندپوینت را تعیین می‌کنند:

extra_headers — نگاشتی از هدرهای HTTP اضافه که به هر درخواست LLMِ مسیریابی‌شده به base URL آن ارائه‌دهنده الصاق می‌شوند. آخرین اعمال می‌شوند — بعد از پیش‌فرض‌های URL/پروفایل و بازنویسی‌های هدر کاربر — پس از تعویض اعتبارنامه و بازسازی کلاینت جان سالم به در می‌برند. برای توکن‌های سرویس Cloudflare Access، احراز پروکسی یا طرح‌های bearer سفارشی مفید:

yaml
providers:
  my-gateway:
    api: https://llm.internal.example.com/v1
    api_key: sk-...
    extra_headers:
      CF-Access-Client-Id: "xxxx.access"
      CF-Access-Client-Secret: "yyyy"

مقادیر هدر روتین‌آور اعتبارنامه‌اند — هرمس هرگز لاگشان نمی‌کند. extra_headers روی مسیرهای سازگار با OpenAI اعمال می‌شود؛ حالت‌های API مربوط به anthropic_messages و bedrock_converse از آن استفاده نمی‌کنند.

discover_models — روی false بگذارید (پیش‌فرض true) تا پرس‌وجوی فهرست /models اندپوینت رد شود و فقط modelsی که روی مدخل پیکربندی کرده‌اید استفاده شوند. برای گیت‌وی‌هایی که فهرست مدلشان کُند، نامطمئن یا پرهیاهوست دست‌ودل‌باز:

yaml
providers:
  my-gateway:
    api: https://llm.internal.example.com/v1
    discover_models: false
    models:
      - my-finetune-v2
      - my-finetune-v1

با کشف خاموش، انتخاب‌گر مدل‏ (hermes model، ‏/model) فهرست پیکربندی‌شده را به‌جای کاو زنده نشان می‌دهد.

برای یک گیت‌وی سازگار-با-آنتروپیک که نام‌مستقل خالیِ مدل را فقط پس از دریافت درخواست حل می‌کند، نام‌مستقل را با قابلیت به‌ازای-مدل prompt_caching به نشانگرهای کش پرامپتِ بومی بیاورید:

yaml
providers:
  anthropic-proxy:
    api: https://gateway.example.com/anthropic
    transport: anthropic_messages
    models:
      fable:
        context_length: 1000000
        prompt_caching: true

هرمس این اعلام را به مسیر دقیق ارائه‌دهنده و شناسهٔ مدلِ زمان-اجرا تطبیق می‌دهد، بدون بازنویسی نام‌مستقل. prompt_caching: false نشانگرهای کش را برای مدلی صریحاً خاموش می‌کند؛ وقتی حذف باشد، هرمس تشخیص عادی قابلیتِ ارائه‌دهنده و مدلش را نگه می‌دارد.

ℹ️ قالب قدیمی

پیکربندی‌های قدیمی‌تر از فهرست سطح‌بالا custom_providers: استفاده می‌کردند (با base_url به‌جای api). همچنان کار می‌کند و در hermes update خودکار به دیکشنری providers: مهاجرت می‌کند (پیکربندی v12).

۷ چه زمانی اثر می‌کند؟

  • CLI‏ (hermes chat): فراخوانی بعدی hermes chat.
  • گیت‌وی (تلگرام، دیسکورد، اسلک و غیره): *نشستِ جدیدِ* بعدی. نشست‌های موجود مدلشان را نگه می‌دارند. اگر می‌خواهید همهٔ نشست‌ها تغییر را بگیرند گیت‌وی را ری‌استارت کنید‏ (hermes gateway restart).
  • تب چت داشبورد‏ (/chat): PTY جدید بعدی. چتِ بازِ فعلی مدلش را نگه می‌دارد — داخلش از /model برای تعویض داغ استفاده کنید.

تغییرها هرگز کش پرامپت نشست‌های در حال اجرا را بی‌اعتبار نمی‌کنند. این عمدی است: تعویض مدل اصلی داخل نشست ریست کش می‌خواهد (پرامپت سیستمی حاوی محتوای مخصوص-مدل است)، و ما آن را برای فرمان اسلش صریح /model داخل چت نگه داشته‌ایم.

۸ عیب‌یابی

«No authenticated providers» در انتخاب‌گر

هرمس ارائه‌دهنده‌ای را فقط وقتی فهرست می‌کند که اعتبار کاری داشته باشد. Keys را در سایدبار چک کنید — باید یکی از این‌ها را ببینید: کلید API، ‏OAuth موفق، یا URL اندپوینت سفارشی. اگر ارائه‌دهندهٔ موردنظر نیست، hermes setup را اجرا کنید تا متصل شود، یا به Keys بروید و متغیر محیطی را اضافه کنید.

مدل اصلی در چتِ در حال اجرا‌ام عوض نشد

انتظارش همین است. داشبورد config.yaml را می‌نویسد که نشست‌های جدید می‌خوانند. چتِ بازِ فعلی یک پروسهٔ ایجنت زنده است — با همان مدلی که باش تولید شده می‌ماند. برای تعویض داغ همان نشست، داخل چت /model <name> بزنید.

بازنویسی کمکی «اثر نکرد»

سه چیز را چک کنید:

  1. نشست جدید شروع کردید؟ چت‌های موجود پیکربندی را دوباره نمی‌خوانند.
  2. provider چیزی جز auto است؟ اگر فیلد auto نشان می‌دهد، آن کار هنوز از مدل اصلی شما استفاده می‌کند. Change را بزنید و ارائه‌دهندهٔ واقعی بردارید.
  3. ارائه‌دهنده احراز شده؟ اگر minimax را به کاری نسبت داده‌اید ولی کلید MiniMax ندارید، آن کار به پیش‌فرض openrouter برمی‌گردد و هشداری در agent.log لاگ می‌کند.

مدلی برداشتم ولی هرمس ارائه‌دهنده‌ام را عوض کرد

روی OpenRouter (یا هر تجمییع‌گر)، نام‌های خالیِ مدل ابتدا *داخل* تجمیع‌گر حل می‌شوند. پس claude-sonnet-4 روی OpenRouter می‌شود anthropic/claude-sonnet-4.6 و روی احراز OpenRouter شما می‌ماند. ولی اگر claude-sonnet-4 را روی احراز آنتروپیکِ بومی تایپ کرده بودید، همان claude-sonnet-4-6 می‌ماند. اگر تعویض ارائه‌دهندهٔ غیرمنتظره‌ای دیدید، چک کنید ارائه‌دهندهٔ فعلی همان چیزی است که انتظار دارید — انتخاب‌گر همیشه اصلیِ فعلی را بالای دیالوگ نشان می‌دهد.

۹ روش‌های جایگزین

فرمان اسلش CLI

داخل هر نشست hermes chat:

فرمان در چت
/model gpt-5.4 --provider openrouter             # فقط همین نشست
/model gpt-5.4 --provider openrouter --global    # همچنین در config.yaml ماندگار می‌شود
/model claude-opus-4.6 --once                    # فقط نوبت بعدی، سپس خودکار برمی‌گردد

--global همان کاری را می‌کند که دکمهٔ Change داشبورد، به‌علاوه نشست در حال اجرا را درجا سوییچ می‌کند.

--once برای یک نوبت سوییچ می‌کند و بعد مدل قبلی را برمی‌گرداند — در موفقیت، خطا یا وقفه یکسان. هیچ‌چیز ماندگار نمی‌شود: ری‌استارت گیت‌وی وسط نوبت، روی مدل اصلی برمی‌گردد. مفید برای ارتقای یک سؤال سخت به مدل گران‏ («فقط همین یک بار از Opus بپرس») یا سقوط به مدل ارزان برای یک کوئری دورانداختن.

ℹ️ هزینهٔ کش-پرامپت

سوییچ یک‌نوبتی پیشوند کش پرامپت ارائه‌دهنده را دو بار می‌شکند (رفتن و برگشتن). در نشست طولانی روی ارائه‌دهندهٔ پیشوند-کش‌شونده (آنتروپیک، OpenAI)، نوبت بعدی هزینهٔ ورودی کامل می‌دهد — ‏--once برای نشست‌های کوتاه یا ارتقای ارزان←گران برنده است، ولی یک سؤال جانبیِ کوچک داخل نشست گرانِ طولانی می‌تواند بیشتری هزینه کند تا صرفه‌جویی کند.

نام‌مستقل‌های سفارشی

نام‌های کوتاه خودتان را برای مدل‌هایی که زیاد سراغشان می‌روید تعریف کنید، بعد در CLI یا هر پلتفرم پیام‌رسانی /model <alias> بزنید. دو قالب هم‌ارز هست — هر کدام را که با گردش‌کارتان می‌خواند بردارید.

متعارف (سطح‌بالا model_aliases:) — کنترل کامل روی provider + base_url:

yaml — ~/.hermes/config.yaml
model_aliases:
  fav:
    model: claude-sonnet-4.6
    provider: anthropic
  grok:
    model: grok-4
    provider: x-ai

فرم رشتهٔ کوتاه‏ (model.aliases.<name>: provider/model) — از شل راحت است چون hermes config set اسکالرها را می‌نویسد و حالا لفظ‌های درون‌خطی فهرست/نگاشت را هم تجزیه می‌کند، هرچند این فرم کوتاه هنوز base_url سفارشی حمل نمی‌تواند:

bash
hermes config set model.aliases.fav anthropic/claude-opus-4.6
hermes config set model.aliases.grok x-ai/grok-4

hermes config set همچنین لفظ‌های فهرست/نگاشت درون‌خطی (سبک جریان JSON/YAML) را می‌پذیرد. گیومه بزنید تا شل سالم ردشان کند:

bash
hermes config set platform_toolsets.line '["clarify", "file", "web"]'
hermes config set display.tool_progress_overrides '{"terminal": "off"}'

هر دو مسیر به همان بارگذار می‌ریزند‏ (hermes_cli/model_switch.py). مدخل‌های model_aliases: بر مدخل‌های هم‌نام model.aliases: مقدم‌اند.

سپس در چت /model fav یا /model grok. نام‌مستقل‌های کاربر، نام‌های کوتاه داخلی‏ (sonnet، ‏kimi، ‏opus و غیره) را سایه می‌اندازند. برای مرجع کامل به «نام‌مستقل‌های سفارشی مدل» در مرجع فرمان‌های اسلش مراجعه کنید.

زیرفرمان hermes model

bash
hermes model            # انتخاب‌گر تعاملی ارائه‌دهنده + مدل (روش متعارف تعویض پیش‌فرض‌ها)

hermes model شما را از انتخاب ارائه‌دهنده، احراز هویت‏ (جریان‌های OAuth مرورگر باز می‌کنند؛ ارائه‌دهندگان کلید-API برای کلید می‌پرسند) و سپس انتخاب مدل مشخصی از کاتالوگ گزینش‌شدهٔ همان ارائه‌دهنده عبور می‌دهد. انتخاب در model.provider و model.default در ~/.hermes/config.yaml نوشته می‌شود.

برای فهرست‌کردن ارائه‌دهندگان/مدل‌ها بدون اجرای انتخاب‌گر، از داشبورد یا اندپوینت‌های REST پایین استفاده کنید. برای دیدن آنچه CLI الان واقعاً استفاده می‌کند: hermes config get model --json و hermes status.

ویرایش مستقیم پیکربندی

~/.hermes/config.yaml را ویرایش و هرچه آن را می‌خواند ری‌استارت کنید. برای طرح‌وارهٔ کامل به «مرجع پیکربندی» مراجعه کنید.

‏REST API

داشبورد از سه اندپوینت استفاده می‌کند. برای اسکریپت‌نویسی مفید:

bash
# فهرست ارائه‌دهندگان احرازشده + فهرست‌های گزینش‌شدهٔ مدل
curl -H "X-Hermes-Session-Token: $TOKEN" http://localhost:PORT/api/model/options

# خواندن نسبت‌های فعلی اصلی + کمکی
curl -H "X-Hermes-Session-Token: $TOKEN" http://localhost:PORT/api/model/auxiliary

# تنظیم مدل اصلی
curl -X POST -H "Content-Type: application/json" -H "X-Hermes-Session-Token: $TOKEN" \
  -d '{"scope":"main","provider":"openrouter","model":"anthropic/claude-opus-4.7"}' \
  http://localhost:PORT/api/model/set

# بازنویسی یک کار کمکی
curl -X POST -H "Content-Type: application/json" -H "X-Hermes-Session-Token: $TOKEN" \
  -d '{"scope":"auxiliary","task":"vision","provider":"openrouter","model":"google/gemini-2.5-flash"}' \
  http://localhost:PORT/api/model/set

# نسبت یک مدل به همهٔ کارهای کمکی
curl -X POST -H "Content-Type: application/json" -H "X-Hermes-Session-Token: $TOKEN" \
  -d '{"scope":"auxiliary","task":"","provider":"openrouter","model":"google/gemini-2.5-flash"}' \
  http://localhost:PORT/api/model/set

# ریست همهٔ کارهای کمکی به auto
curl -X POST -H "Content-Type: application/json" -H "X-Hermes-Session-Token: $TOKEN" \
  -d '{"scope":"auxiliary","task":"__reset__","provider":"","model":""}' \
  http://localhost:PORT/api/model/set

توکن نشست هنگام شروع در HTML داشبورد تزریق و با هر ری‌استارت سرور می‌چرخد. اگر به داشبوردِ در حال اجرا اسکریپت می‌زنید، از devtools مرورگر بگیریدش‏ (window.__HERMES_SESSION_TOKEN__).
