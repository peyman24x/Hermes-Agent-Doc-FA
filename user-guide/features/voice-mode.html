حالت صوتی ‏(Voice Mode)

هرمس ایجنت از تعامل صوتی کامل در CLI و پلتفرم‌های پیام‌رسانی پشتیبانی می‌کند. با میکروفون با ایجنت حرف بزنید، پاسخ گفتاری بشنوید و در کانال‌های صوتی دیسکورد مکالمات صوتی زنده داشته باشید.

اگر یک مرور عملی راه‌اندازی با پیکربندی‌های توصیه‌شده و الگوهای واقعی مصرف می‌خواهید، بخش Use Voice Mode with Hermes را ببینید.

برای شروع نشست بدون-دست — گفتن «hey hermes» ‏(یا هر عبارتی) برای باز کردن نشست صوتی تازه در CLI، TUI یا اپ دسکتاپ — بخش واژهٔ بیدارباش را ببینید.

۱ پیش‌نیازها

قبل از استفاده از قابلیت‌های صوتی مطمئن شوید:

  1. ‏Hermes Agent نصب شده — از طریق اسکریپت نصب ‏(بخش نصب)
  2. یک ارائه‌دهندهٔ LLM پیکربندی شده — ‏hermes model را اجرا یا اعتبارنامهٔ ارائه‌دهندهٔ موردعلاقه‌تان را در ‏~/.hermes/.env ست کنید
  3. یک setup پایه کارا دارید — ‏hermes را اجرا کنید تا قبل از فعال کردن صوت تأیید شود ایجنت به متن جواب می‌دهد
💡

دایرکتوری ‏~/.hermes/ و config.yaml ی پیش‌فرض اولین بار که ‏hermes را اجرا کنید خودکار ساخته می‌شوند. فقط ‏~/.hermes/.env را برای کلیدهای API دستی می‌سازید.

💡 Nous Portal هر دو را پوشش می‌دهد

اشتراک پولی Nous Portal هم LLM را ‏(گام ۲) تأمین می‌کند و TTS ی OpenAI را از طریق Tool Gateway — بدون نیاز به کلید جداگانهٔ OpenAI. روی نصب تازه، ‏hermes setup --portal هر دو را یکجا سیم‌کشی می‌کند.

پکیج‌های پایتون

# CLI voice mode (microphone + audio playback)
cd ~/.hermes/hermes-agent && uv pip install -e ".[voice]"

# Discord + Telegram messaging (includes discord.py[voice] for VC support)
cd ~/.hermes/hermes-agent && uv pip install -e ".[messaging]"

# Premium TTS (ElevenLabs)
cd ~/.hermes/hermes-agent && uv pip install -e ".[tts-premium]"

# Local TTS (NeuTTS, optional)
python -m pip install -U neutts[all]

# Everything at once
cd ~/.hermes/hermes-agent && uv pip install -e ".[all]"

کلیدهای API

به ‏~/.hermes/.env اضافه کنید:

# Speech-to-Text — local provider needs NO key at all
# pip install faster-whisper          # Free, runs locally, recommended
GROQ_API_KEY=your-key                 # Groq Whisper — fast, free tier (cloud)
VOICE_TOOLS_OPENAI_KEY=your-key       # OpenAI Whisper — paid (cloud)

# Text-to-Speech (optional — Edge TTS and NeuTTS work without any key)
ELEVENLABS_API_KEY=***           # ElevenLabs — premium quality
# VOICE_TOOLS_OPENAI_KEY above also enables OpenAI TTS
💡

اگر ‏faster-whisper نصب باشد، حالت صوتی برای STT با صفر کلید API کار می‌کند. مدل ‏(~۱۵۰MB برای base) در اولین استفاده خوددانلود می‌شود.

۳ حالت صوتی CLI

حالت صوتی هم در CLI کلاسیک ‏(hermes chat) و هم در TUI ‏(hermes --tui) موجود است. رفتار در هر دو یکسان است — همان دستورات اسلش، همان آشکارساز سکوت VAD، همان استریم TTS، همان فیلتر توهم. TUI به‌علاوه لاگ‌های جنایی-کرش را به ‏~/.hermes/logs/ forward می‌کند تا شکست‌های push-to-talk روی بک‌اندهای صوتی نادر با stack trace کامل گزارش شوند نه اینکه بی‌سروصدا غیب شوند.

شروع سریع

CLI را شروع و حالت صوتی را روشن کنید:

hermes                # Start the interactive CLI

سپس این فرمان‌ها را داخل CLI استفاده کنید:

/voice          Toggle voice mode on/off
/voice on       Enable voice mode
/voice off      Disable voice mode
/voice tts      Toggle TTS output
/voice status   Show current state

نحوهٔ کار

  1. CLI را با ‏hermes شروع و حالت صوتی را با ‏/voice on روشن کنید
  2. Ctrl+B را فشار دهید — بیپ پخش ‏(۸۸۰Hz) می‌شود، ضبط شروع می‌شود
  3. حرف بزنید — نوار سطح صدای زنده ورودی شما را نشان می‌دهد: ‏● [▁▂▃▅▇▇▅▂] ❯
  4. حرف زدن را تمام کنید — بعد از ۳ ثانیه سکوت ضبط خودکار تمام می‌شود
  5. دو بیپ پخش می‌شود ‏(۶۶۰Hz) تأیید پایان ضبط
  6. صدا با Whisper رونویسی و به ایجنت فرستاده می‌شود
  7. اگر TTS فعال باشد پاسخ ایجنت بلند خوانده می‌شود
  8. ضبط خودکار ری‌استارت می‌شود — دوباره حرف بزنید بدون فشار هیچ کلیدی

این حلقه ادامه می‌یابد تا اینکه هنگام ضبط Ctrl+B بزنید ‏(خروج از حالت پیوسته) یا ۳ ضبط متوالی هیچ سخنی آشکار نکنند.

💡

کلید ضبط از طریق ‏voice.record_key در ‏~/.hermes/config.yaml قابل‌پیکربندی است ‏(پیش‌فرض: ‏ctrl+b).

آشکارسازی سکوت

الگوریتم دومرحله‌ای تشخیص می‌دهد کی حرف زدنتان تمام شده:

  1. تأیید گفتار — منتظر صدای بالای آستانهٔ RMS ‏(۲۰۰) دست‌کم ‎۰٫۳ ثانیه می‌ماند و افت‌های کوتاه بین هجاهارا تحمل می‌کند
  2. آشکارسازی پایان — وقتی گفتار تأیید شد، بعد از ‎۳٫۰ ثانیه سکوت پیوسته شلیک می‌کند

اگر اصلاً طی ۱۵ ثانیه هیچ سخنی آشکار نشود ضبط خودکار تمام می‌شود.

هر ‏silence_threshold و ‏silence_duration در config قابل‌پیکربندی‌اند. بیپ‌های شروع/توقف ضبط را هم می‌توانید با ‏voice.beep_enabled: false خاموش کنید.

پایان دادن به چت صوتی با صدا

بگویید «stop» — و هیچ چیز دیگر — تا مکالمهٔ صوتی بدون-دست تمام شود. تطبیق عمداً سخت‌گیرانه است: کل گفته ‏(بدون حساسیت به بزرگی حروف و نقطه‌گذاری اطراف) باید برابر یک عبارت پیکربندی‌شده باشد، پس «stop doing that and try X instead» همچنان عادی به ایجنت می‌رسد. فهرست عبارت‌ها را با ‏voice.stop_phrases در config سفارشی کنید ‏(مثلاً ‏["stop", "goodbye hermes"]) یا برای غیرفعال شدن روی ‏[] بگذارید. چت صوتی بعد از سه چرخهٔ سکوت متوالی ‏(آشکار نشدن گفتار) هم خودش تمام می‌شود.

تایپ کردن یک عبارت stop ی لخت وقتی چت صوتی فعاله روی همهٔ سطوح ‏(CLI، TUI، دسکتاپ) همین‌طور کار می‌کند: پیام به‌جای رسیدن به ایجنت چت صوتی را تمام می‌کند. خارج از چت صوتی، تایپ «stop» پیامی عادی است.

استریم TTS

وقتی TTS فعاله، ایجنت پاسخش را همزمان با تولید متن جمله‌به-جمله می‌گوید — منتظر پاسخ کامل نمی‌مانید. این با هر ارائه‌دهندهٔ TTS کار می‌کند:

  1. دلتاهای متن را در جمله‌های کامل بافر می‌کند ‏(حداقل ۲۰ نویسه)
  2. فرمت markdown، ایموجی و بلوک‌های ‏<think> را می‌زداید
  3. صدای هر جمله را بلادرنگ پخش می‌کند — ارائه‌دهنده‌های دارای API ی PCM chunked ‏(ElevenLabs، ‏OpenAI) صدای خام را برای کمترین زمان-تا-اولین-واژه استریم می‌کنند؛ بقیهٔ ارائه‌دهنده‌ها ‏(شامل Edge پیش‌فرض) هر جمله را همین که کامل شد ترکیب و پخش می‌کنند

همان خط‌لوله در CLI کلاسیک، TUI و اپ دسکتاپ اجرا می‌شود. در گفتگوی صوتی دسکتاپ متن پاسخ زنده داخل یک WebSocket گفتارِ per-reply تزریق می‌شود همزمان با تولید مدل، پس گفتار روی تولید سوار می‌شود — یک socket و یک ساعت صوتی per-reply، بدون شکاف اتصال بین جملات.

Barge-in

می‌توانید ایجنت را در هر لحظه از نوبتش قطع کنید — میکروفون از لحظه‌ای که حرف زدن تمام می‌کنید تا پخش کامل پاسخ زنده می‌ماند ‏(فول‌دوبلکس):

  • میان حرف بزنید وقتی دارد فکر می‌کند — در حالت صوتی پیوسته، حرف زدن حین تولید LLM ‏(قبل از پخش هر صوتی) نوبت در-جریان را قطع و میان‌جمله‌تان تبدیل به پیام بعدی می‌شود، مثل اینکه روی یک نوبت درحال-اجرا تایپ کرده باشید.
  • روی صدایش حرف بزنید — حرف زدن هنگام پخش پاسخ، پخش را همان لحظه که شروع به صحبت می‌کنید قطع و گفته‌تان را ثبت می‌کند. آشکارساز کف نویزش را نسبت به اتاق ساکت در شروع نوبت کالیبره می‌کند ‏(هرگز نسبت به خود پخش)، پس نشت اسپیکر کرش نمیشود و گفتار عادی قابل‌اعتماد آن را شلیک می‌کند.
  • تایپ کنید یا کلید ضبط را بزنید — فرستادن پیام جدید یا فشار کلید push-to-talk پخش را روی همهٔ سطوح فوراً متوقف می‌کند.
  • بگویید «stop» — عبارت stop در هر دو فاز کار می‌کند: وسط تولید هم نوبت را قطع و هم چت صوتی را تمام می‌کند؛ وسط پخش گفتار را قطع و چت را می‌بندد.

تنظیم دقیق ‏(config.yaml): ‏voice.barge_in: false غیرفعالش می‌کند؛ ‏voice.barge_in_threshold_multiplier ‏(پیش‌فرض ‏۳٫۰) تریگر گفتار را روی کف اتاق-ساکت مقیاس می‌دهد؛ ‏voice.barge_in_grace_seconds ‏(پیش‌فرض ‏۰٫۵) شلیک‌ها را درست بعد از شروع پخش سرکوب می‌کند. ‏HERMES_VOICE_DEBUG=1 را ست کنید تا تشخیص‌های VAD هر-بلوک ‏(کف کالیبره‌شده، ‏RMS، تصمیم‌های شلیک) برای تنظیم زنده به stderr استریم شود.

ایجنت می‌داند قطع شده: پیام بعدی یادداشت کوتاهی حمل می‌کند که به مدل می‌گوید پاسخ گفتاریش بریده شده، تا بتواند طبیعی واکنش نشان دهد ‏(«چه بی‌ادبی!») یا از همان‌جا که مانده بود ادامه دهد به‌جای بی‌خبری.

فیلتر توهم

‏Whisper گاهی از سکوت یا نویز پس‌زمینه متن شبح‌وار تولید می‌کند ‏(«Thank you for watching»، ‏«Subscribe» و…). ایجنت اینها را با مجموعه‌ای از ۲۶ عبارت توهم شناخته‌شده در چند زبان به‌علاوهٔ یک الگوی regex یگیرندهٔ تنوع‌های تکراری فیلتر می‌کند.

۴ پاسخ صوتی گیت‌وی ‏(تلگرام و دیسکورد)

اگر هنوز بات‌های پیام‌رسانی‌تان را راه نینداخته‌اید راهنماهای مخصوص پلتفرم را ببینید: بخش راه‌اندازی تلگرام و بخش راه‌اندازی دیسکورد.

گیت‌وی را شروع کنید تا به پلتفرم‌های پیام‌رسانی وصل شوید:

hermes gateway        # Start the gateway (connects to configured platforms)
hermes gateway setup  # Interactive setup wizard for first-time configuration

دیسکورد: کانال‌ها در برابر DM ها

ربات دو حالت تعامل روی دیسکورد پشتیبانی می‌کند:

حالتچطور حرف بزنیدمنشن لازم؟راه‌اندازی
پیام مستقیم ‏(DM)پروفایل ربات را باز کنید ← «Message»نهفوری کار می‌کند
کانال سروردر یک کانال متنی که ربات حضور دارد تایپ کنیدبله ‏(@botname)ربات باید به سرور دعوت شده باشد

DM ‏(توصیه‌شده برای استفاده شخصی): فقط یک DM با ربات باز کنید و تایپ کنید — بدون نیاز به @mention. پاسخ‌های صوتی و همهٔ فرمان‌ها مثل کانال‌ها کار می‌کنند.

کانال‌های سرور: ربات فقط وقتی @mention اش کنید جواب می‌دهد ‏(مثلاً ‏@hermesbyt4 hello). مطمئن شوید کاربرِ ربات را از popup منشن انتخاب می‌کنید نه role ی همنام را.

💡

برای غیرفعال کردن الزام منشن در کانال‌های سرور به ‏~/.hermes/.env اضافه کنید:
DISCORD_REQUIRE_MENTION=false
یا کانال‌های مشخص را آزاد-پاسخ کنید ‏(بدون نیاز به منشن):
DISCORD_FREE_RESPONSE_CHANNELS=123456789,987654321

۵ کانال‌های صوتی دیسکورد

غرق‌کننده‌ترین قابلیت صوتی: ربات به کانال صوتی دیسکورد می‌پیوندد، به حرف زدن کاربران گوش می‌دهد، گفتارشان را رونویسی، از خط‌لوله ایجنت عبور و پاسخ را در همان کانال صوتی می‌گوید.

Message Content Intentخواندن محتوای پیام متنی در کانال‌ها

Message Content Intent الزامی است. ‏Server Members Intent فقط وقتی لازم است که فهرست DISCORD_ALLOWED_USERS تان از نام کاربری استفاده کند — اگر از ID عددی استفاده می‌کنید می‌توانید OFF بگذارید. نگاشت SSRC ی کانال صوتی ← user_id از opcode ی SPEAKING دیسکورد روی websocket صوتی می‌آید و نیازی به Server Members Intent ندارد.

۳. کدک Opus

کتابخانهٔ کدک Opus باید روی ماشینی که گیت‌وی را اجرا می‌کند نصب باشد:

# macOS (Homebrew)
brew install opus

# Ubuntu/Debian
sudo apt install libopus0

ربات کدک را از این مسیرها auto-load می‌کند:

  • macOS: ‏/opt/homebrew/lib/libopus.dylib
  • لینوکس: ‏libopus.so.0

# ~/.hermes/.env

# Discord bot (already configured for text)

شروع گیت‌وی

hermes gateway        # Start with existing configuration

ربات باید ظرف چند ثانیه در دیسکورد آنلاین شود.

فرمان‌ها

اینها را در کانال متنی دیسکوردی که ربات حضور دارد استفاده کنید:

/voice join      Bot joins your current voice channel
/voice channel   Alias for /voice join
/voice leave     Bot disconnects from voice channel
/voice status    Show voice mode and connected channel
📌

قبل از اجرای ‏/voice join باید خودتان در یک کانال صوتی باشید. ربات به همان VC ی شما می‌پیوندد.

نحوهٔ کار

وقتی ربات به کانال صوتی می‌پیوندد:

  1. گوش می‌دهد به استریم صدای هر کاربر به‌طور مستقل
  2. سکوت را آشکار می‌کند — ‏۱٫۵ ثانیه سکوت بعد از حداقل ‎۰٫۵ ثانیه گفتار پردازش را شلیک می‌کند
  3. رونویسی می‌کند صدا را با Whisper STT ‏(محلی، ‏Groq یا OpenAI)
  4. پردازش می‌کند از کل خط‌لوله ایجنت ‏(نشست، ابزارها، حافظه)
  5. می‌گوید پاسخ را در همان کانال صوتی از طریق TTS

یکپارچگی کانال متنی

وقتی ربات در کانال صوتی است:

  • رونوشت‌ها در کانال متنی ظاهر می‌شوند: ‏[Voice] @user: what you said
  • پاسخ‌های ایجنت هم به‌صورت متن در کانال فرستاده و هم در VC گفته می‌شوند
  • کانال متنی همان است که ‏/voice join در آن صادر شده

جلوگیری از اکو

ربات حین پخش پاسخ‌های TTS شنوندهٔ صوتی‌اش را خودکار pause می‌کند تا صدای خودش را نشنود و دوباره پردازش نکند.

کنترل دسترسی

فقط کاربران فهرست‌شده در ‏DISCORD_ALLOWED_USERS می‌توانند از طریق صوت تعامل کنند. صدای سایر کاربران بی‌صدا نادیده گرفته می‌شود.

# ~/.hermes/.env
DISCORD_ALLOWED_USERS=284102345871466496

۸ عیب‌یابی

«No audio device found» ‏(CLI)

PortAudio نصب نیست:

brew install portaudio    # macOS
sudo apt install portaudio19-dev  # Ubuntu

اگر هرمس را داخل Docker روی دسکتاپ لینوکس اجرا می‌کنید، کانتینر به socket صدای میزبان هم نیاز دارد. یادداشت‌های پل صوتی Docker را برای setup سازگار با PulseAudio/PipeWire ببینید.

ربات در کانال‌های سرور دیسکورد جواب نمی‌دهد

ربات به‌طور پیش‌فرض در کانال‌های سرور @mention می‌خواهد. مطمئن شوید:

  1. ‏@ را تایپ و کاربرِ ربات را انتخاب می‌کنید ‏(با discriminator)، نه role ی همنام
  2. یا به‌جایش از DM استفاده کنید — بدون نیاز به منشن
  3. یا ‏DISCORD_REQUIRE_MENTION=false را در ‏~/.hermes/.env ست کنید

ربات به VC می‌پیوندد ولی صدایم را نمی‌شنود

  • بررسی کنید ID کاربر دیسکوردتان در ‏DISCORD_ALLOWED_USERS باشد
  • مطمئن شوید در دیسکورد mute نیستید
  • ربات قبل از نگاشت صدایتان به یک رویداد SPEAKING از دیسکورد نیاز دارد — چند ثانیه بعد از پیوستن شروع به حرف زدن کنید

ربات می‌شنود ولی جواب نمی‌دهد

  • تأیید کنید STT در دسترس است: ‏faster-whisper را نصب کنید ‏(بدون کلید) یا ‏GROQ_API_KEY / ‏VOICE_TOOLS_OPENAI_KEY ست کنید
  • بررسی کنید مدل LLM پیکربندی و قابل‌دسترس است
  • لاگ‌های گیت‌وی را مرور کنید: ‏tail -f ~/.hermes/logs/gateway.log

ربات در متن جواب می‌دهد ولی در کانال صوتی نه

  • شاید ارائه‌دهندهٔ TTS شکست می‌خورد — کلید API و سهمیه را چک کنید
  • Edge TTS ‏(رایگان، بدون کلید) fallback پیش‌فرض است
  • لاگ‌ها را برای خطاهای TTS بررسی کنید

Whisper متن آشغال برمی‌گرداند

فیلتر توهم بیشتر موارد را خودکار می‌گیرد. اگر هنوز transcript های شبح‌وار می‌گیرید:

  • محیط ساکت‌تری استفاده کنید
  • ‏silence_threshold را در config تنظیم کنید ‏(بالاتر = کم‌حساس‌تر)
  • مدل STT دیگری امتحان کنید
