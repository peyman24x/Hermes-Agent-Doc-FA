کاتالوگ افزونه‌ها

کاتالوگ افزونه‌ها فهرستی گزینش‌شده از افزونه‌های هرمس است که انسان‌ها آن‌ها را بازبینی کرده‌اند. می‌توانید هر افزونه را با نامش و تنها با یک فرمان نصب کنید:

hermes plugins install <name>

برای مرور تصویری کاتالوگ به /docs/plugins بروید. مدخل‌ها در دسته‌های حافظه، دسکتاپ، پلتفرم‌ها، وب و مرورگر، ابزارها، صدا، اتوماسیون و مدل‌ها قرار گرفته‌اند. جستجو، فیلتر سطح (رسمی / جامعهٔ کاربری)، برچسب‌های قابلیت و فرمان نصبِ قابل‌کپی برای هر مدخل در دسترس است.

کاتالوگ مکمل سیستم افزونه‌ها است، نه جایگزین آن. هر چیزی که از کاتالوگ نصب می‌کنید، در اصل یک افزونهٔ معمولی است؛ کاتالوگ فقط امکان کشف افزونه‌ها و یک لایهٔ بازبینی به آن اضافه می‌کند.

۱ هر مدخل شامل چه چیزهایی است

هر مدخل کاتالوگ یک فایل کوچک YAML در پوشهٔ plugin-catalog/ از مخزن hermes-agent است که موارد زیر را مشخص می‌کند:

فیلدمعنا
nameکلید کاتالوگ که به hermes plugins install می‌دهید
repoمخزن عمومی گیتِ افزونه
shaشناسهٔ دقیقِ ۴۰کاراکتریِ شانزده‌شانزدهیِ کامیت بازبینی‌شده — هنگام نصب، همین کامیتِ پین‌شده دریافت می‌شود، نه آخرین کامیت شاخه
tierofficial (با نگهداری NousResearch) یا community
categoryدسته برای مرور: desktop (پیش‌فرض)، memory، platform، web، tools، voice، automation، models یا general
maintainerمسئول افزونه
capabilitiesابزارها، هوک‌ها، میان‌افزارها و متغیرهای محیطیِ موردنیازِ اعلام‌شده
requires_hermesحداقل نسخهٔ هرمس، مثلاً >=0.19 (اختیاری)
platformsمحدودیت‌های سیستم‌عامل؛ خالی یعنی همه (اختیاری)
docs_urlپیوند به مستندات خارجی (اختیاری)

۲ مدل اعتماد

کاتالوگ طوری طراحی شده که دقیقاً بدانید چه چیزی نصب می‌کنید:

  • پذیرش با بازبینی و ادغام انسانی. هر مدخل و هر به‌روزرسانیِ کامیت پین‌شده از طریق یک درخواست ادغام (PR) وارد می‌شود که یکی از نگهدارندگان آن را بازبینی کرده است. هیچ چیز به‌طور خودکار وارد کاتالوگ نمی‌شود.
  • پین‌کردن SHA دقیق. مدخل‌ها به یک کامیت مشخص مقیدند، نه به یک شاخه. ارسال کد جدید به مخزن از سوی نویسندهٔ افزونه، آنچه کاتالوگ نصب می‌کند را تغییر نمی‌دهد؛ تغییر کامیت پین‌شده به یک PR بازبینی‌شدهٔ دیگر نیاز دارد.
  • اعلام قابلیت‌ها. مدخل‌ها از ابتدا مشخص می‌کنند افزونه چه ابزارها، هوک‌ها و میان‌افزارهایی ارائه می‌دهد و به چه متغیرهای محیطی‌ای (کلیدهای API و مانند آن) نیاز دارد، تا پیش از نصب بتوانید دامنهٔ اثرگذاری آن را ارزیابی کنید.
  • فهرست حذف‌شده‌ها. افزونه‌هایی که از کاتالوگ کنار گذاشته می‌شوند (مثلاً پس از یک رخداد امنیتی)، همراه با دلیل و تاریخ در plugin-catalog/removed.yaml ثبت می‌شوند. نصب‌کننده از نصب هر موردی در این فهرست خودداری می‌کند.
  • نصب‌شده ≠ فعال‌شده. نصب افزونه از کاتالوگ فقط آن را روی دیسک قرار می‌دهد؛ مانند هر افزونهٔ دیگری، پیش از بارگذاری باید فعال شود. به «افزونه‌ها ← فعال‌سازی و غیرفعال‌سازی» مراجعه کنید.
بازبینی کاتالوگ فقط به یک مقطع زمانی مربوط است

وجود یک مدخل در کاتالوگ یعنی یک انسان کامیت پین‌شده را بررسی کرده، قابلیت‌های اعلام‌شده بررسی شده‌اند و مخزن شرایط پذیرش را داشته است. این بررسی ممیزی امنیتی نیست و دربارهٔ کامیت‌های دیگر همان مخزن چیزی نمی‌گوید. کد هر چیزی را که اطلاعات احراز هویت در اختیارش می‌گذارید، بازبینی کنید.

۳ نصب از کاتالوگ

# Install a reviewed catalog entry by name (checks out the pinned SHA)
hermes plugins install <name>

# Then enable it, as with any plugin
hermes plugins enable <name>

پیش از کلون‌شدن هر چیزی، پیام تأیید نصب خلاصهٔ قابلیت‌های مدخل — ابزارها، هوک‌ها و متغیرهای محیطیِ موردنیازِ اعلام‌شده — را نمایش می‌دهد.

نام مدخل در کاتالوگ ممکن است با نام خود افزونه در مانیفست فرق داشته باشد؛ hermes plugins install نام نصب‌شده را چاپ می‌کند و enable همان نام را می‌پذیرد. مثلاً مدخل touchdesigner (یک بستهٔ قابل‌حمل مطابق نسخهٔ ۱ استاندارد Agent Plugins که سرور MCPِ twozero را همراه با مهارت touchdesigner-mcp عرضه می‌کند) با نام td نصب می‌شود. این نام کوتاه نگه داشته شده تا نام ابزارهای MCPِ تولیدشده از محدودیت طول نام تابع نزد ارائه‌دهندگان فراتر نرود:

hermes plugins install touchdesigner
hermes plugins enable td

بسته‌های قابل‌حمل می‌توانند یک سرور MCP با ارتباط stdio نیز همراه داشته باشند. مدخل snyk نسخهٔ Snyk CLI را پین می‌کند (npx -y snyk@<version> mcp) و مهارت snyk-security-scan را همراه خود دارد. بنابراین با یک نصب، هرمس امکان اسکن کد، وابستگی‌ها، کانتینرها و زیرساخت به‌صورت کد (IaC)، به‌همراه گردش‌کار استفاده از آن را به دست می‌آورد. نام کاتالوگ و مانیفست در این مورد یکسان است:

hermes plugins install snyk
hermes plugins enable snyk

به‌روزرسانی افزونهٔ نصب‌شده از کاتالوگ

فرمان hermes plugins update <name> برای افزونه‌های نصب‌شده از کاتالوگ هرگز git pull اجرا نمی‌کند؛ کامیت پین‌شدهٔ نصب شما را با کامیت پین‌شدهٔ فعلی کاتالوگ مقایسه می‌کند و اگر کاتالوگ از طریق یک PR بازبینی‌شده تغییر کرده باشد، افزونه را به‌اجبار در SHA جدید دوباره نصب می‌کند. وضعیت فعال یا غیرفعال‌بودن افزونه حفظ می‌شود. فرمان hermes plugins list نصب‌های کاتالوگ را به‌شکل catalog:<tier>@<sha> نشان می‌دهد تا منشأ آن‌ها را با یک نگاه ببینید.

نام‌هایی که در کاتالوگ نیستند

دادن یک نام تنها که مدخلی در کاتالوگ ندارد، خطا ایجاد می‌کند؛ فهرست نامِ دومی بدون بازبینی وجود ندارد. چنین افزونه‌هایی را با owner/repo یا نشانی گیت نصب کنید (منبع سفارشی؛ توضیح در ادامه)، یا آن‌ها را برای پذیرش در کاتالوگ ارسال کنید.

تازه‌سازی زنده

فرایند ساخت مستندات، کاتالوگ را در قالب یک سند JSON منتشر می‌کند (https://hermes-agent.nousresearch.com/docs/api/plugin-catalog.json). فرمان‌های search، install و update آن را حداکثر هر ۶ ساعت یک بار دریافت می‌کنند و در ~/.hermes/cache/ کش می‌کنند. به این ترتیب، مدخل‌های جدید و حذف‌ها بدون به‌روزرسانی هرمس به کلاینت‌های نصب‌شده می‌رسند. در حالت آفلاین، از نسخهٔ همراه با کپی محلی مخزن شما استفاده می‌شود. محدودیت‌های حذف در هر دو فهرستِ داخل مخزن و فهرست زنده، همواره اعمال می‌شوند.

نشانی‌های سفارشی گیت متفاوت‌اند

فرمان hermes plugins install <git-url> همچنان برای هر مخزنی کار می‌کند، اما کاتالوگ را کاملاً دور می‌زند:

  • بدون بازبینی — هرچه در آخرین کامیت شاخه باشد دریافت می‌کنید، نه یک کامیت پین‌شدهٔ بازبینی‌شده.
  • یک بنر هشدار نمایش داده می‌شود تا روشن باشد که کد بررسی نشده است.
  • فهرست حذف‌شده‌ها همچنان بررسی می‌شود (نصب مخزنی که نامعتبر شناخته شده باشد، از طریق نشانی هم رد می‌شود).

از روش نصب با نشانی گیت برای افزونه‌های خودتان و مخزن‌هایی استفاده کنید که از پیش به آن‌ها اعتماد دارید؛ برای کشف افزونه‌ها از کاتالوگ استفاده کنید.

۴ ارسال افزونه برای پذیرش در کاتالوگ

برای ارسال افزونه، یک درخواست ادغام باز کنید که یک فایل plugin-catalog/<name>.yaml اضافه می‌کند. چک‌لیست کامل در README کاتالوگ افزونه‌ها آمده است؛ به‌طور خلاصه، هر مدخل باید این شرایط را داشته باشد:

  1. ارسال از سوی مالک — نویسندهٔ PR مالک یا نگهدارندهٔ مخزن افزونه است. نگهدارندگان کاتالوگ همچنین پس از بررسی گروهیِ افزونه‌های جامعهٔ کاربری، مجموعه‌هایی از آن‌ها را اضافه می‌کنند (هر کامیت پین‌شده اعتبارسنجی و در همان کامیت اسکن می‌شود). اگر افزونهٔ شما به این شکل اضافه شده و می‌خواهید تغییر کند یا حذف شود، برای مدخل خود یک PR باز کنید.
  2. مخزن عمومی — نشانی repo برای عموم قابل‌کلون‌کردن باشد.
  3. دارای انتشار — مخزن انتشارها یا برچسب‌های واقعی داشته باشد، نه فقط یک شاخهٔ پیش‌فرض.
  4. موفقیت در اعتبارسنجی — اکشن گیت‌هابِ اعتبارسنجی کاتالوگ برای PR با موفقیت اجرا شود (بررسی طرح‌واره، قالب SHA و دسترس‌پذیری).
  5. بدون خودبه‌روزرسانی — نسخهٔ ارائه‌شده در کاتالوگ نباید فایل‌های خودش را دانلود و جایگزین کند؛ SHA پین‌شده تنها مسیر به‌روزرسانی است (یک PR برای تغییر SHA، به‌علاوهٔ hermes plugins update <name>).

به‌روزرسانی کامیت پین‌شده (تغییر sha به یک کامیت جدیدتر) نیز همین فرایند PR و بازبینی را طی می‌کند.
