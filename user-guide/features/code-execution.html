اجرای کد ‏(فراخوانی برنامکی ابزار)

ابزار ‏execute_code اجازه می‌دهد ایجنت اسکریپت‌های پایتونی بنویسد که ابزارهای هرمس را به‌صورت برنامکی صدا بزنند و گردش‌کارهای چندمرحله‌ای را در یک نوبت LLM فشرده کنند. اسکریپت در پروسهٔ فرزند روی میزبان ایجنت اجرا و از طریق RPC سوکت دامنه-یونیکس با هرمس حرف می‌زند.

۱ نحوهٔ کار

  1. ایجنت اسکریپتی پایتونی با ‏from hermes_tools import ... می‌نویسد
  2. هرمس ماژول stub ‏hermes_tools.py با توابع RPC تولید می‌کند
  3. هرمس یک سوکت دامنه-یونیکس باز و thread شنوندهٔ RPC را شروع می‌کند
  4. اسکریپت در پروسهٔ فرزند اجرا می‌شود — فراخوانی‌های ابزار روی سوکت به هرمس برمی‌گردند
  5. فقط خروجی ‏print() اسکریپت به LLM برگردانده می‌شود؛ نتایج میانی ابزار هرگز وارد پنجرهٔ زمینه نمی‌شوند
python
# The agent can write scripts like:
from hermes_tools import web_search, web_extract

results = web_search("Python 3.13 features", limit=5)
for r in results["data"]["web"]:
    content = web_extract([r["url"]])
    # ... filter and process ...
print(summary)

ابزارهای موجود داخل اسکریپت‌ها: ‏web_search، ‏web_extract، ‏read_file، ‏write_file، ‏search_files، ‏patch، ‏terminal ‏(فقط foreground).

۲ کِی ایجنت از این استفاده می‌کند

ایجنت وقتی ‏execute_code را استفاده می‌کند که باشد:

  • ۳+ فراخوانی ابزار با منطق پردازش بینشان
  • فیلتر داده انبوه یا انشعاب شرطی
  • حلقه زدن روی نتایج

مزیت کلیدی: نتایج میانی ابزار هرگز وارد پنجرهٔ زمینه نمی‌شوند — فقط خروجی نهایی ‏print() برمی‌گردد که مصرف توکن را شدیداً کم می‌کند.

مثال‌های عملی

خط‌لوله پردازش داده

python
from hermes_tools import search_files, read_file
import json

# Find all config files and extract database settings
matches = search_files("database", path=".", file_glob="*.yaml", limit=20)
configs = []
for match in matches.get("matches", []):
    content = read_file(match["path"])
    configs.append({"file": match["path"], "preview": content["content"][:200]})

print(json.dumps(configs, indent=2))

تحقیق وب چندمرحله‌ای

python
from hermes_tools import web_search, web_extract
import json

# Search, extract, and summarize in one turn
results = web_search("Rust async runtime comparison 2025", limit=5)
summaries = []
for r in results["data"]["web"]:
    page = web_extract([r["url"]])
    for p in page.get("results", []):
        if p.get("content"):
            summaries.append({
                "title": r["title"],
                "url": r["url"],
                "excerpt": p["content"][:500]
            })

print(json.dumps(summaries, indent=2))

Refactor انبوه فایل

python
from hermes_tools import search_files, read_file, patch

# Find all Python files using deprecated API and fix them
matches = search_files("old_api_call", path="src/", file_glob="*.py")
fixed = 0
for match in matches.get("matches", []):
    result = patch(
        path=match["path"],
        old_string="old_api_call(",
        new_string="new_api_call(",
        replace_all=True
    )
    if "error" not in str(result):
        fixed += 1

print(f"Fixed {fixed} files out of {len(matches.get('matches', []))} matches")

خط‌لوله build و تست

python
from hermes_tools import terminal, read_file
import json

# Run tests, parse results, and report
result = terminal("cd /project && python -m pytest --tb=short -q 2>&1", timeout=120)
output = result.get("output", "")

# Parse test output
passed = output.count(" passed")
failed = output.count(" failed")
errors = output.count(" error")

report = {
    "passed": passed,
    "failed": failed,
    "errors": errors,
    "exit_code": result.get("exit_code", -1),
    "summary": output[-500:] if len(output) > 500 else output
}

print(json.dumps(report, indent=2))

۳ حالت اجرا

‏execute_code دو حالت اجرا دارد که با ‏code_execution.mode در config.yaml کنترل می‌شوند:

حالتپوشهٔ کاریمفسر Python
‏project ‏(پیش‌فرض)پوشهٔ کاری نشست ‏(همان ‏terminal())‏python مربوط به ‏VIRTUAL_ENV/CONDA_PREFIX فعال با fallback به python خود هرمس
‏strictیک پوشهٔ staging temp جدا از پروژهٔ کاربر‏sys.executable ‏(python خود هرمس)

کِی روی project بگذارید: می‌خواهید ‏import pandas، ‏from my_project import foo یا مسیرهای نسبی مثل ‏open(".env") همانطور که در ‏terminal() کار می‌کنند کار کنند. تقریباً همیشه همین چیزی است که می‌خواهید.

کِی به strict سوییچ کنید: حداکثر بازتولید‌پذیری لازم دارید — هر نشست همان مفسر را بخواهید فارغ از venv فعال کاربر، و اسکریپت‌ها از درخت پروژه قرنطینه شوند ‏(بدون ریسک خواندن تصادفی فایل‌های پروژه از طریق مسیر نسبی).

yaml — ~/.hermes/config.yaml
code_execution:
  mode: project   # or "strict"

رفتار fallback در حالت ‏project: اگر ‏VIRTUAL_ENV/CONDA_PREFIX unset، خراب یا اشاره‌گر به Python قدیمی‌تر از ۳٫۸ باشد، resolver تمیزانه به ‏sys.executable برمی‌گردد — هرگز ایجنت را بدون مفسر کارا رها نمی‌کند.

ناورداهای امنیتی-حیاتی بین هر دو حالت یکسان‌اند:

  • پاکسازی محیط ‏(حذف کلیدهای API، توکن‌ها، اعتبارنامه‌ها)
  • لیست‌سفید ابزار ‏(اسکریپت‌ها نمی‌توانند ‏execute_code بازگشتی، ‏delegate_task یا ابزارهای MCP صدا بزنند)
  • سقف منابع ‏(timeout، cap خروجی، cap فراخوانی-ابزار)

تغییر حالت فقط عوض می‌کند اسکریپت‌ها کجا اجرا و کدام مفسر اجرایشان کند، نه اینکه چه اعتبارنامه‌هایی می‌بینند یا کدام ابزارها را می‌توانند صدا بزنند.

۴ سقف‌های منابع

منبعحدیادداشت‌ها
Timeout۵ دقیقه ‏(۳۰۰ ثانیه)اسکریپت با SIGTERM کشته سپس بعد از ۵ ثانیه grace ‏SIGKILL
Stdout۵۰ KBخروجی با اعلان ‏[output truncated at 50KB] بریده می‌شود
Stderr۱۰ KBروی خروج غیرصفر برای دیباگ داخل خروجی گنجانده می‌شود
فراخوانی ابزار۵۰ به‌ازای هر اجرابا رسیدن به حد خطا برمی‌گردد

همهٔ حدود از طریق config.yaml قابل پیکربندی‌اند:

yaml — ~/.hermes/config.yaml
code_execution:
  mode: project      # project (default) | strict
  timeout: 300       # Max seconds per script (default: 300)
  max_tool_calls: 50 # Max tool calls per execution (default: 50)

۵ نحوهٔ کار فراخوانی ابزار داخل اسکریپت‌ها

وقتی اسکریپتتان تابعی مثل ‏web_search("query") را صدا بزند:

  1. فراخوانی به JSON سری و از طریق سوکت دامنه-یونیکس به پروسهٔ والد فرستاده می‌شود
  2. والد از طریق هندلر استاندارد ‏handle_function_call dispatch می‌کند
  3. نتیجه از طریق سوکت برمی‌گردد
  4. تابع نتیجهٔ parse‌شده را برمی‌گرداند

یعنی فراخوانی‌های ابزار داخل اسکریپت‌ها عیناً مثل فراخوانی‌های عادی رفتار می‌کنند — همان سقف‌های نرخ، همان هندل خطا، همان قابلیت‌ها. تنها محدودیت این است که ‏terminal() فقط-foreground است ‏(بدون پارامترهای ‏background یا ‏pty).

۶ هندل خطا

وقتی اسکریپتی شکست بخورد ایجنت اطلاعات خطای ساختاریافته می‌گیرد:

  • Exit code غیرصفر: stderr در خروجی گنجانده می‌شود تا ایجنت traceback کامل را ببیند
  • Timeout: اسکریپت کشته و ایجنت می‌بیند ‏"Script timed out after 300s and was killed."
  • وقفه: اگر کاربر حین اجرا پیام جدیدی بفرستد اسکریپت پایان و ایجنت می‌بیند ‏[execution interrupted — user sent a new message]
  • سقف فراخوانی ابزار: با رسیدن به حد ۵۰ فراخوانی، فراخوانی‌های بعدی پیام خطا برمی‌گردانند

پاسخ همیشه شامل ‏status ‏(success/error/timeout/interrupted)، ‏output، ‏tool_calls_made و ‏duration_seconds است.

۷ امنیت

🚨 مدل امنیت

پروسهٔ فرزند با محیط حداقلی اجرا می‌شود. کلیدهای API، توکن‌ها و اعتبارنامه‌ها پیش‌فرض حذف می‌شوند. اسکریپت فقط از طریق کانال RPC به ابزارها دسترسی دارد — نمی‌تواند رمزها را از متغیرهای محیطی بخواند مگر صریحاً اجازه داده شود.

متغیرهای محیطی دارای ‏KEY، ‏TOKEN، ‏SECRET، ‏PASSWORD، ‏CREDENTIAL، ‏PASSWD یا ‏AUTH در نامشان مستثنی می‌شوند. فقط متغیرهای سیستمی امن ‏(PATH، ‏HOME، ‏LANG، ‏SHELL، ‏PYTHONPATH، ‏VIRTUAL_ENV و...) عبور می‌کنند.

عبور متغیر env مهارت‌ها

وقتی مهارتی ‏required_environment_variables را در frontmatter اعلام کند، آن متغیرها بعد از لود شدن مهارت خودکار به پروسه‌های فرزند ‏execute_code و terminal عبور داده می‌شوند. این اجازه می‌دهد مهارت‌ها از کلیدهای API اعلام‌شده‌شان استفاده کنند بدون تضعیف وضعیت امنیتی برای کد دلخواه.

برای موارد غیر-مهارتی می‌توانید متغیرها را صریحاً در config.yaml لیست‌سفید کنید:

yaml
terminal:
  env_passthrough:
    - MY_CUSTOM_KEY
    - ANOTHER_TOKEN

جزئیات کامل در راهنمای امنیت، بخش «عبور متغیر محیطی».

متغیرهای ‏HERMES_* در فرزند

پروسهٔ فرزند فقط مجموعه کوچک ثابتی از متغیرهای عملیاتی ‏HERMES_* را با نام دقیق دریافت می‌کند:

  • ‏HERMES_HOME · ‏HERMES_PROFILE · ‏HERMES_CONFIG · ‏HERMES_ENV

‹+ ‏HERMES_RPC_DIR / HERMES_RPC_SOCKET / TZ / HOME که هرمس صریحاً تزریق می‌کند تا کانال RPC کار کند›.

📌 تغییر رفتار

نسخه‌های قبلی هر متغیری که نامش با ‏HERMES_ شروع می‌شد را به فرزند عبور می‌دادند. آن پیشوند پهن برای سخت‌سازی امنیتی حذف شد: می‌توانست پیکربندی ‏HERMES_*-نامی را که با زیررشتهٔ رمز تطبیق نمی‌کرد ‏(مثل ‏HERMES_BASE_URL، ‏HERMES_KANBAN_DB یا endpoint ‏HERMES_*_WEBHOOK) به کد sandbox‌شدهٔ دلخواه لو بدهد.

اگر یک اسکریپت ‏execute_code — یا ماژول repo/افزونه‌ای که هنگام ایمپورت بار می‌کند — به متغیر ‏HERMES_* خارج از چهار نام عملیاتی بالا اتکا داشت، الان آن متغیر را در فرزند unset می‌یابد. حذف عمدی است نه باگ.

راه‌حل — بازگرداندن صریح متغیر. هر دو مسیر متغیر را به فرزندان ‏execute_code و terminal عبور می‌دهند و هیچ‌کدام تضمین حذف-رمز را ضعیف نمی‌کنند ‏(اعتبارنامه‌های ارائه‌دهندهٔ مدیریت‌شده توسط هرمس هرگز این‌طور مجاز نمی‌شوند):

  1. به‌ازای-ماشین، در config.yaml — نام دقیق متغیر را به لیست‌سفید passthrough بیفزایید:
    yaml
    terminal:
  env_passthrough:
    - HERMES_KANBAN_DB
    - HERMES_BASE_URL
  2. به‌ازای-مهارت، در frontmatter مهارت — اعلام کنید تا هر بار لود شدن آن مهارت خودکار ثبت شود:
    yaml
    required_environment_variables:
  - HERMES_KANBAN_DB

تشخیص. وقتی فرزند یک یا چند متغیر ‏HERMES_* غیر-لیست‌سفیدی را دور می‌ریزد هرمس لاگ ‏debug یک‌خطی صادر می‌کند که آنها را نام می‌برد و به دریچهٔ ‏env_passthrough اشاره می‌کند. با لاگ دیباگ اجرا کنید ‏(hermes logs --level DEBUG یا چک ‏~/.hermes/logs/agent.log) و دنبال ‏execute_code: dropped N non-allowlisted HERMES_* var(s) بگردید اگر اسکریپتی طوری رفتار کرد که انگار متغیر ‏HERMES_*ای غایب است.

هرمس اسکریپت و stub ‏RPC تولیدشدهٔ خودکار ‏hermes_tools.py را همیشه داخل یک پوشهٔ staging موقت می‌نویسد که بعد از اجرا پاک می‌شود. در حالت ‏strict اسکریپت آنجا هم اجرا می‌شود؛ در حالت ‏project در پوشهٔ کاری نشست اجرا می‌شود ‏(پوشهٔ staging روی PYTHONPATH می‌ماند تا ایمپورت‌ها همچنان حل شوند). پروسهٔ فرزند در process group خودش اجرا می‌شود تا روی timeout یا وقفه تمیز کشته شود.

۹ پشتیبانی پلتفرمی

اجرای کد روی لینوکس، macOS و ویندوز در دسترس است. روی لینوکس و macOS کانال RPC از سوکت دامنه-یونیکس استفاده می‌کند؛ روی ویندوز که ‏AF_UNIX غیرقابل‌اتکاست هرمس خودکار به سوکت TCP loopback برای ترنسپورت RPC سندباکس برمی‌گردد. بک‌اندهای ترمینال راه‌دور ‏(Docker/SSH/Modal/و...) به‌جایش از ترنسپورت RPC مبتنی-بر-فایل استفاده و به‌اضافه Python 3 داخل بک‌اند می‌خواهند.
