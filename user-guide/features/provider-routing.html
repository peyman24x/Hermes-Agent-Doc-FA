مسیریابی ارائه‌دهنده ‏(Provider Routing)

وقتی از OpenRouter یا Nous Portal به‌عنوان ارائه‌دهندهٔ LLM تان استفاده می‌کنید، ‏Hermes Agent از مسیریابی ارائه‌دهنده پشتیبانی می‌کند — کنترل ریزدانه بر اینکه کدام ارائه‌دهندگان AI ی زیرین درخواست‌هایتان را هندل کنند و چطور اولویت بگیرند.

‏OpenRouter درخواست‌ها را به ارائه‌دهندگان زیادی مسیریابی می‌کند ‏(مثل Anthropic، ‏Google، ‏AWS Bedrock، ‏Together AI). مسیریابی ارائه‌دهنده اجازه می‌دهد برای هزینه، سرعت، کیفیت بهینه کنید یا نیازمندی‌های مشخصی روی ارائه‌دهنده اجبار کنید.

💡

ترافیکِ مسیریابی‌شده از طریق Nous Portal همان ترجیحات ارائه‌دهنده را محترم می‌شمارد — و مشترکان Portal روی ارائه‌دهندگان صورتحساب-توکنی ‎۱۰٪‎ تخفیف می‌گیرند.

۱ پیکربندی

بخش provider_routing را به ~/.hermes/config.yaml اضافه کنید:

provider_routing:
  sort: "price"           # How to rank providers
  only: []                # Whitelist: only use these providers
  ignore: []              # Blacklist: never use these providers
  order: []               # Explicit provider priority order
  require_parameters: false  # Only use providers that support all parameters
  data_collection: null   # Control data collection ("allow" or "deny")
ℹ️

مسیریابی ارائه‌دهنده فقط با OpenRouter یا Nous Portal اعمال می‌شود. با اتصالات مستقیم به ارائه‌دهنده ‏(مثل وصل شدن مستقیم به API ی Anthropic) اثری ندارد.

۲ گزینه‌ها

sort

کنترل می‌کند OpenRouter ارائه‌دهندگان موجود برای درخواست شما را چطور رتبه کند:

مقدارتوضیح
"price"ارزان‌ترین ارائه‌دهنده اول
"throughput"سریع‌ترین توکن-بر-ثانیه اول
"latency"کمترین زمان-تا-اولین-توکن اول

only

‏Whitelist ی slug های ارائه‌دهنده. ست شود، فقط این ارائه‌دهندگان مصرف می‌شوند و همهٔ بقیه حذف می‌شوند. از slug ی حروف-کوچکی که OpenRouter per-provider نشان می‌دهد استفاده کنید.

provider_routing:
  only:
    - "anthropic"
    - "google"

ignore

‏Blacklist ی نام ارائه‌دهنده‌ها. اینها هرگز مصرف نمی‌شوند حتی اگر ارزان‌ترین یا سریع‌ترین گزینه باشند.

provider_routing:
  ignore:
    - "together"
    - "deepinfra"

order

ترتیب اولویت صریح. ارائه‌دهندگان ابتدای فهرست ترجیح می‌گیرند؛ نام‌ذکرنشده‌ها fallback اند.

provider_routing:
  order:
    - "anthropic"
    - "google"
    - "amazon-bedrock"

require_parameters

وقتی true باشد OpenRouter فقط به ارائه‌دهندگانی مسیریابی می‌کند که همهٔ پارامترهای درخواست شما ‏(temperature، top_p، tools و…) را پشتیبانی کنند. جلوگیری از drop ی بی‌سروصدای پارامترها.

data_collection

کنترل می‌کند ارائه‌دهندگان مجاز باشند پرامپت‌هایتان را برای آموزش استفاده کنند: مقادیر allow یا deny.

۳ مثال‌های عملی

  • بهینه برای هزینه — مسیریابی به ارزان‌ترین ارائه‌دهنده؛ مناسب مصرف پرحجم و توسعه:
    provider_routing:
  sort: "price"
  • بهینه برای سرعت — اولویت ارائه‌دهنده‌های کم‌تأخیر برای مصرف تعاملی: ‏sort: "latency"
  • بهینه برای throughput — بهترین برای تولید بلند که توکن-بر-ثانیه مهم است: ‏sort: "throughput"
  • قفل روی ارائه‌دهنده‌های خاص — اطمینان عبور همهٔ درخواست‌ها از یک ارائه‌دهنده برای یکنواختی: ‏only: ["anthropic"]
  • اجتناب از ارائه‌دهنده‌های مشخص — حذف ارائه‌دهنده‌های ناخواسته مثلاً برای حریم خصوصی داده، همراه deny کردن data_collection
  • ترتیب ترجیحی با fallback ها — امتحان ارائه‌دهنده‌های ترجیحی اول، سپس سایر:
    provider_routing:
  order:
    - "anthropic"
    - "google"
  require_parameters: true

۴ نحوهٔ کار و رفتار پیش‌فرض

ترجیحات مسیریابی ارائه‌دهنده روی درخواست‌های چت ایجنت و خلاصه‌های سقف-تکرار به OpenRouter یا Nous Portal از طریق فیلد extra_body.provider پاس داده می‌شوند ‏(extra_body آرگومان SDK ی Python ی OpenAI است؛ به آبجکت provider ی سطح-بالای درخواست JSON تبدیل می‌شود). تسک‌های کمکی مثل فشرده‌سازی و تولید عنوان مستقلاً زیر auxiliary.<task>.extra_body پیکربندی می‌شوند.

  • حالت CLI — در ~/.hermes/config.yaml پیکربندی و موقع startup لود می‌شود
  • حالت گیت‌وی — همان فایل config، موقع شروع گیت‌وی لود می‌شود

پیکربندی مسیریابی از config.yaml خوانده و موقع ساخت AIAgent به‌صورت پارامتر پاس داده می‌شود: providers_allowed از only، ‏providers_ignored از ignore، ‏providers_order از order، ‏provider_sort از sort، ‏provider_require_parameters از require_parameters و provider_data_collection از data_collection.

💡 ترکیب چند گزینه

مثلاً مرتب‌سازی بر اساس قیمت + حذف ارائه‌دهنده‌های خاص + الزام پشتیبانی پارامترها + ممنوعیت جمع‌آوری داده همزمان ممکن است.

رفتار پیش‌فرض

بدون بخش provider_routing ‏(پیش‌فرض)، aggregator منطق مسیریابی پیش‌فرض خودش را مصرف می‌کند که معمولاً به‌طور خودکار بین هزینه و دسترس‌پذیری تعادل برقرار می‌کند.

💡 مسیریابی ارائه‌دهنده در برابر مدل‌های پشتیبان

مسیریابی ارائه‌دهنده کنترل می‌کند کدام زیرارائه‌دهندگانِ پشت OpenRouter یا Nous Portal درخواست‌هایتان را هندل کنند. برای failover ی خودکار به ارائه‌دهندهٔ کاملاً متفاوت وقتی مدل اصلی شکست می‌خورد، صفحهٔ ارائه‌دهندگان پشتیبان را ببینید.
