پردازش دسته‌ای ‏(Batch Processing)

پردازش دسته‌ای اجازه می‌دهد ایجنت هرمس را روی صدها یا هزاران پرامپت به‌صورت موازی اجرا و دادهٔ مسیر (trajectory) ساختاریافته تولید کنید. کاربرد اصلی آن تولید دادهٔ آموزشی است — تولید مسیرهای قالب ShareGPT با آمار استفاده از ابزار که برای fine-tuning یا ارزیابی قابل استفاده‌اند.

۱ نمای کلی

اجراکنندهٔ دسته‌ای ‏(batch_runner.py) یک دیتاست JSONL از پرامپت‌ها را پردازش و هرکدام را از یک نشست کامل ایجنتی با دسترسی ابزار عبور می‌دهد. هر پرامپت محیط ایزولهٔ خودش را می‌گیرد. خروجی، دادهٔ مسیر ساختاریافته با تاریخچهٔ کامل گفتگو، آمار فراخوانی ابزار و متریک‌های پوشش استدلال است.

شروع سریع

bash
# Basic batch run
python batch_runner.py \
    --dataset_file=data/prompts.jsonl \
    --batch_size=10 \
    --run_name=my_first_run \
    --model=anthropic/claude-sonnet-4.6 \
    --num_workers=4

# Resume an interrupted run
python batch_runner.py \
    --dataset_file=data/prompts.jsonl \
    --batch_size=10 \
    --run_name=my_first_run \
    --resume

# List available toolset distributions
python batch_runner.py --list_distributions
💡 هزینهٔ قابل‌پیش‌بینی در مقیاس

اجراهای دسته‌ای نشست‌های ایجنتی هم‌زمان زیادی بالا می‌آورند که هرکدام فراخوانی مدل و ابزار می‌زنند. اشتراک ‏Nous Portal دسترسی مدل + جست‌وجوی وب، تولید تصویر، TTS و مرورگرهای ابری را زیر یک قبضه جمع می‌کند — برای هزینهٔ ثابت به‌ازای-هر-مسیر بدون juggle کردن سقف نرخ بین پنج حساب فروشنده مفید است. با ‏hermes setup --portal راه بیندازید و بعد ‏--model را به مدلی از Nous اشاره دهید.

۲ قالب دیتاست

دیتاست ورودی فایل JSONL است ‏(یک آبجکت JSON در هر خط). هر ورودی باید فیلد ‏prompt داشته باشد:

jsonl
{"prompt": "Write a Python function that finds the longest palindromic substring"}
{"prompt": "Create a REST API endpoint for user authentication using Flask"}
{"prompt": "Debug this error: TypeError: cannot unpack non-iterable NoneType object"}

ورودی‌ها اختیاراً می‌توانند شامل باشند:

  • ‏image یا ‏docker_image: ایمیج کانتینری برای sandbox همین پرامپت ‏(با بک‌اندهای Docker، ‏Modal و ‏Singularity کار می‌کند)
  • ‏cwd: override پوشهٔ کاری برای نشست ترمینال task

۳ گزینه‌های پیکربندی

پارامترپیش‌فرضتوضیح
--dataset_file‹الزامی›مسیر دیتاست JSONL
--batch_size‹الزامی›پرامپت به‌ازای هر batch
--run_name‹الزامی›نام این اجرا ‏(برای پوشهٔ خروجی و checkpointing)
--distribution"default"توزیع تول‌ست برای نمونه‌گیری
--modelclaude-sonnet-4.6مدل مورد استفاده
--base_urlhttps://openrouter.ai/api/v1URL پایهٔ API
--api_key‹متغیر env›کلید API مدل
--max_turns10حداکثر iteration های فراخوانی-ابزار به‌ازای هر پرامپت
--num_workers4پروسه‌های worker موازی
--resumefalseازسرگیری از checkpoint
--verbosefalseفعال‌سازی لاگ پرجزئیات
--max_samplesهمهفقط N نمونهٔ اول دیتاست پردازش شود
--max_tokensپیش‌فرض مدلحداکثر توکن به‌ازای هر پاسخ مدل

مسیریابی ارائه‌دهنده ‏(OpenRouter)

پارامترتوضیح
--providers_allowedارائه‌دهنده‌های مجاز جداشده با ویرگول ‏(مثل ‏"anthropic,openai")
--providers_ignoredارائه‌دهنده‌های نادیده جداشده با ویرگول ‏(مثل ‏"together,deepinfra")
--providers_orderترتیب ترجیحی ارائه‌دهنده‌ها جداشده با ویرگول
--provider_sortمرتب‌سازی بر اساس ‏"price"، ‏"throughput" یا ‏"latency"

کنترل استدلال

پارامترتوضیح
--reasoning_effortسطح استدلال: ‏none، ‏minimal، ‏low، ‏medium، ‏high، ‏xhigh، ‏max، ‏ultra
--reasoning_disabledغیرفعال‌سازی کامل توکن‌های استدلال/تفکر

گزینه‌های پیشرفته

پارامترتوضیح
--ephemeral_system_promptپرامپت سیستمیِ استفاده‌شده حین اجرا ولی ذخیره‌نشده در مسیرها
--log_prefix_charsکاراکترهای نمایش‌داده‌شده در پیش‌نمایش لاگ ‏(پیش‌فرض: ۱۰۰)
--prefill_messages_fileمسیر فایل JSON دارای پیام‌های prefill برای priming چند-نمونه‌ای

۴ توزیع‌های تول‌ست

هر پرامپت مجموعه‌ای نمونه‌گیری‌تصادفی از تول‌ست‌ها از یک توزیع می‌گیرد. این تضمین می‌کند دادهٔ آموزشی ترکیب‌های متنوع ابزار را پوشش دهد. برای دیدن همهٔ توزیع‌ها از ‏--list_distributions استفاده کنید.

در پیاده‌سازی فعلی، توزیع‌ها به هر تول‌ست منفرد یک احتمال اختصاص می‌دهند. نمونه‌گیر هر تول‌ست را مستقل flip می‌کند و بعد تضمین می‌کند دست‌کم یک تول‌ست فعال باشد. این با جدول دست‌نویسِ ترکیب‌های از-قبل-ساخته متفاوت است.

۵ قالب خروجی

همهٔ خروجی به ‏data/<run_name>/ می‌رود:

text
data/my_run/
├── trajectories.jsonl    # Combined final output (all batches merged)
├── batch_0.jsonl         # Individual batch results
├── batch_1.jsonl
├── ...
├── checkpoint.json       # Resume checkpoint
└── statistics.json       # Aggregate tool usage stats

قالب مسیر ‏(Trajectory)

هر خط در ‏trajectories.jsonl یک آبجکت JSON است:

json
{
  "prompt_index": 42,
  "conversations": [
    {"from": "human", "value": "Write a function..."},
    {"from": "gpt", "value": "I'll create that function...",
     "tool_calls": [...]},
    {"from": "tool", "value": "..."},
    {"from": "gpt", "value": "Here's the completed function..."}
  ],
  "metadata": {
    "batch_num": 2,
    "timestamp": "2026-01-15T10:30:00",
    "model": "anthropic/claude-sonnet-4.6"
  },
  "completed": true,
  "partial": false,
  "api_calls": 3,
  "toolsets_used": ["terminal", "file"],
  "tool_stats": {
    "terminal": {"count": 2, "success": 2, "failure": 0},
    "read_file": {"count": 1, "success": 1, "failure": 0}
  },
  "tool_error_counts": {
    "terminal": 0,
    "read_file": 0
  }
}

فیلد ‏conversations از قالب شبیه-ShareGPT با فیلدهای ‏from و ‏value استفاده می‌کند. آمار ابزار نرمال‌سازی می‌شود تا همهٔ ابزارهای ممکن با پیش‌فرض صفر گنجانده شوند و schema بین ورودی‌ها برای سازگاری با دیتاست‌های HuggingFace یکسان بماند.

۶ Checkpointing

اجراکنندهٔ دسته‌ای checkpointing مطمئنی برای تحمل خطا دارد:

  • فایل checkpoint: بعد از تکمیل هر batch ذخیره می‌شود و ردیابی می‌کند کدام اندیس‌های پرامپت تمام شده‌اند
  • resume مبتنی-بر-محتوا: روی ‏--resume اجراکننده فایل‌های batch موجود را اسکن و پرامپت‌های کامل‌شده را بر اساس متن واقعی‌شان تطبیق می‌دهد ‏(نه فقط اندیس‌ها)، تا بازیابی حتی اگر ترتیب دیتاست عوض شده باشد ممکن شود
  • پرامپت‌های شکست‌خورده: فقط پرامپت‌های موفقانه کامل‌شdone علامت می‌خورند — پرامپت‌های شکسته هنگام resume دوباره تلاش می‌شوند
  • ادغام batch ها: هنگام اتمام همهٔ فایل‌های batch ‏(شامل اجراهای قبلی) داخل یک ‏trajectories.jsonl واحد ادغام می‌شوند

نحوهٔ کار resume

  1. اسکن همهٔ فایل‌های ‏batch_*.jsonl برای پرامپت‌های کامل‌شده ‏(با تطبیق محتوا)
  2. فیلتر دیتاست برای حذف پرامپت‌های قبلاً کامل‌شده
  3. بچ‌کردن مجدد پرامپت‌های باقی‌مانده
  4. پردازش فقط پرامپت‌های باقی‌مانده
  5. ادغام همهٔ فایل‌های batch ‏(قدیم + جدید) در خروجی نهایی

۷ فیلتر کیفیت

اجراکنندهٔ دسته‌ای فیلتر کیفیت خودکار اعمال می‌کند:

  • فیلتر بدون-استدلال: نمونه‌هایی که صفر نوبت assistant دارای استدلال است ‏(بدون ‏<REASONING_SCRATCHPAD> یا توکن‌های تفکر native) دور ریخته می‌شوند
  • فیلتر ورودی خراب: ورودی‌هایی با نام ابزار توهم‌زده ‏(خارج از فهرست معتبر ابزارها) هنگام merge نهایی فیلتر می‌شوند
  • آمار استدلال: درصد نوبت‌های دارای/فاقد استدلال در کل اجرا ردیابی می‌شود

۸ آمار

بعد از اتمام اجراکننده آمار جامعی چاپ می‌کند:

  • مصرف ابزار: تعداد فراخوانی، نرخ موفقیت/شکست به‌ازای هر ابزار
  • پوشش استدلال: درصد نوبت‌های assistant دارای استدلال
  • نمونه‌های دور ریخته‌شده: تعداد نمونه‌های فیلترشده به دلیل فقدان استدلال
  • مدت: کل زمان پردازش

آمار برای تحلیل programmatik در ‏statistics.json هم ذخیره می‌شود.

۹ موارد استفاده

تولید دادهٔ آموزشی

تولید مسیرهای متنوع استفاده-از-ابزار برای fine-tuning:

bash
python batch_runner.py \
    --dataset_file=data/coding_prompts.jsonl \
    --batch_size=20 \
    --run_name=coding_v1 \
    --model=anthropic/claude-sonnet-4.6 \
    --num_workers=8 \
    --distribution=default \
    --max_turns=15

ارزیابی مدل

ارزیابی اینکه مدل چقدر خوب روی پرامپت‌های استاندارد از ابزار استفاده می‌کند:

bash
python batch_runner.py \
    --dataset_file=data/eval_suite.jsonl \
    --batch_size=10 \
    --run_name=eval_gpt4 \
    --model=openai/gpt-4o \
    --num_workers=4 \
    --max_turns=10

ایمیج کانتینری به‌ازای-هر-پرامپت

برای بنچمارک‌هایی که محیط خاص می‌خواهند، هر پرامپت می‌تواند ایمیج کانتینر خودش را مشخص کند:

jsonl
{"prompt": "Install numpy and compute eigenvalues of a 3x3 matrix", "image": "python:3.11-slim"}
{"prompt": "Compile this Rust program and run it", "image": "rust:1.75"}
{"prompt": "Set up a Node.js Express server", "image": "node:20-alpine", "cwd": "/app"}

اجراکنندهٔ دسته‌ای قبل از اجرای هر پرامپت تأیید می‌کند ایمیج Docker قابل‌دسترس است.
