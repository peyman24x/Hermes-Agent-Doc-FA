جستجو و استخراج وب ‏(Web Search & Extract)

هرمس ایجنت دو ابزار وبِ قابل‌فراخوانی-توسط-مدل دارد که چند ارائه‌دهنده پشت آنهاست:

  • ‏web_search — وب را جستجو و نتایج رتبه‌بندی‌شده برمی‌گرداند
  • ‏web_extract — محتوای خوانا را از یک یا چند URL واکشی و استخراج می‌کند

هر دو از طریق یک انتخاب بک‌اند واحد پیکربندی می‌شوند. ارائه‌دهنده‌ها از طریق hermes tools انتخاب یا مستقیماً در config.yaml تنظیم می‌شوند.

Brave Search، ‏DDGS و xAI فقط-جستجو هستند — هر کدام را که خواستید با Firecrawl/Tavily/Exa/Parallel جفت کنید تا web_extract هم داشته باشید. DDGS از پکیج پایتونی ddgs استفاده می‌کند؛ اگر نصب نیست pip install ddgs را اجرا کنید ‏(یا بگذارید هرمس در اولین استفاده lazy نصب کند). xAI ابزار سرور-سمتِ web_search ی Grok را روی Responses API اجرا می‌کند — نتایج LLM-ساخته هستند نه مبتنی بر ایندکس، پس عنوان‌ها، توضیحات و انتخاب URL همگی خروجی مدل‌اند ‏(بخش هشدار مدل اعتماد را ببینید).

تفکیک هر-قابلیت: می‌توانید برای جستجو و استخراج مستقلاً ارائه‌دهنده‌های متفاوت به کار ببرید — مثلاً SearXNG ‏(رایگان) برای جستجو و Firecrawl برای استخراج. بخش پیکربندی هر-قابلیت را ببینید.

📌 همین‌طوری کار می‌کند — چرخش حلقهٔ رایگانِ بدون‌کلید

نصب تازه‌ای که هیچ اعتبارنامهٔ وبی ندارد همان ابتدا web_search و web_extract کارا می‌گیرد: درخواست‌ها به‌صورت round-robin بین تیرهای عمومی رایگان پنج فروشنده می‌چرخند — ‏Exa، ‏Parallel، ‏Tavily، ‏Firecrawl و Keenable — بار یکنواخت پخش می‌شود و درخواست rate-limit شده خودکار روی فروشندهٔ بعدی حلقه دوباره تلاش می‌کند ‏(چند-مرحله‌ای، تا یکی سرویس دهد یا همه throttled شوند). نه ثبت‌نام، نه کلید. این سطح اکیداً آخرین چاره است — هر بک‌اند پیکربندی‌شده یا کلید حاضر همیشه برنده است — و درخواست‌ها هیچ شناسهٔ کاربری حمل نمی‌کنند ‏(فقط یک session id تصادفی per-process که با ری‌استارت عوض می‌شود). برای سرویس تضمینی و بدون throttle یک ارائه‌دهندهٔ کلیددار راه‌اندازی کنید. کل این سطح با web.keyless_fallback: false خاموش می‌شود.

انتخاب صریح رایگان یا پولی: در hermes tools هر یک از Exa، ‏Parallel و Keenable در دو ردیف ظاهر می‌شود — Free ‏(بدون‌کلید) و Paid ‏(کلید API). انتخاب Free نقطهٔ پایانی ناشناس آن فروشنده را پین می‌کند ‏(حتی اگر بعداً کلید اضافه کنید)؛ انتخاب Paid مسیر کلیددار را پین می‌کند ‏(کلید غایب بعد از آن خطا می‌دهد نه اینکه بی‌سروصدا به سطح رایگان سقوط کند). انتخاب به‌صورت web.provider_tier.<name>: free|paid ذخیره می‌شود؛ برای حالت خودکار unset بگذارید ‏(کلید حاضر → paid، وگرنه حلقهٔ بدون‌کلید).

💡 مشترکان Nous

اگر اشتراک پولی Nous Portal دارید، جستجو و استخراج وب از طریق گیت‌وی ابزار ‏(Tool Gateway) با Firecrawl مدیریت‌شده در دسترس است — بدون نیاز به کلید API. نصب‌های جدید می‌توانند hermes setup --portal را اجرا کنند تا وارد شوند و همهٔ ابزارهای گیت‌وی را یکجا روشن کنند؛ نصب‌های موجود فقط وب را از طریق hermes tools روشن کنند.

۲ برخورد web_extract با صفحات طولانی

بک‌اندها markdown خام صفحه را برمی‌گردانند که می‌تواند عظیم باشد ‏(تالار گفتگو، سایت‌های مستندات، اخبار با کامنت‌های تعبیه‌شده). برای اینکه پنجرهٔ زمینه‌تان قابل‌استفاده بماند، web_extract یک بودجهٔ نویسهٔ قطعی اعمال می‌کند — هیچ خلاصه‌سازی LLM در کار نیست:

اندازهٔ صفحه ‏(نویسه)چه می‌شود
در بودجه یا زیر آن ‏(پیش‌فرض ‎۱۵٬۰۰۰)یکجا برگردانده می‌شود — markdown کامل به ایجنت می‌رسد
بالای بودجهپنجرهٔ سر+دم ‏(~۷۵٪ سر / ~۲۵٪ دم، برش روی مرز خطوط markdown) به‌علاوهٔ پانوشت صریح [TRUNCATED]. متن کامل تمیز روی دیسک ذخیره می‌شود و پانوشت مسیر فایل و فراخوانی دقیق read_file را برای ورق‌زدن میانهٔ حذف‌شده به ایجنت می‌گوید
بالای ‎۲٬۰۰۰٬۰۰۰متن ذخیره‌شده روی ‎۲ MB سقف می‌خورد

بودجهٔ هر-صفحه از طریق web.extract_char_limit در config.yaml قابل‌تنظیم است ‏(پیش‌فرض 15000، محدود به بازهٔ ۲٬۰۰۰ تا ۵۰۰٬۰۰۰) و ایجنت می‌تواند با آرگومان char_limit ابزار آن را برای یک فراخوانی بالا ببرد.

وقتی برش مزاحم می‌شود

اگر مشخصاً به DOM زنده نیاز دارید نه markdown استخراج‌شده — مثلاً صفحه‌ای سنگین-JS که استخراج از آن محتوای کمی برمی‌گرداند — به‌جایش از browser_navigate + ‏browser_snapshot استفاده کنید. ابزار مرورگر درخت دسترس‌پذیری زنده را برمی‌گرداند ‏(با سقف snapshot خودش روی صفحات عظیم).

۳ راه‌اندازی

راه‌اندازی سریع با hermes tools

‏hermes tools را اجرا کنید، به Web Search & Extract بروید و یک ارائه‌دهنده انتخاب کنید. ویزارد URL یا کلید API لازم را می‌پرسد و در config شما می‌نویسد.

hermes tools

Firecrawl ‏(پیش‌فرض)

جستجو و استخراج تمام‌عیار. برای بیشتر کاربران پیشنهاد می‌شود.

# ~/.hermes/.env
FIRECRAWL_API_KEY=fc-your-key-here

کلید را از firecrawl.dev بگیرید. سطح رایگان ۵۰۰ credit در ماه دارد.

Firecrawl خودمیزبان: به‌جای API ابری به نمونهٔ خودتان اشاره دهید:

# ~/.hermes/.env
FIRECRAWL_API_URL=http://localhost:3002

وقتی FIRECRAWL_API_URL ست شده باشد کلید API اختیاری است ‏(احراز هویت سرور را با USE_DB_AUTHENTICATION=false غیرفعال کنید).

SearXNG ‏(رایگان، خودمیزبان)

‏SearXNG موتور فراجستجو متن‌باز و حرمت‌گذار حریم خصوصی است که نتایج بیش از ۷۰ موتور جستجو را تجمیع می‌کند. کلید API لازم ندارد — فقط هرمس را به یک نمونهٔ درحال‌اجرا اشاره دهید.

‏SearXNG فقط-جستجو است — ‏web_extract ارائه‌دهندهٔ استخراج جداگانه می‌خواهد.

گزینهٔ A — خودمیزبان با Docker ‏(پیشنهادی)

یک نمونهٔ خصوصی بدون rate limit می‌دهد.

۱. دایرکتوری کار بسازید:

mkdir -p ~/searxng/searxng
cd ~/searxng

۲. یک docker-compose.yml بنویسید:

yaml
# ~/searxng/docker-compose.yml
services:
  searxng:
    image: searxng/searxng:latest
    container_name: searxng
    ports:
      - "8888:8080"
    volumes:
      - ./searxng:/etc/searxng:rw
    environment:
      - SEARXNG_BASE_URL=http://localhost:8888/
    restart: unless-stopped

۳. کانتینر را روشن کنید:

docker compose up -d

۴. قالب JSON API را فعال کنید:

‏SearXNG به‌طور پیش‌فرض خروجی JSON را غیرفعال ارسال می‌کند. config تولیدشده را کپی و فعالش کنید:

# Copy the auto-generated config out of the container
docker cp searxng:/etc/searxng/settings.yml ~/searxng/searxng/settings.yml

فایل ~/searxng/searxng/settings.yml را باز کنید. اگر use_default_settings: true حضور دارد، فایل فقط overrideهای شما را دارد و بقیهٔ تنظیمات از پیش‌فرض‌های داخلی به ارث می‌رسد. برای فعال کردن پاسخ‌های JSON برای هرمس این override را اضافه کنید:

search:
  formats:
    - html
    - json

‏settings.yml شما باید چیزی شبیه این شود:

yaml
# Read the documentation before extending the defaults:
# https://docs.searxng.org/admin/settings/

use_default_settings: true

server:
  secret_key: "abcdef12345678"
  image_proxy: true

search:
  formats:
    - html
    - json

۵. برای اعمال ری‌استارت کنید:

docker cp ~/searxng/searxng/settings.yml searxng:/etc/searxng/settings.yml
docker restart searxng

۶. تأیید کنید کار می‌کند:

curl -s "http://localhost:8888/search?q=test&format=json" | python3 -c \
  "import sys,json; d=json.load(sys.stdin); print(f'{len(d[\"results\"])} results')"

باید چیزی شبیه 10 results ببینید. اگر 403 Forbidden گرفتید قالب JSON هنوز غیرفعال است — گام ۴ را دوباره بررسی کنید.

۷. هرمس را پیکربندی کنید:

# ~/.hermes/.env
SEARXNG_URL=http://localhost:8888

سپس SearXNG را به‌عنوان بک‌اند جستجو در ~/.hermes/config.yaml انتخاب کنید:

yaml
web:
  search_backend: "searxng"

یا از مسیر hermes tools ← Web Search & Extract ← SearXNG ست کنید.

گزینهٔ B — استفاده از نمونهٔ عمومی

نمونه‌های عمومی SearXNG در searx.space فهرست شده‌اند. نمونه‌هایی که قالب JSON فعال دارند را فیلتر کنید ‏(در جدول نمایش داده می‌شود).

# ~/.hermes/.env
SEARXNG_URL=https://searx.example.com
⚠️ نمونه‌های عمومی

نمونه‌های عمومی rate limit دارند، آپ‌تایم متغیری دارند و ممکن است هر لحظه قالب JSON را ببندند. برای استفادهٔ عملیاتی، خودمیزبانی قویاً توصیه می‌شود.

SearXNG را به یک ارائه‌دهندهٔ استخراج جفت کنید

‏SearXNG جستجو را انجام می‌دهد؛ برای web_extract ارائه‌دهندهٔ جداگانه لازم دارید. از کلیدهای هر-قابلیت استفاده کنید:

yaml
# ~/.hermes/config.yaml
web:
  search_backend: "searxng"
  extract_backend: "firecrawl"   # or tavily, exa, parallel

با این config هرمس برای همهٔ کوئری‌های جستجو از SearXNG و برای استخراج URL از Firecrawl استفاده می‌کند — ترکیب جستجوی رایگان با استخراج باکیفیت.

Tavily

جستجو و استخراج بهینه‌شده-برای-AI. Tavily را در hermes tools انتخاب کنید ‏(یا web.backend: tavily ست کنید) تا بدون‌کلید و بدون حساب استفاده شود ‏(rate-limit شده). وقتی سقف‌های بالاتر خواستید کلید API بگذارید.

# optional — skip this for keyless access after selecting Tavily
# ~/.hermes/.env
TAVILY_API_KEY=tvly-your-key-here

کلید را از app.tavily.com بگیرید. بخش Tavily keyless را ببینید.

نصب‌های خالی Firecrawl را به‌عنوان پیش‌فرض نامی نگه می‌دارند. Tavily بدون‌کلید به‌طور خودکار انتخاب نمی‌شود.

Exa

جستجوی عصبی با درک معنایی. برای پژوهش و یافتن محتوای مفهوماً مرتبط خوب است.

# ~/.hermes/.env
EXA_API_KEY=your-exa-key-here

کلید را از exa.ai بگیرید. سطح رایگان ۱٬۰۰۰ جستجو در ماه دارد.

Parallel

جستجو و استخراج AI-native با قابلیت‌های پژوهش عمیق.

# ~/.hermes/.env
PARALLEL_API_KEY=your-parallel-key-here

دسترسی را از parallel.ai بگیرید.

xAI ‏(Grok)

‏web_search را به ابزار سرور-سمتِ web_search ی Grok روی Responses API مسیریابی می‌کند. Grok خود جستجوی واقعی را اجرا و نتایج برتر را به‌صورت JSON ساختاریافته برمی‌گرداند.

با هر مسیر اعتبارنامه‌ای کار می‌کند — بدون متغیر محیطی جدید، بدون ویزارد جدید:

# ~/.hermes/.env (env-var path)
XAI_API_KEY=sk-xai-your-key-here

یا برای مشترکان SuperGrok:

hermes auth add xai-oauth

سپس xAI را به‌عنوان بک‌اند جستجو انتخاب کنید:

yaml
# ~/.hermes/config.yaml
web:
  backend: "xai"

تنظیمات اختیاری:

yaml
web:
  backend: "xai"
  xai:
    model: grok-build-0.1        # reasoning model required by web_search (default)
    allowed_domains:             # optional, max 5 — mutex with excluded_domains
      - arxiv.org
    excluded_domains:            # optional, max 5
      - example-spam.com
    timeout: 90                  # seconds (default)

فقط-جستجو — اگر web_extract هم می‌خواهید با Firecrawl / Tavily / Exa / Parallel جفتش کنید. روی خطای 401 ارائه‌دهنده یک بار نوسازی اجباری توکن OAuth انجام و دوباره تلاش می‌کند ‏(پوشش‌دهندهٔ ابطال وسط-بازه و توکن‌های مبهمی که بررسی proactive انقضا نمی‌تواند decode کند)؛ اعتبارنامه‌های env-var از تلاش مجدد عبور نمی‌کنند.

⚠️ مدل اعتماد

برخلاف ارائه‌دهنده‌های مبتنی-بر-ایندکس ‏(Brave، ‏Tavily، ‏Exa) که نتایج موتور جستجو را کلمه‌به‌کلمه برمی‌گردانند، xAI یک LLM است که انتخاب می‌کند کدام URLها عرضه شوند و خودشان عنوان‌ها و توضیحات را می‌نویسد. محتوای کوئری روی خروجی اثر می‌گذارد، پس یک کوئری خرابکارانه ‏(مثلاً تزریق‌شده از ورودی نامعتبری که ایجنت برداشته) می‌تواند در اصل Grok را به سمت صدور URLهای انتخاب-مهاجم هُل دهد. با URLهای برگشتی مثل هر لینک مدل‌ساخته رفتار کنید — قبل از واکشی اعتبارسنجی کنید، مخصوصاً وقتی کوئری از ورودی غیرقابل‌اعتماد آمده.

۴ پیکربندی

بک‌اند واحد

یک ارائه‌دهنده برای همهٔ قابلیت‌های وب:

yaml
# ~/.hermes/config.yaml
web:
  backend: "searxng"   # firecrawl | searxng | brave-free | ddgs | tavily | exa | parallel | xai

پیکربندی هر-قابلیت

ارائه‌دهنده‌های متفاوت برای جستجو در برابر استخراج. اینطور می‌توانید جستجوی رایگان ‏(SearXNG) را با ارائه‌دهندهٔ استخراج پولی ترکیب کنید یا برعکس:

yaml
# ~/.hermes/config.yaml
web:
  search_backend: "searxng"     # used by web_search
  extract_backend: "firecrawl"  # used by web_extract

وقتی کلیدهای هر-قابلیت خالی‌اند هر دو به web.backend سقوط می‌کنند. فقط وقتی هیچ‌وقت هیچ انتخاب وبی نوشته نشده باشد بک‌اند از هر کلید/URL حاضر auto-detect می‌شود — به‌محض وجود یک انتخاب، runtime همیشه از همان استفاده می‌کند و اضافه کردن یک کلید به .env ترافیک وب را تغییر مسیر نمی‌دهد.

ترتیب اولویت ‏(هر-قابلیت):

  1. web.search_backend / ‏web.extract_backend ‏(صریحِ هر-قابلیت)
  2. web.backend ‏(fallback مشترک؛ ‏nous = Tool Gateway مدیریت‌شده)
  3. آشکارسازی خودکار از متغیرهای محیطی ‏(فقط راه‌اندازی‌های هرگز-پیکربندی‌نشده)

آشکارسازی خودکار

اگر تا حالا هرگز بک‌اندی انتخاب نشده باشد ‏(نه web.backend نه کلید هر-قابلیتی توسط شما یا hermes tools نوشته شده)، هرمس بر اساس کدام اعتبارنامه‌ها ست‌اند، اولین موجود را برمی‌گزیند:

اعتبارنامهٔ حاضربک‌اند خودانتخاب
TAVILY_API_KEYtavily
EXA_API_KEYexa
PARALLEL_API_KEYparallel

(هیچ‌چیز ست نشده)حلقهٔ بدون‌کلید: exa / parallel / tavily / firecrawl / keenable ‏(round-robin)

حلقهٔ رایگانِ بدون‌کلید: وقتی هیچ‌کدام از اعتبارنامه‌های بالا حاضر نیست، درخواست‌ها بین تیرهای عمومی رایگان پنج فروشنده ‏(Exa، ‏Parallel، ‏Tavily، ‏Firecrawl، ‏Keenable) می‌چرخند تا ابزارهای وب روی نصب تازه با صفر پیکربندی کار کنند — و درخواست rate-limit شده خودکار به فروشندهٔ بعدی حلقه failover می‌شود. برای توقف چرخش یک فروشنده را در hermes tools پین کنید ‏(حلقه بعدازآن فقط به‌عنوان زنجیرهٔ failover روی throttle ها به کار می‌رود). همهٔ تیرهای رایگان تحت بار انفجاری vendor-rate-limited اند؛ مصرف عادی پایدار راحت رد می‌شود. برای خاموش کردن سطح web.keyless_fallback: false — با خاموشی و نبود اعتبارنامه، ابزارهای وب تا پیکربندی یک ارائه‌دهنده غیرقابل‌دسترس‌اند.

نجات یک‌بارهٔ بدون‌کلید برای بک‌اندهای کلیددار: وقتی بک‌اند انتخابی/کلیددار شما یک فراخوانی را شکست بخورد ‏(کلید بد، outage، ‏5xx بالادستی)، همان فراخوانی خودکار روی حلقهٔ رایگانِ بدون‌کلید دوباره تلاش می‌کند به‌جای خطا دادن — نتیجه ثبت می‌کند کدام فروشنده سرویس داد و چرا ‏(rescued_from / backend_error). failover هرگز sticky نیست: خیلی زودتر از همین web_search/web_extract بعدی دوباره بک‌اند انتخابی‌تان امتحان می‌شود. با web.keyless_rescue: false غیرفعال شود ‏(هرگاه keyless_fallback خاموش باشد این هم خاموش است).

xAI Web Search در زنجیرهٔ auto-detection نیست — ست بودن XAI_API_KEY ‏(یا ورود با xAI Grok OAuth) ترافیک وب را خودکار از xAI عبور نمی‌دهد، چون آن اعتبارنامه‌ها برای inference / TTS / تولید تصویر هم به کار می‌روند و ممکن است کاربر برای وب بک‌اند دیگری بخواهد. صریحاً با web.backend: "xai" شرکت کنید.

۵ تأیید راه‌اندازی

‏hermes setup را اجرا کنید تا ببینید کدام بک‌اند وب آشکار شده:

✅ Web Search & Extract (searxng)

یا از طریق CLI:

# Activate the venv and run the web tools module directly
source ~/.hermes/hermes-agent/.venv/bin/activate
python -m tools.web_tools

این بک‌اند فعال و وضعیتش را چاپ می‌کند:

✅ Web backend: searxng
   Using SearXNG (search only): http://localhost:8888

۶ عیب‌یابی

‏web_search مقدار {"success": false} برمی‌گرداند

  • بررسی کنید SEARXNG_URL قابل‌رسیدگی است: ‏curl -s "http://localhost:8888/search?q=test&format=json"
  • اگر HTTP 403 گرفتید قالب JSON غیرفعال است — json را به فهرست formats در settings.yml اضافه و ری‌استارت کنید
  • اگر خطای اتصال گرفتید شاید کانتینر روشن نیست: ‏docker ps | grep searxng

‏web_extract می‌گوید «search-only backend»

‏SearXNG نمی‌تواند محتوای URL استخراج کند. ‏web.extract_backend را به ارائه‌دهنده‌ای که استخراج پشتیبانی می‌کند بدهید:

yaml
web:
  search_backend: "searxng"
  extract_backend: "firecrawl"  # or tavily / exa / parallel

‏SearXNG صفر نتیجه برمی‌گرداند

بعضی نمونه‌های عمومی بعضی موتورها یا دسته‌ها را بسته‌اند. امتحان کنید:

  • یک کوئری متفاوت
  • یک نمونهٔ عمومی دیگر از searx.space
  • راه‌اندازی نمونهٔ اختصاصی خودتان برای نتایج قابل‌اعتماد

Rate limit شدن روی نمونهٔ عمومی

به نمونهٔ خودمیزبان سوئیچ کنید ‏(گزینهٔ A بالاتر). با Docker نمونهٔ خودتان هیچ rate limit ای ندارد.

‏web_extract محتوای بریده با پانوشت [TRUNCATED] برمی‌گرداند

برای صفحات بالای بودجهٔ نویسه طبیعی است. پانوشت فایل روی-دیسک حامل متن کامل تمیز و فراخوانی دقیق read_file را برای ورق‌زدن میانهٔ حذف‌شده نام می‌برد. برای دیدن بیشتر داخل خروجی، web.extract_char_limit را در config.yaml بالا ببرید یا char_limit بزرگ‌تری روی فراخوانی پاس دهید.

۷ مهارت اختیاری: ‏searxng-search

برای ایجنت‌هایی که باید مستقیماً با curl از SearXNG استفاده کنند ‏(مثلاً به‌عنوان fallback وقتی تول‌ست وب در دسترس نیست)، مهارت اختیاری searxng-search را نصب کنید:

hermes skills install official/research/searxng-search

این مهارت به ایجنت یاد می‌دهد چگونه:

  • API ی JSON ی SearXNG را با curl یا پایتون صدا بزند
  • بر اساس دسته فیلتر کند ‏(general، ‏news، ‏science و…)
  • صفحه‌بندی و حالت‌های خطا را مدیریت کند
  • وقتی SearXNG در دسترس نیست با لطف fallback کند
