پروکسی اشتراک ‏(Subscription Proxy)

پروکسی اشتراک یک سرور HTTP محلی است که به اپ‌های بیرونی — ‏OpenViking، ‏Karakeep، ‏Open WebUI، هر چیزی که chat completions سازگار-با-OpenAI حرف می‌زند — اجازه می‌دهد اشتراکِ ارائه‌دهندهٔ مدیریت‌شده-توسط-هرمس شما را به‌عنوان نقطهٔ پایانی LLM شان استفاده کنند. پروکسی اعتبارنامهٔ درست را الصاق می‌کند ‏(و خودکار refresh می‌کند) تا اپ هیچ‌وقت کلید API ایستا لازم نداشته باشد.

این با سرور API فرق دارد:

سرور APIپروکسی اشتراک
چه چیزی سرویس می‌کندایجنت خودتان ‏(تول‌ست کامل، حافظه، مهارت‌ها)استنتاج خام مدل
مورد استفاده«هرمس را بک‌اند چت کن»«اشتراک Portal ام را از یک اپ دیگر استفاده کن»
احراز هویت‏API_SERVER_KEY ی شماهر bearer ی ‏(پروکسی واقعی را الصاق می‌کند)
فراخوانی ابزاربله — ایجنت ابزار اجرا می‌کندنه — فقط passthrough

وقتی می‌خواهید ایجنت را بک‌اند کنید از سرور API استفاده کنید. وقتی فقط مدل را از طریق اشتراکتان می‌خواهید از پروکسی.

۱ شروع سریع

۱. وارد ارائه‌دهنده‌تان شوید ‏(یک‌بار)

hermes portal

این مرورگر را برای جریان OAuth ی Nous Portal باز می‌کند. هرمس توکن refresh را در ~/.hermes/auth.json ذخیره می‌کند — همان جایی که همهٔ لاگین‌های ارائه‌دهندهٔ هرمس زندگی می‌کنند.

۲. پروکسی را روشن کنید

hermes proxy start
Starting Hermes proxy for Nous Portal
  Listening on:  http://127.0.0.1:8645/v1
  Forwarding to: (resolved per-request from your subscription)
  Use any bearer token in the client — the proxy attaches your real credential.

بگذارید در پیش‌زمینه اجرا بماند. اگر می‌خواهید بعد از logout هم زنده بماند از tmux، ‏nohup یا یک unit ی systemd استفاده کنید.

۳. اپتان را به آن اشاره دهید

هر config سازگار-با-OpenAI همان سه‌تایی را می‌گیرد:

Base URL:   http://127.0.0.1:8645/v1
API key:    anything (e.g. "sk-unused")
Model:      Hermes-4-70B    # or Hermes-4.3-36B, Hermes-4-405B

پروکسی هدر Authorization ی اپ شما را نادیده می‌گیرد و اعتبارنامهٔ واقعی Portal تان را به درخواست upstream الصاق می‌کند. refresh ها وقتی bearer به انقضا نزدیک شود خودکار انجام می‌شوند.

۲ ارائه‌دهنده‌های موجود

hermes proxy providers

فعلاً ارسال‌شده: ‏nous ‏(Nous Portal) و xai ‏(xAI / Grok). ارائه‌دهنده‌های OAuth بیشتر با پیاده‌سازی رابط UpstreamAdapter در hermes_cli/proxy/adapters/ قابل‌اضافه‌اند.

۳ بررسی وضعیت

hermes proxy status
Hermes proxy upstream adapters

  [nous    ] Nous Portal — ready (bearer expires 2026-05-15T06:43:21Z)

اگر «not logged in» دیدید hermes portal را اجرا کنید. اگر «credentials need attention» دیدید توکن refresh تان ابطال شده ‏(نادر — وقتی رخ می‌دهد که از UI وب Portal خارج شده باشید) — کافی است دوباره hermes portal را اجرا کنید.

۴ مسیرهای مجاز

پروکسی فقط مسیرهایی را عبور می‌دهد که upstream واقعاً سرویس کند. برای Nous Portal:

مسیرهدف
/v1/chat/completionsChat completions ‏(استریم + غیراستریم)
/v1/completionsText completions قدیمی
/v1/embeddingsEmbeddings
/v1/modelsفهرست مدل‌ها

مسیرهای دیگر ‏(/v1/images/generations، ‏/v1/audio/speech و…) خطای 404 با پیام شفافِ اشاره‌کننده به مسیرهای مجاز برمی‌گردانند. این باعث می‌شود کلاینت‌های سرگردان درخواست‌های عجیب به upstream نشت ندهند.

۵ پیکربندی OpenViking برای استفاده از Portal

OpenViking یک پایگاه‌دادهٔ زمینه است که برای VLM اش ‏(مدل بینایی/زبانِ استخراج حافظه‌ها) و مدل embedding به ارائه‌دهندهٔ LLM نیاز دارد. با پروکسی می‌توانید vlm.api_base اش را روی پروکسی محلی‌تان بگذارید:

فایل ~/.openviking/ov.conf را ویرایش کنید:

json
{
  "vlm": {
    "provider": "openai",
    "model": "Hermes-4-70B",
    "api_base": "http://127.0.0.1:8645/v1",
    "api_key": "unused-proxy-attaches-real-creds"
  }
}

سپس پروکسی را در یک ترمینال کنار openviking-server روشن کنید:

# Terminal 1
hermes proxy start

# Terminal 2
openviking-server

فراخوانی‌های VLM ی OpenViking حالا از اشتراک Portal شما عبور می‌کنند. سمت مدل embedding همچنان ارائه‌دهندهٔ خودش را می‌خواهد — Portal ‏/v1/embeddings را سرویس می‌کند ولی انتخاب مدل به سطح پلنتان بستگی دارد؛ ‏portal.nousresearch.com/models را چک کنید.

۶ پیکربندی Karakeep ‏(یا هر اپ بوکمارک/خلاصه‌ساز)

Karakeep برای خلاصه‌سازی بوکمارک‌ها API سازگار-با-OpenAI می‌گیرد. در config آن:

# Karakeep .env
OPENAI_API_BASE_URL=http://127.0.0.1:8645/v1
OPENAI_API_KEY=any-non-empty-string
INFERENCE_TEXT_MODEL=Hermes-4-70B

همین الگو برای Open WebUI، ‏LobeChat، ‏NextChat یا هر کلاینت دیگرِ سازگار-با-OpenAI کار می‌کند.

۷ نمایش روی LAN

به‌طور پیش‌فرض پروکسی روی 127.0.0.1 bind می‌شود ‏(فقط localhost). برای اینکه ماشین‌های دیگر شبکه‌تان استفاده کنند:

hermes proxy start --host 0.0.0.0 --port 8645

⚠ بدانید: هر کسی در شبکه‌تان حالا می‌تواند از اشتراک Portal تان استفاده کند. پروکسی احراز هویت خودش را ندارد — هر bearer ی را می‌پذیرد. اگر فراتر از شبکهٔ مطمئنتان expose اش می‌کنید از فایروال، ‏VPN یا reverse proxy با احراز هویت مناسب استفاده کنید.

۸ Rate limit ها

محدودیت‌های RPM/TPM ی سطح Portal تان روی کل پروکسی اعمال می‌شود. پروکسی fan-out یا pooling نمی‌کند — یک bearer واحد با سهمیهٔ کامل اشتراکتان است. مصرف را در portal.nousresearch.com زیر نظر بگیرید.

۹ معماری

پروکسی عمداً مینیمال است. به‌ازای هر درخواست:

  1. دریافت POST /v1/chat/completions از اپ شما
  2. یافتن اعتبارنامهٔ فعلی adapter ‏(refresh در صورت نزدیک بودن انقضا)
  3. عبور verbatim بدنهٔ درخواست همراه Authorization: Bearer <minted-key>
  4. استریم پاسخ بدون تغییر به عقب ‏(SSE حفظ می‌شود)

بدون تبدیل. بدون لاگ بدنهٔ درخواست‌ها. بدون حلقهٔ ایجنت. پروکسی یک passthrough الصاق-کنندهٔ اعتبارنامه است.

۱۰ آینده: ارائه‌دهنده‌های OAuth بیشتر

سیستم adapter پلاگین‌پذیر است. افزودن ارائه‌دهندهٔ جدید ‏(مثلاً HuggingFace، نقطهٔ پایانی چت GitHub Copilot، ‏Anthropic از طریق OAuth) نیازمند پیاده‌سازی UpstreamAdapter در hermes_cli/proxy/adapters/<provider>.py و ثبت آن در adapters/__init__.py است. ارائه‌دهنده‌هایی که در سطح پروتکل سازگار-با-OpenAI نیستند ‏(مثلاً Anthropic Messages API) به لایهٔ تبدیل نیاز دارند که خارج از دامنهٔ شکل فعلی است.
