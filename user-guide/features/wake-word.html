واژهٔ بیدارباش ‏(«Hey Hermes»)

‏واژهٔ بیدارباش هرمس را در CLI، ‏TUI و اپ دسکتاپ به دستیار بدون-دست تبدیل می‌کند: با یک تنظیم روشن، هرمس در پس‌زمینه گوش می‌دهد تا عبارت تریگر گفته شود. بگوییدش و هرمس نشست تازه‌ای شروع، میکروفون را باز، فرمانتان را از طریق خط‌لوله عادی صوتی ضبط و جواب می‌دهد — دقیقاً مثل «Hey Siri» یا «Alexa». با ‏surface انتخاب کنید کدام گوش می‌دهد.

تشخیص کاملاً روی-دستگاه اجرا می‌شود. شنوندهٔ همیشه-روشن فقط واژهٔ بیداری را زیر نظر دارد؛ هیچ صدایی از ماشین شما خارج نمی‌شود تا واقعاً فرمانی به ایجنت بگویید.

۱ نحوهٔ کار

  1. با ‏wake_word.enabled: true ‏(یا بعد از ‎/wake on)، آشکارساز سبک hotword روی دستگاه ورودی پیکربندی‌شده‌تان یا میکروفون پیش‌فرض پروسه وقتی ‏wake_word.input_device ست نیست گوش می‌دهد.
  2. وقتی عبارت بیداری را بشنود خودش را مکث می‌کند ‏(میکروفون آزاد)، نشست جدیدی شروع و یک گفته با تشخیص سکوت حالت صوتی ضبط می‌کند.
  3. سخنتان رونویسی و به ایجنت فرستاده می‌شود. بعد از ریپلای، شنونده خودکار ازسر گرفته و منتظر واژهٔ بیدارباش بعدی می‌ماند.

پیش‌فرض خاموش است — تا روشنش نکنید هیچ‌چیز گوش نمی‌دهد.

در اپ دسکتاپ، گفتگوی صوتی بدون-دست با صرفاً گفتن «stop» تمام می‌شود ‏(یا «never mind»، «goodbye»، «cancel»، «that's all») — فرمان گفتاری گفتگو را تمام می‌کند به‌جای اینکه به ایجنت برود. فقط فرمان stop کل-گفته تطبیق می‌یابد، پس درخواست واقعی مثل «stop the docker container» همچنان عادی عبور می‌کند.

۲ دسکتاپ راه‌دور ‏(گرفتن سمت-کلاینت)

وقتی اپ دسکتاپ به یک بک‌اند هرمسِ راه‌دور وصل می‌شود ‏(مثلاً میزبان headless داکری یا ماشینی در اتاق دیگر)، بک‌اند اغلب هیچ میکروفونی ندارد. PortAudio سمت-سرور بعداً با «Failed to open the wake-word microphone.» شکست می‌خورد.

هرمس برای این مورد گرفتن سمت-کلاینت را پشتیبانی می‌کند:

  1. دسکتاپ wake را با ‏capture: client مسلح می‌کند ‏(خودکار برای GUI وقتی بک‌اند دستگاه ورودی محلی ندارد، یا صریحاً پایین ست کنید).
  2. ‏openWakeWord همچنان روی بک‌اند اجرا می‌شود ‏(همان موتورها، همان مدل‌ها).
  3. دسکتاپ میکروفون محلی Mac/PC را باز، به ۱۶kHz مونو int16 resample و فریم‌های کوتاه از طریق RPC ‏wake.feed استریم می‌کند.
  4. هنگام تشخیص بک‌اند مثل همیشه ‏wake.detected صادر می‌کند؛ دسکتاپ خط‌لوله عادی صوتی را روی میکروفون کلاینت شروع می‌کند.
yaml
wake_word:
  enabled: true
  capture: auto    # auto | local | client
  # auto   — local PortAudio unless the desktop arms with client_capture
  # local  — always open the backend mic (CLI/TUI default)
  # client — always expect wake.feed PCM from the desktop (remote-friendly)

‏GUI دسکتاپ همیشه روی ‏wake.start مقدار ‏client_capture: true می‌دهد، پس بک‌اندهای راه‌دور بدون میکروفون خودکار در حالت client مسلح می‌شوند. CLI و TUI مگر صریحاً ‏capture: client بگذارید گرفتن محلی نگه می‌دارند.

یادداشت حریم خصوصی: با گرفتن سمت-کلاینت، PCM مربوط به wake از طریق WebSocket احرازشدهٔ دسکتاپ↔بک‌اند سفر می‌کند ‏(همان کانال بقیهٔ نشست). تشخیص همچنان صدا را به APIهای wake شخص ثالث نمی‌فرستد؛ موتور داخل پروسهٔ بک‌اند است.

پیش‌فرض عبارت «hey hermes» است — مدلی برای آن همراه هرمس عرضه می‌شود، پس از جعبه و بدون آموزش کار می‌کند. ‏(در اولین استفاده openWakeWord مدل‌های اشتراکی استخراج-ویژگی خودش را دانلود می‌کند — یک دریافت کوچک یک‌باره.)

هر دو اولین بار که واژهٔ بیدارباش را فعال کنید lazy-install می‌شوند ‏(نصب‌های دسکتاپ ساخته‌شده با ‏--include-desktop آنها را پیش‌نصب می‌کنند تا گوش فوراً کار کند). نصب پیش‌ازموعد:

cd ~/.hermes/hermes-agent && uv pip install -e ".[wake]"

۴ شروع سریع

bash
# In an interactive `hermes` session:
/wake on        # start listening (installs the engine on first use)
/wake status    # show phrase, provider, and state
/wake off       # stop listening

در اپ دسکتاپ روی آیکون گوش در کامپوزر کلیک کنید.

کلید toggle خودِ تنظیم است: روشن/خاموش کردن واژهٔ بیدارباش — از طریق ‏/wake یا دکمهٔ گوش دسکتاپ — مقدار ‏wake_word.enabled را هم در config.yaml می‌نویسد، پس انتخاب شما بین نشست‌ها ماندگار است. دستی هم می‌توانید برگردانید:

wake_word:
  enabled: true

۵ پیکربندی

yaml
wake_word:
  enabled: false
  surface: auto               # eligible surface: "auto" | "cli" | "tui" | "gui"
  input_device: null           # PortAudio input index or device-name substring; null = process default
  capture: auto               # auto | local | client — where PCM is captured (see Remote desktop)
  provider: openwakeword      # "openwakeword" (free, local) | "sherpa" (free, any phrase) | "porcupine"
  phrase: "hey hermes"        # cosmetic label only — detection is keyed by the model/keyword below
  sensitivity: 0.6            # 0.0-1.0 — higher = stricter (fewer false triggers), consistent across all engines
  confirmation_frames: 3      # openWakeWord only — consecutive over-threshold frames required to fire
  start_new_session: true     # start a fresh session on wake vs. continue the current one
  openwakeword:
    model: hey_hermes         # bundled default; OR a built-in name OR a path to a custom .onnx/.tflite
    inference_framework: ""   # "" (auto) | "onnx" | "tflite"
  porcupine:
    keyword: jarvis           # built-in keyword OR path to a custom .ppn

‏sensitivity، ‏phrase و ‏start_new_session روی هر دو موتور اعمال می‌شوند. بلوک‌های ‏openwakeword و ‏porcupine مدل تشخیص واقعی را انتخاب می‌کنند.

‏input_device مستقیم به استریم PortAudio ‏(sounddevice) مربوط به شنونده wake داده می‌شود. یا اندیس عددی دستگاه یا زیررشتهٔ بی‌ابهام نام دستگاه را بدهید. این تنظیم فقط گرفتن wake-word را عوض می‌کند؛ push-to-talk دسکتاپ همچنان مسیر میکروفون اپلیکیشن دسکتاپ را استفاده می‌کند.

کاهش تریگرهای کاذب روی گفتگوی محیطی

‏openWakeWord هر بار یک فریم صوتی کوتاه ‏(~۸۰ms) را امتیاز می‌دهد، پس یک واک خالص در گفتگوی پس‌زمینه گاهی می‌تواند یک فریم واحد را بالای آستانه ببرد و واژهٔ بیدارباش را ناخواسته شلیک کند. دو کلید این را کنترل می‌کنند:

  • ‏confirmation_frames ‏(پیش‌فرض ‏3، فقط openWakeWord) — چند فریم متوالی بالای آستانه لازم است تا wake شلیک شود. یک «hey hermes» واقعی امتیاز بالا را چندین فریم نگه می‌دارد؛ یک لرزش محیطی فقط یکی را می‌زند. اگر هنوز در اتاق پرصدا تریگر کاذب دارید بالا ببرید ‏(مثلاً ‏4–5)؛ هزینه چند ده میلی‌ثانیه تأخیر اضافه است. ‏1 رفتار قدیمیِ شلیک-در-اولین-فریم را برمی‌گرداند.
  • ‏sensitivity ‏(پیش‌فرض ‏0.6) — آستانهٔ تشخیص، ‏0.0–1.0. بالاتر = سخت‌گیرانه‌تر ‏(تریگر کاذب کمتر). جهت در همهٔ موتورها سازگار است — برای openWakeWord همان آستانهٔ امتیاز خام به‌ازای-فریم، برای sherpa به آستانهٔ کلیدواژه نگاشت و برای Porcupune داخلی معکوس می‌شود تا «بالاتر = سخت‌گیرانه‌تر» آنجا هم برقرار باشد. پیش‌فرض ‏0.6 بالاتر از خط پایه سهل‌گیرِ ‏0.5 مربوط به openWakeWord است که اجازه می‌داد near-miss هایی مثل «hey hor» عبور کنند؛ اگر هنوز شلیک کاذب دارید به ‏0.8 نزدیک و اگر گفته‌های واقعی «hey hermes» از دست می‌روند پایینش بیاورید.

موتورهای ‏sherpa و ‏porcupine کل عبارت را داخلی decode می‌کنند، پس مشکل spike تک-فریمی ندارند و ‏confirmation_frames را نادیده می‌گیرند ‏(ولی ‏sensitivity را همچنان رعایت می‌کنند).

‏inference_framework بک‌اند openWakeWord را انتخاب می‌کند. خالی بگذارید ‏(پیش‌فرض) تا هرمس به‌ازای هر پلتفرم انتخاب کند: tflite روی Apple Silicon، جای دیگر onnx. بک‌اند onnx مربوط به openWakeWord روی macOS ARM64 امتیازهای تقریباً-صفر برمی‌گرداند ‏(issue ‏#336)، پس شنونده‌ای که آنجا روی ‏onnx قفل شده مسلح، در وضعیت گوش‌دادن نمایش و هرگز شلیک نمی‌کند. بک‌اند tflite روی macOS به ‏ai-edge-litert نیاز دارد که هرمس هنگام نیاز کنار سایر وابستگی‌های wake-word نصب می‌کند.

سطوح ‏(CLI، ‏TUI، ‏GUI)

‏واژهٔ بیدارباش در هر سه سطح هرمس کار می‌کند و ‏surface تعیین می‌کند کدام مالک شنونده باشد و هنگام شلیک نشست جدید باز کند:

‏surfaceرفتار
auto ‏(پیش‌فرض)همهٔ سطوح محلی واجد شرایط‌اند؛ اولینی که مسلح شود مالک شنونده می‌شود.
cliفقط CLI کلاسیک ‏hermes.
tuiفقط ‏hermes --tui.
guiفقط اپ دسکتاپ.

آشکارساز روی-دستگاه و تک-میکروفونی است، پس در هر لحظه فقط یک سطح گوش می‌دهد حتی وقتی سطوح هرمس در پروسه‌های جدا اجرا می‌شوند. مالکیت چسبناک است: اولین مدعی واجدشرایط شنونده را نگه می‌دارد تا متوقف، قطع یا پروسه‌اش خارج شود. هرمس بی‌صدا به سطح دیگری failover نمی‌کند. وقتی می‌خواهید مالکیت را pin کنید به‌جای برنده-شدن-اولین-مدعی، مقدار ‏surface را ست کنید. ‏TUI و GUI دسکتاپ همان بک‌اند Python را شریک‌اند ‏(tui_gateway) که آشکارساز را سمت-سرور اجرا و حین ضبط فرمان میکروفون را به گرفتن صدا واگذار می‌کند.

۶ استفاده از عبارت متفاوت

«Hey Hermes» از جعبه کار می‌کند — مدل همراه‌بستهٔ openWakeWord ‏(model: hey_hermes) پیش‌فرض است. برای بیدار شدن روی چیز دیگر، ساده‌ترین مسیر موتور واژگان-باز است:

گزینه A — sherpa ‏(هر عبارتی، صفر آموزش)

عبارت موردنظرتان را تایپ کنید؛ هنگام runtime توکنیزه می‌شود — «hey coder»، «computer»، «wake up neo»، هر چیزی:

yaml
wake_word:
  enabled: true
  provider: sherpa
  phrase: "hey coder"        # detection key — just type your phrase

مدل کوچک KWS انگلیسی ‏(~۱۳ MB) یک‌بار در اولین استفاده دانلود می‌شود. هر پروفایل می‌تواند عبارت خودش را داشته باشد — «hey <profile>» برای هر پروفیلی که اجرا می‌کنید.

بیدارکردن یک پروفایل مشخص ‏(دسکتاپ)

با موتور sherpa، یک شنونده می‌تواند هر پروفایلی را بیدار کند. هر پروفایلی که ‏wake_word.enabled: true در پیکربندی‌اش دارد خودکار ثبت می‌شود؛ عبارتش وقتی unset باشد پیش‌فرض ‏hey <profile name> است. عبارت پروفایلی را بگویید و اپ دسکتاپ زنده به آن پروفایل سوئیچ، نشست تازه‌ای آنجا باز و صدای بدون-دست را شروع می‌کند:

  • «hey hermes» ← پروفایل پیش‌فرض
  • «hey coder» ← پروفایل ‏coder
  • «hey trader» ← پروفایل ‏trader

برای انصراف و گوش‌دادن فقط به عبارت خودش، ‏wake_word.profile_routing: false را روی پروفایل شنونده ست کنید. CLI و TUI پروسه‌های تک-پروفایلی‌اند: عبارت بیداری متعلق به پروفایل دیگری فرمان سوییچ ‏(hermes -p <profile>) را چاپ می‌کند به‌جای مسیریابی.

نام‌ها آکوستیک بر اساس زیرواژه‌های انگلیسی‌شان تطبیق می‌یابند: عبارت‌های دومعمودی با نام‌های مجزا و ۲+ بخشی بهترین عمل را دارند. نام‌های خیلی کوتاه، آواشناسی سنگین غیرانگلیسی یا دو پروفایل با نام‌های هم‌صدا دقت را افت می‌دهند — در صورت نیاز ‏sensitivity به‌ازای-پروفایل را تنظیم کنید.

گزینه B — openWakeWord ‏(رایگان، مدل آموزش‌دیده)

مدل داخلی نام‌برد کنید ‏(hey_jarvis، ‏alexa، ‏hey_mycroft و...) یا مدل سفارشی آموزش دهید ‏(~۷۵–۹۰ دقیقه روی GPU رایگان/Colab) برای بیشترین مقاومت، فایل ‏.onnx را جایی بیندازید و ارجاع دهید:

yaml
wake_word:
  enabled: true
  provider: openwakeword
  phrase: "computer"
  openwakeword:
    model: ~/.hermes/wakewords/computer.onnx   # or a built-in name like hey_jarvis

مراجع آموزش:

  • openWakeWord
  • Colab آموزش ۲۰۲۶
💡 عبارت متمایز انتخاب کنید

عبارت‌های بیداری که با گفتار روزمره تداخل ندارند بهترین تعمیم را دارند. دو بخشی با واژه‌ای غیررایج («hermes» واجد شرایط است) بر واژه‌های رایج مثل «hello» یا «stop» می‌چربد.

گزینه C — Porcupine ‏(کلیدواژه سفارشی ظرف چند ثانیه)

کلیدواژه «Hey Hermes» را در Picovoice Console بسازید، فایل ‏.ppn را دانلود و:

yaml
wake_word:
  enabled: true
  provider: porcupine
  phrase: "hey hermes"
  porcupine:
    keyword: ~/.hermes/wakewords/hey_hermes.ppn

کلید دسترسی‌تان را در ‏~/.hermes/.env ست کنید:

PORCUPINE_ACCESS_KEY=your-key-here

۷ الزامات

  • میکروفون کارا و پشتهٔ صدای ‏sounddevice + ‏numpy ‏(مشترک با حالت صوتی).
  • یک ارائه‌دهندهٔ STT برای رونویسی فرمان گفتاری — ‏faster-whisper محلی از جعبه کار می‌کند؛ فهرست کامل ارائه‌دهنده‌ها در حالت صوتی.
  • یک ارائه‌دهندهٔ TTS برای گفتن پاسخ ‏(edge-tts پیش‌فرض بدون کلید کار می‌کند). جریان wake کاملاً بدون-دست است، پس کلید toggle تا هر دو STT و TTS آماده نباشند از مسلح شدن امتناع می‌کند — ‏hermes tools ‏(بخش Voice) آنها را راه می‌اندازد.
  • وابستگی‌های موتور wake ‏(خودکار نصب، یا ‏hermes-agent[wake]).

اگر شنونده شروع نشود ‏/wake status دقیقاً گزارش می‌کند چه چیزی غایب است.

«گوش می‌دهد» ولی هرگز بیدار نمی‌شود ‏(macOS)

‏macOS دسترسی میکروفون را به‌ازای پروسه اعطا می‌کند. کار کردن STT در اپ دسکتاپ ثابت می‌کند رندرر دسترسی میکروفون دارد — شنونده wake در بک‌اند Python اجرا می‌شود که grant خودش را می‌خواهد. بدون آن CoreAudio به بک‌اند استریمی «کارا» می‌دهد که فقط سکوت تحویل می‌دهد، پس گوش نشان می‌دهد گوش می‌دهد ولی عبارت هرگز شلیک نمی‌شود. هرمس این را تشخیص می‌دهد ‏(/wake status نشان می‌دهد «mic delivers only silence»؛ tooltip گوش دسکتاپ همین سرنخ را حمل می‌کند). اصلاح: System Settings ← Privacy & Security ← Microphone ← فعال‌سازی بک‌اند هرمس ‏(شاید به‌نام ترمینال، ‏python یا Hermes ظاهر شود)، سپس واژهٔ بیدارباش را خاموش/روشن کنید.

«گوش می‌دهد» ولی سکوت دریافت می‌کند ‏(Windows)

‏push-to-talk دسکتاپ و گرفتن wake-word از مسیرهای میکروفون متفاوتی استفاده می‌کنند. ‏push-to-talk از گرفتن مرورگریِ اپلیکیشن دسکتاپ استفاده می‌کند در حالی که شنونده wake-word یک استریم PortAudio در بک‌اند Python باز می‌کند. ممکن است یکی کار کند در حالی که دیگری ورودی ویندوزیِ بی‌صدای یا غیرقابل‌استفاده‌ای را انتخاب کرده.

‏/wake status دستگاه ورودی انتخابی و audio host API ویندوز را گزارش می‌کند. وقتی سکوت گزارش کرد ‏wake_word.input_device را روی اندیس عددی یا نام بی‌ابهام ورودی PortAudio کارا ست و بعد واژهٔ بیدارباش را toggle کنید:

hermes config set wake_word.input_device "Microphone Array"

برای برگشت به پیش‌فرض پروسه از ‏null استفاده کنید:

hermes config set wake_word.input_device null

۸ یادداشت‌ها و حدود

  • فقط سطوح محلی. واژهٔ بیدارباش در CLI، TUI و GUI دسکتاپ اجرا می‌شود — هرجا میکروفون محلی موجود باشد. در گیت‌وی پیام‌رسانی ‏(تلگرام، دیسکورد و...) اجرا نمی‌شود که میکروفون ندارد.
  • یک میکروفون در لحظه. آشکارساز حین ضبط فرمان میکروفون را آزاد و بعد از پایان نوبت پس می‌گیرد، پس با گرفتن صدا نجنگد.
  • حریم خصوصی. تشخیص hotword محلی است. اگر تریگر کاذب گرفتید ‏sensitivity را بالا و اگر شمارا از دست می‌دهد پایین ببرید.
