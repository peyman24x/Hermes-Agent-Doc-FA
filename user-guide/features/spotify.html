اسپاتیفای

هرمس می‌تواند اسپاتیفای را مستقیماً کنترل کند — پخش، صف، جستجو، پلی‌لیست‌ها، ترک‌ها/آلبوم‌های ذخیره‌شده و تاریخچهٔ شنیدن — با Web API رسمی اسپاتیفای و PKCE OAuth. توکن‌ها در ~/.hermes/auth.json ذخیره و روی خطای 401 خودکار refresh می‌شوند؛ فقط یک بار به‌ازای هر ماشین وارد می‌شوید ‏(refresh token ها بعد از ~۶ ماه منقضی می‌شوند؛ موقعش دوباره hermes auth spotify را اجرا کنید).

برخلاف یکپارچه‌سازی‌های OAuth داخلی هرمس ‏(Google، ‏GitHub Copilot، ‏Codex)، اسپاتیفای از هر کاربری می‌خواهد اپ دولوپر سبک خودش را ثبت کند. اسپاتیفای اجازه نمی‌دهد اشخاص ثالث یک اپ OAuth عمومی برای استفادهٔ همه ارسال کنند. حدود دو دقیقه وقت می‌گیرد و hermes auth spotify قدم‌به‌قدم همراهتان است.

۱ پیش‌نیازها

  • یک حساب اسپاتیفای. حساب Free برای ابزارهای جستجو، پلی‌لیست، کتابخانه و فعالیت کار می‌کند. برای کنترل پخش ‏(play، ‏pause، ‏skip، ‏seek، ‏volume، افزودن به صف، انتقال) Premium لازم است.
  • Hermes Agent نصب‌شده و در حال اجرا.
  • برای ابزارهای پخش: یک دستگاه فعال Spotify Connect — اپ اسپاتیفای باید دست‌کم روی یک دستگاه ‏(گوشی، دسکتاپ، پخش‌کنندهٔ وب، بلندگو) باز باشد تا Web API چیزی برای کنترل داشته باشد. اگر هیچ‌چیز فعال نباشد خطای 403 Forbidden با پیام «no active device» می‌گیرید؛ اسپاتیفای را روی هر دستگاهی باز کنید و دوباره تلاش کنید.

۲ راه‌اندازی

یک‌مرحله‌ای: ‏hermes tools یا setup اولین-اجرا

سریع‌ترین مسیر. اجرا کنید:

hermes tools

به 🎵 Spotify اسکرول کنید، با space روشنش کنید و با s ذخیره کنید. همین toggle هنگام جریان اولین-اجرای hermes setup / ‏hermes setup tools هم موجود است. اسپاتیفای انتخابی می‌ماند، پس فعال کردنش همانجا پیکربندی آگاه-از-ارائه‌دهندهٔ مشابه hermes tools را اجرا می‌کند.

هرمس مستقیم شما را به جریان OAuth می‌برد — اگر هنوز اپ اسپاتیفای ندارید، ساختش را inline قدم‌به‌قدم انجام می‌دهد. بعد از پایان، تول‌ست هم فعال است هم احراز هویت‌شده در یک پاس.

اگر ترجیح می‌دهید مرحله‌ها جدا باشند ‏(یا بعداً re-auth می‌کنید) از جریان دومرحله‌ای پایین استفاده کنید.

جریان دومرحله‌ای

۱. فعال کردن تول‌ست

hermes tools

‏🎵 Spotify را روشن، ذخیره کنید و وقتی ویزارد inline باز شد آن را ببندید ‏(Ctrl+C). تول‌ست روشن می‌ماند؛ فقط مرحلهٔ auth به تعویق می‌افتد.

۲. اجرای ویزارد ورود

hermes auth spotify

۷ ابزار Spotify فقط بعد از مرحلهٔ ۱ در تول‌ست ایجنت ظاهر می‌شوند — به‌طور پیش‌فرض خاموش‌اند تا کسانی که نمی‌خواهندشان schema های ابزار اضافه را در هر فراخوانی API حمل نکنند.

اگر هیچ HERMES_SPOTIFY_CLIENT_ID ای ست نباشد، هرمس ثبت اپ را inline قدم‌به‌قدم انجام می‌دهد:

  1. ‏https://developer.spotify.com/dashboard را در مرورگرتان باز می‌کند
  2. مقادیر دقیقِ قابل-چسباندن در فرم «Create app» اسپاتیفای را چاپ می‌کند
  3. Client ID ی برگشتی را از شما می‌پرسد
  4. در ~/.hermes/.env ذخیره می‌کند تا اجراهای بعدی از این مرحله عبور کنند
  5. مستقیم به جریان رضایت OAuth ادامه می‌دهد

بعد از تأیید شما، توکن‌ها زیر providers.spotify در ~/.hermes/auth.json نوشته می‌شوند. ارائه‌دهندهٔ inference فعال تغییر نمی‌کند — auth ی اسپاتیفای مستقل از ارائه‌دهندهٔ LLM شماست.

ساخت اپ اسپاتیفای ‏(آنچه ویزارد می‌خواهد)

وقتی داشبورد باز شد روی Create app کلیک و اینها را پر کنید:

شرایط را قبول و Save کنید. در صفحهٔ بعد Settings ← کپی Client ID ← چسباندن در پرامپت هرمس. تنها مقداری که هرمس لازم دارد همین است — ‏PKCE از client secret استفاده نمی‌کند.

اجرا از طریق SSH / محیط headless

اگر SSH_CLIENT یا SSH_TTY ست باشد، هرمس هم در ویزارد هم در مرحلهٔ OAuth از باز شدن خودکار مرورگر صرف‌نظر می‌کند. URL داشبورد و URL مجوزی که هرمس چاپ می‌کند را کپی، در مرورگر ماشین محلی‌تان باز و عادی ادامه دهید — شنوندهٔ HTTP محلی همچنان روی میزبان راه‌دور و پورت 43827 اجراست. مرورگر لپ‌تاپ‌تان بدون SSH local-forward به loopback راه‌دور نمی‌رسد:

ssh -N -L 43827:127.0.0.1:43827 user@remote-host

برای راه‌اندازی‌های jump-box / bastion و گیراندازی‌های دیگر ‏(mosh، ‏tmux، تداخل پورت)، بخش OAuth over SSH / Remote Hosts را ببینید.

۳ تأیید

hermes auth status spotify

نشان می‌دهد توکن‌ها حاضرند و access token چه وقت منقضی می‌شود. Refresh خودکار است: هر فراخوانی API اسپاتیفای که 401 بدهد، کلاینت refresh token را مبادله و یک بار دوباره تلاش می‌کند. refresh token ها بین ری‌استارت‌های هرمس می‌مانند، پس فقط اگر اپ را از تنظیمات حساب اسپاتیفتان لغو کنید یا hermes auth logout spotify اجرا کنید دوباره auth می‌شوید.

۴ استفاده

بعد از ورود، ایجنت به ۷ ابزار Spotify دسترسی دارد. طبیعی با ایجنت حرف می‌زنید — خودش ابزار و اقدام درست را برمی‌دارد. برای بهترین رفتار، ایجنت یک مهارت همراه بارگذاری می‌کند که الگوهای استاندارد مصرف را یاد می‌دهد ‏(اول-جستجو-بعد-پخش، چه وقت نباید preflight ی get_state کرد و…).

> what am I listening to

بلندگوهای مدیریت‌شده توسط Home Assistant

اگر Home Assistant بلندگوهایی را مدیریت کند که از قبل Spotify Connect را پشتیبانی می‌کنند ‏(مثلاً Sonos، ‏Echo، ‏Nest یا سایر بلندگوهای Connect-capable)، هر وقت اسپاتیفای آنها را ببیند خودکار در spotify_devices list ظاهر می‌شوند. هرمس برای این مسیر به پُلی بین Home Assistant ↔ اسپاتیفای نیاز ندارد — اسپاتیفای مسیریابی دستگاه را native هندل می‌کند.

از هرمس بخواهید پخش را با نام نمایشی بلندگو منتقل کند ‏(مثلاً «اسپاتیفای را ببر روی بلندگوی آشپزخانه»)، یا در اسکریپت‌نویسی ‏spotify_devices list را صدا و device_id دقیق را به spotify_devices transfer پاس دهید. اگر بلندگو غایب بود یک بار اپ اسپاتیفای یا یکپارچه‌سازی Spotify ی بلندگو را باز کنید تا اسپاتیفای آن را به‌عنوان هدف فعال Connect ثبت کند.

۵ زمان‌بندی: اسپاتیفای + cron

چون ابزارهای Spotify ابزارهای عادی هرمس‌اند، یک cron job که در نشست هرمس اجرا می‌شود می‌تواند پخش را در هر زمان‌بندی شروع کند. بدون کد جدید.

پلی‌لیست صبحگاهی

hermes cron add \
  --name "morning-commute" \
  "0 7 * * 1-5" \
  "Transfer playback to my kitchen speaker and start my 'Morning Commute' playlist. Volume to 40. Shuffle on."

ساعت ۷ صبح همهٔ روزهای هفته چه می‌شود:

  1. Cron یک نشست هرمس headless بالا می‌آورد.
  2. ایجنت پرامپت را می‌خواند، برای پیدا کردن «kitchen speaker» با نام ‏spotify_devices list را صدا و سپس ‏spotify_devices transfer ← ‏spotify_playback set_volume ← ‏spotify_playback set_shuffle ← ‏spotify_search + ‏spotify_playback play را اجرا می‌کند.
  3. موزیک روی بلندگوی هدف شروع می‌شود. هزینهٔ کل: یک نشست، چند فراخوانی ابزار، بدون ورودی انسانی.

آرام‌سازی شبانه

hermes cron add \
  --name "wind-down" \
  "30 22 * * *" \
  "Pause Spotify. Then set volume to 20 so it's quiet when I start it again tomorrow."

گیراندازی‌ها

  • هنگام شلیک cron باید یک دستگاه فعال وجود داشته باشد. اگر هیچ کلاینتی اسپاتیفای اجرا نباشد ‏(گوشی/دسکتاپ/بلندگوی Connect)، اقدامات پخش 403 no active device برمی‌گردانند. برای پلی‌لیست‌های صبحگاهی ترفند این است که به دستگاهی همیشه-روشن نشانه‌گیری کنید ‏(Sonos، ‏Echo، یک بلندگوی هوشمند) نه گوشی‌تان.
  • Premium برای هر تغییری در پخش لازم است — play، ‏pause، ‏skip، ‏volume، ‏transfer. cron job های فقط-خواندنی ‏(مثل «هر روز ترک‌های اخیراً پخش‌شده را ایمیل کن») روی Free هم بی‌نقص کار می‌کنند.
  • ایجنت cron تول‌ست‌های فعال شما را به ارث می‌برد. اسپاتیفای باید در hermes tools فعال باشد تا نشست cron ابزارهای Spotify را ببیند.
  • cron job ها با ‏skip_memory=True اجرا می‌شوند تا در انبار حافظه‌تان بنویسند.

مرجع کامل cron: بخش کارهای زمان‌بندی‌شده.

۶ خروج

hermes auth logout spotify

توکن‌ها را از ~/.hermes/auth.json حذف می‌کند. برای پاک کردن config اپ هم، ‏HERMES_SPOTIFY_CLIENT_ID ‏(و HERMES_SPOTIFY_REDIRECT_URI اگر ست کرده‌اید) را از ~/.hermes/.env حذف کنید یا ویزارد را دوباره اجرا کنید.

برای لغو اپ سمت اسپاتیفای به اپ‌های متصل به حسابتان بروید و REMOVE ACCESS را بزنید.

۷ عیب‌یابی

‏403 Forbidden — Player command failed: No active device found — اسپاتیفای باید دست‌کم روی یک دستگاه اجرا باشد. اپ اسپاتیفای را روی گوشی، دسکتاپ یا وب‌پلیر باز کنید، برای یک لحظه هر ترکی را پخش کنید تا ثبت شود و دوباره تلاش کنید. ‏spotify_devices list نشان می‌دهد الان چه چیزی مرئی است.

‏403 Forbidden — Premium required — روی حساب Free هستید و اقدامی تغییردهندهٔ پخش زده‌اید. ماتریس قابلیت بالا را ببینید.

‏204 No Content روی ‏get_currently_playing — روی هیچ دستگاهی چیزی پخش نمی‌شود. این پاسخ عادی اسپاتیفای است نه خطا؛ هرمس آن را به‌صورت نتیجهٔ خالیِ توضیحی نشان می‌دهد ‏(is_playing: false).

‏INVALID_CLIENT: Invalid redirect URI — redirect URI در تنظیمات اپ اسپاتیفتان با چیزی که هرمس استفاده می‌کند یکی نیست. پیش‌فرض http://127.0.0.1:43827/spotify/callback است. یا آن را به URI های مجاز اپ اضافه کنید یا HERMES_SPOTIFY_REDIRECT_URI را در ~/.hermes/.env روی همان که ثبت کرده‌اید بگذارید.

‏429 Too Many Requests — rate limit اسپاتیفای. هرمس خطای دوستانه برمی‌گرداند؛ یک دقیقه صبر و تلاش دوباره. اگر ادامه یافت احتمالاً حلقهٔ فشرده‌ای در یک اسکریپت دارید — سهمیهٔ اسپاتیفای تقریباً هر ۳۰ ثانیه reset می‌شود.

‏401 Unauthorized مدام برمی‌گردد — refresh token تان ابطال شده ‏(معمولاً چون اپ را از حسابتان حذف کرده‌اید یا اپ delete شده). ‏hermes auth spotify را دوباره اجرا کنید.

ویزارد مرورگر را باز نمی‌کند — اگر روی SSH هستید یا در کانتینری بدون نمایشگر، هرمس تشخیص می‌دهد و auto-open را رد می‌کند. URL داشبوردی که چاپ می‌کند را کپی و دستی باز کنید.

۸ پیشرفته: scope های سفارشی

به‌طور پیش‌فرض هرمس scope هایی را می‌خواهد که هر ابزار ارسال‌شده لازم دارد. برای محدود کردن دسترسی بازنویسی کنید:

hermes auth spotify --scope "user-read-playback-state user-modify-playback-state playlist-read-private"

مرجع scope ها: Spotify Web API scopes. اگر scope کمتری از نیاز یک ابزار بخواهید، فراخوانی‌های آن ابزار با 403 شکست می‌خورند.

پیشرفته: client ID / redirect URI سفارشی

hermes auth spotify --client-id <id> --redirect-uri http://localhost:3000/callback

یا برای همیشه در ~/.hermes/.env:

HERMES_SPOTIFY_CLIENT_ID=<your_id>
HERMES_SPOTIFY_REDIRECT_URI=http://localhost:3000/callback

redirect URI باید در تنظیمات اپ اسپاتیفتان allow-list شده باشد. پیش‌فرض برای تقریباً همه کار می‌کند — فقط اگر پورت ۴۳۸۲۷ اشغال است عوضش کنید.
