صدا و TTS ‏(Voice & Text-to-Speech)

هرمس ایجنت هم خروجی تبدیل متن به گفتار و هم رونویسی پیام صوتی را روی همهٔ پلتفرم‌های پیام‌رسانی پشتیبانی می‌کند.

💡 مشترکان Nous

اگر اشتراک پولی Nous Portal دارید، OpenAI TTS از طریق Tool Gateway بدون کلید API ی جداگانهٔ OpenAI در دسترس است. نصب‌های تازه می‌توانند ‏hermes setup --portal را اجرا کنند تا وارد شوند و همهٔ ابزارهای گیت‌وی را یکجا روشن کنند؛ نصب‌های موجود فقط برای TTS از طریق ‏hermes model یا ‏hermes tools مقدار Nous Subscription را بردارند.

‏MiniMax TTS ناحیه، نقطهٔ پایانی و اعتبارنامه را با هم انتخاب می‌کند:

  • ‏region: "global" از ‏https://api.minimax.io/v1/t2a_v2 با ‏MINIMAX_API_KEY استفاده می‌کند.
  • ‏region: "cn" از ‏https://api.minimaxi.com/v1/t2a_v2 با ‏MINIMAX_CN_API_KEY استفاده می‌کند.
  • اگر region حذف شود، ‏MINIMAX_API_KEY برای سازگاری با گذشته مقدم می‌ماند. اگر فقط MINIMAX_CN_API_KEY پیکربندی شده باشد هرمس ‏cn را برمی‌گزیند.
  • ناحیهٔ صریحاً انتخاب‌شده باید اعتبارنامهٔ متناظر خودش را داشته باشد. هرمس هرگز کلید ناحیهٔ دیگر را قرض نمی‌گیرد. بازنویسی base_url اعتبارنامهٔ انتخاب‌شده را عوض نمی‌کند و بازنویسی‌ای که به نقطهٔ پایانی رسمیِ ناحیهٔ دیگر اشاره کند reject می‌شود.

کنترل سرعت: مقدار سراسری ‏tts.speed به‌طور پیش‌فرض روی همهٔ ارائه‌دهنده‌ها اعمال می‌شود. هر ارائه‌دهنده می‌تواند با تنظیم speed خودش آن را override کند ‏(مثلاً ‏tts.openai.speed: 1.5). سرعت مخصوص-ارائه‌دهنده بر مقدار سراسری مقدم است. پیش‌فرض ‏۱٫۰ است ‏(سرعت عادی).

پرامپت‌های شخصیت Gemini

‏Gemini TTS می‌تواند جهت اجرایی زبان-طبیعی را دنبال کند. مقدار ‏tts.gemini.persona_prompt_file را روی یک فایل Markdown یا متنی محلی ست کنید که شخصیت صدا را توصیف می‌کند. فایل می‌تواند بخش‌هایی به سبک Gemini مثل ‏AUDIO PROFILE، ‏SCENE، ‏DIRECTOR'S NOTES، ‏SAMPLE CONTEXT و TRANSCRIPT داشته باشد.

اگر فایل شامل ‏{transcript} یا ‏{{ transcript }} باشد، هرمس همان placeholder را با متن زندهٔ TTS جایگزین می‌کند. در غیر این صورت هرمس خودکار بخشی برچسب‌دار TRANSCRIPT الحاق می‌کند. پرامپت شخصیت محلی می‌ماند و در پاسخ چت نشان داده نمی‌شود.

yaml
tts:
  provider: gemini
  gemini:
    voice: Algieba
    persona_prompt_file: ~/.hermes/tts/butler-voice.md

تگ‌های صوتی ‏(Gemini و xAI)

‏Gemini 3.1 Flash TTS گوگل و Grok TTS ی xAI از تگ‌های صوتی آزاد کروشه‌ای مثل ‏[whispers]، ‏[excitedly]، ‏[very slow]، ‏[laughs] و سایر یادداشت‌های اجرایی ابرازکننده پشتیبانی می‌کنند. ‏tts.gemini.audio_tags یا ‏tts.xai.auto_speech_tags را روشن کنید تا هرمس یک پاس بازنویسی مخفی قبل از TTS اجرا کند. بازنویسی فقط تگ‌های inline را داخل اسکریپت TTS درج می‌کند؛ پاسخ مرئی چت تغییر نمی‌کند.

yaml
tts:
  provider: gemini
  gemini:
    model: gemini-3.1-flash-tts-preview
    audio_tags: true
  xai:
    auto_speech_tags: true

بازنویسی از ‏auxiliary.tts_audio_tags استفاده می‌کند که پیش‌فرضش مدل اصلی چت شماست. آن تسک کمکی را override کنید اگر می‌خواهید درج تگ توسط مدلی ارزان‌تر یا سریع‌تر انجام شود.

زبان ‏(نقاط پایانی سازگار-با-OpenAI): ‏tts.openai.language به‌صورت پارامتر درخواست ‏lang_code به نقطهٔ پایانی forward می‌شود. برای سرورهای TTS سازگار-با-OpenAI است که ‏lang_code را پشتیبانی می‌کنند — مثلاً ‏Kokoro-FastAPI که در آن ‏language: "es" phonemizer اسپانیایی را به‌جای پیش‌فرض انگلیسی برمی‌گزیند. هنگام استفاده از API رسمی OpenAI که این پارامتر را نمی‌پذیرد unset بگذارید. وقتی unset باشد چیزی اضافه فرستاده نمی‌شود.

فقط اعداد صحیح مثبت پذیرفته می‌شوند. مقادیر صفر، منفی، غیرعددی یا بولی به پیش‌فرض ارائه‌دهنده برمی‌گردند تا config ی خراب نتواند تصادفاً از حد درخواست ارائه‌دهنده عبور کند.

۳ حباب‌های صوتی تلگرام و ffmpeg

حباب‌های صوتی تلگرام فرمت Opus/OGG می‌خواهند:

  • OpenAI، ‏ElevenLabs و Mistral natively Opus تولید می‌کنند — بدون setup اضافه
  • Edge TTS ‏(پیش‌فرض) MP3 خروجی می‌دهد و به ffmpeg برای تبدیل نیاز دارد
  • MiniMax TTS MP3 خروجی می‌دهد و برای حباب صوتی تلگرام به ffmpeg نیاز دارد
  • Google Gemini TTS PCM خام خروجی می‌دهد و برای کدگذاری مستقیم Opus در حباب‌های تلگرام از ffmpeg استفاده می‌کند
  • xAI TTS MP3 خروجی می‌دهد و برای حباب صوتی تلگرام به ffmpeg نیاز دارد
  • NeuTTS WAV خروجی می‌دهد و هم برای حباب صوتی تلگرام به ffmpeg نیاز دارد
  • KittenTTS WAV خروجی می‌دهد و هم برای حباب صوتی تلگرام به ffmpeg نیاز دارد
  • Piper WAV خروجی می‌دهد و هم برای حباب صوتی تلگرام به ffmpeg نیاز دارد
# Ubuntu/Debian
sudo apt install ffmpeg

# macOS
brew install ffmpeg

# Fedora
sudo dnf install ffmpeg

بدون ffmpeg، صدای Edge TTS، ‏MiniMax TTS، ‏NeuTTS، ‏KittenTTS و Piper به‌عنوان فایل صوتی معمولی فرستاده می‌شود ‏(قابل‌پخش، ولی به‌صورت پخش‌کنندهٔ مستطیلی نمایش داده می‌شود نه حباب صوتی).

💡

اگر حباب صوتی بدون نصب ffmpeg می‌خواهید به ارائه‌دهندهٔ OpenAI، ‏ElevenLabs یا Mistral سوئیچ کنید.

صداهای سفارشی xAI ‏(همانندسازی صدا)

‏xAI از همانندسازی صدای شما و استفاده از آن در TTS پشتیبانی می‌کند. در کنسول xAI یک صدای سفارشی بسازید و سپس ‏voice_id ی حاصل را در config ست کنید:

yaml
tts:
  provider: xai
  xai:
    voice_id: "nlbqfwie"   # your custom voice ID

جزئیات ضبط، فرمت‌های پشتیبانی‌شده و محدودیت‌ها را در مستندات Custom Voices ی xAI ببینید.

Piper ‏(محلی، ۴۴ زبان)

‏Piper موتور TTS عصبی سریع و محلی از Open Home Foundation ‏(نگهدارندگان Home Assistant) است. کاملاً روی CPU اجرا می‌شود، ۴۴ زبان با صداهای از-پیش-آموزش‌دیده دارد و کلید API نمی‌خواهد.

نصب با hermes tools ← Voice & TTS ← Piper — هرمس ‏pip install piper-tts را برایتان اجرا می‌کند. یا دستی نصب کنید: ‏pip install piper-tts.

سوئیچ به Piper:

yaml
tts:
  provider: piper
  piper:
    voice: en_US-lessac-medium

در اولین فراخوانی TTS برایصدایی که محلی کش نشده، هرمس ‏python -m piper.download_voices <name> را اجرا و مدل را ‏(~۲۰–۹۰MB بسته به سطح کیفیت) داخل ‏~/.hermes/cache/piper-voices/ دانلود می‌کند. فراخوانی‌های بعدی از مدل کش‌شده استفاده می‌کنند.

انتخاب صدا. کاتالوگ کامل صداها انگلیسی، اسپانیایی، فرانسوی، آلمانی، ایتالیایی، هلندی، پرتغالی، روسی، لهستانی، ترکی، چینی، عربی، هندی و بیشتر را پوشش می‌دهد — هر کدام با سطوح کیفیت ‏x_low / low / medium / high. نمونه‌ی صداها را در ‏rhasspy.github.io/piper-samples بشنوید.

استفاده از صدای از-قبل-دانلود‌شده. ‏tts.piper.voice را روی مسیر مطلقی که به ‏onnx ختم می‌شود ست کنید:

yaml
tts:
  piper:
    voice: /path/to/my-custom-voice.onnx

پیچ‌ومهره‌های پیشرفته ‏(tts.piper.length_scale/noise_scale/noise_w_scale/volume/normalize_audio، ‏use_cuda) یک‌به-یک معادل SynthesisConfig ی Piper هستند. روی نسخه‌های قدیمی‌تر piper-tts نادیده گرفته می‌شوند.

۴ ارائه‌دهنده‌های فرمان سفارشی ‏(TTS)

اگر موتور TTS موردنظرتان natively پشتیبانی نمی‌شود ‏(VoxCPM، ‏MLX-Kokoro، ‏XTTS CLI، یک اسکریپت همانندسازی صدا، هر چیزی که CLI دارد)، می‌توانید آن را به‌عنوان یک ارائه‌دهندهٔ نوع-فرمان بدون نوشتن هیچ پایتونی سیم‌کشی کنید. هرمس متن ورودی را در یک فایل temp ی UTF-8 می‌نویسد، فرمان شل شما را اجرا و فایل صدایی که فرمان تولید کرده می‌خواند.

یک یا چند ارائه‌دهنده زیر ‏tts.providers.<name> اعلام و بین آنها با ‏tts.provider: <name> سوئیچ کنید — دقیقاً مثل تعویض بین داخلی‌ها مثل edge و openai.

yaml
tts:
  provider: voxcpm                 # pick any name under tts.providers
  providers:
    voxcpm:
      type: command
      command: "voxcpm --ref ~/voice.wav --text-file {input_path} --out {output_path}"
      output_format: mp3
      timeout: 180
      voice_compatible: true       # try to deliver as a Telegram voice bubble

    mlx-kokoro:
      type: command
      command: "python -m mlx_kokoro --in {input_path} --out {output_path} --voice {voice}"
      voice: af_sky
      output_format: wav

    piper-custom:                  # native Piper also supports custom .onnx via tts.piper.voice
      type: command
      command: "piper -m /path/to/custom.onnx -f {output_path} < {input_path}"
      output_format: wav

مقادیر پشتیبانی‌شدهٔ output_format: ‏mp3 ‏(پیش‌فرض)، ‏wav، ‏ogg، ‏flac، ‏m4a، ‏aac، ‏amr، ‏opus. فرمان شما باید واقعاً آن فرمت را تولید کند ‏(مثلاً از طریق ffmpeg)؛ هرمس فقط مقدار اعلام‌شده را اعتبارسنجی و نام فایل خروجی را مطابق آن می‌گذارد. مقدار ناشناخته به mp3 برمی‌گردد. فرمت انتخابی به‌عنوان placeholder ی ‏{format} هم به فرمان expose می‌شود.

محیط زیرپروسه: ارائه‌دهنده‌های فرمان ‏(TTS و STT) با secrets ی هرمس پاک‌سازی‌شده از env فرزند اجرا می‌شوند — توکن بات‌های گیت‌وی، کلیدهای API ی ارائه‌دهندگان LLM و اعتبارنامه‌های relay داخلی حذف می‌شوند؛ ‏PATH، ‏HOME، locale و سایر متغیرهای عادی حفظ می‌شوند. اگر قالب فرمان‌تان کلید API ی خودش را از محیط می‌خواهد ‏(مثلاً یک خط curl)، نام متغیرها را زیر ‏env_passthrough در config ی ارائه‌دهنده بنویسید:

yaml
tts:
  providers:
    mycloud:
      type: command
      command: 'curl -s -H "Authorization: Bearer $MYCLOUD_API_KEY" ... -o {output_path}'
      env_passthrough: [MYCLOUD_API_KEY]

مثال: Doubao ‏(seed-tts-2.0 چینی)

برای TTS چینی باکیفیت از طریق API ی استریم دوطرفهٔ ‏seed-tts-2.0 ی ByteDance، پکیج PyPI ی ‏doubao-speech را نصب و به‌عنوان ارائه‌دهندهٔ فرمان سیم‌کشی کنید:

pip install doubao-speech
export VOLCENGINE_APP_ID="your-app-id"
export VOLCENGINE_ACCESS_TOKEN="your-access-token"
yaml
tts:
  provider: doubao
  providers:
    doubao:
      type: command
      command: "doubao-speech say --text-file {input_path} --out {output_path}"
      output_format: mp3
      max_text_length: 1024
      timeout: 30

اعتبارنامه‌ها از محیط شل ‏(VOLCENGINE_APP_ID / VOLCENGINE_ACCESS_TOKEN) یا ‏~/.doubao-speech/config.yaml می‌آیند. صدا را با افزودن ‏--voice zh-female-warm ‏(یا هر alias دیگری از ‏doubao-speech list-voices) به فرمان برگزینید. ‏doubao-speech یک ASR ی استریم هم همراه دارد — یکپارچه‌سازی با هرمس را در بخش STT پایین ببینید. سورس و مستندات کامل: ‏github.com/Hypnus-Yuan/doubao-speech.

Placeholder ها

قالب فرمان می‌تواند به این placeholder ها ارجاع دهد. هرمس موقع render جایگزین و هر مقدار را برای زمینهٔ اطراف shell-quote می‌کند ‏(لخت / تک-کوتیشن / دابل-کوتیشن)، پس مسیرهای دارای فاصله و سایر نویسه‌های حساس-به-شل امن هستند.

Placeholderمعنا
{input_path}مسیر فایل متنی temp ی UTF-8 که هرمس نوشته
{text_path}نام مستعار {input_path}
{output_path}مسیری که فرمان باید صدا را در آن بنویسد
{format}‏mp3 / wav / ogg / flac
{voice}‏tts.providers.<name>.voice؛ خالی وقتی ست نیست
{model}‏tts.providers.<name>.model
{speed}ضریب سرعت حل‌شده ‏(ارائه‌دهنده یا سراسری)

برای آکولاد لفظی از ‏{{ و ‏}} استفاده کنید.

کلیدهای اختیاری

کلیدپیش‌فرضمعنا
timeout120ثانیهٔ بی‌کاری؛ خروجی stdout یا stderr مهلت را reset می‌کند. درخت پروسه بعد از بی‌کاری کشته می‌شود ‏(killpg یونیکس، ‏taskkill /T ویندوز).
output_formatmp3یکی از ‏mp3 / wav / ogg / flac. اگر هرمس مسیر را خودش انتخاب کند از پسوند خروجی استنتاج می‌شود.
voice_compatiblefalseوقتی true، هرمس خروجی MP3/WAV را با ffmpeg به Opus/OGG تبدیل می‌کند تا تلگرام حباب صوتی رندر کند.
max_text_length5000حداکثر نویسه ورودی به‌ازای هر فراخوانی فرمان؛ متن بلندتر به chunk های مرتب شکسته می‌شود.
voice / ‏modelخالیفقط به‌عنوان مقادیر placeholder به فرمان پاس داده می‌شود.

یادداشت‌های رفتاری

  • نام‌های داخلی همیشه برنده‌اند. یک ورودی ‏tts.providers.openai هرگز ارائه‌دهندهٔ native ی OpenAI را سایه نمی‌اندازد، پس هیچ config ی کاربری نمی‌تواند بی‌سروصدا داخلی را جایگزین کند.
  • تحویل پیش‌فرض یک document است. ارائه‌دهنده‌های فرمان روی همهٔ پلتفرم‌ها به‌صورت پیوست صوتی عادی تحویل می‌دهند. تحویل حباب-صوتی را per-provider با ‏voice_compatible: true انتخاب کنید.
  • شکست‌های فرمان به ایجنت surface می‌شوند. کد خروج غیرصفر، خروجی خالی یا timeout همه خطایی همراه stderr/stdout ی فرمان برمی‌گردانند تا ارائه‌دهنده را از داخل گفتگو دیباگ کنید.
  • ‏type: command وقتی command ست شده پیش‌فرض است. نوشتن صریح type: command رویهٔ خوبی است ولی لازم نیست؛ ورودی با رشتهٔ command ی غیرخالی ارائه‌دهندهٔ فرمان حساب می‌شود.
  • ‏{input_path} / {text_path} جایگزین هم‌اند. هر کدام که در فرمانتان خواناتر بود.

امنیت

ارائه‌دهنده‌های نوع-فرمان هر فرمان شلی را که پیکربندی می‌کنید با مجوزهای کاربر شما اجرا می‌کنند. هرمس مقادیر placeholder را quote و timeout را اعمال می‌کند ولی خود قالب فرمان ورودی محلیِ مورد-اعتماد است — با آن مثل یک اسکریپت شل روی PATH تان رفتار کنید.

ارائه‌دهنده‌های پلاگین پایتونی ‏(TTS)

برای موتورهای TTS که با یک فرمان شل واحد بیان نمی‌شوند — SDK های پایتونی بدون CLI، موتورهای استریم، API های فهرست صدا، auth های refresh شونده OAuth — یک پلاگین پایتونی از طریق ‏ctx.register_tts_provider() ثبت کنید. پلاگین همراه registry ی ارائه‌دهنده‌های فرمان سفارشی زندگی می‌کند ‏(جایگزینش نمی‌شود)؛ سطح مناسب موتورتان را بردارید.

کی کدام را انتخاب کنیم

بک‌اند شما…استفاده
یک CLI ی واحد که متن را از فایل/stdin می‌خواند و صدا را به فایل/stdout می‌نویسدارائه‌دهندهٔ فرمان ‏(بدون پایتون)
دو سه CLI زنجیر‌شده با pipe های شلارائه‌دهندهٔ فرمان
فقط یک SDK ی پایتون — بدون CLIپلاگین
بایت‌های استریم که می‌خواهید chunked تحویل شوند ‏(حباب صوتی وسط-تولید)پلاگین ‏(override ی stream())
API ی فهرست صدا که hermes setup استفاده می‌کندپلاگین ‏(override ی list_voices())
جریان refresh ی OAuth ‏(نه bearer token ایستا)پلاگین

داخلی‌ها همیشه برنده‌اند و ارائه‌دهنده‌های فرمان بر پلاگین همنام برتری دارند — پس ثبت پلاگین روی هر نامِ غیر-داخلی امن است بدون نگرانی از سایه‌انداختن روی config فعلی‌تان.

حداقل پلاگین

این را در ‏~/.hermes/plugins/my-tts/ بگذارید:

‏plugin.yaml:

name: my-tts
version: 0.1.0
description: "My custom Python TTS backend"

‏__init__.py:

from agent.tts_provider import TTSProvider


class MyTTSProvider(TTSProvider):
    @property
    def name(self) -> str:
        return "my-tts"  # what tts.provider matches against

    @property
    def display_name(self) -> str:
        return "My Custom TTS"

    def is_available(self) -> bool:
        # Return False when credentials/deps are missing — picker skips
        # this row but the dispatcher still routes here on explicit config.
        import os
        return bool(os.environ.get("MY_TTS_API_KEY"))

    def synthesize(self, text, output_path, *, voice=None, model=None,
                   speed=None, format="mp3", **extra) -> str:
        # Write audio bytes to output_path, return the path.
        # Raise on failure — the dispatcher converts exceptions to a
        # standard error envelope.
        import my_tts_sdk
        client = my_tts_sdk.Client()
        audio_bytes = client.synthesize(text=text, voice=voice or "default")
        with open(output_path, "wb") as f:
            f.write(audio_bytes)
        return output_path


def register(ctx):
    ctx.register_tts_provider(MyTTSProvider())

فعالش کنید ‏(hermes plugins enable my-tts)، ‏tts.provider را به آن اشاره دهید ‏(tts.provider: my-tts در config.yaml) و ابزار ‏text_to_speech از پلاگین شما عبور خواهد کرد.

هوک‌های اختیاری

  • ‏list_voices() ← فهرستی از dict های ‏{id, display, language, gender, preview_url} که در hermes tools نشان داده می‌شود.
  • ‏list_models() ← فهرستی از dict های ‏{id, display, languages, max_text_length}.
  • ‏get_setup_schema() ← برگرداندن ‏{name, badge, tag, env_vars: [{key, prompt, url}]} برای قدرت دادن به ردیف picker در hermes tools / hermes setup. بدون این پلاگین همچنان کار می‌کند ولی ردیفش در picker مینیمال است.
  • ‏stream(text, *, voice, model, format, **extra) ← iterator ای که بایت‌های صوتی برای تحویل استریمی yield می‌کند ‏(پیش‌فرض NotImplementedError).
  • property ی ‏voice_compatible ← True بگذارید اگر خروجی‌تان Opus-compatible است و گیت‌وی باید حباب صوتی تحویل دهد ‏(پیش‌فرض False = پیوست صوتی عادی).

ABC ی کامل همراه docstring ها را در ‏agent/tts_provider.py ببینید.

۵ رونویسی پیام صوتی ‏(STT)

پیام‌های صوتی فرستاده‌شده در تلگرام، ‏دیسکورد، ‏واتساپ، ‏اسلک یا سیگنال خودکار رونویسی و به‌صورت متن داخل گفتگو تزریق می‌شوند. ایجنت transcript را مثل متن عادی می‌بیند.

ارائه‌دهندهکیفیتهزینهکلید API
Local Whisper ‏(پیش‌فرض)خوبرایگاننیازی نیست
Groq Whisper APIخوب تا بهترینتیر رایگانGROQ_API_KEY
OpenAI Whisper APIخوب تا بهترینپولیVOICE_TOOLS_OPENAI_KEY یا ‏OPENAI_API_KEY
📌 بدون پیکربندی

رونویسی محلی وقتی faster-whisper نصب باشد همان اول کار می‌کند. اگر آن موجود نباشد هرمس می‌تواند از CLI ی محلی whisper از مکان‌های نصب رایج ‏(مثل ‏/opt/homebrew/bin) یا یک فرمان سفارشی از طریق HERMES_LOCAL_STT_COMMAND استفاده کند.

پیکربندی

yaml
# In ~/.hermes/config.yaml
stt:
  provider: "local"           # "local" | "groq" | "openai" | "mistral" | "xai" | "elevenlabs" | "deepinfra"
  language: "en"              # Global language hint applied to every provider unless a per-provider language overrides it; set "" to restore auto-detect
  local:
    model: "base"             # tiny, base, small, medium, large-v3
    language: ""              # optional ISO-639-1 hint; blank = use HERMES_LOCAL_STT_LANGUAGE if set, else auto-detect
  groq:
    language: ""              # optional ISO-639-1 hint; blank = use HERMES_LOCAL_STT_LANGUAGE if set, else auto-detect
  openai:
    model: "whisper-1"        # whisper-1, gpt-4o-mini-transcribe, gpt-4o-transcribe, gpt-transcribe
  mistral:
    model: "voxtral-mini-latest"  # voxtral-mini-latest, voxtral-mini-2602
  xai:
    model: "grok-stt"         # xAI Grok STT
    language: ""              # optional ISO-639-1 hint; blank = use HERMES_LOCAL_STT_LANGUAGE if set, else "en"

جزئیات ارائه‌دهنده‌ها

محلی ‏(faster-whisper) — Whisper را به‌صورت محلی از طریق faster-whisper اجرا می‌کند. پیش‌فرض CPU و در صورت وجود GPU. اندازه‌های مدل:

مدلحجمسرعتکیفیت
tiny~۷۵MBسریع‌ترینپایه
base~۱۵۰MBسریعخوب ‏(پیش‌فرض)
small~۵۰۰MBمتوسطبهتر
medium~۱٫۵GBکندترعالی
large-v3~۳GBکندترینبهترین

Groq API — ‏GROQ_API_KEY لازم دارد. fallback ابری خوب وقتی گزینهٔ STT میزبانی‌شده رایگان می‌خواهید. ‏stt.groq.language ‏(یا متغیر سراسری HERMES_LOCAL_STT_LANGUAGE) را ست کنید تا auto-detect ی Whisper رد شود و تأخیر روی صدای زبان-معلوم کم شود.

OpenAI API — اول VOICE_TOOLS_OPENAI_KEY را می‌پذیرد و بعد به OPENAI_API_KEY برمی‌گردد. ‏whisper-1، ‏gpt-4o-mini-transcribe، ‏gpt-4o-transcribe و gpt-transcribe را پشتیبانی می‌کند.

Mistral API ‏(Voxtral Transcribe) — ‏MISTRAL_API_KEY لازم دارد. از مدل‌های ‏Voxtral Transcribe ی Mistral استفاده می‌کند. ‏۱۳ زبان، diarization ی گوینده و timestamp های سطح-واژه را پشتیبانی می‌کند. نصب: ‏cd ~/.hermes/hermes-agent && uv pip install -e ".[mistral]".

xAI Grok STT — ‏XAI_API_KEY لازم دارد. به ‏https://api.x.ai/v1/stt به‌صورت multipart/form-data پست می‌کند. انتخاب خوب اگر از قبل برای چت یا TTS از xAI استفاده می‌کنید و یک کلید API برای همه‌چیز می‌خواهید. ترتیب آشکارسازی خودکار آن را بعد از Groq می‌گذارد — صریحاً ‏stt.provider: xai ست کنید تا اجبار شود.

Fallback ی CLI ی محلی سفارشی — اگر می‌خواهید هرمس مستقیماً یک فرمان رونویسی محلی را صدا بزند ‏HERMES_LOCAL_STT_COMMAND را ست کنید. قالب فرمان placeholder های ‏{input_path}، ‏{output_dir}، ‏{language} و {model} را پشتیبانی می‌کند. هرمس قالب رندر شده را به فهرست آرگومان tokenize و بدون شل اجرا می‌کند، پس عملگرهای ‏|، ‏>، ‏&& و ؛ به‌عنوان آرگومان تحت‌اللفظی پاس داده می‌شوند. فرمان شما باید یک transcript با پسوند .txt جایی زیر {output_dir} بنویسد.

مثال: Doubao / Volcengine ASR

اگر از ‏doubao-speech برای TTS ی Doubao استفاده می‌کنید، همان پکیج تبدیل گفتار-به-متن را از طریق مسیر STT ی فرمان-محلی هندل می‌کند:

pip install doubao-speech
export VOLCENGINE_APP_ID="your-app-id"
export VOLCENGINE_ACCESS_TOKEN="your-access-token"
export HERMES_LOCAL_STT_COMMAND='doubao-speech transcribe {input_path} --out {output_dir}/transcript.txt'

اگر یک قالب محلی مورد-اعتماد عمداً به pipe، redirect یا ویژگی شل دیگری نیاز دارد، شل را صریحاً invoke کنید. مسیرهای داینامیک را بیرون برنامهٔ شل نگه دارید و به‌عنوان آرگومان موقعیتی پاس دهید:

export HERMES_LOCAL_STT_COMMAND='sh -c '\''whisper "$1" --output_format txt --output_dir "$2" | tee "$2/whisper.log"'\'' _ {input_path} {output_dir}'

روی ویندوز به‌جایش از wrapper ی صریح ‏cmd /c یا PowerShell استفاده کنید. wrapper ی صریح تفسیر شل را بخشی opt-in از argv ی پیکربندی‌شده می‌کند نه ویژگی ضمنی هر قالب STT محلی.

stt:
  provider: local_command

هرمس پیام صوتی ورودی را در {input_path} می‌نویسد، فرمان را اجرا و فایل .txt تولیدشده زیر {output_dir} را می‌خواند. زبان توسط نقطهٔ پایانی bigmodel ی Volcengine خودآشکار می‌شود.

رفتار Fallback

انتخاب صریحِ ‏stt.provider ‏(نوشته‌شده در config.yaml مثلاً از طریق hermes tools) سخت‌گیرانه محترم شمرده می‌شود — اگر آن ارائه‌دهنده نتواند اجرا شود رونویسی با خطای شفاف شکست می‌خورد ‏(stt is configured to use <provider> (set via hermes tools), but <failure>. Run 'hermes tools' to change it.) نه اینکه بی‌سروصدا موتور عوض کند. توجه کنید ‏stt.provider: local ی نوشته‌شده در config شما انتخاب صریح حساب می‌شود.

وقتی هیچ ارائه‌دهنده‌ای هرگز انتخاب نشده باشد هرمس از آنچه موجود است خودآشکار می‌کند:

  • faster-whisper ی محلی غیرموجود ← قبل از ارائه‌دهنده‌های ابری CLI ی محلی whisper یا HERMES_LOCAL_STT_COMMAND را امتحان می‌کند
  • کلید Groq ست نیست ← رد می‌شود؛ ارائه‌دهندهٔ بعدی موجود
  • کلید OpenAI ست نیست ← رد می‌شود؛ ارائه‌دهندهٔ بعدی موجود
  • کلید/SDK ی Mistral ست نیست ← در آشکارسازی خودکار رد؛ به ارائه‌دهندهٔ بعدی می‌رسد
  • هیچ‌چیز موجود نبود ← پیام‌های صوتی با یادداشت دقیقی برای کاربر passthrough می‌شوند

۶ ارائه‌دهنده‌های فرمان سفارشی STT

اگر موتور STT موردنظرتان natively پشتیبانی نمی‌شود ‏(Doubao ASR، ‏NVIDIA Parakeet، یک build ی whisper.cpp، یک CLI ی متن‌باز SenseVoice، هر چیزی که فرمان شل دارد)، بدون نوشتن هیچ پایتونی به‌عنوان ارائه‌دهندهٔ نوع-فرمان سیم‌کشی‌اش کنید. هرمس فرمان شل شما را روی فایل صوتی اجرا و transcript را برمی‌گرداند.

یک یا چند ارائه‌دهنده زیر ‏stt.providers.<name> اعلام و بین آنها با ‏stt.provider: <name> سوئیچ کنید — هم‌شکل registry ی ارائه‌دهنده-فرمان TTS، تطبیق‌یافته برای جهت ورودی=صدا ← خروجی=transcript.

yaml
stt:
  provider: parakeet                # pick any name under stt.providers
  providers:
    parakeet:
      type: command
      command: "parakeet-asr --model nvidia/parakeet-tdt-0.6b-v2 --in {input_path} --out {output_path}"
      format: txt
      language: en
      timeout: 300

    whispercpp:
      type: command
      command: "whisper-cli -m ~/models/ggml-large-v3.bin -f {input_path} -otxt -of {output_dir}/transcript"
      format: txt

    sensevoice:
      type: command
      command: "sensevoice-cli {input_path} --json | tee {output_path}"
      format: json

این مکمل hatch قدیمی ‏HERMES_LOCAL_STT_COMMAND است از طریق مسیر داخلی local_command. برخلاف registry ی رانده-با-شل، قالب قدیمی به argv ی tokenize شده و بدون تفسیر ضمنی شل اجرا می‌شود. وقتی ‏چندین موتور STT رانده-با-شل می‌خواهید، نامی که با ‏stt.provider قابل‌انتخاب باشد، یا چیزی که ‏language/model/timeout ی per-provider لازم دارد از ‏stt.providers.<name> استفاده کنید.

placeholder های STT

Placeholderمعنا
{input_path}مسیر مطلق فایل صدای ورودی ‏(محل اصلی، فقط-خواندنی)
{output_path}مسیر مطلقی که فرمان باید transcript را در آن بنویسد
{output_dir}دایرکتوری والد {output_path} ‏(برای ابزارهای سبک whisper handy است)
{format}فرمت خروجی پیکربندی‌شده: ‏txt / json / srt / vtt
{language}کد زبان پیکربندی‌شده ‏(پیش‌فرض en)
{model}‏stt.providers.<name>.model؛ خالی وقتی ست نیست

برای آکولاد لفظی از ‏{{ و }} استفاده کنید ‏(وقتی snippet ی JSON داخل فرمان تعبیه می‌کنید handy است).

نحوهٔ بازخوانی transcript

بعد از خروج موفق فرمان شما:

  1. اگر {output_path} وجود داشته باشد و غیرخالی باشد ← هرمس آن را به‌عنوان متن UTF-8 می‌خواند.
  2. در غیر این صورت اگر فرمان به stdout نوشته باشد ← هرمس همان را استفاده می‌کند.
  3. در غیر این صورت ← خطا: «Command STT provider wrote no output file and produced no stdout».

این اجازه می‌دهد registry را هم برای CLI های فایل‌نویس ‏(whisper-cli، ‏parakeet-asr) هم برای خط‌های-یگانه سبک curl که transcript را به stdout می‌دهند ‏(curl … | jq -r .text) به کار ببرید.

برای ‏format: json/srt/vtt هرمس محتوای خام فایل را به‌عنوان فیلد transcript برمی‌گرداند. استخراج text از JSON خارج از دامنه runner است — یا ‏format: txt پیکربندی کنید یا JSON را پایین‌دستی post-process کنید.

کلیدهای اختیاری ارائه‌دهندهٔ فرمان STT

کلیدپیش‌فرضمعنا
timeout300ثانیه؛ درخت پروسه در انقضا کشته می‌شود ‏(start_new_session یونیکس، ‏taskkill /T ویندوز).
formattxtیکی از txt / json / srt / vtt. پسوند {output_path} را ست می‌کند.
languageenبه {language} forward می‌شود. پیش‌فرض ‏stt.language سپس en.
modelخالیبه {model} forward می‌شود. آرگومان model= به transcribe_audio() این را override می‌کند.

یادداشت‌های رفتاری ارائه‌دهندهٔ فرمان STT

  • داخلی‌ها همیشه برنده‌اند. اعلام ‏stt.providers.openai با type: command هندلر واقعی Whisper ی OpenAI را override نمی‌کند. نام داخلی قبل از اجرای resolver ی ارائه‌دهنده-فرمان short-circuit می‌شود.
  • پاکسازی درخت پروسه. فرمانی که از timeout عبور کند کل درخت پروسه‌اش کشته می‌شود نه فقط wrapper ی شل. خط‌لوله‌های ASR ی بلندمدتی که زیرپروسه‌های بارگذاری مدل fork می‌کنند قابل‌اعتماد جمع می‌شوند.
  • shell-quoting خودکار است. placeholder ها داخل '…' با escaping امن-تک-کوتیشن؛ داخل "…" با escaping ی $/`/"؛ بیرون کوتیشن با shlex.quote. مقادیر placeholder را از قبل quote نکنید.

امنیت ارائه‌دهندهٔ فرمان STT

فرمان شل زیر همان کاربر هرمس با دسترسی کامل فایل‌سیستم اجرا می‌شود — همان مدل اعتماد ‏tts.providers.<name>: type: command و ‏HERMES_LOCAL_STT_COMMAND. فقط ارائه‌دهنده‌های فرمان از منابع مورد اعتماد اعلام کنید.

۷ ارائه‌دهنده‌های پلاگین پایتونی ‏(STT)

برای موتورهای STT ای که داخلی نیستند و نمی‌توانند به‌عنوان فرمان شل بیان شوند ‏(SDK ی پایتون لازم دارند، auth ی refresh شونده OAuth، chunk های استریم و…)، یک پلاگین پایتونی از طریق ‏ctx.register_transcription_provider() ثبت کنید. پلاگین همراه ۸ ارائه‌دهندهٔ داخلی ‏(local، ‏local_command، ‏groq، ‏openai، ‏mistral، ‏xai، ‏elevenlabs، ‏deepinfra) و registry ی ‏stt.providers.<name>: type:command زندگی می‌کند — داخلی‌ها پیاده‌سازی native شان را حفظ و در تداخل نام همیشه برنده‌اند؛ ارائه‌دهنده‌های فرمان بر پلاگین‌های همنام برتری دارند ‏(config محلی‌تر از نصب پلاگین است).

کی کدام را انتخاب کنیم ‏(STT)

بک‌اند دارد…استفاده
یک فرمان شل واحد که فایل صوتی می‌گیرد و متن می‌دهد‏stt.providers.<name>: type: command ‏(بدون پایتون)
فقط hatch ی تک-فرمانی قدیمی مدنظر استمتغیر محیطی HERMES_LOCAL_STT_COMMAND ‏(argv-tokenized؛ بدون شل ضمنی)
SDK ی پایتون بدون CLIپلاگین ‏register_transcription_provider()
auth ی refresh شونده OAuth، chunk های استریم، متادیتای فهرست صداهاپلاگین ‏register_transcription_provider()
داخلی‌ای از قبل پوششش می‌دهد ‏(local، groq، openai و…)‏stt.provider: <name> — داخلی‌ها inline هستند

ترتیب حل

  1. ‏stt.provider یک نام داخلی است ← dispatch داخلی. همیشه برنده.
  2. ‏stt.provider با stt.providers.<name> دارای command: بخورد ← runner ی ارائه‌دهنده-فرمان. بر پلاگین همنام برتری دارد.
  3. ‏stt.provider با TranscriptionProvider ثبت‌شده توسط پلاگین بخورد ← dispatch پلاگینی:
    • اگر ‏is_available() ی پلاگین False برگرداند ‏(creds یا SDK غایب)، فراخوانی پاکت خطای غیرقابل‌دسترس‌بودنی می‌دهد که پلاگین را مشخص می‌کند — نه پیام عمومی «No STT provider available».
    • در غیر این صورت ‏transcribe() ی پلاگین با model ‏(از آرگومان عمومی model= با fallback به stt.<provider>.model) و language ‏(از stt.<provider>.language) صدا زده می‌شود.
  4. بدون تطبیق ← خطای «No STT provider available».

namespace ی config ی per-provider

پلاگین‌ها پیکربندی per-provider شان را از ‏stt.<provider> در config.yaml می‌خوانند، آینهٔ روشی که داخلی‌ها ‏stt.openai.model / stt.mistral.model را می‌خوانند:

yaml
stt:
  provider: my-stt
  my-stt:
    model: whisper-large-v3
    language: ja          # forwarded as language= to transcribe()
    # any other plugin-specific keys go here; read them via your
    # own config.yaml access in __init__/is_available/transcribe

dispatcher مقدار model و language را از این بخش forward می‌کند؛ بقیه را پلاگین خودش می‌خواند.

حداقل پلاگین

این را در ‏~/.hermes/plugins/my-stt/ بگذارید:

‏plugin.yaml:

name: my-stt
version: 0.1.0
description: "My custom Python STT backend"

‏__init__.py:

from agent.transcription_provider import TranscriptionProvider


class MySTTProvider(TranscriptionProvider):
    @property
    def name(self) -> str:
        return "my-stt"  # what stt.provider matches against

    @property
    def display_name(self) -> str:
        return "My Custom STT"

    def is_available(self) -> bool:
        # Return False when credentials/deps are missing — picker skips
        # this row but the dispatcher still routes here on explicit config.
        import os
        return bool(os.environ.get("MY_STT_API_KEY"))

    def transcribe(self, file_path, *, model=None, language=None, **extra):
        # Return the standard transcribe envelope:
        #   {"success": bool, "transcript": str, "provider": str, "error": str}
        # Do NOT raise — convert exceptions to the error envelope so the
        # gateway/CLI caller sees a consistent shape on failure.
        try:
            import my_stt_sdk
            client = my_stt_sdk.Client()
            text = client.transcribe(open(file_path, "rb"))
            return {
                "success": True,
                "transcript": text,
                "provider": "my-stt",
            }
        except Exception as exc:
            return {
                "success": False,
                "transcript": "",
                "error": f"my-stt failed: {exc}",
                "provider": "my-stt",
            }


def register(ctx):
    ctx.register_transcription_provider(MySTTProvider())

فعالش کنید ‏(hermes plugins enable my-stt)، ‏stt.provider: my-stt را در config.yaml ست کنید و رونویسی پیام صوتی از پلاگین شما عبور خواهد کرد.

هوک‌های اختیاری

  • ‏list_models() ← فهرستی از dict های ‏{id, display, languages, max_audio_seconds}.
  • ‏default_model() ← رشته‌ای که وقتی کاربر مدل را override نکرده برگردانده می‌شود.
  • ‏get_setup_schema() ← برگرداندن ‏{name, badge, tag, env_vars: [{key, prompt, url}]} برای قدرت دادن به ردیف‌های picker در hermes tools / hermes setup ‏(دستهٔ picker برای STT هنوز ارسال نشده — این متادیتا برای سازگاری رو-به-جلو در دسترس پلاگین‌هاست).
