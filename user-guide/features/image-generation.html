تولید تصویر

‏هرمس ایجنت تصاویر را از پرامپت‌های متنی از طریق FAL.ai تولید می‌کند. یازده مدل پیش‌فرض پشتیبانی می‌شود، هرکدام با موازنهٔ متفاوت سرعت، کیفیت و هزینه. مدل فعال توسط کاربر از طریق ‏hermes tools قابل تنظیم است و در config.yaml ماندگار می‌شود.

۲ راه‌اندازی

💡 مشترکان Nous

اگر اشتراک پرداختی ‏Nous Portal دارید، می‌توانید تولید تصویر را از طریق Tool Gateway بدون کلید API فال استفاده کنید. انتخاب مدل شما بین هر دو مسیر ماندگار است. نصب‌های جدید می‌توانند ‏hermes setup --portal را اجرا کنند تا وارد شوند و همهٔ ابزارهای گیت‌وی را یکجا روشن کنند؛ نصب‌های موجود می‌توانند از طریق ‏hermes tools مقدار Nous Subscription را به‌عنوان بک‌اند image-gen انتخاب کنند.

اگر گیت‌وی مدیریتی برای مدلی خاص ‏HTTP 4xx برگرداند، آن مدل هنوز سمت portal پروکسی نشده — ایجنت همین را با گام‌های اصلاح به شما می‌گوید ‏(سوییچ به FAL.ai در ‏hermes tools با ‏FAL_KEY خودتان برای دسترسی مستقیم، یا انتخاب مدل دیگر).

گرفتن کلید API فال

  1. در fal.ai ثبت‌نام کنید
  2. از داشبوردتان کلید API بسازید

پیکربندی و انتخاب مدل

فرمان tools را اجرا کنید:

hermes tools

به 🎨 Image Generation بروید، بک‌اند‌تان را انتخاب کنید ‏(Nous Subscription یا FAL.ai)، سپس انتخاب‌گر همهٔ مدل‌های پشتیبانی‌شده را در جدول هم‌تراز ستونی نشان می‌دهد — کلیدهای جهت‌دار برای حرکت، Enter برای انتخاب:

text
  Model                          Speed    Strengths                    Price
  fal-ai/flux-2/klein/9b         <1s      Fast, crisp text             $0.006/MP   ← currently in use
  fal-ai/flux-2-pro              ~6s      Studio photorealism          $0.03/MP
  fal-ai/z-image/turbo           ~2s      Bilingual EN/CN, 6B          $0.005/MP
  ...

انتخاب شما در config.yaml ذخیره می‌شود:

yaml
image_gen:
  provider: fal                 # `nous` اگر Nous Subscription انتخاب کرده باشید
  model: fal-ai/flux-2/klein/9b
  max_parallel_requests: 4      # تصاویر هم‌زمان در یک batch فراخوانی-ابزار

‏image_gen.provider کلید انتخاب واحد است: ‏nous از طریق Tool Gateway مدیریتی مسیریابی می‌کند؛ نام فروشنده ‏(fal، ‏openai، ‏xai، ‏krea و...) مستقیم با کلید خودتان می‌رود. runtime همیشه از همین انتخاب ذخیره‌شده پیروی می‌کند — وقتی ‏provider: nous باشد یک ‏FAL_KEY داخل .env نادیده گرفته می‌شود و ‏provider: fal بدون ‏FAL_KEY خطای ‏image_gen is configured to use fal (set via hermes tools), but FAL_KEY is not set. Run 'hermes tools' to change it. می‌دهد نه اینکه بی‌صدا بازمسیریابی کند. ارائه‌دهنده‌ها را از طریق ‏hermes tools عوض کنید نه با افزودن/حذف کلیدها. ‏(بولین قدیمی ‏use_gateway میراثی است — همچنان هنگام ‏true به‌صورت ‏nous خوانده ولی دیگر نوشته نمی‌شود.)

‏max_parallel_requests پیش‌فرض ‏4 دارد. هرمس آن را حداقل به یکی و حداکثر به سقف tool-worker سراسری clamp می‌کند تا ارائه‌دهنده‌های تصویر درخواست‌های موازی محدود دریافت کنند بدون اینکه batch تصویری از سقف هم‌زمانی ایجنت عبور کند.

‏OpenRouter: کاتالوگ کامل Image API

با ‏image_gen.provider: openrouter، انتخاب‌گر مدل کل کاتالوگ زندهٔ تصویری OpenRouter را فهرست می‌کند — مدل‌های اختصاصی Image API ‏(Seedream، ‏FLUX.2، ‏Recraft، ‏Qwen Image، ‏MAI، ‏Krea، ‏Riverflow، ‏Grok Imagine و بیشتر — ۴۰+ شناسه) ادغام‌شده با مدل‌های تصویری chat-completions. کاتالوگ زنده از ‏GET /images/models و ‏GET /models گرفته می‌شود، پس مدل‌های جدید به‌محض سرو شدن توسط OpenRouter در انتخاب‌گر ظاهر می‌شوند؛ بدون به‌روزرسانی هرمس. تولید هر مدل را به سطحی که سروش می‌کند ‏(‏POST /images/generations اختصاصی vs chat-completions) خودکار مسیریابی می‌کند. ‏Nous Portal فقط پروتکل chat-completions را پروکسی می‌کند، پس انتخاب‌گرش مدل‌های chat-served را پیشنهاد می‌دهد.

دسته‌های اختیاری به‌ازای-درخواست برای مدل‌های Image API زیر بخش پیکربندی scoped می‌روند ‏(یا متغیرهای env ‏OPENROUTER_IMAGE_API_*):

yaml
image_gen:
  provider: openrouter
  model: bytedance-seed/seedream-4.5
  openrouter:
    resolution: 2K        # model-dependent: 1K / 2K / 4K
    quality: high         # gpt-image models
    output_format: png

کیفیت ‏GPT-Image

کیفیت درخواست ‏fal-ai/gpt-image-1.5 و ‏fal-ai/gpt-image-2 روی ‏medium قفل شده ‏(~$0.034–$0.06/تصویر در ۱۰۲۴×۱۰۲۴). سطوح ‏low/high را به‌عنوان گزینهٔ رو-به-کاربر expose نمی‌کنیم تا صورتحساب Nous Portal برای همهٔ کاربران قابل‌پیش‌بینی بماند — پراکندگی هزینه بین سطوح ۳ تا ۲۲ برابر است. اگر گزینهٔ ارزان‌تر می‌خواهید Klein 9B یا Z-Image Turbo را بردارید؛ اگر کیفیت بالاتر می‌خواهید Nano Banana Pro یا Recraft V4 Pro استفاده کنید.

۳ استفاده

schema رو-به-ایجنت عمداً حداقلی است — مدل هرچه پیکربندی کرده باشید را برمی‌دارد:

Generate an image of a serene mountain landscape with cherry blossoms
Create a square portrait of a wise old owl — use the typography model
Make me a futuristic cityscape, landscape orientation

۴ تصویر-به-تصویر / ویرایش

همان ابزار ‏image_generate وقتی مدل فعال پشتیبانی کند تصاویر موجود را ویرایش هم می‌کند — تصویر مبدأ بدهید و بک‌اند خودکار به endpoint ویرایشش مسیریابی می‌کند ‏(آینهٔ نحوهٔ هندل image-to-video توسط ‏video_generate). حذف تصویر مبدأ یعنی text-to-image ساده.

Take this photo and make it a rainy Tokyo street at night → <image>
Blend these two product shots into one hero image → <image1> <image2>

دو ورودی ویرایش را می‌رانند:

  • ‏image_url — تصویر مبدأ اصلی برای ویرایش/تبدیل ‏(URL عمومی یا مسیر محلی).
  • ‏reference_image_urls — ارجاع‌های اضافی سبک/ترکیب ‏(سقف به‌ازای-مدل).

کدام بک‌اندها ویرایش را پشتیبانی می‌کنند

بک‌اندتصویر-به-تصویرسقف مرجعچگونه
‏FAL.ai ‏(مدل‌های edit-capable پایین)✓تا ۹به endpoint ‏/edit مربوط به مدل مسیریابی می‌کند
‏OpenAI ‏(gpt-image-2)✓تا ۱۶‏images.edit()
‏xAI ‏(Grok Imagine)✓۱‏/v1/images/edits ‏(grok-imagine-image-quality)
Krea ‏(Krea 2)✓تا ۱۰تولید راهنمایی-با-ارجاع ‏(image_style_references)
‏OpenAI ‏(احراز Codex)✓تا ۱۶ابزار ‏image_generation مربوط به Codex Responses با بخش‌های محتوایی ‏input_image
‏OpenRouter ‏(مدل‌های Image API)✓تا ۱۴–۱۶ ‏(به‌ازای مدل)‏input_references روی ‏POST /images/generations؛ مدل‌های chat-served از بخش‌های محتوایی ‏image_url ‏(تا ۳) استفاده می‌کنند

مدل‌های FAL دارای endpoint ویرایش: ‏flux-2/klein/9b، ‏flux-2-pro، ‏nano-banana-pro، ‏gpt-image-1.5، ‏gpt-image-2، ‏ideogram/v3 و ‏qwen-image. مدل‌های FAL صرفاً-text-to-image ‏(z-image/turbo، ‏recraft، ‏krea/*) ورودی‌های تصویری را با خطای واضحی که به مدلی edit-capable اشاره می‌کند رد می‌کنند.

📌 OpenAI ‏(احراز Codex) بهترین-تلاش است

سطح Codex ‏(chatgpt.com/backend-api/codex) مقدار ‏image_generation را به‌عنوان ابزاری که مدل چت ممکن است صدا بزند میزبانی می‌کند و هرمس نمی‌تواند فراخوانی را اجبار کند — بک‌اند هر شکل ‏tool_choice را برای ابزارهای میزبانی‌شده رد می‌کند، پس درخواست به دستورالعمل‌ها برای هدایت مدل اتکا دارد. وقتی مدل میزبان از invoke کردن ابزار سر باز زند فراخوانی با ‏empty_response شکست می‌خورد. گزارش شده که حتی قابلیت رسیدن به ابزار تصویری میزبانی‌شده بین حساب‌ها متغیر است. اگر نیاز دارید تولید تصویر قطعی کار کند به‌جایش بک‌اند OpenAI ‏(کلید API)، ‏FAL یا ‏xAI را پیکربندی کنید.

قابلیت ویرایش مدل فعال هنگام runtime در توضیح ابزار surface می‌شود، پس ایجنت قبل از صدازدن ابزار می‌داند آیا ‏image_url محترم شمرده خواهد شد.

۶ Upscaling

فقط-با-انتخاب

هیچ مدلی پیش‌فرض upscale نمی‌کند. مدل‌های مدرن تصویر بهترین کیفیتشان را native تولید می‌کنند و upscaler های موجود بهبوددهنده‌های خلاقند ‏(pass های diffusion) که می‌توانند محتوا را ظریف بازترسیم کنند — افت متن رندرشده، صورت‌ها و جزئیات دقیق. ‏Upscaling فقط وقتی اجرا می‌شود که ایجنت صریحاً درخواستش کند.

پارامتر ‏upscale ‏(انتخاب به‌ازای-فراخوانی)

  • ‏upscale: true — بعد از تولید یک pass با-وضوح-بالا زنجیر می‌شود:
بک‌اندUpscaler
FAL.aiClarity Upscaler ‏(۲×، +$0.03/MP)
KreaKrea Enhance ‏(۲×، سقف تا ۸K)
سایر بک‌اندهابدون upscaler؛ رزولوشن native برگردانده می‌شود
  • ‏upscale: false/حذف‌شده — رزولوشن native ‏(پیش‌فرض)

‏video_generate هم روی بک‌اند FAL مقدار ‏upscale: true می‌پذیرد و upscaler ویدیویی SeedVR2 شرکت ByteDance ‏(۲×، ‏$0.001/MP ویدیوی خروجی) را بعد از تولید زنجیر می‌کند.

وقتی pass تصویری FAL اجرا شود از این تنظیمات استفاده می‌کند:

تنظیممقدار
ضریب upscale۲×
Creativity۰٫۳۵
Resemblance۰٫۶
Guidance scale۴
Inference steps۱۸

اگر upscaling شکست بخورد ‏(مشکل شبکه، rate limit)، تصویر اصلی خودکار برمی‌گردد. پاسخ ‏upscaled: true/false را گزارش می‌کند تا ایجنت بداند چه رزولوشنی گرفته.

۷ نحوهٔ کار داخلی

  1. حل مدل — ‏_resolve_fal_model() مقدار ‏image_gen.model را از config.yaml می‌خواند، به متغیر env ‏FAL_IMAGE_MODEL و بعد به ‏fal-ai/flux-2/klein/9b برمی‌گردد.
  2. ساخت payload — ‏_build_fal_payload() مقدار ‏aspect_ratio شما را به قالب native مدل ترجمه می‌کند ‏(enum preset، enum نسبت ابعاد یا literal مربوط به GPT)، پارامترهای پیش‌فرض مدل را merge، override های فراخواننده را اعمال و بعد به لیست سفید ‏supports مدل فیلتر می‌کند تا کلیدهای پشتیبان‌نشده هرگز فرستاده نشوند.
  3. ارسال — ‏_submit_fal_request() طبق انتخاب ذخیره‌شدهٔ ‏image_gen.provider از طریق اعتبارنامه‌های مستقیم FAL یا دروازهٔ مدیریتی Nous مسیریابی می‌کند.
  4. Upscaling — فقط وقتی اجرا می‌شود که ایجنت ‏upscale: true داده باشد؛ پیش‌فرض کاتالوگ همهٔ مدل‌ها خاموش است.
  5. تحویل — URL تصویر نهایی به ایجنت برمی‌گردد که تگ ‏MEDIA:<url> صادر می‌کند و آداپتورهای پلتفرم به رسانهٔ native تبدیلش می‌کنند.

۱۰ محدودیت‌ها

  • نیازمند اعتبارنامه برای بک‌اند فعال ‏(‏FAL ‏FAL_KEY / اشتراک Nous، ‏OPENAI_API_KEY، ‏OAuth مربوط به xAI، ‏KREA_API_KEY)
  • ویرایش وابسته-به-مدل است — تصویر-به-تصویر فقط روی مدل‌های edit-capable کار می‌کند ‏(جدول بالا)؛ مدل‌های صرفاً-text-to-image ورودی‌های تصویری را با خطای واضح رد می‌کنند
  • URL های گذرا — بک‌اندها URLهای میزبانی‌شده‌ای برمی‌گردانند که بعد از ساعت‌ها/روزها منقضی می‌شوند؛ هرمس آنها را به کش محلی materialize می‌کند تا تحویل بعد از انقضا هم کار کند
  • محدودیت‌های به‌ازای-مدل — بعضی مدل‌ها ‏seed، ‏num_inference_steps و... را پشتیبانی نمی‌کنند. فیلتر ‏supports/edit_supports پارامترهای پشتیبان‌نشده را بی‌صدا حذف می‌کند؛ این رفتار موردانتظار است
