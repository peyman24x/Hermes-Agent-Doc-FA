ضربان نشست‌ها ‏(‏/heartbeat)

‏/heartbeat به نشست فعلی یک دستورالعمل تکرارشونده می‌دهد. هر وقت نشست بیکار باشد و فاصلهٔ زمانی سپری شده باشد، پرامپت مثل یک نوبت عادی کاربر شلیک می‌شود — همان گفتگو، همان زمینه، همان کش پرامپت.

/heartbeat every 10m Check the deployment and report meaningful changes

الهام‌گرفته از ‏/heartbeat مربوط به Prime-Agent. اقتباس هرمس ناورداهای سخت جریان-پیام را حفظ می‌کند: ضربان فقط بین نوبت‌ها تزریق می‌شود ‏(هرگز میان-اجرا نه)، به‌عنوان یک پیام عادی با نقش کاربر.

۱ ‏Heartbeat در برابر cron: کدام را می‌خواهم؟

شبیه به نظر می‌رسند ولی کارهای متفاوتی انجام می‌دهند:

‏/heartbeat‏hermes cron
اجرا درهمین گفتگو — زمینهٔ کامل، حافظهٔ بحثنشست ایزولهٔ تازه به‌ازای هر تیک
جان‌سپردن از ری‌استارت پروسهوضعیت جان می‌برد ‏(SessionDB)؛ شلیک دفعه بعد که نشست رانده شود ازسر می‌گیردبله — زمان‌بند کاملاً ماندگار
چندتایکی به‌ازای هر نشستjob های نامحدود
بهترین برای«حین کارمان در همین رشته مراقب X باش»job های ثابت، گزارش‌ها، watchdog ها، تحویل‌ها

قاعدهٔ سرانگشتی: اگر پرامپت تکرارشونده به زمینهٔ گفتگو نیاز دارد از ‏/heartbeat استفاده کنید. اگر job خودبسنده است از cron.

۲ فرمان‌ها

فرمانچه می‌کند
/heartbeat every <interval> <prompt>ست ‏(یا جایگزینی) ضربان نشست. فواصل: ‏90s، ‏10m، ‏2h، ‏1d ‏(حداقل ۶۰ ثانیه).
/heartbeat یا ‏/heartbeat statusنمایش ضربان، فاصله و زمان تا شلیک بعدی.
/heartbeat pauseتوقف شلیک بدون پاک‌کردن.
/heartbeat resumeازسرگیری ‏(تایمر دوباره لنگر می‌اندازد — بدون شلیک کهنهٔ آنی).
/heartbeat clearحذف ضربان.

‏/hb نام جایگزین است. روی CLI و پلتفرم‌های گیت‌وی کار می‌کند ‏(روی Slack از ‏/hermes heartbeat … استفاده کنید).

۳ جزئیات رفتار

  • فقط-بیکاری. ضربان هرگز نوبت در حال اجرا را قطع نمی‌کند. اگر ایجنت هنگام سررسید تیک مشغول باشد، در poll بیکاری بعدی شلیک می‌شود.
  • تیک‌های از‌دست‌رفته ادغام می‌شوند. اگر نشست چند interval مشغول بود ‏(یا پروسه اجرا نباشد) فقط یک نوبت ضربان می‌گیرید نه backlog. تایمر با هر شلیک دوباره لنگر می‌اندازد.
  • پیام‌های کاربر برنده‌اند. پیام صف‌شدهٔ کاربر همیشه اولویت دارد؛ ضربان منتظر تخلیهٔ صف ورودی می‌ماند.
  • امن-برای-کش. پرامپت تزریق‌شده یک پیام معمولی کاربر است. هیچ جهش پرامپت-سیستمی، هیچ تغییر تول‌ست.
  • ماندگاری. وضعیت در ‏SessionDB.state_meta با کلید ‏heartbeat:<session_id> زندگی می‌کند — از ‏/resume جان می‌برد و از چرخه‌های نشستِ فشرده‌سازی-زمینه عبور می‌کند. شلیک نیازمند اجرای پروسهٔ مالک ‏(نشست CLI یا گیت‌وی) است؛ برای برنامه‌هایی که باید از همه‌چیز جان ببرند از cron استفاده کنید.
  • گیتی ابداع-کار. پرامپت تزریق‌شده به ایجنت می‌گوید وقتی هیچ تغییر معناداری نبود کوتاه جواب بدهد و متوقف شود، تا ضربان بی‌کار کار بیهوده تولید نکند.

۴ مثال

text
You: /heartbeat every 15m Check whether the CI run for PR #1234 finished; summarize the result when it does

  ♥ Heartbeat set (every 15m): Check whether the CI run for PR #1234 finished; ...

[15 minutes of you working on other things in the same session]

Hermes: [Heartbeat — recurring instruction, fires every 15m]
  💻 gh pr checks 1234   (1.2s)
  CI is still running (14/37 checks complete). Nothing to report yet.

وقتی جواب دیگر عوض نمی‌شود آن را ‏/heartbeat clear کنید — یا بگذارید مراقبت را ادامه دهد.
