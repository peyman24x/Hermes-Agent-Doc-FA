خانه/کار با Hermes/پروفایل‌ها

پروفایل‌ها: اجرای چند ایجنت

چند ایجنت هرمسِ مستقل را روی همان ماشین اجرا کنید — هر کدام با پیکربندی، کلیدهای API، حافظه، نشست‌ها، مهارت‌ها و وضعیت گیت‌ویِ خودش.

۱ پروفایل چیست؟

پروفایل، یک پوشهٔ home جداگانه برای هرمس است. هر پروفایل پوشهٔ خودش را می‌گیرد شامل config.yaml، .env، SOUL.md، حافظه‌ها، نشست‌ها، مهارت‌ها، کارهای کرون و دیتابیس وضعیتِ خودش. پروفایل‌ها به شما اجازه می‌دهند برای اهداف مختلف ایجنت‌های جدا اجرا کنید — یک دستیار کدنویسی، یک بات شخصی، یک ایجنت پژوهش — بدون قاطی‌شدن وضعیت هرمس.

⛔ به هر ایجنت پروفایل جداگانه‌اش را بدهید

هرگز دو پروسهٔ ایجنت را به یک پروفایل (همان home هرمس) اشاره ندهید. هر دو به‌طور خودکار حافظه می‌نویسند، و هر کدام نوشته‌های دیگری را هنگام شروع نشست به پرامپت سیستمی‌اش بارگذاری می‌کند — پس دو نویسنده روی یک home، وضعیت هم را ترکیب می‌کنند تا اینکه دیگر چیزی که پیکربندی کرده بودید باقی نماند. پروفایل‌ها دقیقاً برای جلوگیری از همین‌اند؛ ایجنت‌هایی که به حافظهٔ مشترک نیاز دارند به‌جای آن از یک ارائه‌دهندهٔ حافظهٔ خارجی استفاده کنند.

وقتی پروفایلی می‌سازید، به‌طور خودکار به فرمانِ خودش تبدیل می‌شود. پروفایلی به نام coder بسازید و بلافاصله coder chat، coder setup، coder gateway start و غیره را دارید.

۲ شروع سریع

bash
hermes profile create coder       # ساخت پروفایل + نام مستعار فرمان "coder"
coder setup                       # پیکربندی کلیدهای API و مدل
coder chat                        # شروع گفتگو

همین. coder حالا یک پروفایل هرمسِ مستقل با پیکربندی، حافظه و وضعیت خودش است.

۳ ساخت پروفایل

💡 نکته

سریع‌ترین راه‌اندازی: داخل پروفایل جدید hermes setup --portal را اجرا کنید تا مدل + ابزارها یک‌جا متصل شوند. به «Nous Portal» مراجعه کنید.

پروفایل خالی

bash
hermes profile create mybot

یک پروفایل تازه با مهارت‌های داخلیِ کاشته‌شده می‌سازد. mybot setup را برای پیکربندی کلیدهای API، مدل و توکن‌های گیت‌وی اجرا کنید.

اگر قرار است از این پروفایل به‌عنوان کارگرِ کانبان استفاده کنید (یا می‌خواهید ارکستراتور کانبان کار به او بفرستد)، هنگام ساخت --description "<role>" بدهید تا ارکستراتور بداند در چه چیزی خوب است:

bash
hermes profile create researcher --description "Reads source code and external docs, writes findings."

می‌توانید توضیحات را بعداً هم با hermes profile describe تنظیم یا خودکار تولید کنید — برای مدل کامل مسیریابی به «راهنمای کانبان» مراجعه کنید.

فقط کلون پیکربندی (--clone)

bash
hermes profile create work --clone

config.yaml، .env، SOUL.md و مهارت‌های پروفایل فعلی‌تان را به پروفایل جدید کپی می‌کند. همان کلیدهای API، مدل و توانایی‌ها، اما نشست‌ها و حافظهٔ تازه. برای کلیدهای API متفاوت ~/.hermes/profiles/work/.env و برای شخصیت متفاوت ~/.hermes/profiles/work/SOUL.md را ویرایش کنید.

کلون همه‌چیز (--clone-all)

bash
hermes profile create backup --clone-all

همه‌چیز را کپی می‌کند — پیکربندی، کلیدهای API، شخصیت، تمام حافظه‌ها، مهارت‌ها، کارهای کرون و پلاگین‌ها. یک اسنپ‌شات کاریِ کامل. تاریخچهٔ به‌ازای-پروفایل مستثناست (تاریخچهٔ نشست، state.db، backups/، state-snapshots/، checkpoints/) — این‌ها متعلق به پروفایل مبدأند و می‌توانند به ده‌ها گیگابایت برسند. برای پشتیبان کاملِ شامل تاریخچه، به‌جایش از hermes profile export یا hermes backup استفاده کنید.

کلون از پروفایل مشخص

bash
hermes profile create work --clone-from coder

--clone-from <source> پروفایل مبدأ را مستقیم انتخاب می‌کند و به معنای کلونِ پیکربندی/مهارت/SOUL است. وقتی کپی کامل آن پروفایل مبدأ را می‌خواهید با --clone-all ترکیبش کنید:

bash
hermes profile create work-backup --clone-from coder --clone-all
💡 حافظهٔ Honcho + پروفایل‌ها

وقتی Honcho فعال است، عملیات کلون به‌طور خودکار یک AI peer اختصاصی برای پروفایل جدید می‌سازد در حالی که همان ورک‌اسپیس کاربر را به اشتراک می‌گذارد. هر پروفایل مشاهدات و هویت خودش را می‌سازد. برای جزئیات به «Honcho — چندایجنت / پروفایل‌ها» مراجعه کنید.

۴ استفاده از پروفایل‌ها

نام‌های مستقل فرمان

هر پروفایل به‌طور خودکار یک نام مستعار فرمان در ~/.local/bin/<name> می‌گیرد:

bash
coder chat                    # گفتگو با ایجنت coder
coder setup                   # پیکربندی تنظیمات coder
coder gateway start           # راه‌اندازی گیت‌وی coder
coder doctor                  # بررسی سلامت coder
coder skills list             # فهرست مهارت‌های coder
coder config set model.default anthropic/claude-sonnet-4

این نام مستعار با هر زیرفرمان هرمس کار می‌کند — در پس‌زمینه فقط hermes -p <name> است.

پرچم -p

همچنین می‌توانید پروفایل را با هر فرمانی صریح هدف بگیرید:

bash
hermes -p coder chat
hermes --profile=coder doctor
hermes chat -p coder -q "hello"    # در هر جای فرمان کار می‌کند

پیش‌فرض چسبان (hermes profile use)

bash
hermes profile use coder
hermes chat                   # حالا به coder اشاره می‌کند
hermes tools                  # ابزارهای coder را پیکربندی می‌کند
hermes profile use default    # بازگشت به پیش‌فرض

یک پیش‌فرض تنظیم می‌کند تا فرمان‌های سادهٔ hermes به آن پروفایل هدف بگیرند. مثل kubectl config use-context.

بدانید کجا هستید

CLI همیشه نشان می‌دهد کدام پروفایل فعال است:

  • پرامپت: coder ❯ به‌جای ❯
  • بنر: هنگام راه‌اندازی Profile: coder را نشان می‌دهد
  • hermes profile: نام پروفایل فعلی، مسیر، مدل و وضعیت گیت‌وی را نشان می‌دهد

۵ پروفایل در برابر ورک‌اسپیس در برابر سندباکس

پروفایل‌ها اغلب با ورک‌اسپیس یا سندباکس اشتباه گرفته می‌شوند، اما چیزهای متفاوتی‌اند:

  • پروفایل به هرمس پوشهٔ وضعیت خودش را می‌دهد: config.yaml، .env، SOUL.md، نشست‌ها، حافظه، لاگ‌ها، کارهای کرون و وضعیت گیت‌وی.
  • ورک‌اسپیس یا پوشهٔ کاری جایی است که دستورات ترمینال شروع می‌شوند. این جداگانه با terminal.cwd کنترل می‌شود.
  • سندباکس چیزی است که دسترسی فایل‌سیستم را محدود می‌کند. پروفایل‌ها ایجنت را سندباکس نمی‌کنند.

روی بک‌اند ترمینال پیش‌فرضِ local، ایجنت همان دسترسی فایل‌سیستمِ حساب کاربری شما را دارد. پروفایل مانع دسترسی‌اش به پوشه‌های بیرون از پوشهٔ پروفایل نمی‌شود.

اگر می‌خواهید پروفایلی در پوشهٔ پروژهٔ مشخصی شروع شود، terminal.cwd مطلق را در config.yaml همان پروفایل صریح تنظیم کنید:

yaml
terminal:
  backend: local
  cwd: /absolute/path/to/project

استفاده از cwd: "." روی بک‌اند local یعنی «پوشه‌ای که هرمس از آن راه‌اندازی شده»، نه «پوشهٔ پروفایل».

همچنین توجه کنید:

  • SOUL.md می‌تواند مدل را هدایت کند، اما مرز ورک‌اسپیس اجباری نمی‌کند.
  • تغییرات SOUL.md تمیز روی نشست جدید اثر می‌کنند. نشست‌های موجود ممکن است هنوز از وضعیت پرامپت قدیمی استفاده کنند.
  • پرسیدن از مدل «در کدام پوشه هستی؟» یک آزمون ایزوله‌سازی قابل‌اعتماد نیست. اگر پوشهٔ شروعِ قابل‌پیش‌بینی برای ابزارها می‌خواهید، terminal.cwd را صریح تنظیم کنید.

۶ اجرای گیت‌وی‌ها

هر پروفایل گیت‌وی خودش را به‌عنوان پروسه‌ای جدا با توکن بات خودش اجرا می‌کند:

bash
coder gateway start           # گیت‌وی coder را راه می‌اندازد
assistant gateway start       # گیت‌وی assistant (پروسهٔ جدا)

توکن‌های بات متفاوت

هر پروفایل فایل .env خودش را دارد. توکن بات تلگرام/دیسکورد/اسلک متفاوتی در هر کدام پیکربندی کنید:

bash
# ویرایش توکن‌های coder
nano ~/.hermes/profiles/coder/.env

# ویرایش توکن‌های assistant
nano ~/.hermes/profiles/assistant/.env

ایمنی: قفل توکن

اگر دو پروفایل تصادفاً از یک توکن بات استفاده کنند، گیت‌وی دوم با خطایی روشن که پروفایل متناقض را نام می‌برد مسدود می‌شود. برای تلگرام، دیسکورد، اسلک، واتساپ و سیگنال پشتیبانی شده است.

سرویس‌های پایدار

bash
coder gateway install         # سرویس systemd/launchd به نام hermes-gateway-coder می‌سازد
assistant gateway install     # سرویس hermes-gateway-assistant را می‌سازد

هر پروفایل نام سرویس خودش را می‌گیرد. مستقل اجرا می‌شوند.

ℹ️ داخل ایمیج رسمی داکر

گیت‌وی‌های هر پروفایل توسط s6-overlay نظارت می‌شوند (PID 1 در کانتینر)، پس hermes profile create <name> به‌طور خودکار یک جایگاه سرویس s6 در /run/service/gateway-<name>/ ثبت می‌کند. hermes -p <name> gateway start/stop/restart به‌جای تولید پروسهٔ خام به s6-svc فرمان می‌دهد — خرابی‌ها خودکار دوباره راه‌اندازی می‌شوند و docker restart مجموعهٔ قبلیِ گیت‌وی‌های در حال اجرا را حفظ می‌کند. برای جزئیات به «نظارت بر گیت‌وی هر پروفایل» مراجعه کنید.

۷ پیکربندی پروفایل‌ها

هر پروفایل این مواردِ مخصوص به خودش را دارد:

  • config.yaml — مدل، ارائه‌دهنده، تول‌ست‌ها و همهٔ تنظیمات
  • .env — کلیدهای API و توکن‌های بات
  • SOUL.md — شخصیت و دستورالعمل‌ها
bash
coder config set model.default anthropic/claude-sonnet-4
echo "You are a focused coding assistant." > ~/.hermes/profiles/coder/SOUL.md

اگر می‌خواهید این پروفایل به‌طور پیش‌فرض در پروژهٔ مشخصی کار کند، terminal.cwd خودش را هم تنظیم کنید:

bash
coder config set terminal.cwd /absolute/path/to/project

از داشبورد

داشبورد وب سطحی در مقیاس ماشین است که می‌تواند پیکربندی، کلیدهای API، مهارت‌ها، MCPها و مدل هر پروفایلی را از طریق سوییچر پروفایل در سایدبارش مدیریت کند — بدون نیاز به داشبورد جداگانه به‌ازای هر پروفایل. coder dashboard به داشبورد ماشین با پروفایل coder از-پیش-انتخاب‌شده می‌رود. تب چت داشبورد هم از سوییچر پیروی می‌کند و گفتگو را زیر home پروفایل انتخاب‌شده شروع می‌کند.

نکته: «Set as active» در صفحهٔ پروفایل‌های داشبورد همان پیش‌فرض چسبان برای اجراهای آتیِ CLI/گیت‌وی است (مثل hermes profile use) — برای ویرایش یک پروفایل از داشبورد، به‌جایش از سوییچر استفاده کنید.

۸ به‌روزرسانی

hermes update کد را یک بار می‌گیرد (مشترک) و مهارت‌های داخلی جدید را به‌طور خودکار با همهٔ پروفایل‌ها همگام می‌کند:

bash
hermes update
# → Code updated (12 commits)
# → Skills synced: default (up to date), coder (+2 new), assistant (+2 new)

مهارت‌های تغییر یافته توسط کاربر هرگز بازنویسی نمی‌شوند.

۹ مدیریت پروفایل‌ها

bash
hermes profile list           # نمایش همهٔ پروفایل‌ها با وضعیت
hermes profile show coder     # اطلاعات دقیق یک پروفایل
hermes profile rename coder dev-bot   # تغییر نام (نام مستعار + سرویس به‌روز می‌شود)
hermes profile export coder   # بسته‌بندی در coder.tar.gz (قابل اشتراک؛ کلیدها حذف می‌شوند)
hermes profile import coder.tar.gz   # نصب یک آرشیو به‌عنوان پروفایل جدید

در چت، همین دو به‌صورت /export و /import موجودند — و در اپ دسکتاپ به‌صورت ⌘K ← Export/Import profile…. به «اشتراک یک پروفایل» مراجعه کنید.

نام‌گذاری پروفایل پیش‌فرض

شناسهٔ داخلی پروفایل پیش‌فرض همیشه default است — واقعاً قابل تغییر نام نیست چون ~/.hermes ریشهٔ نصب است. تغییر نامش در عوض یک نام نمایشی تنظیم می‌کند که سطوح UI به‌جای شناسهٔ خالی نشان می‌دهند:

bash
hermes profile rename default Harumesu   # یونیکد هم اوکی: 小助手

نام نمایشی در hermes profile list/show، فرمان چتِ /profile، داشبورد و اپ دسکتاپ (شامل فهرست حالت بات) ظاهر می‌شود. فقط نمایشی است: -p default، نام سرویس‌ها، کارهای کرون و هر ارجاع دیگری به شناسهٔ رسمی default ادامه می‌دهند. به‌صورت display_name در ~/.hermes/profile.yaml ذخیره می‌شود؛ آن خط را حذف کنید تا برگردد. پروفایل‌های نام‌دار هم می‌توانند display_name داشته باشند (از یک تغییر نام واقعی جان سالم به در می‌برد)، اما rename برایشان همچنان خود پروفایل را تغییر نام می‌دهد.

۱۰ حذف پروفایل

bash
hermes profile delete coder

گیت‌وی را متوقف می‌کند، سرویس systemd/launchd را حذف می‌کند، نام مستعار فرمان را برمی‌دارد و تمام داده‌های پروفایل را پاک می‌کند. برای تأیید از شما خواسته می‌شود نام پروفایل را تایپ کنید.

برای رد کردن تأیید از --yes استفاده کنید: hermes profile delete coder --yes

ℹ️ توجه

پروفایل پیش‌فرض (~/.hermes) قابل حذف نیست. برای حذف همه‌چیز از hermes uninstall استفاده کنید.

۱۱ تکمیل خودکار با Tab

bash
# Bash
eval "$(hermes completion bash)"

# Zsh
eval "$(hermes completion zsh)"

این خط را به ~/.bashrc یا ~/.zshrc اضافه کنید تا تکمیل پایدار باشد. نام پروفایل‌ها بعد از -p، زیرفرمان‌های profile و فرمان‌های سطح بالا را تکمیل می‌کند.

۱۲ چگونه کار می‌کند

پروفایل‌ها از متغیر محیطی HERMES_HOME استفاده می‌کنند. وقتی coder chat را اجرا می‌کنید، اسکریپت پوشاننده پیش از راه‌اندازی هرمس HERMES_HOME=~/.hermes/profiles/coder را تنظیم می‌کند. چون بیش از ۱۱۹ فایل کدبیس مسیرها را از طریق get_hermes_home() حل می‌کنند، وضعیت هرمس به‌طور خودکار به پوشهٔ پروفایل محدود می‌شود — پیکربندی، نشست‌ها، حافظه، مهارت‌ها، دیتابیس وضعیت، PID گیت‌وی، لاگ‌ها و کارهای کرون.

این از پوشهٔ کاریِ ترمینال جدا است. اجرای ابزار از terminal.cwd شروع می‌شود (یا پوشهٔ راه‌اندازی وقتی cwd: "." روی بک‌اند local است)، نه به‌طور خودکار از HERMES_HOME.

روی نصب‌های میزبان، زیرپروسه‌های ابزار به‌طور پیش‌فرض HOME واقعیِ کاربر سیستم‌عامل شما را نگه می‌دارند تا اعتبارنامه‌های موجودِ CLI زیر ~ بین پروفایل‌ها کار کنند. دادهٔ پروفایل با HERMES_HOME ایزوله است، نه با تغییر HOME. بک‌اندهای کانتینری همچنان از {HERMES_HOME}/home برای وضعیت پایدار ابزار استفاده می‌کنند، و کاربران میزبان که پیکربندی ابزارِ سخت‌گیرانه به‌ازای-پروفایل می‌خواهند می‌توانند با terminal.home_mode: profile فعالش کنند.

یعنی دو چیزی که آسان قاطی می‌شوند:

  • HERMES_HOME مرز پروفایل است. پیکربندی هرمس، .env، حافظه، نشست‌ها، مهارت‌ها، لاگ‌ها، کارهای کرون، وضعیت گیت‌وی و سایر داده‌های هرمس را کنترل می‌کند.
  • HOME خانهٔ کاربر/سیستم‌عامل است که CLIهای خارجی انتظارش را دارند. روی نصب‌های میزبان، هرمس به‌طور پیش‌فرض آن را همان خانهٔ واقعی کاربر نگه می‌دارد تا ابزارهایی مثل git، ssh، gh، az، npm، Claude Code و Codex همان اعتبارنامه‌هایی را پیدا کنند که در شل عادی شما استفاده می‌کنند.

مبادله این است که پروفایل‌های میزبان به‌طور پیش‌فرض وضعیت CLI در سطح کاربر را به اشتراک می‌گذارند. اگر به هویت CLI جداگانه به‌ازای هر پروفایل نیاز دارید، terminal.home_mode: profile را در config.yaml همان پروفایل تنظیم کنید. در آن حالت هرمس زیرپروسه‌های ابزار را با HOME={HERMES_HOME}/home اجرا می‌کند؛ آن‌گاه باید ~/.ssh، ~/.gitconfig، ~/.config/gh، احراز هویت CLIهای ابری، احراز Claude/Codex، وضعیت npm و فایل‌های مشابهِ مخصوص پروفایل را داخل آن home مقداردهی یا لینک کنید.

هرمس همچنین HERMES_REAL_HOME را به زیرپروسه‌ها عرضه می‌کند تا اسکریپت‌ها وقتی home_mode: profile فعال است بتوانند خانهٔ واقعی حساب را پیدا کنند.

پروفایل پیش‌فرض خودِ ~/.hermes است. نیازی به مهاجرت نیست — نصب‌های موجود یکسان کار می‌کنند.

۱۳ اشتراک یک پروفایل

پروفایلی که روی یک ماشین ساختید می‌تواند به ماشین دیگری برود — ورک‌استیشن خودتان، لپ‌تاپ هم‌تیمی یا جامعه. دو مسیر:

ارسال فایل. /export پروفایل را در یک .tar.gz بسته می‌کند — مهارت‌ها، حافظه، پرسونا، کرون‌ها، پلاگین‌ها، تنظیمات و (از دسکتاپ) تم و چیدمان شما. کلیدهای API حذف می‌شوند. دریافت‌کننده /import را اجرا می‌کند.

bash
# در چت /export را اجرا کنید، فایل را بدهید و او /import را روی آن اجرا کند
hermes profile export coder
hermes profile import ./coder.tar.gz --name coder

انتشار یک توزیع. پروفایل را به‌صورت یک مخزن گیت بسته‌بندی کنید تا دریافت‌کنندگان با یک فرمان نصبش کنند و بعداً به‌روزرسانی‌های نسخه‌بندی‌شده بگیرند. SOUL، پیکربندی، مهارت‌ها، کارهای کرون و اتصالات MCP را حمل می‌کند؛ اعتبارنامه‌ها، حافظه‌ها و نشست‌ها به‌ازای-ماشین می‌مانند.

bash
# نصب یک ایجنت کامل از یک مخزن گیت
hermes profile install github.com/you/research-bot --alias

# به‌روزرسانی بعدی وقتی نویسنده نسخهٔ جدید داد (حافظه‌ها + .env شما حفظ می‌شوند)
hermes profile update research-bot

برای تحویل یک‌باره یا جابه‌جایی از فایل خروجی استفاده کنید؛ برای ایجنتی که به انتشارش ادامه می‌دهید از توزیع. برای هر دو — جدول مقایسه، تألیف، انتشار، معنای به‌روزرسانی و مدل امنیتی — به «توزیع پروفایل: اشتراک یک ایجنت کامل» مراجعه کنید.
