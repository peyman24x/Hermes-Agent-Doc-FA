رابط خط فرمان (CLI)

CLI هرمس ایجنت یک رابط کاربری کامل ترمینالی است — نه UI وب. دارای ویرایش چندخطی، تکمیل‌خودکار فرمان‌های اسلش، تاریخچهٔ گفتگو، وقفه-و-بازهدایت، و خروجی استریم‌شدهٔ ابزار. برای آدم‌هایی ساخته شده که در ترمینال زندگی می‌کنند.

💡 راه‌اندازی اولیه

یک فرمان — hermes setup --portal — و آمادهٔ hermes chat هستید. به «Nous Portal» مراجعه کنید.

💡 نکته

هرمس همچنین یک TUI مدرن با اورلی‌های مودال، انتخاب موسی و ورودی غیرمسدودکننده عرضه می‌کند. با hermes --tui اجرایش کنید — به راهنمای «TUI» مراجعه کنید.

۱ اجرای CLI

bash
# شروع نشست تعاملی (پیش‌فرض)
hermes

# حالت تک-کوئری (غیرتعاملی)
hermes chat -q "Hello"

# تک-کوئری از فایل یا stdin — هیچ چیز شلی-تفسیر نمی‌شود، پس
# متن دلخواه (گیومه‌ها، $(...)، بک‌تیک‌ها) تحت‌اللفظی می‌رسد
hermes chat --query-file prompt.txt
hermes chat --query-file - < prompt.txt

# با مدل مشخص
hermes chat --model "anthropic/claude-sonnet-4"

# با ارائه‌دهندهٔ مشخص
hermes chat --provider nous        # استفاده از Nous Portal
hermes chat --provider openrouter  # اجبار OpenRouter

# با تول‌ست‌های مشخص
hermes chat --toolsets "web,terminal,skills"

# شروع با یک یا چند مهارتِ از-پیش-بارگذاری‌شده
hermes -s hermes-agent-dev,github-auth
hermes chat -s github-pr-workflow -q "open a draft PR"

# ازسرگیری نشست‌های قبلی
hermes --continue             # ازسرگیری جدیدترین نشست CLI (-c)
hermes --resume <session_id>  # ازسرگیری نشستی مشخص با شناسه (-r)
hermes --resume latest        # جدیدترین نشست (مثل -c)
hermes --resume latest --in ./dir  # جدیدترین نشست ./dir، ماندن در ./dir

# حالت پرگویی (خروجی دیباگ)
hermes chat --verbose

# ورک‌تری گیت ایزوله (برای اجرای چند ایجنت موازی)
hermes -w                         # حالت تعاملی در ورک‌تری
hermes -w -z "Fix issue #123"     # تک-کوئری در ورک‌تری

پاک‌سازی ورک‌تری

نشست‌های hermes -w ورک‌تری‌های یک‌بارمصرف زیر <repo>/.worktrees/ می‌سازند. یک هرس‌کنندهٔ محافظه‌کار هنگام شروع خودکار اجرا می‌شود (فقط درخت‌های تمیزِ کاملاً-merge‌شدهٔ عبورکرده از آستانهٔ سن را برمی‌دارد)، ولی درخت‌های نگه‌داشته‌شده و شاخه‌های محلیِ merge‌شده روی ماشین‌های شلوغ همچنان انباشته می‌شوند. صریح پس بگیریدشان:

bash
hermes worktree list              # ممیزی: سن، حجم، حکم و دلیل به‌ازای هر درخت
hermes worktree prune             # حذف درخت‌های امن + حذف شاخه‌های merge‌شده
hermes worktree prune --dry-run   # نمایش برنامه بدون تغییر هیچ‌چیز
hermes worktree prune --trees-only     # شاخه‌های محلی را دست نزن
hermes worktree prune --branches-only  # ورک‌تری‌ها را دست نزن

درون نشست، /worktree prune [--dry-run] همین کار را می‌کند (و هرگز درختی که نشست در آن اجراست را لمس نمی‌کند).

تضمین‌های ایمنی (همهٔ حالت‌ها، هر سن):

  • تغییرات ردیابی‌شدهٔ کامیت‌نشده هرگز حذف نمی‌شوند.
  • کامیت‌های یکتای ناپوش‌شده هرگز حذف نمی‌شوند — کامیت‌هایی که با rebase/squash بالادستی merge شده‌اند از طریق هم‌ارزی پچِ git cherry تشخیص داده و merge‌شده حساب می‌شوند، که همان چیزی است که اجازه می‌دهد نشتیِ غالبِ «PR مرج‌شده، درخت برای همیشه نگه‌داشته‌شده» بالاخره پس گرفته شود.
  • درخت‌های در حال استفاده توسط نشست هرمس در حال اجرا هرگز لمس نمی‌شوند.
  • خراشِ فقط-untracked (پیش‌نویس بدنهٔ PR، یادداشت‌ها) قبل از حذف درختش به ~/.hermes/archive/worktree-prune/ آرشیو می‌شود — هرگز نابود نمی‌گردد.
  • حذف شاخه با محتوا گیت می‌خورد نه با نام: هر شاخهٔ محلی‌ای که همهٔ کامیت‌هایش روی بالادستی است امنِ حذف است؛ شاخه‌های دارای کار یکتا، شاخه‌های چک‌اوت‌شده و main/master/develop همیشه نگه داشته می‌شوند.

وقتی .worktrees/ از ۱۰ درخت یا ۵ گیگابایت بگذرد، شروع یک خط اعلان چاپ می‌کند که به این فرمان‌ها اشاره دارد.

مدیریت پلاگین

فرمان‌های hermes plugins پلاگین‌های بومی هرمس و بسته‌های قابل‌حمل Agent Plugins v1 را از همان گردش‌کار اختیاری مدیریت می‌کنند:

bash
hermes plugins install owner/repository --no-enable
hermes plugins list
hermes plugins enable <plugin-name>
hermes plugins disable <plugin-name>
hermes plugins update <plugin-name>
hermes plugins remove <plugin-name>

بسته‌های قابل‌حمل تا فعال‌سازی صریح غیرفعال می‌مانند. هرمس در حال حاضر Agent Skills قابل‌حمل و مدخل‌های stdio مربوط به MCP را بارگذاری می‌کند. برای زیرمجموعهٔ دقیق پشتیبانی‌شده و مرز اعتماد به «راهنمای توسعه‌دهندهٔ پلاگین ← بسته‌های قابل‌حمل Agent Plugins v1» مراجعه کنید.

از /usage برای تفکیک دقیق شامل هزینه‌های به‌ازای-دسته (توکن ورودی در برابر خروجی) استفاده کنید.

روی ارائه‌دهندهٔ openai-codex، ‏/usage همچنین ریست‌های ذخیره‌شدهٔ سقف مصرف حساب ChatGPT شما را نشان می‌دهد («You have N resets banked - use /usage reset to activate»). ‏/usage reset یکی از ریست‌های ذخیره‌شده را نقد می‌کند و سقف‌های ۵ ساعته و هفتگی‌تان را کامل بازیابی می‌کند. هرمس تا وقتی سقف‌هاتان تمام نشده نقد‌کردن را رد می‌کند (یک ریستِ ذخیره‌شده کل سهمیه را برمی‌گرداند، پس خرج‌کردنش زودهنگام هدر دادنش است) — ‏/usage reset --force بدهید تا به‌هرحال نقد شود.

نمایش ازسرگیری نشست

هنگام ازسرگیری نشستی قبلی‏ (hermes -c یا hermes --resume <id>)، پنلی با نام «Previous Conversation» بین بنر و پرامپت ورودی ظاهر می‌شود که خلاصهٔ فشرده‌ای از تاریخچهٔ گفتگو نشان می‌دهد. برای جزئیات و پیکربندی به «نشست‌ها ← خلاصهٔ گفتگو هنگام ازسرگیری» مراجعه کنید.

!<command>حالت شل — خودتان یک فرمان شلی اجرا کنید بدون خرج یک نوبت مدل (مثلاً !git status، ‏!pytest -x). پایین را ببینید.

پیش‌نمایش چسباندن چندخطی. وقتی بلوکی چندخطی می‌چسبانید، CLI به‌جای ریختن کل محتوا در اسکرول‌بک، یک پیش‌نمایش فشردهٔ یک‌خطی طنین می‌دهد‏ ([pasted: 47 lines, 1,842 chars — press Enter to send]). محتوای کامل همچنان همان چیزی است که ارسال می‌شود؛ این فقط پولیش نمایشی است.

حالت شل !

خطی را با ! شروع کنید تا به‌عنوان فرمان شلی اجرا شود به‌جای ارسال به ایجنت:

نمونه
> !git status
> !ls -la
> !pytest -x tests/cli
  • هزینهٔ صفر. مدل هرگز فراخوانی نمی‌شود — بدون فراخوانی API، بدون توکن، بدون تأخیر.
  • هیچ‌چیز وارد گفتگو نمی‌شود. فرمان و خروجیش به تاریخچه اضافه نمی‌شوند، پس زمینه‌تان تمیز و کش پرامپت دست‌نخورده می‌ماند.
  • همان‌جایی اجرا می‌شود که ابزار terminal ایجنت اجرا می‌شود. از پوشهٔ کاری نشست استفاده می‌کند، پس !pwd با چیزی که ایجنت می‌دید مطابق است.
  • تأییدها همچنان اعمال‌اند. فرمان خطرناک‏ (rm -rf، نوشتن در ~/.hermes/config.yaml و غیره) از همان اعلان تأییدی می‌گذرد که ابزار terminal ایجنت استفاده می‌کند. ! میان‌بر هزینه/تأخیر است، نه دورزدن امنیتی.
  • خروج‌های غیرصفر نشان داده می‌شوند. فرمان شکست‌خورده بعد از خروجیش ! exited <code> چاپ می‌کند.
  • ! به‌تنهایی یک یادآور یک‌خطی چاپ می‌کند.

حالت شل فقط CLI است. پلتفرم‌های گیت‌وی‏ (دیسکورد، تلگرام، اسلک) و اجراهای کرونی آن را نادیده می‌گیرند — آن کاربران شل خودشان را دارند.

حذف مارک‌داون در پاسخ‌های نهایی. CLI پرگفتارترین حصارهای مارک‌داون و پوشش‌های **پررنگ** / *مورب* را از پاسخ‌های نهایی ایجنت حذف می‌کند تا به‌صورت نثر ترمینالیِ خوانا رندر شوند نه سورس خام. بلوک‌های کد و فهرست‌ها حفظ می‌شوند. این به پلتفرم‌های گیت‌وی یا نتایج ابزار اثری ندارد — آن‌ها مارک‌داونشان را برای رندر بومی نگه می‌دارند.

۴ فرمان‌های اسلش

/ را تایپ کنید تا دراپ‌داون تکمیل‌خودکار ببینید. هرمس مجموعهٔ بزرگی از فرمان‌های اسلش CLI، فرمان‌های داینامیک مهارت و فرمان‌های سریع تعریف‌شده توسط کاربر پشتیبانی می‌کند. نمونه‌های رایج:

برای فهرست کامل داخلیِ CLI و پیام‌رسانی، به «مرجع فرمان‌های اسلش» مراجعه کنید. برای راه‌اندازی، ارائه‌دهندگان، تنظیم سکوت و استفادهٔ صوتی/دیسکورد به «حالت صوتی» مراجعه کنید.

💡 نکته

فرمان‌ها بدون حساسیت به بزرگی/کوچکی‌اند — ‏/HELP مثل /help کار می‌کند. مهارت‌های نصب‌شده هم خودکار فرمان اسلش می‌شوند.

فرمان‌های سریع

می‌توانید فرمان‌های سفارشی تعریف کنید که فرمان‌های شلی را بدون فراخوانی LLM فوری اجرا کنند. این‌ها هم در CLI و هم در پلتفرم‌های پیام‌رسانی (تلگرام، دیسکورد و غیره) کار می‌کنند:

yaml — ~/.hermes/config.yaml
quick_commands:
  status:
    type: exec
    command: systemctl status hermes-agent
  gpu:
    type: exec
    command: nvidia-smi --query-gpu=utilization.gpu,memory.used --format=csv,noheader
  restart:
    type: alias
    target: /gateway restart

سپس در هر چتی /status، ‏/gpu یا /restart را تایپ کنید. برای مثال‌های بیشتر به راهنمای پیکربندی ← فرمان‌های سریع مراجعه کنید.

پیش‌بارگذاری مهارت‌ها هنگام اجرا

اگر از قبل می‌دانید کدام مهارت‌ها را برای نشست فعال می‌خواهید، هنگام اجرا پاسشان دهید:

bash
hermes -s hermes-agent-dev,github-auth
hermes chat -s github-pr-workflow -s github-auth

هرمس هر مهارتِ نام‌برده را پیش از اولین نوبت در پرامپت نشست بارگذاری می‌کند. همان پرچم در حالت تعاملی و تک-کوئری کار می‌کند.

۶ ورودی چندخطی

دو راه برای واردکردن پیام‌های چندخطی هست:

  1. Alt+Enter، ‏Ctrl+J یا Shift+Enter — خط جدید درج می‌کند
  2. ادامه با بک‌اسلش — خطی را با \ تمام کنید تا ادامه یابد:
نمونه
❯ Write a function that:\
  1. Takes a list of numbers\
  2. Returns the sum

Ctrl+J و ادامهٔ بک‌اسلش به‌طور پیش‌فرض فعال‌اند، هم‌راستا با میان‌برهای چندخطی Claude Code / ‏Codex / ‏OpenCode. روی ترمینال‌های پشتیبان‌شده مثل iTerm2، هرمس گزارش‌دهی کلید گسترده هم می‌خواهد تا Shift+Enter به‌صورت کلید خط-جدیدِ متمایز برسد. اگر ترمینال‌تان برای Enter ساده LF می‌فرستد و جایگزین قدیمیِ «Ctrl+J به‌عنوان-ارسال» را می‌خواهید، خارج شوید:

yaml — ~/.hermes/config.yaml
display:
  cli_multiline_shortcuts: false
ℹ️ توجه

چسباندن متن چندخطی پشتیبانی می‌شود — از هر کدام از کلیدهای خط-جدین بالا استفاده کنید، یا ساده محتوا را مستقیم پیست کنید.

سازگاری Shift+Enter

اغلب ترمینال‌ها به‌طور پیش‌فرض برای Enter و Shift+Enter همان دنبالهٔ بایتی را می‌فرستند، پس اپلیکیشن‌ها نمی‌توانند تفکیکشان کنند. هرمس Shift+Enter را فقط وقتی می‌شناسد که ترمینال دنباله‌ای متمایز از طریق پروتکل کیبورد Kitty یا حالت modifyOtherKeys مربوط به xterm بفرستد.

ترمینالوضعیت
‏Kitty، ‏foot، ‏WezTerm، ‏GhosttyShift+Enter متمایز به‌طور پیش‌فرض فعال
‏iTerm2 (اخیر)، ‏Alacritty، ‏ترمینال VS Code، ‏Warpبا فعال‌سازی پروتکل Kitty در تنظیمات پشتیبانی می‌شود
‏Windows Terminal Preview نسخهٔ ۱.۲۵+با فعال‌سازی پروتکل Kitty در تنظیمات پشتیبانی می‌شود
‏Terminal.app مک، ویندوز ترمینال پایدارِ خامپشتیبانی نشده — Shift+Enter از Enter تفکیک‌ناپذیر است

جایی که ترمینال نمی‌تواند تفکیک کند، Alt+Enter و Ctrl+J به‌طور پیش‌فرض به کار ادامه می‌دهند. به‌طور خاص روی ویندوز ترمینال، Alt+Enter را خود ترمینال می‌گیرد (تمام‌صفحه را سوییچ می‌کند) و هرگز به هرمس نمی‌رسد — برای خط جدید از Ctrl+Enter (که به‌صورت Ctrl+J تحویل می‌شود) یا مستقیم Ctrl+J استفاده کنید.

۷ بازهدایت ایجنت میان-نوبت

وقتی ایجنت در حال کار است، می‌توانید بدون شروع نوبت جدید اصلاحی بفرستید:

  • پیام جدید تایپ + ‏Enter — نوبت فعال را با اصلاح شما بازهدایت می‌کند
  • Ctrl+C — وقفهٔ عملیات فعلی (دو بار در ۲ ثانیه برای خروج اجباری)
  • کار ابزاری و استدلالِ نمایش‌داده‌شدهٔ تکمیل‌شده در زمینه می‌مانند
  • ابزارِ در حال اجرا پیش از اعمال اصلاح به مرز امنش می‌رسد

حالت ورودی هنگام اشغال

کلید پیکربندی display.busy_input_mode تعیین می‌کند هنگام فشردن Enter حین کار ایجنت چه شود:

حالترفتار
"interrupt" (پیش‌فرض)پیام شما نوبت فعال را بازهدایت می‌کند. تولید مدل با حفظ استدلالِ نمایش‌داده‌شده و کارِ تکمیل‌شده دوباره شروع می‌شود؛ ابزارهای در حال اجرا اول تمام می‌شوند
"queue"پیام شما خاموش صف و پس از اتمام ایجنت به‌عنوان نوبت بعدی ارسال می‌شود
"steer"پیام شما از طریق /steer به اجرای فعلی تزریق و بعد از فراخوانی ابزار بعدی به ایجنت می‌رسد — بدون وقفه، بدون نوبت جدید
yaml — ~/.hermes/config.yaml
display:
  busy_input_mode: "steer"   # یا "queue" یا "interrupt" (پیش‌فرض)

حالت "queue" یک نوبت پیگیریِ جداگانه آماده می‌کند. "steer" همیشه تا مرز نتیجهٔ ابزار بعدی صبر می‌کند. حالت پیش‌فرض "interrupt" حین تولید مدل زودتر پاسخ می‌دهد در حالی که از لغو ابزارِ در حال اجرا خودداری می‌کند. وقتی می‌خواهید نوبت و کار پیش‌زمینه‌اش لغو شود از /stop استفاده کنید. مقادیر ناشناخته به "interrupt" سقوط می‌کنند.

"steer" دو بازگشت خودکار دارد: اگر ایجنت هنوز شروع نشده، یا تصویری پیوست شده، پیام به رفتار "queue" برمی‌گردد تا هیچ‌چیز از دست نرود.

داخل CLI هم می‌توانید عوضش کنید:

فرمان‌ها
/busy queue
/busy steer
/busy interrupt
/busy status
💡 راهنمای لمس-اول

اولین باری که حین کار هرمس Enter بزنید، هرمس یک یادآور یک‌خطی چاپ می‌کند که پیچ /busy را توضیح می‌دهد. فقط یک بار به‌ازای نصب صادر می‌شود؛ onboarding.seen.busy_input_prompt در config.yaml ثبت می‌کند که نشان داده شده. آن کلید را حذف کنید تا نکته دوباره بیاید.

معلق‌کردن به پس‌زمینه

روی سیستم‌های یونیکسی، Ctrl+Z را بزنید تا هرمس مثل هر پروسهٔ ترمینالیِ دیگری به پس‌زمینه معلق شود. شل تأیید چاپ می‌کند:

خروجی
Hermes Agent has been suspended. Run `fg` to bring Hermes Agent back.

در شل خود fg را تایپ کنید تا نشست دقیقاً از همان‌جا که رها کردید ادامه یابد. روی ویندوز پشتیبانی نمی‌شود.

۸ نمایش پیشرفت ابزار

‏CLI حین کار ایجنت بازخورد انیمیت‌شده نشان می‌دهد:

انیمیشن تفکر (حین فراخوانی‌های API):

نمونه
  ◜ (｡•́︿•̀｡) pondering... (1.2s)
  ◠ (⊙_⊙) contemplating... (2.4s)
  ✧٩(ˊᗜˋ*)و✧ got it! (3.1s)

فید اجرای ابزار:

نمونه
  ┊ 💻 terminal `ls -la` (0.3s)
  ┊ 🔍 web_search (1.2s)
  ┊ 📄 web_extract (2.1s)

با /verbose بین حالت‌های نمایش بچرخید: off → new → all → verbose. این فرمان برای پلتفرم‌های پیام‌رسانی هم قابل فعال‌سازی است — به بخش تنظیمات نمایش در مستندات پیکربندی مراجعه کنید.

طول پیش‌نمایش ابزار

کلید پیکربندی display.tool_preview_length حداکثر تعداد کاراکترهای نشان‌داده‌شده در خطوط پیش‌نمایش فراخوانی ابزار را کنترل می‌کند (مثلاً مسیرهای فایل، فرمان‌های ترمینال). پیش‌فرض 0 است یعنی بدون سقف — مسیرها و فرمان‌های کامل نمایش داده می‌شوند.

yaml — ~/.hermes/config.yaml
display:
  tool_preview_length: 80   # بریدن پیش‌نمایش ابزار به ۸۰ کاراکتر (۰ = بدون سقف)

روی ترمینال‌های باریک یا وقتی آرگومان‌های ابزار مسیرهای فایل خیلی بلند دارند مفید است.

۹ مدیریت نشست

ازسرگیری نشست‌ها

وقتی از نشست CLI خارج می‌شوید، یک فرمان ازسرگیری چاپ می‌شود:

خروجی
Resume this session with:
  hermes --resume 20260225_143052_a1b2c3

Session:        20260225_143052_a1b2c3
Duration:       12m 34s
Messages:       28 (5 user, 18 tool calls)

گزینه‌های ازسرگیری:

bash
hermes --continue                          # ازسرگیری جدیدترین نشست CLI
hermes -c                                  # شکل کوتاه
hermes -c "my project"                     # ازسرگیری نشست نام‌دار (جدیدترین تبار)
hermes --resume 20260225_143052_a1b2c3     # ازسرگیری نشست مشخص با شناسه
hermes --resume "refactoring auth"         # ازسرگیری با عنوان
hermes --resume latest                     # جدیدترین نشست (مثل -c)
hermes --resume latest --in ./my-project   # جدیدترین نشست ورک‌اسپیس ./my-project
hermes -r 20260225_143052_a1b2c3           # شکل کوتاه

ازسرگیری، تاریخچهٔ کامل گفتگو را از SQLite بازیابی می‌کند. ایجنت همهٔ پیام‌ها، فراخوانی‌های ابزار و پاسخ‌های قبلی را می‌بیند — درست انگار هرگز نرفته بودید.

درون چت از /title My Session Name برای نام‌گذاری نشست فعلی استفاده کنید، یا از خط فرمان hermes sessions rename <id> <title>. برای مرور نشست‌های گذشته hermes sessions list.

ذخیره‌گاه نشست

نشست‌های CLI در دیتابیس وضعیت SQLite هرمس زیر ~/.hermes/state.db ذخیره می‌شوند. دیتابیس نگه می‌دارد:

  • فرادادهٔ نشست (شناسه، عنوان، مهرهای زمانی، شمارنده‌های توکن)
  • تاریخچهٔ پیام
  • تبار در سراسر نشست‌های فشرده/ازسرگرفته
  • اندیس‌های جستجوی تمام‌متنِ استفاده‌شده توسط session_search

برخی آداپتورهای پیام‌رسانی همچنین فایل‌های رونوشت به‌ازای-پلتفرم را کنار دیتابیس نگه می‌دارند، اما خود CLI از مخزن نشست SQLite ازسر می‌گیرد.

فشرده‌سازی زمینه

گفتگوهای طولانی هنگام نزدیک‌شدن به سقف زمینه خودکار خلاصه می‌شوند:

yaml — در ~/.hermes/config.yaml
compression:
  enabled: true
  threshold: 0.50    # فشرده‌سازی در ۵۰٪ سقف زمینه به‌طور پیش‌فرض

# مدل خلاصه‌سازی زیر auxiliary پیکربندی می‌شود:
auxiliary:
  compression:
    model: ""  # خالی بگذارید تا مدل چت اصلی استفاده شود (پیش‌فرض). یا یک مدل سریع ارزان پین کنید، مثل "google/gemini-3-flash-preview".

وقتی فشرده‌سازی تریگر می‌شود، نوبت‌های میانی خلاصه می‌شوند در حالی که ۳ نوبت اول و ۲۰ نوبت آخر همیشه حفظ می‌شوند.

۱۰ نشست‌های پس‌زمینه

یک پرامپت را در نشست پس‌زمینهٔ جداگانه اجرا کنید در حالی که به استفاده از CLI برای کارهای دیگر ادامه می‌دهید:

فرمان در چت
/background Analyze the logs in /var/log and summarize any errors from today

هرمس بلافاصله کار را تأیید و پرامپت را به شما برمی‌گرداند:

خروجی
🔄 Background task #1 started: "Analyze the logs in /var/log and summarize..."
   Task ID: bg_143022_a1b2c3

چگونه کار می‌کند

هر پرامپت /background یک نشست ایجنت کاملاً جدا در نخ دیمن تولید می‌کند:

  • گفتگوی ایزوله — ایجنت پس‌زمینه هیچ دانشی از تاریخچهٔ نشست فعلی شما ندارد. فقط پرامپتی که می‌دهید را دریافت می‌کند.
  • همان پیکربندی — ایجنت پس‌زمینه مدل، ارائه‌دهنده، تول‌ست‌ها، تنظیمات استدلال و مدل fallback شما را از نشست فعلی به ارث می‌برد.
  • غیرمسدودکننده — نشست پیش‌زمینه‌تان کاملاً تعاملی می‌ماند. می‌توانید چت کنید، فرمان اجرا کنید یا حتی کارهای پس‌زمینهٔ بیشتری شروع کنید.
  • چند کار — می‌توانید چند کار پس‌زمینه را هم‌زمان اجرا کنید. هر کدام شناسهٔ شماره‌دار خودش را می‌گیرد.

نتایج

وقتی کار پس‌زمینه تمام شد، نتیجه به‌صورت پنلی در ترمینال شما ظاهر می‌شود:

نمونه
╭─ ⚕ Hermes (background #1) ──────────────────────────────────╮
│ Found 3 errors in syslog from today:                         │
│ 1. OOM killer invoked at 03:22 — killed process nginx        │
│ 2. Disk I/O error on /dev/sda1 at 07:15                      │
│ 3. Failed SSH login attempts from 192.168.1.50 at 14:30      │
╰──────────────────────────────────────────────────────────────╯

اگر کار شکست بخورد، به‌جایش اعلان خطا می‌بینید. اگر display.bell_on_complete در پیکربندی‌تان فعال باشد، زنگ ترمینال با اتمام کار به صدا درمی‌آید.

موارد استفاده

  • پژوهش طولانی — «‏/background research the latest developments in quantum error correction» در حالی که روی کد کار می‌کنید
  • پردازش فایل — «‏/background analyze all Python files in this repo and list any security issues» در حالی که به گفتگو ادامه می‌دهید
  • تحقیقات موازی — چند کار پس‌زمینه را برای کاوش هم‌زمان زوایای مختلف شروع کنید
ℹ️ توجه

نشست‌های پس‌زمینه در تاریخچهٔ گفتگوی اصلی‌تان ظاهر نمی‌شوند. نشست‌های مستقلی با شناسهٔ کار خودشان‌اند (مثلاً bg_143022_a1b2c3).

  • بازخورد انیمیت‌شدهٔ سبک kawaii را فعال می‌کند
