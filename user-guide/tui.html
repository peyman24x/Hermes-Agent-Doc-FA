رابط ترمینال مدرن (TUI)

TUI فرانت‌اند مدرن هرمس است — یک رابط ترمینالی با همان زمان اجرای پایتونیِ CLI کلاسیک. همان ایجنت، همان نشست‌ها، همان فرمان‌های اسلش؛ یک سطح تمیزتر و پاسخ‌گوتر برای تعامل با آن‌ها.

این روش توصیه‌شده برای اجرای تعاملی هرمس است.

۱ اجرا

bash
# اجرای TUI
hermes --tui

# ازسرگیری آخرین نشست TUI (به آخرین نشست کلاسیک برمی‌گردد)
hermes --tui -c
hermes --tui --continue
hermes --tui --resume latest

# ازسرگیری نشستی مشخص با شناسه یا عنوان
hermes --tui -r 20260409_000000_aa11bb
hermes --tui --resume "my t0p session"

# ازسرگیری آخرین نشست برای پوشهٔ پروژهٔ مشخص
hermes --tui --resume latest --in ./my-project

# اجرای مستقیم سورس — مرحلهٔ prebuild را رد می‌کند (برای مشارکت‌کنندگان TUI)
hermes --tui --dev

همچنین می‌توانید با متغیر محیطی فعالش کنید:

bash
export HERMES_TUI=1
hermes          # حالا از TUI استفاده می‌کند
hermes chat     # همینطور

یا در ~/.hermes/config.yaml پیش‌فرض پایدارش کنید:

yaml
display:
  interface: tui   # "cli" (پیش‌فرض) یا "tui"

با display.interface: tui، یک hermes ساده (و hermes chat) ‏TUI را راه می‌اندازد. پرچم‌های صریح همیشه می‌برند — ‏hermes --cli را اجرا کنید تا برای یک بار به REPL کلاسیک برگردید، یا hermes --tui / ‏HERMES_TUI=1 وقتی پیش‌فرض پیکربندی cli است TUI را اجباری کنید.

CLI کلاسیک پیش‌فرضِ عرضه‌شده باقی می‌ماند. هر چیزی که در «رابط CLI» مستند شده — فرمان‌های اسلش، فرمان‌های سریع، پیش‌بارگذاری مهارت، شخصیت‌ها، ورودی چندخطی، وقفه‌ها — در TUI یکسان کار می‌کند.

۲ چرا TUI

  • اولین فریم آنی — بنر پیش از اتمام بارگذاری اپ رسم می‌شود، پس ترمینال هنگام شروع هرمس هرگز منجمد حس نمی‌شود.
  • ورودی غیرمسدودکننده — پیش از آماده‌شدن نشست تایپ کنید و پیام‌ها را صف کنید. اولین پرامپت شما لحظه‌ای که ایجنت آنلاین شد ارسال می‌شود.
  • اورلی‌های غنی — انتخاب‌گر مدل، انتخاب‌گر نشست، اعلان‌های تأیید و شفاف‌سازی همه به‌صورت پنل مودال رندر می‌شوند نه جریان‌های درون‌خطی.
  • پنل نشست زنده — ابزارها و مهارت‌ها هم‌زمان با مقداردهی اولیه تدریجاً پر می‌شوند.
  • انتخاب موس‌دوست — برای هایلایت بکشید با پس‌زمینهٔ یکدست به‌جای معکوس SGR. با حرکت کپی معمولی ترمینالتان کپی کنید.
  • رندر صفحهٔ جایگزین — به‌روزرسانی‌های دیفرانسیلی یعنی بدون سوسو هنگام استریم، بدون شلوغی اسکرول‌بک بعد از خروج.
  • تسهیلات کامپوزر — جمع‌شدنِ درجا برای قطعات بلند پیست‌شده، ‏چسباندن متن با Cmd+V / ‏Ctrl+V با جایگزینِ تصویر-کلیپ‌بورد، ایمنی bracketed-paste و نرمال‌سازی پیوستِ مسیر-فایل/تصویر.

همان پوسته‌ها و شخصیت‌ها اعمال می‌شوند. وسط نشست عوضشان کنید با /skin ares، ‏/personality pirate، و UI زنده دوباره رنگ می‌شود.

بخش‌های تاشوی بنر

بنر شروع TUI اطلاعات اجرا را در چهار بخش تاشو گروه می‌کند، هر کدام با شورون ▸ / ‏▾ کنار عنوان بخش:

بخشوضعیت پیش‌فرض
ابزارهاباز
مهارت‌هاجمع‌شده
پرامپت سیستمیجمع‌شده
سرورهای MCPجمع‌شده

روی هر جای سرصفحهٔ بخش (یا شورونش) کلیک کنید تا تغییر کند. فهرست ابزارها به‌طور پیش‌فرض باز است چون پرمراجعه‌ترین بخش در شروع نشست است؛ مهارت‌ها، پرامپت سیستمی و سرورهای MCP به‌طور پیش‌فرض جمع می‌شوند تا بنر حتی وقتی ده‌ها مهارت نصب کرده‌اید یا سرورهای MCP زیادی وصل کرده‌اید فشرده بماند. وضعیت محلیِ همین نمونهٔ بنر است، پس اجرای بعدی به پیش‌فرض‌ها برمی‌گردد.

۳ نیازمندی‌ها

  • Node.js ≥ نسخهٔ ۲۰ — ‏TUI به‌صورت زیرپروسه‌ای که از CLI پایتونی راه‌اندازی شده اجرا می‌شود. hermes doctor این را تأیید می‌کند.
  • TTY — مثل CLI کلاسیک، پایپ‌کردن stdin یا اجرای در محیط‌های غیرتعاملی به حالت تک-کوئری برمی‌گردد.

در اولین اجرا هرمس وابستگی‌های Node مربوط به TUI را در ui-tui/node_modules نصب می‌کند (یک‌باره، چند ثانیه). اجراهای بعدی سریع‌ند. اگر نسخهٔ جدیدی از هرمس بکشید، باندل TUI وقتی سورس‌ها جدیدتر از dist باشند خودکار دوباره بیلد می‌شود.

💡 روی ورک‌تری‌های گیت کار می‌کنید؟

مشارکت‌کنندگانی که hermes --tui --dev را از چند ورک‌تری اجرا می‌کنند می‌توانند به‌جای نصب به‌ازای-چک‌اوت، یک node_modules مشترک داشته باشند — به «TUI و دسکتاپ از Worktreeها» مراجعه کنید.

پربیلد بیرونی

توزیع‌هایی که باندل از-پیش-ساخته عرضه می‌کنند (‏Nix، پکیج‌های سیستمی) می‌توانند هرمس را به آن اشاره دهند:

bash
export HERMES_TUI_DIR=/path/to/prebuilt/ui-tui
hermes --tui

پوشه باید dist/entry.js داشته باشد.

۴ کلیدهای میان‌بر

میان‌برها دقیقاً مطابق CLI کلاسیک هستند. تنها تفاوت‌های رفتاری:

  • کشیدن با موس متن را با پس‌زمینهٔ انتخابِ یکدست هایلایت می‌کند.
  • Cmd+V / ‏Ctrl+V اول چسباندن متنی عادی را امتحان می‌کند، بعد به خواندن‌های OSC52/کلیپ‌بورد بومی برمی‌گردد، و در نهایت وقتی کلیپ‌بورد یا محتوای پیست‌شده به تصویر حل شود، پیوست تصویر.
  • /terminal-setup اتصالات ترمینال محلی VS Code / ‏Cursor / ‏Windsurf را برای Cmd+Enter بهتر و هم‌ارزی undo/redo در مک نصب می‌کند.
  • تکمیل‌خودکار اسلش به‌صورت پنل شناور با توضیحات باز می‌شود، نه دراپ‌داون درون‌خطی.
  • Ctrl+X سوییچر نشست زنده را باز می‌کند. وقتی پیامِ صف‌شده‌ای هایلایت است (ارسال‌شده حین اجرای ایجنت)، به‌جایش همان پیام صف‌شده را حذف می‌کند. Esc ویرایش را لغو و هایلایت را برمی‌دارد بدون حذف.
  • Ctrl+G / ‏Ctrl+X Ctrl+E — بافر ورودی فعلی را در $EDITOR باز می‌کنند برای نگارش چندخطی/پرامپت‌های بلند؛ ذخیره-و-خروج محتوا را به‌عنوان پرامپت پس می‌فرستد.

۵ فرمان‌های اسلش

همهٔ فرمان‌های اسلش بدون تغییر کار می‌کنند. چند تا متعلق به TUI‌اند — خروجی غنی‌تری تولید می‌کنند یا به‌صورت اورلی رندر می‌شوند:

فرمانرفتار TUI
/helpاورلی با فرمان‌های دسته‌بندی‌شده، قابل ناوبری با کلیدهای جهت
/sessions (نام‌مستقل /switch)سوییچر نشست زنده — فهرست نشست‌های باز TUI، جابه‌جایی بینشان، بستنشان یا شروع یکی دیگر
/modelانتخاب‌گر مودالِ مدلِ گروه‌بندی‌شده بر اساس ارائه‌دهنده، با اشاره‌های هزینه
/skinپیش‌نمایش زنده — تغییر تم هم‌زمان با مرور اعمال می‌شود
/detailsتغییر حالت جزئیات فراخوانی ابزار (سراسری یا به‌ازای-بخش)
/usageپنل غنی توکن / هزینه / زمینه
/agents (نام‌مستقل /tasks)اورلی مشاهده‌پذیری — درخت زندهٔ ساب‌ایجنت با کنترل‌های کشتن/توقف، جمع‌های هزینه/توکن/فایل به‌ازای-شاخه، تاریخچهٔ نوبت‌به‌نوبت
/reload~/.hermes/.env را در پروسهٔ در حال اجرای TUI دوباره می‌خواند تا کلیدهای API تازه‌اضافه‌شده بدون ری‌استارت اثر کنند
/mouse [on|off|toggle|wheel|buttons|all]انتخاب یک پیش‌تنظیم ردیابی موس در زمان اجرا (همچنین در display.mouse_tracking در config.yaml ماندگار می‌شود). wheel ‏(1000+1006) اسکرول با چرخ را بدون رویدادهای hover نگه می‌دارد — همان‌هایی که در tmux باعث اسپمِ «No image in clipboard» روی سطر پرامپت می‌شوند؛ ‏buttons کشیدن-برای-انتخاب را اضافه می‌کند؛ ‏all پیش‌فرض با UI مبتنی-بر-hover.

هر فرمان اسلش دیگر (شامل مهارت‌های نصب‌شده، فرمان‌های سریع و سوییچ‌های شخصیت) دقیقاً مثل CLI کلاسیک کار می‌کند. به «مرجع فرمان‌های اسلش» مراجعه کنید.

۶ سوییچر نشست زنده

وقتی می‌خواهید یک ترمینال نقش دیسپچرِ چند نشست TUI را بازی کند از سوییچر نشست زنده استفاده کنید. فقط نشست‌هایی که الان در همین پروسهٔ TUI زنده‌اند را فهرست می‌کند؛ نشست‌های بسته رونوشت‌های ذخیره‌شده باقی می‌مانند و همچنان با /resume یا hermes --tui --resume <id-or-title> بازگشتنی‌اند.

با هر کدام از این‌ها بازش کنید:

  • Ctrl+X از داخل TUI.
  • /sessions یا /switch.
  • /sessions new برای ساخت فوری نشست زندهٔ تازه.
  • کلیک روی شمارندهٔ N live sessions در خط وضعیت.

داخل سوییچر:

  • ↑ / ‏↓ جابه‌جایی انتخاب؛ کلیک موس هم سطرها را انتخاب می‌کند.
  • Enter به نشست زندهٔ انتخاب‌شده سوییچ می‌کند.
  • Ctrl+D نشست زندهٔ انتخاب‌شده را می‌بندد.
  • Ctrl+N یک نشست زندهٔ خالی شروع می‌کند.
  • Ctrl+R فهرست نشست‌های زنده را نوسازی می‌کند.
  • Esc سوییچر را می‌بندد.
  • +new را انتخاب کنید، پرامپتی تایپ و Enter بزنید تا نشست زندهٔ جدیدی اعزام شود. اول Tab را بزنید اگر می‌خواهید فقط برای همان نشست جدید مدلی انتخاب کنید.

۷ رندر ریاضی LaTeX

خط لولهٔ مارک‌داون TUI ریاضی LaTeX را درون‌خطی رندر می‌کند: $E = mc^2$ و $$\frac{a}{b}$$ به‌جای سورس خام TeX به‌صورت ریاضیِ قالب‌بندی‌شده-با-یونیکد نمایش می‌یابند. برای ریاضی درون‌خطی و بلوکی کار می‌کند؛ نگارش پشتیبانی‌نشده به نمایش تحت‌اللفظی TeX در یک code span برمی‌گردد تا قابل‌کپی بماند.

این همیشه-روشن است — چیزی برای پیکربندی نیست. CLI کلاسیک TeX خام را نگه می‌دارد.

۸ تشخیص ترمینال روشن

TUI ترمینال‌های روشن را خودکار تشخیص و متناسب به تم روشن سوییچ می‌کند. تشخیص در سه لایه کار می‌کند:

  1. متغیر محیطی HERMES_TUI_THEME — بالاترین اولویت. مقادیر: light، ‏dark، یا هگز ۶ کاراکتری خام پس‌زمینه (مثلاً ffffff، ‏1a1a2e).
  2. متغیر محیطی COLORFGBG — اشارهٔ کلاسیکِ «رنگ پس‌زمینه‌ام چیست؟» که ترمینال‌های مشتق-از-xterm استفاده می‌کنند.
  3. کاو زیرزمینهٔ ترمینال با OSC 11 — روی ترمینال‌های مدرن‏ (Ghostty، ‏Warp، ‏iTerm2، ‏WezTerm، ‏Kitty) که COLORFGBG را نمی‌گذارند کار می‌کند.

اگر تم روشن را صرف‌نظر از ترمینال همیشگی می‌خواهید:

bash
export HERMES_TUI_THEME=light

۹ سبک‌های نشانگر مشغولیت

نشانگر مشغولیت نوار وضعیت افزونه‌پذیر است — پیش‌فرض هر ۲.۵ ثانیه در حین کار ایجنت از پالت چهره‌های کاوایی هرمس می‌چرخد. سبک دیگری را با پیکربندی یا فرمان اسلش /indicator بردارید:

yaml
display:
  tui_status_indicator: kaomoji   # kaomoji | emoji | unicode | ascii

یا در نشست: /indicator emoji (و غیره). سبک‌ها با عرض‌های گلیف منطبق عرضه می‌شوند تا باقی نوار وضعیت هنگام چرخش نلرزد.

۱۰ ازسرگیری خودکار

به‌طور پیش‌فرض hermes --tui در هر اجرا نشست تازه‌ای شروع می‌کند. برای اتصال مجدد خودکار به جدیدترین نشست TUI‏ (مفید وقتی ترمینال یا اتصال SSH‌تان غیرمنتظره قطع می‌شود)، فعالش کنید:

bash
export HERMES_TUI_RESUME=1          # جدیدترین نشست TUI
# یا:
export HERMES_TUI_RESUME=<session-id>   # نشست مشخص

برای ابطال به‌ازای-اجرا، متغیر را حذف یا --resume <id> را صریح بدهید.

۱۱ خط وضعیت

خط وضعیت TUI وضعیت ایجنت را در زمان واقعی دنبال می‌کند:

پس از نام‌گذاری نشست، عنوانش به‌صورت نشانِ رنگ-تأکیدی در لبهٔ دور سطر وضعیت ظاهر می‌شود. عنوان جای برچسب ورک‌اسپیس را می‌گیرد و روی ترمینال‌های باریک بریده می‌شود.

وضعیتمعنا
starting agent…شناسهٔ نشست زنده است؛ ابزارها و مهارت‌ها هنوز در حال آنلاین‌شدن‌اند. می‌توانید تایپ کنید — پیام‌ها صف می‌شوند و وقتی آماده شد ارسال.
readyایجنت بیکار است و ورودی می‌پذیرد.
thinking… / running…ایجنت در حال استدلال یا اجرای ابزار است.
interruptedنوبت فعلی لغو شد؛ برای ارسال مجدد Enter بزنید.
forging session… / resuming…اتصال اولیه یا دست‌دادنِ --resume.

رنگ‌ها و آستانه‌های نوار وضعیت به‌ازای-پوسته با CLI کلاسیک مشترک‌اند — برای سفارشی‌سازی به «پوسته‌ها» مراجعه کنید.

خط وضعیت همچنین نشان می‌دهد:

  • پوشهٔ کاری با شاخهٔ گیت — ‏~/projects/hermes-agent (docs/two-week-gap-sweep). پسوند شاخه وقتی در ترمینال کناری git checkout بزنید نوسازی می‌شود (کش mtime) تا TUI شاخهٔ فعالِ واقعی‌تان را بازتاب دهد نه چیزی که هنگام اجرا بود.
  • زمان سپری‌شده به‌ازای-پرامپت — ‏⏱ 12s/3m 45s حین اجرای نوبت (زنده)، بعد از اتمام نوبت منجمد به ⏲ 32s / 3m 45s. عدد اول زمان از آخرین پیام کاربر است؛ دومی کل مدت نشست. با هر پرامپت جدید ریست می‌شود.
  • 🗜️ N — تعداد دفعات فشرده‌سازی خودکار نشستِ در حال اجرا. با اولین فشرده‌سازی ظاهر می‌شود.
  • ▶ N — تعداد کارهای /backgroundِ در حال اجرا در این نشست. هر وقت حداقل یک کار در پرواز باشد ظاهر می‌شود.
  • ⚠ YOLO — هشدار دیدنی هر وقت حالت YOLO روشن است‏ (hermes --yolo، ‏/yolo یا HERMES_YOLO_MODE=1). همان نشان در بنر شروع هم ظاهر می‌شود تا نتوانید نشستِ خودتأیید را بدون توجه اجرا کنید.

۱۲ پیکربندی

TUI به همهٔ پیکربندی استاندارد هرمس احترام می‌گذارد: ~/.hermes/config.yaml، پروفایل‌ها، شخصیت‌ها، پوسته‌ها، فرمان‌های سریع، استخرهای اعتبارنامه، ارائه‌دهندگان حافظه، فعال‌سازی ابزار/مهارت. هیچ فایل پیکربندی مخصوص TUI وجود ندارد.

مشتی کلید مخصوصاً سطح TUI را تنظیم می‌کنند:

yaml
display:
  skin: default              # هر پوستهٔ داخلی یا سفارشی
  personality: helpful
  details_mode: collapsed    # hidden | collapsed | expanded — پیش‌فرض سراسری آکاردئون
  sections:                  # اختیاری: بازنویسی به‌ازای-بخش (هر زیرمجموعه)
    thinking: expanded       # همیشه باز
    tools: expanded          # همیشه باز
    activity: collapsed      # بازگرداندن پنل فعالیت (پیش‌فرض مخفی)
  mouse_tracking: all        # off | wheel | buttons | all (یا true/false برای سازگاری).
                             #   wheel   — 1000+1006 (اسکرول + کلیک؛ بدون درگ، بدون hover —
                             #             داخل tmux توصیه می‌شود تا اسپم «No image in
                             #             clipboard» سطر پرامپت از رویدادهای hover ساکت شود)
                             #   buttons — 1002 را برای انتخاب-کشیدی سمت ترمینال اضافه می‌کند
                             #   all     — 1003 را برای hover اضافه می‌کند (صفحه‌بندی-اسکرول‌بار
                             #             هنگام hover، mouseenter لینک و غیره)

کلیدهای زمان اجرا:

  • /details [hidden|collapsed|expanded|cycle] — تنظیم حالت سراسری
  • /details <section> [hidden|collapsed|expanded|reset] — بازنویسی یک بخش (بخش‌ها: thinking، ‏tools، ‏subagents، ‏activity)

دیدبانی پیش‌فرض

TUI با پیش‌فرض‌های نظرمحورِ به‌ازای-بخش عرضه می‌شود که نوبت را به‌جای دیواری از شورون به‌صورت رونوشت زنده استریم می‌کنند:

  • thinking — باز. استدلال هم‌زمان با انتشار مدل درون‌خطی استریم می‌شود.
  • tools — باز. فراخوانی‌های ابزار و نتایجشان باز رندر می‌شوند.
  • subagents — به details_mode سراسری سقوط می‌کند (پیش‌فرض زیر شورون جمع — تا وقتی واگذاری واقعاً اتفاق بیفتد ساکت می‌ماند).
  • activity — مخفی. فرادادهٔ محیطی (راهنماهای گیت‌وی، یادآورهای هم‌ارزی ترمینال، اعلان‌های پس‌زمینه) برای اغلب استفادهٔ روزمره نویز است. شکست‌های ابزار همچنان درون‌خطی روی سطر ابزارِ شکست‌خورده رندر می‌شوند؛ خطا/هشدارهای محیطی از طریق پشتیبان هشدار-شناور وقتی هر پنل مخفی است ظاهر می‌شوند.

بازنویسی‌های به‌ازای-بخش بر هم پیش‌فرض بخش و هم details_mode سراسری مقدم‌اند. برای بازآرایی چیدمان:

  • display.sections.thinking: collapsed — برگرداندن thinking زیر شورون
  • display.sections.tools: collapsed — برگرداندن فراخوانی ابزار زیر شورون
  • display.sections.activity: collapsed — بازگرداندن پنل فعالیت
  • /details <section> <mode> در زمان اجرا

هر چیزی که صریحاً در display.sections تنظیم شود بر پیش‌فرض‌ها مقدم است، پس پیکربندی‌های موجود بدون تغییر کار می‌کنند.

۱۳ نشست‌ها

نشست‌ها بین TUI و CLI کلاسیک مشترک‌اند — هر دو به همان ~/.hermes/state.db می‌نویسند. می‌توانید نشست را در یکی شروع و در دیگری ازسر بگیرید. انتخاب‌گر نشست، نشست‌های هر دو منبع را با برچسب منشأ ظاهر می‌کند.

برای چرخهٔ حیات، جستجو، فشرده‌سازی و صادرات به «نشست‌ها» مراجعه کنید.

۱۴ TUI چگونه با گیت‌وی خودش حرف می‌زند

به‌طور پیش‌فرض TUI گیت‌وی درون-پروسهٔ خودش را تولید می‌کند، پس هر نمونهٔ TUI خودبسنده است — چیزی برای پیکربندی نیست.

ممکن است متغیر محیطی HERMES_TUI_GATEWAY_URL را در کدبیس یا لاگ‌ها ببینید. این یک جزئیات سیم‌کشی داخلیِ داشبورد وب است، نه یک پیچ اتصال-راهنِ رو-به-کاربر. وقتی تب «Chat» داشبورد را باز می‌کنید‏ (hermes dashboard ← ‏/chat)، وب‌سرور داشبورد یک پروسهٔ فرزند TUIِ جاسازی‌شده تولید و HERMES_TUI_GATEWAY_URL را تزریق می‌کند تا آن فرزند به tui_gateway درون-پروسهٔ خود داشبورد روی یک WebSocket لوپ‌بک‏ (/api/ws) وصل شود. اندپوینت /api/ws فقط داخل سرور داشبورد‏ (hermes_cli/web_server.py) وجود دارد و به عمر پروسه و احراز همان فرآیند بسته است.

حالت عمومیِ «اشارهٔ هر TUI به هر پورت گیت‌وی مستقلی» وجود ندارد. به‌طور خاص، سرور API سازگار با OpenAI‏ (hermes gateway / پلتفرم api_server) ‏/api/ws سرو نمی‌کند — سطح بک‌اند-مدل است‏ (/v1/chat/completions، ‏/v1/models، …) و عمداً کانال کنترل JSON-RPC مربوط به TUI را عرضه نمی‌کند. تنظیم HERMES_TUI_GATEWAY_URL روی آن پورت ۴۰۴ می‌گیرد.

اگر می‌خواهید چند سطح یک مجموعه نشست را به اشتراک بگذارند، از ~/.hermes/state.db مشترک استفاده کنید (به «نشست‌ها») یا چت جاسازی‌شدهٔ داشبورد وب — نه یک URL گیت‌وی دست‌کار.

۱۵ بازگشت به CLI کلاسیک

اجرای hermes (بدون --tui) به‌طور پیش‌فرض روی CLI کلاسیک می‌ماند. برای اینکه ماشینی TUI را ترجیح دهد، display.interface: tui را در ~/.hermes/config.yaml بگذارید (پایدار) یا HERMES_TUI=1 در پروفایل شل (به‌ازای-شل). برای برگشتن، interface: cli / حذف متغیر، یا برای یک‌بار hermes --cli.

اگر TUI اجرا نشود (نبود Node، باندل مفقود، مشکل TTY)، هرمس یک تشخیص چاپ و بازمی‌گردد — به‌جای اینکه گیرتان بیندازد.
