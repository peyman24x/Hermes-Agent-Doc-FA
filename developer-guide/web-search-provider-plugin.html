پلاگین جستجوی وب

پلاگین‌های ارائه‌دهندهٔ جستجوی وب، بک‌اندی ثبت می‌کنند که فراخوانی‌های ابزارهای web_search، web_extract و (به‌صورت اختیاری) خزش عمیق را پاسخ می‌دهد. ارائه‌دهندگان داخلی — Firecrawl، SearXNG، Tavily، Perplexity، Exa، Parallel، Keenable، Brave Search (ردهٔ رایگان)، xAI و DDGS — همگی به‌صورت پلاگین در plugins/web/<name>/ عرضه می‌شوند. با قراردادن یک پوشه در کنار آن‌ها می‌توانید ارائه‌دهندهٔ جدیدی اضافه کنید یا یکی از ارائه‌دهندگان همراه برنامه را جایگزین کنید.

💡 نکته

جستجوی وب یکی از چند نوع پلاگین بک‌اند است که هرمس پشتیبانی می‌کند. انواع دیگر (با کلاس‌های پایهٔ انتزاعی مخصوص خود) عبارت‌اند از پلاگین‌های ارائه‌دهندهٔ تولید تصویر، پلاگین‌های ارائه‌دهندهٔ تولید ویدیو، پلاگین‌های ارائه‌دهندهٔ حافظه، پلاگین‌های موتور زمینه و پلاگین‌های ارائه‌دهندهٔ مدل. پلاگین‌های عمومی ابزار/هوک/CLI در ساخت پلاگین هرمس پوشش داده شده‌اند.

۱ سازوکار کشف

هرمس در سه محل به‌دنبال بک‌اندهای جستجوی وب می‌گردد:

  1. همراه برنامه — <repo>/plugins/web/<name>/ (بارگذاری خودکار با kind: backend، همیشه در دسترس)
  2. کاربر — ~/.hermes/plugins/web/<name>/ (فعال‌سازی اختیاری از طریق plugins.enabled یا hermes plugins enable <name>)
  3. Pip — بسته‌هایی که یک نقطهٔ ورود hermes_agent.plugins اعلام می‌کنند

تابع register(ctx) هر پلاگین، ctx.register_web_search_provider(...) را فراخوانی می‌کند — این کار نمونه را در رجیستریِ agent/web_search_registry.py قرار می‌دهد. ارائه‌دهندهٔ فعال هر قابلیت از طریق پیکربندی انتخاب می‌شود:

قابلیتکلید پیکربندیگزینهٔ پشتیبان
web_searchweb.search_backendweb.backend
web_extractweb.extract_backendweb.backend
حالت‌های خزش عمیق درون web_extractweb.extract_backendweb.backend

وقتی هیچ‌یک از دو کلید تنظیم نشده باشد، هرمس بک‌اند را از روی کلید API یا نشانی اینترنتی موجود در محیط به‌طور خودکار تشخیص می‌دهد. hermes tools کاربران را در فرایند انتخاب راهنمایی می‌کند.

۲ ساختار پوشه

plugins/web/my-backend/
├── __init__.py     # register() entry point
├── provider.py     # WebSearchProvider subclass
└── plugin.yaml     # Manifest with kind: backend and provides_web_providers

brave_free/ و ddgs/ کوچک‌ترین نمونه‌های مرجع در درخت کد هستند — brave_free برای ارائه‌دهنده‌ای صرفاً جستجوگر که دسترسی به آن نیازمند کلید API است، و ddgs برای ارائه‌دهنده‌ای بدون کلید که SDK خود را هنگام نیاز نصب می‌کند.

۳ کلاس پایهٔ انتزاعی WebSearchProvider

از agent.web_search_provider.WebSearchProvider زیرکلاس بسازید. تنها اعضای الزامی name، is_available() و هرکدام از search() / extract() هستند که پیاده‌سازی می‌کنید. (خزش عمیق متد جداگانه‌ای نیست — یکی از حالت‌های extract() است.)

# plugins/web/my-backend/provider.py
from __future__ import annotations

import os
from typing import Any, Dict, List

from agent.web_search_provider import WebSearchProvider


class MyBackendWebSearchProvider(WebSearchProvider):
    """Minimal search-only provider against the My Backend HTTP API."""

    @property
    def name(self) -> str:
        # Stable id used in web.search_backend / web.extract_backend / web.backend
        # config keys. Lowercase, no spaces; hyphens permitted.
        return "my-backend"

    @property
    def display_name(self) -> str:
        # Human label shown in `hermes tools`. Defaults to `name`.
        return "My Backend"

    def is_available(self) -> bool:
        # Cheap check — env var present, optional dep importable, etc.
        # MUST NOT make network calls (runs on every `hermes tools` paint).
        return bool(os.getenv("MY_BACKEND_API_KEY", "").strip())

    def supports_search(self) -> bool:
        return True

    def supports_extract(self) -> bool:
        return False

    def search(self, query: str, limit: int = 5) -> Dict[str, Any]:
        import httpx

        api_key = os.environ["MY_BACKEND_API_KEY"]
        try:
            resp = httpx.get(
                "https://api.example.com/search",
                params={"q": query, "count": max(1, min(int(limit), 20))},
                headers={"Authorization": f"Bearer {api_key}"},
                timeout=15,
            )
            resp.raise_for_status()
            data = resp.json()
        except httpx.HTTPError as exc:
            return {"success": False, "error": str(exc)}

        # Response shape is fixed — see "Response shape" below.
        return {
            "success": True,
            "data": {
                "web": [
                    {
                        "title": item.get("title", ""),
                        "url": item.get("url", ""),
                        "description": item.get("snippet", ""),
                        "position": idx + 1,
                    }
                    for idx, item in enumerate(data.get("results", []))
                ],
            },
        }

# plugins/web/my-backend/__init__.py
from plugins.web.my_backend.provider import MyBackendWebSearchProvider


def register(ctx) -> None:
    """Plugin entry point — called once at load time."""
    ctx.register_web_search_provider(MyBackendWebSearchProvider())

۵ مرجع کلاس پایهٔ انتزاعی

قرارداد کامل در agent/web_search_provider.py است. متدهایی که می‌توانید بازنویسی کنید:

عضوالزامیپیش‌فرضهدف

ارائه‌دهندگان می‌توانند چند قابلیت را از یک کلاس واحد اعلام کنند — Firecrawl، Tavily، Perplexity، Keenable، Exa و Parallel همگی جستجو و استخراج را پیاده‌سازی می‌کنند. Brave Search و DDGS صرفاً جستجوگرند؛ SearXNG نیز صرفاً جستجوگر است و روند کاریِ مستندی برای «استفاده از آن در کنار یک ارائه‌دهندهٔ استخراج» دارد.

۶ ساختار پاسخ

لایهٔ پوشانندهٔ ابزار، قالب بیرونی ثابتی انتظار دارد تا نیازی به تبدیل قالب پاسخ بک‌اندهای مختلف نداشته باشد.

موفقیت جستجو:

{
    "success": True,
    "data": {
        "web": [
            {"title": str, "url": str, "description": str, "position": int},
            ...
        ],
    },
}

موفقیت استخراج:

{
    "success": True,
    "data": [
        {
            "url": str,
            "title": str,
            "content": str,
            "raw_content": str,
            "metadata": dict,    # optional
            "error": str,        # optional, only on per-URL failure
        },
        ...
    ],
}

در صورت شکست هر یک از دو قابلیت:

{"success": False, "error": "human-readable message"}

هر دو متد search() و extract() می‌توانند async def باشند — توزیع‌کننده، توابع کوروتین را با inspect.iscoroutinefunction تشخیص می‌دهد و بر همان اساس منتظر نتیجه می‌ماند. پیاده‌سازی‌های همگام که ورودی/خروجی مسدودکننده انجام می‌دهند (HTTP، فراخوانی‌های SDK)، برای بک‌اندهای کوچک مناسب‌اند؛ توزیع‌کننده مدیریت تردها را بر عهده می‌گیرد.

۷ پرچم‌های قابلیت

هرمس بر اساس پرچم‌های supports_*، فراخوانی‌ها را به ارائه‌دهندهٔ مناسب هدایت می‌کند. یک پیکربندی رایج با چند ارائه‌دهنده:

# ~/.hermes/config.yaml
web:
  search_backend: "brave-free"     # search-only, fast, free 2k/mo
  extract_backend: "firecrawl"     # extract + crawl, paid quota

وقتی web.search_backend یا web.extract_backend تنظیم نشده باشند، هر دو به web.backend رجوع می‌کنند. وقتی آن هم تنظیم نشده باشد، هرمس بر اساس وجود متغیر محیطی، نخستین ارائه‌دهندهٔ در دسترس را که قابلیت درخواستی را پشتیبانی کند انتخاب می‌کند.

اگر ارائه‌دهندهٔ شما فقط یک قابلیت را پشتیبانی می‌کند، پرچم‌های دیگر را در مقدار پیش‌فرضشان (False) نگه دارید تا رجیستری آن را برای آن ابزار کنار بگذارد — وقتی کاربران از X فقط برای جستجو استفاده می‌کنند و از ایجنت درخواست استخراج دارند، خطاهای گمراه‌کنندهٔ «ارائه‌دهندهٔ X شکست خورد» نمی‌بینند.

۸ هرمس چگونه آن را به ابزارها متصل می‌کند

ابزارهای web_search و web_extract در tools/web_tools.py قرار دارند. هنگام فراخوانی، این مراحل را انجام می‌دهند:

  1. کلید پیکربندی مربوط را می‌خوانند (web.search_backend برای web_search، web.extract_backend برای web_extract)
  2. ارائه‌دهنده‌ای با آن name را از رجیستری درخواست می‌کنند
  3. is_available() و پرچم supports_*() متناظر را بررسی می‌کنند
  4. اجرا را به search() / extract() می‌سپارند (خزش عمیق به‌عنوان یک حالت درون extract() اجرا می‌شود) و اگر متد کوروتین باشد، منتظر نتیجه می‌مانند
  5. پاسخ را با قالب بیرونی‌اش به JSON سریال‌سازی می‌کنند و به LLM برمی‌گردانند

خطاها به‌عنوان نتیجهٔ ابزار ارائه می‌شوند؛ LLM تصمیم می‌گیرد چگونه آن‌ها را توضیح دهد. اگر هیچ ارائه‌دهنده‌ای ثبت نشده باشد (یا هیچ‌یک از ارائه‌دهندگان در دسترس از بررسی قابلیت عبور نکند)، ابزار خطای راهنمایی‌کننده‌ای برمی‌گرداند که به hermes tools اشاره دارد.

۹ نصب وابستگی‌های اختیاری هنگام نیاز

اگر ارائه‌دهندهٔ شما یک SDK شخص ثالث را پوشش می‌دهد (مانند DDGS با بستهٔ ddgs)، آن را در سطح بالای ماژول import نکنید. درون is_available() یا search() از tools.lazy_deps.ensure(...) استفاده کنید — هرمس در نخستین استفاده، بسته را با توجه به مجوز security.allow_lazy_installs نصب می‌کند. برای مدل امنیتی، ساخت پلاگین هرمس ← نصب هنگام نیاز را ببینید.

۱۰ پیاده‌سازی‌های مرجع

  • plugins/web/brave_free/ — ارائه‌دهندهٔ HTTP کوچک و صرفاً جستجوگر که دسترسی به آن نیازمند کلید API است. قالب شروع خوبی است.
  • plugins/web/ddgs/ — ارائه‌دهندهٔ بدون کلید که SDK خود را هنگام نیاز نصب می‌کند. الگویی مفید برای بک‌اندهایی که یک بستهٔ پایتون را پوشش می‌دهند.
  • plugins/web/firecrawl/ — ارائه‌دهندهٔ کامل با چند قابلیت (جستجو + استخراج + خزش) و چند حالت قالب خروجی.
  • plugins/web/searxng/ — بک‌اند خودمیزبان، پیکربندی‌شده با نشانی اینترنتی و بدون احراز هویت.
  • plugins/web/xai/ — جستجوی متکی به LLM از طریق ابزار سمت سرور web_search در Grok. نشان می‌دهد چگونه بدون افزودن متغیرهای محیطی جدید، از سازوکار موجود اعتبارنامه‌های OAuth/متغیر محیطی (tools/xai_http.py) دوباره استفاده کنید، و چگونه یک is_available() کم‌هزینه بنویسید که قرارداد عدم استفاده از شبکه را رعایت کند.

۱۱ توزیع از طریق pip

# pyproject.toml
[project.entry-points."hermes_agent.plugins"]
my-backend-web = "my_backend_web_package"

my_backend_web_package باید یک تابع register در سطح بالا ارائه کند. برای راه‌اندازی کامل، توزیع از طریق pip در راهنمای عمومی پلاگین را ببینید.
