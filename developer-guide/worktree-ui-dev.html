توسعهٔ TUI و دسکتاپ در Worktree

هستهٔ پایتون از هر گیت‌ورک‌تری بی‌دردسر اجرا می‌شود — کافی است cd کنید و hermes همین‌طور کار می‌کند. اما دو سطح TypeScript این‌طور نیستند: ui-tui/ و apps/desktop/ هرکدام به node_modules پرشده نیاز دارند و یک npm ci تازه به‌ازای هر ورک‌تری، هم کند است و هم برای هر شاخه‌ای که چک‌اوت کرده‌اید گیگابایت‌ها تکرار می‌سازد.

‏htui و hgui دو هلپر شل هستند که همین شکاف را می‌بندند. هرکدام سطحِ مربوطه را از ورک‌تری فعلی اجرا می‌کنند ولی node_modules را از یک چک‌اوت مرجع قرض می‌گیرند — تا یک شاخهٔ یک‌بارمصرف به‌جای نصب، فقط یک سیم‌لینک هزینه داشته باشد.

این‌ها ابزارهای راحتیِ توسعه‌دهنده‌اند، نه فرمان‌های ارسالی با محصول. آن‌ها را در ~/.zshrc بگذارید و مسیرها را به سلیقهٔ خودتان تنظیم کنید.

۱ مدل مشترک‌سازی وابستگی‌ها

یک چک‌اوت، چک‌اوت وابستگی‌ها است — تنها جایی که واقعاً npm install اجرا می‌کنید. هر ورک‌تری دیگر به آن لینک می‌شود و فقط وقتی لاک‌فایلش واگرا شد محلی نصب می‌کند (شاخه‌ای که یک وابستگی را ارتقا داده نباید بی‌سروصدا روی پکیج‌های قدیمی اجرا شود).

flowchart TD
    A[htui / hgui in a worktree] --> B{package-lock.json<br/>matches deps checkout?}
    B -- yes --> C[symlink node_modules<br/>from deps checkout]
    B -- no --> D[local npm ci<br/>in this worktree]
    C --> E[launch surface]
    D --> E

دو متغیر محیطی چک‌اوت مرجع را نام‌گذاری می‌کنند:

متغیرمعنا
HERMES_MAIN_CHECKOUTچک‌اوت وابستگی‌ها — جایی که node_modules واقعاً زندگی می‌کند و .venv/bin/python آن بک‌اند را اجرا می‌کند.
HERMES_GUI_DEPS_CHECKOUTجای وابستگی‌های دسکتاپ (apps/desktop/node_modules). پیش‌فرضش HERMES_MAIN_CHECKOUT است؛ فقط اگر وابستگی‌های دسکتاپ را جای دیگری نگه می‌دارید بازنویسیش کنید.

هیچ‌کدام توسط خود هرمس خوانده نمی‌شوند — مخصوص همین هلپرها هستند. متغیرهایی که هرمس واقعاً می‌خواند در متغیرهای محیطی پوشش داده شده‌اند.

۲ ‏htui — اجرای TUI از ورک‌تری

‏TUI مبتنی بر Ink از قبل مسیر توسعه دارد: hermes --tui --dev به‌جای باندلِ ازپیش‌ساخته، سورس‌های TypeScript را با tsx اجرا می‌کند. htui یک خطِ راحت روی همین است که اجرا را به ui-tui/ ورک‌تری فعلی هم اشاره می‌دهد:

htui() {
  local root
  root="$(_hermes_root)" || { echo "htui: not in a Hermes checkout" >&2; return 1; }
  ( cd "$root" && PYTHONPATH="$root" \
      "$HERMES_MAIN_CHECKOUT/.venv/bin/python" -m hermes_cli.main --tui --dev "$@" )
}

‏--dev از سورس کامپایل می‌کند، پس وقتی لاک‌فایلِ ریشه بخواند ui-tui/node_modules را از HERMES_MAIN_CHECKOUT لینک می‌کند و در غیر این صورت محلی نصب می‌کند (بخش هلپرهای _hermes_root و لینک‌سازی را ببینید).

⚠️ ‏--dev و HERMES_TUI_DIR با هم جمع نمی‌شوند

‏HERMES_TUI_DIR هرمس را به یک باندلِ ازپیش‌ساخته اشاره می‌دهد (Nix، پکیج‌های سیستمی) که سورسی برای hot-reload ندارد. اگر در شل‌تان ست باشد، hermes --tui --dev با خطا خارج می‌شود. قبل از htui دستور unset HERMES_TUI_DIR را اجرا کنید.

۳ ‏hgui — اپلیکیشن دسکتاپ از ورک‌تری

اپلیکیشن دسکتاپ سنگین‌تر است: به node_modules هم در ریشهٔ مخزن و هم در apps/desktop/ نیاز دارد، یک سرور توسعهٔ Vite با پورت ثابت 5174 و یک بک‌اند پایتون. hgui همهٔ این‌ها را برای ورک‌تری فعلی سیم‌کشی می‌کند:

hgui() {
  local root deps desktop
  root="$(_hermes_root)" || { echo "hgui: not in a Hermes checkout" >&2; return 1; }
  deps="${HERMES_GUI_DEPS_CHECKOUT:-$HERMES_MAIN_CHECKOUT}"
  desktop="$root/apps/desktop"

  # اگر لاک‌ها بخوانند از چک‌اوت وابستگی‌ها قرض بگیر؛ وگرنه محلی نصب کن.
  if cmp -s "$root/package-lock.json" "$deps/package-lock.json"; then
    _hermes_link_deps "$desktop" "$deps/apps/desktop"
    _hermes_link_deps "$root" "$deps"
  else
    ( cd "$root" && npm ci ) || return 1
  fi

  # Vite روی 5174 قفل است — نشست کهنه‌ی hgui دیگری را بیرون بینداز.
  lsof -t -i:5174 >/dev/null 2>&1 && killport 5174

  # الکترون معمولاً Ctrl+C را بدون جمع‌کردن بک‌اندهای زودگذرش زنده می‌ماند.
  trap '_hermes_gui_cleanup "$root"' INT TERM EXIT

  ( cd "$desktop"
    export PATH="$root/node_modules/.bin:$PATH"
    HERMES_DESKTOP_HERMES_ROOT="$root" \
    HERMES_DESKTOP_PYTHON="$HERMES_MAIN_CHECKOUT/.venv/bin/python" \
    HERMES_DESKTOP_IGNORE_EXISTING=1 \
    HERMES_DESKTOP_CWD="$root" \
    npm run dev )
}

متغیرهای محیطی دسکتاپی که ست می‌کند همگی دسته‌های واقعیِ حل بک‌اند هستند:

متغیرنقش در hgui
HERMES_DESKTOP_HERMES_ROOTبک‌اند را از همین ورک‌تری اجرا می‌کند، نه hermes بسته‌بندی‌شده یا روی PATH.
HERMES_DESKTOP_PYTHONvenv چک‌اوت وابستگی‌ها را دوباره‌کاری نمی‌کند و همان را استفاده می‌کند.
HERMES_DESKTOP_IGNORE_EXISTINGهر hermes روی PATH را نادیده می‌گیرد تا روی ورک‌تری سایه نیندازد.
HERMES_DESKTOP_CWDگفتگوی دسکتاپ را با ریشهٔ ورک‌تری باز می‌کند.

دو دام که hgui هندل می‌کند و یک npm run dev خام نه:

  • پورت 5174 ثابت است. دومین hgui با سرور Vite اولی تصادم می‌کند؛ هلپر اول نشستِ کهنه را می‌کشد.
  • فرزندان یتیم. الکترون اغلب Ctrl+C را از داخل concurrently زنده می‌گذرد و بک‌اند زودگذرِ dashboard --port 0 یا فرایند Vite را جمع نمی‌کند. تلهٔ EXIT/INT/TERM یک پاک‌سازی اجرا می‌کند که پوستهٔ الکترون، شنوندهٔ :5174 و هر داشبوردِ --port 0 که ساخته را خاتمه می‌دهد.

۴ هلپرهای مشترک

هر دو تابع، چک‌اوت دربرگیرنده را پیدا و وابستگی‌ها را یک‌شکل لینک می‌کنند:

# ورک‌تری دربرگیرنده، با تأیید اینکه چک‌اوت واقعی هرمس است.
_hermes_root() {
  local root
  root="$(git rev-parse --show-toplevel 2>/dev/null)" || return 1
  [[ -f "$root/hermes_cli/main.py" && -d "$root/ui-tui" ]] && print -r "$root"
}

# سیم‌لینک node_modules از چک‌اوت وابستگی‌ها — هرگز روی یک درخت موجود نمی‌گذارد.
_hermes_link_deps() {
  local target="${1%/}" source="${2%/}"
  [[ -d "$source/node_modules" ]] || return 1
  [[ -e "$target/node_modules" ]] || ln -s "$source/node_modules" "$target/node_modules"
}

# جمع‌کردن بک‌اندهای زودگذری که الکترون موقع خروج جا می‌گذارد.
_hermes_gui_cleanup() {
  local root="$1"
  [[ -n "$root" ]] && pkill -TERM -f "${root}/apps/desktop/node_modules/electron" 2>/dev/null
  lsof -t -i:5174 >/dev/null 2>&1 && killport 5174
  pgrep -f 'hermes_cli\.main.*dashboard.*--port 0' 2>/dev/null | xargs -r kill -TERM 2>/dev/null
}

‏killport یک هلپر کوچک خودتان است (lsof -ti:$1 | xargs kill)؛ معادلِ موردعلاقهٔ خودتان را جایگزین کنید.

ℹ️ چرا فقط وقتی لاک‌ها بخوانند لینک می‌کنیم

سیم‌لینک به یک node_modules واگرا از بی‌نصبی هم بدتر است — ورک‌تری روی پکیج‌هایی بیلد می‌شد که لاک‌فایل خودش هرگز اعلامشان نکرده بود. مقایسهٔ بایت‌به‌بایت package-lock.json همان گاردِ ارزان و دقیق است: لاک یکسان ⇐ قرض گرفتن امن است؛ لاک متفاوت ⇐ npm ci محلی. Vite پیش از اعمال server.fs.allow سیم‌لینک‌ها را به مسیر واقعی باز می‌کند؛ به همین دلیل apps/desktop/vite.config.ts مکان واقعی node_modules را سفید می‌کند.
