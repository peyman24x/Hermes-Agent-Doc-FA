قالب مسیرهای گفتگو

Hermes Agent مسیرهای گفتگو (Trajectory) را در قالب JSONL سازگار با ShareGPT ذخیره می‌کند تا به‌عنوان دادهٔ آموزش، خروجی اشکال‌زدایی و مجموعه‌دادهٔ یادگیری تقویتی استفاده شوند.

فایل‌های منبع: agent/trajectory.py، agent/session_persistence.py (عبارت _save_trajectory را جستجو کنید)، batch_runner.py.

۱ قرارداد نام‌گذاری فایل‌ها

مسیرهای گفتگو در فایل‌هایی در پوشهٔ کاری جاری نوشته می‌شوند:

فایلزمان استفاده
trajectory_samples.jsonlگفتگوهایی که با موفقیت کامل شده‌اند (completed=True)
failed_trajectories.jsonlگفتگوهایی که شکست خورده یا قطع شده‌اند (completed=False)

اجراگر دسته‌ای (batch_runner.py) برای هر دسته در فایل خروجی سفارشی (مثلاً batch_001_output.jsonl) با فیلدهای فرادادهٔ اضافی می‌نویسد. می‌توانید نام فایل را با پارامتر filename در save_trajectory() تغییر دهید.

۲ قالب هر رکورد JSONL

هر خط فایل یک شیء JSON مستقل است. دو گونه وجود دارد:

قالب CLI/تعاملی (از _save_trajectory)

{
  "conversations": [ ... ],
  "timestamp": "2026-03-30T14:22:31.456789",
  "model": "anthropic/claude-sonnet-4.6",
  "completed": true
}

قالب اجراگر دسته‌ای (از batch_runner.py)

{
  "prompt_index": 42,
  "conversations": [ ... ],
  "metadata": { "prompt_source": "gsm8k", "difficulty": "hard" },
  "completed": true,
  "partial": false,
  "api_calls": 7,
  "toolsets_used": ["code_tools", "file_tools"],
  "tool_stats": {
    "terminal": {"count": 3, "success": 3, "failure": 0},
    "read_file": {"count": 2, "success": 2, "failure": 0},
    "write_file": {"count": 0, "success": 0, "failure": 0}
  },
  "tool_error_counts": {
    "terminal": 0,
    "read_file": 0,

دیکشنری‌های tool_stats و tool_error_counts نرمال می‌شوند تا تمام ابزارهای ممکن (از model_tools.TOOL_TO_TOOLSET_MAP) را با پیش‌فرض صفر دربر گیرند؛ در نتیجه اسکیما برای بارگذاری مجموعه‌دادهٔ HuggingFace در همهٔ رکوردها یکسان می‌ماند.

۴ قواعد نرمال‌سازی

نشانه‌گذاری محتوای استدلال

مبدل مسیر گفتگو، صرف‌نظر از شیوهٔ تولید اولیهٔ مدل، تمام استدلال را در تگ‌های <think> نرمال می‌کند:

  1. توکن‌های بومی تفکر (فیلد msg["reasoning"] از ارائه‌دهندگانی مانند Anthropic و سری o شرکت OpenAI): به‌شکل <think>\n{reasoning}\n</think>\n محصور می‌شوند و پیش از محتوا قرار می‌گیرند.
  2. XML مربوط به REASONING_SCRATCHPAD (وقتی تفکر بومی غیرفعال است و مدل با XML تعیین‌شده در پرامپت سیستم استدلال می‌کند): تگ‌های <REASONING_SCRATCHPAD> از طریق convert_scratchpad_to_think() به <think> تبدیل می‌شوند.
  3. بلوک‌های خالی تفکر: تضمین می‌شود هر نوبت gpt یک بلوک <think> داشته باشد. اگر استدلالی تولید نشده باشد، بلوک خالی <think>\n</think>\n درج می‌شود تا قالب دادهٔ آموزشی یکسان بماند.

نرمال‌سازی فراخوانی ابزار

فراخوانی‌های ابزار از قالب API (با tool_call_id، نام تابع و آرگومان‌ها به‌شکل رشتهٔ JSON) به JSON محصور در XML تبدیل می‌شوند:

<tool_call>
{"name": "terminal", "arguments": {"command": "ls -la"}}
</tool_call>
  • آرگومان‌ها از رشته‌های JSON به اشیا برگردانده می‌شوند؛ دوباره کدگذاری نمی‌شوند.
  • اگر تجزیهٔ JSON شکست بخورد (نباید رخ دهد، چون در طول گفتگو اعتبارسنجی شده است)، از {} خالی استفاده و هشداری ثبت می‌شود.
  • چند فراخوانی ابزار در یک نوبت دستیار، چند بلوک <tool_call> را در یک پیام gpt تولید می‌کند.

نرمال‌سازی پاسخ ابزار

تمام نتایج ابزار که پس از پیام دستیار می‌آیند، در یک نوبت tool با پاسخ‌های JSON محصور در XML گروه‌بندی می‌شوند:

<tool_response>
{"tool_call_id": "call_abc123", "name": "terminal", "content": "output here"}
</tool_response>
  • اگر محتوای ابزار شبیه JSON باشد (با { یا [ شروع شود)، تجزیه می‌شود تا فیلد محتوا به‌جای رشته، شیء یا آرایهٔ JSON داشته باشد.
  • چند نتیجهٔ ابزار با نویسهٔ خط جدید در یک پیام به هم پیوند داده می‌شوند.
  • نام ابزار بر اساس موقعیت با آرایهٔ tool_calls دستیار والد تطبیق داده می‌شود.

پیام سیستم

پیام سیستم هنگام ذخیره تولید می‌شود و از گفتگو گرفته نمی‌شود. این پیام از الگوی پرامپت فراخوانی تابع Hermes پیروی می‌کند و شامل موارد زیر است:

  • مقدمه‌ای برای توضیح پروتکل فراخوانی تابع
  • بلوک XML با تگ <tools> شامل تعریف‌های JSON ابزارها
  • مرجع اسکیما برای اشیای FunctionCall
  • مثالی از <tool_call>

تعریف ابزارها شامل name، description، parameters و required است؛ مقدار آخری برای تطابق با قالب مرجع روی null تنظیم می‌شود.

۵ بارگذاری مسیرهای گفتگو

مسیرهای گفتگو JSONL استاندارد هستند؛ آن‌ها را با هر خوانندهٔ JSON-lines بارگذاری کنید:

import json

def load_trajectories(path: str):
    """Load trajectory entries from a JSONL file."""
    entries = []
    with open(path, "r", encoding="utf-8") as f:
        for line in f:
            line = line.strip()
            if line:
                entries.append(json.loads(line))
    return entries

# Filter to successful completions only
successful = [e for e in load_trajectories("trajectory_samples.jsonl")
              if e.get("completed")]

# Extract just the conversations for training
training_data = [e["conversations"] for e in successful]

بارگذاری برای مجموعه‌داده‌های HuggingFace

from datasets import load_dataset

ds = load_dataset("json", data_files="trajectory_samples.jsonl")

اسکیمای نرمال‌شدهٔ tool_stats تضمین می‌کند تمام رکوردها ستون‌های یکسان داشته باشند و هنگام بارگذاری مجموعه‌داده، خطای عدم تطابق اسکیمای Arrow رخ ندهد.

۶ کنترل ذخیرهٔ مسیر گفتگو

ذخیرهٔ مسیر گفتگو کلیدی در سطح run_agent.py یا کتابخانه است؛ CLI با نام hermes کلید پیکربندی یا پرچمی برای آن ارائه نمی‌دهد:

python run_agent.py --save_trajectories --query='your question here'

یا به‌شکل برنامه‌نویسی: AIAgent(..., save_trajectories=True) / initialize_agent(..., save_trajectories=True). هنگام فعال‌بودن، متد _save_trajectory() در پایان هر نوبت گفتگو فراخوانی می‌شود.

اجراگر دسته‌ای همیشه مسیرهای گفتگو را ذخیره می‌کند؛ هدف اصلی آن همین است.

اجراگر دسته‌ای نمونه‌هایی را که در هیچ نوبتی استدلال ندارند، خودکار کنار می‌گذارد تا داده‌های آموزشی با نمونه‌های فاقد استدلال آمیخته نشوند.
