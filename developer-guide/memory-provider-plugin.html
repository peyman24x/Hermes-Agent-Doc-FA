پلاگین ارائه‌دهندهٔ حافظه

پلاگین‌های ارائه‌دهندهٔ حافظه به Hermes Agent دانش پایدار و میان‌نشستی می‌دهند که فراتر از MEMORY.md و USER.md داخلی است. این راهنما پوشش می‌دهد که چگونه یکی بسازید.

💡

ارائه‌دهندگان حافظه یکی از دو نوع پلاگین ارائه‌دهنده هستند. نوع دیگر، پلاگین موتور زمینه است که فشرده‌ساز زمینهٔ داخلی را جایگزین می‌کند. هر دو از یک الگو پیروی می‌کنند: تک‌انتخابی، مبتنی بر پیکربندی و مدیریت‌شده از طریق hermes plugins.

۱ چیدمان‌های نصب

هرمس ارائه‌دهندگان حافظه را از چهار منبع کشف می‌کند، با این ترتیب اولویت:

منبعمکانتوضیحات
همراه بستهplugins/memory/<name>/همراه با Hermes عرضه می‌شود. برای ارائه‌دهندگان جدید بسته است — CONTRIBUTING را ببینید.
کاربر$HERMES_HOME/plugins/<name>/به‌دست کاربر اضافه می‌شود، به‌ازای هر پروفایل.
پروژه./.hermes/plugins/<name>/با انتخاب از طریق HERMES_ENABLE_PROJECT_PLUGINS=1.
پکیجنقطهٔ ورودی hermes_agent.memory_providerspip install؛ چیزی برای کپی کردن نیست.

در برخورد نام، منابعِ زودتر برنده می‌شوند؛ بنابراین پوشه‌ای که در یک درخت کاری قرار بگیرد هرگز نمی‌تواند سایه‌ای بر ارائه‌دهندهٔ عرضه‌شده بیندازد.

ℹ️ توجه

این برعکسِ ترتیبِ «بعدی برنده می‌شود» در سیستم پلاگین عمومی است. ارائه‌دهندهٔ حافظه با نام فعال می‌شود (memory.provider)، پس سایه‌انداختن حافظهٔ ایجنت را بی‌سروصدا منحرف می‌کند، نه صرفاً بازنویسی یک ابزار.

کشف فقط فهرست‌برداری می‌کند — هرگز ارائه‌دهنده‌ای را import نمی‌کند. تا وقتی memory.provider نامش را نبرد، هیچ‌چیز اجرا نمی‌شود.

ارائه‌دهندهٔ پوشه‌ای

ارائه‌دهندهٔ پوشه‌ای در plugins/memory/<name>/ وقتی همراه Hermes است، در $HERMES_HOME/plugins/<name>/ وقتی کاربر نصبش کرده، یا در ./.hermes/plugins/<name>/ برای نمونهٔ محلیِ پروژه قرار می‌گیرد:

plugins/memory/my-provider/
├── __init__.py      # پیاده‌سازی MemoryProvider + نقطهٔ ورود register()
├── plugin.yaml      # متادیتا (name، description، hooks)
└── README.md        # دستورالعمل راه‌اندازی، مرجع پیکربندی، ابزارها

ارائه‌دهندهٔ پکیجی

ارائه‌دهندهٔ نصب‌شده با pip یک نقطهٔ ورودی در گروه hermes_agent.memory_providers منتشر می‌کند. نام نقطهٔ ورودی همان نام ارائه‌دهنده‌ای است که کاربران در memory.provider انتخاب می‌کنند؛ مقدارش به تابع register(ctx) ارائه‌دهنده اشاره می‌کند:

# pyproject.toml
[project.entry-points."hermes_agent.memory_providers"]
my-provider = "my_provider:register"

نقطهٔ ورودی را به پکیج اشاره دهید، یا به یک register(ctx) داخل آن، و پیاده‌سازی، مهارت‌ها و سایر منابع را در چیدمان معمول پکیج پایتون نگه دارید. نیازی به هیچ کپی‌ای زیر $HERMES_HOME/plugins/ نیست.

نقطهٔ ورود پکیجی همه‌چیزِ یک نصب پوشه‌ای را می‌گیرد، از جمله دو فایلی که هرمس از روی دیسک می‌خواند نه با import — config_schema.py (پنل پیکربندی داشبورد) و cli.py (زیرفرمان‌های hermes <provider> شما). هر دو کنار __init__.py پکیج شما پیدا می‌شوند؛ پس اگر یکی را عرضه می‌کنید، نقطهٔ ورودی را به یک پکیج اشاره دهید نه یک ماژول تکی.

۲ کلاس انتزاعی MemoryProvider

پلاگین شما کلاس انتزاعی MemoryProvider را از agent/memory_provider.py پیاده‌سازی می‌کند:

from agent.memory_provider import MemoryProvider

class MyMemoryProvider(MemoryProvider):
    @property
    def name(self) -> str:
        return "my-provider"

    def is_available(self) -> bool:
        """بررسی اینکه آیا این ارائه‌دهنده می‌تواند فعال شود. هیچ فراخوانی شبکه‌ای."""
        return bool(os.environ.get("MY_API_KEY"))

    def initialize(self, session_id: str, **kwargs) -> None:
        """یک‌بار در شروع ایجنت صدا زده می‌شود.

        kwargs همیشه شامل این است:
          hermes_home (str): مسیر فعال HERMES_HOME. برای ذخیره‌سازی استفاده کنید.
        """
        self._api_key = os.environ.get("MY_API_KEY", "")
        self._session_id = session_id

    # ... متدهای باقی‌مانده را پیاده‌سازی کنید

۴ اسکیمای پیکربندی

get_config_schema() فهرستی از توصیف‌گرهای فیلد برمی‌گرداند که hermes memory setup از آن‌ها استفاده می‌کند:

def get_config_schema(self):
    return [
        {
            "key": "api_key",
            "description": "My Provider API key",
            "secret": True,           # → در .env نوشته می‌شود
            "required": True,
            "env_var": "MY_API_KEY",   # نام صریح متغیر محیطی
            "url": "https://my-provider.com/keys",  # محل دریافت
        },
        {
            "key": "region",
            "description": "Server region",
            "default": "us-east",
            "choices": ["us-east", "eu-west", "ap-south"],
        },
        {
            "key": "project",
            "description": "Project identifier",
            "default": "hermes",
        },
    ]

فیلدهای دارای secret: True و env_var به .env می‌روند. فیلدهای غیرمخفی به save_config() پاس داده می‌شوند.

💡 نکته: اسکیمای حداقلی در برابر کامل

هر فیلد در get_config_schema() هنگام hermes memory setup از کاربر پرسیده می‌شود. ارائه‌دهندگانی که گزینه‌های زیادی دارند باید اسکیما را حداقلی نگه دارند — فقط فیلدهایی را بگنجانند که کاربر باید پیکربندی کند (کلید API، اعتبارنامه‌های الزامی). تنظیمات اختیاری را در یک مرجع فایل پیکربندی مستند کنید (مثلاً $HERMES_HOME/myprovider.json) نه این‌که همه را هنگام راه‌اندازی بپرسید. این جادوگر راه‌اندازی را سریع نگه می‌دارد و هم‌زمان از پیکربندی پیشرفته پشتیبانی می‌کند. ارائه‌دهندهٔ Supermemory را برای مثال ببینید — فقط کلید API را می‌پرسد؛ بقیهٔ گزینه‌ها در supermemory.json زندگی می‌کنند.

۵ ذخیرهٔ پیکربندی

def save_config(self, values: dict, hermes_home: str) -> None:
    """پیکربندی غیرمخفی را در مکان بومی خودتان بنویسید."""
    import json
    from pathlib import Path
    config_path = Path(hermes_home) / "my-provider.json"
    config_path.write_text(json.dumps(values, indent=2))

برای ارائه‌دهندگان فقط-متغیر-محیطی، همان no-op پیش‌فرض را باقی بگذارید.

۶ نقطهٔ ورود پلاگین

def register(ctx) -> None:
    """توسط سیستم کشف پلاگین حافظه صدا زده می‌شود."""
    ctx.register_memory_provider(MyMemoryProvider())

یک ارائه‌دهنده می‌تواند از همان callback مهارت‌های فقط‌خواندنی هم در معرض بگذارد. مهارت‌ها با نام نقطهٔ ورودی تعیین‌صلاحیت می‌شوند و فقط وقتی آن ارائه‌دهندهٔ حافظه فعال است بارگذاری می‌شوند:

from pathlib import Path

SKILLS_DIR = Path(__file__).parent / "skills"

def register(ctx) -> None:
    ctx.register_memory_provider(MyMemoryProvider())
    ctx.register_skill(
        "maintenance",
        SKILLS_DIR / "maintenance" / "SKILL.md",
        "Maintain the provider's memory store",
    )

با فعال‌بودن نقطهٔ ورودی my-provider، مهارت به‌شکل my-provider:maintenance از طریق skill_view() در دسترس است.

۸ قرارداد نخ‌بندی

sync_turn() باید مسدودکننده نباشد. اگر بک‌اند شما تأخیر دارد (فراخوانی‌های API، پردازش LLM)، کار را در یک نخ دیمون اجرا کنید:

def sync_turn(self, user_content, assistant_content, *, session_id="", messages=None):
    def _sync():
        try:
            self._api.ingest(user_content, assistant_content, session_id=session_id, messages=messages)
        except Exception as e:
            logger.warning("Sync failed: %s", e)

    if self._sync_thread and self._sync_thread.is_alive():
        self._sync_thread.join(timeout=5.0)
    self._sync_thread = threading.Thread(target=_sync, daemon=True)
    self._sync_thread.start()

messages زمینهٔ اختیاریِ گفتگو به سبک OpenAI تا پایان نوبتِ کامل‌شده است. وقتی موجود باشد، شامل پیام‌های کاربر/دستیار، فراخوانی‌های ابزار دستیار و پیام‌های نتیجهٔ ابزار است. ارائه‌دهندگانی که به زمینهٔ خام نوبت نیاز ندارند می‌توانند پارامتر messages را حذف کنند؛ هرمس همچنان آن‌ها را با امضای قدیمی فراخوانی خواهد کرد.

ارائه‌دهندگان ابری باید مستند کنند که کدام بخش‌های messages از دستگاه خارج می‌شوند. فراخوانی‌های ابزار و نتایج ابزار ممکن است شامل مسیر فایل، خروجی دستور یا دادهٔ دیگرِ فضای کاری باشند.

۹ ایزوله‌سازی پروفایل

همهٔ مسیرهای ذخیره‌سازی باید از kwarg به نام hermes_home از initialize() استفاده کنند، نه ~/.hermes هاردکد‌شده:

# درست — مختص پروفایل
from hermes_constants import get_hermes_home
data_dir = get_hermes_home() / "my-provider"

# غلط — میان همهٔ پروفایل‌ها مشترک
data_dir = Path("~/.hermes/my-provider").expanduser()

۱۱ افزودن دستورهای CLI

پلاگین‌های ارائه‌دهندهٔ حافظه می‌توانند درخت زیرفرمان CLI مخصوص خودشان را ثبت کنند (مثلاً hermes my-provider status، hermes my-provider config). این از یک سیستم کشف قرارداد‌محور استفاده می‌کند — بدون نیاز به تغییر فایل‌های هسته.

نحوهٔ کار

  1. یک فایل cli.py به پوشهٔ پلاگین اضافه کنید
  2. یک تابع register_cli(subparser) تعریف کنید که درخت argparse را بسازد
  3. سیستم پلاگین حافظه آن را هنگام شروع از طریق discover_plugin_cli_commands() کشف می‌کند
  4. دستورهای شما زیر hermes <provider-name> <subcommand> ظاهر می‌شوند

گیتِ ارائه‌دهندهٔ فعال: دستورهای CLI شما فقط وقتی ظاهر می‌شوند که ارائه‌دهندهٔ شما memory.provider فعال در پیکربندی باشد. اگر کاربر ارائه‌دهندهٔ شما را پیکربندی نکرده باشد، دستورهایتان در hermes --help نشان داده نمی‌شوند.

مثال

# plugins/memory/my-provider/cli.py

def my_command(args):
    """هندلری که argparse dispatch می‌کند."""
    sub = getattr(args, "my_command", None)
    if sub == "status":
        print("Provider is active and connected.")
    elif sub == "config":
        print("Showing config...")
    else:
        print("Usage: hermes my-provider <status|config>")

def register_cli(subparser) -> None:
    """درخت argparse مربوط به hermes my-provider را می‌سازد.

    در زمان راه‌اندازی argparse توسط discover_plugin_cli_commands() صدا زده می‌شود.
    """
    subs = subparser.add_subparsers(dest="my_command")
    subs.add_parser("status", help="Show provider status")
    subs.add_parser("config", help="Show provider config")
    subparser.set_defaults(func=my_command)

plugins/memory/honcho/cli.py را برای مثال کامل با ۱۳ زیرفرمان، مدیریت میان‌پروفیلی (--target-profile) و خواندن/نوشتن پیکربندی ببینید.

۱۲ قاعدهٔ ارائه‌دهندهٔ تکی

در هر لحظه فقط یک ارائه‌دهندهٔ حافظهٔ خارجی می‌تواند فعال باشد. اگر کاربر بخواهد دومی را ثبت کند، MemoryManager آن را با یک هشدار رد می‌کند. این از بادکردن اسکیمای ابزارها و بک‌اندهای متعارض جلوگیری می‌کند.
