پلاگین‌های ارائه‌دهندهٔ محیط ترمینال

Hermes فرمان‌های شِل را از طریق مجموعه‌ای قابل‌گسترش از بک‌اندهای ترمینال اجرا می‌کند. بک‌اندهای داخلی (local، Docker، Singularity، Modal، Daytona، Vercel Sandbox و SSH) در مخزن اصلی، زیر مسیر tools/environments/ قرار دارند. در مقابل، عرضه‌کنندگان شخص ثالثِ سندباکس از طریق پلاگین‌ها یکپارچه می‌شوند: مخزنی مستقل برای پلاگین که زیر مسیر ~/.hermes/plugins/ نصب می‌شود و بک‌اندی را ثبت می‌کند که کاربر آن را دقیقاً مانند یک بک‌اند داخلی، از طریق terminal.backend در config.yaml انتخاب می‌کند.

این صفحه همتای راهنمای پلاگین‌های ارائه‌دهندهٔ مرورگر است؛ فرایند ثبت و قواعد دامنهٔ اثر در هر دو یکسان‌اند.

۱ آنچه ارائه‌دهنده کنترل می‌کند

بک‌اند ثبت‌شده به‌طور خودکار در همهٔ بخش‌های زیر از هسته به کار گرفته می‌شود:

بخشعامل تعیین‌کننده
ارسال فرمان برای اجرا (terminal، execute_code و ابزارهای فایل)create_environment()
انتخاب‌گر بک‌اند در hermes setupdisplay_name، description، setup_instructions()، post_setup()
انتخاب‌گر بک‌اند ترمینال در داشبورد (وضعیت بررسی آمادگی)probe()
hermes status / hermes doctordoctor_checks()
راهنمایی‌های مربوط به محیط در پرامپت سیستمیis_remote، env_description
صرف‌نظر کردن از دریافت تأیید برای فرمان‌های خطرناکskip_container_guards
مدیریت مسیر و پوشهٔ کاری جاری (cwd) در کانتینرis_container
تبدیل مسیر فایل‌های کش همگام‌سازی‌شدهcache_path_base
حذف اطلاعات محرمانه از زیرفرایندهای ایجادشدهstrip_env_keys
جداسازی سندباکس به‌ازای هر نشست (container_persistent: false)session_isolated_when_nonpersistent

اعلام این پرچم‌ها در ارائه‌دهنده، دستهٔ شناخته‌شده‌ای از باگ‌ها را برطرف می‌کند که در آن «بک‌اند جدید در یکی از محل‌های طبقه‌بندی بک‌اندها از قلم افتاده است». هسته در هر محل، به‌جای تکیه بر فهرستی از نام‌های ثابت در کد، به رجیستری مراجعه می‌کند.

۲ ارائه‌دهندهٔ حداقلی

فایل ~/.hermes/plugins/acmebox/__init__.py:

from agent.terminal_env_provider import TerminalEnvironmentProvider


class AcmeBoxEnvironment:
    """Must satisfy the BaseEnvironment duck-typed contract."""

    def __init__(self, cwd, timeout, task_id):
        self.cwd, self.timeout, self.task_id = cwd, timeout, task_id

    def execute(self, command, timeout=None, **kwargs):
        ...  # run the command in the sandbox
        return {"output": "...", "exit_code": 0}

    def cleanup(self):
        ...  # tear down / detach


class AcmeBoxProvider(TerminalEnvironmentProvider):
    name = "acmebox"
    display_name = "AcmeBox"
    is_remote = True          # commands don't run on the host
    is_container = True       # container-style path/cwd semantics

    @property
    def description(self):
        return "Run commands in an AcmeBox cloud sandbox."

    @property
    def cache_path_base(self):
        return "~/.hermes"    # where synced cache files land, or None

    @property
    def strip_env_keys(self):
        return frozenset({"ACMEBOX_TOKEN"})

    def is_available(self):
        import importlib.util, os
        return (
            importlib.util.find_spec("acmebox") is not None
            and bool(os.getenv("ACMEBOX_TOKEN"))
        )

    def create_environment(self, *, cwd, timeout, task_id="default",
                           image=None, container_config=None, **kwargs):
        return AcmeBoxEnvironment(cwd, timeout, task_id)


def register(ctx):
    ctx.register_terminal_environment_provider(AcmeBoxProvider())

فایل ~/.hermes/plugins/acmebox/plugin.yaml:

name: acmebox
version: 0.1.0
description: AcmeBox cloud sandbox terminal backend
kind: backend

پلاگین را فعال کنید، آن را به‌عنوان بک‌اند انتخاب کنید و اجرا کنید:

hermes plugins enable acmebox
hermes config set terminal.backend acmebox

۳ قواعد

  • نام‌های رزروشده. ثبت‌هایی که نامشان با نام یکی از بک‌اندهای داخلی (local، docker، singularity، modal، managed_modal، daytona، vercel_sandbox، ssh) تداخل داشته باشد، رد می‌شوند. پلاگین‌ها مجموعهٔ بک‌اندها را گسترش می‌دهند؛ هرگز جای بک‌اندهای موجود در درخت کد اصلی را نمی‌گیرند.
  • create_environment باید **kwargs را بپذیرد و کلیدهای ناشناخته را نادیده بگیرد. این قراردادِ سازگاری با نسخه‌های آینده، امکان تغییر امضای تابع سازندهٔ محیط را بدون از کار انداختن پلاگین‌های قدیمی‌تر فراهم می‌کند.
  • is_available() و probe() باید کم‌هزینه باشند. هیچ فراخوانی شبکه‌ای انجام ندهید؛ این متدها هنگام بررسی پیش‌نیازها و رسم رابط کاربری اجرا می‌شوند.
  • مدیریت خطا بدون از کار انداختن سامانه، در همه‌جا. اگر دسترسی به یک ویژگیِ ارائه‌دهنده استثنا ایجاد کند، هسته مقدار پیش‌فرض آن را در نظر می‌گیرد؛ برای مثال، اگر skip_container_guards استثنا ایجاد کند، لایهٔ تأیید همچنان فعال می‌ماند. برای کنترل جریان اجرا به استثناها تکیه نکنید.
  • اطلاعات محرمانه باید در strip_env_keys فهرست شوند. توکن سرویس‌دهندهٔ شما هرگز نباید برای فرمان شِلی که مدل نوشته است قابل‌خواندن باشد. با قرار دادن نام متغیر آن در این فهرست، آن متغیر بدون هیچ شرطی از محیط هر زیرفرایند ایجادشده حذف می‌شود؛ درست مانند رفتار داخلی برای MODAL_* و DAYTONA_API_KEY.

۴ قرارداد شیء محیط

create_environment() شیئی برمی‌گرداند که همان رابط مبتنی بر نوع‌دهی اردکی (duck typing) کلاس tools.environments.base.BaseEnvironment را پیاده‌سازی می‌کند:

  • execute(command, timeout=None, ...) ← خروجی: {"output": str, "exit_code": int}
  • cleanup() — منابع را آزاد می‌کند؛ هنگام پایان نشست یا پاک‌سازی منابع بی‌کار فراخوانی می‌شود.
  • اختیاری: هوک‌های ماندگاری، مشابه هوک‌های بک‌اندهای ابری داخلی.

ارث‌بری از BaseEnvironment توصیه می‌شود، اما الزامی نیست. با این کار، زیرساخت مشترک همگام‌سازی فایل و فرایندهای پس‌زمینه را به ارث می‌برید.

۵ قواعد جداسازی نشست‌ها

اگر سندباکس شما با نام از سر گرفته می‌شود (یعنی ماشین مجازی ماندگاری است که بک‌اند دوباره به آن متصل می‌شود)، مقدار session_isolated_when_nonpersistent = True را تنظیم کنید. در این صورت، با تنظیم terminal.container_persistent: false، هر نشست به‌جای اشتراک یک سندباکس، هویت سندباکس مختص خود را دریافت می‌کند. بدون این تنظیم، دو اجرای موقتی و مستقل ممکن است به یک ماشین مجازیِ در حال اجرا متصل شوند و یکی آن را در حالی حذف کند که دیگری هنوز از آن استفاده می‌کند.
