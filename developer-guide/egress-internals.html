درون‌مایهٔ پروکسی خروجی

این صفحه، معماری دیوار آتشِ تزریق اعتبارنامهٔ خروجی (egress) (hermes egress / iron-proxy) را از دیدگاه مشارکت‌کننده / نویسندهٔ پلاگین پوشش می‌دهد. مستندات راه‌اندازی و استفادهٔ رو به کاربر نهایی در پروکسی iron (تزریق اعتبارنامه) قرار دارد.

مدل تهدید و طراحی کلان در صفحهٔ کاربر خلاصه شده است؛ این صفحه دربارهٔ نحوهٔ سیم‌کشی آن است، اینکه کدِ مرتبط با امنیت کجا زندگی می‌کند، و اگر دست به آن بزنید باید کدام ناورداها را حفظ کنید.

۲ چرخهٔ حیات

hermes egress install
  -> agent.proxy_sources.iron_proxy.install_iron_proxy(force=...)
       Downloads pinned tarball + checksums.txt from GitHub Releases.
       SHA-256 verification before extraction.
       tarfile.extract(..., filter="data") on Python 3.12+ (PEP 706);
         falls back to plain extract on older Python with member-name
         sanitisation via _pick_tar_member.
       Stage into ~/.hermes/bin/.iron-proxy_XXXX, chmod 755, os.replace
         to ~/.hermes/bin/iron-proxy (atomic).
       _VERSION_CACHE.pop(target) so a forced reinstall re-probes
         --version on next call.

hermes egress setup [--from-bitwarden | --no-bitwarden] [--rotate-tokens]
  -> proxy_cli.cmd_setup
       Step 1. find_iron_proxy(install_if_missing=False) -> install if absent.
       Step 2. ensure_ca_cert()
                 Run openssl genrsa + req via subprocess.
                 Write CA key via os.open(O_WRONLY|O_CREAT|O_TRUNC|O_NOFOLLOW, 0o600)
                   + os.replace.  Never exists on disk under default umask.
                 Write CA cert with 0o644 (public).
       Step 3. discover_provider_mappings() or pull names from BWS via
                 fetch_bitwarden_secrets() when --from-bitwarden.
                 merge_mappings(existing=load_mappings(), discovered,
                                rotate=args.rotate_tokens) preserves prior
                 tokens unless --rotate-tokens is passed.
                 discover_uncovered_providers() and surface warnings.
       Step 4. ensure_audit_log(audit_log_path)   # در صورت OSError استثنا می‌دهد
               build_proxy_config(...) with defaults applied at the call site
                 (deny CIDRs default, bind policy from _default_http_listen).
               write_proxy_config(cfg)            # اتمیک از طریق .tmp + os.replace، 0o600
               write_mappings(mappings)           # اتمیک، 0o600
       Step 5. proxy_cfg["enabled"] = True; credential_source preservation logic
               (do NOT silently downgrade bitwarden -> env on re-run);
               save_config(cfg).

hermes egress start
  -> proxy_cli.cmd_start
       Pre-checks (refuse-start path):
         - credential_source=bitwarden? -> pre-validate access_token_env + project_id
       -> iron_proxy.start_proxy(
            refresh_secrets_from_bitwarden=...,
            bitwarden_config=...,
          )
            existing=_read_pid(); if alive, idempotent return.
            _build_proxy_subprocess_env(...):  ALLOWLIST + mapped real_env_names,
              strip HTTPS_PROXY/etc. to avoid recursion, optional BWS refresh
              (raises on missing values unless allow_env_fallback=true).
            Plant nonce: _proxy_nonce = sha256(urandom(16)); env[NONCE_ENV] = ...
            Open log_path via O_NOFOLLOW + 0o600 + st_uid check.
            Popen with stdin=DEVNULL, stdout=log_fd, stderr=STDOUT,
              start_new_session=True (POSIX).
            Close parent's log_fd in finally.
            _write_pidfile_safely(pidfile, proc.pid)
              O_EXCL + O_NOFOLLOW + uid check + persisted nonce sidecar.
              FileExistsError -> discriminate live vs stale, retry once if stale.
            Install SIGINT/SIGTERM handlers (main-thread only).
            Poll loop (do-while shape):
              while True:
                if proc.poll() is not None: tail log + unlink pidfile + raise
                if _port_listening(probe_host, tunnel_port): break  # probe_host = میزبان bind پیکربندی‌شده
                if time.time() >= deadline: break  (do-while: checked AFTER first probe)
                time.sleep(0.1)
            If not listening at exit: _kill_and_wait(proc) + unlink pidfile + raise.

hermes egress stop
  -> iron_proxy.stop_proxy
       _read_pid + _pid_alive guard.
       starttime_before = _pid_proc_starttime(pid)   # فقط لینوکس؛ در جای دیگر None
       os.kill(pid, SIGTERM)
       Wait up to 5s for graceful exit.
       After grace: re-check starttime + _pid_alive.
         If recycled (starttime drift OR _pid_alive False), DO NOT SIGKILL.
         Otherwise os.kill(pid, _KILL_SIGNAL).
       _cleanup_state_files: unlink pidfile + nonce sibling.

کمینه‌سازی env ساب‌پروسس

_build_proxy_subprocess_env نباید از os.environ.copy() استفاده کند. فهرست مجاز، _PROXY_SUBPROCESS_ENV_ALLOWLIST است (PATH، HOME، locale و...) به‌علاوهٔ نام‌های env ارجاع‌شده در load_mappings(). هر چیز دیگری روی میزبان می‌ماند.

تست‌های رگرسیون: test_subprocess_env_strips_unrelated_secrets، test_subprocess_env_strips_proxy_recursion_vars، test_subprocess_env_keeps_infrastructure_vars.

سیاست bind

_default_http_listen فهرستی تک‌عضوی برمی‌گرداند: روی لینوکس، IP گیت‌ویِ پل docker (کانتینرها از طریق host.docker.internal:host-gateway به پروکسی می‌رسند که به گیت‌ویِ پل حل می‌شود — bind روی loopback از درون کانتینرها آنجا دست‌نیافتنی است)؛ روی Docker Desktop مک/ویندوز، loopback (VPNkit مسیر host.docker.internal را به میزبان می‌برد). لینوکسی که پل docker0 قابل‌تشخیصی ندارد، با هشدار به loopback برمی‌گردد. هرگز 0.0.0.0، هرگز :PORT (INADDR_ANY).

_detect_docker_bridge_ip از طریق ipaddress.IPv4Address اعتبارسنجی می‌کند و is_unspecified / is_loopback / is_multicast / is_reserved / is_link_local / is_global را رد می‌کند. یک شیم ip مخرب روی PATH نمی‌تواند 0.0.0.0 تزریق کند.

محدودیت اسکیمای v0.39 و نقش‌های شنونده (به‌صورت زنده روی باینری تأیید شده): ساختار config.Proxy باینری فقط فیلدهای شنوندهٔ مفرد دارد — فهرست http_listens (جمع) وجود ندارد. tunnel_listen شنوندهٔ CONNECT + MITM است (ترافیک HTTPS_PROXY به آن می‌خورد)؛ http_listen فقط فورواردهای plain-HTTPِ فرم-مطلق را هندل می‌کند (CONNECTی که به آن فرستاده شود، به‌عنوان یک درخواست معمولی به بالادست رله می‌شود و 400 می‌گیرد). بنابراین build_proxy_config روی tunnel_port به tunnel_listen و روی tunnel_port + 1 به http_listen bind می‌زند، هر دو روی میزبان bind پلتفرم. بک‌اند Docker مقدار HTTPS_PROXY را روی tunnel_port و HTTP_PROXY را روی tunnel_port + 1 می‌گذارد.

پروب‌های زنده‌بودن (حلقهٔ poll در start_proxy، get_status) میزبان bind پیکربندی‌شده را از طریق _read_http_listen_from_config() می‌خوانند و همان میزبان را پروب می‌کنند — پروبِ هاردکدشدهٔ loopback، دیمونِ سالمِ متصل-به-پل را مرده گزارش می‌داد.

تست‌های رگرسیون: test_default_bind_is_loopback_not_zero_zero (اعلام می‌کند نه INADDR_ANY هست و نه http_listens در yaml خروجی)، test_default_bind_uses_docker_bridge_on_linux، test_default_bind_falls_back_to_loopback_without_bridge، test_default_bind_is_loopback_on_macos، test_detect_docker_bridge_ip_rejects_dangerous (پارامتری‌شده روی ۸ ورودی حمله).

برخورد پورت متریک‌ها

metrics.listen در iron-proxy v0.39 به‌طور پیش‌فرض :9090 است — همان پورتی که پیش‌فرض هرمس یعنی tunnel_port: 9090 است. build_proxy_config باید صریحاً metrics.listen: 127.0.0.1:0 را پین کند تا اتصال متریک‌ها پورت loopback گذرایی بگیرد که هرگز با شنوندهٔ پروکسی برخورد نکند، فارغ از tunnel_port انتخابی اپراتور.

تست رگرسیون: test_metrics_listener_pinned_to_loopback_ephemeral.

CIDRهای پیش‌فرضِ رد

_DEFAULT_UPSTREAM_DENY_CIDRS شامل loopback (v4 + v6)، link-local (از جمله IMDS در 169.254.169.254 و فرم IPv4-mapped-v6)، RFC1918، IPv6 ULA، CGNAT و بازهٔ بنچمارک RFC2544 است. build_proxy_config(..., upstream_deny_cidrs=None) باید پیش‌فرض را صادر کند؛ فقط یک لیست خالیِ صریح از آن انصراف می‌دهد.

تست‌های رگرسیون: test_default_deny_cidrs_present_when_unspecified، test_default_deny_includes_ipv4_mapped_v6.

خرابی پرصدای لاگ ممیزی

ensure_audit_log روی هر OSError یک RuntimeError پرتاب می‌کند. روی v0.39 پین‌شده، دیمون هرگز این فایل را نمی‌نویسد (فیلد log.audit_path وجود ندارد)، پس cmd_setup خرابی را یک WARNING تلقی می‌کند (تا پیش از ارتقای نسخه، فایل تکیه‌گاهی نیست) و خط موفقیت را با عبارت «reserved» تعیین‌ویژگی می‌کند. وقتی پین به نسخه‌ای با log.audit_path منتقل شد، دوباره بررسی کنید: پیش‌ساختِ فایل برای تضمین «0o600 از اولین بایت» تکیه‌گاهی می‌شود و ویزارد باید دوباره پرصدا شکست بخورد.

محدودیت اسکیمای v0.39: log.audit_path فیلدی در ساختار config.Log در iron-proxy v0.39 نیست، پس build_proxy_config آرگومان کلیدواژه‌ای audit_log را می‌پذیرد ولی آن را در yaml خروجی صادر نمی‌کند. رکوردهای هر-درخواست در v0.39 کنار رویدادهای سطح دیمون در iron-proxy.log فرود می‌آیند. فایل audit.log همچنان با 0o600 و O_NOFOLLOW پیش‌ساخته می‌شود تا وقتی نسخهٔ پین‌شده به نسخه‌ای که جریان جداگانه را پشتیبانی می‌کند ارتقا یابد، قرارداد حریم خصوصی برقرار بماند.

تست‌های رگرسیون: test_ensure_audit_log_raises_on_immutable_parent، test_audit_log_kwarg_does_not_inject_audit_path_v039.

خرابی پرصدای حالت Bitwarden

وقتی credential_source: bitwarden باشد و proxy.allow_env_fallback: false (پیش‌فرض):

  • متغیر محیطی توکن دسترسی غایب باشد ← cmd_start امتناع می‌کند.
  • project_id غایب باشد ← cmd_start امتناع می‌کند.
  • bws secret list برای یک یا چند ارائه‌دهندهٔ نگاشت‌شده هیچ مقداری برنگرداند ← _build_proxy_subprocess_env استثنا می‌دهد.

بازگشت به env میزبان در حالت BW، دقیقاً همان باگِ کهنگی را دوباره وارد می‌کند که مسیر BW برای شکست‌دادنش ساخته شده است.

تست‌های رگرسیون: test_cmd_start_refuses_when_bitwarden_token_missing (لایهٔ CLI)؛ ادعاهای حالت سخت‌گیرانه در _build_proxy_subprocess_env (لایهٔ دیمون).

تشخیص برخورد docker_env

وقتی enforce_on_docker: true باشد، بازنویسیِ docker_env روی هر یک از متغیرهای کنترل‌کنندهٔ خروجی (HTTPS_PROXY، SSL_CERT_FILE، NODE_EXTRA_CA_CERTS و...) یا هر real_env_name نگاشت‌شده (OPENROUTER_API_KEY و...)، قبل از راه‌افتادن کانتینر یک RuntimeError برمی‌گرداند.

تست رگرسیون: test_docker_env_collision_with_proxy_raises_when_enforce.

دفاع در برابر بازیافت PID

_pid_alive قبل از اعتماد به تطبیق نام پایهٔ argv[0]، باید یا _proxy_nonce درون‌پروسسی (حالت هم‌پروسس) یا iron-proxy.nonce روی دیسک (حالت بین-CLI) را بررسی کند. stop_proxy قبل از SIGKILL باید starttime مربوط به /proc/<pid>/stat را دوباره چک کند و در صورت رانش starttime، سیگنال را سرکوب کند.

تست‌های رگرسیون: test_stop_proxy_suppresses_sigkill_on_pid_recycle، test_pid_proc_starttime_parses_comm_with_parens، test_persisted_nonce_roundtrip.

حفظ توکن‌ها در راه‌اندازی مجدد

merge_mappings(existing, discovered, rotate=False) برای ارائه‌دهنده‌های هم‌پوشان باید توکن‌های قبلی را برگرداند. اجرای دوبارهٔ hermes egress setup نباید سندباکس‌های در حال اجرا را بی‌سروصدا 401 کند. --rotate-tokens انتخابِ آگاهانهٔ صریح است.

تست‌های رگرسیون: test_merge_mappings_preserves_existing_tokens، test_merge_mappings_rotate_mints_fresh_tokens.

حفظ credential_source

cmd_setup نباید بدون پرچم صریح --no-bitwarden، در اجرای مجدد credential_source: bitwarden را به env تنزل دهد. اجرای hermes egress setup (بدون پرچم) هر چه قبلاً پیکربندی شده را حفظ می‌کند.

از طریق جریان cmd_setup در تست‌های CLI آزموده شده (مسیر حفظ bitwarden وقتی آزموده می‌شود که --from-bitwarden با یک اجرای مجددِ setup ساده دنبال شود).

۴ نقاط توسعه

افزودن یک ارائه‌دهندهٔ توکن Bearer جدید

_BEARER_PROVIDERS در iron_proxy.py نام متغیر env را به یک تاپلی از میزبان‌های بالادست نگاشت می‌کند. افزودن یک ورودی، آن را برای discover_provider_mappings() قابل‌کشف می‌کند؛ ویزارد وقتی متغیر env موجود باشد، به‌طور خودکار برایش توکن ضرب می‌کند.

_BEARER_PROVIDERS: Dict[str, Tuple[str, ...]] = {
    ...,
    "MY_PROVIDER_API_KEY": ("api.myprovider.com",),
}

_DEFAULT_ALLOWED_HOSTS را هم به‌روزرسانی کنید تا پروکسی به‌طور پیش‌فرض بالادست را مجاز بداند. برای اطمینان test_discover_provider_mappings_* را اجرا کنید.

افزودن یک ارائه‌دهندهٔ توکن هدری جدید (خانوادهٔ x-api-key)

اگر ارائه‌دهنده با یک هدرِ استاتیکِ غیر-Authorization احرازهویت می‌کند (مثل x-api-key در Anthropic، api-key در Azure، یا x-goog-api-key در Gemini)، آن را به _HEADER_AUTH_PROVIDERS بیفزایید — secrets.replace.match_headers در iron-proxy نام هدرهای دلخواه را نشانه می‌گیرد، پس این‌ها ارائه‌دهنده‌های تعویض‌شوندهٔ درجه‌یک هستند:

_HEADER_AUTH_PROVIDERS: Dict[str, Dict[str, Tuple[str, ...]]] = {
    ...,
    "MY_PROVIDER_API_KEY": {
        "hosts": ("api.myprovider.com",),
        "match_headers": ("x-my-auth-header", "Authorization"),
        "aliases": (),
    },
}

از aliases فقط برای نام‌های متغیر envِ قابل‌جایگزینِ همان اعتبارنامه استفاده کنید (مثلاً GOOGLE_API_KEY به‌جای GEMINI_API_KEY) — نام‌های مستعار در یک نگاشت واحد جمع می‌شوند، چون دو قانون require: true روی یک میزبان، درخواست‌های همدیگر را رد می‌کنند. _DEFAULT_ALLOWED_HOSTS را هم به‌روزرسانی کنید.

افزودن یک ارائه‌دهندهٔ احرازهویت امضایی جدید (بدون پوشش)

اگر ارائه‌دهنده از SigV4 / OAuth ضرب‌شده در SDK / امضای درخواست استفاده می‌کند، تعویض هدرِ استاتیک نمی‌تواند آن را پوشش دهد. متغیر env را به _NON_BEARER_PROVIDERS بیفزایید تا ویزارد و hermes egress status درباره‌اش هشدار بدهند:

_NON_BEARER_PROVIDERS: Tuple[str, ...] = (
    ...,
    "MY_SIGNED_PROVIDER_ACCESS_KEY",
)

سیم‌کشی iron-proxy در یک بک‌اند غیر-Docker

_egress_proxy_args_for_docker مخصوص Docker است. بک‌اندهایی که سیم‌کشی مشابه می‌خواهند به همتای مخصوص خودشان نیاز دارند که:

  1. load_config().get("proxy", {}) را می‌خواند؛ اگر enabled نادرست باشد آرگومان‌های خالی برمی‌گرداند.
  2. iron_proxy.get_status() را صدا می‌زند؛ معناشناسی enforce را روی مسیرهای خرابیِ configured / pid / listening / ca_cert_path آشکار می‌کند.
  3. iron_proxy.load_mappings() را صدا می‌زند؛ اگر خالی بود و enforce_on_docker: true، از سوارکردن امتناع می‌کند.
  4. هفت متغیر env را ست می‌کند (HTTPS_PROXY، NO_PROXY، REQUESTS_CA_BUNDLE، SSL_CERT_FILE، CURL_CA_BUNDLE، NODE_EXTRA_CA_CERTS، HERMES_EGRESS_PROXY) و متغیرهای HERMES_PROXY_TOKEN_<NAME> را به‌ازای هر نگاشت.
  5. گواهی CA را در مسیری که زمان اجرا به آن اعتماد می‌کند داخل سندباکس توزیع می‌کند (معمولاً /etc/ssl/certs/hermes-egress-ca.crt).
  6. تشخیص برخورد را نسبت به پیکربندی env اختصاصیِ بک‌اندِ کاربر پیاده‌سازی می‌کند.

پیاده‌سازی Docker حدود ۱۵۰ خط است؛ برای Modal / Daytona / SSH حجمی مشابه انتظار داشته باشید.

مشترک‌شدن در رویدادهای ممیزیِ هر-درخواست

iron-proxy روی v0.39ِ فعلاً پین‌شده، JSON خط-جدا شده در ~/.hermes/proxy/iron-proxy.log می‌نویسد (رکوردهای دیمون + هر-درخواست، ترکیب‌شده؛ «لاگ‌برداری در iron-proxy v0.39» را در راهنمای کاربر ببینید). یک پلاگین / ناظر بیرونی می‌تواند آن فایل را tail کند و به ردِ فهرست مجاز، تعویض رمزها یا خطاهای بالادست واکنش نشان دهد. وقتی نسخهٔ پین‌شده به نسخه‌ای ارتقا یابد که log.audit_path را پشتیبانی می‌کند، جریان هر-درخواست به audit.log منتقل می‌شود و ناظرهایی که به آن مسیر وصل‌اند بدون اقدام اپراتور زنده می‌شوند. اسکیما در docs.iron.sh/audit مستند شده است (لینک).
