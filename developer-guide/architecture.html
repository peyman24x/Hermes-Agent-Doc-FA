۳ جریان داده

نشست CLI

User input → HermesCLI.process_input()
  → AIAgent.run_conversation()
    → prompt_builder.build_system_prompt()
    → runtime_provider.resolve_runtime_provider()
    → API call (chat_completions / codex_responses / anthropic_messages)
    → tool_calls? → model_tools.handle_function_call() → loop
    → final response → display → save to SessionDB

پیام گیت‌وی

Platform event → Adapter.on_message() → MessageEvent
  → GatewayRunner._handle_message()
    → authorize user
    → resolve session key
    → create AIAgent with session history
    → AIAgent.run_conversation()
    → deliver response back through adapter

کار کرون

Scheduler tick → load due jobs from jobs.json
  → create fresh AIAgent (no history)
  → inject attached skills as context
  → run job prompt
  → deliver response to target platform
  → update job state and next_run

۴ ترتیب پیشنهادی مطالعه

اگر تازه با کدبیس آشنا شده‌اید:

  1. همین صفحه — جهت‌یابی اولیه
  2. درون‌مایهٔ حلقهٔ ایجنت — AIAgent چطور کار می‌کند
  3. ساخت پرامپت سیستمی — ساختار پرامپت سیستمی
  4. زمان اجرای ارائه‌دهنده — ارائه‌دهنده‌ها چطور انتخاب می‌شوند
  5. افزودن ارائه‌دهندهٔ جدید — راهنمای عملی افزودن یک ارائه‌دهندهٔ جدید
  6. زمان اجرای ابزارها — رجیستری ابزار، دیسپچ، محیط‌ها
  7. ذخیره‌سازی نشست — اسکیمای SQLite، FTS5، تبار نشست
  8. درون‌مایهٔ گیت‌وی — گیت‌وی پلتفرم پیام‌رسانی
  9. فشرده‌سازی و کش پرامپت — فشرده‌سازی و کش
  10. درون‌مایهٔ ACP — یکپارچگی با IDE

۵ زیرسیستم‌های اصلی

حلقهٔ ایجنت

موتور هماهنگ‌سازی همگام (AIAgent در run_agent.py). انتخاب ارائه‌دهنده، ساخت پرامپت، اجرای ابزار، تلاش مجدد، پشتیبان، کال‌بک‌ها، فشرده‌سازی و ماندگاری را مدیریت می‌کند. از سه حالت API برای بک‌اندهای مختلف ارائه‌دهنده پشتیبانی می‌کند.

→ درون‌مایهٔ حلقهٔ ایجنت

سیستم پرامپت

ساخت و نگهداری پرامپت در طول چرخهٔ حیات گفتگو:

  • system_prompt.py + prompt_builder.py — طبقات مرتبِ پرامپت سیستمی را مونتاژ می‌کند (stable → context → volatile): هویت/راهنمای ابزار/مهارت‌ها، فایل‌های زمینه، و سپس بلوک‌های حافظه/پروفایل/زمان
  • prompt_caching.py — نقاط شکست کش Anthropic را برای کش پیشوندی اعمال می‌کند
  • context_compressor.py — وقتی زمینه از آستانه بگذرد، نوبت‌های میانی گفتگو را خلاصه می‌کند

→ ساخت پرامپت سیستمی، فشرده‌سازی و کش پرامپت

تشخیص ارائه‌دهنده

یک resolver مشترکِ زمان اجرا که CLI، گیت‌وی، کرون، ACP و فراخوانی‌های کمکی از آن استفاده می‌کنند. تاپل‌های (provider, model) را به (api_mode, api_key, base_url) نگاشت می‌کند. بیش از ۱۸ ارائه‌دهنده، جریان‌های OAuth، مخازن اعتبارنامه و resolve نام‌های مستعار را مدیریت می‌کند.

→ زمان اجرای ارائه‌دهنده

سیستم ابزار

رجیستری مرکزی ابزار (tools/registry.py) با بیش از ۷۰ ابزار ثبت‌شده در حدود ۲۸ تول‌ست. هر فایل ابزار در زمان import خودش را ثبت می‌کند. رجیستری جمع‌آوری اسکیما، دیسپچ، بررسی دسترس‌پذیری و بسته‌بندی خطا را انجام می‌دهد. ابزارهای ترمینال از ۷ بک‌اند پشتیبانی می‌کنند (local، Docker، SSH، Daytona، Modal، Singularity، Vercel Sandbox).

→ زمان اجرای ابزارها

ماندگاری نشست

ذخیره‌سازی نشست مبتنی بر SQLite با جستجوی تمام‌متن FTS5. نشست‌ها ردیابی تبار دارند (والد/فرزند در میان فشرده‌سازی‌ها)، ایزوله‌سازی به تفکیک پلتفرم و نوشتن اتمیک با مدیریت تنازع دارند.

→ ذخیره‌سازی نشست

گیت‌وی پیام‌رسانی

پروسس بلندمدت با بیش از ۲۵ آداپتور پلتفرم (داخلی + پلاگین‌های همراه)، مسیریابی یکپارچهٔ نشست، مجوزدهی کاربر (فهرست مجاز + جفت‌سازی DM)، دیسپچ فرمان‌های اسلش، سیستم هوک، تیک کرون و نگهداری پس‌زمینه‌ای.

→ درون‌مایهٔ گیت‌وی

سیستم پلاگین

سه منبع کشف: ~/.hermes/plugins/ (کاربر)، .hermes/plugins/ (پروژه) و entry pointهای pip. پلاگین‌ها ابزارها، هوک‌ها و فرمان‌های CLI را از طریق یک context API ثبت می‌کنند. دو نوع پلاگین تخصصی وجود دارد: ارائه‌دهندگان حافظه (plugins/memory/) و موتورهای زمینه (plugins/context_engine/). هر دو تک‌انتخابی‌اند — در هر لحظه فقط یکی از هر نوع می‌تواند فعال باشد و از طریق hermes plugins یا config.yaml پیکربندی می‌شوند.

→ راهنمای پلاگین، پلاگین ارائه‌دهندهٔ حافظه

کرون

کارهای ایجنتیِ درجه‌یک (نه کارهای شل). کارها در JSON ذخیره می‌شوند، از چند قالب زمان‌بندی پشتیبانی می‌کنند، می‌توانند مهارت و اسکریپت پیوست داشته باشند و به هر پلتفرمی تحویل بدهند.

→ درون‌مایهٔ Cron

یکپارچگی ACP

هرمس را برای VS Code، Zed و JetBrains به‌شکل ایجنتی بومیِ ادیتور از طریق stdio/JSON-RPC در دسترس می‌گذارد.

→ درون‌مایهٔ ACP

ترایکتوری‌ها

ترایکتوری‌های قالب ShareGPT را از نشست‌های ایجنت برای تولید دادهٔ آموزشی تولید می‌کند.

→ قالب Trajectory

۶ اصول طراحی

اصلمعنای عملی آن
پایداری پرامپتپرامپت سیستمی وسط گفتگو تغییر نمی‌کند. هیچ جهشِ کش‌شکنی به‌جز اقدام صریح کاربر (/model) وجود ندارد.
اجرای قابل‌مشاهدههر فراخوانی ابزار از طریق کال‌بک‌ها برای کاربر دیده می‌شود. به‌روزرسانی پیشرفت در CLI (اسپینر) و گیت‌وی (پیام‌های چت).
قابل‌وقفهفراخوانی‌های API و اجرای ابزار را می‌توان وسط کار با ورودی کاربر یا سیگنال‌ها لغو کرد.
هستهٔ مستقل از پلتفرمیک کلاس AIAgent به CLI، گیت‌وی، ACP، batch و سرور API سرویس می‌دهد. تفاوت‌های پلتفرم در نقطهٔ ورود زندگی می‌کنند، نه در ایجنت.
اتصال سستزیرسیستم‌های اختیاری (MCP، پلاگین‌ها، ارائه‌دهندگان حافظه، محیط‌های RL) از الگوهای رجیستری و گیتِ check_fn استفاده می‌کنند، نه وابستگی سخت.
ایزوله‌سازی پروفایلهر پروفایل (hermes -p <name>) HERMES_HOME، پیکربندی، حافظه، نشست‌ها و PID گیت‌وی مخصوص خودش را دارد. چند پروفایل هم‌زمان اجرا می‌شوند.

۷ زنجیرهٔ وابستگی فایل‌ها

tools/registry.py  (no deps — imported by all tool files)
       ↑
tools/*.py  (each calls registry.register() at import time)
       ↑
model_tools.py  (imports tools/registry + triggers tool discovery)
       ↑
run_agent.py, cli.py, batch_runner.py, environments/

این زنجیره یعنی ثبت ابزارها در زمان import اتفاق می‌افتد، قبل از اینکه هر نمونهٔ ایجنتی ساخته شود. هر فایل tools/*.py که فراخوانی سطح‌بالای registry.register() داشته باشد خودکار کشف می‌شود — نیازی به فهرست import دستی نیست.
