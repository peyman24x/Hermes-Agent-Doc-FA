پلاگین منبع رمز

منابع رمز، اعتبارنامه‌های ارائه‌دهنده را هنگام آغاز فرایند از مدیر رمز خارجی (خزانه، مدیر گذرواژه، مخزن کلید سیستم‌عامل یا اسکریپت سفارشی) به متغیرهای محیطی تبدیل می‌کنند — پس از بارگذاری ~/.hermes/.env و پیش از خواندن اعتبارنامه‌ها توسط هرمس. Bitwarden، 1Password و منبع عمومیِ کمک‌فرمان در درخت پروژه عرضه می‌شوند؛ هر بک‌اند دیگری یک پلاگین است. این راهنما ساخت چنین پلاگینی را پوشش می‌دهد.

نکته

مجموعهٔ همراه عمداً بسته است، با همان سیاست ارائه‌دهندگان حافظه: PRهایی که بک‌اند خزانهٔ جدیدی زیر agent/secret_sources/ اضافه کنند، با ارجاع به این راهنما بسته می‌شوند. بک‌اند خود را به‌عنوان مخزن مستقل پلاگین منتشر کنید و در Discord مربوط به Nous Research (#plugins-skills-and-skins) به اشتراک بگذارید.

۱ زمان‌بندی راه‌اندازی اولیهٔ نخستین فرایند

load_hermes_dotenv() اغلب هنگام ایمپورت و پیش از ثبت پلاگین‌ها اجرا می‌شود. سپس هرمس، اگر منبع رمز پلاگینِ فعالی پیکربندی شده باشد، پس از کشف پلاگین‌ها رمزها را دوباره می‌گیرد. فعال‌بودن بر اساس قرارداد is_enabled(cfg) منبع تعیین می‌شود؛ شکل استاندارد secrets.<name>.enabled: true است، اما فعال‌سازی سفارشی هم پشتیبانی می‌شود. این کار شکاف نخستین فرایند در «جایگزینی Bitwarden با خزانهٔ خودم» را رفع می‌کند (#64177).

  • دریافت دوباره هم‌توان (idempotent) است و در صورت شکست راه را باز می‌گذارد (fail-open)؛ هرگز مانع آغاز کار نمی‌شود.
  • منابع تنها از طریق هماهنگ‌کننده متغیرهای محیطی را تأمین می‌کنند؛ هیچ API پلاگینی برای تخلیهٔ تمام مخزن رمز کاربر یا پلاگین‌های دیگر، فراتر از آنچه پیکربندی خود منبع اجازه می‌دهد، وجود ندارد.
  • خواندن os.environ پس از بارگذاری برای هر کد درون‌فرایندی ممکن است — مرز اعتماد همچنان «پلاگین‌های فعال با اختیارات ایجنت اجرا می‌شوند» است.

۲ مسئولیت چارچوب در برابر مسئولیت شما

هماهنگ‌کننده (agent.secret_sources.registry.apply_all) تمام امور حساس به امنیت و تقدم را بر عهده دارد تا بک‌اند نتواند آن‌ها را اشتباه انجام دهد:

۴ کلاس پایهٔ انتزاعی SecretSource

agent.secret_sources.base.SecretSource را پیاده‌سازی کنید. یک متد الزامی است:

from pathlib import Path

from agent.secret_sources.base import (
    ErrorKind,
    FetchResult,
    SecretSource,
    run_secret_cli,
)


class MyVaultSource(SecretSource):
    name = "myvault"          # config section key: secrets.myvault
    label = "My Vault"        # used in startup lines + provenance labels
    shape = "mapped"          # "mapped" (explicit VAR→ref map) or "bulk" (project dump)
    scheme = "mv"             # optional: unique URI scheme you own (mv://...)

    def fetch(self, cfg: dict, home_path: Path) -> FetchResult:
        """Resolve secrets. MUST NOT raise. MUST NOT prompt."""
        result = FetchResult()
        token = os.environ.get("MYVAULT_TOKEN", "").strip()
        if not token:
            result.error = "secrets.myvault.enabled is true but MYVAULT_TOKEN is not set."
            result.error_kind = ErrorKind.NOT_CONFIGURED
            return result

        try:
            proc = run_secret_cli(
                ["myvault-cli", "export", "--json"],
                allow_env=["MYVAULT_TOKEN"],   # ONLY your auth vars — never full os.environ
                timeout=30,
            )
        except RuntimeError as exc:           # spawn failure / timeout
            result.error = str(exc)
            result.error_kind = ErrorKind.BINARY_MISSING
            return result

        if proc.returncode != 0:
            result.error = f"myvault-cli exited {proc.returncode}: {proc.stderr[:200]}"
            result.error_kind = ErrorKind.AUTH_FAILED
            return result

        result.secrets = parse_your_output(proc.stdout)  # {ENV_VAR: value}
        return result

    def protected_env_vars(self, cfg: dict):
        # Your bootstrap token — no source (including yours) may ever overwrite it.
        return frozenset({"MYVAULT_TOKEN"})

قواعد قرارداد (اعمال می‌شوند، پیشنهاد نیستند)

  • fetch() هرگز استثنا ایجاد نمی‌کند. خطاها در result.error + result.error_kind قرار می‌گیرند. دریافتِ استثنازا توسط هماهنگ‌کننده مهار و به‌عنوان INTERNAL گزارش می‌شود — نقض قرارداد است، نه قابلیت.
  • fetch() هرگز ورودی تعاملی نمی‌خواهد. آغاز کار در زمینه‌های بدون TTY (گیت‌وی، کرون، Docker) انجام می‌شود. run_secret_cli() ورودی استاندارد را می‌بندد تا کمک‌فرمانی که سؤال می‌پرسد سریع شکست بخورد. احراز هویت تعاملی متعلق به جریان راه‌اندازی CLI شما است، نه مسیر آغاز کار.
  • همگام و در محدودهٔ زمان. هماهنگ‌کننده مهلت زمان واقعی را اعمال می‌کند (پیش‌فرض ۱۲۰ ثانیه، قابل‌تنظیم توسط کاربر از طریق secrets.<name>.timeout_seconds). عبور از آن TIMEOUT گزارش می‌کند و نتیجهٔ شما دور ریخته می‌شود.
  • شما می‌گیرید؛ هماهنگ‌کننده اعمال می‌کند. نگاشتی را برگردانید که قرار است ارائه دهید. هرگز خودتان در os.environ ننویسید — تقدم، تشخیص تعارض و منشأ را دور می‌زنید.
  • نسخه‌بندی API. پیش‌فرض SecretSource.api_version نسخهٔ فعلی SECRET_SOURCE_API_VERSION است. رجیستری به‌جای ازکارانداختن آغاز کار، منابع ساخته‌شده برای نسخه‌ای متفاوت را با هشدار رد می‌کند.

انتخاب shape

  • mapped — کاربر نام متغیرهای محیطی را صریحاً در پیکربندی به ارجاع‌ها متصل می‌کند (مانند نگاشت env: در 1Password). صریح‌ترین قصد: در متغیرهای مورد اختلاف، ادعای نگاشتی بر ادعای انبوه مقدم است.
  • bulk — یک پروژه/پوشهٔ کامل از رمزها را ضمنی تزریق می‌کنید (مانند Bitwarden BSM). به منابع نگاشتی تقدم می‌دهد.

۵ ایمنی زیرفرایند: از run_secret_cli() استفاده کنید

اگر بک‌اند شما CLI اجرا می‌کند، به‌جای استفادهٔ مستقیم از subprocess.run از کمک‌تابع مشترک استفاده کنید. وضعیت ممیزی‌شده را بدون کار اضافه فراهم می‌کند: فقط argv (بدون shell=True)، محیط حداقلیِ فرزند با فهرست مجاز (هنگام اجرای منابع، os.environ تمام اعتبارنامه‌های شناخته‌شدهٔ هرمس را دارد — هرگز آن را به فرایند فرزند ندهید)، NO_COLOR و stderr پاک‌شده از ANSI، ورودی استاندارد بسته، و تبدیل پایان مهلت به RuntimeError تمیز. رشته‌های ارجاعِ ارائه‌شده توسط کاربر را پس از پایان‌دهندهٔ -- در argv قرار دهید تا هرگز به‌عنوان پرچم تجزیه نشوند.

۶ ثبت

# __init__.py
def register(ctx):
    ctx.register_secret_source(MyVaultSource())

ثبت در این موارد رد می‌شود (با هشدار لاگ، هرگز کرش): نمونه‌هایی غیر از SecretSource، نام نامعتبر/تکراری، scheme متعلق به منبع دیگر، api_version نادرست یا shape خارج از mapped/bulk.

زمان‌بندی

کشف پلاگین در آغاز کار دیرتر از اولین فراخوانی load_hermes_dotenv() اجرا می‌شود. بلافاصله پس از کشف، هرمس منابع رمز فعالِ پلاگین را دوباره می‌گیرد (reset_secret_source_cache() + load_hermes_dotenv())؛ بنابراین فرایند کاشف واقعاً آن‌ها را دریافت می‌کند — زمان‌بندی راه‌اندازی اولیهٔ نخستین فرایند در بالا را ببینید (#64177). دریافت دوباره در صورت خطا مانع کار نمی‌شود و وقتی هیچ منبع پلاگینی فعال نیست، رد می‌شود. هر کدی که هنگام ایمپورت ماژول پلاگین یا register(ctx) مقدار os.environ را بخواند، همچنان پیش از دریافت دوباره اجرا می‌شود و نمی‌تواند به اعتبارنامه‌های همان منبع متکی باشد؛ کار نیازمند اعتبارنامه را داخل fetch() نگه دارید. فرایندهای گیت‌وی، کرون و ساب‌ایجنت همین توالی کشف/دریافت دوباره را اجرا می‌کنند.

۷ کاربران آن را مانند هر منبع دیگری پیکربندی می‌کنند

secrets:

  myvault:
    enabled: true
    # ... your config_schema keys

تقدم چندمنبعی، هشدارهای تعارض و برچسب‌های منشأ (from My Vault) همگی خودکار کار می‌کنند — برای سلسله‌مراتب تقدم، مستندات رمزها برای کاربران را ببینید.

۸ اعتبارسنجی با مجموعهٔ آزمون انطباق

در تست‌های پلاگین خود از کلاس مجموعهٔ آزمون مخزن هرمس (tests/secret_sources/conformance.py) ارث‌بری کنید:

import pytest
from tests.secret_sources.conformance import SecretSourceConformance

class TestMyVaultConformance(SecretSourceConformance):
    @pytest.fixture
    def source(self):
        return MyVaultSource()

این مجموعه قواعدی را بررسی می‌کند که نقضشان دیگران را دچار مشکل می‌کند: عدم ایجاد استثنا برای پیکربندی بدشکل، انواع خطای ماشین‌خوان، غیرفعال‌بودن پیش‌فرض، مهلت‌های مثبت، نام معتبر متغیرهای محافظت‌شده و رفت‌وبرگشت کامل apply_all(). سبزشدن آزمون انطباق معیار بازبینی برای نامیدن بک‌اند به‌عنوان منطبق با قرارداد است.
