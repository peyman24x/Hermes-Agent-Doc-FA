API عمومی چرخهٔ حیات ساب‌ایجنت

پلاگین‌ها می‌توانند نشست‌های فرزندِ تازهٔ هرمس را بدون ایمپورت tools.delegate_tool، درون‌مایهٔ گیت‌وی، وضعیت TUI یا فیلدهای AIAgent راه بیندازند و تحت نظارت داشته باشند. این سرویس والدش را از نوبتِ فعلی ایجنت پیدا می‌کند، پس در نشست‌های CLI، گیت‌وی، غیرتعاملی و کارگر کانبان کار می‌کند. راه‌اندازی خارج از یک نوبت فعال ایجنت با No active Hermes parent session به‌شکل ایمن شکست می‌خورد.

from agent.subagent_lifecycle import SubagentLaunchRequest

def launch_review(ctx):
    # Call from a plugin tool or hook while an agent turn is active.
    service = ctx.subagent_lifecycle
    handle = service.launch(SubagentLaunchRequest(
        goal="Review this change for regressions.",
        context="Only inspect the supplied repository.",
        role="leaf",
        correlation_id="review-42",
        allowed_toolsets=("file",),
    ))
    # Persist handle.to_dict() if desired.
    if service.wait(handle, timeout_seconds=2).timed_out:
        return handle.to_dict()
    return service.result(handle)

SubagentHandle سریال‌پذیر است و یک قابلیت ماتِ نسخه‌دار با خود حمل می‌کند. آن را به status، ‏wait، ‏cancel، ‏result یا reconnect پس بدهید؛ هندل‌های بدشکل یا جعلی UNKNOWN/UNKNOWN_HANDLE برمی‌گردانند و به فرزند دسترسی ندارند.

وضعیت‌های پایدار عبارت‌اند از PENDING، ‏STARTING، ‏RUNNING، ‏SUCCEEDED، ‏FAILED، ‏INTERRUPTED، ‏CANCEL_REQUESTED، ‏CANCELLED و UNKNOWN.

‏cancel(handle, reason=...) مشارکتی است: از ایجنتِ فرزند می‌خواهد در بعدی مرزِ امن وقفه بیندازد و CANCEL_REQUESTED برمی‌گرداند؛ تا وقتی wait یا result یک وضعیت پایانی را مشاهده نکرده، هرگز تکمیل‌شدن را ادعا نمی‌کند. نتایج پایانی تغییرناپذیرند، ایدمپوتنت‌اند، به ۳۲هزار کاراکتر محدودند، رونوشت گفتگو و استدلال‌های پنهان را حذف می‌کنند و یک هشِ نتیجهٔ پایدار دارند.

این API اجرای ناهمگامِ مدیریت‌شدهٔ چرخهٔ حیات است. ساختِ فرزند و تکمیلش از همان مسیرِ متعلق به میزبانِ delegate_task استفاده می‌کند — شامل بازگردانی تفکیک ابزارِ والد، اعلان حافظه، هوک‌های سریال‌شدهٔ subagent_stop، پاک‌سازی منابع و تجمیع هزینهٔ فرزند. ابزارِ همگامِ delegate_task، واگذاری دسته‌ای یا نمایش گیت‌وی/TUI آن را تغییر نمی‌دهد. پیاده‌سازی اولیه فراداده و نتایج پایانی را به‌مدت یک ساعت درون همان فرایند نگه می‌دارد.

بعد از ری‌استارت فرایند، reconnect مقدار RECONNECT_UNAVAILABLE برمی‌گرداند و هرگز فرزندِ جایگزینی راه نمی‌اندازد. تردهای پایتونِ در حال اجرا هم نمی‌توانند از خروج فرایند جان سالم ببرند؛ فراخوان‌ها باید آن هندل‌ها را «قطع‌شده به‌دلیل خروج فرایند» ببینند.

درخواست‌ها fail-closed هستند: اندازهٔ goal/context/فراداده سقف دارد، تول‌ست‌های ناشناخته یا گسترش‌دهندهٔ اختیاراتِ والد رد می‌شوند و بلوک‌های per-tool، بازنویسی‌های پوشهٔ کاری و تایم‌اوت‌های per-launch صریحاً رد می‌شوند تا هرمس بتواند بدون تضعیف ایزوله‌سازی از آن‌ها پشتیبانی کند. از allowed_toolsets برای محدود کردن فرزند استفاده کنید؛ بلوکِ ابزارهای ناامنِ فعلی هرمس همچنان برقرار است.
