ساخت مهارت

مهارت‌ها روش ترجیحی برای افزودن قابلیت‌های جدید به Hermes Agent هستند. ساختنشان از ابزارها آسان‌تر است، هیچ تغییری در کد ایجنت نمی‌خواهند و می‌توانشان را با جامعه به اشتراک گذاشت.

۱ مهارت باشد یا ابزار؟

آن را مهارت بسازید وقتی:

  • قابلیت بتواند به‌شکل دستورالعمل + فرمان‌های شل + ابزارهای موجود بیان شود
  • یک CLI یا API بیرونی را بسته‌بندی کند که ایجنت بتواند از طریق terminal یا web_extract صدا بزند
  • نیازی به یکپارچه‌سازی پایتونِ سفارشی یا مدیریت کلید API داخل خود ایجنت ندارد
  • مثال‌ها: جستجوی arXiv، گردش‌کارهای git، مدیریت Docker، پردازش PDF، ایمیل با ابزارهای CLI

آن را ابزار بسازید وقتی:

  • به یکپارچه‌سازی سرتاسری با کلیدهای API، جریان‌های احراز هویت یا پیکربندی چندجزئی نیاز دارد
  • منطق پردازش سفارشی می‌خواهد که باید هر بار دقیقاً اجرا شود
  • دادهٔ دودویی، استریم یا رخدادهای بی‌درنگ را مدیریت می‌کند
  • مثال‌ها: اتوماسیون مرورگر، TTS، تحلیل بینایی

۲ ساختار پوشهٔ مهارت

مهارت‌های همراه در skills/ به تفکیک دسته زندگی می‌کنند. مهارت‌های اختیاریِ رسمی همین ساختار را در optional-skills/ دارند:

skills/
├── research/
│   └── arxiv/
│       ├── SKILL.md              # الزامی: دستورالعمل‌های اصلی
│       └── scripts/              # اختیاری: اسکریپت‌های کمکی
│           └── search_arxiv.py
├── productivity/
│   └── ocr-and-documents/
│       ├── SKILL.md
│       ├── scripts/
│       └── references/
└── ...

۳ قالب SKILL.md

name: my-skill
description: Brief description (shown in skill search results)
version: 1.0.0
author: Your Name
license: MIT
platforms: [macos, linux]          # اختیاری — محدود به پلتفرم‌های سیستمی خاص
                                   #   معتبر: macos, linux, windows
                                   #   برای بارگیری روی همهٔ پلتفرم‌ها حذفش کنید (پیش‌فرض)
metadata:
  hermes:
    tags: [Category, Subcategory, Keywords]
    related_skills: [other-skill-name]
    requires_toolsets: [web]            # اختیاری — فقط وقتی این تول‌ست‌ها فعال‌اند نشان بده
    requires_tools: [web_search]        # اختیاری — فقط وقتی این ابزارها در دسترس‌اند نشان بده
    fallback_for_toolsets: [browser]    # اختیاری — وقتی این تول‌ست‌ها فعال‌اند پنهان کن
    fallback_for_tools: [browser_navigate]  # اختیاری — وقتی این ابزارها موجودند پنهان کن
    config:                              # اختیاری — تنظیمات config.yaml که مهارت لازم دارد
      - key: my.setting
        description: "What this setting controls"
        default: "sensible-default"
        prompt: "Display prompt for setup"
    blueprint:                              # اختیاری — این مهارت را به‌عنوان اتوماسیون قابل‌اجرا علامت می‌زند
      schedule: "0 9 * * *"              #   عبارت کرون / "every 2h" / مهرزمان ISO
      deliver: origin                    #   اختیاری (پیش‌فرض origin)
      prompt: "Task instruction for each run"  # اختیاری
      no_agent: false                    # اختیاری
required_environment_variables:          # اختیاری — متغیرهای محیطی که مهارت لازم دارد
  - name: MY_API_KEY
    prompt: "Enter your API key"
    help: "Get one at https://example.com"
    required_for: "API access"

# Skill Title

Brief intro.

## When to Use
Trigger conditions — when should the agent load this skill?

## Quick Reference
Table of common commands or API calls.

## Procedure
Step-by-step instructions the agent follows.

## Pitfalls
Known failure modes and how to handle them.

## Verification
How the agent confirms it worked.

مهارت‌های مخصوص پلتفرم

مهارت‌ها می‌توانند خودشان را با فیلد platforms به سیستم‌عامل‌های خاص محدود کنند:

platforms: [macos]            # فقط macOS (مثلاً iMessage، Apple Reminders)
platforms: [macos, linux]     # macOS و لینوکس
platforms: [windows]          # فقط ویندوز

وقتی ست شده باشد، مهارت روی پلتفرم‌های ناسازگار به‌طور خودکار از پرامپت سیستمی، skills_list() و فرمان‌های اسلش پنهان می‌شود. اگر حذف یا خالی باشد، مهارت روی همهٔ پلتفرم‌ها بارگیری می‌شود (سازگار با رفتار قبلی).

فعال‌سازی شرطی مهارت

مهارت‌ها می‌توانند وابستگی به ابزارها یا تول‌ست‌های خاص را اعلام کنند. این کنترل می‌کند که مهارت در پرامپت سیستمیِ یک نشست معیّن ظاهر شود یا نه.

metadata:
  hermes:
    requires_toolsets: [web]           # پنهان کن اگر تول‌ست وب فعال نیست
    requires_tools: [web_search]       # پنهان کن اگر ابزار web_search در دسترس نیست
    fallback_for_toolsets: [browser]   # پنهان کن اگر تول‌ست مرورگر فعال است
    fallback_for_tools: [browser_navigate]  # پنهان کن اگر browser_navigate در دسترس است
فیلدرفتار
requires_toolsetsمهارت وقتی هر یک از تول‌ست‌های فهرست‌شده در دسترس نباشد، پنهان است
requires_toolsمهارت وقتی هر یک از ابزارهای فهرست‌شده در دسترس نباشد، پنهان است
fallback_for_toolsetsمهارت وقتی هر یک از تول‌ست‌های فهرست‌شده در دسترس باشد، پنهان است
fallback_for_toolsمهارت وقتی هر یک از ابزارهای فهرست‌شده در دسترس باشد، پنهان است

کاربرد fallback_for_*: مهارتی بسازید که وقتی ابزار اصلی در دسترس نیست، راه دورزیدنِ جایگزین فراهم کند. برای مثال، مهارت duckduckgo-search با fallback_for_tools: [web_search] فقط وقتی نشان داده می‌شود که ابزار جستجوی وب (که به کلید API نیاز دارد) پیکربندی نشده باشد.

کاربرد requires_*: مهارتی بسازید که فقط در حضور ابزارهای خاص معنا پیدا می‌کند. برای مثال، مهارت گردش‌کار وب‌اسکرپ با requires_toolsets: [web] وقتی ابزارهای وب غیرفعال‌اند، پرامپت را شلوغ نمی‌کند.

الزامات متغیرهای محیطی

مهارت‌ها می‌توانند متغیرهای محیطی موردنیازشان را اعلام کنند. وقتی مهارتی از طریق skill_view بارگیری می‌شود، متغیرهای الزامی‌اش به‌طور خودکار برای گذر به محیط‌های اجرای سندباکس‌شده (terminal، execute_code) ثبت می‌شوند.

required_environment_variables:
  - name: TENOR_API_KEY
    prompt: "Tenor API key"               # هنگام پرامپت‌گرفتن از کاربر نشان داده می‌شود
    help: "Get your key at https://tenor.com"  # متن راهنما یا URL
    required_for: "GIF search functionality"   # چه چیزی به این متغیر نیاز دارد

هر مدخل از این‌ها پشتیبانی می‌کند:

  • name (الزامی) — نام متغیر محیطی
  • prompt (اختیاری) — متن پرامپت هنگام درخواست مقدار از کاربر
  • help (اختیاری) — متن راهنما یا URL برای به‌دست‌آوردن مقدار
  • required_for (اختیاری) — توضیح می‌دهد کدام قابلیت به این متغیر نیاز دارد

کاربران می‌توانند متغیرهای گذر را دستی هم در config.yaml پیکربندی کنند:

terminal:
  env_passthrough:
    - MY_CUSTOM_VAR
    - ANOTHER_VAR

برای نمونه‌های مهارت‌های مخصوص macOS به skills/apple/ نگاه کنید.

۴ راه‌اندازی امن هنگام بارگیری

وقتی مهارتی به کلید API یا توکن نیاز دارد، از required_environment_variables استفاده کنید. نبودِ مقدارها مهارت را از کشف پنهان نمی‌کند. در عوض، هرمس وقتی مهارت در CLI محلی بارگیری می‌شود، آن‌ها را به‌شکل امن پرامپت می‌کند.

required_environment_variables:
  - name: TENOR_API_KEY
    prompt: Tenor API key
    help: Get a key from https://developers.google.com/tenor
    required_for: full functionality

کاربر می‌تواند از راه‌اندازی عبور کند و مهارت را همچنان بارگیری کند. هرمس هرگز مقدار خامِ رمز را به مدل نشان نمی‌دهد. گیت‌وی و نشست‌های پیام‌رسانی به‌جای جمع‌آوری رمزها درون باند، راهنمای راه‌اندازی محلی نشان می‌دهند.

💡 گذر به سندباکس

وقتی مهارت شما بارگیری می‌شود، هر required_environment_variables اعلام‌شده‌ای که ست شده باشد به‌طور خودکار گذر داده می‌شود به سندباکس‌های execute_code و terminal — از جمله بک‌اندهای راه دور مثل Docker و Modal. اسکریپت‌های مهارت شما می‌توانند به $TENOR_API_KEY (یا os.environ["TENOR_API_KEY"] در پایتون) دسترسی داشته باشند، بدون آن‌که کاربر لازم باشد چیز اضافه‌ای پیکربندی کند. جزئیات را در عبور متغیرهای محیطی ببینید.

prerequisites.env_vars قدیمی هم به‌عنوان نام مستعار سازگار با گذشته پشتیبانی می‌شود.

تنظیمات پیکربندی (config.yaml)

مهارت‌ها می‌توانند تنظیمات غیررمزی را اعلام کنند که در config.yaml زیر فضای‌نام skills.config ذخیره می‌شوند. برخلاف متغیرهای محیطی (که رمزهایی ذخیره‌شده در .env هستند)، تنظیمات پیکربندی برای مسیرها، ترجیحات و دیگر مقادیر غیرحساس است.

metadata:
  hermes:
    config:
      - key: myplugin.path
        description: Path to the plugin data directory
        default: "~/myplugin-data"
        prompt: Plugin data directory path
      - key: myplugin.domain
        description: Domain the plugin operates on
        default: ""
        prompt: Plugin domain (e.g., AI/ML research)

هر مدخل از این‌ها پشتیبانی می‌کند:

  • key (الزامی) — دات‌پَثِ تنظیم (مثلاً myplugin.path)
  • description (الزامی) — توضیح می‌دهد تنظیم چه چیزی را کنترل می‌کند
  • default (اختیاری) — مقدار پیش‌فرض اگر کاربر پیکربندی‌اش نکند
  • prompt (اختیاری) — متن پرامپتی که در hermes config migrate نشان داده می‌شود؛ در نبودش به description برمی‌گردد

چطور کار می‌کند:

  1. ذخیره‌سازی: مقدارها در config.yaml زیر skills.config.<key> نوشته می‌شوند: 
    skills:
  config:
    myplugin:
      path: ~/my-data
  2. کشف: hermes config migrate همهٔ مهارت‌های فعال را اسکن می‌کند، تنظیمات پیکربندی‌نشده را پیدا می‌کند و از کاربر پرامپت می‌گیرد. تنظیمات همچنین در hermes config show زیر «Skill Settings» دیده می‌شوند.
  3. تزریق در زمان اجرا: وقتی مهارتی بارگیری می‌شود، مقدارهای پیکربندی‌اش resolve و به پیام مهارت افزوده می‌شوند: 
    [Skill config (from ~/.hermes/config.yaml):
  myplugin.path = /home/user/my-data
]

    ایجنت مقدارهای پیکربندی‌شده را می‌بیند، بدون آن‌که لازم باشد خود config.yaml را بخواند.

  4. راه‌اندازی دستی: کاربران می‌توانند مقدارها را مستقیم هم ست کنند: 
    hermes config set skills.config.myplugin.path ~/my-data
💡 کدام را کجا استفاده کنیم

برای کلیدهای API، توکن‌ها و دیگر رمزها از required_environment_variables استفاده کنید (در ~/.hermes/.env ذخیره می‌شوند و هرگز به مدل نشان داده نمی‌شوند). برای مسیرها، ترجیحات و تنظیمات غیرحساس از config استفاده کنید (در config.yaml ذخیره می‌شوند و در config show دیده می‌شوند).

الزامات فایل‌های اعتبارنامه (توکن‌های OAuth و مانند آن)

مهارت‌هایی که از OAuth یا اعتبارنامه‌های فایل‌محور استفاده می‌کنند می‌توانند فایل‌هایی را اعلام کنند که باید به سندباکس‌های راه دور mount شوند. این برای اعتبارنامه‌هایی است که به‌شکل فایل ذخیره شده‌اند (نه متغیر محیطی) — معمولاً فایل‌های توکن OAuth که یک اسکریپت راه‌اندازی تولید می‌کند.

required_credential_files:
  - path: google_token.json
    description: Google OAuth2 token (created by setup script)
  - path: google_client_secret.json
    description: Google OAuth2 client credentials

هر مدخل از این‌ها پشتیبانی می‌کند:

  • path (الزامی) — مسیر فایل نسبت به ~/.hermes/
  • description (اختیاری) — توضیح می‌دهد فایل چیست و چطور ساخته می‌شود

هنگام بارگیری، هرمس وجود این فایل‌ها را بررسی می‌کند. فایل‌های غایب setup_needed را فعال می‌کنند. فایل‌های موجود به‌طور خودکار:

  • به‌شکل bind mount فقط‌خواندنی به کانتینرهای Docker mount می‌شوند
  • به سندباکس‌های Modal همگام‌سازی می‌شوند (هنگام ساخت + قبل از هر فرمان، تا OAuth وسط نشست کار کند)
  • روی بک‌اند محلی بدون هیچ مدیریت خاصی در دسترس‌اند
💡 کدام را کجا استفاده کنیم

برای کلیدها و توکن‌های سادهٔ API (رشته‌هایی که در ~/.hermes/.env ذخیره می‌شوند) از required_environment_variables استفاده کنید. برای فایل‌های توکن OAuth، client secretها، JSON حساب سرویس، گواهی‌ها یا هر اعتبارنامه‌ای که روی دیسک فایل است، از required_credential_files استفاده کنید.

برای یک مثال کامل که از هر دو استفاده می‌کند، به skills/productivity/google-workspace/SKILL.md نگاه کنید.

۵ رهنمودهای مهارت

بدون وابستگی خارجی

پایتون استاندارد (stdlib)، curl و ابزارهای موجود هرمس (web_extract، terminal، read_file) را ترجیح بدهید. اگر وابستگی لازم شد، گام‌های نصب را داخل خود مهارت مستند کنید.

افشای تدریجی

رایج‌ترین گردش‌کار را اول بگذارید. حالت‌های مرزی و کاربرد پیشرفته پایین می‌روند. این کار مصرف توکن را برای کارهای رایج پایین نگه می‌دارد.

اسکریپت‌های کمکی را بگنجانید

برای تجزیهٔ XML/JSON یا منطق پیچیده، اسکریپت‌های کمکی را در scripts/ بگنجانید — توقع نداشته باشید LLM هر بار پارسر را درون‌خطی بنویسد.

تحویل رسانه به‌شکل سند ([[as_document]])

اگر مهارت شما اسکرین‌شات با وضوح بالا، نمودار یا هر تصویری تولید می‌کند که فشرده‌سازی پیش‌نمایشِ اتلافی به آن ضربه می‌زند — دایرکتیوِ واقعیِ [[as_document]] را جایی در پاسخ صادر کنید (معمولاً آخرین خط). گیت‌وی دایرکتیو را حذف می‌کند و هر مسیر رسانهٔ استخراج‌شده در آن پاسخ را به‌جای حباب تصویر درون‌خطی، به‌شکل پیوست فایلِ قابل‌دانلود تحویل می‌دهد. برای معناشناسی کامل به خروجی مهارت و تحویل رسانه نگاه کنید.

ارجاع به اسکریپت‌های همراه از داخل SKILL.md

وقتی مهارتی بارگیری می‌شود، پیامِ فعال‌سازی دایرکتوری مطلق مهارت را به‌شکل [Skill directory: /abs/path] نمایان می‌کند و دو توکن قالبی را هم هر جای بدنهٔ SKILL.md جایگزین می‌کند:

توکنجایگزین می‌شود با
${HERMES_SKILL_DIR}مسیر مطلق دایرکتوری مهارت
${HERMES_SESSION_ID}شناسهٔ نشست فعال (اگر نشستی نباشد، سر جایش می‌ماند)

پس یک SKILL.md می‌تواند به ایجنت بگوید اسکریپت همراه را مستقیم با این اجرا کند:

To analyse the input, run:

    node ${HERMES_SKILL_DIR}/scripts/analyse.js <input>

ایجنت مسیر مطلقِ جایگزین‌شده را می‌بیند و ابزار terminal را با فرمانی آمادهٔ اجرا صدا می‌زند — نه محاسبهٔ مسیر، نه رفت‌وبرگشت اضافهٔ skill_view. جایگزینی را به‌صورت سراسری با skills.template_vars: false در config.yaml خاموش کنید.

اسنیپت‌های شل درون‌خطی (opt-in)

مهارت‌ها می‌توانند اسنیپت‌های شل درون‌خطی را هم به‌شکل !`cmd` در بدنهٔ SKILL.md بگنجانند. وقتی فعال باشد، خروجی استانداردِ هر اسنیپت قبل از آن‌که ایجنت پیام را بخواند درون پیام می‌نشیند؛ پس مهارت‌ها می‌توانند زمینهٔ پویا تزریق کنند:

Current date: !`date -u +%Y-%m-%d`
Git branch: !`git -C ${HERMES_SKILL_DIR} rev-parse --abbrev-ref HEAD`

این قابلیت به‌صورت پیش‌فرض خاموش است — هر اسنیپت داخل SKILL.md بدون تأیید روی هاست اجرا می‌شود؛ پس فقط برای منابع مهارتی که به آن‌ها اعتماد دارید فعالش کنید:

# config.yaml
skills:
  inline_shell: true
  inline_shell_timeout: 10   # ثانیه برای هر اسنیپت

اسنیپت‌ها با دایرکتوری مهارت به‌عنوان دایرکتوری کاری اجرا می‌شوند و خروجی‌شان به ۴۰۰۰ نویسه محدود است. شکست‌ها (تایم‌اوت، خروج غیرصفر) به‌شکل نشان کوتاه [inline-shell error: ...] دیده می‌شوند به‌جای آن‌که کل مهارت را بشکنند.

تستش کنید

مهارت را اجرا کنید و بررسی کنید ایجنت درست طبق دستورالعمل‌ها عمل می‌کند:

hermes chat --toolsets skills -q "Use the X skill to do Y"

۶ مهارت کجا باید باشد؟

مهارت‌های همراه (در skills/) با هر نصب هرمس عرضه می‌شوند. آن‌ها باید برای بیشتر کاربران به‌طور گسترده مفید باشند:

  • مدیریت اسناد، پژوهش وب، گردش‌کارهای رایج توسعه، مدیریت سیستم
  • به‌طور منظم توسط طیف گسترده‌ای از افراد استفاده می‌شوند

اگر مهارت شما رسمی و مفید است ولی برای همه ضروری نیست (مثلاً یکپارچه‌سازی سرویس پولی، وابستگی سنگین)، آن را در optional-skills/ بگذارید — با مخزن عرضه می‌شود، از طریق hermes skills browse قابل‌کشف است (با برچسب "official") و با اعتماد داخلی نصب می‌شود.

اگر مهارت شما تخصصی، مشارکتی از سوی جامعه یا کم‌مخاطب است، جای بهتری برای آن Skills Hub است — آن را در یک رجیستری بارگذاری کنید و از طریق hermes skills install به اشتراک بگذارید.

۷ نقشه‌های اتوماسیون (Blueprint): مهارت‌هایی که اتوماسیون هم هستند

یک نقشهٔ اتوماسیون (blueprint) یک مهارت معمولی است که در فرانت‌متر خود زمان‌بندی هم اعلام می‌کند. یک بلوک metadata.hermes.blueprint اضافه کنید و مهارت به اتوماسیونی قابل‌اشتراک و قابل‌اجرا تبدیل می‌شود:

metadata:
  hermes:
    tags: [blueprint, email]
    blueprint:
      schedule: "0 8 * * *"     # حضور blueprint: آن را قابل‌اجرا علامت می‌زند
      deliver: telegram          # اختیاری (پیش‌فرض: origin)
      prompt: "Summarize my unread email and today's calendar."  # اختیاری
      no_agent: false            # اختیاری

چون نقشهٔ اتوماسیون خودش مهارت است، بدون تغییر از کل خط لولهٔ مهارت‌ها می‌گذرد — جستجو، بازرسی، نصب، اسکن امنیتی، منشأ، tapها، فهرست متمرکز و hermes skills publish برای اشتراک. چیز جدیدی برای یادگرفتن نیست.

نصب یک نقشهٔ اتوماسیون. وقتی مهارتی را نصب می‌کنید که بلوک blueprint: دارد، هرمس آن را به‌عنوان کار کرون پیشنهادی ثبت می‌کند نه آن‌که زمان‌بندی‌اش کند. زمان‌بندی با پذیرش شماست — نصب هرگز بی‌سروصدا کار تکرارشونده نمی‌سازد. شما آن را از طریق /suggestions بازبینی و می‌پذیرید:

hermes skills install owner/morning-brief
# → Blueprint: 'morning-brief' یک اتوماسیون است (schedule 0 8 * * *).
#   به پیشنهادهای شما اضافه شد — برای زمان‌بندی یا رد کردن، /suggestions را اجرا کنید.

# سپس، در یک نشست:
/suggestions             # پیشنهادهای در انتظار را شماره‌دار فهرست می‌کند
/suggestions accept 1    # کار کرون را می‌سازد
/suggestions dismiss 1   # دیگر هرگز پیشنهادش نمی‌کند

نقشه‌های اتوماسیون یکی از منابع سطح یکپارچهٔ کارهای کرون پیشنهادی‌اند — همان‌جایی که اتوماسیون‌های شروعِ منتخب و (بعداً) پیشنهادهای الگوی مصرف و یکپارچه‌سازی ظاهر می‌شوند. به کارهای کرون پیشنهادی در پایین نگاه کنید.

به‌اشتراک‌گذاشتن اتوماسیونی که ساخته‌اید. نقشهٔ اتوماسیونی که یک کار کرون بارش می‌کند (hermes cron create --skill <name> ...) می‌تواند دوباره به SKILL.md برون‌بری شود و مثل هر مهارت دیگری منتشر شود؛ تا اتوماسیونی که برای خودتان تنظیم کرده‌اید، برای دیگری به نصبی با یک فرمان تبدیل شود.

لایهٔ نقشهٔ اتوماسیون هیچ نوع شیء، مخزن یا مسیر انتقال جدیدی اضافه نمی‌کند — نقشهٔ اتوماسیون یک مهارت است، زمان‌بندی یک کار کرون است و اشتراک همان مسیر موجودِ publish/tap/index است.

۸ کارهای کرون پیشنهادی

هرمس می‌تواند اتوماسیون‌ها را پیشنهاد دهد و بگذارد آن‌ها را با یک لمس بپذیرید، به‌جای آن‌که شما مجبور شوید کارهای کرون را دستی سرهم کنید. هر پیشنهاد، فارغ از منبعش، از یک سطح واحد می‌گذرد — فرمان /suggestions:

منبعمحرک
catalogاتوماسیون‌های شروعِ منتخب (/suggestions catalog) — بریفینگ روزانه، پایش ایمیل‌های مهم، مرور هفتگی، یادآور شروع روز کاری
blueprintمهارتی نصب کرده‌اید که بلوک blueprint: دارد
usageبازبینی پس‌زمینه درخواست تکرارشونده‌ای را دیده که زمان‌بندی پاسخگوی آن است
integrationیک حساب وصل کرده‌اید (Gmail، GitHub و...) و اتوماسیون‌های بدیهی پیشنهاد می‌شوند
 
/suggestions             # فهرست موارد در انتظار
/suggestions accept N    # پیشنهاد N را زمان‌بندی می‌کند (کار کرون می‌سازد)
/suggestions dismiss N   # رد می‌کند — قفل می‌شود و دیگر هرگز پیشنهاد نمی‌شود
/suggestions catalog     # اتوماسیون‌های شروعِ منتخب را اضافه می‌کند

پذیرفتن یک پیشنهاد همان cron.jobs.create_job را صدا می‌زند که ابزار cronjob استفاده می‌کند — موتور دومی برای کارها وجود ندارد. پیشنهادها هرگز به‌طور خودکار کار نمی‌سازند؛ پذیرش همیشه صریح است. پیشنهادهای ردشده با یک کلید پایدار قفل می‌شوند تا همان پیشنهاد دیگر هرگز تکرار نشود. فهرستِ در انتظارها سقف دارد تا هرگز به دیوارِ مزاحم تبدیل نشود.

مدخل پایش ایمیل‌های مهم در کاتالوگ، الگوی پیمایش→طبقه‌بندی→نمایش است: آیتم‌های صندوق ورودی را با یک مدل طبقه‌بند ارزان (auxiliary.monitor در config.yaml) امتیاز می‌دهد و فقط موارد بالاتر از آستانهٔ فوریت را تحویل می‌دهد؛ در غیر این صورت ساکت می‌ماند.

۹ انتشار مهارت‌ها

به Skills Hub

hermes skills publish skills/my-skill --to github --repo owner/repo

به مخزن سفارشی

مخزن خودتان را به‌عنوان tap اضافه کنید:

hermes skills tap add owner/repo

سپس کاربران می‌توانند از مخزن شما جستجو و نصب کنند.

۱۰ اسکن امنیتی

همهٔ مهارت‌های نصب‌شده از هاب از یک اسکنر امنیتی می‌گذرند که این‌ها را بررسی می‌کند:

  • الگوهای برون‌بری داده
  • تلاش‌های تزریق پرامپت
  • فرمان‌های مخرب
  • تزریق شل

سطوح اعتماد:

  • builtin — همراه هرمس عرضه می‌شود (همیشه مورد اعتماد)
  • official — از optional-skills/ در مخزن (اعتماد داخلی، بدون هشدار شخص ثالث)
  • trusted — از openai/skills، anthropics/skills، huggingface/skills
  • community — یافته‌های غیرخطرناک با --force قابل‌نادیده‌گرفتن‌اند؛ حکم‌های dangerous همچنان مسدود می‌مانند

هرمس حالا می‌تواند مهارت‌های شخص ثالث را از چندین مدل کشف بیرونی مصرف کند:

  • شناسه‌های مستقیم GitHub (مثلاً openai/skills/k8s)
  • شناسه‌های skills.sh (مثلاً skills-sh/vercel-labs/json-render/json-render-react)
  • نقاط پایانی well-known که از /.well-known/skills/index.json سرو می‌شوند

اگر می‌خواهید مهارت‌هایتان بدون نصب‌کنندهٔ وابسته به GitHub قابل‌کشف باشند، علاوه بر انتشارشان در مخزن یا مارکت‌پلیس، سروکردنشان از یک نقطهٔ پایانی well-known را در نظر بگیرید.
