درون‌مایهٔ ACP

آداپتور ACP، ایجنتِ همگامِ AIAgent هرمس را در یک سرور ناهمگام JSON-RPC روی stdio می‌پیچد.

فایل‌های کلیدی پیاده‌سازی:

  • acp_adapter/entry.py
  • acp_adapter/server.py
  • acp_adapter/session.py
  • acp_adapter/events.py
  • acp_adapter/permissions.py
  • acp_adapter/tools.py
  • acp_adapter/auth.py

۱ جریان راه‌اندازی

hermes acp / hermes-acp / python -m acp_adapter
  -> acp_adapter.entry.main()
  -> تجزیهٔ --version / --check / --setup قبل از راه‌اندازی سرور
  -> بارگذاری ~/.hermes/.env
  -> پیکربندی لاگ روی stderr
  -> ساخت HermesACPAgent
  -> acp.run_agent(agent, use_unstable_protocol=True)

stdout برای ترابرد JSON-RPC مربوط به ACP رزرو شده است. لاگ‌های خوانا برای انسان به stderr می‌روند.

۲ اجزای اصلی

HermesACPAgent

acp_adapter/server.py پروتکل ایجنت ACP را پیاده‌سازی می‌کند.

مسئولیت‌ها:

  • مقداردهی اولیه / احراز هویت
  • متدهای نشست new/load/resume/fork/list/cancel
  • اجرای پرامپت
  • تغییر مدل نشست
  • اتصال کال‌بک‌های همگام AIAgent به اعلان‌های ناهمگام ACP

SessionManager

acp_adapter/session.py نشست‌های زندهٔ ACP را ردیابی می‌کند.

هر نشست این‌ها را ذخیره می‌کند:

  • session_id
  • agent
  • cwd
  • model
  • history
  • cancel_event

مدیر thread-safe است و از این‌ها پشتیبانی می‌کند:

  • ساخت
  • دریافت
  • حذف
  • انشعاب
  • فهرست‌کردن
  • پاک‌سازی
  • به‌روزرسانی‌های cwd

پل رویدادها

acp_adapter/events.py کال‌بک‌های AIAgent را به رویدادهای session_update مربوط به ACP تبدیل می‌کند.

کال‌بک‌های پل‌شده:

  • tool_progress_callback
  • thinking_callback (در حال حاضر در پل ACP روی None تنظیم شده است — استدلال به‌جایش از طریق step_callback ارسال می‌شود)
  • step_callback

چون AIAgent در یک ترد کارگر اجرا می‌شود در حالی که I/O مربوط به ACP روی حلقهٔ رویداد اصلی زندگی می‌کند، پل از این استفاده می‌کند:

asyncio.run_coroutine_threadsafe(...)

پل مجوزها

acp_adapter/permissions.py پرامپت‌های تأیید ترمینال خطرناک را به درخواست‌های مجوز ACP تبدیل می‌کند.

نگاشت:

  • allow_once ← once در هرمس
  • allow_always ← always در هرمس
  • گزینه‌های رد ← deny در هرمس

تایم‌اوت‌ها و شکست‌های پل به‌طور پیش‌فرض رد (deny) می‌کنند.

کمک‌تابع‌های رندر ابزار

acp_adapter/tools.py ابزارهای هرمس را به انواع ابزار ACP نگاشت می‌کند و محتوای رو به ویرایشگر می‌سازد.

مثال‌ها:

  • patch / write_file ← دیف فایل‌ها
  • terminal ← متن فرمان شل
  • read_file / search_files ← پیش‌نمایش‌های متنی
  • نتایج بزرگ ← بلوک‌های متنی بریده‌شده برای ایمنی UI

۳ چرخهٔ حیات نشست

new_session(cwd)
  -> ساخت SessionState
  -> ساخت AIAgent(platform="acp", enabled_toolsets=["hermes-acp"])
  -> اتصال task_id/session_id به بازنویسی cwd

prompt(..., session_id)
  -> استخراج متن از بلوک‌های محتوای ACP
  -> ریست رویداد لغو
  -> نصب کال‌بک‌ها + پل تأیید
  -> اجرای AIAgent در ThreadPoolExecutor
  -> به‌روزرسانی تاریخچهٔ نشست
  -> ساطع کردن قطعهٔ نهایی پیام ایجنت

لغو

cancel(session_id):

  • رویداد لغو نشست را تنظیم می‌کند
  • وقتی موجود باشد، agent.interrupt() را صدا می‌زند
  • باعث می‌شود پاسخ پرامپت stop_reason="cancelled" برگرداند

انشعاب (fork)

fork_session() تاریخچهٔ پیام‌ها را به‌صورت deep-copy در یک نشست زندهٔ جدید کپی می‌کند؛ وضعیت گفتگو حفظ می‌شود، در حالی که انشعاب شناسهٔ نشست و cwd مخصوص خودش را می‌گیرد.

۴ رفتار ارائه‌دهنده/احراز هویت

ACP مخزن احراز هویت خودش را پیاده‌سازی نمی‌کند.

به‌جایش از حل‌وفصل‌کنندهٔ زمان اجرای هرمس استفادهٔ مجدد می‌کند:

  • acp_adapter/auth.py
  • hermes_cli/runtime_provider.py

بنابراین ACP همان ارائه‌دهنده/اعتبارنامه‌های پیکربندی‌شدهٔ فعلی هرمس را اعلام و استفاده می‌کند. همچنین همیشه یک روش احراز هویتِ از نوع راه‌اندازی ترمینالی اعلام می‌کند (hermes-setup با آرگومان‌های --setup) تا کلاینت‌های ACP در اولین اجرا بتوانند قبل از شروع یک نشست عادی ACP، پیکربندی تعاملی مدل/ارائه‌دهندهٔ هرمس را باز کنند.

۵ اتصال پوشهٔ کاری

نشست‌های ACP یک cwd ویرایشگر با خود حمل می‌کنند.

مدیر نشست آن cwd را از طریق بازنویسی‌های ترمینال/فایلِ در-سطح-تسک به شناسهٔ نشست ACP می‌بندد، تا ابزارهای فایل و ترمینال نسبت به فضای کاری ویرایشگر عمل کنند.

۶ فراخوانی‌های ابزار هم‌نامِ تکراری

پل رویدادها شناسه‌های ابزار را به‌صورت FIFO برای هر نام ابزار ردیابی می‌کند، نه فقط یک شناسه برای هر نام. این برای موارد زیر مهم است:

  • فراخوانی‌های هم‌نامِ موازی
  • فراخوانی‌های هم‌نامِ تکراری در یک گام

بدون صف‌های FIFO، رویدادهای تکمیل به فراخوانی ابزار اشتباهی وصل می‌شدند.

۷ بازگردانی کال‌بک تأیید

ACP در طول اجرای پرامپت، موقتاً یک کال‌بک تأیید روی ابزار ترمینال نصب می‌کند و بعد از آن، کال‌بک قبلی را بازمی‌گرداند. این کار جلوی می‌دهد که هندلرهای تأییدِ مخصوص نشست ACP برای همیشه به‌صورت سراسری نصب‌شده باقی بمانند.

۸ محدودیت‌های فعلی

  • نشست‌های ACP در ~/.hermes/state.db مشترک (SessionDB) ذخیره می‌شوند و پس از ری‌استارت پروسس به‌طور شفاف بازیابی می‌شوند؛ در session_search ظاهر می‌شوند
  • بلوک‌های پرامپت غیرمتنی در استخراج متن درخواست، فعلاً نادیده گرفته می‌شوند
  • تجربهٔ کاربری مخصوص هر ویرایشگر بسته به پیاده‌سازی کلاینت ACP متفاوت است
