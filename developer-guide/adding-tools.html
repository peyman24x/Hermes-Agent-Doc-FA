افزودن ابزار جدید

قبل از نوشتن ابزار، از خودتان بپرسید: آیا این نباید به‌جایش یک مهارت باشد؟

⚠️ فقط ابزارهای هستهٔ داخلی

این صفحه برای افزودن یک ابزار داخلی هرمس به خود مخزن است. اگر ابزار شخصی، محلیِ پروژه یا سفارشیِ دیگری می‌خواهید بدون دست‌کاری هستهٔ هرمس، به‌جایش از مسیر پلاگین استفاده کنید:

  • پلاگین‌ها
  • ساخت پلاگین هرمس

برای بیشتر ساخت ابزار سفارشی، پلاگین‌ها انتخاب پیش‌فرض‌اند. فقط وقتی این صفحه را دنبال کنید که صریحاً می‌خواهید یک ابزار داخلی جدید در tools/ و toolsets.py عرضه کنید.

وقتی قابلیت را می‌توان با دستورالعمل + فرمان‌های شل + ابزارهای موجود بیان کرد، آن را یک مهارت بسازید (جستجوی arXiv، گردش‌کارهای git، مدیریت Docker، پردازش PDF).

وقتی به یکپارچه‌سازی سرتاسری با کلیدهای API، منطق پردازش سفارشی، کار با دادهٔ باینری یا استریمینگ نیاز دارد، آن را یک ابزار بسازید (اتوماسیون مرورگر، TTS، تحلیل بینایی).

۱ نمای کلی

افزودن یک ابزار ۲ فایل را درگیر می‌کند:

  1. tools/your_tool.py — هندلر، طرح‌واره، تابع بررسی و فراخوانی registry.register()
  2. toolsets.py — افزودن نام ابزار به _HERMES_CORE_TOOLS (یا یک تول‌ست مشخص)

هر فایل tools/*.py که فراخوانی registry.register() در سطح بالای آن باشد، هنگام راه‌اندازی به‌طور خودکار کشف می‌شود — نیازی به فهرست ایمپورت دستی نیست.

۲ گام ۱: ساخت فایل ابزار داخلی

هر فایل ابزار همین ساختار را دارد:

# tools/weather_tool.py
"""Weather Tool -- look up current weather for a location."""

import json
import os
import logging

logger = logging.getLogger(__name__)


# --- بررسی در دسترس بودن ---

def check_weather_requirements() -> bool:
    """Return True if the tool's dependencies are available."""
    return bool(os.getenv("WEATHER_API_KEY"))


# --- هندلر ---

def weather_tool(location: str, units: str = "metric") -> str:
    """Fetch weather for a location. Returns JSON string."""
    api_key = os.getenv("WEATHER_API_KEY")
    if not api_key:
        return json.dumps({"error": "WEATHER_API_KEY not configured"})
    try:
        # ... فراخوانی API هوا ...
        return json.dumps({"location": location, "temp": 22, "units": units})
    except Exception as e:
        return json.dumps({"error": str(e)})


# --- طرح‌واره ---

WEATHER_SCHEMA = {
    "name": "weather",
    "description": "Get current weather for a location.",
    "parameters": {
        "type": "object",
        "properties": {
            "location": {
                "type": "string",
                "description": "City name or coordinates (e.g. 'London' or '51.5,-0.1')"
            },
            "units": {
                "type": "string",
                "enum": ["metric", "imperial"],
                "description": "Temperature units (default: metric)",
                "default": "metric"
            }
        },
        "required": ["location"]
    }
}


# --- ثبت ---

from tools.registry import registry

registry.register(
    name="weather",
    toolset="weather",
    schema=WEATHER_SCHEMA,
    handler=lambda args, **kw: weather_tool(
        location=args.get("location", ""),
        units=args.get("units", "metric")),
    check_fn=check_weather_requirements,
    requires_env=["WEATHER_API_KEY"],
)

قواعد کلیدی

⛔ مهم
  • هندلرها باید یک رشتهٔ JSON برگردانند (با json.dumps())، هرگز دیکشنری خام نه
  • خطاها باید به‌صورت {"error": "message"} برگردند، هرگز به‌شکل اکششن پرتاب نشوند
  • check_fn هنگام ساختن تعریف ابزارها صدا زده می‌شود — اگر False برگرداند، ابزار بی‌سروصدا حذف می‌شود
  • handler مقدار (args: dict, **kwargs) می‌گیرد که در آن args آرگومان‌های فراخوانی ابزارِ LLM است

۳ گام ۲: افزودن ابزار داخلی به یک تول‌ست

در toolsets.py نام ابزار را اضافه کنید:

# اگر باید روی همهٔ پلتفرم‌ها (CLI + پیام‌رسانی) در دسترس باشد:
_HERMES_CORE_TOOLS = [
    ...
    "weather",  # <-- اینجا اضافه کنید
]

# یا یک تول‌ست مستقل جدید بسازید:
"weather": {
    "description": "Weather lookup tools",
    "tools": ["weather"],
    "includes": []
},

۴ گام ۳: افزودن ایمپورت برای کشف (دیگر لازم نیست)

ماژول‌های ابزار که فراخوانی registry.register() در سطح بالایشان باشد، توسط discover_builtin_tools() در tools/registry.py به‌طور خودکار کشف می‌شوند. فهرست ایمپورت دستی برای نگه‌داری وجود ندارد — فقط فایلتان را در tools/ بسازید و هنگام راه‌اندازی برداشته می‌شود.

رجیستری پل‌زدن ناهمگام را به‌طور شفاف انجام می‌دهد — شما هرگز خودتان asyncio.run() را صدا نمی‌زنید.

۶ هندلرهایی که به task_id نیاز دارند

ابزارهایی که وضعیت مخصوص هر نشست را مدیریت می‌کنند، task_id را از طریق **kwargs می‌گیرند:

def _handle_weather(args, **kw):
    task_id = kw.get("task_id")
    return weather_tool(args.get("location", ""), task_id=task_id)

registry.register(
    name="weather",
    ...
    handler=_handle_weather,
)

۷ ابزارهای رهگیری‌شده در حلقهٔ ایجنت

برخی ابزارها (todo، memory، session_search، delegate_task) به وضعیت ایجنتِ مخصوص هر نشست نیاز دارند. این‌ها قبل از رسیدن به رجیستری، توسط run_agent.py رهگیری می‌شوند. رجیستری همچنان طرح‌واره‌هایشان را نگه می‌دارد، اما اگر رهگیری دور زده شود، dispatch() یک خطای پشتیبان برمی‌گرداند.

۸ اختیاری: یکپارچه‌سازی با جادوگر راه‌اندازی

اگر ابزارتان به کلید API نیاز دارد، آن را به hermes_cli/config.py اضافه کنید:

OPTIONAL_ENV_VARS = {
    ...
    "WEATHER_API_KEY": {
        "description": "Weather API key for weather lookup",
        "prompt": "Weather API key",
        "url": "https://weatherapi.com/",
        "tools": ["weather"],
        "password": True,
    },
}
